Calls and voice

Calls and voice channels send audio, video and screen sharing straight to the server on their own port. This page covers the network side, the settings to check after installing, and transcription with a speech-to-text model you run yourself.

How calls work

Calls are provided by the Calls app (id com.mattermost.calls), which is installed and enabled by default. Voice channels (the Voice Channels app, antimatter-next image) are permanent call rooms built on Calls: they need Calls to be enabled and use the same settings, ports and servers.

The Calls app runs a media server inside Antimatter. The web app, the desktop app and the mobile apps connect to it with WebRTC:

  • the signalling goes through the normal web connection (your HTTPS proxy);
  • the media (audio, video, screen sharing) does not: it goes straight to the server on the calls port, 8443 UDP and TCP by default.

The settings are in System Console › Plugins › Calls. Each of them can also be set with an AM_CALLS_ environment variable on the antimatter service, which then wins over the System Console and locks the setting there. The legacy MM_CALLS_ names also work.

Check these after installing

  1. Open the calls port. Allow 8443/udp and 8443/tcp in the firewall of the server and of your cloud provider.
  2. Turn test mode off. Test mode (DefaultEnabled) is on by default: only system administrators can start calls in channels, so you can check that calls work before everyone uses them. Set it to Off in System Console › Plugins › Calls, or set AM_CALLS_DEFAULT_ENABLED=true.
  3. Decide on video. Enable video calls in DMs (Experimental) (EnableVideo, AM_CALLS_ENABLE_VIDEO) is off by default. While it is off, nobody can turn on a camera, not even in voice channels. When it is on, cameras work in direct message calls and in voice channels (unless the Voice Channels app's Allow video in voice channels is off).
  4. Behind NAT, set the public address (next section).

Ports must be between 80 and 49151. With the site's compose file, change CALLS_PORT in .env: it sets both variables and publishes the port, the same number on the host and in the container. Clients first try UDP and fall back to TCP on the same port.

Which address clients send media to

The server tells each client the address to send media to (its "host candidate"). By default it finds its public address by asking a STUN server, a public service that replies with the address and port a request came from. The default is Cloudflare's public STUN server, stun:stun.cloudflare.com:3478. The server isn't the only one to use it: every client that joins a call also asks it for its own public address. The STUN server sees only IP addresses and ports, never call audio, video or messages.

A server that still has Mattermost's STUN server (stun.global.calls.mattermost.com) saved in ICE Servers Configurations, for example after moving from Mattermost, uses Cloudflare's instead. The saved setting isn't changed.

Set the address yourself when:

  • the server is behind NAT, or has several public addresses: set ICE Host Override to the public IP address (or a hostname that resolves to it);
  • the NAT maps a different public port to 8443: also set ICE Host Port Override to that public port;
  • the server has no Internet access, or you don't want the server and the clients to contact an outside STUN server: set ICE Host Override, and empty the STUN list with AM_CALLS_ICE_SERVERS_CONFIGS=[]. With ICE Host Override set, the server no longer asks a STUN server for its address; the empty list stops the clients from asking one.
services:
  antimatter:
    environment:
      AM_CALLS_ICE_HOST_OVERRIDE: 203.0.113.10
      AM_CALLS_ICE_SERVERS_CONFIGS: "[]"

To keep STUN without a third party, run your own STUN server (a TURN server such as coturn also answers STUN requests) and list it in ICE Servers Configurations instead, as in the TURN example below.

On a local network only, use the server's LAN address. Restart the server after changing ports, addresses or ICE settings, or disable and enable the Calls app: the media server is set up when the app starts.

TURN, for strict firewalls

Some networks block both UDP and outgoing connections to unusual TCP ports. People on them need a TURN server, which relays the media over a port they can reach (often 443). Antimatter doesn't include one; run a TURN server such as coturn and add it to ICE Servers Configurations, a JSON list:

[
  {"urls": ["stun:turn.example.com:3478"]},
  {"urls": ["turn:turn.example.com:3478?transport=udp", "turns:turn.example.com:443?transport=tcp"]}
]
  • With a shared secret (coturn's use-auth-secret), put the same secret in TURN Static Auth Secret (AM_CALLS_TURN_STATIC_AUTH_SECRET): the server gives each client short-lived credentials, valid for TURN Credentials Expiration (minutes) (240 by default).
  • With fixed credentials, add "username" and "credential" to the TURN entry instead.
  • Server Side TURN (off by default) also uses the TURN servers for connections the server starts.

The Voice Channels app has two settings, in System Console › Plugins › Voice Channels: Join when opening a voice channel (on by default) and Allow video in voice channels (on by default, but see video above). Community admins turn a channel into a voice channel in its settings.

To turn calls off completely, disable the Calls app in System Console › Plugins › Plugin Management, or set AM_CALLS_DISABLE=true. Voice channels then stop working too.

Larger servers: an external rtcd

By default one Antimatter server carries all the call media. For many simultaneous calls, or to keep the media off the chat server, the Calls app can hand the media to rtcd, a separate media server (Mattermost's open-source rtcd, version 0.17 or newer). Set RTCD service URL (AM_CALLS_RTCD_SERVICE_URL), for example https://rtcd.example.com: all calls then go through it, and clients send their media to rtcd's own port instead of Antimatter's. Credentials can be given with AM_CALLS_RTCD_CLIENT_ID and AM_CALLS_RTCD_AUTH_KEY; without them, the app registers itself with rtcd. No licence is needed. The Calls app shows administrators a warning recommending rtcd when a server often has more than 50 people in calls at once.

Transcription and live captions

Antimatter can transcribe calls with a speech-to-text model you run yourself, and show live captions while people speak. Antimatter uses any server that offers an OpenAI-compatible /v1/audio/transcriptions endpoint, such as a Whisper server on your network. No extra service from Antimatter is needed.

How it works

  • The host of a call starts transcription with Transcribe the call in the call controls. A Transcribing badge tells everyone.
  • Each participant's app listens to its own microphone, cuts the speech into short pieces (up to 12 seconds, never while muted) and sends them to Antimatter, which forwards them to your speech-to-text server.
  • With live captions on, each piece's text is shown to the participants as a caption right away.
  • When transcription stops or the call ends, the Calls bot posts the transcript as a text file and a WebVTT subtitle file, in the call's thread (in voice channels, in the channel).
  • With Summarize transcriptions on, the default agent of the Agents app also posts a summary in the thread (see AI).

Set it up

Set these on the antimatter service:

services:
  antimatter:
    environment:
      AM_CALLS_ENABLE_TRANSCRIPTIONS: "true"
      AM_CALLS_TRANSCRIBE_API: openai
      AM_CALLS_TRANSCRIBE_API_OPEN_AIURL: http://stt.internal:8000/v1
      AM_CALLS_TRANSCRIBE_API_OPEN_AI_MODEL: whisper-1
      AM_CALLS_TRANSCRIBE_API_OPEN_AI_KEY: ""
      AM_CALLS_ENABLE_LIVE_CAPTIONS: "true"
      AM_CALLS_LIVE_CAPTIONS_LANGUAGE: en

In the System Console, the transcription settings only appear once Enable call recordings is on, although this kind of transcription needs no recording. Setting them with the variables above avoids that. Don't turn recordings on together with the openai transcriber: starting a recording would then try to start the job-service transcriber and fail.

The audio of everyone who speaks while transcription is on goes to the speech-to-text server you configured, and the transcript is posted where everyone in the channel can read it. Tell your users, and keep that server on your own network if calls are confidential.

Recordings

Recording calls (and transcribing with the built-in whisper.cpp or Azure transcribers) runs in separate containers started by a job service, Mattermost's open-source calls-offloader, which you deploy yourself next to Antimatter. The settings are Enable call recordings (AM_CALLS_ENABLE_RECORDINGS, off by default), Job service URL (AM_CALLS_JOB_SERVICE_URL), Maximum call recording duration (60 minutes by default, 15 to 180) and Call recording quality (low, medium or high; medium by default). No licence is needed. For transcripts and captions alone, the speech-to-text setup above is simpler: it needs no job service.
