Security

A checklist to harden an Antimatter server: what to expose, the limits and privacy settings to review, the outside services the server contacts, and how to report a security problem.

What to expose

PortServiceExposure
443/tcp, 443/udp, 80/tcpYour HTTPS proxy (Caddy or nginx)Public: this is how people reach Antimatter.
8443/udp and 8443/tcpCall mediaPublic, if people use calls from outside your network.
8065/tcpAntimatter's web serverOnly to the proxy: publish it on 127.0.0.1 (HTTP_PORT=127.0.0.1:8065).
8067/tcpMetricsPrivate network only, when enabled. No sign-in.
8074/tcp and udpCluster gossipBetween cluster nodes only.
5432, 9000, 8080, 8066PostgreSQL, file storage, GIF service, push proxyNever. The compose files keep them on internal networks with no published port.

The site's compose file also runs every container with no-new-privileges, runs Antimatter as an unprivileged user on a distroless image, and runs the GIF service with a read-only file system. The database, the storage and the GIF service sit on a network without Internet access.

Checklist after installing

  1. Create the first administrator account before anyone else can reach the server (Installing).
  2. Serve Antimatter over HTTPS only, and set the site URL to the https:// address (Domain and HTTPS).
  3. Keep .env, config.json and TLS keys readable by root (or the server's user) only: chmod 600 .env.
  4. Decide who can create accounts, keep Enable Open Server off unless the community is public, and turn on Require Email Verification once email works (Sign-in and accounts).
  5. Turn on multi-factor authentication, and enforce it for administrators' accounts at least, or use your identity provider's.
  6. Review the outside connections below, in particular the STUN server Calls uses by default.
  7. Back up, and test a restore (Backups and upgrades).
  8. Keep the images up to date: security fixes arrive with new images.

Rate limiting

The server can limit how many API requests each client makes. It is off by default. In System Console › Environment › Rate Limiting:

SettingKeyDefault
Enable Rate LimitingRateLimitSettings.Enableoff
Maximum Queries per SecondRateLimitSettings.PerSec10
Maximum Burst SizeRateLimitSettings.MaxBurst100
Memory Store SizeRateLimitSettings.MemoryStoreSize10000 clients tracked
Vary rate limit by remote addressRateLimitSettings.VaryByRemoteAddron
Vary rate limit by userRateLimitSettings.VaryByUseroff
Vary rate limit by HTTP headerRateLimitSettings.VaryByHeaderempty

Behind a proxy, limits by address only work if the server knows each client's address (ServiceSettings.TrustedProxyIPHeader and ServiceSettings.TrustedProxyIPs, see Client addresses behind a proxy). Otherwise every request seems to come from the proxy, and everyone shares one limit. The same goes for IP filtering and for the addresses in audit logs.

Sign-in attempts are limited separately: Maximum Login Attempts (10) locks an account after that many failed passwords.

IP filtering

System Console › Site Configuration › IP Filtering limits access to the server by IP address, with allow and deny rules (an address or a CIDR range each). With Enable IP Filtering on, people whose address matches a deny rule, or no allow rule when there are allow rules, can't reach the server. The page refuses rules that would block your own address. Behind a proxy, set up client addresses first (Client addresses behind a proxy): otherwise every request seems to come from the proxy.

Privacy settings

In System Console › Site Configuration › Users and Teams:

SettingKeyDefaultWhat it does
Show Email AddressPrivacySettings.ShowEmailAddressonOff, members' email addresses are hidden from everyone but administrators. Turn it off on public servers.
Show Full NamePrivacySettings.ShowFullNameonOff, full names are hidden and usernames shown instead.
Enable ignoring, blocking and message requestsPrivacySettings.EnableUserBlockingonSee below.
Enable users to open Direct Message channels withTeamSettings.RestrictDirectMessageAny user on the Antimatter serverOr Any member of the team: only people who share a community.

Ignoring, blocking and message requests

With Enable ignoring, blocking and message requests on (the default), people can ignore and block each other, and can choose to receive direct messages from people they don't know as message requests, which don't notify them until accepted. This suits public communities. In a workplace where colleagues must always be able to reach each other, turn it off (AM_PRIVACYSETTINGS_ENABLEUSERBLOCKING=false): none of it is enforced any more, but the lists and choices people made are kept, and apply again if you turn it back on.

Sessions and tokens

  • Session lengths and idle timeout: see Sign-in and accounts. Shorter sessions mean a lost laptop or phone stays signed in for less time.
  • Enable Personal Access Tokens (ServiceSettings.EnableUserAccessTokens, off) lets people create API tokens; Maximum Personal Access Token Lifetime (days) limits them. Both are in System Console › Integrations › Integration Management.
  • To sign everyone out at once, for example after a suspected breach: Revoke All Sessions in System Console › User Management › Users.

Connections to outside services

Antimatter contacts no service run by Mattermost, Inc. It sends no telemetry, crash reports or security update checks, and fetches no product notices. A configuration brought over from Mattermost that still names one of Mattermost's services (its push services, its app marketplace, its notices or its STUN server for calls) doesn't make the server contact them: those addresses are ignored.

The server and the apps connect to other outside services only for the features that need them, and to the services you configure:

FeatureContactsBy default
Calls: finding public addresses with STUN. The server and each person joining a call send a request, which shows the STUN server their IP address and port.Cloudflare's public STUN server, stun.cloudflare.comon, while the Calls app is enabled. To change it, see Calls.
Link previews: the server fetches the pages linked in messages (Enable website link previews, ServiceSettings.EnableLinkPreviews)the websites people link toon. Turn off with AM_SERVICESETTINGS_ENABLELINKPREVIEWS=false.
Push notifications to the mobile appyour own push proxy (Push notifications)off until you set its address
The remote app marketplace (PluginSettings.EnableRemoteMarketplace)the Marketplace URL you setoff, and no address
Emailyour SMTP serverthe default server is localhost
Single sign-on, AI models, speech-to-text and translation, outgoing webhooks, and apps such as Mail, Calendar, GitHub, GitLab or Jirathe services you configureoff until you configure them

By default the server refuses to connect to private and loopback addresses for these (link previews, webhooks, apps), so a message or an integration can't be used to reach your internal network. List the internal hosts it may reach in Allow untrusted internal connections to (ServiceSettings.AllowedUntrustedInternalConnections, in System Console › Environment › Developer); the site's compose file lists gifs there.

Reporting a vulnerability

Report security problems privately, as explained in the Antimatter security policy, not in public issues.
