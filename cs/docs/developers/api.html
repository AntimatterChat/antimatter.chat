REST API

Vše, co aplikace Antimatter dělají, probíhá přes stejné HTTP API, takže to umí i vaše skripty. Tato stránka vysvětluje, jak se autentizovat, které zdroje budete nejčastěji používat, jak vypadají odpovědi a chyby a jak živě sledovat události přes WebSocket.

Základy

  • Základní URL: https://chat.example.com/api/v4. Všechny níže uvedené koncové body jsou relativní vůči ní.
  • Formát: JSON na vstupu i výstupu, s výjimkou nahrávání souborů (multipart). Pošlete Content-Type: application/json.
  • ID: každý objekt má 26 znaků dlouhé id. Časy jsou v milisekundách od Unix epochu (create_at, update_at, delete_at; 0 znamená „nesmazáno“).
  • Komunity jsou týmy: API je nazývá teams a používá team_id.
  • Sebou: kdekoliv, kde cesta bere user_id, me znamená přihlášeného uživatele, např. GET /users/me.

Úplný seznam koncových bodů najdete v kódu serveru: trasy jsou deklarovány v server/channels/api4/*.go a typy v server/public/model. Popis OpenAPI ve složce api/v4/source v repozitáři pokrývá koncové body zděděné z Mattermostu a některé přidané funkce Antimatteru: přesun vláken, připojení modelů, agenty, pravidla komunity, režim soustředění a akce se zprávami. Ostatní jsou pouze v kódu.

Autentizace

Každý požadavek, s výjimkou přihlášení a několika veřejných koncových bodů, vyžaduje token v hlavičce Authorization:

curl -H "Authorization: Bearer $TOKEN" https://chat.example.com/api/v4/users/me

Přijímány jsou tři druhy tokenů: osobní přístupové tokeny, session tokeny a OAuth přístupové tokeny. Přijímá se i Authorization: Token …. Tokeny v dotazovém řetězci (?access_token=) se přijímají pouze pro OAuth přístupové tokeny.

Osobní přístupové tokeny (doporučeno pro skripty)

Osobní přístupový token jedná za vás, nevyprší, pokud mu nenastavíte datum vypršení, a lze ho kdykoli odvolat. Osobní přístupové tokeny jsou ve výchozím nastavení vypnuté:

  1. Systémový administrátor zapne Povolit osobní přístupové tokeny v Systémová konzole › Integrace › Správa integrací (ServiceSettings.EnableUserAccessTokens, AM_SERVICESETTINGS_ENABLEUSERACCESSTOKENS).
  2. Pro každého, kdo může vytvářet tokeny, systémový administrátor otevře Systémová konzole › Správa uživatelů › Uživatelé, v menu dané osoby zvolí Spravovat role a zaškrtně Povolit tomuto účtu generovat osobní přístupové tokeny. Systémoví administrátoři je mohou vždy vytvářet.
  3. Uživatel klikne na svůj avatar v pravém horním rohu a poté na Profil a nastavení › Zabezpečení. V sekci Osobní přístupové tokeny popíše, k čemu token slouží, a zvolí Vytvořit token. Token se zobrazí pouze jednou: zkopírujte ho.

Přes API: POST /users/{user_id}/tokens s tělem {"description": "backup script", "expires_at": 0} (expires_at v milisekundách; 0 znamená bez expirace). Pole token v odpovědi je tajný klíč; jeho id použijete k jeho odvolání (POST /users/tokens/revoke s {"token_id": "…"}). Z příkazového řádku: amctl token generate <user> <description>.

Systémový administrátor může omezit platnost tokenů pomocí Maximální platnost osobního přístupového tokenu (dny) na stejné stránce Systémové konzole.

Relační tokeny

Přihlášení heslem vrátí relační token v hlavičce odpovědi Token, což je stejný typ relace, který používají aplikace:

curl -i -X POST https://chat.example.com/api/v4/users/login \
  -H 'Content-Type: application/json' \
  -d '{"login_id": "maya", "password": "…"}'

Pro účet s vícefaktorovou autentizací přidejte "token": "123456". Relace expirují podle nastavení relací na serveru a koncový bod pro přihlášení je omezen rychlostí (5 požadavků za sekundu). POST /users/logout relaci ukončí.

Prohlížeče se autentizují pomocí cookie. Požadavek autentizovaný cookie musí pro jakoukoli metodu kromě GET také odesílat hlavičku X-CSRF-Token; token v hlavičce Authorization hlavičku CSRF nevyžaduje.

OAuth 2.0 aplikace

Pokud chcete, aby se lidé mohli přihlásit do vaší aplikace svým účtem Antimatter, zaregistrujte OAuth 2.0 aplikaci. Antimatter pak slouží jako OAuth poskytovatel:

  1. Povolit službu OAuth 2.0 musí být zapnuto (Systémová konzole › Integrace › Správa integrací, ServiceSettings.EnableOAuthServiceProvider, výchozí stav je zapnuto).
  2. Uživatel s oprávněním spravovat aplikace OAuth (výchozí jsou systémoví administrátoři) otevře Integrace › Aplikace OAuth 2.0 (nabídka komunity › Nastavení týmu › Integrace) a přidá aplikaci včetně jejích zpětných URL. Získá ID klienta a tajný klíč klienta.
  3. Vaše aplikace posílá uživatele na https://chat.example.com/oauth/authorize s parametry response_type=code, client_id, redirect_uri a state. Podporováno je PKCE s code_challenge_method=S256.
  4. Kód vymění na POST https://chat.example.com/oauth/access_token (nejdřív grant_type=authorization_code, pak refresh_token pro obnovu) a volá API s hlavičkou Authorization: Bearer <access token>.

Uživatelé vidí aplikace, které autorizovali, v Profil & nastavení › Zabezpečení › Aplikace, které jste autorizovali.

Zprávy jsou v Markdownu. Pro odpověď ve vláknu přidejte "root_id" (ID prvního příspěvku vlákna), pro soubory "file_ids" a pro přílohy a další doplňky "props" (viz Přílohy).

curl -H "Authorization: Bearer $TOKEN" \

Jména jsou ta, která najdete v odkazu na kanál: /lumen-labs/channels/ops-alerts.

Stránkování

Koncové body pro seznamy přijímají page (od 0) a per_page (výchozí 60, maximálně 200). Neustále žádejte další stránku, dokud se nevrátí stránka kratší než per_page.

Zprávy kanálu (GET /channels/{channel_id}/posts) také přijímají parametr since (čas: vše, co se od té doby změnilo), nebo before a after (ID příspěvku). Odpověď je seznam příspěvků: {"order": [IDs, newest first], "posts": {ID: post}, "next_post_id", "prev_post_id"}.

Chyby

Chyby používají běžné HTTP stavové kódy (400 nesprávný vstup, 401 neautorizováno, 403 zakázáno, 404 nenalezeno, 501 funkce vypnutá) a JSON tělo:

{
  "id": "api.context.permissions.app_error",
  "message": "You do not have the appropriate permissions.",
  "detailed_error": "",
  "request_id": "jz8zm5nunpbt8f3gpqsz5dq6so",
  "status_code": 403
}

Ve svém kódu používejte id: message je přeloženo do jazyka uživatele. detailed_error je prázdné, pokud server neběží v režimu vývojáře (ServiceSettings.EnableDeveloper). Uveďte request_id administrátorovi serveru: je v logu.

Omezení rychlosti

Omezení frekvence je výchozí vypnuté. Když systémový administrátor ho zapne (Systémová konzole › Prostředí › Omezení frekvence), každý klient má výchozí 10 požadavků za sekundu s bursty 100, počítáno podle IP adresy nebo podle uživatele. Odpovědi nesou X-RateLimit-Limit, X-RateLimit-Remaining a X-RateLimit-Reset; nad limitem server odpoví 429 s hlavičkou Retry-After v sekundách. Některé endpointy, jako je přihlášení, mají vlastní limit bez ohledu na nastavení.

Píšte skripty, které čekají a při 429 se opakují, a vyhýbejte se dotazování: sledujte WebSocket.

WebSocketový tok událostí

Připojte se k wss://chat.example.com/api/v4/websocket. Autentizujte se buď hlavičkou Authorization: Bearer v požadavku na připojení, nebo odesláním tohoto jako první zprávy:

{"seq": 1, "action": "authentication_challenge", "data": {"token": "…"}}

Server pošle událost hello, pak událost pro vše, co máte právo vidět:

{
  "event": "posted",
  "data": {"channel_id": "…", "channel_type": "O", "post": "{\"id\":\"…\",\"message\":\"Hello\",…}"},
  "broadcast": {"channel_id": "…", "team_id": "", "user_id": "", "omit_users": null},
  "seq": 4
}

Pozor, data.post je příspěvek jako JSON řetězec. Běžné události: posted, post_edited, post_deleted, reaction_added, reaction_removed, typing, status_change, user_added, direct_added. Aplikace posílají vlastní události, pojmenované custom_<app id>_<event>.

Můžete také posílat akce, každá s rostoucím seq: user_typing s {"channel_id", "parent_id"}, nebo get_statuses. Připojte se znovu, když se připojení přeruší, a načtěte to, co jste přehlédli, pomocí since (viz Stránkování).

Antimatter přidává tyto události: agent_activity_changed a agent_post_stream (viz Agenti), community_rules_updated a community_rules_accepted (viz Pravidla komunity), focus_ended (viz Režim soustředění), community_attributes_updated, member_timeouts_updated, post_put_on_top, post_removed_from_top, server_categories_updated, channel_overrides_updated a category_overrides_updated.

Klientské knihovny

  • Jít: model.Client4 v server/public/model (import github.com/mattermost/mattermost/server/public/model). model.NewAPIv4Client(url), pak client.SetToken(token); model.NewWebSocketClient4(wsURL, token) sleduje události. Antimatter's copy adds methods for its own endpoints, such as UpdateMessageRequest, PutPostOnTop and ExportChannel.
  • TypeScript: třída Client4 z balíčku @mattermost/client v webapp/platform/client, s typy v webapp/platform/types. Kopie v repozitáři Antimatteru obsahuje koncové body Antimatteru; balíček publikovaný na npm společností Mattermost je neobsahuje.
package main

import (
	"context"
	"log"

	"github.com/mattermost/mattermost/server/public/model"
)

func main() {
	client := model.NewAPIv4Client("https://chat.example.com")
	client.SetToken("…")
	post, _, err := client.CreatePost(context.Background(), &model.Post{
		ChannelId: "…",
		Message:   "Hello from Go",
	})
	if err != nil {
		log.Fatal(err)
	}
	log.Println("posted", post.Id)
}

Nová pole

  • Komunity (Team, a PUT /teams/{team_id}/patch): all_channels_membership (každý je ve všech kanálech, které může vidět), default_channel_id (kam nováčci přistanou; prázdné znamená General), kind (community nebo workplace: v workplace mohou administrátoři kanálů archivovat i své kanály; nové komunity dostanou TeamSettings.DefaultCommunityKind serveru, výchozí je community), member_list_view (jak seznam členů členy grupuje: choice, výchozí možnost, nechá každého člena, aby si vybral; roles nebo teams to fixuje), hide_role_colors, require_team_badges, onboarding a autolinks (oba JSON řetězce).
  • Výchozí kanál nové komunity je general (Obecné), nikoli town-square. Aktualizace na verzi 0.9.0 přejmenuje town-square každé komunity na general a zachová jeho ID, pokud komunita již kanál general nemá. Staré názvy fungují i nadále: GET /teams/{team_id}/channels/name/town-square, GET /teams/name/{team}/channels/name/town-square a příchozí webhook channel vrátí výchozí kanál komunity, pokud žádný kanál tento název nemá. V novém kódu používejte default_channel_id nebo název general.
  • Odkazy na kanály: #channel-name odkazuje na kanál stejně jako ~channel-name. Vlastnost channel_mentions příspěvku obsahuje seznam kanálů odkázaných kterakoli; #word, který neodpovídá žádnému kanálu, zůstává štítkem. Webové rozhraní a mobilní aplikace Antimatter zapisují #name.
  • Archivované kanály stále přijímají nové členy (POST /channels/{channel_id}/members), kteří si mohou přečíst jejich historii. Nikdo tam nemůže publikovat, reagovat, připínat, přesouvat zprávy na vrchol, přejmenovávat kanál ani měnit role členů.
  • Vložené odpovědi: příspěvek s "props": {"reply_to": "<post id>"} cituje danou zprávu ze stejného kanálu. Přidejte "reply_to_mention": false, abyste autora neoznamovali. Server vyplní metadata.reply_to krátkým popisem citované zprávy.
  • Varování před senzitivním obsahem: "props": {"spoiler": true} skryje text a soubory příspěvku, dokdy čtenář nevybere, že je chce zobrazit.
  • Ignorování a blokace jsou preference: kategorie user_block, pojmenovaná podle ID druhé osoby, s hodnotou ignore nebo block. Zda přímá zpráva čeká jako žádost, je v notify_props.dm_request vašeho člena kanálu (pending, accepted nebo dismissed).
  • Přílohy zpráv mohou nést stages a chart: viz Karty.

Přesunout vlákno

POST /posts/{post_id}/move_to_channel přesune vlákno, jeho první zprávu a všechny odpovědi do jiného kanálu téže komunity. post_id může být první zpráva nebo libovolná odpověď.

curl -X POST https://chat.example.com/api/v4/posts/$POST_ID/move_to_channel \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"channel_id": "'$TARGET_CHANNEL_ID'", "flatten": false}'
  • channel_id (povinné): kanál, do kterého se vlákno přesouvá.
  • flatten (výchozí hodnota false): true způsobí, že odpovědi se stanou zprávami cílového kanálu místo vlákna. V Fusion se k tomu používá Make it a channel.

Zprávy si zachovají autory, časy, reakce a soubory. Jejich kopie nesou vlastnost silent_notification, takže nikoho neupozorní. Původní zprávy jsou smazány. Odpovědí je přesunutá první zpráva s jejím novým ID.

Kdo může přesouvat vlákno

  • Musíte mít možnost vlákno číst a publikovat v cílovém kanálu.
  • Administrátoři kanálu, administrátoři komunity, osoby s oprávněním Spravovat zprávy (delete_others_posts) v kanálu a systémoví administrátoři mohou přesunout libovolné vlákno.
  • Autor vlákna ho může přesunout, pokud jsou oba kanály veřejné, nebo pokud jsou všechny zprávy vlákna jeho. V opačném případě je odpovědí 403 s ID api.post.move_thread.private_needs_moderator.app_error.
  • Oba kanály musí patřit do stejné komunity (přímé a skupinové zprávy se nepřenášejí), musí být odlišné a nemohou být archivované. Systémové zprávy a zprávy, které se po přečtení smažou, nelze přesunout.
  • Vlákno delší než WranglerSettings.MoveThreadMaxCount zpráv (výchozí hodnota je 100; 0 znamená bez omezení) se nepřijme.

Ukazatel a poznámka

Přesun zanechá dvě systémové zprávy typu system_wrangler: ukazatel v původním kanálu („Vlákno se 13 zprávami bylo přesunuto do #target“) a poznámku v cílovém kanálu („Toto vlákno bylo přesunuto z #source“), umístěné pod přesunutým vlákнем nebo, při použití flatten, za jeho zprávy. Kromě textu zprávy umožňují jejich atributy klientovi vykreslit název kanálu jako odkaz:

  • Ukazatel: MovedThreadPermalink, NumMessages, MovedThreadChannelId, MovedThreadTeamName, MovedThreadPostId a, pro veřejný cíl, MovedThreadChannelName a MovedThreadChannelDisplayName.
  • Poznámka: MovedFromChannelId, MovedFromTeamName, MovedFromPostId (ukazatel), MovedFromPermalink a, pro veřejný zdroj, MovedFromChannelName a MovedFromChannelDisplayName.

Obě zprávy mají také TranslationID. Název soukromého kanálu se neuvádí: čtenáři vidí „jiný kanál“. Vlastní endpoint Mattermost POST /posts/{post_id}/move je v Antimatter vypnutý; použijte tento endpoint.

Pravidla komunity

Administrátoři komunity mohou vyžadovat, aby členové před zveřejněním příspěvku v jejích kanálech souhlasili s jejími pravidly. Pokud jsou pravidla aktivní, člen, který nesouhlasil s aktuální verzí, nemůže zveřejňovat příspěvky, odpovídat, posílat soubory, plánovat, upravovat nebo obnovovat zprávy ani spouštět příkazy, které zveřejňují příspěvky v kanálech komunity: server odpoví 403 s ID api.post.community_rules_not_accepted a naplánovaná zpráva, která má být odeslána v tuto dobu, selže s chybovým kódem community_rules_not_accepted. Čtení, reakce, přímé zprávy a skupinové zprávy nejsou blokovány; stejně tak ani boti, příchozí webhooky, systémové zprávy a administrátoři komunity (manage_team, které mají i systémoví administrátoři).

Koncový bodCo dělá
GET /teams/{team_id}/rulesPravidla (enabled, text ve formátu Markdown, version), spolu s nejnovější verzí, se kterou jste souhlasili (accepted_version), a informací, zda musíte souhlasit před zveřejněním příspěvku (must_accept). Pro členy a pro kohokoli, kdo se může připojit k otevřené komunitě.
PUT /teams/{team_id}/rulesUloží je pomocí {"enabled", "text", "ask_again"} (manage_team). ask_again vytvoří novou verzi, se kterou musí všichni znovu souhlasit; první uložení je verze 1. Text je povinný pro zapnutí pravidel a může mít maximálně 16 000 znaků.
POST /teams/{team_id}/rules/acceptSouhlasí jako člen s verzí version, kterou jste přečetli; 409, pokud byla od té doby uložena novější verze, a 0 pro souhlas s aktuální verzí.
GET /teams/{team_id}/rules/statsKolik členů komunity souhlasilo s aktuální verzí (manage_team).

Událost community_rules_updated je odeslána komunitě, když administrátor uloží pravidla (team_id, enabled, version), a událost community_rules_accepted je odeslána uživateli, který souhlasil, na všech jeho relacích (team_id, version).

Režim soustředění

Režim soustředění je stav Nevýrušovat s koncovým časem: oznámení jsou ztlumena (žádná push, e-mailová, desktopová ani trvalá oznámení, včetně naléhavých zpráv), důvod se stane vlastním stavem s emoji 🎯 (dart), který vyprší v koncovém čase, a aplikace Antimatteru skryjí uživateli vlastní odznaky nepřečtených zpráv. Tyto koncové body mohou používat pouze sami uživatelé (me nebo jejich vlastní ID): nikdo jiný, včetně systémových administrátorů, nemůže zahájit, ukončit nebo číst režim soustředění někoho jiného ani jeho shrnutí.

Koncový bodCo dělá
GET /users/me/focusAktuální režim soustředění (active, start_at, end_at, reason), nebo poslední režim soustředění po jeho ukončení (ended_at nastaveno), nebo všechny hodnoty nulové.
POST /users/me/focusSpustí soustředění nebo při soustředění změní jeho konec a důvod: {"duration": "1h30m", "reason": "…"}, nebo místo délky trvání {"end_at": ms}, a to od jedné minuty do jednoho týdne dopředu. "duration": "tomorrow" znamená konec v 09:00 následujícího dne podle časového pásma uživatele. Konec je zaokrouhlen dolů na minuty; důvod může mít nejvýše 100 znaků. Vyžaduje zapnuté stavy uživatelů (ServiceSettings.EnableUserStatuses); botové nemohou soustředit.
DELETE /users/me/focusUkončí soustředění okamžitě.
GET /users/me/focus/summary?since=&until=Co bylo v daném okně zmeškáno (start_at a ended_at soustředění): kanály s nepřečtenými zprávami od ostatních (nejprve přímé a skupinové zprávy, poté ty se zmínkami; ztlumené kanály pouze s výskytem zmínky) a u sbalených vláken odpovědí sledovaná vlákna s novými odpověďmi, každé s počtem, zmínkami a posledním odesílatelem.
POST /users/me/focus/summary/readS parametry {"since", "until"} označí tyto kanály a vlákna jako přečtené pouze do until; zprávy přidané po této době zůstanou nepřečtené.

Během soustředění má uživatel atribut focus_until (v milisekundách), který klienti používají k zobrazení stavu soustředění; nelze jej měnit prostřednictvím profilu. Soustředění končí, když jej uživatel ukončí, když uplyne stanovený čas (s tolerancí jedné minuty), nebo když si uživatel sám vybere stav, který pak zůstane zachován. Jinak se obnoví stav a vlastní stav z doby před soustředěním. Všechny relace uživatele pak obdrží událost focus_ended s poli start_at, end_at a ended_by (user, timer nebo status).

Připojení k modelům

Připojení modelu je adresa a klíč poskytovatele AI, které nastaví administrátor. Používají je AI funkce serveru i aplikace, které volají AI službu. Systémoví administrátoři spravují celoserverová připojení (manage_ai_connections); administrátoři komunity spravují připojení své komunity (manage_team_ai_connections). Klíče jsou pouze pro zápis: žádná odpověď je neobsahuje, pouze api_key_set a api_key_last4.

Koncový bodCo dělá
GET /ai/connections?scope=Připojení, která spravujete. scope je server nebo ID komunity; bez něj se vrátí všechna připojení, která spravujete.
POST /ai/connectionsPřidá připojení (odpovídá 201).
POST /ai/connections/test, POST /ai/connections/modelsOtestuje připojení nebo vypíše jeho modely, než se uloží. Stejné tělo požadavku jako při přidávání; nic se neukládá.
GET, PATCH (nebo PUT), DELETE /ai/connections/{connection_id}Načte, změní nebo smaže připojení. Patch obsahuje pouze pole, která se mají změnit; vynechání api_key zachová klíč.
POST /ai/connections/{connection_id}/testOtestuje uložené připojení: {"ok", "error", "status_code", "latency_ms", "model_count"}.
GET /ai/connections/{connection_id}/modelsModely, které poskytovatel nabízí.
GET /ai/connections/{connection_id}/usagePočet požadavků a tokenů za tento měsíc.
GET /ai/connections/usable?channel_id=&team_id=Pro každého přihlášeného: připojení, která tam můžete použít, včetně jejich modelů a funkcí, nikdy však klíčů ani adres.

Tělo nového připojení:

{
  "name": "Local models",
  "scope": "server",
  "provider": "openai_compatible",
  "base_url": "http://llm.internal:8000/v1",
  "api_key": "…",
  "extra_headers": {},
  "models": {"chat": "qwen3-32b", "embeddings": "", "transcription": "", "decisions": ""},
  "limits": {"requests_per_minute": 0, "monthly_token_budget": 0, "per_user_requests_per_minute": 0, "per_user_monthly_token_budget": 0},
  "sharing": {"all_teams": true, "team_ids": []},
  "audience": {"everyone": true, "group_ids": [], "roles": [], "allow_guests": false}
}

provider je openai_compatible nebo anthropic. scope má výchozí hodnotu server; ID komunity z něj udělá připojení této komunity. V limits znamená 0 žádný limit; požadavky za minutu se počítají na každém serveru, rozpočet tokenů na kalendářní měsíc (UTC) pro celý cluster. sharing určuje, které komunity mohou použít serverové připojení (přímé a skupinové zprávy vyžadují all_teams), a audience určuje, kdo ho může používat; hosté pouze s allow_guests. Změny se zapisují do auditního protokolu. Nastavení vysvětluje administrátorský průvodce: viz AI.

Agenti

Agent je účet bota typu agent (s atributem is_agent u uživatele) se svými nastaveními: rozsah (server nebo ID komunity), vestavěný nebo external, a u vestavěného agenta připojení k modelu, model, systémový prompt a úvody. Administrátoři systému spravují agenty v rámci celého serveru (manage_system), administrátoři komunity agenty své komunity (manage_team); k tomu navíc manage_own_agent pro agenta, kterého vytvořili, a manage_others_agent pro ostatní. ID agenta v těchto cestách je jeho ID uživatele. Spouštění externího agenta je popsáno v Botové.

Koncový bodCo dělá
GET /ai/agents?scope=Agenti, které spravujete: scope je server nebo ID komunity; bez tohoto parametru se vrátí všichni agenti, které spravujete.
POST /ai/agentsVytvoří agenta a jeho účet (vrátí 201). Agent komunity se přidá do své komunity.
GET, PATCH, DELETE /ai/agents/{agent_id}
POST …/enable, POST …/disable		Čte, mění, maže (jeho účet je deaktivován, zprávy zůstávají), zapíná nebo vypíná agenta.
GET /ai/agents/connections?scope=
GET /ai/agents/connections/{connection_id}/models		Připojení k modelům, která může agent v daném rozsahu používat, a jejich modely.
GET, PUT /ai/agents/{agent_id}/activity
POST /ai/agents/activity/ids		Co agent dělá; nastavuje se jeho vlastním tokenem nebo jeho správci. Dávková operace zpracuje až 200 ID uživatelů.
POST /ai/agents/{agent_id}/tasksŽádá vestavěného agenta, kterého můžete použít pro úlohu: summarize_thread, find_action_items nebo find_open_questions (pro post_id vlákna nebo channel_id od since výše), summarize_channel, ask_channel (s parametrem question) nebo summarize_transcription (příspěvek s přepisem hovoru). Požadavek se stane vaší zprávou ve vaší přímé zprávě s agentem, ve vašem jazyce, a je na něj odpovězeno tam; odpověď (201) je tato zpráva. Na příspěvek nebo kanál, který nemůžete číst, je odpovězeno tak, jako by neexistoval.
GET /ai/agents/conversations?agent_id=&before=&per_page=Vaše konverzace s agenty, které můžete používat, nejnovější první: vlákna, která jste začali ve svých přímých zprávách s nimi, a vlákna jinde, ve kterých jeden z nich odpověděl a která sledujete. Parametr before (čas) vrátí další stránku; per_page je maximálně 100.

Tělo nového agenta:

{
  "username": "researcher",
  "display_name": "Researcher",
  "description": "Answers with sources",
  "scope": "server",
  "external": false,
  "connection_id": "…",
  "model": "",
  "system_prompt": "You research questions and answer with sources.",
  "reasoning": {"enabled": false, "effort": "", "budget_tokens": 0},
  "max_tool_turns": 0,
  "access": {"everyone": true, "team_ids": [], "channel_ids": [], "roles": [], "user_ids": [], "allow_guests": false}
}

Prázdné model používá chatový model připojení. access.channel_ids znamená členy těchto kanálů. Externí agent nemá žádné připojení, model ani systémový prompt. GET /agents vypíše agenty, se kterými můžete mluvit, tak, jak je čte aplikace AI chat.
