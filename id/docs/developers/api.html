REST API

Semua yang dilakukan oleh aplikasi Antimatter melewati HTTP API yang sama, sehingga skrip Anda juga dapat melakukannya. Halaman ini menjelaskan cara melakukan autentikasi, sumber daya yang paling sering Anda gunakan, bagaimana bentuk respons dan kesalahan, serta cara mengikuti peristiwa secara langsung melalui WebSocket.

Dasar-dasar

  • URL Dasar: https://chat.example.com/api/v4. Semua endpoint di bawah ini relatif terhadap URL tersebut.
  • Format: JSON masuk dan keluar, kecuali unggahan file (multipart). Kirim Content-Type: application/json.
  • ID: setiap objek memiliki id 26 karakter. Waktu adalah milidetik sejak epoch Unix (create_at, update_at, delete_at; 0 berarti "tidak dihapus").
  • Komunitas adalah tim: API menyebutnya teams, dengan team_id.
  • Diri Anda: di mana pun jalur menerima user_id, me berarti pengguna yang sedang masuk, seperti dalam GET /users/me.

Daftar lengkap endpoint ada di kode server: rute dideklarasikan di server/channels/api4/*.go dan tipe di server/public/model. Deskripsi OpenAPI di folder api/v4/source di repositori mencakup endpoint yang diwarisi dari Mattermost, bukan tambahan Antimatter.

Autentikasi

Setiap permintaan, kecuali masuk dan beberapa endpoint publik, membutuhkan token di header Authorization:

curl -H "Authorization: Bearer $TOKEN" https://chat.example.com/api/v4/users/me

Tiga jenis token diterima di sana: token akses pribadi, token sesi, dan token akses OAuth. Authorization: Token … juga diterima. Token di string kueri (?access_token=) hanya diterima untuk token akses OAuth.

Token akses pribadi (disarankan untuk skrip)

Token akses pribadi bertindak sebagai Anda, tidak kedaluwarsa kecuali Anda memberikannya tanggal kedaluwarsa, dan dapat dicabut kapan saja. Token akses pribadi nonaktif secara bawaan:

  1. Admin sistem mengaktifkan Aktifkan Token Akses Pribadi di Konsol Sistem › Integrasi › Manajemen Integrasi (ServiceSettings.EnableUserAccessTokens, AM_SERVICESETTINGS_ENABLEUSERACCESSTOKENS).
  2. Untuk setiap orang yang dapat membuat token, admin sistem membuka Konsol Sistem › Manajemen Pengguna › Pengguna, memilih Kelola peran di menu orang tersebut, dan mencentang Izinkan akun ini untuk membuat token akses pribadi. Admin sistem selalu dapat membuat token.
  3. Orang tersebut membuka avatar mereka di kanan atas, lalu Profil & pengaturan › Keamanan. Di bawah Token akses pribadi, mereka menjelaskan kegunaan token dan memilih Buat token. Token hanya ditampilkan sekali: salin.

Dengan API: POST /users/{user_id}/tokens dengan {"description": "backup script", "expires_at": 0} (expires_at dalam milidetik; 0 untuk tidak ada). Field token dalam respons adalah rahasia; id adalah yang Anda gunakan untuk mencabutnya (POST /users/tokens/revoke dengan {"token_id": "…"}). Dari baris perintah: amctl token generate <user> <description>.

Admin sistem dapat membatasi masa berlaku token dengan Masa Berlaku Maksimum Token Akses Pribadi (hari) di halaman Konsol Sistem yang sama.

Token sesi

Masuk dengan kata sandi mengembalikan token sesi di header respons Token, jenis sesi yang sama yang digunakan aplikasi:

curl -i -X POST https://chat.example.com/api/v4/users/login \
  -H 'Content-Type: application/json' \
  -d '{"login_id": "maya", "password": "…"}'

Tambahkan "token": "123456" untuk akun dengan autentikasi multi-faktor. Sesi kedaluwarsa sesuai pengaturan sesi server, dan endpoint login dibatasi laju (5 permintaan per detik). POST /users/logout mengakhiri sesi.

Peramban mengautentikasi dengan cookie. Permintaan yang diautentikasi dengan cookie juga harus mengirim header X-CSRF-Token untuk apa pun selain GET; token di header Authorization tidak memerlukan header CSRF.

Aplikasi OAuth 2.0

Untuk memungkinkan orang masuk ke aplikasi Anda dengan akun Antimatter mereka, daftarkan aplikasi OAuth 2.0. Antimatter kemudian menjadi penyedia OAuth:

  1. Aktifkan Penyedia Layanan OAuth 2.0 harus diaktifkan (Konsol Sistem › Integrasi › Manajemen Integrasi, ServiceSettings.EnableOAuthServiceProvider, diaktifkan secara default).
  2. Seseorang yang memiliki hak untuk mengelola aplikasi OAuth (admin sistem secara default) membuka avatar mereka, lalu Integrasi › Aplikasi OAuth 2.0, dan menambahkan aplikasi dengan URL callback. Mereka mendapatkan ID klien dan rahasia klien.
  3. Aplikasi Anda mengarahkan pengguna ke https://chat.example.com/oauth/authorize dengan response_type=code, client_id, redirect_uri, dan state. PKCE dengan code_challenge_method=S256 didukung.
  4. Kode ditukarkan di POST https://chat.example.com/oauth/access_token (grant_type=authorization_code, lalu refresh_token untuk memperbarui), dan API dipanggil dengan Authorization: Bearer <access token>.

Pengguna dapat melihat aplikasi yang mereka izinkan di Profil & Pengaturan › Keamanan › Aplikasi yang Anda izinkan.

Kirim pesan

curl -X POST https://chat.example.com/api/v4/posts \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"channel_id": "'$CHANNEL_ID'", "message": "Backup finished: **42 GB** in 3 min"}'

Pesan menggunakan Markdown. Tambahkan "root_id" (pesan pertama dari utas) untuk membalas dalam utas, "file_ids" untuk berkas, dan "props" untuk lampiran dan tambahan lainnya (lihat Lampiran).

Cari ID kanal

curl -H "Authorization: Bearer $TOKEN" \
  https://chat.example.com/api/v4/teams/name/lumen-labs/channels/name/ops-alerts

Nama-nama tersebut adalah nama yang ada di tautan kanal: /lumen-labs/channels/ops-alerts.

Paginasi

Endpoint daftar menerima page (mulai dari 0) dan per_page (60 secara default, maksimal 200). Terus minta halaman berikutnya sampai halaman yang dikembalikan lebih pendek dari per_page.

Pesan pada sebuah kanal (GET /channels/{channel_id}/posts) juga menerima parameter since (waktu: semua perubahan sejak saat itu), atau before dan after (ID pesan). Hasilnya berupa daftar pesan: {"order": [IDs, newest first], "posts": {ID: post}, "next_post_id", "prev_post_id"}.

Kesalahan

Kesalahan menggunakan kode status HTTP yang umum (400 masukan salah, 401 belum masuk, 403 tidak diizinkan, 404 tidak ditemukan, 501 fitur dimatikan) dan isi JSON:

{
  "id": "api.context.permissions.app_error",
  "message": "You do not have the appropriate permissions.",
  "detailed_error": "",
  "request_id": "jz8zm5nunpbt8f3gpqsz5dq6so",
  "status_code": 403
}

Gunakan id di kode Anda: message diterjemahkan ke bahasa pengguna. detailed_error kosong kecuali server berjalan dalam mode pengembang (ServiceSettings.EnableDeveloper). Sampaikan request_id ke admin server: ID ini ada di log.

Batas Laju

Batas laju dimatikan secara bawaan. Ketika admin sistem mengaktifkannya (Konsol Sistem › Lingkungan › Batas Laju), setiap klien mendapat 10 permintaan per detik dengan lonjakan hingga 100 secara bawaan, dihitung berdasarkan alamat IP atau pengguna. Respons membawa X-RateLimit-Limit, X-RateLimit-Remaining, dan X-RateLimit-Reset; jika melebihi batas, server menjawab 429 dengan header Retry-After dalam detik. Beberapa titik akhir, seperti masuk, memiliki batasnya sendiri terlepas dari pengaturan.

Tulis skrip yang menunggu dan mencoba lagi saat 429, dan hindari polling: ikuti WebSocket saja.

Aliran peristiwa WebSocket

Hubungkan ke wss://chat.example.com/api/v4/websocket. Autentikasi dengan header Authorization: Bearer pada permintaan koneksi, atau dengan mengirim ini sebagai pesan pertama:

{"seq": 1, "action": "authentication_challenge", "data": {"token": "…"}}

Server mengirim peristiwa hello, lalu peristiwa untuk semua yang Anda diizinkan untuk melihat:

{
  "event": "posted",
  "data": {"channel_id": "…", "channel_type": "O", "post": "{\"id\":\"…\",\"message\":\"Hello\",…}"},
  "broadcast": {"channel_id": "…", "team_id": "", "user_id": "", "omit_users": null},
  "seq": 4
}

Perhatikan bahwa data.post adalah pesan sebagai string JSON. Peristiwa umum: posted, post_edited, post_deleted, reaction_added, reaction_removed, typing, status_change, user_added, direct_added. Aplikasi mengirim peristiwanya sendiri, bernama custom_<app id>_<event>.

Anda juga dapat mengirim aksi, masing-masing dengan seq yang meningkat: user_typing dengan {"channel_id", "parent_id"}, atau get_statuses. Hubungkan ulang saat koneksi terputus, dan ambil yang terlewat dengan since (lihat Paginasi).

Antimatter menambahkan event-event berikut: community_attributes_updated, member_timeouts_updated, post_put_on_top, post_removed_from_top, server_categories_updated, channel_overrides_updated, dan category_overrides_updated.

Perpustakaan klien

  • Lanjut: model.Client4 di server/public/model (impor github.com/mattermost/mattermost/server/public/model). model.NewAPIv4Client(url), lalu client.SetToken(token); model.NewWebSocketClient4(wsURL, token) mengikuti peristiwa. Salinan Antimatter menambahkan metode untuk endpoint miliknya sendiri, seperti UpdateMessageRequest, PutPostOnTop, dan ExportChannel.
  • TypeScript: kelas Client4 dari @mattermost/client, di webapp/platform/client, dengan tipenya di webapp/platform/types. Salinan di repositori Antimatter mencakup endpoint Antimatter; paket yang dipublikasikan di npm oleh Mattermost tidak.
package main

import (
	"context"
	"log"

	"github.com/mattermost/mattermost/server/public/model"
)

func main() {
	client := model.NewAPIv4Client("https://chat.example.com")
	client.SetToken("…")
	post, _, err := client.CreatePost(context.Background(), &model.Post{
		ChannelId: "…",
		Message:   "Hello from Go",
	})
	if err != nil {
		log.Fatal(err)
	}
	log.Println("posted", post.Id)
}

Bidang baru

  • Komunitas (Team, dan PUT /teams/{team_id}/patch): all_channels_membership (semua orang berada di setiap kanal yang dapat mereka lihat, seperti di Discord), default_channel_id (tempat pendaratan orang baru; kosong berarti Town Square), hide_role_colors, require_team_badges, onboarding dan autolinks (keduanya string JSON).
  • Balasan inline: sebuah kiriman dengan "props": {"reply_to": "<post id>"} mengutip pesan tersebut dari kanal yang sama. Tambahkan "reply_to_mention": false untuk tidak memberi tahu penulisnya. Server mengisi metadata.reply_to dengan deskripsi singkat dari pesan yang dikutip.
  • Spoiler: "props": {"spoiler": true} menyembunyikan teks dan file sebuah kiriman sampai pembaca memilih untuk melihatnya.
  • Abai dan blokir adalah preferensi: kategori user_block, dinamai sesuai ID orang lain, dengan nilai ignore atau block. Apakah pesan langsung menunggu sebagai permintaan ada di notify_props.dm_request anggota kanal Anda (pending, accepted atau dismissed).
  • Lampiran pesan dapat membawa stages dan chart: lihat Kartu.
