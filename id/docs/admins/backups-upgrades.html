Cadangan dan peningkatan

Apa yang harus dicadangkan, cara memulihkannya di host baru, cara melakukan peningkatan, dan cara memindahkan server Mattermost atau satu komunitas ke Antimatter.

Basis data dan file harus bersama-sama: cadangkan keduanya pada saat yang sama, dan simpan salinannya di luar server. Nama volume diawali dengan nama proyek compose, antimatter (perintah docker volume ls akan menampilkannya).

Cadangkan

Jalankan dari direktori compose.yaml. Menghentikan Antimatter terlebih dahulu menghasilkan salinan yang sepenuhnya konsisten; cadangan yang diambil saat server berjalan biasanya tidak masalah, tetapi file yang diunggah selama proses pencadangan mungkin tidak ada di dalamnya.

stamp=$(date +%Y%m%d-%H%M%S)
mkdir -p backups
docker compose stop antimatter
# Database
docker compose exec -T postgres pg_dump -U antimatter -d antimatter -Fc \
    > "backups/antimatter-db-$stamp.dump"
# File storage and GIF service
for v in files gifs; do
    docker run --rm -v "antimatter_$v:/data:ro" -v "$PWD/backups:/backup" \
        alpine tar -czf "/backup/antimatter-$v-$stamp.tar.gz" -C /data .
done
docker compose start antimatter
# Secrets
cp .env "backups/env-$stamp"

Jalankan melalui cron untuk cadangan harian, dan salin direktori backups/ ke mesin lain. Simpan salinan .env dengan keamanan setara server: file tersebut menyimpan kata sandi server.

Untuk menyalin file yang diunggah per objek (misalnya ke penyimpanan S3 lain), gunakan alat baris perintah AWS dari layanan bucket:

docker compose run --rm -v "$PWD/backups/files:/backup" bucket \
    "aws --endpoint-url http://files:9000 s3 sync s3://antimatter /backup"

Dengan arsip rilis, cadangkan basis data dengan pg_dump -Fc, dan direktori data/ serta config/ dengan alat Anda yang biasa digunakan.

Pulihkan di host baru

Letakkan compose.yaml, .env yang tersimpan, dan file cadangan di direktori baru, kemudian:

stamp=20261016-030000          # the backup to restore
docker compose create           # creates the volumes, starts nothing
docker compose up -d postgres
docker compose exec -T postgres pg_restore -U antimatter -d antimatter --no-owner \
    < "backups/antimatter-db-$stamp.dump"
for v in files gifs; do
    docker run --rm -v "antimatter_$v:/data" -v "$PWD/backups:/backup" \
        alpine tar -xzf "/backup/antimatter-$v-$stamp.tar.gz" -C /data
done
docker compose up -d

Gunakan .env yang sama: penyimpanan dan basis data harus tetap menggunakan kata sandi yang sama. Jika host baru memiliki alamat lain, perbarui SITE_URL (dan DOMAIN).

Uji cadangan Anda dengan memulihkannya di mesin lain dari waktu ke waktu.

Tingkatkan

  1. Ambil cadangan.
  2. Ubah tag gambar di .env (ANTIMATTER_IMAGE), jika Anda menguncinya, seperti yang direkomendasikan.
  3. Tarik dan mulai ulang: 
    docker compose pull
docker compose up -d
docker compose logs -f antimatter

Saat dimulai, server akan memutakhirkan skema database (pantau prosesnya di log; server besar dapat memakan waktu beberapa menit) dan menginstal versi terbaru dari aplikasi bawaan dari image. Dengan arsip rilis: hentikan server, ganti semua konten kecuali config/, data/, logs/, plugins/, dan client/plugins/ dengan konten arsip baru, lalu mulai ulang.

Pemutakhiran hanya dapat dilakukan ke versi yang lebih baru. Setelah server versi baru memutakhirkan database, versi yang lebih lama tidak dapat menggunakannya: untuk kembali ke versi lama, pulihkan cadangan yang dibuat sebelum pemutakhiran. Hal yang sama berlaku untuk perpindahan dari antimatter-next kembali ke antimatter.

Versi

Server Antimatter melaporkan versi baris Mattermost yang menjadi dasarnya (saat ini 12.0.0). Image dibangun ulang dari cabang main: antimatter-next setiap malam (tag nightly-<YYYYMMDD>), dan kedua image pada setiap perubahan (tag sha-<commit>). Kunci salah satu tag ini, lakukan pemutakhiran secara sengaja, dan catat tag sebelumnya agar Anda tahu cadangan mana yang sesuai.

Versi utama PostgreSQL

Berkas compose menggunakan postgres:17-alpine. Antimatter membutuhkan PostgreSQL 15 atau lebih baru. Versi utama PostgreSQL yang baru tidak dapat membaca direktori data versi sebelumnya: untuk berpindah ke versi baru, buat dump database, mulai versi baru pada volume baru, dan pulihkan dump ke dalamnya.

Beralih dari Mattermost

Antimatter menggunakan skema database Mattermost dan menambahkan tabelnya sendiri, sehingga dapat mengambil alih database PostgreSQL dan file server Mattermost. Coba dulu pada salinannya:

  1. Cadangkan database Mattermost, penyimpanan file-nya (data/ atau bucket S3), dan config.json, lalu hentikan Mattermost.
  2. Pulihkan database ke PostgreSQL Antimatter, atau arahkan Antimatter ke salinannya (AM_SQLSETTINGS_DATASOURCE).
  3. Salin file ke penyimpanan Antimatter, pertahankan jalur mereka: ke bucket antimatter dengan alat S3, atau ke data/ dengan arsip rilis.
  4. Gunakan ulang pengaturan Anda: salin config.json, atau pindahkan ke database dengan amctl --local config migrate (lihat Pengaturan). Variabel lingkungan MM_ Anda tetap berfungsi; ganti namanya menjadi AM_ jika memungkinkan.
  5. Jalankan Antimatter dan pantau log saat database ditingkatkan. Kemudian periksa Konsol Sistem › Plugin › Manajemen Plugin. Antimatter menginstal build miliknya sendiri untuk Calls, Playbooks, Kanban (Papan), Agents, dan integrasi jika versi tersebut lebih baru daripada versi yang terpasang. Jika Mattermost memiliki versi yang lebih baru untuk salah satu dari aplikasi tersebut, hapus aplikasi itu dan mulai ulang Antimatter agar build miliknya sendiri terpasang.
  6. Atur ulang notifikasi push dengan proxy push Anda sendiri: Antimatter tidak pernah mengirim notifikasi ke layanan push Mattermost, baik yang uji coba maupun yang dihosting, karena layanan tersebut hanya mengirim ke aplikasi milik Mattermost. Selama Anda belum mengubah Server Notifikasi Push, server tidak mengirim notifikasi push (lihat Notifikasi push).

Antimatter tidak menghubungi layanan apa pun yang dijalankan oleh Mattermost, Inc. (lihat Koneksi ke layanan eksternal), bahkan jika konfigurasi Anda masih menyebutkan salah satu layanan tersebut:

  • server notifikasi push di Mattermost tetap disimpan dalam pengaturan tetapi tidak pernah digunakan;
  • alamat Mattermost untuk marketplace aplikasi (URL Marketplace) dan untuk pemberitahuan produk dikosongkan;
  • aplikasi Calls menggunakan server STUN publik Cloudflare alih-alih milik Mattermost, tanpa mengubah pengaturan yang tersimpan (lihat Calls);
  • periksa pembaruan keamanan dan pelaporan crash dihapus, begitu juga pengaturan Konsol Sistem-nya (Aktifkan Peringatan Keamanan, Aktifkan Diagnostik dan Pelaporan Error) serta halaman Pemberitahuan.

Socket mode lokal sekarang adalah /var/tmp/antimatter_local.socket; amctl juga mencoba /var/tmp/mattermost_local.socket yang lama. Mattermost hanya mendukung PostgreSQL dalam versi-versi terbarunya, dan Antimatter juga demikian: pindahkan database MySQL ke PostgreSQL terlebih dahulu. Kembali ke Mattermost setelah Antimatter meningkatkan database berarti memulihkan cadangan Mattermost Anda.

Ekspor dan impor data

Format ekspor massal memindahkan data antar server: seluruh server, beberapa komunitas, atau beberapa kanal, lengkap dengan lampiran, foto profil, dan emoji kustom jika Anda menginginkannya.

# on the source server
amctl export create --team-name design --include-profile-pictures
amctl export list
amctl export download <export file> design.zip
# on the destination server
amctl import upload design.zip
amctl import list available
amctl import process <uploaded file> --imported-users active

Pantau pekerjaan dengan amctl export job list dan amctl import job list. Untuk ekspor komunitas atau kanal, --imported-users wajib diisi: active jika orang-orang tersebut pindah ke server ini, inactive saat mengimpor ke server tempat mereka sudah memiliki akun, sehingga akun yang dibuat dari kecocokan yang tidak pasti tetap nonaktif sampai admin memeriksanya. --destination-team-name mengimpor ke komunitas yang sudah ada. Ekspor dan impor disimpan di penyimpanan server (ExportSettings.Directory, ImportSettings.Directory) selama 30 hari secara bawaan.

Di server itu sendiri, antimatter export bulk dan antimatter import bulk --apply melakukan hal yang sama dari file, tanpa menggunakan API.
