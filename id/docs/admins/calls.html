Panggilan dan suara

Panggilan dan kanal suara mengirim audio, video, dan berbagi layar langsung ke server melalui port khusus. Halaman ini membahas sisi jaringan, pengaturan yang perlu diperiksa setelah instalasi, dan transkripsi dengan model speech-to-text yang Anda jalankan sendiri.

Cara kerja panggilan

Panggilan disediakan oleh aplikasi Panggilan (id com.mattermost.calls), yang terpasang dan diaktifkan secara bawaan. Kanal suara (aplikasi Kanal Suara, image antimatter-next) adalah ruang panggilan permanen yang dibangun di atas Panggilan: mereka membutuhkan Panggilan untuk diaktifkan dan menggunakan pengaturan, port, dan server yang sama.

Aplikasi Panggilan menjalankan server media di dalam Antimatter. Aplikasi web, aplikasi desktop, dan aplikasi seluler terhubung ke server tersebut dengan WebRTC:

  • sinyal (signalling) melewati koneksi web normal (proxy HTTPS Anda);
  • media (audio, video, berbagi layar) tidak: media dikirim langsung ke server melalui port panggilan, 8443 UDP dan TCP secara bawaan.

Pengaturannya ada di Konsol Sistem › Plugin › Panggilan. Masing-masing juga dapat diatur dengan variabel lingkungan AM_CALLS_ pada layanan antimatter, yang kemudian mengungguli Konsol Sistem dan mengunci pengaturan di sana. Nama lama MM_CALLS_ juga berfungsi.

Periksa ini setelah instalasi

  1. Buka port panggilan. Izinkan 8443/udp dan 8443/tcp di firewall server dan penyedia cloud Anda.
  2. Matikan mode uji. Mode uji (DefaultEnabled) aktif secara bawaan: hanya administrator sistem yang dapat memulai panggilan di kanal, sehingga Anda dapat memeriksa apakah panggilan berfungsi sebelum semua orang menggunakannya. Atur ke Nonaktif di Konsol Sistem › Plugin › Panggilan, atau setel AM_CALLS_DEFAULT_ENABLED=true.
  3. Putuskan tentang video. Aktifkan panggilan video di DM (Eksperimental) (EnableVideo, AM_CALLS_ENABLE_VIDEO) nonaktif secara bawaan. Selama nonaktif, tidak ada yang dapat menyalakan kamera, bahkan di kanal suara. Saat aktif, kamera berfungsi di panggilan pesan langsung dan di kanal suara (kecuali Izinkan video di kanal suara dari aplikasi Kanal Suara nonaktif).
  4. Di belakang NAT, setel alamat publik (bagian berikutnya).

Port harus berada di antara 80 dan 49151. Dengan file compose situs, ubah CALLS_PORT di .env: ini mengatur kedua variabel dan menerbitkan port, dengan nomor yang sama di host dan di dalam kontainer. Klien pertama-tama mencoba UDP dan beralih ke TCP pada port yang sama.

Alamat mana yang digunakan klien untuk mengirim media

Server memberi tahu setiap klien alamat untuk mengirim media ("kandidat host"-nya). Secara default, server menemukan alamat publiknya dengan bertanya ke server STUN, sebuah layanan publik yang membalas dengan alamat dan port tempat permintaan berasal. Defaultnya adalah server STUN publik Cloudflare, stun:stun.cloudflare.com:3478. Server bukan satu-satunya yang menggunakannya: setiap klien yang bergabung ke panggilan juga bertanya ke server tersebut untuk alamat publiknya sendiri. Server STUN hanya melihat alamat IP dan port, tidak pernah melihat audio, video, atau pesan panggilan.

Server yang masih menyimpan server STUN Mattermost (stun.global.calls.mattermost.com) di Konfigurasi Server ICE, misalnya setelah bermigrasi dari Mattermost, akan menggunakan server Cloudflare sebagai gantinya. Pengaturan yang tersimpan tidak diubah.

Atur alamat Anda sendiri ketika:

  • server berada di belakang NAT, atau memiliki beberapa alamat publik: atur Penimpaan ICE Host ke alamat IP publik (atau nama host yang dipecahkan ke alamat tersebut);
  • NAT memetakan port publik yang berbeda ke 8443: atur juga Penimpaan Port ICE Host ke port publik tersebut;
  • server tidak memiliki akses ke Internet, atau Anda tidak ingin server dan klien menghubungi server STUN eksternal: atur Penimpaan ICE Host, dan kosongkan daftar STUN dengan AM_CALLS_ICE_SERVERS_CONFIGS=[]. Dengan Penimpaan ICE Host diatur, server tidak lagi bertanya ke server STUN untuk alamatnya; daftar kosong menghentikan klien dari bertanya ke server STUN.
services:
  antimatter:
    environment:
      AM_CALLS_ICE_HOST_OVERRIDE: 203.0.113.10
      AM_CALLS_ICE_SERVERS_CONFIGS: "[]"

Untuk mempertahankan STUN tanpa pihak ketiga, jalankan server STUN Anda sendiri (server TURN seperti coturn juga menjawab permintaan STUN) dan cantumkan di Konfigurasi Server ICE sebagai gantinya, seperti pada contoh TURN di bawah.

Hanya di jaringan lokal, gunakan alamat LAN server. Mulai ulang server setelah mengubah port, alamat, atau pengaturan ICE, atau nonaktifkan dan aktifkan ulang aplikasi Calls: server media diatur saat aplikasi dimulai.

TURN, untuk firewall yang ketat

Beberapa jaringan memblokir UDP dan koneksi keluar ke port TCP yang tidak umum. Pengguna di jaringan tersebut memerlukan server TURN, yang meneruskan media melalui port yang dapat mereka jangkau (sering kali 443). Antimatter tidak menyertakan server TURN; jalankan server TURN seperti coturn dan tambahkan ke ICE Servers Configurations, sebuah daftar JSON:

[
  {"urls": ["stun:turn.example.com:3478"]},
  {"urls": ["turn:turn.example.com:3478?transport=udp", "turns:turn.example.com:443?transport=tcp"]}
]
  • Dengan rahasia bersama (coturn's use-auth-secret), masukkan rahasia yang sama ke TURN Static Auth Secret (AM_CALLS_TURN_STATIC_AUTH_SECRET): server memberikan kredensial berumur pendek untuk setiap klien, berlaku selama TURN Credentials Expiration (minutes) (240 menit secara bawaan).
  • Dengan kredensial tetap, tambahkan "username" dan "credential" ke entri TURN sebagai gantinya.
  • Server Side TURN (nonaktif secara default) juga menggunakan server TURN untuk koneksi yang dimulai oleh server.

Server yang lebih besar: rtcd eksternal

Secara bawaan, satu server Antimatter menampung semua media panggilan. Untuk banyak panggilan serentak, atau untuk memisahkan media dari server obrolan, aplikasi Panggilan dapat menyerahkan media ke rtcd, server media terpisah (rtcd open-source dari Mattermost, versi 0.17 atau lebih baru). Atur RTCD service URL (AM_CALLS_RTCD_SERVICE_URL), misalnya https://rtcd.example.com: semua panggilan kemudian akan melewati server tersebut, dan klien akan mengirim media mereka ke port rtcd sendiri, bukan ke port Antimatter. Kredensial dapat diberikan dengan AM_CALLS_RTCD_CLIENT_ID dan AM_CALLS_RTCD_AUTH_KEY; tanpa kredensial, aplikasi akan mendaftarkan dirinya ke rtcd. Tidak diperlukan lisensi. Aplikasi Panggilan menampilkan peringatan kepada admin yang merekomendasikan penggunaan rtcd ketika server sering memiliki lebih dari 50 orang dalam panggilan secara bersamaan.

Transkripsi dan teks langsung

Antimatter dapat mentranskripsikan panggilan dengan model speech-to-text yang Anda jalankan sendiri, dan menampilkan teks langsung (live captions) saat orang berbicara. Antimatter menggunakan server apa pun yang menyediakan endpoint /v1/audio/transcriptions yang kompatibel dengan OpenAI, seperti server Whisper di jaringan Anda. Tidak diperlukan layanan tambahan dari Antimatter.

Cara kerjanya

  • Tuan rumah panggilan memulai transkripsi dengan Transkripsikan panggilan di kontrol panggilan. Lencana Mentranskripsikan memberi tahu semua orang.
  • Aplikasi setiap peserta mendengarkan mikrofonnya sendiri, memotong ucapan menjadi potongan-potongan pendek (maksimal 12 detik, dan tidak pernah saat dibisukan), lalu mengirimkannya ke Antimatter, yang meneruskannya ke server speech-to-text Anda.
  • Dengan teks langsung (live captions) diaktifkan, teks dari setiap potongan ditampilkan kepada peserta sebagai caption segera.
  • Saat transkripsi berhenti atau panggilan berakhir, bot Panggilan memposting transkripsi sebagai file teks dan file subtitle WebVTT, di utas panggilan (di kanal suara, di dalam kanal).
  • Dengan Ringkasan transkripsi diaktifkan, agen bawaan dari aplikasi Agen juga memposting ringkasan di utas (lihat AI).

Cara mengaturnya

Atur ini di layanan antimatter:

services:
  antimatter:
    environment:
      AM_CALLS_ENABLE_TRANSCRIPTIONS: "true"
      AM_CALLS_TRANSCRIBE_API: openai
      AM_CALLS_TRANSCRIBE_API_OPEN_AIURL: http://stt.internal:8000/v1
      AM_CALLS_TRANSCRIBE_API_OPEN_AI_MODEL: whisper-1
      AM_CALLS_TRANSCRIBE_API_OPEN_AI_KEY: ""
      AM_CALLS_ENABLE_LIVE_CAPTIONS: "true"
      AM_CALLS_LIVE_CAPTIONS_LANGUAGE: en

Di Konsol Sistem, pengaturan transkripsi hanya muncul setelah Aktifkan rekaman panggilan diaktifkan, padahal jenis transkripsi ini tidak memerlukan rekaman. Menyetelnya dengan variabel di atas menghindari hal tersebut. Jangan aktifkan rekaman bersamaan dengan transkripsi openai: memulai rekaman akan mencoba memulai transkripsi job-service dan gagal.

Audio dari semua orang yang berbicara saat transkripsi aktif dikirim ke server speech-to-text yang Anda konfigurasikan, dan transkripsi diposting di tempat yang bisa dibaca oleh semua orang di kanal. Informasikan kepada pengguna Anda, dan simpan server tersebut di jaringan Anda sendiri jika panggilan bersifat rahasia.

Rekaman

Rekaman panggilan (dan transkripsi dengan transkripsi bawaan whisper.cpp atau Azure) dijalankan di kontainer terpisah yang dimulai oleh layanan tugas, calls-offloader open-source dari Mattermost, yang Anda deploy sendiri di samping Antimatter. Pengaturannya adalah Aktifkan rekaman panggilan (AM_CALLS_ENABLE_RECORDINGS, nonaktif secara default), URL layanan tugas (AM_CALLS_JOB_SERVICE_URL), Durasi maksimum rekaman panggilan (60 menit secara default, 15 hingga 180) dan Kualitas rekaman panggilan (rendah, sedang, atau tinggi; sedang secara default). Tidak diperlukan lisensi. Untuk transkripsi dan teks langsung saja, pengaturan speech-to-text di atas lebih sederhana: tidak memerlukan layanan tugas.
