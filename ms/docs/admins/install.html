Memasang Antimatter

Pasang Antimatter dengan fail compose yang sedia ada, pilih imej yang betul, atau jalankan pelayan daripada arkib keluaran. Kemudian, cipta akaun pentadbir pertama.

Pasang dengan Docker Compose

Ini adalah cara yang disyorkan. Satu fail compose menjalankan Antimatter, PostgreSQL, storan fail dan perkhidmatan GIF. Anda memerlukan pelayan Linux dengan Docker Engine dan plugin Compose-nya (docker compose), 2 teras CPU dan 4 GB memori atau lebih.

1. Muat turun fail compose

mkdir antimatter && cd antimatter
curl -fsSLO https://antimatter.chat/compose.yaml

2. Cipta fail .env

Fail compose membaca tetapan daripada fail .env dalam direktori yang sama. Ciptakannya dengan rahsia rawak:

cat > .env <<EOF
SITE_URL=http://localhost:8065
POSTGRES_PASSWORD=$(openssl rand -hex 24)
S3_SECRET_KEY=$(openssl rand -hex 24)
GIFS_API_KEY=$(openssl rand -hex 24)
EOF
chmod 600 .env

Tetapkan SITE_URL kepada alamat yang akan diketik pengguna dalam pelayar mereka, contohnya http://192.168.1.20:8065 dalam rangkaian tempatan atau https://chat.example.com dengan nama domain. Simpan fail .env: pangkalan data dan storan menggunakan kata laluan ini daripada permulaan pertama, dan anda memerlukan fail yang sama untuk memulihkan sandaran.

3. Mulakannya

docker compose up -d
docker compose ps

Permulaan pertama mengambil masa satu atau dua minit: PostgreSQL mencipta pangkalan data, perkhidmatan bucket sekali sahaja mencipta baldah storan, perkhidmatan gifs-stickers sekali sahaja mengimport pakej stiker permulaan, dan Antimatter mencipta jadualnya. Ikuti dengan docker compose logs -f antimatter.

Untuk menggunakan nama domain dan HTTPS dari permulaan, lihat Domain dan HTTPS: dengan fail compose, ia hanya dua baris lagi dalam .env dan profil https.

PostgreSQL, penyimpanan dan perkhidmatan GIF berada pada rangkaian dalaman (private) tanpa akses Internet, yang hanya disertai oleh Antimatter. Tiada satu pun daripada mereka menerbitkan port.

Kontena Antimatter tidak menyimpan apa-apa pada cakera: tetapanannya berada dalam pangkalan data (AM_CONFIG menunjuk ke sana) dan fail serta aplikasinya berada dalam perkhidmatan penyimpanan. Anda boleh memadam dan mencipta semula kontena pada bila-bila masa. Semua yang perlu disalai berada dalam volume postgres, files dan gifs, serta .env anda.

Pilih imej

Dua imej Antimatter diterbitkan, kedua-duanya untuk linux/amd64 dan linux/arm64, dan kedua-duanya dibina dari cawangan main setiap repositori:

ImejAplikasi terpalitTag
ghcr.io/antimatterchat/antimatterEjen, Panggilan, GitHub, GitLab, Jira, Kanban, Metrik dan Buku Taktik.latest, X.Y.Z untuk pelepasan, sha-<commit>
ghcr.io/antimatterchat/antimatter-nextSama seperti di atas, ditambah Saluran Suara, Undian, Mel, Kalendar, Nota, Papan Putih, GIF, Senarai tugasan dan Meme. Dibina semula setiap malam.latest, nightly, nightly-<YYYYMMDD>, sha-<commit>

Fail compose laman web menggunakan antimatter-next, kerana perkhidmatan GIF dan kebanyakan aplikasi yang diterangkan pada laman web ini hanya terdapat dalam imej tersebut. Untuk mengubah imej, tetapkan ANTIMATTER_IMAGE dalam .env dan jalankan docker compose up -d.

latest berubah di bawah anda. Dalam pengeluaran, semat tag seperti nightly-20261015 atau sha-<commit>, dan ubah dengan sengaja apabila anda menaik taraf. Pelayan menaik taraf pangkalan datanya apabila ia bermula, jadi anda tidak boleh kembali ke imej yang lebih lama, atau dari antimatter-next ke antimatter, tanpa memulihkan salai yang diambil sebelum itu. Lihat Salai dan peningkatan.

Di dalam imej

  • Pelayan berada di /antimatter, dengan binari antimatter dan amctl di /antimatter/bin (pada PATH).
  • Ia berjalan sebagai pengguna tidak berkeistimewaan antimatter (uid 2000) pada asas distroless minimum, tanpa shell.
  • Port: 8065 (web dan API), 8067 (metrik), 8074 (kluster), 8443 UDP dan TCP (panggilan).
  • Mod lokal (ServiceSettings.EnableLocalMode) dihidupkan, jadi amctl --local berfungsi di dalam kontena. Semakan kesihatan menjalankan amctl system status --local.
  • Aplikasi terpalit berada di /antimatter/prepackaged_plugins, ditandatangani dengan kunci penandatanganan aplikasi Antimatter.
  • Alat pengekstrakan teks (pdftotext, wvText, unrtf, tidy) disertakan, jadi kandungan dokumen yang dimuat naik boleh dicari.

Fail compose lain

Repositori antimatter-docker mempunyai persediaan pengeluaran di deploy/compose/: nginx dengan sijil anda sendiri atau Let's Encrypt (certbot), PostgreSQL, perkhidmatan GIF pilihan (profil gifs) dan isipadu bernama untuk konfigurasi, data dan log pelayan, yang didokumentasikan dalam README-nya. Ia menggunakan imej stabil secara lalai dan menyimpan fail pada isipadu tempatan berbanding storan S3. Guna ini jika anda lebih suka nginx berbanding Caddy, atau sudah mempunyai sijil.

Cipta pentadbir pertama

Buka SITE_URL dalam pelayar anda dan cipta akaun. Akaun pertama yang dicipta pada pelayan baharu menjadi pentadbir sistem, dan persediaan kemudian membimbing anda melalui penciptaan komuniti pertama anda (nama Antimatter untuk pasukan atau ruang kerja).

Lakukannya segera selepas permulaan pertama: sehingga ketika itu, sesiapa sahaja yang mencapai pelayan terlebih dahulu akan menjadi pentadbirnya. Untuk mencipta akaun dari baris arahan sebaliknya, sebelum pelayan boleh dicapai dari luar:

docker compose exec antimatter amctl --local user create --system-admin --email-verified \
    --email admin@example.com --username admin --password 'a-long-password'
docker compose exec antimatter amctl --local team create --name main --display-name "Main"
docker compose exec antimatter amctl --local team users add main admin

Kemudian log masuk di SITE_URL. Mula arahan dengan ruang untuk mengekalkan kata laluan keluar dari sejarah shell anda (dengan HISTCONTROL=ignorespace), atau ubah kata laluan setelah log masuk.

Langkah seterusnya setelah anda masuk:

  1. Tentukan siapa yang boleh mencipta akaun: Log masuk dan akaun.
  2. Konfigurasikan e-mel, supaya jemputan dan tetapan semula kata laluan berfungsi: E-mel dan pemberitahuan push.
  3. Buka port panggilan dalam tembok api anda: Panggilan dan suara.
  4. Semak aplikasi mana yang dihidupkan: Aplikasi terpalit.

Pasang dari arkib keluaran

Tanpa Docker, pelayan dijalankan daripada arkib bernama antimatter-<os>-<arch>.tar.gz (contohnya antimatter-linux-amd64.tar.gz). Ia mengandungi satu direktori antimatter/ dengan bin/antimatter, bin/amctl, config/config.json, aplikasi web (client/ dan client-fusion/), templat e-mel, dan terjemahan.

1. Sediakan PostgreSQL

Antimatter hanya menyokong PostgreSQL, versi 15 atau lebih baharu (versi yang lebih lama akan bermula, dengan ralat dalam log). Cipta pengguna dan pangkalan data:

sudo -u postgres psql <<'EOF'
CREATE USER antimatter WITH PASSWORD 'a-long-password';
CREATE DATABASE antimatter OWNER antimatter;
EOF

2. Buka dan konfigurasi

sudo tar -xzf antimatter-linux-amd64.tar.gz -C /opt
sudo useradd --system --user-group antimatter
sudo mkdir -p /opt/antimatter/data
sudo chown -R antimatter:antimatter /opt/antimatter

Tunjuk pelayan ke pangkalan data, sama ada dalam /opt/antimatter/config/config.json (SqlSettings.DataSource) atau dengan pemboleh ubah persekitaran, dan tetapkan URL laman web:

AM_SQLSETTINGS_DRIVERNAME=postgres
AM_SQLSETTINGS_DATASOURCE=postgres://antimatter:a-long-password@localhost:5432/antimatter?sslmode=disable&connect_timeout=10
AM_SERVICESETTINGS_SITEURL=https://chat.example.com

config.json arkib ialah konfigurasi lalai yang lengkap: tetapan yang anda ubah dalam Konsol Sistem disimpan semula ke dalamnya. Untuk mengekalkan konfigurasi dalam pangkalan data sebaliknya, lihat Konfigurasi.

3. Jalankan sebagai perkhidmatan

Unit systemd, dalam /etc/systemd/system/antimatter.service:

[Unit]
Description=Antimatter
After=network.target postgresql.service

[Service]
Type=notify
User=antimatter
Group=antimatter
WorkingDirectory=/opt/antimatter
ExecStart=/opt/antimatter/bin/antimatter
EnvironmentFile=-/etc/antimatter.env
TimeoutStartSec=3600
Restart=always
RestartSec=10
LimitNOFILE=49152

[Install]
WantedBy=multi-user.target

Letakkan pemboleh ubah AM_ anda dalam /etc/antimatter.env (boleh dibaca oleh root sahaja), kemudian:

sudo systemctl daemon-reload
sudo systemctl enable --now antimatter
journalctl -u antimatter -f

Pelayan mendengar pada port 8065. Buka http://<server>:8065, atau domain anda setelah proksi songsang dipasang (lihat Domain dan HTTPS), dan cipta akaun pertama: ia menjadi pentadbir sistem.

bin/amctl mengurus pelayan yang sedang berjalan dari baris arahan. Pada pelayan itu sendiri, ia berfungsi tanpa log masuk melalui mod tempatan: tetapkan AM_SERVICESETTINGS_ENABLELOCALMODE=true, kemudian jalankan sudo -u antimatter /opt/antimatter/bin/amctl --local system status.

Arahan pelayan lain

Selain menjalankan pelayan (antimatter, atau antimatter server), binari ini mempunyai beberapa arahan penyelenggaraan. Ia membaca konfigurasi yang sama seperti pelayan.

ArahanFungsinya
antimatter versionMencetak versi, nombor binaan, tarikh binaan dan hash binaan.
antimatter db pingMengecek bahawa pangkalan data boleh dicapai.
antimatter db initMencipta konfigurasi dalam pangkalan data (dengan AM_CONFIG ditetapkan ke URL postgres://).
antimatter db migrateMenerapkan migrasi pangkalan data tanpa memulakan pelayan.
antimatter db versionMencetak migrasi terakhir yang diterapkan pada pangkalan data.
antimatter import bulk, antimatter export bulkMengimport atau mengekspor data dalam format pukal (lihat Sandaran dan naik taraf).
