Sandaran dan peningkatan

Apa yang perlu disandar, cara memulihkannya pada hos baharu, cara meningkatkan, dan cara mengalihkan pelayan Mattermost atau komuniti tunggal ke Antimatter.

Apa yang perlu disandar

Pangkalan data dan fail adalah saling berkait: sandarkan pada masa yang sama, dan simpan salinan di luar pelayan. Nama volum bermula dengan nama projek compose, antimatter (docker volume ls menyenaraikannya).

Sandar

Dari direktori compose.yaml. Menghentikan Antimatter terlebih dahulu memberikan salinan yang konsisten sepenuhnya; sandaran yang diambil semasa ia berjalan biasanya tidak menjadi masalah, tetapi fail yang dimuat naik semasa sandaran mungkin tidak ada di dalamnya.

stamp=$(date +%Y%m%d-%H%M%S)
mkdir -p backups
docker compose stop antimatter
# Database
docker compose exec -T postgres pg_dump -U antimatter -d antimatter -Fc \
    > "backups/antimatter-db-$stamp.dump"
# File storage and GIF service
for v in files gifs; do
    docker run --rm -v "antimatter_$v:/data:ro" -v "$PWD/backups:/backup" \
        alpine tar -czf "/backup/antimatter-$v-$stamp.tar.gz" -C /data .
done
docker compose start antimatter
# Secrets
cp .env "backups/env-$stamp"

Jalankan dari cron untuk sandaran harian, dan salin direktori backups/ ke mesin lain. Simpan salinan .env seaman pelayan: ia menyimpan kata lalunya.

Untuk menyalin fail yang dimuat naik objek demi objek (contohnya ke stor S3 lain), gunakan alat baris arahan AWS perkhidmatan bucket:

docker compose run --rm -v "$PWD/backups/files:/backup" bucket \
    "aws --endpoint-url http://files:9000 s3 sync s3://antimatter /backup"

Dengan arkib keluaran, sandar pangkalan data dengan pg_dump -Fc, dan direktori data/ dan config/ dengan alat biasa anda.

Pulihkan pada hos baharu

Letakkan compose.yaml, .env yang disimpan dan sandaran dalam direktori baharu, kemudian:

stamp=20261016-030000          # the backup to restore
docker compose create           # creates the volumes, starts nothing
docker compose up -d postgres
docker compose exec -T postgres pg_restore -U antimatter -d antimatter --no-owner \
    < "backups/antimatter-db-$stamp.dump"
for v in files gifs; do
    docker run --rm -v "antimatter_$v:/data" -v "$PWD/backups:/backup" \
        alpine tar -xzf "/backup/antimatter-$v-$stamp.tar.gz" -C /data
done
docker compose up -d

Gunakan .env yang sama: stor dan pangkalan data mesti mengekalkan kata lalunya. Jika hos baharu mempunyai alamat lain, kemas kini SITE_URL (dan DOMAIN).

Uji sandaran anda dengan memulihkannya pada mesin lain dari semasa ke semasa.

Tingkatkan

  1. Ambil sandaran.
  2. Tukar tag imej dalam .env (ANTIMATTER_IMAGE), jika anda menetapkan satu, seperti yang disyorkan.
  3. Tarik dan mulakan semula: 
    docker compose pull
docker compose up -d
docker compose logs -f antimatter

Semasa mula, pelayan akan menaik taraf skema pangkalan data (pantau log; pelayan besar boleh mengambil beberapa minit) dan memasang versi baharu aplikasi terikat daripada imej. Dengan arkib pelepasan: hentikan pelayan, gantikan semua kandungan kecuali config/, data/, logs/, plugins/ dan client/plugins/ dengan kandungan arkib baharu, kemudian mulakannya semula.

Naik taraf hanya boleh ke hadapan. Sekali pelayan baharu telah menaik taraf pangkalan data, versi lama tidak dapat memakainya: untuk kembali, pulihkan sandaran yang diambil sebelum naik taraf. Perkara yang sama terpakai untuk berpindah daripada antimatter-next kembali ke antimatter.

Versi

Pelayan Antimatter melaporkan versi baris Mattermost yang menjadi asasnya (semasa 12.0.0). Imej dibina semula daripada cawangan main: antimatter-next setiap malam (tag nightly-<YYYYMMDD>), dan kedua-dua imej pada setiap perubahan (tag sha-<commit>). Tetapkan salah satu tag ini, naik taraf dengan sengaja, dan rekodkan tag sebelumnya supaya anda tahu sandaran mana yang sepadan dengannya.

Versi utama PostgreSQL

Fail compose menggunakan postgres:17-alpine. Antimatter memerlukan PostgreSQL 15 atau baharu. Versi utama baharu PostgreSQL tidak dapat membaca direktori data versi sebelumnya: untuk berpindah ke versi baharu, keluarkan (dump) pangkalan data, mulakan versi baharu pada isipadu (volume) baharu dan pulihkan dump ke dalamnya.

Berpindah daripada Mattermost

Antimatter menggunakan skema pangkalan data Mattermost dan menambah jadualnya sendiri, jadi ia boleh mengambil alih pangkalan data PostgreSQL dan fail pelayan Mattermost. Cuba pada salinan dahulu:

  1. Sandarkan pangkalan data Mattermost, storan failnya (data/ atau baldah S3) dan config.json, kemudian hentikan Mattermost.
  2. Pulihkan pangkalan data ke PostgreSQL Antimatter, atau arahkan Antimatter ke salinannya (AM_SQLSETTINGS_DATASOURCE).
  3. Salin fail ke storan Antimatter, kekalkan laluan mereka: ke baldah antimatter dengan alat S3, atau ke data/ dengan arkib pelepasan.
  4. Guna semula tetapan anda: salin config.json, atau pindahkan ke pangkalan data dengan amctl --local config migrate (lihat Konfigurasi). Pemboleh ubah persekitaran MM_ anda terus berfungsi; namakan semula kepada AM_ bila sesuai.
  5. Mula Antimatter dan ikuti log semasa ia mengemas kini pangkalan data. Kemudian semak Konsol Sistem › Plugin › Pengurusan Plagin. Antimatter memasang binaannya sendiri untuk Panggilan, Buku Taktik, Kanban (Papan), Ejen dan integrasi apabila versi tersebut lebih baharu daripada versi yang dipasang. Jika Mattermost mempunyai versi yang lebih baharu untuk mana-mana aplikasi tersebut, buang aplikasi itu dan mulakan semula Antimatter supaya binaannya sendiri dipasang.
  6. Set up push notifications again, with your own push proxy: Antimatter tidak pernah menghantar pemberitahuan ke perkhidmatan dorong Mattermost, sama ada ujian atau dihoskan, kerana perkhidmatan tersebut hanya menghantar kepada aplikasi Mattermost sendiri. Sehingga anda mengubah Pelayan Pemberitahuan Dorong, pelayan tidak menghantar sebarang pemberitahuan dorong (lihat Pemberitahuan dorong).

Antimatter tidak menghubungi sebarang perkhidmatan yang dikendalikan oleh Mattermost, Inc. (lihat Sambungan ke perkhidmatan luar), walaupun konfigurasi anda masih menamakannya:

  • pelayan notifikasi push di Mattermost dikekalkan dalam tetapan tetapi tidak pernah digunakan;
  • Alamat Mattermost untuk pasaran aplikasi (URL Pasaran) dan untuk notis produk dikosongkan;
  • aplikasi Panggilan menggunakan pelayan STUN awam Cloudflare sebagai ganti pelayan Mattermost, tanpa mengubah tetapan yang disimpan (lihat Panggilan);
  • semakan kemas kini keselamatan dan pelaporan kemalangan telah dibuang, dan begitu juga tetapan Konsol Sistem (Benarkan Amaran Keselamatan, Benarkan Diagnostik dan Pelaporan Ralat) serta halaman Notis.

Soket mod tempatan kini ialah /var/tmp/antimatter_local.socket; amctl juga mencuba /var/tmp/mattermost_local.socket yang lama. Mattermost hanya menyokong PostgreSQL dalam versinya yang terkini, dan begitu juga Antimatter: pindahkan pangkalan data MySQL ke PostgreSQL terlebih dahulu. Kembali ke Mattermost selepas Antimatter menaik taraf pangkalan data bermaksud memulihkan sandaran Mattermost anda.

Eksport dan import data

Format eksport pukal memindahkan data antara pelayan: keseluruhan pelayan, beberapa komuniti, atau beberapa saluran, dengan lampiran, gambar profil dan emoji tersuai jika anda menginginkannya.

# on the source server
amctl export create --team-name design --include-profile-pictures
amctl export list
amctl export download <export file> design.zip
# on the destination server
amctl import upload design.zip
amctl import list available
amctl import process <uploaded file> --imported-users active

Pantau kerja dengan amctl export job list dan amctl import job list. Untuk eksport komuniti atau saluran, --imported-users adalah wajib: active apabila orang berpindah ke pelayan ini, inactive apabila mengimport ke pelayan di mana mereka sudah mempunyai akaun, supaya akaun yang dibuat daripada padanan yang tidak pasti kekal tidak aktif sehingga seorang pentadbir menyemaknya. --destination-team-name mengimport ke komuniti sedia ada. Eksport dan import disimpan pada storan pelayan (ExportSettings.Directory, ImportSettings.Directory) selama 30 hari secara lalai.

Pada pelayan itu sendiri, antimatter export bulk dan antimatter import bulk --apply melakukan perkara yang sama daripada fail, tanpa API.
