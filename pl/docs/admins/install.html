Instalowanie Antimatter

Zainstaluj Antimatter za pomocą gotowego pliku compose, wybierz odpowiedni obraz lub uruchom serwer z archiwum wydania. Następnie utwórz konto pierwszego administratora.

Instalacja za pomocą Docker Compose

To zalecana metoda. Jeden plik compose uruchamia Antimatter, PostgreSQL, magazyn plików i usługę GIF. Wymagany jest serwer Linux z Docker Engine i jego wtyczką Compose (docker compose), 2 rdzenie CPU oraz 4 GB pamięci RAM lub więcej.

1. Pobierz plik compose

mkdir antimatter && cd antimatter
curl -fsSLO https://antimatter.chat/compose.yaml

2. Utwórz plik .env

Plik compose odczytuje swoje ustawienia z pliku .env w tym samym katalogu. Utwórz go z losowymi hasłami:

cat > .env <<EOF
SITE_URL=http://localhost:8065
POSTGRES_PASSWORD=$(openssl rand -hex 24)
S3_SECRET_KEY=$(openssl rand -hex 24)
GIFS_API_KEY=$(openssl rand -hex 24)
EOF
chmod 600 .env

Ustaw SITE_URL na adres, który użytkownicy będą wpisywać w przeglądarce, na przykład http://192.168.1.20:8065 w sieci lokalnej lub https://chat.example.com z domeną. Zachowaj plik .env: baza danych i magazyn plików używają tych haseł od pierwszego uruchomienia, a tego samego pliku potrzebujesz do przywracania kopii zapasowej.

3. Uruchom

docker compose up -d
docker compose ps

Pierwsze uruchomienie trwa minutę lub dwie: PostgreSQL tworzy bazę danych, jednorazowa usługa bucket tworzy bucket magazynu, jednorazowa usługa gifs-stickers importuje pakiet startowy naklejek, a Antimatter tworzy swoje tabele. Obserwuj postęp za pomocą docker compose logs -f antimatter.

Aby od początku używać nazwy domeny i HTTPS, zobacz Domena i HTTPS: w przypadku pliku compose to dwie dodatkowe linie w .env i profil https.

PostgreSQL, magazynowanie i usługa GIF-ów znajdują się na wewnętrznej sieci (private) bez dostępu do Internetu, do której dołącza tylko Antimatter. Żadna z tych usług nie publikuje portu.

Kontener Antimatter nie przechowuje niczego na dysku: jego ustawienia znajdują się w bazie danych (AM_CONFIG wskazuje na nią), a pliki i aplikacje w usłudze magazynowania. Możesz usunąć i odtworzyć kontener w dowolnym momencie. Wszystko, co należy zapisać w kopii zapasowej, znajduje się w wolumenach postgres, files i gifs, oraz w pliku .env.

Wybierz obraz

Opublikowano dwa obrazy Antimatter, oba dla linux/amd64 i linux/arm64, a oba zbudowane z gałęzi main każdego repozytorium:

ObrazAplikacje wbudowaneTagi
ghcr.io/antimatterchat/antimatterAgenci, Rozmowy, GitHub, GitLab, Jira, Kanban, Metryki i Playbooki.latest, X.Y.Z dla wydań, sha-<commit>
ghcr.io/antimatterchat/antimatter-nextTo samo, plus Kanały głosowe, Ankiety, Poczta, Kalendarz, Notatki, Biała tablica, GIF-y, Do zrobienia i Memy. Przetwarzane co noc.latest, nightly, nightly-<YYYYMMDD>, sha-<commit>

Plik compose witryny używa antimatter-next, ponieważ usługa GIF-ów i większość aplikacji opisanych na tej witrynie znajduje się tylko w tym obrazie. Aby zmienić obraz, ustaw ANTIMATTER_IMAGE w .env i uruchom docker compose up -d.

latest zmienia się pod Tobą. W środowisku produkcyjnym przypnij tag, np. nightly-20261015 lub sha-<commit>, i zmieniaj go świadomie podczas aktualizacji. Serwer aktualizuje swoją bazę danych przy starcie, więc nie można wrócić do starszego obrazu ani przejść z antimatter-next na antimatter bez przywrócenia kopii zapasowej wykonanej wcześniej. Zobacz Kopie zapasowe i aktualizacje.

Wewnątrz obrazu

  • Serwer znajduje się w /antimatter, z binariami antimatter i amctl w /antimatter/bin (na PATH).
  • Uruchamia się jako użytkownik nieuprzywilejowany antimatter (uid 2000) na minimalnej bazie distroless, bez powłoki.
  • Porty: 8065 (web i API), 8067 (metryki), 8074 (klaster), 8443 UDP i TCP (rozmowy).
  • Tryb lokalny (ServiceSettings.EnableLocalMode) jest włączony, więc amctl --local działa wewnątrz kontenera. Test stanu uruchamia amctl system status --local.
  • Dołączone aplikacje znajdują się w /antimatter/prepackaged_plugins i są podpisane kluczem podpisywania aplikacji Antimatter.
  • Dołączone są narzędzia do ekstrakcji tekstu (pdftotext, wvText, unrtf, tidy), dzięki czemu można przeszukiwać zawartość przesłanych dokumentów.

Inne pliki compose

Repozytorium antimatter-docker zawiera konfigurację produkcyjną w deploy/compose/: nginx z własnymi certyfikatami lub Let's Encrypt (certbot), PostgreSQL, opcjonalną usługę GIF (profil gifs) oraz nazwane wolumeny dla konfiguracji, danych i logów serwera, opisane w jego README. Domyślnie używa stabilnego obrazu i przechowuje pliki na lokalnym wolumenie zamiast w magazynie S3. Wykorzystaj ją, jeśli wolisz nginx do Caddy lub już posiadasz certyfikaty.

Utwórz pierwszego administratora

Otwórz SITE_URL w przeglądarce i utwórz konto. Pierwsze konto utworzone na nowym serwerze staje się administratorem systemu, a następnie konfiguracja poprowadzi Cię przez proces tworzenia pierwszej społeczności (nazwa Antimatter na zespół lub przestrzeń roboczą).

Zrób to zaraz po pierwszym uruchomieniu: do tego czasu każdy, kto jako pierwszy dotrze do serwera, stanie się jego administratorem. Aby utworzyć konto z wiersza polecenia, zanim serwer będzie dostępny z zewnątrz:

docker compose exec antimatter amctl --local user create --system-admin --email-verified \
    --email admin@example.com --username admin --password 'a-long-password'
docker compose exec antimatter amctl --local team create --name main --display-name "Main"
docker compose exec antimatter amctl --local team users add main admin

Następnie zaloguj się na SITE_URL. Zacznij polecenie od spacji, aby hasło nie trafiło do historii powłoki (przy HISTCONTROL=ignorespace), lub zmień hasło po zalogowaniu.

Następne kroki po zalogowaniu:

  1. Określ, kto może tworzyć konta: Logowanie i konta.
  2. Skonfiguruj e-mail, aby zaproszenia i resetowanie hasła działały: E-mail i powiadomienia push.
  3. Otwórz port rozmów w zaporze sieciowej: Rozmowy i głos.
  4. Sprawdź, które aplikacje są włączone: Dołączone aplikacje.

Instalacja z archiwum wydania

Bez Docker serwer działa z archiwum o nazwie antimatter-<os>-<arch>.tar.gz (na przykład antimatter-linux-amd64.tar.gz). Zawiera ono pojedynczy katalog antimatter/ z plikami bin/antimatter, bin/amctl, config/config.json, aplikacjami webowymi (client/ i client-fusion/), szablonami e-mail oraz tłumaczeniami.

1. Przygotuj PostgreSQL

Antimatter obsługuje wyłącznie PostgreSQL w wersji 15 lub nowszej (starsze wersje uruchamiają się, ale z błędem w logu). Utwórz użytkownika i bazę danych:

sudo -u postgres psql <<'EOF'
CREATE USER antimatter WITH PASSWORD 'a-long-password';
CREATE DATABASE antimatter OWNER antimatter;
EOF

2. Rozpakuj i skonfiguruj

sudo tar -xzf antimatter-linux-amd64.tar.gz -C /opt
sudo useradd --system --user-group antimatter
sudo mkdir -p /opt/antimatter/data
sudo chown -R antimatter:antimatter /opt/antimatter

Wskaż serwerowi bazę danych, w pliku /opt/antimatter/config/config.json (SqlSettings.DataSource) lub za pomocą zmiennych środowiskowych, oraz ustaw adres URL witryny:

AM_SQLSETTINGS_DRIVERNAME=postgres
AM_SQLSETTINGS_DATASOURCE=postgres://antimatter:a-long-password@localhost:5432/antimatter?sslmode=disable&connect_timeout=10
AM_SERVICESETTINGS_SITEURL=https://chat.example.com

Plik config.json z archiwum to kompletna domyślna konfiguracja: zmiany wprowadzone w Konsoli systemu są zapisywane z powrotem w tym pliku. Aby przechowywać konfigurację w bazie danych, zobacz Konfiguracja.

3. Uruchom jako usługę

Jednostka systemd, w pliku /etc/systemd/system/antimatter.service:

[Unit]
Description=Antimatter
After=network.target postgresql.service

[Service]
Type=notify
User=antimatter
Group=antimatter
WorkingDirectory=/opt/antimatter
ExecStart=/opt/antimatter/bin/antimatter
EnvironmentFile=-/etc/antimatter.env
TimeoutStartSec=3600
Restart=always
RestartSec=10
LimitNOFILE=49152

[Install]
WantedBy=multi-user.target

Umieść zmienne AM_ w pliku /etc/antimatter.env (czytelnym tylko przez roota), a następnie:

sudo systemctl daemon-reload
sudo systemctl enable --now antimatter
journalctl -u antimatter -f

Serwer nasłuchuje na porcie 8065. Otwórz http://<server>:8065 lub swój domenę, gdy skonfigurujesz proxy odwrotne (zobacz Domena i HTTPS), i utwórz pierwsze konto: stanie się ono administratorem systemu.

Plik bin/amctl zarządza działającym serwerem z wiersza poleceń. Na samym serwerze działa bez logowania w trybie lokalnym: ustaw AM_SERVICESETTINGS_ENABLELOCALMODE=true, a następnie uruchom sudo -u antimatter /opt/antimatter/bin/amctl --local system status.

Inne polecenia serwera

Oprócz uruchamiania serwera (antimatter lub antimatter server), binarny plik ma kilka poleceń konserwacyjnych. Czytają one tę samą konfigurację co serwer.

PolecenieOpis
antimatter versionWyświetla wersję, numer kompilacji, datę kompilacji i hash kompilacji.
antimatter db pingSprawdza, czy baza danych jest dostępna.
antimatter db initTworzy konfigurację w bazie danych (z ustawioną zmienną AM_CONFIG na adres URL postgres://).
antimatter db migrateStosuje migracje bazy danych bez uruchamiania serwera.
antimatter db versionWyświetla ostatnią zastosowaną migrację bazy danych.
antimatter import bulk, antimatter export bulkImportuje lub eksportuje dane w formacie zbiorczym (zobacz Kopie zapasowe i aktualizacje).
