AI

ฟีเจอร์ AI ของ Antimatter ใช้โมเดลที่คุณเลือก: ผู้ให้บริการบนคลาวด์ หรือเซิร์ฟเวอร์บนเครือข่ายของคุณเอง ข้อมูลจะไม่ถูกส่งไปที่ใดจนกว่าคุณจะตั้งค่าโมเดลหน้านี้ครอบคลุมการเชื่อมต่อโมเดล แต่ละฟีเจอร์ ข้อมูลที่ส่ง และวิธีปิดใช้งาน

ฟีเจอร์ AI

ฟีเจอร์กำหนดค่าในประเภทของโมเดลเปิดใช้งานโดยค่าเริ่มต้น
เขียนใหม่ในช่องพิมพ์ข้อความ: ปรับปรุง ย่อ แก้ไข หรือแปลข้อความก่อนส่งAI › ฟีเจอร์ในตัว พร้อมการเชื่อมต่อโมเดลโมเดลแชท (LLM)ไม่
สรุป: การสรุปเนื้อหาในช่องที่ผู้ใช้เลือกAI › ฟีเจอร์ในตัว พร้อมการเชื่อมต่อโมเดลโมเดลแชท (LLM)ไม่
การแปลช่องอัตโนมัติการตั้งค่าไซต์ › การปรับภาษาการเชื่อมต่อโมเดล LibreTranslate หรือ API ที่เข้ากันได้กับ OpenAIไม่
การอ่านออกเสียงอินทิเกรชัน › แปลงข้อความเป็นเสียง พร้อมการเชื่อมต่อโมเดล (ถ้าต้องการ)การแปลงข้อความเป็นเสียง (Text-to-speech) ที่เข้ากันได้กับ OpenAIไม่
เอเจนต์ AI: แชทกับบอท สรุปเธรด สรุปการโทรแอป Agentsบริการโมเดลภาษาขนาดใหญ่ (LLM) ใดก็ได้แอปเปิดใช้งานอยู่ แต่จะไม่ทำอะไรจนกว่าคุณจะเพิ่มบริการ
บันทึกการโทรและคำบรรยายสดแอป Callsการถอดเสียง (Speech-to-text) ที่เข้ากันได้กับ OpenAIไม่

"เข้ากันได้กับ OpenAI" หมายถึงเซิร์ฟเวอร์ที่ให้บริการ HTTP API เดียวกับ OpenAI เซิร์ฟเวอร์โมเดลส่วนใหญ่ที่คุณโฮสต์เองรองรับ (เช่น Ollama, vLLM, เซิร์ฟเวอร์ของ llama.cpp หรือเซิร์ฟเวอร์ Whisper และ text-to-speech) เช่นเดียวกับผู้ให้บริการบนคลาวด์และเกตเวย์หลายราย เช่น LiteLLM หรือ OpenRouter ฟีเจอร์เหล่านี้ไม่จำเป็นต้องมีใบอนุญาต

ฟีเจอร์ในตัว (เขียนใหม่ สรุป แปล และอ่านออกเสียง) ไม่จำเป็นต้องใช้แอป Agents: ฟีเจอร์เหล่านี้ใช้ การเชื่อมต่อโมเดล ที่คุณเพิ่มในคอนโซลระบบ

การเชื่อมต่อโมเดล

การเชื่อมต่อโมเดลคือผู้ให้บริการ AI ที่ Antimatter อาจเรียกใช้: ที่อยู่ กุญแจ และโมเดล คุณเพิ่มเพียงครั้งเดียว จากนั้นเลือกสำหรับแต่ละฟีเจอร์ที่ต้องการใช้งาน มีสองประเภท:

  • การเชื่อมต่อทั้งเซิร์ฟเวอร์ จัดการโดยผู้ดูแลระบบใน คอนโซลระบบ › AI › การเชื่อมต่อโมเดล เฉพาะผู้ดูแลระบบเท่านั้นที่สามารถให้บริการฟีเจอร์ในตัว แอปสามารถใช้ได้เช่นกัน สำหรับผู้ที่ได้รับอนุญาต
  • การเชื่อมต่อของชุมชน ซึ่งผู้ดูแลของชุมชนเพิ่มสำหรับชุมชนของตนเองในการตั้งค่าของชุมชน (ดู ด้านล่าง) แอปใช้สำหรับสมาชิกของชุมชน ไม่สามารถให้บริการฟีเจอร์ในตัวได้

ส่วน AI ในคอนโซลระบบแสดงสำหรับผู้ที่มีสิทธิ์จัดการการเชื่อมต่อทั้งเซิร์ฟเวอร์: ผู้ดูแลระบบโดยค่าเริ่มต้น หน้า การเชื่อมต่อโมเดล แสดงรายการการเชื่อมต่อทั้งเซิร์ฟเวอร์และการเชื่อมต่อของทุกชุมชน

เพิ่มการเชื่อมต่อ

ใน คอนโซลระบบ › AI › การเชื่อมต่อโมเดล คลิก เพิ่มการเชื่อมต่อ จากนั้นกรอกแบบฟอร์ม:

ฟิลด์สิ่งที่ต้องกรอก
ชุดค่าเริ่มต้นกรอกข้อมูลผู้ให้บริการและที่อยู่ของบริการที่รู้จักกันดี: OpenAI, Mistral, Gemini, OpenRouter หรือ Ollama และ LiteLLM บนเซิร์ฟเวอร์เอง เป็นตัวเลือกที่ไม่บังคับ
ชื่oชื่อที่ผู้ดูแลระบบจะเห็นเมื่อเลือกใช้งาน เช่น "Company OpenAI"
ผู้ให้บริการOpenAI-compatible (ผู้ให้บริการส่วนใหญ่, เกตเวย์ และเซิร์ฟเวอร์โมเดลที่คุณรันเอง) หรือ Anthropic บริการคลาวด์ที่มีระบบเข้าสู่ระบบของตัวเอง เช่น AWS Bedrock, Google Vertex AI หรือ Azure with Entra ID จะทำงานผ่าน endpoint ที่เข้ากันได้กับ OpenAI หรือเกตเวย์เช่น LiteLLM
Base URLที่อยู่ของ API จนถึง /v1 เช่น http://ollama:11434/v1 หากเว้นว่างไว้ ระบบจะใช้ค่าเริ่มต้นของผู้ให้บริการ (https://api.openai.com/v1 หรือ https://api.anthropic.com/v1)
API keyคีย์ของผู้ให้บริการ เว้นว่างไว้หาก endpoint ไม่ต้องการคีย์ คีย์จะถูกเก็บอย่างเข้ารหัสและไม่แสดงอีก: ฟอร์มจะแสดงเฉพาะ 4 ตัวอักษรสุดท้าย และให้เลือกรักษาไว้, เปลี่ยน หรือลบออก
หัวเรื่องเพิ่มเติมHeaders ที่ต้องส่งพร้อมกับทุกคำขอ สำหรับเกตเวย์ที่ต้องการข้อมูลเหล่านี้ ค่าของ Headers จะถูกเก็บอย่างเข้ารหัสเหมือนคีย์ และไม่แสดงอีก: หากต้องการเปลี่ยน ให้พิมพ์ค่าทั้งหมดใหม่อีกครั้ง
โมเดลโมเดลที่ใช้สำหรับแต่ละความสามารถเมื่อฟีเจอร์หรือแอปไม่ได้ระบุชื่อ: แชท, Embeddings, การถอดเสียง และ Decisions โหลดโมเดล จะแสดงรายการโมเดลที่ endpoint เสนอให้ เว้นความสามารถว่างไว้หาก endpoint ไม่รองรับ Anthropic connections ใช้ได้เฉพาะแชทเท่านั้น
Decisions APIวิธีการเรียกใช้โมเดลสำหรับ Decisions: OpenAI decisions หรือ SystemOne สำคัญเฉพาะสำหรับแอปที่ต้องการ Decisions
ขีดจำกัดดู ขีดจำกัดและงบประมาณ
ชุมชนการเชื่อมต่อระดับเซิร์ฟเวอร์เท่านั้น ทุกชุมชน: ใช้ได้ในทุกชุมชน รวมถึงข้อความส่วนตัวและข้อความกลุ่ม ในกรณีอื่น ใช้ได้เฉพาะในชุมชนที่คุณเลือก
ใครสามารถใช้ได้ทุกคน ที่สามารถใช้งานได้ หรือเฉพาะทีม (กลุ่มคนภายในชุมชน) และบทบาทที่คุณเลือก (ผู้ดูแลระบบ, ผู้ดูแลชุมชน) รวมถึงแขก อนุญาตให้แขกใช้งาน; หากไม่เลือกนี้ แขกจะไม่สามารถใช้งานได้ แม้จะเลือก ทุกคน แล้วก็ตาม

ทดสอบการเชื่อมต่อ จะตรวจสอบที่อยู่และคีย์: เซิร์ฟเวอร์จะขอโมเดลจาก endpoint หรือส่งข้อความแชท 1 โทเคน ที่อยู่ที่ถูกแก้ไขจะถูกทดสอบด้วยคีย์ที่บันทึกไว้เฉพาะหลังจากคุณบันทึก หรือหากคุณพิมพ์คีย์ใหม่อีกครั้ง คลิก เพิ่มการเชื่อมต่อ เพื่อบันทึก

เซิร์ฟเวอร์จะเป็นผู้ส่งคำขอด้วยตนเอง ดังนั้นจึงต้องสามารถเข้าถึง API ได้: เซิร์ฟเวอร์โมเดลในโปรเจกต์ compose เดียวกัน บนเครือข่ายของคุณ หรือบนอินเทอร์เน็ต คำขอที่ส่งออกจะเคารพตัวแปร HTTP_PROXY และ HTTPS_PROXY

การลบการเชื่อมต่อจะลบบุญญัติ (key) ของมันไปด้วย ฟีเจอร์ที่เคยใช้การเชื่อมต่อนี้จะหยุดใช้ AI จนกว่าคุณจะเลือกการเชื่อมต่ออื่น

ขีดจำกัดและงบประมาณ

แต่ละการเชื่อมต่อมีขีดจำกัด 4 ประเภท ค่าว่างหรือ 0 หมายความว่าไม่มีขีดจำกัด

  • คำขอต่อนาที และ ต่อนักใช้ คำขอต่อนาที แต่ละเซิร์ฟเวอร์จะนับจำนวนคำขอแยกกัน: คลัสเตอร์ที่มี 3 เซิร์ฟเวอร์จะอนุญาตให้ผ่านได้สูงสุด 3 เท่าของอัตรา
  • โทเคนต่อเดือน และ ต่อนักใช้ โทเคนต่อเดือน: งบประมาณโทเคนต่อเดือนปฏิทิน (UTC) ซึ่งนับในฐานข้อมูลสำหรับทั้งคลัสเตอร์ คำขอหลายรายการที่ทำงานพร้อมกันอาจเกินงบประมาณเล็กน้อยได้

ขีดจำกัดต่อนักใช้ยังใช้กับฟีเจอร์เขียนใหม่และสรุปบทสนทนาด้วย: จะนับรวมกับผู้ที่เขียนใหม่ หรือผู้ที่ครอบครองสรุปบทสนทนานั้น

การใช้งาน

รายการแสดงการใช้งานของแต่ละการเชื่อมต่อในเดือนนี้ การใช้งาน เปิดดูรายละเอียด: โทเคนเข้าและออก คำขอ งบประมาณต่อเดือน การใช้งานรายวัน (UTC) และตามประเภทการใช้งาน (เขียนใหม่, สรุปบทสนทนา, การแปลอัตโนมัติ, แปลงข้อความเป็นเสียง, บุคคล ผ่านแอป หรือแอป)

ทุกการเรียกใช้ที่บุคคลหรือแอปทำผ่านการเชื่อมต่อจะบันทึกรายการตรวจสอบ (audit record) ด้วย: ใคร การเชื่อมต่อ ประเภทการใช้งาน โมเดล จำนวนโทเคน และว่าสำเร็จหรือไม่ แต่จะไม่บันทึกเนื้อหาที่พูด ฟีเจอร์ในตัวระบบจะถูกนับเฉพาะในรายการการใช้งานเท่านั้น: การแปลเพียงอย่างเดียวจะสร้างการเรียกใช้ 1 ครั้งต่อข้อความและต่อภาษา

การเชื่อมต่อของชุมชน

ผู้ดูแลชุมชนจะเพิ่มการเชื่อมต่อของชุมชนตนเองในการตั้งค่าของชุมชน ในแท็บ การเชื่อมต่อโมเดล ฟอร์มมีลักษณะเดียวกัน แต่ไม่มี ชุมชน: การเชื่อมต่อของชุมชนจะทำงานเฉพาะในช่องของชุมชนนั้น สำหรับสมาชิกรวมถึงผู้ชมที่สามารถระบุทีมของตนเองเท่านั้น บทบาทที่มีสิทธิ์ จัดการการเชื่อมต่อโมเดล สามารถจัดการได้เช่นกัน โดยค่าเริ่มต้น ผู้ดูแลชุมชนมีสิทธิ์นี้

การเชื่อมต่อของชุมชนไม่สามารถเข้าถึงที่อยู่ส่วนตัวหรือ loopback (เช่น เซิร์ฟเวอร์ Ollama บนเครือข่ายของคุณ) เว้นแต่ คอนโซลระบบ › สภาพแวดล้อม › นักพัฒนา › อนุญาตการเชื่อมต่อภายในที่ไม่น่าเชื่อถือถึง (ServiceSettings.AllowedUntrustedInternalConnections) จะระบุที่อยู่เหล่านั้นไว้ การเชื่อมต่อทั้งเซิร์ฟเวอร์สามารถทำได้

ดู การตั้งค่าชุมชน สำหรับมุมมองของผู้ดูแลชุมชน

กุญแจการเข้ารหัส

คีย์และหัวข้อมากกว่าปกติ (extra headers) ของการเชื่อมต่อโมเดลถูกเข้ารหัสในฐานข้อมูล (AES-256-GCM) ด้วยคีย์เข้ารหัสเพียงตัวเดียว การสำรองข้อมูลฐานข้อมูลเพียงอย่างเดียวจะไม่เปิดเผยคีย์เหล่านี้ เซิร์ฟเวอร์จะค้นหาคีย์ตามลำดับดังนี้:

  1. ตัวแปร AM_AI_ENCRYPTION_KEY: 32 ไบต์สุ่ม ในรูปแบบ base64 สร้างคีย์ด้วย openssl rand -base64 32
  2. ในกรณีที่ไม่ได้กำหนดตัวแปร เซิร์ฟเวอร์จะค้นหาไฟล์ ai-encryption.key ที่รากของไดเรกทอรีข้อมูลของเซิร์ฟเวอร์ (FileSettings.Directory ซึ่งค่าเริ่มต้นคือ ./data/) เซิร์ฟเวอร์จะสร้างไฟล์นี้ขึ้นเองโดยให้สิทธิ์อ่านได้เฉพาะตัวเซิร์ฟเวอร์เท่านั้น เมื่อมีการเชื่อมต่อที่ต้องการใช้คีย์เป็นครั้งแรก แอป การส่งออกข้อมูล และไฟล์อาร์ไคฟ์จะไม่สามารถอ่านไฟล์นี้ได้
หากไม่มีคีย์ คีย์ API ที่บันทึกไว้จะไม่สามารถอ่านได้ และต้องป้อนคีย์ใหม่สำหรับทุกการเชื่อมต่อ ควรสำรองข้อมูลคีย์นี้พร้อมกับฐานข้อมูล (ดู การสำรองข้อมูลและการอัปเกรด) และเก็บคีย์แยกต่างหากจากการสำรองข้อมูลฐานข้อมูล

เมื่อใดควรกำหนดตัวแปร:

  • โดยใช้ไฟล์ compose ของไซต์. compose.yaml จะส่งต่อ AM_AI_ENCRYPTION_KEY จาก .env และจะเก็บไฟล์คีย์ไว้ในโวลุ่ม data เมื่อตัวแปรนี้ว่างเปล่า การกำหนดตัวแปรนี้ถือเป็นวิธีที่ดีกว่า เพราะการสำรองข้อมูล .env จะเก็บคีย์ไว้แยกต่างหากจากฐานข้อมูล เพิ่มคีย์ลงใน .env แล้วรัน docker compose up -d: 
    echo "AM_AI_ENCRYPTION_KEY=$(openssl rand -base64 32)" >> .env
    หากเซิร์ฟเวอร์ได้สร้างไฟล์คีย์ไว้แล้ว ให้ป้อนคีย์ที่อยู่ในไฟล์นั้นลงใน .env แทน เพื่อให้คีย์ที่บันทึกไว้ยังคงอ่านได้: docker compose exec antimatter cat /antimatter/data/ai-encryption.key จะแสดงคีย์นั้น
  • คลัสเตอร์ที่ไฟล์อยู่ใน S3. เซิร์ฟเวอร์ในคลัสเตอร์ไม่แชร์ไดเรกทอรีร่วมกัน ดังนั้นเซิร์ฟเวอร์จึงไม่สร้างไฟล์: กำหนดตัวแปรเดียวกันบนทุกเซิร์ฟเวอร์ จนกว่าจะกำหนดตัวแปรนี้ การเชื่อมต่อจะไม่สามารถบันทึกคีย์ได้
  • เมื่อใช้ไฟล์อาร์ไคฟ์ของเวอร์ชันที่ปล่อยออกมาหรือแพ็กเกจ ไฟล์จะอยู่ใน data/ (สำหรับแพ็กเกจคือ /var/lib/antimatter/data) คุณสามารถเก็บไฟล์ไว้ที่นั่น หรือกำหนดตัวแปรในไฟล์ environment ของคุณ

เพื่อเปลี่ยนคีย์ ให้กำหนดคีย์ใหม่ใน AM_AI_ENCRYPTION_KEY และคีย์เก่าใน AM_AI_ENCRYPTION_PREVIOUS_KEYS (คีย์หลายตัวคั่นด้วยเครื่องหมายจุลภาค): คีย์ที่บันทึกไว้ด้วยคีย์เก่าจะยังคงอ่านได้ คีย์ของการเชื่อมต่อจะถูกรหัสด้วยคีย์ใหม่เมื่อคุณป้อนคีย์นั้นอีกครั้ง เก็บคีย์เก่าไว้ในรายการจนกว่าคีย์ของทุกการเชื่อมต่อจะได้รับการป้อนใหม่

ฟีเจอร์ในตัว

ใน คอนโซลระบบ › AI › ฟีเจอร์ในตัว ให้เลือกการเชื่อมต่อทั้งเซิร์ฟเวอร์และโมเดลสำหรับแต่ละฟีเจอร์ หรือเลือก ปิด ฟีเจอร์ที่ไม่มีเชื่อมต่อจะไม่ได้ใช้ AI โหลดโมเดล จะแสดงรายการโมเดลทั้งหมดของการเชื่อมต่อ โดยค่าเริ่มต้นแต่ละฟีเจอร์จะใช้โมเดลแชทของการเชื่อมต่อ

ฟีเจอร์การตั้งค่าสิ่งอื่นที่จำเป็น
เขียนใหม่ในกล่องข้อความ: เมนู AI ของกล่องข้อความ (ปรับปรุง, ย่อ, แก้ไข, แปล)AISettings.Rewriteไม่มี: เมนูจะแสดงเมื่อมีการเลือกการเชื่อมต่อแล้ว
สรุปบทสนทนา: สรุปของช่องที่ผู้ใช้เลือก โดยทำเมื่อต้องการหรือตามกำหนดเวลาAISettings.Recapsเปิดใช้งาน AI Recaps ใน คอนโซลระบบ › การตั้งค่าไซต์ › สรุปบทสนทนา (เปิดใช้งานโดยค่าเริ่มต้น) ซึ่งยังกำหนดจำนวนสรุปบทสนทนาที่ผู้ใช้สามารถสร้างได้ด้วย
การแปลอัตโนมัติAISettings.AutoTranslationผู้ให้บริการการแปล การเชื่อมต่อโมเดล (แนะนำ) ใน การแปลอัตโนมัติ
แปลงข้อความเป็นเสียงAISettings.TextToSpeechเปิด อ่านข้อความออกเสียง ใน Text-to-speech จุดเชื่อมต่อ /audio/speech ของการเชื่อมต่อจะแทนที่ที่อยู่และคีย์ที่ตั้งไว้ที่นั่น

แต่ละการตั้งค่ามีคีย์ ConnectionId และ Model ตัวอย่างเช่น AISettings.Rewrite.ConnectionId (AM_AISETTINGS_REWRITE_CONNECTIONID) หาก Model ว่างเปล่า จะใช้โมเดลเริ่มต้นของการเชื่อมต่อ

ฟีเจอร์ในตัวจะใช้ขีดจำกัดของการเชื่อมต่อ แต่ไม่ใช่อัปเดต: ทุกคนที่สามารถใช้ฟีเจอร์นั้นได้สามารถใช้การเชื่อมต่อได้ การเชื่อมต่อที่ต้องการความสนใจ หรือที่ถูกลบไปแล้ว จะทำให้ฟีเจอร์ล้มเหลวจนกว่าคุณจะเลือกการเชื่อมต่ออื่น: หน้าเว็บจะแจ้งเรื่องนี้

เอเจนต์ AI

แอป Agents (id mattermost-ai) เปิดใช้งานโดยค่าเริ่มต้น การตั้งค่าประกอบด้วยสองขั้นตอน: เพิ่มบริการ (การเชื่อมต่อกับผู้ให้บริการโมเดล) จากนั้นสร้างเอเจนต์ (บอทที่ใช้บริการนั้น)

เอเจนต์ของแอป Agents ยังคงใช้ AI Services ของแอปเอง ไม่ใช่การเชื่อมต่อโมเดล ฟีเจอร์ในตัวไม่ผ่านแอปอีกต่อไป ในเซิร์ฟเวอร์ที่อัปเกรดเป็น 0.9.0 บริการของแอปยังถูกคัดลอกหนึ่งครั้งไปยังการเชื่อมต่อโมเดลทั้งเซิร์ฟเวอร์ (ดู การอัปเกรดเป็น 0.9.0)

1. เพิ่มบริการ

ไปที่ คอนโซลระบบ › ปลั๊กอิน › เอเจนต์ แล้วภายใต้ AI Services ให้คลิก Add an AI Service จากนั้นเลือก Service type:

  • OpenAI Compatible: สำหรับเซิร์ฟเวอร์โมเดลที่คุณรันด้วยตัวเอง หรือผู้ให้บริการใด ๆ ที่มี API ในรูปแบบ OpenAI กรอกAPI URL (เช่น http://ollama:11434/v1 หรือ http://vllm.internal:8000/v1) และAPI Key เฉพาะเมื่อเซิร์ฟเวอร์ต้องการเท่านั้น หากเซิร์ฟเวอร์รองรับเฉพาะ Chat Completions API ให้ปิดUse Responses API
  • OpenAI, Anthropic, Google Gemini, Google Vertex AI, AWS Bedrock, Azure, Cohere, Mistral: ผู้ให้บริการแบบโฮสต์ แต่ละรายต้องการAPI Key (Bedrock: ภูมิภาค AWS และข้อมูลรับรองหรือ IAM role; Vertex AI: โปรเจกต์, ภูมิภาค และ service account; Azure: API URL ด้วย)

จากนั้นตั้้งค่าโมเดลเริ่มต้น (เป็นรายชื่อบุคคลเมื่อผู้ให้บริการสามารถรายงานโมเดลได้ หรือพิมพ์ชื่อโมเดลเอง) และหากผู้ให้บริการไม่รายงาน ให้ตั้้งค่าขีดจำกัดโทเคนอินพุตและขีดจำกัดโทเคนเอาต์พุตด้วย บริการสำรองสามารถเข้ามารับหน้าที่เมื่อบริการนี้ล้มเหลวได้ บันทึกการตั้้งค่า

เซิร์ฟเวอร์จะเป็นผู้ส่งคำขอเหล่านี้เอง ดังนั้นจึงต้องสามารถเข้าถึง API ได้: เซิร์ฟเวอร์โมเดลในโปรเจกต์ compose เดียวกัน บนเครือข่ายของคุณ หรือบนอินเทอร์เน็ต คำขอขาออกจะเคารพตัวแปร HTTP_PROXY และ HTTPS_PROXY

2. สร้างเอเจนต์

สร้างเอเจนต์ได้ที่หน้า เอเจนต์ ของเว็บแอป: เปิดด้วย จัดการ ในตัวเลือกเอเจนต์ของแผงเอเจนต์ (ในอินเทอร์เฟซแบบคลาสสิก ยังเปิดได้จากเมนูผลิตภัณฑ์ด้วย) ที่อยู่ของหน้าคือ https://chat.example.com/plug/mattermost-ai/agents แต่ละเอเจนต์มี ชื่่อที่แสดง, ชื่อผู้ใช้เอเจนต์ (ชื่อที่คนใช้เมนชัน), บริการ และโดยอัตรากมีโมเดล, คำสั่่งพิเศษ, และสวิตช์สำหรับ เปิดใช้ Vision (รูปภาพ) และ เปิดใช้ Tools แท็บ การเข้้าถึ่่ง กำหนดช่องที่เอเจนต์นั้นใช้ได้อีกทั้่งผู้ใชท่ีใช้ได้อีกด้วย ใต้ AI Functions ในคอนโซลระบบ, บอทเริ่มต้น เลือกเอเจนต์ที่ใช้เมื่่อไม่ได้อีกตั้่งไว้ เช่น สำหรบั การสร้้างสรุปการโทร

โดยค่าเริ่มต้น ผู้ใช้ทุกคนสามารถสร้างเอเจนต์ของตัวเองได้ โดยใช้บริการที่คุณตั้งค่าไว้ หากต้องการจำกัดสิทธิ์นี้ไว้สำหรับผู้ดูแลระบบเท่านั้น ให้ลบสิทธิ์ จัดการเอเจนต์ AI ของคุณเอง ออกจากบทบาทของสมาชิกใน คอนโซลระบบ › การจัดการผ้้ใช้ › สิทธิ์

ฟีเจอร์เสริมของแอปเอเจนต์

  • การค้นหาค่าฝัง (ทดลองใช้, ปิดอยู่): การค้นหาเชิงความหมายในข้อความ ต้องใช้ PostgreSQL พร้อมส่วนขยาย pgvector และโมเดลค่าฝัง (OpenAI หรือเข้ากันได้กับ OpenAI) ฟีเจอร์นี้จะส่งทุกข้อความไปยังโมเดลค่าฝัง รวมถึงข้อความในช่องส่วนตัวและข้อความส่วนตัว
  • การค้นหาวีบ (ปิดอยู่): อนุญาตให้เอเจนต์ค้นหาวีบผ่าน Google, Brave หรือเซิร์ฟเวอร์ SearXNG ที่คุณรัน
  • เครื่องมือเนทีฟ: เมื่อผู้ให้บริการมีเครื่องมือเหล่านี้ เอเจนต์สามารถใช้การค้นหาวีบของผู้ให้บริการเอง (เปิดอยู่โดยค่าเริ่มต้นสำหรับเอเจนต์ใหม่ เมื่อรองรับ), การดึงข้อมูลจากเว็บ และการรันโค้ด ฟีเจอร์เหล่านี้ทำงานที่ผู้ให้บริการ ปิดใช้งานแยกตามเอเจนต์ได้
  • โปรโตคอลบริบทโมเดล (MCP): เชื่อมต่อเอเจนต์กับเซิร์ฟเวอร์ MCP ที่คุณไว้วางใจ เพื่อเพิ่มเครื่องมือ
  • Debug: Trace Output (ปิด, บันทึกเซิร์ฟเวอร์ หรือปลายทาง OpenTelemetry) และ Enable Token Usage Logging ซึ่งบันทึกรายการจำนวนโทเคนไปยัง logs/agents/token_usage.log

การแปลงเสียงเป็นข้อความ: การถอดเสียงและคำบรรยายในการโทร

การโทรสามารถถอดเสียงพร้อมคำบรรยายสดได้ โดยใช้เซิร์ฟเวอร์ speech-to-text ที่รองรับ endpoint /v1/audio/transcriptions ที่เข้ากันได้กับ OpenAI การตั้งค่าอยู่ใน การโทรและเสียง เมื่อเปิด สรุปการถอดเสียง เอเจนต์เริ่มต้นจะโพสต์สรุปของแต่ละบันทึกการถอดเสียงด้วย

Text-to-speech: อ่านออกเสียง

เมื่อเปิดใช้งานการแปลงข้อความเป็นเสียงแล้ว เมนูของทุกข้อความจะมี อ่านออกเสียง: เซิร์ฟเวอร์จะส่งข้อความไปยัง API สำหรับแปลงข้อความเป็นเสียงและเล่นเสียงนั้น การตั้งค่าอยู่ใน คอนโซลระบบ › อินทิเกรชัน › แปลงข้้อความเป็นเสีียง:

การตั้งค่าคีย์และตัวแปรสิ่งที่ต้องกรอก
อ่านข้อความออกเสียงTextToSpeechSettings.Enable, AM_TEXTTOSPEECHSETTINGS_ENABLEtrue (ปิดเป็นค่าเริ่มต้น)
URL ฐาน APITextToSpeechSettings.URL, AM_TEXTTOSPEECHSETTINGS_URLURL เบื้องต้นจนถึง /v1 เช่น http://tts.internal:8000/v1 เซิร์ฟเวอร์จะเรียกใช้ endpoint /audio/speech ของมัน
โมเดลTextToSpeechSettings.Model, AM_TEXTTOSPEECHSETTINGS_MODELชื่อโมเดลตามที่ API เรียก เช่น tts-1 จำเป็นต้องกรอก
เสียงTextToSpeechSettings.Voice, AM_TEXTTOSPEECHSETTINGS_VOICEหนึ่งในเสียงของโมเดล หรือเว้นว่างเพื่อใช้ค่าเริ่มต้น
API keyTextToSpeechSettings.APIKey, AM_TEXTTOSPEECHSETTINGS_APIKEYส่งเป็น bearer token เว้นว่างหาก API ไม่ต้องการ

เพื่อใช้การเชื่อมต่อโมเดลแทนที่อยู่และคีย์ด้านบน, เลือกมันสำหรับ แปลงข้้้อความเป็็นเสีียง ใน AI › ฟีเจอร์ในตััว หน้้าจะบอกว่าข้้อความถูกอ่่านออกเสีียงด้วยขั้อต่อนั้้น: URL ฐาน API และ API key ไม่ถูกใช้, เสีียง ยังถูกใช้, และ โมเดล ก็ถูกใช้ด้วยเมื่่อข้้อต่อนไม่ได้อีกตั้่งโมเดลไว้ อ่่านข้้อความออกเสีียง ยังต้้องเปิิดอยู่

ก่อนส่ง เซิร์ฟเวอร์จะลบโค้ดบล็อก ลิงก์ โค้ดอิโมจิ และรูปแบบการจัดหน้า และเก็บไว้ไม่เกิน 4000 ตัวอักษร โดยขอเสียง MP3 และเก็บผลลัพธ์ 64 รายการล่าสุดไว้ในหน่วยความจำ ดังนั้นข้อความที่อ่านซ้ำจะถูกส่งเพียงครั้งเดียว

การแปลอัตโนมัติ

การแปลอัตโนมัติแสดงข้อความในช่องเป็นภาษาของผู้ใช้แต่ละคน ตั้งค่าได้ที่ คอนโซลระบบ › การตั้่งค่าไซต์ › การปรับภาษา ภายใต้ การแปลอัตโนมัติ:

การตั้งค่าคีย์ค่าเริ่มต้น
เปิดใช้งานAutoTranslationSettings.Enableปิด
ผู้ให้บริการแปลAutoTranslationSettings.Providerconnection (แสดงเป็น "Model connection (recommended)", ตัวที่ถูกเลือกเมื่อไม่ได้ตั้งไว้), libretranslate, openai ("OpenAI-compatible API, set up here") หรือ agents ("AI chat app's service (older)")
ภาษาท่ีอนุญาตAutoTranslationSettings.TargetLanguagesen: ภาษาที่สามารถแปลข้อความได้
Timeout การแปล (ms)AutoTranslationSettings.TimeoutMs5000
จำกัดการแปลอัตโนมัติในข้อความส่วนตัวและข้อความกลุ่มAutoTranslationSettings.RestrictDMAndGMปิด

แต่ละผู้ให้บริการมีฟิลด์ของตัวเอง:

  • Model connection: การเชื่อมต่อทั้งเซิร์ฟเวอร์และโมเดลของมัน, การตั้งค่าเดียวกันกับ การแปลอัตโนมัติ ใน AI › ฟีเจอร์ในตัว (AISettings.AutoTranslation) โมเดลแปลเฉพาะทางนั้นเร็วและแม่นยำ; LLM ทั่วไปก็ใช้ได้
  • LibreTranslate: LibreTranslate API Endpoint และ LibreTranslate API Key (AutoTranslationSettings.LibreTranslate.URL, .APIKey) เซิร์ฟเวอร์ LibreTranslate สามารถรันบนเครือข่ายของคุณเองได้
  • OpenAI-compatible API: URL ฐาน API (จนถึงและรวม /v1; เซิร์ฟเวอร์จะใช้ปลายทาง chat completions ของมัน), โมเดล และ API key (AutoTranslationSettings.OpenAI.URL, .Model, .APIKey) โมเดลแปลขนาดเล็กที่รันบนเครื่องท้องถิ่นทำงานได้ดี
  • AI chat app's service (older): ผู้ให้บริการของเซิร์ฟเวอร์ที่ตั้งค่าก่อน 0.9.0 ซึ่งใช้บริการของแอป Agents. ตอนนี้ไม่จำเป็นต้องใช้แอปอีก: มันแปลด้วย connection ที่เลือกสำหรับการแปลอัตโนมัติใน AI › ฟีเจอร์ในตัว หรือด้วย connection ที่คัดลอกจากบริการของแอปเมื่ออัปเกรด Switch to Model connection ย้ายการตั้งค่าไปยังผู้ให้บริการที่แนะนำ

เมื่อเปิดใช้งานแล้ว ผู้ดูแลช่องสามารถเปิดการแปลสำหรับช่องได้ในการตั้งค่าของช่องนั้น (การแปลอัตโนมัติ) และสมาชิกแต่ละคนสามารถเลือกไม่รับบริการนี้ได้จากเมนูของช่อง (แปลข้อความ) ในข้อความส่วนตัวและข้อความกลุ่ม สมาชิกทุกคนสามารถเปิดใช้งานได้; เมื่อมีการจำกัดสิทธิ์ การแปลจะไม่พร้อมใช้งาน在那里 ข้อความที่แปลแล้วจะแสดง "Translated from …" พร้อมลิงก์ไปยังข้อความต้นฉบับ

โค้ด ลิงค์ เมนชั่่น และอิโมจี่จะถืกแทนท่ีด้วย placeholder ก่อนท่ีจะส่่งข้้อความ และถืกนั่่งท่ีเดิ่่มหลั่่งนั้่น

ข้้อมูลท่ีถืกส่่งไปท่ีใด

ฟีเจอร์สิ่่งท่ีถืกส่่งไปยั่่ง
เขียนใหม่ข้อความที่กำลังเขียน และคำสั่งที่เลือกการเชื่อมต่อที่เลือกสำหรับมัน
สรุปข้อความของช่องในสรุป และคำสั่งของบุคคลนั้นการเชื่อมต่อที่เลือกสำหรับมัน
แอปที่ใช้การเชื่อมต่อโมเดลสิ่งที่แต่ละแอปส่ง สำหรับบุคคลที่ใช้มันการเชื่อมต่อที่บุคคลนั้นอาจใช้
เอเจนต์คำข้้อ, ข้้อความของเธรดหรือช่องท่ีเกี่่ยวข้้อง, คำสั่่งของเอเจนต์, ผลลัพธ์ของเครื่องมือ, ภาพเม่ือเปิ่ด vision, และชื่่อ, user name, ตำแหน่ง และภาษาของผู้ข้้อAPI ของบริการ
การค้้นหาด้วย embeddingข้้อความทุกข้้อ (ยกเว้้นข้้อความของบอทและข้้อความของระบบ)API ของ embedding
เครื่องมือเนทิฟและเว็บค้้นหาคำค้้นหา, หน้่าท่ีจะ fetch, โค้ดผู้ให้บริการ หรือเครื่่องค้้นหาท่ีคุณเลืก
การถอดเสิ่่งของการโทรเสิ่่งของทุกคนท่ีพูดเม่ือเปิ่ดการถอดเสิ่่งAPI ของ speech-to-text
การอ่านออกเสียงข้้อความของข้้อความท่ีถืกอ่านAPI แปลข้อความเป็นเสียง หรือการเชื่อมต่อที่เลือกสำหรับมัน
การแปลภาษาข้้อความของข้้อความในช่องท่ีถืกแปลการเชื่อมต่อโมเดล, LibreTranslate หรือ OpenAI-compatible API

เพื่่อเก็บทัง้หมดไว้ในเนทเวอร์คของคุณ, จงั้่งทุกฟีเจอร์ไปยั่่งเซิร์ฟเวอร์ท่ีคุณรันเอง เมื่่อใช้ผู้ให้บริการคลาวด์, ตรวจสอบข้้อตกลงเกี่่ยวกั่่งการเก็บข้้อมูลของเขา, และบอกผู้ใช้ของคุณว่าฟีเจอร์ใดท่ีส่่งข้้อความของเขาออกนอก

การปิ่ด AI

ไม่มีสวิตช์เดีียว: ฟีเจอร์แต่ล่ะอย่างมีสวิตช์ของตัวมันเอง

  • การเขียนใหม่และสรุป: ตั้งค่าเป็น ปิด ใน คอนโซลระบบ › AI › ฟีเจอร์ในตัว ผู้ใช้ยังคงอ่านสรุปที่มีอยู่แล้ว
  • การเชื่อมต่อโมเดล: ลบการเชื่อมต่อเพื่อหยุดการใช้งานทั้งหมด หากไม่มีเชื่อมต่อ ฟีเจอร์ในตัวและแอปจะไม่สามารถใช้ AI ผ่านเซิร์ฟเวอร์ได้
  • เอเจนต์: ปิดแอปเอเจนต์ใน คอนโซลระบบ › ปลั๊กอิน › การจัดการปลั๊กอิน การดำเนินการนี้จะลบสรุปการโทรด้วย
  • การถอดเสิ่่งและคำบรรยายสด: AM_CALLS_ENABLE_TRANSCRIPTIONS=false และ AM_CALLS_ENABLE_LIVE_CAPTIONS=false (ค่าเดิ่่ม).
  • อ่านออกเสียง: ปิด อ่านข้อความออกเสียง (AM_TEXTTOSPEECHSETTINGS_ENABLE=false, ค่าเริ่มต้น) ไม่ว่าจะใช้การเชื่อมต่อหรือไม่ก็ตาม
  • การแปลภาษา: ปิ่ดการแปลภาษาอัตโนมัติ (AM_AUTOTRANSLATIONSETTINGS_ENABLE=false, ค่าเดิ่่ม).

การปิดแอปเอเจนต์ไม่ได้ปิดฟีเจอร์อื่น: ฟีเจอร์เหล่านั้นใช้การเชื่อมต่อโมเดลหรือ API ของตัวเอง
