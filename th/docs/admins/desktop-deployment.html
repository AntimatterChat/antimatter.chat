การติดตั้งแอปเดสก์ท็อป

วิธีการติดตั้งแอปเดสก์ท็อป Antimatter บนคอมพิวเตอร์ของบริษัทหรือโรงเรียน และกำหนดค่าเซิร์ฟเวอร์ ชื่อผู้ใช้ และการตรวจสอบการอัปเดตส่วนกลางบน Windows, macOS และ Linux

ดาวน์โหลดแอป

เวอร์ชันของแอปเดสก์ท็อปอยู่บน GitHub ที่ github.com/AntimatterChat/desktop-app/releases เช่นเดียวกับเซิร์ฟเวอร์ แอปนี้อยู่ในสถานะเบต้า: เวอร์ชันที่มีคำต่อท้ายหลังเครื่องหมายขีดกลางจะถูกทำเครื่องหมายว่า Pre-release แต่ละเวอร์ชันมีไฟล์ SHA256SUMS ที่ระบุค่า checksum ของทุกไฟล์ ตรวจสอบการดาวน์โหลดด้วย sha256sum --check --ignore-missing SHA256SUMS บน Linux หรือเปรียบเทียบผลลัพธ์ของ Get-FileHash <file> -Algorithm SHA256 ใน PowerShell กับบรรทัดใน SHA256SUMS

  • Windows (x64 และ arm64): ตัวติดตั้ง .exe, แพ็กเกจ .msi หรือไฟล์ .zip ตัวอย่างเช่น antimatter-desktop-<version>-win-x64.exe และ antimatter-desktop-<version>-win-x64.msi
  • macOS: ไฟล์ดิสก์ .dmg หรือ .zip สำหรับ Apple silicon (arm64), Mac Intel (x64) หรือทั้งสอง (universal)
  • Linux (x64 และ arm64): แพ็กเกจ .deb หรือ .rpm, AppImage, Flatpak bundle หรือไฟล์ .tar.gz

ตัวติดตั้ง Windows แบบใดควรใช้

ตัวติดตั้ง .exeแพ็กเกจ .msi
สำหรับผู้ที่ติดตั้งแอปด้วยตนเองบริษัทที่ติดตั้งบนคอมพิวเตอร์ของบริษัท
การติดตั้งเฉพาะบัญชี Windows ปัจจุบันเท่านั้น ใน %LOCALAPPDATA%\Programs\antimatter-desktop โดยไม่ต้องการสิทธิ์ผู้ดูแลระบบสำหรับผู้ใช้ทุกคนบนคอมพิวเตอร์ ใน C:\Program Files\Antimatter โดยต้องมีสิทธิ์ผู้ดูแลระบบ
การอัปเดตแอปจะตรวจสอบเวอร์ชันใหม่และเสนอให้ดาวน์โหลด .exe ใหม่ ซึ่งจะทำให้อัปเดตสำเนาที่ติดตั้งไว้ที่เดิมแอปจะไม่ตรวจสอบเวอร์ชันใหม่: คุณต้องเป็นผู้ติดตั้งเอง

แอปจะตรวจสอบเวอร์ชันใหม่บน GitHub ทุกชั่วโมงระหว่างที่ทำงาน และจะเห็นเฉพาะการปล่อยเวอร์ชันเต็มเท่านั้น ไม่รวมเวอร์ชันพรีรีลีส เมื่อพบเวอร์ชันใหม่ แอปจะแจ้งให้ผู้ใช้ทราบและเสนอลิงก์สำหรับดาวน์โหลด สำหรับสำเนาที่ติดตั้งด้วย MSI จะไม่ตรวจสอบโดยค่าเริ่มต้น เนื่องจากผู้ใช้มักไม่มีสิทธิ์ติดตั้งซอฟต์แวร์ คุณสามารถเปิดการตรวจสอบสำหรับสำเนานี้ได้ด้วยการตั้งค่า EnableAutoUpdater: ไฟล์ที่เสนอให้ดาวน์โหลดจะเป็น .msi ใหม่ ซึ่งต้องการสิทธิ์ผู้ดูแลระบบ

ใช้ MSI สำหรับการจัดวางแบบจัดการด้วย SCCM (Configuration Manager), Intune หรือการติดตั้งซอฟต์แวร์ผ่าน Group Policy การติดตั้ง MSI จะลบสำเนา .exe ของบัญชีผู้ใช้ที่กำลังดำเนินการติดตั้ง (ถ้ามี)

การตั้งค่าที่คุณสามารถจัดการได้

การตั้งค่าเหล่านี้มีอยู่ในทุกระบบ บน Windows จะเป็นค่าในรีจิสทรีภายใต้ SOFTWARE\Policies\Antimatter ใน HKEY_LOCAL_MACHINE (สำหรับคอมพิวเตอร์) หรือ HKEY_CURRENT_USER (สำหรับผู้ใช้แต่ละคน) บน macOS และ Linux จะเป็นคีย์ของ managed preferences หรือไฟล์ policy

การตั้งค่าบน Windowsบน macOS และ Linuxสิ่งที่ทำ
DefaultServerListซับคีย์ที่มีค่าสตริงหนึ่งค่าต่อเซิร์ฟเวอร์: ชื่อค่าคือชื่อแท็บ และข้อมูลคือ URL ของแท็บนั้นอาร์เรย์ของดิกชันนารี (อ็อบเจกต์บน Linux) ที่มี name และ urlเพิ่มเซิร์ฟเวอร์ลงในแอป ผู้ใช้ไม่สามารถแก้ไขหรือลบเซิร์ฟเวอร์เหล่านี้ได้
DefaultUsernameสตริงสตริงกรอกชื่อผู้ใช้ในหน้าเข้าสู่ระบบของเซิร์ฟเวอร์เหล่านี้
EnableServerManagementDWORD, 0 หรือ 1บูลีน0 หรือ false: ผู้ใช้สามารถใช้เฉพาะเซิร์ฟเวอร์ที่ตั้งค่าไว้ด้วย DefaultServerList และแอปจะซ่อนตัวเลือกสำหรับเพิ่ม แก้ไข และลบเซิร์ฟเวอร์ ไม่ตั้งค่า: ผู้ใช้สามารถเพิ่มเซิร์ฟเวอร์ของตัวเองได้
EnableAutoUpdaterDWORD, 0 หรือ 1บูลีน0 หรือ false: แอปจะไม่ตรวจสอบเวอร์ชันใหม่เลย และจะซ่อน ตรวจสอบการอัปเดต 1 หรือ true: แอปจะตรวจสอบ แม้จะติดตั้งด้วย MSI ก็ตาม ไม่ตั้งค่า: สำเนา .exe จะตรวจสอบ แต่สำเนา MSI จะไม่ตรวจสอบ
TrustedEmbeddedMediaOriginsซับคีย์ที่มีค่าสตริง แต่ละค่าเป็นอ็อบเจกต์ JSON ที่มี serverOrigin และ embeddedOriginอาร์เรย์ของดิกชันนารีที่มี serverOrigin และ embeddedOriginอนุญาตให้เนื้อหาที่ฝังอยู่ในหน้าของเซิร์ฟเวอร์ เช่น หน้าการประชุมวิดีโอ สามารถใช้สิทธิ์กล้องและไมโครโฟนที่มอบให้สำหรับเซิร์ฟเวอร์นั้นได้
  • ชื่อบัญชีผู้ใช้ จะถูกกรอกให้อัตโนมัติเฉพาะในหน้าเข้าสู่ระบบของเซิร์ฟเวอร์ที่ระบบกำหนดไว้เท่านั้น ไม่เคยกรอกในเซิร์ฟเวอร์ที่ผู้ใช้เพิ่มเอง และจะไม่ทับค่าที่ผู้ใช้พิมพ์ไว้ ผู้ใช้ยังคงสามารถแก้ไขค่านี้ได้ ตัวแปรในวงเล็บเปอร์เซ็นต์จะถูกแทนที่ ดังนั้นค่าเดียวจึงใช้ได้กับทุกคน: %USERNAME% บน Windows หรือ %USER% บน macOS และ Linux จะให้ชื่อบัญชี และ %USERNAME%@example.com จะให้ที่อยู่อีเมลตามรูปแบบนี้ หากตัวแปรไม่ถูกตั้งค่า แอปจะเว้นว่างไว้
  • หากคุณปิดการจัดการเซิร์ฟเวอร์ ให้ตั้งค่าอย่างน้อยหนึ่งเซิร์ฟเวอร์ใน DefaultServerList
  • บน Windows นโยบายคอมพิวเตอร์ (HKEY_LOCAL_MACHINE) จะมีผลเหนือกว่านโยบายผู้ใช้ (HKEY_CURRENT_USER) รายการเซิร์ฟเวอร์จากทั้งสองแหล่งจะถูกรวมเข้าด้วยกัน
  • แอปจะอ่านการตั้งค่าเมื่อเริ่มทำงาน: หลังจากมีการเปลี่ยนแปลง ผู้ใช้ต้องปิดและเปิดแอปใหม่อีกครั้ง

Windows: การติดตั้งแบบเงียบด้วย MSI

MSI รับ public properties ที่เขียนการตั้งค่าเป็นนโยบายคอมพิวเตอร์ ใน HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Antimatter ใช้สิ่งเหล่านี้ในแอป SCCM, แอป Intune หรือสคริปต์ ใน PowerShell:

msiexec /i antimatter-desktop-<version>-win-x64.msi /qn SERVERURL=https://chat.example.com SERVERNAME=Chat DEFAULTUSERNAME='%USERNAME%' AUTOUPDATE=0 SERVERMANAGEMENT=0
Propertyเขียนค่าหากไม่ระบุ
SERVERURLเซิร์ฟเวอร์ใน DefaultServerList พร้อม URL นี้ไม่มีเซิร์ฟเวอร์
SERVERNAMEชื่อแท็บของเซิร์ฟเวอร์นั้นAntimatter
DEFAULTUSERNAMEDefaultUsernameไม่มี
AUTOUPDATEEnableAutoUpdater, 0 หรือ 1ไม่มี: คัดลอกของ MSI จะไม่ตรวจสอบการอัปเดต
SERVERMANAGEMENTEnableServerManagement, 0 หรือ 1ไม่มี: ผู้ใช้สามารถเพิ่มเซิร์ฟเวอร์ได้
  • Property ที่ไม่ระบุจะเขียนค่าว่าง ดังนั้นจึงจะไม่ทับค่าที่ตั้งไว้โดย Group Policy AUTOUPDATE และ SERVERMANAGEMENT รับเฉพาะ 0 หรือ 1 เท่านั้น MSI ตั้งค่าเซิร์ฟเวอร์ได้เพียงหนึ่งตัว: ใช้ Group Policy สำหรับหลายตัว
  • DEFAULTUSERNAME ต้องไปถึงตัวติดตั้งในรูปข้อความ %USERNAME% เพื่อให้แอปแทนที่ค่าสำหรับแต่ละบุคคล มิฉะนั้น shell ที่รันการติดตั้งจะแทนที่ด้วยชื่อบัญชีของมันเอง ใน PowerShell ให้ใช้เครื่องหมายอัญประกาศเดี่ยว ในไฟล์ .bat ให้เขียนว่า %%USERNAME%% หลังการติดตั้งเพื่อทดสอบ ให้ตรวจสอบใน registry ว่า DefaultUsername มีค่าเป็น %USERNAME%
  • ส่ง properties อีกครั้งในทุกการอัปเกรด. การติดตั้งเวอร์ชันใหม่ของ MSI จะลบเวอร์ชันเก่าพร้อมค่าที่เขียนไว้ จากนั้นจึงเขียนค่าจาก command line ใหม่ SCCM และ Intune จะเก็บ command line ของแอปไว้: นำกลับมาใช้ใหม่สำหรับแต่ละเวอร์ชันใหม่ หรือใช้นโยบายผ่าน Group Policy หรือ Intune แทน ซึ่งการอัปเกรดจะไม่แตะต้อง
  • MSI และ Group Policy จะเขียนค่ารีจิสทรีเดียวกัน สำหรับแต่ละการตั้งค่า ให้ใช้วิธีใดวิธีหนึ่ง: การถอนการติดตั้ง MSI จะลบค่าที่เขียนไว้ แม้ Group Policy จะตั้งค่าเหล่านั้นไว้ก็ตาม
  • MSI ยังบันทึกโฟลเดอร์การติดตั้งไว้ใน HKEY_LOCAL_MACHINE\SOFTWARE\Antimatter\Desktop (InstallDir) อีกด้วย นี่คือวิธีที่แอปทราบว่าถูกติดตั้งด้วย MSI

เพื่อถอนการติดตั้ง: msiexec /x antimatter-desktop-<version>-win-x64.msi /qn ใน Intune ประเภท "Windows app (Win32)" ใช้บรรทัดคำสั่งเดียวกัน สำหรับประเภท "Line-of-business app" ให้เพิ่มคุณสมบัติลงในอาร์กิวเมนต์บรรทัดคำสั่ง

Windows: Group Policy และ Intune

เทมเพลตการจัดการ antimatter.admx และ en-US\antimatter.adml อยู่ในโฟลเดอร์ gpo ของแอปที่ติดตั้งแล้ว (C:\Program Files\Antimatter\gpo สำหรับ MSI) และในโฟลเดอร์ resources/windows/gpo ของรีพอสิทอรีแอป แสดงนโยบายเหล่านี้ภายใต้ Administrative Templates › Antimatter:

นโยบายค่ารีจิสทรีการตั้งค่า
เซิร์ฟเวอร์ (DefaultServerList)ซับคีย์ DefaultServerListคอมพิวเตอร์และผู้ใช้
ชื่อผู้ใช้สำหรับกรอกไว้ล่วงหน้า (DefaultUsername)DefaultUsernameคอมพิวเตอร์และผู้ใช้
อนุญาตให้ผู้ใช้เพิ่มและลบเซิร์ฟเวอร์ (EnableServerManagement)EnableServerManagementคอมพิวเตอร์และผู้ใช้
แจ้งเตือนเกี่ยวกับเวอร์ชันใหม่ (EnableAutoUpdater)EnableAutoUpdaterเฉพาะคอมพิวเตอร์
แหล่งที่มาของสื่อฝังตัวที่เชื่อถือได้ (TrustedEmbeddedMediaOrigins)ซับคีย์ TrustedEmbeddedMediaOriginsคอมพิวเตอร์และผู้ใช้

Group Policy ในโดเมน

  1. คัดลอก antimatter.admx ไปยังคลังกลาง \\<domain>\SYSVOL\<domain>\Policies\PolicyDefinitions และ antimatter.adml ไปยังโฟลเดอร์ en-US ของมัน
  2. ใน Group Policy Management Editor ให้เปิด Computer Configuration (หรือ User Configuration) › Policies › Administrative Templates › Antimatter
  3. แก้ไขนโยบาย เลือก เปิดใช้งาน และกรอกข้อมูล สำหรับ เซิร์ฟเวอร์ ให้คลิก แสดง และเพิ่มหนึ่งบรรทัดต่อเซิร์ฟเวอร์: ชื่อค่าคือชื่อแท็บ ค่าคือ URL ของเซิร์ฟเวอร์ เช่น https://chat.example.com

การเปิดใช้งาน อนุญาตให้ผู้ใช้เพิ่มและลบเซิร์ฟเวอร์ หรือ แจ้งเตือนเกี่ยวกับเวอร์ชันใหม่ จะเขียนค่า 1; การปิดใช้งานจะเขียนค่า 0

Intune

ใน Devices › Configuration ใช้ Import ADMX เพื่ออิมพอร์ต antimatter.admx พร้อม en-US\antimatter.adml จากนั้นสร้างโปรไฟล์จาก Templates › Imported Administrative templates และตั้งค่า Antimatter policies ในโปรไฟล์นั้น

คอมพิวเตอร์เครื่องเดียว หรือสคริปต์

คัดลอกเทมเพลตไปยัง C:\Windows\PolicyDefinitions เพื่อใช้งานใน gpedit.msc (Windows Pro และ Enterprise) หรือเขียนค่า registry โดยตรงด้วยไฟล์ .reg ที่อิมพอร์ตในฐานะผู้ดูแลระบบ (reg import antimatter-policies.reg) เช่นไฟล์นี้ ไฟล์ example-policies.reg ในโฟลเดอร์เดียวกันมีค่าเหล่านี้พร้อมคำอธิบาย

REGEDIT4

[HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Antimatter]
"EnableServerManagement"=dword:00000000
"EnableAutoUpdater"=dword:00000000
"DefaultUsername"="%USERNAME%"

[HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Antimatter\DefaultServerList]
"Chat"="https://chat.example.com"

macOS: โปรไฟล์การตั้งค่า

บน macOS แอปอ่านค่าการตั้งค่าจาก managed preferences ของ bundle identifier chat.antimatter.desktop โดยใช้คีย์จากตารางการตั้งค่า จัดส่งด้วย MDM (เช่น Jamf, Intune, Kandji, Mosyle และอื่นๆ) ในรูปแบบโปรไฟล์การตั้งค่า

  • โฟลเดอร์ resources/mac/mdm ในรีพอสิทอรีของแอปมีตัวอย่างโปรไฟล์ antimatter.mobileconfig แก้ไขค่าต่างๆ ให้มี PayloadIdentifier และ PayloadUUID เป็นของคุณเอง (uuidgen สร้าง UUID ใหม่) จากนั้นอัปโหลดเป็นโปรไฟล์แบบกำหนดเอง
  • MDM ส่วนใหญ่ยอมรับคีย์เดี่ยวๆ ในรูปแบบ "custom settings" หรือ "preference domain" payload สำหรับ chat.antimatter.desktop โฟลเดอร์เดียวกันมีคีย์เหล่านี้ใน example-managed-preferences.plist

ค่าการตั้งค่าภายใน payload ของโปรไฟล์:

<key>PayloadType</key>
<string>chat.antimatter.desktop</string>
<key>DefaultServerList</key>
<array>
    <dict>
        <key>name</key>
        <string>Chat</string>
        <key>url</key>
        <string>https://chat.example.com</string>
    </dict>
</array>
<key>DefaultUsername</key>
<string>%USER%</string>
<key>EnableServerManagement</key>
<false/>
<key>EnableAutoUpdater</key>
<false/>

ค่าบูลีนสามารถระบุเป็นจำนวนเต็ม 0 และ 1 ได้

Linux: ไฟล์ policy

บน Linux แอปอ่าน /etc/antimatter-desktop/policies.json ซึ่งเป็น JSON object ที่มีคีย์จากตารางการตั้งค่า:

{
    "DefaultServerList": [
        {"name": "Chat", "url": "https://chat.example.com"}
    ],
    "DefaultUsername": "%USER%",
    "EnableServerManagement": false,
    "EnableAutoUpdater": false,
    "TrustedEmbeddedMediaOrigins": []
}

จัดส่งด้วยเครื่องมือจัดการการตั้งค่าของคุณ (เช่น Ansible, Puppet, Salt และอื่นๆ) โดยให้ root เป็นเจ้าของไฟล์ อ่านได้โดยทุกคน และเขียนได้โดย root เท่านั้น:

sudo install -d /etc/antimatter-desktop
sudo install -m 644 policies.json /etc/antimatter-desktop/policies.json

ไฟล์ที่ไม่ใช่ JSON ที่ถูกต้องจะถูกเพิกเฉยพร้อมคำเตือนใน log ของแอป เวอร์ชัน Flatpak ไม่สามารถเข้าถึง /etc ของโฮสต์ได้: ให้สิทธิ์การอ่าน และมันจะอ่านไฟล์จาก /run/host/etc/antimatter-desktop/policies.json:

sudo flatpak override --system --filesystem=host-etc:ro chat.antimatter.desktop

Policies ที่ตั้งค่าไว้สำหรับแอป Mattermost desktop

บน Windows แอปยังอ่านนโยบายที่ตั้งไว้สำหรับแอปเดสก์ท็อป Mattermost ภายใต้ SOFTWARE\Policies\Mattermost เป็นค่าสำรอง โดยจะอ่านตามตำแหน่ง: ค่าที่อยู่โดยตรงภายใต้คีย์นโยบาย คีย์ย่อย DefaultServerList และคีย์ย่อย TrustedEmbeddedMediaOrigins สำหรับแต่ละตำแหน่งทั้งสามนี้ แอปจะอ่านคีย์ของ Mattermost เฉพาะเมื่อคีย์ของ Antimatter ไม่มีค่าอยู่ที่นั่นใน hive ใด hive หนึ่ง ดังนั้นเมื่อตั้งค่าใดค่าหนึ่งโดยตรงภายใต้คีย์ Antimatter แล้ว เช่น ผ่านคุณสมบัติ AUTOUPDATE ของ MSI ค่าที่อยู่โดยตรงภายใต้คีย์ Mattermost ทั้งหมดจะไม่ถูกอ่าน กรุณาโอนย้ายนโยบายทั้งหมดของคุณไปยังคีย์ Antimatter ในครั้งเดียว

บน macOS ค่าการตั้งค่าแบบจัดการ (managed preferences) ของแอปเดสก์ท็อป Mattermost (com.mattermost.desktop) จะไม่ถูกอ่าน: กรุณาตั้งค่าเหล่านี้สำหรับ chat.antimatter.desktop แทน

การติดตั้งที่ไม่ได้ลงนาม

การติดตั้งของแอปเดสก์ท็อปยังไม่ได้ลงนามด้วยใบรับรองของผู้เผยแพร่

  • Windows. เมื่อผู้ใช้เปิดไฟล์ .exe หรือ .msi ที่ดาวน์โหลดมา Microsoft Defender SmartScreen จะแจ้งว่า Windows ได้ปกป้องคอมพิวเตอร์ไว้ และระบุชื่อผู้เผยแพร่ที่ไม่รู้จัก ผู้ใช้ต้องเลือก More info จากนั้นเลือก Run anyway SmartScreen จะตรวจสอบไฟล์ที่ผู้ใช้เปิดหลังจากดาวน์โหลด ดังนั้นผู้ใช้จะไม่เห็นคำเตือนนี้เมื่อคุณติดตั้งแอปผ่าน SCCM, Intune หรือ Group Policy หากคอมพิวเตอร์ของคุณรันซอฟต์แวร์จากผู้เผยแพร่ที่ได้รับอนุญาตเท่านั้น (กฎของ AppLocker หรือ App Control for Business) กรุณาอนุญาตแอปโดยระบุเส้นทางติดตั้งหรือแฮชของไฟล์แทน
  • macOS. แปปลงนามแบบ ad hoc แต่ไม่ได้ผ่านการรับรอง (notarise) จาก Apple ครั้งแรกที่ผู้ใช้เปิดสำเนาที่ดาวน์โหลดมา macOS จะแจ้งว่าไม่สามารถตรวจสอบได้ว่าแอปปลอดจากมัลแวร์ และไม่เปิดแอป บน macOS 15 และใหม่กว่า ผู้ใช้ต้องเปิด System Settings › Privacy & Security และเลือก Open Anyway บนเวอร์ชันก่อนหน้า ให้ผู้ใช้ Control-click ที่แอปแล้วเลือก Open Gatekeeper จะตรวจสอบเฉพาะไฟล์ที่มีเครื่องหมายว่าดาวน์โหลดมา (มี quarantine attribute): เมื่อคุณติดตั้งแอปด้วยเครื่องมือของคุณเอง ให้ลบเครื่องหมายนี้ในสคริปต์ติดตั้งของคุณ โดยใช้ xattr -dr com.apple.quarantine /Applications/Antimatter.app
