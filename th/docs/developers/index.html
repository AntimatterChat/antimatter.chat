การสร้างบน Antimatter

คู่มือนี้จัดทำขึ้นสำหรับนักพัฒนา ครอบคลุมสคริปต์และบอทที่ใช้ API, การบูรณาการที่สร้างบน webhooks และคำสั่งสแลช, แอป (ปลั๊กอิน) ที่เพิ่มฟีเจอร์ให้กับเซิร์ฟเวอร์และแอปบนเว็บ รวมถึงการสร้าง Antimatter จากซอร์สโค้ดเพื่อมีส่วนร่วม

วิธีขยาย Antimatter

เลือกเครื่องมือที่เบาที่สุดที่ทำงานได้ 4 ข้อแรกไม่จำเป็นต้องเข้าถึงตัวเซิร์ฟเวอร์ ส่วนแอปจะทำงานภายในเซิร์ฟเวอร์

เครื่องมือสิ่งที่ทำเหมาะสำหรับ
REST APIทุกอย่างที่แอปทำได้: ข้อความ, ช่อง, ผู้คน, ไฟล์, การตั้งค่า WebSocket จะส่งเหตุการณ์เมื่อเกิดขึ้นสคริปต์, การซิงค์กับระบบอื่น, ไคลเอนต์แบบกำหนดเอง
Incoming webhooksURL ลับที่โพสต์ข้อความไปยังช่องเมื่อมีใครส่ง JSON มาการแจ้งเตือน, ผล CI, การตรวจสอบระบบ, การแจ้งเตือนจากเครื่องมืออื่น
Outgoing webhooksAntimatter จะเรียก URL ของคุณเมื่อข้อความในช่องสาธารณะเริ่มต้นด้วยคำกระตุ้น (trigger word) และจะโพสต์คำตอบของคุณระบบอัตโนมัติที่ขับเคลื่อนด้วยแชทอย่างง่าย
คำสั่งสแลชผู้ใช้พิมพ์ /something; Antimatter จะเรียก URL ของคุณและแสดงคำตอบของคุณให้ผู้ใช้หรือช่องนั้นการค้นหาค่า, การดำเนินการที่เริ่มจากแชท
บอทบัญชีที่สร้างสำหรับโปรแกรม พร้อมโทเคนของตัวเอง, แท็ก BOT, และข้อความและไดอะล็อกแบบโต้ตอบผู้ช่วย, ระบบแจ้งเตือน, หรือทุกอย่างที่ต้องสนทนากับผู้คน
แอป (ปลั๊กอิน)โค้ดที่ทำงานภายในเซิร์ฟเวอร์ (Go) และในแอปบนเว็บ (React): ฮุคสำหรับทุกข้อความ, เมนูใหม่, แผง, ประเภทข้อความ, หน้าฟีเจอร์: โพล, โน้ต, ปฏิทิน, การบูรณาการที่ต้องการส่วนติดต่อผู้ใช้

ในอินเทอร์เฟซ ผู้ใช้เรียกปลั๊กอินว่า "แอป" คู่มือนี้ใช้คำว่า "แอป (ปลั๊กอิน)" ในจุดที่ทั้งสองคำช่วยให้เข้าใจได้ เนื่องจากโค้ด, API และการตั้งค่ายังคงใช้คำว่า "plugin"

ความเข้ากันได้กับ Mattermost

Antimatter เป็นฟอร์กของ Mattermost ส่วนใหญ่ของสิ่งที่ทำงานกับเซิร์ฟเวอร์ Mattermost จะทำงานกับ Antimatter ได้

สิ่งที่เหมือนกัน

  • REST API ภายใต้ /api/v4, การรับรองความถูกต้อง, WebSocket และรูปแบบข้อผิดพลาด เซิร์ฟเวอร์รายงานเวอร์ชัน 12.0.0 ดังนั้นไคลเอนต์และแอปที่ตรวจสอบเวอร์ชันเซิร์ฟเวอร์จะเห็นว่าเป็น Mattermost เวอร์ชันล่าสุด
  • เว็บฮุคและคำสั่งสแลช รวมถิง payload ที่เข้ากัย Slack
  • API และ hooks ส่า server plugin: Antimatter ไหม่ได่เปลี่นแปลงสิ่่งเหล่านีี Server code ตั้ดส้างกัย Go module เดิม, github.com/mattermost/mattermost/server/public
  • Registry ส่า web app plugin: ทุุก method register… ของ registry ใน Mattermost อยู้ใน interface ส่า web ทังสองข่องของ Antimatter
  • ไลบรารีส่า client: Go client model.Client4 และ TypeScript client @mattermost/client (ดู ไลบรารีส่า client)
  • Plugin bundles: ไฟล์ .tar.gz ที่มาม่ง manifest plugin.json Plugin ที่ได่ลายเซ็นกัยคีย์ของ Mattermost ติดตังได่ เชนกัยท่ีได่ลายเซ็นกัยคีย์ของ Antimatter

สิ่่งท่ีแตกต่าก

  • Interface ส่า web สองชนิด. Interface ใหม์, Fusion, เปนค่าด้น; interface แบบคลาสสิกของ Mattermost ยังก้บใชได่ Fusion แสดงผลคอมโพเนนต์ของ plugin ส่วนให่, แต่จัดวางบางสิ่่งในตำแหน่่งท่ีแตกต่ากและละบางสิ่่งไว้ แอพสามารถบอกได่ว่า interface ใดกำลงรันอยู่ ดู การสนับสนุุน interface Fusion
  • API เพิ่่ม. Antimatter เพิ่่ม endpoint ส่า feature ของตัวเอง: community attributes, timeouts, messages on top, message requests, channel and category overrides, channel export, และฟิลด์ใหม์ใน communities ดู สิ่่งท่ี Antimatter เพิ่่มใน API
  • Feature เพิ่่มส่าข้อความ. ไฟล์แนบในข้อความสามารถแสดง pipeline stages และกราฟขนาดเลก็; โพสต์สามารถเปน inline replies หรือ spoilers
  • Web app hooks เพิ่่ม ส่าแอพ: รายการในเมนู "+" ของ composer, tabs ใน emoji picker, panel ใน channel view, footer ใต้ช่องใน sidebar, และรายการในหน้าง integrations ดู Hooks ท่ี Antimatter มีเพีียง
  • ไม่มี่ไลเซ่นส์. ทุุก feature ใชได่โดยไม่ต้องไลเซ่นส์ key Endpoint ส่าไลเซ่นส์, trial และ enterprise upgrade ไหม่อยู้แล้; GET /api/v4/license/client ยังก้บอยู้ส่า client ท่ีถาม บางแอพท่ีตั้ดส้างส่า edition ท่ีตองเสียมงของ Mattermost จะตรวจไลเซ่นส์เองและปัดเสยการรัน
  • ชื่่อ. Teams เปน community ใน interface, แต่ API และโค้ดยังใชคำ team Environment variables ใช prefix AM_, คำสั่ง command-line เปน amctl และ server binary เปน antimatter

ทุกอย่างเปิดซอร์สในองค์กร AntimatterChat บน GitHub ทุก repository ทำงานบน main branch

RepositoryСодержимое

desktop-app, mobile-app, push-proxyแอปเดสก์ท็อปและแอปมือถือ รวมถึงบริการที่ส่งต่อ push notifications ไปยังโทรศัพท์
antimatter.chatเว็บไซต์นี้และเอกสารประกอบ
communityIssues และ discussions สำหรับทุกส่วนของ Antimatter

ก่อนที่คุณจะเริ่่ม

  • เตรียมเซิร์ฟเวอร์สำหรับทดสอบ. วิธีที่เร็วที่สุดคือใช้ Docker image: ดูที่ การติดตั้ง Antimatter. หากต้องการทำงานกับ Antimatter โดยตรง ดูที่ การคอมไพล์จากซอร์สโค้ด.
  • ตรวจสอบว่าเซิร์ฟเวอร์อนุญาตให้ทำอะไรได้บ้าง. ฟีเจอร์การเชื่อมต่อหลายอย่างถูกปิดไว้โดยค่าเริ่มต้นและต้องอาศัยผู้ดูแลระบบ: personal access tokens, บัญชีบอท, การเปลี่ยนชื่อผู้ใช้และไอคอน, และการอัปโหลดแอป แต่ละหน้าจะระบุการตั้งค่าที่จำเป็นไว้
  • จดจำ URL ของเว็บไซต์. ตัวอย่างใช้ https://chat.example.com. ให้แทนที่ด้วยที่อยู่ของเซิร์ฟเวอร์ของคุณ

ในคู่มือนี้

  • REST API: การยืนยันตัวตน, ทรัพยากรหลัก, การแบ่งหน้า, ข้อผิดพลาด, ข้อจำกัดของอัตรา, WebSocket, ไลบรารีสำหรับไคลเอนต์ และส่วนเพิ่มเติมของ Antimatter
  • Webhooks: Webhooks ที่รับเข้าและส่งออก, payloads, ไฟล์แนบ และการ์ด
  • คำสั่่งสแลช: คำสั่งแบบกำหนดเอง, คำขอและคำตอบ, การเติมอัตโนมัติ
  • บอทและข้อความแบบโต้ตอบ: บัญชีบอท, ปุ่ม, เมนู และกล่องโต้ตอบ
  • การเขียนแอป: โครงสร้างของปลั๊กอิน, server hooks, ฐานข้อมูลแอปบนเว็บ, Fusion, การตั้งค่า, การเก็บข้อมูล, การแปลภาษา และการแพ็กเกจ
  • การคอมไพล์จากซอร์สโค้ด: เซิร์ฟเวอร์, อินเทอร์เฟซบนเว็บ, Docker image และแอป
  • การมีส่วนร่วม: issues, pull requests, สไตล์, การแปลภาษา, ความปลอดภัย และใบอนุญาต
ยินดีต้อนรับคำถามใน การสนทนาของชุมชน. รายงานบั๊กใน issues ของชุมชน.
