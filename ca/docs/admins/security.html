Seguretat

Una llista de verificació per endurir un servidor d'Antimatter: què exposar, els límits i les configuracions de privadesa a revisar, els serveis externs amb els quals el servidor es comunica i com informar d'un problema de seguretat.

Què exposar

PortServeiExposició
443/tcp, 443/udp, 80/tcpEl vostre proxy HTTPS (Caddy o nginx)Públic: així és com la gent accedeix a Antimatter.
8443/udp i 8443/tcpMèdia de trucadesPúblic, si la gent utilitza trucades des de fora de la vostra xarxa.
8065/tcpEl servidor web d'AntimatterNomés per al proxy: publiqueu-lo a 127.0.0.1 (HTTP_PORT=127.0.0.1:8065).
8067/tcpMètriquesNomés xarxa privada, quan està habilitat. Sense inici de sessió.
8074/tcp i udpXerrada del clústerNomés entre els nodes del clúster.
5432, 9000, 8080, 8066PostgreSQL, emmagatzematge de fitxers, servei de GIF, proxy de notificacions pushMai. Els fitxers compose els mantenen en xarxes internes sense cap port publicat.

El fitxer compose del lloc també executa cada contenidor amb no-new-privileges, executa Antimatter com a usuari no privilegiat en una imatge distroless i executa el servei de GIF amb un sistema de fitxers només de lectura. La base de dades, l'emmagatzematge i el servei de GIF es troben en una xarxa sense accés a Internet.

Llista de verificació després de la instal·lació

  1. Creeu el primer compte d'administrador abans que ningú altre pugui accedir al servidor (Instal·lació).
  2. Serveu Antimatter només per HTTPS i establiu l'URL del lloc a l'adreza https:// (Domini i HTTPS).
  3. Mantingueu .env, config.json i les claus TLS legibles només per root (o l'usuari del servidor): chmod 600 .env.
  4. Decideu qui pot crear comptes, mantingueu Activa el servidor obert desactivat a menys que la comunitat sigui pública i activeu Requereix la verificació del correu electrònic un cop el correu funcioni (Inici de sessió i comptes).
  5. Activeu l'autenticació de factor múltiple i imposeu-la, com a mínim, per als comptes dels administradors, o utilitzeu la del vostre proveïdor d'identitat.
  6. Revisiu les connexions externes següents, en particular el servidor STUN que les Trucades utilitzen per defecte.
  7. Feu còpies de seguretat i proveu una restauració (Còpies de seguretat i actualitzacions).
  8. Mantingueu les imatges actualitzades: les correccions de seguretat arriben amb les noves imatges.

Limitació de freqüència

El servidor pot limitar el nombre de sol·licituds d'API que fa cada client. Per defecte, està desactivat. A Consola del sistema › Entorn › Limitació de freqüència:

ParàmetreClauValor per defecte
Activa la limitació de taxesRateLimitSettings.Enabledesactivat
Consultes màximes per segonRateLimitSettings.PerSec10
Mida màxima de picRateLimitSettings.MaxBurst100
Mida de l'emmagatzematge en memòriaRateLimitSettings.MemoryStoreSize10000 clients seguits
Varia el límit de freqüència segons l'adreça remotaRateLimitSettings.VaryByRemoteAddractivat
Varia el límit de freqüència segons l'usuariRateLimitSettings.VaryByUserdesactivat

Darrere d'un proxy, els límits per adreça només funcionen si el servidor coneix l'adreça de cada client (ServiceSettings.TrustedProxyIPHeader i ServiceSettings.TrustedProxyIPs, vegeu Adreces de clients darrere d'un proxy). En cas contrari, totes les sol·licituds semblen provenir del proxy, i tothom comparteix un sol límit. El mateix passa amb el filtratge per IP i amb les adreces als registres d'auditoria.

Els intents d'inici de sessió es limiten per separat: Intents d’inici de sessió màxims (10) bloqueja un compte després d'aquest nombre de contrasenyes incorrectes.

Filtratge per IP

Consola del sistema › Configuració del lloc › Filtratge per IP limita l'accés al servidor per adreça IP, amb regles de permís i de denegació (una adreça o un interval CIDR cadascuna). Amb Activa el filtratge IP activat, les persones la seva adreça coincideix amb una regla de denegació, o no coincideix amb cap regla de permís quan n'hi ha, no poden accedir al servidor. La pàgina rebutja les regles que bloquejarien la pròpia adreça. Darrere d'un proxy, configureu primer les adreces de clients (Adreces de clients darrere d'un proxy): en cas contrari, totes les sol·licituds semblen provenir del proxy.

Ignorar, bloquejar i sol·licituds de missatge

Amb Activa ignorar, bloquejar i sol·licituds de missatge activat (l'opció per defecte), les persones poden ignorar-se i bloquejar-se mútuament, i poden triar rebre missatges directes de persones que no coneixen com a sol·licituds de missatge, que no les notifiquen fins que s'accepten. Això és adequat per a comunitats públiques. En un entorn de treball on els col·legues han de poder contactar-se sempre, desactiva-ho (AM_PRIVACYSETTINGS_ENABLEUSERBLOCKING=false): ja no s'aplica cap d'aquestes restriccions, però es mantenen les llistes i les opcions que les persones van triar, i tornen a aplicar-se si l'actives de nou.

Sessions i tokens

  • Durada de les sessions i temps d'inactivitat: consulta Inici de sessió i comptes. Sessions més curtes signifiquen que un portàtil o telèfon perdut romandrà iniciat durant menys temps.
  • Habilita els tokens d’accés personals (ServiceSettings.EnableUserAccessTokens, desactivat) permet a les persones crear tokens d'API; Durada màxima dels tokens d’accés personals (dies) els limita. Tots dos es troben a Consola del sistema › Integracions › Gestió d'integracions.
  • Per tancar la sessió de tothom alhora, per exemple després d'una possible violació de seguretat: Revoca totes les sessions a Consola del sistema › Gestió d'usuaris › Usuaris.

Connexions amb serveis externs

Antimatter no contacta cap servei operat per Mattermost, Inc. No envia telemetria, informes d'errors ni comprovacions d'actualitzacions de seguretat, i no recupera avisos de producte. Una configuració portada des de Mattermost que encara nomena un dels serveis de Mattermost (els seus serveis de notificacions push, el seu mercat d'aplicacions, els seus avisos o el seu servidor STUN per a trucades) no fa que el servidor els contacti: aquestes adreces s'ignoren.

El servidor i les aplicacions es connecten a altres serveis externs només per a les funcions que els necessiten, i als serveis que configureu:

Per canviar-ho, consulta Trucades.

Per defecte, el servidor rebutja les connexions a adreces privades i de bucle per a aquests serveis (vistes prèvies d’enllaços, webhooks, aplicacions), de manera que un missatge o una integració no es pot utilitzar per accedir a la teva xarxa interna. Enumera els amfitrions interns als quals pot connectar-hi a Permet connexions internes no fiables a (ServiceSettings.AllowedUntrustedInternalConnections, a Consola del sistema › Entorn › Desenvolupador); el fitxer compose del lloc n’enumera gifs allà.
