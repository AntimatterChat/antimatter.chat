بدون مفتاح تشفير الذكاء الاصطناعي، لا يستطيع الخادم المُستعاد قراءة مفاتيح واجهة برمجة التطبيقات الخاصة باتصالات النماذج، ويجب إعادة إدخال كل مفتاح يدويًا. احتفظ بنسخة من المفتاح منفصلة عن نسخ احتياطية لقاعدة البيانات، حتى لا تحتوي النسخة المسروقة على كليهما. راجع مفتاح التشفير.

قاعدة البيانات والملفات متلازمان: انسخهما احتياطياً في نفس الوقت، واحتفظ بنسخ منهما خارج الخادم. تبدأ أسماء الأحجام باسم مشروع compose، antimatter (تُعرض القائمة عبر docker volume ls).

النسخ الاحتياطي

من مجلد compose.yaml. إيقاف Antimatter أولاً يمنحك نسخة متسقة تماماً؛ والنسخة المأخوذة أثناء التشغيل غالباً ما تكون جيدة، لكن الملفات المرفوعة أثناء النسخ الاحتياطي قد لا تكون موجودة فيها.

stamp=$(date +%Y%m%d-%H%M%S)
mkdir -p backups
docker compose stop antimatter
# Database
docker compose exec -T postgres pg_dump -U antimatter -d antimatter -Fc \
    > "backups/antimatter-db-$stamp.dump"
# File storage, GIF service and the data directory (the AI key file)
for v in files gifs data; do
    docker run --rm -v "antimatter_$v:/data:ro" -v "$PWD/backups:/backup" \
        alpine tar -czf "/backup/antimatter-$v-$stamp.tar.gz" -C /data .
done
docker compose start antimatter
# Secrets
cp .env "backups/env-$stamp"

إذا لم تضبط AM_AI_ENCRYPTION_KEY، فإن ملف مفتاح الخادم موجود في مجلد data، والذي يحفظه الحلقة أعلاه مع الملفات. الأفضل وضع محتواه في .env كما يشرح مفتاح التشفير، والاحتفاظ بنسخة منه منفصلة عن نسخ احتياطية لقاعدة البيانات.

شغّله من cron للنسخ الاحتياطي اليومي، وانسخ مجلد backups/ إلى جهاز آخر. احتفظ بنسخ .env بأمان مساوٍ للخادم: فهي تحتوي على كلمات المرور الخاصة به.

لنسخ الملفات المرفوعة كائنًا تلو الآخر (على سبيل المثال إلى تخزين S3 آخر)، استخدم أداة سطر الأوامر AWS الخاصة بخدمة bucket:

docker compose run --rm -v "$PWD/backups/files:/backup" bucket \
    "aws --endpoint-url http://files:9000 s3 sync s3://antimatter /backup"

عند استخدام أرشيف إصدار، احفظ نسخة احتياطية من قاعدة البيانات باستخدام pg_dump -Fc، ومجلدي data/ وconfig/ باستخدام أدواتك المعتادة (يحتوي data/ على ملف مفتاح الذكاء الاصطناعي). عند استخدام الحزم، احفظ نسخة احتياطية من قاعدة البيانات بالطريقة نفسها، ومن /etc/antimatter، /var/lib/antimatter، /etc/gifs-server و/var/lib/gifs-server.

الاستعادة على مضيف جديد

ضع compose.yaml، و .env المحفوظ، والنسخ الاحتياطية في مجلد جديد، ثم:

stamp=20261016-030000          # the backup to restore
docker compose create           # creates the volumes, starts nothing
docker compose up -d postgres
docker compose exec -T postgres pg_restore -U antimatter -d antimatter --no-owner \
    < "backups/antimatter-db-$stamp.dump"
for v in files gifs data; do
    docker run --rm -v "antimatter_$v:/data" -v "$PWD/backups:/backup" \
        alpine tar -xzf "/backup/antimatter-$v-$stamp.tar.gz" -C /data
done
docker compose up -d

استخدم نفس ملف .env: يجب أن تحتفظ وحدة التخزين وقاعدة البيانات بكلمات المرور التي كانت لديها، وتحتاج اتصالات النماذج إلى نفس مفتاح تشفير الذكاء الاصطناعي. إذا كان المضيف الجديد له عنوان آخر، حدّث SITE_URL (وDOMAIN).

اختبر نسخك الاحتياطية من خلال استعادتها على جهاز آخر من حين لآخر.

الترقية

ملفات Compose التي تم تنزيلها قبل 17 أكتوبر 2026 لم تحتوي على مجلد data: كان ملف مفتاح الذكاء الاصطناعي داخل الحاوية. قبل استخدام ملف compose.yaml الجديد، وإذا لم يحتوي .env على AM_AI_ENCRYPTION_KEY، احفظ المفتاح الذي أنشأه الخادم: echo "AM_AI_ENCRYPTION_KEY=$(docker compose exec -T antimatter cat /antimatter/data/ai-encryption.key)" >> .env. إذا لم يجد الأمر أي ملف، فلا توجد أي اتصال نموذج قد حفظ مفتاحًا بعد.
  1. أنشئ نسخة احتياطية.
  2. غيّر وسم الصورة في .env (ANTIMATTER_IMAGE)، إذا كنت تثبته، كما يُوصى به.
  3. اسحب الصورة وأعد التشغيل: 
    docker compose pull
docker compose up -d
docker compose logs -f antimatter

عند بدء التشغيل، يحدّث الخادم مخطط قاعدة البيانات (يمكنك متابعة ذلك في السجل؛ وقد يستغرق الأمر عدة دقائق على خادم كبير) ويثبّت الإصدارات الأحدث من التطبيقات المضمّنة من الصورة. عند استخدام أرشيف الإصدار: أوقف الخادم، واستبدل كل شيء باستثناء config/، data/، logs/، plugins/، وclient/plugins/ بمحتوى الأرشيف الجديد، ثم أعد تشغيله. عند استخدام حزمة ‎.deb أو ‎.rpm، ثبّت الحزمة الجديدة كما يشرح ترقية الحزمة.

التحديثات تتم للأمام فقط. بمجرد أن يحدّث خادم أحدث قاعدة البيانات، لا يمكن للإصدار الأقدم استخدامها: للرجوع، استعِد النسخة الاحتياطية المأخوذة قبل التحديث. وينطبق الأمر نفسه على الانتقال من antimatter-next إلى antimatter.

الإصدارات

يُبلّغ خادم Antimatter عن إصدار خط Mattermost الذي يستند إليه (حاليًا 12.0.0). للإصدارات على GitHub، مع أرشيفاتها وحزمها، أرقام إصدار خاصة، في سلسلة 0.9.0 خلال فترة بيتا: يعرض antimatter version ذلك كـرقم الإصدار. تُعاد بناء الصور من فروع main: antimatter-next كل ليلة (وسوم nightly-<YYYYMMDD>)، وكلا من الصور عند كل تغيير (وسوم sha-<commit>). ثبّت أحد هذه الوسوم، وترفّع عمدًا، واحتفظ بتدوين الوسم السابق حتى تعرف أي نسخة احتياطية تتوافق معه.

الإصدارات الرئيسية لـ PostgreSQL

يستخدم ملف compose postgres:17-alpine. يحتاج Antimatter إلى PostgreSQL 15 أو أحدث. لا يمكن لإصدار رئيسي جديد من PostgreSQL قراءة مجلد بيانات الإصدار السابق: للانتقال إلى إصدار جديد، قم بتصدير قاعدة البيانات، ابدأ الإصدار الجديد على مجلد جديد، واستعِد التصدير فيه.

الترقية إلى 0.9.0

يُجري أول تشغيل للإصدار 0.9.0 (أو صورة مبنية من 17 أكتوبر 2026 فصاعدًا) بعض التغييرات لمرة واحدة على البيانات. يُنفَّذ كل منها مرة واحدة، ويُسجَّل في قاعدة البيانات. تُنقل هذه التغييرات ما كان متروكًا على إعداد افتراضي قديم إلى الإعداد الجديد، وتترك ما اختاره المدير. تابعها في السجل.

إذا كان Antimatter مخصصًا لشركة أو مؤسسة، اضبط نوع المجتمعات الجديدة على مكان العمل قبل الترقية: AM_TEAMSETTINGS_DEFAULTCOMMUNITYKIND=workplace. تمنح الترقية كل مجتمع النوع الذي يحمله هذا الإعداد في تلك اللحظة، وتكون المكالمات معطلة افتراضيًا في قنوات مجتمعات نوع المجتمع. راجع مكان العمل أو المجتمع.
العنصرالتغيير
أنواع المجتمعيحصل كل مجتمع على نوع، المجتمع أو مكان العمل: قيمة نوع المجتمعات الجديدة (TeamSettings.DefaultCommunityKind) عند أول تشغيل. يُحفظ النوع المُعيَّن مسبقًا. يمكن لمديري المجتمع تغيير نوع مجتمعهم لاحقًا، في إعدادات الفريق › قنوات › نوع المجتمع.
من يُرشف القنواتلم يعد أعضاء القنوات يقومون بأرشفة القنوات التي ينتمون إليها، بل يقوم بذلك مسؤولو المجتمع. في بيئة العمل، يقوم مسؤولو القناة (من أنشأها، ومن جعلهم مسؤولين) بأرشفتها أيضًا. هذا التغيير يؤثر على أدوار مخطط النظام؛ أما مخططات الأذونات التي أنشأها مدير النظام لبعض المجتمعات فتبقى كما هي.
دور المشرفين في قوالب التخطيطيحصل دور المشرفين الذي تحصل عليه المجتمعات من قالب التخطيط على صلاحية إزالة أشخاص، وهي صلاحية ضرورية لإيقاف مؤقت للأشخاص وإزالتهم. لا تتغير إلا الأدوار التي ما زالت مطابقة تمامًا لما أنشأه القالب؛ أما الأدوار التي عدّلها شخص ما فتُترك كما هي.
الأدوار التي تحتوي على مديرتصبح الآن أيّ دور مجتمعي مُفعّل بمفتاح مدير حائزًا على جميع الصلاحيات التي يمكن لإداريي المجتمع تنفيذها، كما يشير المفتاح، وليس فقط إعدادات المجتمع.
حدّ الأعضاءالحد الأقصى لعدد الأعضاء في كل مجتمع (TeamSettings.MaxUsersPerTeam) ينتقل من 50، وهو الحد الافتراضي السابق، إلى 0 (بدون حد). تُحفظ أي قيمة أخرى، وكذلك أي حد مُعيَّن باستخدام AM_TEAMSETTINGS_MAXUSERSPERTEAM.
اتصالات النماذجيحصل مسؤولو النظام على إدارة اتصالات النماذج، بينما يحصل مسؤولو المجتمع (والأدوار التي تحمل صلاحية مدير) على إدارة اتصالات نماذج مجتمعهم. تصبح خدمات الذكاء الاصطناعي لتطبيق الوكلاء اتصالات نماذج على مستوى الخادم، راجع ما يلي.
تصبح ساحة المدينة القناة العامةيتم إعادة تسمية القناة الافتراضية لكل مجتمع من town-square (Town Square) إلى general (General). تحافظ القناة على معرّفها وأعضائها ورسائلها وإعداداتها، بالإضافة إلى الاسم المعروض الذي اختاره المسؤولون. لا تزال الروابط القديمة والبحث باستخدام town-square تؤدي إلى القناة. المجتمعات التي لديها بالفعل قناة باسم general، حتى لو كانت مؤرشفة، تحتفظ بقناة town-square كقناة افتراضية، وكذلك المجتمعات التي تكون قناة town-square فيها مؤرشفة: تُذكر هذه القنوات في السجل، ويمكن للمسؤولين إعادة تسميتها.

خدمات تطبيق الوكلاء

ينسخ الترقية كل خدمة ذكاء اصطناعي لتطبيق الوكلاء إلى اتصال نموذج على مستوى الخادم، يُشارَك مع كل مجتمع ويمكن استخدامه من قبل الجميع باستثناء الضيوف (فعّل الضيوف أيضاً للسماح لهم بذلك). تُشفَّر المفاتيح أثناء النقل، لذا يحتاج الخادم إلى مفتاح تشفير الذكاء الاصطناعي الخاص به: في حالة التجمّع الذي تُخزَّن ملفاتّه في S3، اضبط AM_AI_ENCRYPTION_KEY أولاً، وإلا فسيبقى النسخ في انتظار التشغيل التالي. ثم افحص وحدة التحكم بالنظام › الذكاء الاصطناعي › اتصالات النماذج:

  • يحافظ كل اتصال على معرّف خدمته، لذا لا يزال وكلاء التطبيق وإعداد الترجمة التلقائية المرتبط بخدمة الوكلاء يجدونه.
  • تتحول خدمات OpenAI، وOpenAI المتوافقة، وAnthropic، وMistral، وCohere، وGemini إلى اتصالات بنهاية OpenAI المتوافقة (أو Anthropic). تتحول خدمة Azure إلى اتصال بنهاية OpenAI المتوافقة للمورد: اختبرها.
  • تُوسم خدمات AWS Bedrock، وGoogle Vertex AI، وCohere North، والأنواع غير المعروفة بـتحتاج إلى انتباه، مع ذكر السبب. لا تُنسخ بيانات اعتماد السحابة الخاصة بها: وجّهها إلى نهاية OpenAI المتوافقة للمورد أو إلى بوابة مثل LiteLLM، ثم احفظ.
  • تتحول خدمة التضمين إلى نموذج التضمينات للاتصال الذي يحمل نفس العنوان والمفتاح، أو إلى اتصال خاص بها. تحصل خدمة النسخ النصي على نموذج whisper-1.
  • عندما لا يكون هناك اتصال بعد للإعادة الصياغة والملخصات، تحصل على الخدمة والنموذج الخاص بالوكيل الافتراضي للتطبيق.

وكلاء تطبيق الوكلاء

بعد الخدمات، يحوّل الترقية كل وكيل من تطبيق الوكلاء (الذي أصبح الآن تطبيق الدردشة بالذكاء الاصطناعي) إلى وكيل على مستوى الخادم، على الحساب نفسه: اتصاله (المنسوخ من خدمته)، ونموذجه، وتعليماته، واستدلاله، وأدواته، ومن يمكنه استخدامه. ثم يجيب الخادم نيابةً عن هؤلاء الوكلاء. وفي الحالات التي كان فيها التطبيق يحدّ من وكيل بطريقة لا يعبر عنها وكلاء الخادم (مثل القنوات التي يجيب فيها، أو قوائم الحظر، أو الوصول القائم على السمات)، يتم تقييد الوكيل بأعضاء تلك القنوات، أو لا يُسمح لأحد باستخدامه، ويُميَّز بأنه يحتاج إلى انتباه، وكذلك يُفعل ذلك مع أي وكيل لم تتحول خدمته إلى اتصال. راجعهم في التكاملات › الوكلاء. أما إعدادات التطبيق الأخرى فتبقى كما هي.

تغييرات أخرى في الإعدادات الافتراضية

  • المكالمات: وضع الاختبار غير مفعّل وتفعيل الفيديو مفعّل افتراضياً. يُحفظ أي خيار محفوظ في الإعدادات. تتبع المكالمات أيضاً نوع المجتمع (انظر المكالمات والصوت).
  • وضع الرسائل في المقدمة متاح لإداريي القناة، وإداريي المجتمع، والمشرفين (مع إدارة الرسائل)؛ لا يزال أعضاء الرسائل المباشرة أو الجماعية قادرين على ذلك.
  • يمكن للقنوات المؤرشفة قبول أعضاء جدد، الذين يقرؤون سجلها. لا ينشر أحد، ولا يرد بردود فعل، ولا يغيّر أي شيء فيها.

الانتقال من Mattermost

يستخدم Antimatter مخطط قاعدة بيانات Mattermost ويضيف جداوله الخاصة، لذا يمكنه الاستيلاء على قاعدة بيانات PostgreSQL وملفات خادم Mattermost. جرّب ذلك على نسخة أولاً:

  1. أنشئ نسخة احتياطية من قاعدة بيانات Mattermost، وتخزين الملفات الخاص بها (data/ أو حاوية S3) وconfig.json، ثم أوقف Mattermost.
  2. استعِد قاعدة البيانات في PostgreSQL الخاص بـ Antimatter، أو وجّه Antimatter إلى نسخة منها (AM_SQLSETTINGS_DATASOURCE).
  3. انسخ الملفات إلى تخزين Antimatter، مع الحفاظ على مساراتها: إلى حاوية antimatter باستخدام أداة S3، أو إلى data/ باستخدام أرشيف إصدار.
  4. أعد استخدام إعداداتك: انسخ config.json، أو انقله إلى قاعدة البيانات باستخدام amctl --local config migrate (انظر الإعدادات). تبقى متغيرات البيئة MM_ الخاصة بك تعمل؛ أعد تسميتها إلى AM_ عند الحاجة.
  5. ابدأ تشغيل Antimatter وتابع السجل أثناء ترقية قاعدة البيانات. ثم راجع وحدة التحكم بالنظام › الإضافات › إدارة الإضافات. يقوم Antimatter بتثبيت إصداراته الخاصة من المكالمات، وأدلة التشغيل، ولوحات كانبان (اللوحة)، والدردشة بالذكاء الاصطناعي، والتكاملات عندما تكون أحدث من الإصدار المثبت. وإذا كان لدى Mattermost إصدار أحدث من أحد هذه التطبيقات، فأزل ذلك التطبيق وأعد تشغيل Antimatter، ليتم تثبيت إصداره الخاص.
  6. قم بإعداد الإشعارات الفورية مرة أخرى باستخدام وكيل الإشعارات الخاص بك: لا يرسل Antimatter أي إشعارات إلى خدمات Mattermost الفورية، سواء كانت تجريبية أو مستضافة، لأنها تصل فقط إلى تطبيقات Mattermost الخاصة. حتى تقوم بتغيير خادم الإشعارات الفورية، لن يرسل الخادم أي إشعارات فورية (راجع الإشعارات الفورية).

لا يتواصل Antimatter مع أي خدمة تشغّلها Mattermost, Inc. (راجع الاتصالات مع الخدمات الخارجية)، حتى إذا كان تكوينك لا يزال يذكر خدمةً منها:

  • يُحفظ خادم الإشعارات الفورية الخاص بـ Mattermost في الإعدادات لكنه لا يُستخدم أبداً؛
  • تُفرَّغ عناوين Mattermost الخاصة بسوق التطبيقات (عنوان URL للمتجر) والإشعارات المتعلقة بالمنتج؛
  • تُستبدل روابط تنزيل التطبيقات التي كانت هي الافتراضية في Mattermost (رابط صفحة تنزيل تطبيقات Antimatter، رابط تنزيل تطبيق Android، ورابط تنزيل تطبيق iOS) بصفحات تنزيل تطبيقات Antimatter على GitHub؛ الروابط التي اضبطتها بنفسك تُحفظ؛
  • يستخدم تطبيق المكالمات خادم STUN العام من Cloudflare بدلاً من خادم Mattermost، دون تغيير الإعداد المحفوظ (راجع المكالمات)؛
  • تمت إزالة فحص التحديثات الأمنية والإبلاغ عن الأعطال، وكذلك إعدادات وحدة التحكم بالنظام الخاصة بها (تفعيل التنبيهات الأمنية، تفعيل التشخيص والإبلاغ عن الأخطاء) وصفحة الإشعارات.

أصبح المقبس الخاص بالوضع المحلي /var/tmp/antimatter_local.socket؛ ويحاول amctl أيضاً استخدام المقبس القديم /var/tmp/mattermost_local.socket. يدعم Mattermost قاعدة بيانات PostgreSQL فقط في إصداراته الحديثة، وكذلك يفعل Antimatter: انقل قاعدة بيانات MySQL إلى PostgreSQL أولاً. العودة إلى Mattermost بعد ترقية Antimatter لقاعدة البيانات تعني استعادة نسخة احتياطية من Mattermost.

تصدير واستيراد البيانات

تنسيق التصدير الشامل ينقل البيانات بين الخوادم: الخادم بأكمله، أو بعض المجتمعات، أو بعض القنوات، مع المرفقات وصور الملفات الشخصية والرموز التعبيرية المخصصة إذا رغبت في ذلك.

# on the source server
amctl export create --team-name design --include-profile-pictures
amctl export list
amctl export download <export file> design.zip
# on the destination server
amctl import upload design.zip
amctl import list available
amctl import process <uploaded file> --imported-users active

راقب المهام باستخدام amctl export job list وamctl import job list. عند تصدير مجتمع أو قناة، يكون --imported-users مطلوبًا: active إذا انتقل الأشخاص إلى هذا الخادم، وinactive عند الاستيراد إلى خادم لديهم فيه حسابات بالفعل، حتى تبقى الحسابات المُنشأة من تطابقات غير مؤكدة موقوفة حتى يفحصها مدير. يستورد --destination-team-name إلى مجتمع موجود. تُحفظ عمليات التصدير والاستيراد على تخزين الخادم (ExportSettings.Directory، ImportSettings.Directory) لمدة 30 يومًا افتراضيًا.

على الخادم نفسه، تنجز antimatter export bulk وantimatter import bulk --apply نفس الشيء من الملفات، دون استخدام واجهة برمجة التطبيقات.
