التثبيت باستخدام Docker Compose

هذه هي الطريقة الموصى بها. ملف compose واحد يشغّل Antimatter وPostgreSQL وتخزين الملفات وخدمة GIF. تحتاج إلى خادم Linux مزوّد بـ Docker Engine وإضافة Compose الخاصة به (docker compose)، ونواة معالجة مركزي (CPU) واحدة على الأقل و4 جيجابايت من الذاكرة أو أكثر.

1. تنزيل ملف compose

mkdir antimatter && cd antimatter
curl -fsSLO https://antimatter.chat/compose.yaml

2. إنشاء ملف .env

يقوم ملف compose بقراءة إعداداته من ملف .env في نفس المجلد. أنشئ هذا الملف باستخدام أسرار عشوائية:

cat > .env <<EOF
SITE_URL=http://localhost:8065
POSTGRES_PASSWORD=$(openssl rand -hex 24)
S3_SECRET_KEY=$(openssl rand -hex 24)
GIFS_API_KEY=$(openssl rand -hex 24)
AM_AI_ENCRYPTION_KEY=$(openssl rand -base64 32)
EOF
chmod 600 .env

اضبط SITE_URL على العنوان الذي سيكتبه المستخدمون في متصفحاتهم، مثل http://192.168.1.20:8065 على شبكة محلية أو https://chat.example.com مع نطاق. احتفظ بملف .env: فقاعدة البيانات والتخزين تستخدمان هذه كلمات المرور منذ التشغيل الأول، وتُشفَّر مفاتيح API لاتصالات نماذج الذكاء الاصطناعي باستخدام AM_AI_ENCRYPTION_KEY، وتحتاج إلى نفس الملف لاستعادة نسخة احتياطية.

3. التشغيل

docker compose up -d
docker compose ps

يستغرق التشغيل الأول دقيقة أو دقيقتين: يقوم PostgreSQL بإنشاء قاعدة البيانات، وخدمة bucket ذات التشغيل الواحد تنشئ حاوية التخزين، وخدمة gifs-stickers ذات التشغيل الواحد تستورد مجموعة الملصقات المبدئية، وAntimatter تنشئ جداولها. تابع العملية باستخدام docker compose logs -f antimatter.

لاستخدام اسم نطاق وHTTPS من البداية، راجع النطاق وHTTPS: باستخدام ملف compose، الأمر لا يتطلب سوى سطرين إضافيين في .env وملف https.

PostgreSQL، والتخزين، وخدمة GIF على شبكة داخلية (private) لا تملك اتصالاً بالإنترنت، ولا ينضم إليها سوى Antimatter. لا ينشر أي منها منفذًا.

لا يحتفظ حاوية Antimatter بأي شيء على القرص: إعداداتها في قاعدة البيانات (يشير AM_CONFIG إليها)، وملفاتها وتطبيقاتها في خدمة التخزين. يمكنك حذف الحاوية وإنشائها من جديد في أي وقت. مجلد data الخاص بها يحتوي فقط على ملف مفتاح تشفير الذكاء الاصطناعي، الذي ينشئه الخادم عندما يكون AM_AI_ENCRYPTION_KEY فارغاً. كل ما يجب نسخه احتياطياً موجود في مجلدات postgres، files، gifs، وdata، بالإضافة إلى ملف .env الخاص بك.

اختر صورة

يُنشر صورتان لـ Antimatter، وكلاهما لـ linux/amd64 وlinux/arm64، وكلاهما مبنيان من فرع main لكل مستودع:

الصورةالتطبيقات المدمجةالوسوم
ghcr.io/antimatterchat/antimatterالوكلاء، المكالمات، GitHub، GitLab، Jira، Kanban، المقاييس، وأدلة التشغيل.latest، X.Y.Z للإصدارات، sha-<commit>
ghcr.io/antimatterchat/antimatter-nextنفس الشيء، بالإضافة إلى القنوات الصوتية، الاستطلاعات، البريد، التقويم، الملاحظات، السبورة البيضاء، GIF، قوائم المهام، والميمات. يُعاد بناؤه كل ليلة.latest, nightly, nightly-<YYYYMMDD>, sha-<commit>

يستخدم ملف compose الخاص بالموقع antimatter-next، لأن خدمة GIF ومعظم التطبيقات الموصوفة في هذا الموقع موجودة فقط في تلك الصورة. لتغيير الصورة، اضبط ANTIMATTER_IMAGE في .env ثم نفّذ docker compose up -d.

يتغير latest تحتك. في بيئة الإنتاج، ثبّت وسمًا مثل nightly-20261015 أو sha-<commit>، وغيّره عمدًا عند الترقية. يقوم الخادم بترقية قاعدة بياناته عند بدء التشغيل، لذا لا يمكنك الرجوع إلى صورة أقدم، أو الانتقال من antimatter-next إلى antimatter، دون استعادة نسخة احتياطية أُخذت قبل ذلك. راجع النسخ الاحتياطي والترقيات.

داخل الصورة

  • يوجد الخادم في /antimatter، مع الملفات التنفيذية antimatter وamctl في /antimatter/bin (على PATH).
  • يعمل كمستخدم غير مخصص antimatter (uid 2000) على أساس distroless بسيط، دون shell.
  • المنافذ: 8065 (الويب وواجهة برمجة التطبيقات)، 8067 (المقاييس)، 8074 (العقدة)، 8443 UDP وTCP (المكالمات).
  • وضع المحلّي (ServiceSettings.EnableLocalMode) مفعّل، لذا يعمل amctl --local داخل الحاوية. يقوم فحص الحالة بتشغيل amctl system status --local.
  • تتواجد التطبيقات المضمّنة في /antimatter/prepackaged_plugins، وهي موقّعة بمفتاح توقيع تطبيقات Antimatter.
  • تتضمن الحزمة أدوات استخراج النصوص (pdftotext، wvText، unrtf، tidy)، مما يتيح البحث في محتوى المستندات المرفوعة.

ملفات compose أخرى

يحتوي مستودع antimatter-docker على إعداد للإنتاج في deploy/compose/: nginx مع شهاداتك الخاصة أو Let's Encrypt (certbot)، PostgreSQL، خدمة GIF الاختيارية (الملف الشخصي gifs)، وأحجام مسماة لإعدادات الخادم وبياناته وسجلاته، موثّقة في ملف README الخاص به. يستخدم الصورة المستقرة افتراضيًا ويخزّن الملفات على حجم محلي بدلاً من تخزين S3. استخدمه إذا كنت تفضّل nginx على Caddy، أو إذا كان لديك شهادات بالفعل.

إنشاء أول مدير

افتح SITE_URL في متصفحك وأنشئ حسابًا. أول حساب يُنشأ على خادم جديد يصبح مدير النظام، ثم يوجهك الإعداد لإنشاء أول مجتمع (وهو الاسم الذي تعتمده Antimatter للفريق أو مساحة العمل).

قم بذلك فورًا بعد أول تشغيل: حتى ذلك الحين، يصبح أول من يصل إلى الخادم مديره. لإنشاء الحساب من سطر الأوامر بدلاً من ذلك، قبل أن يصبح الخادم قابلًا للوصول من الخارج:

docker compose exec antimatter amctl --local user create --system-admin --email-verified \
    --email admin@example.com --username admin --password 'a-long-password'
docker compose exec antimatter amctl --local team create --name main --display-name "Main"
docker compose exec antimatter amctl --local team users add main admin

ثم سجّل الدخول في SITE_URL. ابدأ الأمر بمسافة لتجنب حفظ كلمة المرور في سجل shell الخاص بك (مع HISTCONTROL=ignorespace)، أو غيّر كلمة المرور بعد تسجيل الدخول.

الخطوات التالية بعد الدخول:

  1. بالنسبة لشركة أو منظمة، اضبط نوع المجتمعات الجديدة على مكان العمل، وغيّر نوع المجتمع الذي أنشأته بالفعل من إعداداته: مكان العمل أو المجتمع.
  2. حدد من يمكنه إنشاء حسابات: تسجيل الدخول والحسابات.
  3. اضبط البريد الإلكتروني حتى تعمل الدعوات وإعادة تعيين كلمات المرور: البريد الإلكتروني والإشعارات الدافعة.
  4. افتح منفذ المكالمات في جدار الحماية الخاص بك: المكالمات والصوت.
  5. تحقق من التطبيقات المفعّلة: التطبيقات المضمّنة.

تنزيل إصدار

بدون Docker، ثبّت Antimatter من ملفات الإصدار على GitHub: github.com/AntimatterChat/antimatter/releases. لكل إصدار رقم إصدار مثل 0.9.0، ووسمه هو نفس الرقم مع حرف v في البداية (v0.9.0).

Antimatter في مرحلة تجريبية: إصداراته ضمن سلسلة 0.9.0. الإصدار الذي يحتوي على لاحقة بعد شرطة في رقمه، مثل 0.9.0-rc.1، يُوسم بـ إصدار مسبق على GitHub. إنه إصدار تجريبي، يُنشر قبل الإصدار النهائي.

يحتوي كل إصدار على هذه الملفات، لخوادم amd64 وarm64:

الملفما هو
antimatter_<version>-1_amd64.deb, antimatter_<version>-1_arm64.debالحزمة الخاصة بـ Debian وUbuntu وتوزيعاتهما المشتقة.
antimatter-<version>-1.x86_64.rpm, antimatter-<version>-1.aarch64.rpmالحزمة الخاصة بـ Fedora وRHEL والتوزيعات المتوافقة مع RHEL.
antimatter-<version>-linux-amd64.tar.gz, antimatter-<version>-linux-arm64.tar.gzأرشيف الإصدار، لأي توزيع Linux، يُضبط يدويًا.
SHA256SUMSملف SHA-256 الخاص بكل ملف في الإصدار.

تحتوي الحزم والأرشيف على نفس البرنامج: الخادم (antimatter)، وأداة سطر الأوامر (amctl)، وكلا التطبيقين الويب (الواجهة الافتراضية والكلاسيكية)، والتطبيقات المدمجة، وقوالب البريد الإلكتروني، والترجمات. تضيف الحزم خدمة systemd وملف إعدادات، لذا كل واحدة منها تثبيت شامل: كل ما عليك فعله هو إضافة قاعدة بيانات PostgreSQL. لا توجد تنزيلات منفصلة للثنائيات: فهي موجودة في الأرشيف، في antimatter/bin/. وهي ثنائيات ثابتة، لذا تعمل على أي توزيع Linux من نفس معماريتها.

في أسماء الحزم، يُستبدل شرطة السطر السفلي في الإصدار التجريبي بعلامة الموجّه، وذلك حتى يرتّب مدير الحزم الإصدار التجريبي قبل الإصدار النهائي: يعطي الإصدار 0.9.0-rc.1 antimatter_0.9.0~rc.1-1_amd64.deb وantimatter-0.9.0~rc.1-1.x86_64.rpm. أما الأرشيف فيحتفظ بشرطة السطر السفلي.

يطبع antimatter version إصدار الإصدار كـرقم الإصدار، مع الالتزام الذي بُني منه كـتجزئة الإصدار. أما سطر الإصدار فيه فهو إصدار خط Mattermost الذي يستند إليه Antimatter.

التحقق من التحميل

حمّل الملف الذي تحتاجه وSHA256SUMS إلى نفس المجلد، من صفحة الإصدار أو باستخدام curl، ثم تحقق من الملف:

curl -fLO https://github.com/AntimatterChat/antimatter/releases/download/v<version>/antimatter_<version>-1_amd64.deb
curl -fLO https://github.com/AntimatterChat/antimatter/releases/download/v<version>/SHA256SUMS
sha256sum --check --ignore-missing SHA256SUMS

يجب أن يُدرج كل ملف حمّلته مع OK. أي نتيجة أخرى تعني أن الملف تالف أو غير مكتمل: حمّله مرة أخرى، ولا تثبّته. SHA256SUMS غير موقّع: يكشف عن التحميل التالف، ولا يثبت أكثر مما يثبته التحميل عبر HTTPS من GitHub.

تثبيت حزمة .deb أو .rpm

تثبّت الحزمة Antimatter كخدمة systemd، والتي تحتاج فقط إلى قاعدة بيانات للبدء. استخدمها على خادم 64-بت متوافق مع Debian أو Ubuntu أو Fedora أو RHEL مع systemd.

ما تثبّته الحزمة

المسارمحتواها
/opt/antimatterالبرنامج: bin/antimatter، bin/amctl، تطبيقات الويب (client/، client-fusion/)، التطبيقات المدمجة (prepackaged_plugins/)، القوالب، الترجمات والخطوط. يستبدلها كل ترقية.
/etc/antimatter/antimatter.envإعدادات الخدمة، كمتغيرات AM_: قاعدة البيانات، عنوان الموقع، خدمة GIF. قابلة للقراءة بواسطة root فقط. تحتفظ بها الترقيات.
/etc/antimatter/config/config.jsonملف الإعدادات، حيث يحفظ الخادم الإعدادات المُعدّلة في وحدة التحكم بالنظام. يُنشأ من /opt/antimatter/defaults/config.json عند التثبيت الأول، ولا يُستبدل بعد ذلك أبداً.
/var/lib/antimatterالملفات المرفوعة (data/) والتطبيقات المثبتة (plugins/، client-plugins/).
/var/log/antimatterملفات السجلات، إذا فعّلت تسجيل الملفات. إنه معطّل: تذهب السجلات إلى السجل.
/usr/lib/systemd/system/antimatter.serviceالخدمة.
/usr/bin/amctlرابط إلى /opt/antimatter/bin/amctl.

المجلدات التي يكتب إليها الخادم داخل /opt/antimatter (config، data، plugins، client/plugins وlogs) هي روابط إلى /etc/antimatter، /var/lib/antimatter و/var/log/antimatter. لذلك، لن يمسّ الترقية، التي تستبدل /opt/antimatter، بياناتك أبدًا. كما ينشئ الحزمة مستخدم النظام antimatter، الذي يشغّل الخادم ويمتلك هذه المجلدات.

تعتمد الحزمة على ca-certificates. وتوصي بـ PostgreSQL (postgresql في Debian وUbuntu، وpostgresql-server في Fedora وRHEL)، وmedia-types (mailcap في حالة .rpm)، وgifs-server، وهو خدمة GIF التي لها إصدار خاص بها (انظر أسفل). يقوم apt وdnf بتثبيت الحزم الموصى بها عند توفرها. وتقترح الحزمة poppler-utils، wv، unrtf وtidy (بدون wv في حالة .rpm): فهي تستخرج النص من المستندات المرفوعة، مما يتيح للبحث العثور على الكلمات داخلها. قم بتثبيتها بنفسك إذا أردت ذلك.

1. تثبيت الحزم

حمّل حزمة Antimatter وحزمة خدمة GIF الخاصة ببنيتك، وتحقق منهما كما هو موضح أعلاه، ثم ثبّت كلاهما في أمر واحد، حتى يتم تلبية توصية gifs-server (لأنها غير متوفرة في مستودعات التوزيعات):

# Debian, Ubuntu
sudo apt install ./antimatter_<version>-1_amd64.deb ./gifs-server_*_amd64.deb
# Fedora, RHEL
sudo dnf install ./antimatter-<version>-1.x86_64.rpm ./gifs-server-*.x86_64.rpm

احتفظ بـ ./: فهي تخبر apt وdnf بتثبيت ملف محلي. لتثبيت دون خدمة GIF، اترك حزمتها خارج الأمر. تمكّن الحزمة خدمة antimatter لكنها لا تبدأها، وتطبع الخطوات التالية.

2. إنشاء قاعدة البيانات

تتطلب Antimatter PostgreSQL 15 أو أحدث، على هذا الخادم أو على خادم آخر. تحقق من إصدار PostgreSQL الخاص بتوزيعتك باستخدام psql --version. إذا كان الإصدار أقدم، فقم بتثبيت إصدار أحدث من مستودعات مشروع PostgreSQL نفسه، أو استخدم قاعدة بيانات على خادم آخر. في Debian وUbuntu، تبدأ حزمة postgresql قاعدة البيانات. في Fedora وRHEL، أنشئها وابدأها أولاً:

sudo postgresql-setup --initdb
sudo systemctl enable --now postgresql

ثم أنشئ مستخدمًا وقاعدة بيانات لـ Antimatter:

sudo -u postgres psql -c "CREATE USER antimatter WITH PASSWORD 'a-long-password'"
sudo -u postgres psql -c "CREATE DATABASE antimatter OWNER antimatter"

يجب أن يقبل PostgreSQL اتصالات كلمة المرور من 127.0.0.1: سطور host في ملف pg_hba.conf الخاص به، مع الطريقة scram-sha-256.

3. ضبط قاعدة البيانات وعنوان الموقع

حرّر /etc/antimatter/antimatter.env (sudoedit /etc/antimatter/antimatter.env). احذف # من أمام الأسطر التي تستخدمها، ثم اضبط قاعدة البيانات والعنوان الذي سيفتحه المستخدمون:

AM_SQLSETTINGS_DRIVERNAME=postgres
AM_SQLSETTINGS_DATASOURCE=postgres://antimatter:a-long-password@localhost:5432/antimatter?sslmode=disable&connect_timeout=10
AM_SERVICESETTINGS_SITEURL=https://chat.example.com

يمكن وضع أي إعداد من إعدادات التهيئة في هذا الملف بصيغة AM_<SECTION>_<SETTING>: على سبيل المثال، SqlSettings.DataSource يصبح AM_SQLSETTINGS_DATASOURCE. لا يمكن تغيير الإعدادات المحددة هنا من وحدة التحكم بالنظام. راجع التهيئة. أعد تشغيل الخادم بعد كل تغيير: sudo systemctl restart antimatter.

يضبط الخادم أيضًا بعض القيم الافتراضية، والتي يمكن تجاوزها بسطر في antimatter.env: تسجيل الأحداث في الملفات معطّل (AM_LOGSETTINGS_ENABLEFILE=false, AM_NOTIFICATIONLOGSETTINGS_ENABLEFILE=false)، ووضع المحلّل مفعّل (AM_SERVICESETTINGS_ENABLELOCALMODE=true)، حتى يعمل amctl --local على الخادم.

4. ابدأ التشغيل

sudo systemctl start antimatter
journalctl -u antimatter -f
sudo -u antimatter amctl --local system status

عند التشغيل الأول، ينشئ الخادم جداوله، ثم يستمع على المنفذ 8065. افتح http://<server>:8065، أو نطاقك بعد إعداد وكيل عكسي (راجع النطاق وHTTPS)، وأنشئ الحساب الأول فورًا: سيصبح مدير النظام. لإنشائه من سطر الأوامر بدلاً من ذلك، استخدم أوامر amctl الواردة في إنشاء أول مدير، مع استخدام sudo -u antimatter amctl --local بدلاً من docker compose exec antimatter amctl --local.

5. فعّل GIF

تطبيق GIF مضمّن ومفعّل، ويحدد antimatter.env بالفعل عنوان خدمة GIF على نفس الخادم (AM_GIFS_SERVICE_URL=http://127.0.0.1:8080/v2). لكنه لا يزال بحاجة إلى مفتاح الواجهة البرمجية للخدمة. قام حزمة gifs-server بتوليد مفتاح عند تثبيتها:

sudo systemctl start gifs-server-stickers    # imports the sticker pack, about a minute and a half
sudo systemctl start gifs-server
sudo grep -v '^#' /etc/gifs-server/api-keys

ضع المفتاح في antimatter.env بصيغة AM_GIFS_API_KEY=<key> وأعد تشغيل Antimatter، أو أدخله كـمفتاح الواجهة البرمجية في وحدة التحكم بالنظام › الإضافات › GIF. إذا كانت خدمة GIF تعمل على خادم آخر، اضبط AM_GIFS_SERVICE_URL على عنوانه. للسماح للمستخدمين بإضافة GIF وملصقاتهم الخاصة، راجع GIF.

الخدمة

  • يعمل الخادم باسم مستخدم antimatter، في المسار /opt/antimatter، ويقرأ الملف /etc/antimatter/antimatter.env. يعيد systemd تشغيل الخادم عند انتهائه، ويمنحه مهلة تصل إلى ساعة واحدة للبدء، لأن ترحيلات قاعدة البيانات لإصدار جديد قد تستغرق وقتاً طويلاً.
  • تُحفظ سجلاته في الدورية (journal): journalctl -u antimatter.
  • الخادم مُعزَّز الأمان: المساران /usr و/etc للقراءة فقط بالنسبة للخادم، باستثناء /etc/antimatter/config، ولا يمكنه رؤية /home أو /root أو /run/user. إذا قمت بنقل تخزين الملفات (FileSettings.Directory)، فاختر مجلداً خارج هذه المسارات، يكون مملوكاً لمستخدم antimatter.
  • تستبدل عمليات الترقية ملف الخدمة. لتعديله، استخدم sudo systemctl edit antimatter، حيث تُحفظ تعديلاتك في ملف منفصل.

ترقية الحزمة

  1. خذ نسخة احتياطية (انظر النسخ الاحتياطية والترقيات).
  2. حمّل الحزمة الجديدة وملف SHA256SUMS، وتحقق منهما.
  3. أوقف الخادم، وثبّت الحزمة الجديدة فوق القديمة، ثم أعد تشغيله: 
    sudo systemctl stop antimatter
sudo apt install ./antimatter_<new version>-1_amd64.deb     # or: sudo dnf install ./antimatter-<new version>-1.x86_64.rpm
sudo systemctl start antimatter
journalctl -u antimatter -f

لا تعيد الحزمة تشغيل الخادم بنفسها. بعد الترقية، تُطبع الرسالة: Antimatter was upgraded; restart it to run the new version: sudo systemctl restart antimatter: إذا لم تكن قد أوقفت الخادم أولاً، أعد تشغيله فوراً. تستبدل الترقية /opt/antimatter وملف الخدمة، وتحافظ على antimatter.env، وconfig.json، و/var/lib/antimatter، والسجلات. عند بدء التشغيل، يحدّث الخادم قاعدة البيانات ويثبّت الإصدارات الأحدث من التطبيقات المدمجة.

إذا غيّر إصدار جديد الملف الافتراضي antimatter.env، يسأل apt عما إذا كنت تريد الإبقاء على نسختك: الإبقاء عليها. يحافظ dnf على نسختك ويحفظ النسخة الجديدة باسم /etc/antimatter/antimatter.env.rpmnew. الترقية تتم للأمام فقط: لا تثبّت إصداراً أقدم فوق أحدث.

إزالة الحزمة

أمر sudo apt remove antimatter أو sudo dnf remove antimatter يوقف الخدمة ويعطّلها، ويحذف البرنامج. يحافظ على البيانات (/var/lib/antimatter)، والإعدادات (/etc/antimatter)، وقاعدة البيانات، ومستخدم antimatter: احذفها بنفسك لإزالة Antimatter بالكامل.

التطبيقات في الحزم والأرشيف

تتضمن الحزم والأرشيف أحدث إصدار موقّع لهذه التطبيقات، في prepackaged_plugins/: الوكلاء، المكالمات، صور GIF، الميمات، الملاحظات، الاستطلاعات، قائمة المهام، القنوات الصوتية، والسبورة البيضاء. يُستبعد أي تطبيق لم يُصدر له إصدار بعد عند إنشاء إصدار الخادم: يُظهر الأمر ls /opt/antimatter/prepackaged_plugins ما يتضمنه إصدارك. تتضمن الميمات وقائمة المهام، لكنها غير مفعّلة: يشرح التطبيقات المدمجة كيفية تثبيتها وتفعيلها.

التطبيقات الأخرى في صور Docker غير موجودة في الحزم أو الأرشيف: Kanban، أدلة التشغيل، البريد، التقويم، GitHub، GitLab، Jira، ومؤشرات الأداء. ثبّت كل تطبيق من إصداراته الخاصة:

# 1. In /etc/antimatter/antimatter.env, add this line, then restart Antimatter

cd /tmp

لترقية تطبيق مثبّت بهذه الطريقة، أضف الحزمة الجديدة باستخدام plugin add --force: فترقيات الحزم ترقّي التطبيقات المدمجة فقط. يمكنك إزالة سطر AM_PLUGINSETTINGS_ENABLEUPLOADS مرة أخرى بعد ذلك. راجع تثبيت تطبيقات أخرى لمعرفة الطرق الأخرى لتثبيت التطبيقات.

توقيعات التطبيقات

تُوقّع حزم التطبيقات بمفتاح توقيع تطبيقات Antimatter: كل ملف .tar.gz.sig هو توقيع GPG منفصل لحزمته. يفحص الخادم هذه التوقيعات قبل تثبيت أي تطبيق مدمج. لفحص حزمة بنفسك:

curl -fsSLO https://raw.githubusercontent.com/AntimatterChat/antimatter-docker/main/keys/antimatter-plugin-signing.asc
gpg --import antimatter-plugin-signing.asc
gpg --verify <bundle>.tar.gz.sig <bundle>.tar.gz

يجب أن يُبلّغ gpg عن توقيع سليم من Antimatter Plugin Signing، مع البصمة 06C8 1032 4677 0F08 BBA7 78B9 E69B 05C3 92A6 9A45. كما يحذّر من أن المفتاح غير مُوثَّق بتوقيع موثوق؛ وهذا أمر طبيعي لمفتاح لم توقّعه بنفسك. الإصدار الذي لا يحتوي على ملفات .sig يكون غير موقّع، وتُبيّن ملاحظات الإصدار ذلك.

التثبيت من أرشيف إصدار

الحزمة antimatter-<version>-linux-<arch>.tar.gz (مثل antimatter-0.9.0-linux-amd64.tar.gz) مناسبة لتوزيعات لا تتوفر فيها حزم .deb أو .rpm، أو لتخطيط خاص بك. تحتوي على مجلد واحد باسم antimatter/ يضم bin/antimatter، وbin/amctl، وconfig/config.json، وتطبيقات الويب (client/ وclient-fusion/)، والتطبيقات المضمّنة (prepackaged_plugins/، راجع ما سبق)، وقوالب البريد الإلكتروني والترجمات.

1. تجهيز PostgreSQL

يدعم Antimatter قاعدة بيانات PostgreSQL فقط، الإصدار 15 أو أحدث (الإصدارات الأقدم تبدأ مع خطأ في السجل). أنشئ مستخدمًا وقاعدة بيانات:

sudo -u postgres psql <<'EOF'
CREATE USER antimatter WITH PASSWORD 'a-long-password';
CREATE DATABASE antimatter OWNER antimatter;
EOF

2. فك الضغط والإعداد

sudo tar -xzf antimatter-<version>-linux-amd64.tar.gz -C /opt
sudo useradd --system --user-group antimatter
sudo mkdir -p /opt/antimatter/data
sudo chown -R antimatter:antimatter /opt/antimatter

وجّه الخادم إلى قاعدة البيانات، إما في /opt/antimatter/config/config.json (SqlSettings.DataSource) أو باستخدام متغيرات البيئة، وعرّف عنوان الموقع:

AM_SQLSETTINGS_DRIVERNAME=postgres
AM_SQLSETTINGS_DATASOURCE=postgres://antimatter:a-long-password@localhost:5432/antimatter?sslmode=disable&connect_timeout=10
AM_SERVICESETTINGS_SITEURL=https://chat.example.com

ملف config.json الموجود في الأرشيف هو إعداد افتراضي كامل: تُحفظ التغييرات التي تجريها في وحدة التحكم بالنظام فيه. للاحتفاظ بالإعداد في قاعدة البيانات بدلاً من ذلك، راجع الإعداد.

3. تشغيله كخدمة

وحدة systemd، في /etc/systemd/system/antimatter.service:

[Unit]
Description=Antimatter
After=network.target postgresql.service

[Service]
Type=notify
User=antimatter
Group=antimatter
WorkingDirectory=/opt/antimatter
ExecStart=/opt/antimatter/bin/antimatter
EnvironmentFile=-/etc/antimatter.env
TimeoutStartSec=3600
Restart=always
RestartSec=10
LimitNOFILE=49152

[Install]
WantedBy=multi-user.target

ضع متغيرات AM_ الخاصة بك في /etc/antimatter.env (قابلة للقراءة بواسطة root فقط)، ثم:

sudo systemctl daemon-reload
sudo systemctl enable --now antimatter
journalctl -u antimatter -f

يستمع الخادم على المنفذ 8065. افتح http://<server>:8065، أو نطاقك بعد إعداد وكيل عكسي (راجع النطاق وHTTPS)، وأنشئ الحساب الأول: سيصبح مدير النظام.

يدير bin/amctl الخادم قيد التشغيل من سطر الأوامر. على الخادم نفسه، يعمل دون تسجيل الدخول عبر الوضع المحلي: اضبط AM_SERVICESETTINGS_ENABLELOCALMODE=true، ثم نفّذ sudo -u antimatter /opt/antimatter/bin/amctl --local system status.

بالنسبة إلى GIF، ثبّت خدمة GIF (انظر أدناه) واضبط AM_GIFS_SERVICE_URL وAM_GIFS_API_KEY كما في الخطوة 5 من حزم التثبيت.

حزم خدمة GIF والوكيل الدافعي

تتوفر لخدمة GIF والوكيل الدافعي إصدارات مستقلة، وتخضع للقواعد ذاتها الخاصة بالخادم: حزمة .tar.gz، وحزمة .deb وحزمة .rpm لكل من amd64 وarm64، وملف SHA256SUMS. الإصدارات التي تحتوي على شرطة هي إصدارات مسبقة. تحقّق من التحميلات باستخدام sha256sum --check --ignore-missing SHA256SUMS، كما هو الحال مع الخادم.

خدمة GIF (gifs-server)

الإصدارات: github.com/AntimatterChat/gifs-server/releases. الحزمة هي gifs-server-<version>-linux-<arch>.tar.gz؛ وتُسمّى الحزم gifs-server.

sudo apt install ./gifs-server_*_amd64.deb      # Debian, Ubuntu
sudo dnf install ./gifs-server-*.x86_64.rpm     # Fedora, RHEL

تُثبّت الحزمة:

  • /usr/bin/gifs-server، وخدمة gifs-server التي تعمل باسم مستخدم gifs-server وتحتفظ بمكتبتها في /var/lib/gifs-server؛
  • خدمة gifs-server-stickers، التي تستورد أو تحدّث حزمة الملصقات في /usr/share/gifs-server/stickers عند بدء تشغيلها، ثم تتوقف؛
  • إعداداتها، /etc/gifs-server/gifs-server.env (متغيرات AM_GIFS_، وتُحفظ عند الترقية)، و/etc/gifs-server/api-keys، بمفتاح API واحد في كل سطر، مع توليد مفتاح عشوائي عند التثبيت الأول.

يستمع على 127.0.0.1:8080، لذا يمكن لـ Antimatter على الخادم نفسه الوصول إليه فقط. إذا كان Antimatter يعمل في مكان آخر، فاضبط AM_GIFS_LISTEN=:8080 في gifs-server.env وقَيِّد الوصول إلى المنفذ عبر جدار الحماية. يحدد الملف الإعدادات الأخرى: AM_GIFS_UPLOAD_KEYS (المفاتيح المسموح بها لإضافة GIFs والملصقات، وحذف تلك التي أُضيفت باستخدامها)، وAM_GIFS_PUBLIC_URL، وAM_GIFS_TRUST_PROXY، وAM_GIFS_LOG_LEVEL. يوصي الحزمة باستخدام ffmpeg، وgifsicle، وlibrsvg2-bin (librsvg2-tools في حالة .rpm)، وخط DejaVu: يستخدم الخادم هذه الأدوات لإنشاء صيغ GIF والفيديو والملصقات عند استيراد الملفات أو استلامها، ويعمل دونها.

على غرار الخادم، يكون الخادم مفعّلًا لكنه غير مُشغَّل عند التثبيت. شغّله كما هو موضح في الخطوة 5 من الحزم. بعد الترقية، أعد تشغيله: sudo systemctl restart gifs-server. عند إزالة الحزمة، يبقى الكتالوج في /var/lib/gifs-server.

الوكيل الوسيط للإشعارات الفورية

الإصدارات: github.com/AntimatterChat/push-proxy/releases. الملف المضغوط هو antimatter-push-proxy-<version>-linux-<arch>.tar.gz، وتُسمّى الحزم antimatter-push-proxy. تُثبّت الحزمة /usr/bin/antimatter-push-proxy وخدمة antimatter-push-proxy، التي تعمل باسم مستخدم antimatter-push-proxy وتقرأ /etc/antimatter-push-proxy/antimatter-push-proxy.json (يُحفظ عند الترقية). تُوضع بيانات اعتماد Apple وFirebase في /etc/antimatter-push-proxy/certs: يشرح إشعارات الدفع مصدرها.

sudo apt install ./antimatter-push-proxy_*_amd64.deb      # or: sudo dnf install ./antimatter-push-proxy-*.x86_64.rpm
sudo install -o root -g antimatter-push-proxy -m 0640 \
    AuthKey_ABCDE12345.p8 firebase-service-account.json /etc/antimatter-push-proxy/certs/
sudoedit /etc/antimatter-push-proxy/antimatter-push-proxy.json
sudo systemctl start antimatter-push-proxy
journalctl -u antimatter-push-proxy -f

في ملف الإعدادات، تكون المسارات نسبية إلى /etc/antimatter-push-proxy: على سبيل المثال "AppleAuthKeyFile": "./certs/AuthKey_ABCDE12345.p8" و"ServiceFileLocation": "./certs/firebase-service-account.json". ثم اضبط خادم الإشعارات الفورية في Antimatter على http://<proxy host>:8066. بعد الترقية، أعد تشغيله: sudo systemctl restart antimatter-push-proxy.

يستمع الوكيل الوسيط للإشعارات الفورية على المنفذ 8066 على كل العناوين ولا يتحقق من هوية من يستدعيه. أبقِ المنفذ على شبكة خاصة، أو خلف وكيل عكسي يقيّد الوصول.

أوامر الخادم الأخرى

إلى جانب تشغيل الخادم (antimatter، أو antimatter server)، يحتوي الملف التنفيذي على بعض أوامر الصيانة. تقرأ هذه الأوامر نفس الإعداد الذي يستخدمه الخادم.
