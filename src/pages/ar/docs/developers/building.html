ما تحتاجه

  • تأكيد، عند الإصدار الموجود في server/go.mod (1.26.7 عند كتابة هذا النص).
  • Node.js وnpm، بالإصدارات الموجودة في .nvmrc وwebapp/package.json (Node 24.11.1 مع npm 11.6.2). باستخدام mise، يقوم ملف mise.toml في المستودع بتثبيت الإصدار الصحيح من Node.
  • Docker مع Compose: يعمل إعداد التطوير على PostgreSQL وعدة خدمات أخرى داخل حاويات.
  • make، git، وجهاز يعمل بنظام Linux أو macOS.
  • الذاكرة: بناء واجهات الويب هو الجزء الثقيل. خطط لتخصيص 16 جيجابايت من ذاكرة RAM؛ راجع البناء والذاكرة.
git clone https://github.com/AntimatterChat/antimatter.git
cd antimatter

يحتوي المستودع على الخادم في server/، وواجهات الويب في webapp/ (Fusion في webapp/fusion، والكلاسيكية في webapp/channels، والحزم المشتركة في webapp/platform)، والاختبارات الشاملة في e2e-tests/.

تشغيل خادم التطوير

cd server
make run

يبدأ make run حاويات التطوير (PostgreSQL، Redis، أداة لالتقاط البريد الإلكتروني وأدوات المراقبة)، ويربط بنود تطبيق الويب في مكانها، ويشغل الخادم في الخلفية باستخدام go run، ويشغل مراقب تطبيق الويب الذي يعيد بناء الواجهة الكلاسيكية أثناء تحريرها. افتح http://localhost:8065 وأنشئ حساباً: يصبح الحساب الأول مدير النظام.

الأمر (في server/)وظيفته
make run-server, make run-clientتشغيل الخادم فقط، أو مراقب تطبيق الويب فقط.
make restart-serverإعادة تشغيل الخادم بعد تغيير كود Go.
make stopإيقاف الخادم والمراقب والحاويات.
make debug-serverتشغيل الخادم تحت مُصحح Delve.
make run-cli ARGS="-version"تشغيل أمر خادم.
make config-resetإعادة تعيين config/config.json إلى القيم الافتراضية.
make clean, make nukeإزالة ملفات البناء؛ يحذف nuke أيضاً بيانات التطوير.

قاعدة بيانات التطوير هي postgres://mmuser:mostest_password@localhost/mattermost_test، وهي مصدر البيانات الافتراضي للخادم. اختر الحاويات التي تبدأ باستخدام ENABLED_DOCKER_SERVICES، في ملف server/config.override.mk أو في بيئة النظام (راجع server/config.mk).

واجهات الويب

في webapp/:

npm install      # also builds the shared packages
npm run build    # the classic interface, then Fusion

تُحفظ النتائج في webapp/channels/dist (الكلاسيكي) وwebapp/fusion/dist (Fusion). الأمر make client في server/ يربطها كـ server/client وserver/client-fusion، حيث يقدّمها الخادم: الكلاسيكي تحت /static/، وFusion تحت /static/fusion/.

  • الأمر npm run run (أو make run في webapp/) يراقب ويعيد بناء الواجهة الكلاسيكية. أضف WATCH_FUSION=true لإعادة بناء Fusion أيضًا.
  • الأمر npm run dev-server (make dev) يشغّل خادم التطوير الخاص بـ webpack بدلاً من ذلك: الكلاسيكي على المنفذ 9005، وFusion على المنفذ 9006.
  • لعرض إحدى الواجهتين في المتصفح، أضف ?webui=fusion أو ?webui=classic إلى عنوان أي صفحة.

الاختبارات والفحوصات

make test-server-quickserver/الاختبارات القصيرة فقط.
go test ./channels/app/... -run TestNameserver/حزمة واحدة أو اختبار واحد، مع تشغيل الحاويات (make start-docker).
make check-styleserver/go vet وgolangci-lint وفحوصات Go الأخرى.

شغّل make modules-tidy بدلاً من go mod tidy في server/.

أرشيفات الإصدارات

cd webapp && npm run build && cd ..
cd server
make build-linux       # the antimatter and amctl binaries
make package-linux     # dist/antimatter-linux-amd64.tar.gz and -arm64

الأمر make build يبني الواجهات الويب والثنائيات الخاصة بنظام Linux دفعة واحدة. يحتوي الأرشيف على bin/antimatter، وbin/amctl، وملف config/config.json الافتراضي، وكلا الواجهتين الويب، والقوالب، والخطوط، والترجمات. المنصات الأخرى: make package-osx، make package-windows، make package-freebsd. لا تتضمن الأرشيفات التطبيقات المدمجة؛ أما صورة Docker فتشملها.

صورة Docker

مستودع antimatter-docker يبني الصور المنشورة، والخادم مع تطبيقاته، بالكامل داخل Docker:

git clone https://github.com/AntimatterChat/antimatter-docker.git
cd antimatter-docker
scripts/build-all.sh                     # from the main branches on GitHub
SOURCES=local scripts/build-all.sh       # from your checkouts next to this folder
VARIANT=next scripts/build-all.sh        # the "next" image, with every Antimatter app

يتطلب Docker مع buildx، وPython 3، وgit وgpg، وحوالي 16 جيجابايت من ذاكرة RAM و30 جيجابايت من مساحة القرص. يُحمَّل الناتج كـ ghcr.io/antimatterchat/antimatter:dev؛ جرّبه باستخدام ANTIMATTER_IMAGE=ghcr.io/antimatterchat/antimatter:dev docker compose -f compose.local.yml up -d. يحدد plugins.json التطبيقات والإصدارات المبنية، ويشرح README الخاص بالمستودع المتغيرات.

يوقّع build-all.sh التطبيقات المضمّنة بمفتاح توقيع Antimatter، ويرفض بناء الصورة التطبيقات غير الموقّعة. بدون هذا المفتاح الخاص، الذي لا يملكه سوى المُحافظون على المشروع، نفّذ الخطوات الأولى فقط: scripts/fetch-sources.sh، scripts/build-plugins.sh (حزم التطبيقات في out/plugins/)، وscripts/build-server.sh (أرشيفات الخادم في out/server/).

البناء والذاكرة

واجهات الويب هي حِزم webpack كبيرة، ونفاد الذاكرة هو أكثر أسباب فشل البناء شيوعًا.

  • يبني npm run build الواجهة الكلاسيكية ثم Fusion واحدة تلو الأخرى، وليس معًا، للحفاظ على الحد الأقصى للذاكرة منخفضًا. لا تشغّلهما بالتوازي بنفسك.
  • يبدأ المُصغِّر عاملًا واحدًا لكل معالج. على جهاز بعدد كبير من الأنوية وذاكرة قليلة، حدّد عدد المعالجات التي يراها البناء: taskset -c 0-5 npm run build.
  • إذا نفدت ذاكرة الكومة (heap) في Node، ارفع حدّها: NODE_OPTIONS=--max-old-space-size=6144. يستخدم بناء Docker هذه القيمة (BUILD_NODE_OPTIONS في build.env).
  • تجنّب تشغيل مجموعة اختبارات الخادم الكاملة، وبناء الويب، وبناء Docker في الوقت نفسه على جهاز صغير.

التطبيقات

لكل تطبيق (إضافة) مستودع وملف Makefile خاص به؛ make dist يبني حزمته. راجع البناء والتثبيت والتصحيح.

تطبيق سطح المكتب

تطبيق سطح المكتب هو تطبيق Electron. باستخدام Node.js 24 أو أحدث:

npm install --allow-git=all
npm run build          # development build, into dist/
npm start              # run it
npm run package:linux  # packages into release/ (also package:windows, package:mac)

إعدادات وقت البناء، مثل الخوادم التي يجب ضبطها مسبقًا، موجودة في src/common/config/buildConfig.ts.

التطبيق المحمول

التطبيق المحمول هو تطبيق React Native؛ يدرج ملف README أوامره (npm run ios، npm run android). لبناء نسختك الخاصة، تحتاج أيضًا إلى مفاتيح توقيع خاصة بك، ومشروع Firebase لإشعارات Android، ومفتاح APNs لـ iOS، ووكيل دفع يحتفظ بهذه البيانات.
