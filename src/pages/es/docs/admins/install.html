Instalación con Docker Compose

Esta es la forma recomendada. Un solo archivo compose ejecuta Antimatter, PostgreSQL, el almacenamiento de archivos y el servicio de GIF. Necesita un servidor Linux con Docker Engine y su plugin Compose (docker compose), 2 núcleos de CPU y 4 GB de memoria o más.

1. Descargar el archivo compose

mkdir antimatter && cd antimatter
curl -fsSLO https://antimatter.chat/compose.yaml

2. Crear el archivo .env

El archivo compose lee su configuración desde un archivo .env en el mismo directorio. Créelo con secretos aleatorios:

cat > .env <<EOF
SITE_URL=http://localhost:8065
POSTGRES_PASSWORD=$(openssl rand -hex 24)
S3_SECRET_KEY=$(openssl rand -hex 24)
GIFS_API_KEY=$(openssl rand -hex 24)
EOF
chmod 600 .env

Establezca SITE_URL con la dirección que las personas escribirán en su navegador, por ejemplo http://192.168.1.20:8065 en una red local o https://chat.example.com con un dominio. Guarde el archivo .env: la base de datos y el almacenamiento usan estas contraseñas desde el primer inicio, y necesitará el mismo archivo para restaurar una copia de seguridad.

3. Iniciar

docker compose up -d
docker compose ps

El primer inicio tarda uno o dos minutos: PostgreSQL crea la base de datos, un servicio de un solo uso bucket crea el contenedor de almacenamiento, un servicio de un solo uso gifs-stickers importa el paquete de pegatinas inicial y Antimatter crea sus tablas. Sígalo con docker compose logs -f antimatter.

Para usar un nombre de dominio y HTTPS desde el inicio, consulte Dominio y HTTPS: con el archivo compose, son dos líneas más en .env y el perfil https.

PostgreSQL, el almacenamiento y el servicio de GIF están en una red interna (private) sin acceso a Internet, a la que solo se une Antimatter. Ninguno de ellos publica un puerto.

El contenedor de Antimatter no guarda nada en el disco: su configuración está en la base de datos (AM_CONFIG apunta a ella) y sus archivos y aplicaciones están en el servicio de almacenamiento. Puedes eliminar y recrear el contenedor en cualquier momento. Todo lo que hay que hacer copia de seguridad está en los volúmenes postgres, files y gifs, además de tu .env.

Elegir una imagen

Se publican dos imágenes de Antimatter, ambas para linux/amd64 y linux/arm64, y ambas construidas desde la rama main de cada repositorio:

ImagenAplicaciones incluidasEtiquetas
ghcr.io/antimatterchat/antimatterAgentes, Llamadas, GitHub, GitLab, Jira, Kanban, Métricas y Playbooks.latest, X.Y.Z para las versiones, sha-<commit>
ghcr.io/antimatterchat/antimatter-nextLo mismo, más Canales de voz, Encuestas, Correo, Calendario, Notas, Pizarra, GIF, Por hacer y Memes. Se reconstruye cada noche.latest, nightly, nightly-<YYYYMMDD>, sha-<commit>

El archivo compose del sitio usa antimatter-next, porque el servicio de GIF y la mayoría de las aplicaciones descritas en este sitio solo están en esa imagen. Para cambiar la imagen, configura ANTIMATTER_IMAGE en .env y ejecuta docker compose up -d.

latest cambia bajo tus pies. En producción, fija una etiqueta como nightly-20261015 o sha-<commit>, y cámbiala deliberadamente al actualizar. El servidor actualiza su base de datos al iniciarse, por lo que no puedes volver a una imagen anterior, ni pasar de antimatter-next a antimatter, sin restaurar una copia de seguridad tomada antes. Consulta Copias de seguridad y actualizaciones.

Dentro de la imagen

  • El servidor está en /antimatter, con los binarios antimatter y amctl en /antimatter/bin (en el PATH).
  • Se ejecuta como el usuario sin privilegios antimatter (uid 2000) sobre una base distroless mínima, sin shell.
  • Puertos: 8065 (web y API), 8067 (métricas), 8074 (clúster), 8443 UDP y TCP (llamadas).
  • El modo local (ServiceSettings.EnableLocalMode) está activado, por lo que amctl --local funciona dentro del contenedor. La comprobación de estado ejecuta amctl system status --local.
  • Las aplicaciones incluidas se encuentran en /antimatter/prepackaged_plugins y están firmadas con la clave de firma de aplicaciones de Antimatter.
  • Se incluyen herramientas de extracción de texto (pdftotext, wvText, unrtf, tidy), de modo que se pueda buscar en el contenido de los documentos subidos.

Otros archivos de compose

El repositorio antimatter-docker incluye una configuración de producción en deploy/compose/: nginx con tus propios certificados o Let's Encrypt (certbot), PostgreSQL, el servicio opcional de GIF (perfil gifs) y volúmenes con nombre para la configuración, los datos y los registros del servidor, todo documentado en su README. Utiliza la imagen estable por defecto y almacena los archivos en un volumen local en lugar de almacenamiento S3. Úsalo si prefieres nginx a Caddy o si ya tienes certificados.

Crear el primer administrador

Abre SITE_URL en tu navegador y crea una cuenta. La primera cuenta creada en un servidor nuevo se convierte en el administrador del sistema, y la configuración te guiará a continuación para crear tu primera comunidad (el nombre que Antimatter da a un equipo o espacio de trabajo).

Hazlo inmediatamente después del primer inicio: hasta entonces, cualquiera que acceda al servidor primero se convertirá en su administrador. Para crear la cuenta desde la línea de comandos en su lugar, antes de que el servidor sea accesible desde el exterior:

docker compose exec antimatter amctl --local user create --system-admin --email-verified \
    --email admin@example.com --username admin --password 'a-long-password'
docker compose exec antimatter amctl --local team create --name main --display-name "Main"
docker compose exec antimatter amctl --local team users add main admin

Después, inicia sesión en SITE_URL. Comienza el comando con un espacio para mantener la contraseña fuera del historial de tu shell (con HISTCONTROL=ignorespace), o cambia la contraseña una vez que hayas iniciado sesión.

Próximos pasos una vez que estés dentro:

  1. Decide quién puede crear cuentas: Inicio de sesión y cuentas.
  2. Configura el correo electrónico para que las invitaciones y los restablecimientos de contraseña funcionen: Correo electrónico y notificaciones push.
  3. Abre el puerto de las llamadas en tu cortafuegos: Llamadas y voz.
  4. Comprueba qué aplicaciones están activas: Aplicaciones incluidas.

Instalar desde un archivo de liberación

Sin Docker, el servidor se ejecuta desde un archivo llamado antimatter-<os>-<arch>.tar.gz (por ejemplo, antimatter-linux-amd64.tar.gz). Contiene un único directorio antimatter/ con bin/antimatter, bin/amctl, config/config.json, las aplicaciones web (client/ y client-fusion/), las plantillas de correo electrónico y las traducciones.

1. Preparar PostgreSQL

Antimatter solo admite PostgreSQL, versión 15 o posterior (las versiones anteriores se inician, pero generan un error en el registro). Crea un usuario y una base de datos:

sudo -u postgres psql <<'EOF'
CREATE USER antimatter WITH PASSWORD 'a-long-password';
CREATE DATABASE antimatter OWNER antimatter;
EOF

2. Descomprimir y configurar

sudo tar -xzf antimatter-linux-amd64.tar.gz -C /opt
sudo useradd --system --user-group antimatter
sudo mkdir -p /opt/antimatter/data
sudo chown -R antimatter:antimatter /opt/antimatter

Indica al servidor la base de datos, ya sea en /opt/antimatter/config/config.json (SqlSettings.DataSource) o mediante variables de entorno, y establece la URL del sitio:

AM_SQLSETTINGS_DRIVERNAME=postgres
AM_SQLSETTINGS_DATASOURCE=postgres://antimatter:a-long-password@localhost:5432/antimatter?sslmode=disable&connect_timeout=10
AM_SERVICESETTINGS_SITEURL=https://chat.example.com

El config.json del archivo es una configuración predeterminada completa: los ajustes que cambies en la Consola de sistema se guardan en él. Para mantener la configuración en la base de datos en su lugar, consulta Configuración.

3. Ejecutarlo como un servicio

Una unidad de systemd, en /etc/systemd/system/antimatter.service:

[Unit]
Description=Antimatter
After=network.target postgresql.service

[Service]
Type=notify
User=antimatter
Group=antimatter
WorkingDirectory=/opt/antimatter
ExecStart=/opt/antimatter/bin/antimatter
EnvironmentFile=-/etc/antimatter.env
TimeoutStartSec=3600
Restart=always
RestartSec=10
LimitNOFILE=49152

[Install]
WantedBy=multi-user.target

Coloca tus variables AM_ en /etc/antimatter.env (legible solo por root) y luego:

sudo systemctl daemon-reload
sudo systemctl enable --now antimatter
journalctl -u antimatter -f

El servidor escucha en el puerto 8065. Abre http://<server>:8065, o tu dominio una vez que esté configurado un proxy inverso (consulta Dominio y HTTPS), y crea la primera cuenta: esta se convertirá en el administrador del sistema.

bin/amctl gestiona el servidor en ejecución desde la línea de comandos. En el propio servidor, funciona sin iniciar sesión mediante el modo local: establece AM_SERVICESETTINGS_ENABLELOCALMODE=true y luego ejecuta sudo -u antimatter /opt/antimatter/bin/amctl --local system status.

Otros comandos del servidor

Además de ejecutar el servidor (antimatter o antimatter server), el binario tiene algunos comandos de mantenimiento. Leen la misma configuración que el servidor.

ComandoQué hace
antimatter versionImprime la versión, el número de compilación, la fecha de compilación y el hash de compilación.
antimatter db pingComprueba que la base de datos es accesible.
antimatter db initCrea la configuración en la base de datos (con AM_CONFIG establecido en una URL postgres://).
antimatter db migrateAplica las migraciones de la base de datos sin iniciar el servidor.
antimatter db versionImprime la última migración aplicada a la base de datos.
antimatter import bulk, antimatter export bulkImporta o exporta datos en el formato por lotes (consulta Copias de seguridad y actualizaciones).
