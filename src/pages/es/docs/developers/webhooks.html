Dónde gestionar webhooks

Abre tu avatar en la esquina superior derecha y luego selecciona Integraciones. Las páginas de integraciones de la comunidad actual muestran Webhooks de Entrada y Webhooks de Salida. Cada webhook pertenece a una comunidad.

Por defecto, los administradores de la comunidad y los administradores del sistema pueden crear webhooks. Un administrador del sistema puede otorgar este permiso a otros roles en la configuración de permisos de la Consola de sistema. También puede desactivar cada tipo en Consola de sistema › Integraciones › Gestión de Integraciones: Habilitar Webhooks de Entrada y Habilitar Webhooks de Salida están activados por defecto.

Crear un webhook entrante

  1. En Integraciones, selecciona Webhooks de Entrada y luego Agregar Webhook de Entrada.
  2. Completa un Título y una Descripción: solo se muestran en las páginas de integraciones.
  3. Selecciona el Channel al que van los mensajes por defecto. Para un canal privado, debes ser miembro de él.
  4. Marca Fijar a este canal si los remitentes no deben poder publicar en otros lugares.
  5. Opcionalmente, establece una URL para el Nombre de usuario y la Foto del Perfil de sus mensajes (ver Nombre e icono).
  6. Selecciona Guardar. Copia la URL mostrada: https://chat.example.com/hooks/<key>.
La URL es el único secreto: cualquiera que la tenga puede publicar en el canal. Manténla fuera de repositorios públicos y elimina el webhook si se filtra.

Con la API: POST /api/v4/hooks/incoming con {"channel_id", "display_name", "description", "username", "icon_url", "channel_locked"}; el id de la respuesta es la clave. Desde la línea de comandos: amctl webhook create-incoming --channel <channel id> --user <user> --display-name "CI".

Enviar un mensaje a un webhook entrante

curl -X POST https://chat.example.com/hooks/xgh5ycrx1jf7mbs9w8z4c8e7ho \
  -H 'Content-Type: application/json' \
  -d '{"text": "Deploy of **api 2.4.0** finished :white_check_mark:"}'

El servidor responde 200 con el cuerpo ok. También acepta application/x-www-form-urlencoded con el JSON en un campo payload, como hacen los webhooks de Slack, por lo que las herramientas hechas para Slack suelen funcionar sin cambios.

CampoSignificado
textEl mensaje, en Markdown. Obligatorio, salvo que haya attachments. Un texto más largo que el límite de mensajes del servidor se divide en varios mensajes.
channelOtro canal de la comunidad del webhook, por nombre (ops-alerts o #ops-alerts), o @username para un mensaje directo del propietario del webhook. Se rechaza si el webhook está bloqueado en su canal.
username, icon_url, icon_emojiEl nombre y la imagen que se mostrarán, si el servidor permite reemplazos.
attachmentsAdjuntos del mensaje, representados como tarjetas (abajo).
propsPropiedades adicionales almacenadas en el mensaje, para que las apps las lean.
typeUn tipo de mensaje personalizado, como custom_poll, para una app que lo represente. Se rechazan los tipos que comienzan por system_.
root_idEl ID del primer mensaje de un hilo, para responder en ese hilo.
priorityPrioridad del mensaje, por ejemplo {"priority": "urgent"}.
silenttrue envía el mensaje sin notificaciones push.

Los mensajes mostrados con un nombre reemplazado llevan una etiqueta BOT junto a él, para que se puedan distinguir de las cuentas reales. Los mensajes de webhook nunca activan webhooks salientes.

Nombre e icono

Un webhook publica como la persona que lo creó, a menos que el servidor permita reemplazos. Dos ajustes en Consola de sistema › Integraciones › Gestión de integraciones, ambos desactivados por defecto, cambian esto:

  • Permitir a las integraciones reescribir nombres de usuario (ServiceSettings.EnablePostUsernameOverride): se muestra el Nombre de usuario del webhook o el parámetro username de la solicitud; si no hay ninguno, el nombre es webhook.
  • Permitir a las integraciones reescribir imágenes de perfil (ServiceSettings.EnablePostIconOverride): se muestra la Foto del Perfil del webhook, o el parámetro icon_url o icon_emoji de la solicitud.

Un valor en la solicitud tiene prioridad sobre el guardado en el webhook.

Adjuntos

Los adjuntos añaden contenido estructurado debajo del texto. Siguen el formato de adjuntos de mensajes de Slack:

{
  "text": "Build failed on `main`",
  "attachments": [{
    "fallback": "main #1902 failed",
    "color": "#d24b4e",
    "author_name": "GitHub Actions",
    "author_icon": "https://chat.example.com/static/ci.png",
    "title": "main #1902 failed",
    "title_link": "https://ci.example.com/runs/1902",
    "text": "Commit `0f4d8e2` by Jonas Weber",
    "fields": [
      {"title": "Branch", "value": "zephyr-3.7", "short": true},
      {"title": "Duration", "value": "3m 40s", "short": true}
    ],
    "footer": "Lumen CI",
    "ts": 1760000000
  }]
}
CampoSignificado
fallbackTexto plano para lugares que no pueden mostrar la tarjeta, como las notificaciones.
colorLa barra de color: un color hexadecimal, o good, warning, danger.
pretextTexto sobre la tarjeta.
author_name, author_link, author_iconUna pequeña línea de encabezado.
title, title_linkEl título de la tarjeta, opcionalmente un enlace.
textEl cuerpo de la tarjeta, en Markdown.
fieldsUna lista de {"title", "value", "short"}; los campos short se colocan uno al lado del otro.
image_url, thumb_urlUna imagen grande abajo, o una pequeña al lado.
footer, footer_icon, tsUna línea de pie de página y una hora (segundos Unix).
actionsBotones y menús: ver Mensajes interactivos.

Tarjetas: etapas y gráficos

Antimatter añade dos campos a los adjuntos, que la interfaz predeterminada representa:

  • stages: los pasos de un pipeline como pastillas, hasta 20. Cada uno es {"name", "status"}, con un estado de passed, failed, running, pending, skipped o canceled.
  • chart: un pequeño gráfico de líneas de valores recientes, {"values": [2 to 200 numbers], "threshold": number, "label": "…"}. El umbral se dibuja como una línea discontinua, para el límite de una alerta.
{
  "attachments": [{
    "color": "danger",
    "title": "main #1902 failed",
    "stages": [
      {"name": "build", "status": "failed"},
      {"name": "unit", "status": "skipped"},
      {"name": "publish", "status": "skipped"}
    ]
  }, {
    "color": "warning",
    "title": "API latency above 400 ms",
    "chart": {"values": [210, 230, 260, 390, 450, 470], "threshold": 400, "label": "p95 latency, ms"}
  }]
}

La interfaz clásica y otros clientes ignoran estos dos campos, así que también incluye lo esencial en text o fields.

Crear un webhook saliente

Un webhook de salida vigila los canales Público de una comunidad. Cuando la primera palabra de un mensaje coincide con una de sus palabras que disparan la acción, Antimatter envía el mensaje a tu URL.

  1. En Integraciones, selecciona Webhooks de Salida y luego Agregar Webhook de Salida.
  2. Completa el Título y la Descripción.
  3. Selecciona el Tipo de contenido de la solicitud: application/x-www-form-urlencoded o application/json.
  4. Elige un Canal, ingresa las Palabras que disparan acciones (Una por Línea), o ambos. Con un canal y sin palabras que disparan la acción, se envía cada mensaje de ese canal. Con ambos, el mensaje debe coincidir con ambos.
  5. Bajo Disparar Cuando, selecciona La primera palabra coincide exactamente con una palabra que dispara la acción o La primera palabra empieza con una palabra que dispara la acción.
  6. Ingresa las Callback URLs (Uno por Línea). Cada URL recibe todos los mensajes coincidentes.
  7. Opcionalmente, establece el Nombre de usuario y la Foto del Perfil utilizados para las respuestas.
  8. Elija Guardar y copie el token mostrado. Su servicio lo utiliza para verificar que las solicitudes provienen de su servidor.

Con la API: POST /api/v4/hooks/outgoing con {"team_id", "channel_id", "trigger_words", "trigger_when", "callback_urls", "content_type", "display_name"} (trigger_when: 0 para coincidencia exacta, 1 para "empieza con").

Si su servicio está en una red privada, un administrador del sistema debe permitir su dirección en Permitir conexiones internas no son de confianza (ServiceSettings.AllowedUntrustedInternalConnections). De lo contrario, el servidor no llamará a direcciones privadas.

La solicitud saliente

Antimatter envía un POST con estos campos, como JSON o codificado en formulario según el tipo de contenido:

{
  "token": "6kd1ofo5ojr5zgu5ipfipybgnc",
  "team_id": "…",
  "team_domain": "lumen-labs",
  "channel_id": "…",
  "channel_name": "ops-alerts",
  "timestamp": 1760010000000,
  "user_id": "…",
  "user_name": "priya",
  "post_id": "…",
  "text": "deploy api 2.4.0",
  "trigger_word": "deploy",
  "file_ids": ""
}

Compare token con el token del webhook antes de hacer nada. En la versión codificada en formulario, timestamp está en segundos en lugar de milisegundos. El servidor espera su respuesta durante el tiempo que permita Tiempo de espera de solicitud de integración (30 segundos por defecto, ServiceSettings.OutgoingIntegrationRequestsTimeout).

Responder a un webhook saliente

Para publicar una respuesta, responde con JSON. Para no publicar nada, responde con un cuerpo vacío.

{
  "text": "Deploying **api 2.4.0** to staging…",
  "response_type": "comment",
  "username": "deploy-bot",
  "icon_url": "https://chat.example.com/static/deploy.png"
}
  • text y attachments: la respuesta. Sin ninguno de los dos, no se publica nada.
  • response_type: comment publica la respuesta en el hilo del mensaje que la activó; de lo contrario, se publica en el canal.
  • username, icon_url: se muestran cuando el servidor permite sobrescribirlos; en caso contrario, se usan los valores propios del webhook.
  • props, type, priority: como en los webhooks entrantes.

La respuesta se publica como el creador del webhook, bajo el nombre sobrescrito si lo hay. Para cualquier cosa más larga que una respuesta rápida, responde de inmediato y publica después con un webhook entrante o la API.

Cuando un webhook no funciona

  • 501 desde la URL del webhook: los webhooks entrantes están desactivados en el servidor.
  • 400 "Failed to decode the payload…": el JSON no es válido, o el campo del formulario no se llama payload. "No text specified." significa que la solicitud no tiene ni text ni attachments.
  • 403: el webhook está bloqueado a otro canal, o su propietario ya no puede leer el canal.
  • Un webhook saliente nunca se activa: el canal es privado, el disparador no es la primera palabra, o el mensaje provino de un webhook.
  • Registros: con Habilitar Depuración de Webhook activado (LogSettings.EnableWebhookDebugging) y el nivel de registro en DEBUG, el servidor registra las cargas de las solicitudes entrantes fallidas. Las llamadas salientes fallidas se registran como Outgoing Webhook POST failed.
