مبانی

  • آدرس پایه: https://chat.example.com/api/v4. همه‌ی نقاط پایانی زیر نسبت به این آدرس هستند.
  • قالب: ورودی و خروجی به‌صورت JSON است، به‌جز بارگذاری فایل‌ها (multipart). Content-Type: application/json را ارسال کنید.
  • شناسه‌ها: هر شیء یک id با ۲۶ کاراکتر دارد. زمان‌ها به‌صورت میلی‌ثانیه از مبدأ Unix هستند (create_at، update_at، delete_at؛ مقدار 0 به معنای «حذف‌نشده» است).
  • جوامع همان تیم‌ها هستند: رسانه برنامه‌نویسی به آن‌ها teams می‌گوید و برای هر کدام یک team_id وجود دارد.
  • خودتان: هر جا که در مسیر یک user_id لازم باشد، me به کاربر واردشده اشاره دارد، همان‌طور که در GET /users/me می‌بینید.

فهرست کامل نقاط پایانی در کد سرور موجود است: مسیرها در server/channels/api4/*.go تعریف شده‌اند و انواع داده در server/public/model. توضیحات OpenAPI در پوشه api/v4/source مخزن، نقاط پایانی را پوشش می‌دهد که از Mattermost به ارث برده شده‌اند، نه افزودنی‌های Antimatter.

احراز هویت

هر درخواست، به‌جز ورود و چند نقطه پایانی عمومی، به یک توکن در هدر Authorization نیاز دارد:

curl -H "Authorization: Bearer $TOKEN" https://chat.example.com/api/v4/users/me

سه نوع توکن در آنجا پذیرفته می‌شود: توکن‌های دسترسی شخصی، توکن‌های نشست و توکن‌های دسترسی OAuth. Authorization: Token … هم پذیرفته می‌شود. توکن‌ها در رشته پرس (query string) (?access_token=) فقط برای توکن‌های دسترسی OAuth پذیرفته می‌شوند.

توکن‌های دسترسی شخصی (برای اسکریپت‌ها توصیه می‌شود)

یک توکن دسترسی شخصی به‌جای شما عمل می‌کند، مگر اینکه تاریخ انقضایی برای آن تعیین کنید، و می‌توان آن را در هر لحظه باطل کرد. توکن‌های دسترسی شخصی به‌طور پیش‌فرض غیرفعال هستند:

  1. یک مدیر سیستم گزینه فعال کردن رمزهای دسترسی شخصی را در کنسول سیستم › ادغام ها › مدیریت یکپارچه سازی (ServiceSettings.EnableUserAccessTokens، AM_SERVICESETTINGS_ENABLEUSERACCESSTOKENS) فعال می‌کند.
  2. برای هر فردی که ممکن است توکن‌ها را ایجاد کند، یک مدیر سیستم کنسول سیستم › مدیریت کاربران › کاربران را باز می‌کند، در منوی آن فرد مدیریت نقش‌ها را انتخاب می‌کند و اجازه تولید توکن‌های دسترسی شخصی برای این حساب را فعال می‌کند. مدیران سیستم همیشه می‌توانند این توکن‌ها را ایجاد کنند.
  3. کاربر روی آواتار خود در گوشه بالا سمت راست کلیک می‌کند و سپس به بخش مشخصات و تنظیمات › امنیت می‌رود. در زیر بخش توکن های دسترسی شخصی، توضیح می‌دهد که این توکن برای چه کاری استفاده می‌شود و گزینه توکن ایجاد کنید را انتخاب می‌کند. توکن فقط یک بار نمایش داده می‌شود: آن را کپی کنید.

با استفاده از API: POST /users/{user_id}/tokens همراه با {"description": "backup script", "expires_at": 0} (expires_at بر حسب میلی‌ثانیه؛ 0 برای بدون انقضا). فیلد token در پاسخ، راز (secret) است؛ id آن چیزی است که برای لغو توکن استفاده می‌شود (POST /users/tokens/revoke همراه با {"token_id": "…"}). از خط فرمان: amctl token generate <user> <description>.

یک مدیر سیستم می‌تواند مدت اعتبار توکن‌ها را با حداکثر مدت اعتبار توکن دسترسی شخصی (روز) در همان صفحه کنسول سیستم محدود کند.

توکن‌های نشست

ورود با رمز عبور، یک توکن نشست را در هدر پاسخ Token برمی‌گرداند، همان نوع نشستی که برنامه‌ها از آن استفاده می‌کنند:

curl -i -X POST https://chat.example.com/api/v4/users/login \
  -H 'Content-Type: application/json' \
  -d '{"login_id": "maya", "password": "…"}'

برای حسابی که احراز هویت چندعاملی دارد، "token": "123456" را اضافه کنید. نشست‌ها طبق تنظیمات نشست سرور منقضی می‌شوند و نقطه ورود (login endpoint) محدودیت نرخ دارد (۵ درخواست بر ثانیه). POST /users/logout نشست را پایان می‌دهد.

مرورگرها به جای توکن، با کوکی احراز هویت می‌کنند. درخواستی که با کوکی احراز هویت شده، برای هر عملی غیر از GET باید هدر X-CSRF-Token را نیز ارسال کند؛ توکن در هدر Authorization به هدر CSRF نیاز ندارد.

برنامه‌های OAuth 2.0

برای اینکه افراد بتوانند با حساب Antimatter خود به برنامه شما وارد شوند، یک برنامه OAuth 2.0 ثبت کنید. در این صورت Antimatter به عنوان ارائه‌دهنده OAuth عمل می‌کند:

  1. گزینه فعال کردن OAuth 2.0 Service Provider باید فعال باشد (کنسول سیستم › ادغام ها › مدیریت یکپارچه سازی، ServiceSettings.EnableOAuthServiceProvider، به صورت پیش‌فرض فعال است).
  2. کسی که مجوز مدیریت برنامه‌های OAuth را دارد (به صورت پیش‌فرض مدیران سیستم) روی آواتار خود کلیک می‌کند، سپس به بخش ادغام ها › برنامه‌های OAuth 2.0 می‌رود و برنامه را به همراه URLهای بازگشت (callback) اضافه می‌کند. در این مرحله یک client ID و یک client secret دریافت می‌کند.
  3. برنامه شما کاربران را به https://chat.example.com/oauth/authorize با response_type=code، client_id، redirect_uri و state می‌فرستد. پشتیبانی از PKCE با code_challenge_method=S256 وجود دارد.
  4. کد را در POST https://chat.example.com/oauth/access_token (با grant_type=authorization_code و سپس refresh_token برای تمدید) تبدیل می‌کند و با Authorization: Bearer <access token> به API دسترسی پیدا می‌کند.

کاربران می‌توانند برنامه‌هایی که به آن‌ها مجوز داده‌اند را در بخش مشخصات و تنظیمات › امنیت › برنامه‌هایی که به آن‌ها مجوز داده‌اید مشاهده کنند.

ارسال پیام

curl -X POST https://chat.example.com/api/v4/posts \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"channel_id": "'$CHANNEL_ID'", "message": "Backup finished: **42 GB** in 3 min"}'

پیام‌ها به صورت Markdown هستند. برای پاسخ در یک رشته، "root_id" (اولین پیام رشته) را اضافه کنید، برای فایل‌ها "file_ids" و برای پیوست‌ها و سایر موارد اضافی "props" (به پیوست‌ها مراجعه کنید).

یافتن شناسه کانال

curl -H "Authorization: Bearer $TOKEN" \
  https://chat.example.com/api/v4/teams/name/lumen-labs/channels/name/ops-alerts

نام‌ها همان‌هایی هستند که در لینک کانال آمده است: /lumen-labs/channels/ops-alerts.

صفحه‌بندی

پایانه‌های فهرست‌دهنده page (از 0) و per_page (به‌طور پیش‌فرض 60، حداکثر 200) را می‌پذیرند. برای دریافت صفحه بعدی درخواست بدهید تا زمانی که صفحه‌ای کوتاه‌تر از per_page برگردد.

پیام‌های یک کانال (GET /channels/{channel_id}/posts) نیز می‌پذیرند since (یک زمان: همه‌چیز که از آن زمان تغییر کرده است)، یا before و after (یک شناسه پیام). پاسخ به‌صورت یک فهرست پیام برمی‌گردد: {"order": [IDs, newest first], "posts": {ID: post}, "next_post_id", "prev_post_id"}.

خطاها

خطاها از کدهای وضعیت HTTP معمول استفاده می‌کنند (400 ورودی نامعتبر، 401 عدم ورود، 403 عدم مجوز، 404 یافت نشد، 501 غیرفعال بودن قابلیت) و بدنه JSON:

{
  "id": "api.context.permissions.app_error",
  "message": "You do not have the appropriate permissions.",
  "detailed_error": "",
  "request_id": "jz8zm5nunpbt8f3gpqsz5dq6so",
  "status_code": 403
}

در کد خود از id استفاده کنید: message به زبان کاربر ترجمه می‌شود. detailed_error خالی است، مگر اینکه سرور در حالت توسعه‌دهنده اجرا شود (ServiceSettings.EnableDeveloper). request_id را به مدیر سرور ذکر کنید: این شناسه در لاگ‌ها موجود است.

محدودیت نرخ

محدود کردن نرخ به صورت پیش‌فرض غیرفعال است. وقتی یک مدیر سیستم آن را فعال می‌کند (کنسول سیستم › محیط › محدود کردن نرخ)، هر کلاینت به صورت پیش‌فرض ۱۰ درخواست در ثانیه با امکان افزایش تا ۱۰۰ درخواست (burst) مجاز است؛ این شمارش بر اساس آدرس IP یا کاربر انجام می‌شود. پاسخ‌ها هدرهای X-RateLimit-Limit، X-RateLimit-Remaining و X-RateLimit-Reset را همراه دارند؛ در صورت عبور از حد مجاز، سرور با کد 429 و هدر Retry-After (به ثانیه) پاسخ می‌دهد. برخی از نقاط پایانی (endpoints)، مانند ورود به سیستم، صرف‌نظر از تنظیمات، محدودیت اختصاصی خود را دارند.

اسکریپتی بنویسید که در صورت دریافت 429 صبر کند و دوباره تلاش کند، و از پُلینگ (polling) خودداری کنید: به جای آن از WebSocket استفاده کنید.

جریان رویدادهای WebSocket

به wss://chat.example.com/api/v4/websocket متصل شوید. یا با هدر Authorization: Bearer در درخواست اتصال احراز هویت کنید، یا با ارسال این پیام به عنوان اولین پیام:

{"seq": 1, "action": "authentication_challenge", "data": {"token": "…"}}

سرور یک رویداد hello ارسال می‌کند، سپس برای هر چیزی که مجاز به مشاهده آن هستید یک رویداد می‌فرستد:

{
  "event": "posted",
  "data": {"channel_id": "…", "channel_type": "O", "post": "{\"id\":\"…\",\"message\":\"Hello\",…}"},
  "broadcast": {"channel_id": "…", "team_id": "", "user_id": "", "omit_users": null},
  "seq": 4
}

توجه داشته باشید که data.post همان پیام به صورت رشته JSON است. رویدادهای رایج: posted، post_edited، post_deleted، reaction_added، reaction_removed، typing، status_change، user_added، direct_added. اپلیکیشن‌ها رویدادهای خاص خود را ارسال می‌کنند که با نام custom_<app id>_<event> مشخص می‌شوند.

شما همچنین می‌توانید عملیات (actions) ارسال کنید، هر کدام با یک seq افزایشی: user_typing با {"channel_id", "parent_id"}، یا get_statuses. هنگام قطع شدن اتصال دوباره متصل شوید و آنچه را از دست داده‌اید با since بازیابی کنید (به صفحه‌بندی مراجعه کنید).

Antimatter این رویدادها را اضافه می‌کند: community_attributes_updated, member_timeouts_updated, post_put_on_top, post_removed_from_top, server_categories_updated, channel_overrides_updated و category_overrides_updated.

کتابخانه‌های کلاینت

  • برو: model.Client4 در مسیر server/public/model (با import کردن github.com/mattermost/mattermost/server/public/model). ابتدا model.NewAPIv4Client(url) را صدا بزنید، سپس client.SetToken(token) را؛ model.NewWebSocketClient4(wsURL, token) رویدادها را دنبال می‌کند. نسخه Antimatter روش‌هایی برای نقاط پایانی اختصاصی خود، مانند UpdateMessageRequest، PutPostOnTop و ExportChannel اضافه کرده است.
  • TypeScript: کلاس Client4 از بسته @mattermost/client در مسیر webapp/platform/client، با تایپ‌های آن در webapp/platform/types. نسخه موجود در مخزن Antimatter شامل نقاط پایانی Antimatter است؛ اما بسته‌ای که Mattermost در npm منتشر کرده، این موارد را ندارد.
package main

import (
	"context"
	"log"

	"github.com/mattermost/mattermost/server/public/model"
)

func main() {
	client := model.NewAPIv4Client("https://chat.example.com")
	client.SetToken("…")
	post, _, err := client.CreatePost(context.Background(), &model.Post{
		ChannelId: "…",
		Message:   "Hello from Go",
	})
	if err != nil {
		log.Fatal(err)
	}
	log.Println("posted", post.Id)
}

GET /posts/{post_id}/speechپیام به‌صورت صوتی که هنگام پیکربندی تبدیل متن به گفتار پخش می‌شود.

فیلدهای جدید

  • جوامع (Team، و PUT /teams/{team_id}/patch): all_channels_membership (همه افراد عضو تمام کانال‌هایی هستند که می‌توانند آن‌ها را ببینند، مانند Discord)، default_channel_id (جایی که افراد جدید به آن وارد می‌شوند؛ اگر خالی باشد، Town Square در نظر گرفته می‌شود)، hide_role_colors، require_team_badges، onboarding و autolinks (هر دو رشته JSON هستند).
  • پاسخ‌های درون‌متنی: پستی با "props": {"reply_to": "<post id>"} پیام همان کانال را نقل می‌کند. برای اینکه نویسنده آن پیام اعلان دریافت نکند، "reply_to_mention": false را اضافه کنید. سرور metadata.reply_to را با یک توضیح کوتاه از پیام نقل‌شده پر می‌کند.
  • اسپویلرها: "props": {"spoiler": true} متن و فایل‌های یک پست را تا زمانی که خواننده بخواهد آن‌ها را ببیند، پنهان می‌کند.
  • نادیده‌گرفتن و مسدودکردن ترجیحات کاربری هستند: دسته user_block، نام‌گذاری‌شده بر اساس شناسه شخص دیگر، با مقدار ignore یا block. اینکه آیا یک پیام مستقیم به‌صورت درخواست در انتظار می‌ماند یا نه، در notify_props.dm_request عضو کانال شما مشخص است (pending، accepted یا dismissed).
  • پیوست‌های پیام می‌توانند stages و یک chart داشته باشند: به کارت‌ها مراجعه کنید.
