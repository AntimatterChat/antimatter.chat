نصب با Docker Compose

این روش توصیه‌شده است. یک فایل compose، Antimatter، PostgreSQL، ذخیره‌سازی فایل و سرویس GIF را اجرا می‌کند. شما به یک سرور لینوکس با Docker Engine و افزونه Compose آن (docker compose)، ۲ هسته CPU و ۴ گیگابایت حافظه یا بیشتر نیاز دارید.

۱. دانلود فایل compose

mkdir antimatter && cd antimatter
curl -fsSLO https://antimatter.chat/compose.yaml

۲. ساخت فایل .env

فایل compose تنظیمات خود را از یک فایل .env در همان دایرکتوری می‌خواند. آن را با رازهای تصادفی ایجاد کنید:

cat > .env <<EOF
SITE_URL=http://localhost:8065
POSTGRES_PASSWORD=$(openssl rand -hex 24)
S3_SECRET_KEY=$(openssl rand -hex 24)
GIFS_API_KEY=$(openssl rand -hex 24)
EOF
chmod 600 .env

SITE_URL را به آدرسی تنظیم کنید که افراد در مرورگر خود تایپ می‌کنند، برای مثال http://192.168.1.20:8065 در یک شبکه محلی یا https://chat.example.com با یک دامنه. فایل .env را نگه دارید: پایگاه داده و ذخیره‌سازی از اولین اجرا از این گذرواژه‌ها استفاده می‌کنند و برای بازیابی یک پشتیبان به همان فایل نیاز دارید.

۳. اجرای آن

docker compose up -d
docker compose ps

اجرای اولیه یک یا دو دقیقه طول می‌کشد: PostgreSQL پایگاه داده را ایجاد می‌کند، یک سرویس یک‌بار مصرف bucket سطل ذخیره‌سازی را ایجاد می‌کند، یک سرویس یک‌بار مصرف gifs-stickers بسته برچسب‌های شروع را وارد می‌کند و Antimatter جدول‌های خود را ایجاد می‌کند. با docker compose logs -f antimatter از آن پیروی کنید.

برای استفاده از نام دامنه و HTTPS از ابتدا، به دامنه و HTTPS مراجعه کنید: با فایل compose، این دو خط دیگر در .env و پروفایل https است.

PostgreSQL، ذخیره‌سازی و سرویس GIF روی یک شبکه داخلی (private) بدون دسترسی به اینترنت قرار دارند که فقط Antimatter به آن پیوسته است. هیچ‌کدام از این‌ها پورتی را منتشر نمی‌کنند.

کانتینر Antimatter چیزی روی دیسک نگه نمی‌دارد: تنظیمات آن در پایگاه داده است (AM_CONFIG به آن اشاره می‌کند) و فایل‌ها و اپلیکیشن‌های آن در سرویس ذخیره‌سازی. می‌توانید کانتینر را در هر زمان حذف و دوباره بسازید. همه چیز برای پشتیبان‌گیری در حجم‌های postgres، files و gifs است، به‌علاوه .env شما.

یک تصویر انتخاب کنید

دو تصویر Antimatter منتشر شده است، هر دو برای linux/amd64 و linux/arm64، و هر دو از شاخه main هر مخزن ساخته شده‌اند:

تصویراپلیکیشن‌های همراهتگ‌ها
ghcr.io/antimatterchat/antimatterAgents, Calls, GitHub, GitLab, Jira, Kanban, Metrics and Playbooks.latest، X.Y.Z برای ریلیزها، sha-<commit>
ghcr.io/antimatterchat/antimatter-nextهمان موارد، به‌علاوه کانال‌های صوتی، نظرسنجی‌ها، Mail, Calendar, Notes, Whiteboard, GIFs, Todo and Memes. هر شب بازسازی می‌شود.latest, nightly, nightly-<YYYYMMDD>, sha-<commit>

فایل compose سایت از antimatter-next استفاده می‌کند، زیرا سرویس GIF و بیشتر اپلیکیشن‌های توضیح‌داده‌شده در این سایت فقط در آن تصویر موجود است. برای تغییر تصویر، ANTIMATTER_IMAGE را در .env تنظیم کنید و docker compose up -d را اجرا کنید.

latest زیر پای شما تغییر می‌کند. در محیط تولید، یک تگ مانند nightly-20261015 یا sha-<commit> را پین کنید و فقط هنگام ارتقا به‌طور عمدی آن را تغییر دهید. سرور هنگام راه‌اندازی پایگاه داده خود را ارتقا می‌دهد، بنابراین نمی‌توانید بدون بازگرداندن یک پشتیبان‌گیری گرفته‌شده قبل از آن، به یک تصویر قدیمی‌تر یا از antimatter-next به antimatter برگردید. به پشتیبان‌گیری و ارتقا مراجعه کنید.

داخل تصویر

  • سرور در /antimatter قرار دارد، با باینری‌های antimatter و amctl در /antimatter/bin (روی PATH).
  • به‌عنوان کاربر غیرمجاز antimatter (uid 2000) روی یک پایه distroless حداقلی اجرا می‌شود، بدون shell.
  • پورت‌ها: 8065 (وب و API)، 8067 (metrics)، 8074 (cluster)، 8443 UDP و TCP (مکالمه‌ها).
  • حالت محلی (ServiceSettings.EnableLocalMode) فعال است، بنابراین amctl --local داخل کانتینر کار می‌کند. بررسی سلامت سیستم با اجرای amctl system status --local انجام می‌شود.
  • اپلیکیشن‌های همراه در مسیر /antimatter/prepackaged_plugins قرار دارند و با کلید امضای اپلیکیشن‌های Antimatter امضا شده‌اند.
  • ابزارهای استخراج متن (pdftotext، wvText، unrtf و tidy) در دسترس هستند، بنابراین می‌توانید در محتوای اسناد بارگذاری‌شده جستجو کنید.

فایل‌های compose دیگر

مخزن antimatter-docker یک پیکربندی برای محیط تولید در مسیر deploy/compose/ دارد: nginx با گواهی‌های شخصی شما یا Let's Encrypt (certbot)، PostgreSQL، سرویس اختیاری GIF (پروفایل gifs) و حجم‌های نام‌گذاری‌شده برای پیکربندی، داده‌ها و لاگ‌های سرور که در README آن مستند شده است. این پیکربندی به‌طور پیش‌فرض از تصویر پایدار استفاده می‌کند و فایل‌ها را به‌جای ذخیره‌سازی S3 در یک حجم محلی نگه می‌دارد. اگر ترجیح می‌دهید به‌جای Caddy از nginx استفاده کنید یا از قبل گواهی دارید، از این پیکربندی بهره ببرید.

ایجاد اولین مدیر سیستم

SITE_URL را در مرورگر خود باز کنید و یک حساب کاربری بسازید. اولین حسابی که روی یک سرور جدید ساخته می‌شود، مدیر سیستم می‌شود و سپس پیکربندی شما را در ایجاد اولین جامعه (نامی که Antimatter برای تیم یا فضای کاری به کار می‌برد) راهنمایی می‌کند.

این کار را بلافاصله پس از اولین راه‌اندازی انجام دهید؛ تا آن زمان، هر کسی که زودتر به سرور دسترسی پیدا کند، مدیر آن خواهد شد. برای ایجاد حساب از خط فرمان به‌جای مرورگر، پیش از آنکه سرور از بیرون قابل دسترسی باشد:

docker compose exec antimatter amctl --local user create --system-admin --email-verified \
    --email admin@example.com --username admin --password 'a-long-password'
docker compose exec antimatter amctl --local team create --name main --display-name "Main"
docker compose exec antimatter amctl --local team users add main admin

سپس در SITE_URL وارد شوید. دستور را با یک فاصله شروع کنید تا رمز عبور در تاریخچه shell شما ذخیره نشود (با تنظیم HISTCONTROL=ignorespace)، یا پس از ورود، رمز عبور را تغییر دهید.

گام‌های بعدی پس از ورود:

  1. تعیین کنید چه کسانی می‌توانند حساب کاربری بسازند: ورود و حساب‌های کاربری.
  2. ایمیل را پیکربندی کنید تا دعوت‌نامه‌ها و بازنشانی رمز عبور کار کنند: ایمیل و اعلان‌های push.
  3. پورت مکالمات را در فایروال خود باز کنید: مکالمات و صدا.
  4. بررسی کنید کدام اپلیکیشن‌ها فعال هستند: اپلیکیشن‌های همراه.

نصب از بایگانی نسخه

بدون Docker، سرور از یک بایگانی به نام antimatter-<os>-<arch>.tar.gz (برای مثال antimatter-linux-amd64.tar.gz) اجرا می‌شود. این بایگانی شامل یک دایرکتوری واحد به نام antimatter/ است که در آن bin/antimatter، bin/amctl، config/config.json، برنامه‌های وب (client/ و client-fusion/)، قالب‌های ایمیل و ترجمه‌ها قرار دارند.

۱. آماده‌سازی PostgreSQL

Antimatter فقط از PostgreSQL نسخه ۱۵ یا جدیدتر پشتیبانی می‌کند (نسخه‌های قدیمی با خطا در لاگ راه‌اندازی می‌شوند). یک کاربر و یک پایگاه داده ایجاد کنید:

sudo -u postgres psql <<'EOF'
CREATE USER antimatter WITH PASSWORD 'a-long-password';
CREATE DATABASE antimatter OWNER antimatter;
EOF

۲. استخراج و پیکربندی

sudo tar -xzf antimatter-linux-amd64.tar.gz -C /opt
sudo useradd --system --user-group antimatter
sudo mkdir -p /opt/antimatter/data
sudo chown -R antimatter:antimatter /opt/antimatter

سرور را به پایگاه داده متصل کنید، چه در /opt/antimatter/config/config.json (SqlSettings.DataSource) و چه با متغیرهای محیطی، و آدرس سایت را تنظیم کنید:

AM_SQLSETTINGS_DRIVERNAME=postgres
AM_SQLSETTINGS_DATASOURCE=postgres://antimatter:a-long-password@localhost:5432/antimatter?sslmode=disable&connect_timeout=10
AM_SERVICESETTINGS_SITEURL=https://chat.example.com

فایل config.json موجود در بایگانی یک پیکربندی پیش‌فرض کامل است: تنظیماتی که در کنسول سیستم تغییر می‌دهید، دوباره در آن ذخیره می‌شوند. اگر می‌خواهید پیکربندی را در پایگاه داده نگه دارید، به پیکربندی مراجعه کنید.

۳. اجرای آن به‌عنوان یک سرویس

یک واحد systemd در /etc/systemd/system/antimatter.service:

[Unit]
Description=Antimatter
After=network.target postgresql.service

[Service]
Type=notify
User=antimatter
Group=antimatter
WorkingDirectory=/opt/antimatter
ExecStart=/opt/antimatter/bin/antimatter
EnvironmentFile=-/etc/antimatter.env
TimeoutStartSec=3600
Restart=always
RestartSec=10
LimitNOFILE=49152

[Install]
WantedBy=multi-user.target

متغیرهای AM_ خود را در /etc/antimatter.env (فقط قابل خواندن توسط root) قرار دهید، سپس:

sudo systemctl daemon-reload
sudo systemctl enable --now antimatter
journalctl -u antimatter -f

سرور روی پورت ۸۰۶۵ گوش می‌دهد. http://<server>:8065 را باز کنید، یا دامنه خود را پس از راه‌اندازی یک reverse proxy (مراجعه به دامنه و HTTPS)، و اولین حساب را ایجاد کنید: این حساب به‌عنوان مدیر سیستم عمل می‌کند.

bin/amctl سرور در حال اجرا را از خط فرمان مدیریت می‌کند. روی خود سرور، بدون نیاز به ورود از طریق حالت محلی کار می‌کند: AM_SERVICESETTINGS_ENABLELOCALMODE=true را تنظیم کنید، سپس sudo -u antimatter /opt/antimatter/bin/amctl --local system status را اجرا کنید.

دستورهای دیگر سرور

علاوه بر اجرای سرور (antimatter یا antimatter server)، این باینری چند دستور نگهداری نیز دارد. این دستورها همان پیکربندی سرور را می‌خوانند.

دستورعملکرد
antimatter versionنسخه، شماره بیلد، تاریخ بیلد و هش بیلد را چاپ می‌کند.
antimatter db pingبررسی می‌کند که آیا پایگاه داده در دسترس است یا خیر.
antimatter db initپیکربندی را در پایگاه داده ایجاد می‌کند (با تنظیم AM_CONFIG به یک URL postgres://).
antimatter db migrateمهاجرت‌های پایگاه داده را اعمال می‌کند بدون اینکه سرور را راه‌اندازی کند.
antimatter db versionآخرین مهاجرتی که روی پایگاه داده اعمال شده است را چاپ می‌کند.
antimatter import bulk, antimatter export bulkداده‌ها را در قالب بULK (حجمی) وارد یا خروجی می‌کند (مراجعه به پشتیبان‌گیری و ارتقاء).
