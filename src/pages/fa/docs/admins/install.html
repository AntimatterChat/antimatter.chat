نصب با Docker Compose

این روش توصیه‌شده است. یک فایل compose، Antimatter، PostgreSQL، ذخیره‌سازی فایل و سرویس GIF را اجرا می‌کند. شما به یک سرور لینوکس با Docker Engine و افزونه Compose آن (docker compose)، ۲ هسته CPU و ۴ گیگابایت حافظه یا بیشتر نیاز دارید.

۱. دانلود فایل compose

mkdir antimatter && cd antimatter
curl -fsSLO https://antimatter.chat/compose.yaml

۲. ایجاد فایل .env

فایل compose تنظیمات خود را از یک فایل .env در همان دایرکتوری می‌خواند. آن را با رازهای تصادفی ایجاد کنید:

cat > .env <<EOF
SITE_URL=http://localhost:8065
POSTGRES_PASSWORD=$(openssl rand -hex 24)
S3_SECRET_KEY=$(openssl rand -hex 24)
GIFS_API_KEY=$(openssl rand -hex 24)
AM_AI_ENCRYPTION_KEY=$(openssl rand -base64 32)
EOF
chmod 600 .env

SITE_URL را به آدرسی تنظیم کنید که افراد در مرورگر خود تایپ می‌کنند، برای مثال http://192.168.1.20:8065 در یک شبکه محلی یا https://chat.example.com با یک دامنه. فایل .env را نگه دارید: پایگاه داده و ذخیره‌سازی از اولین اجرا از این گذرواژه‌ها استفاده می‌کنند، کلیدهای API اتصالات مدل‌های هوش مصنوعی با AM_AI_ENCRYPTION_KEY رمزگذاری می‌شوند، و برای بازیابی یک پشتیبان به همان فایل نیاز دارید.

۳. اجرای آن

docker compose up -d
docker compose ps

اجرای اولیه یک یا دو دقیقه طول می‌کشد: PostgreSQL پایگاه داده را ایجاد می‌کند، یک سرویس یک‌بار مصرف bucket سطل ذخیره‌سازی را ایجاد می‌کند، یک سرویس یک‌بار مصرف gifs-stickers بسته برچسب‌های شروع را وارد می‌کند، و Antimatter جداول خود را ایجاد می‌کند. با docker compose logs -f antimatter از آن پیروی کنید.

برای استفاده از نام دامنه و HTTPS از ابتدا، به دامنه و HTTPS مراجعه کنید: با فایل compose، این دو خط دیگر در .env و پروفایل https است.

PostgreSQL، ذخیره‌سازی و سرویس GIF روی یک شبکه داخلی (private) بدون دسترسی به اینترنت قرار دارند که فقط Antimatter به آن پیوسته است. هیچ‌کدام از این‌ها پورتی را منتشر نمی‌کنند.

کانتینر Antimatter چیزی روی دیسک نگه نمی‌دارد: تنظیمات آن در پایگاه داده است (AM_CONFIG به آن اشاره می‌کند) و فایل‌ها و اپ‌های آن در سرویس ذخیره‌سازی. می‌توانید هر زمان کانتینر را حذف و دوباره بسازید. حجم data آن فقط فایل کلید رمزنگاری AI را نگه می‌دارد که سرور هنگام خالی بودن AM_AI_ENCRYPTION_KEY آن را می‌سازد. همه چیز برای پشتیبان‌گیری در حجم‌های postgres، files، gifs و data است، به‌علاوه فایل .env شما.

انتخاب تصویر

دو تصویر Antimatter منتشر شده است، هر دو برای linux/amd64 و linux/arm64، و هر دو از شاخه main همه مخازن ساخته شده‌اند:

تصویراپلیکیشن‌های همراهتگ‌ها
ghcr.io/antimatterchat/antimatterAgents, Calls, GitHub, GitLab, Jira, Kanban, Metrics and Playbooks.latest، X.Y.Z برای نسخه‌های رسمی، sha-<commit>
ghcr.io/antimatterchat/antimatter-nextهمان موارد، به‌علاوه کانال‌های صوتی، نظرسنجی، ایمیل، تقویم، یادداشت، تخته سفید، GIF، کارهای در انتظار و میم. هر شب دوباره ساخته می‌شود.latest, nightly, nightly-<YYYYMMDD>, sha-<commit>

فایل compose سایت از antimatter-next استفاده می‌کند، زیرا سرویس GIF و بیشتر اپ‌های توضیح‌داده‌شده در این سایت فقط در آن تصویر موجود است. برای تغییر تصویر، ANTIMATTER_IMAGE را در .env تنظیم کنید و docker compose up -d را اجرا کنید.

تغییرات latest زیر شما قرار می‌گیرند. در محیط تولید، یک تگ مانند nightly-20261015 یا sha-<commit> را مشخص (pin) کنید و هنگام ارتقاء، آن را به‌طور آگاهانه تغییر دهید. سرور هنگام راه‌اندازی، پایگاه داده خود را ارتقاء می‌دهد، بنابراین بدون بازگردانی یک پشتیبان‌گیری که پیش از آن گرفته شده باشد، نمی‌توانید به یک تصویر (image) قدیمی‌تر برگردید یا از antimatter-next به antimatter تغییر دهید. برای جزئیات بیشتر، به پشتیبان‌گیری و ارتقاء مراجعه کنید.

داخل تصویر

  • سرور در مسیر /antimatter قرار دارد و باینری‌های antimatter و amctl در /antimatter/bin (روی PATH) موجود هستند.
  • این سرور به‌عنوان کاربر بدون امتیاز antimatter (uid 2000) روی یک پایه (base) مینیمال distroless اجرا می‌شود و هیچ شلی (shell) در آن وجود ندارد.
  • پورت‌ها: 8065 (وب و API)، 8067 (متریک‌ها)، 8074 (کلاستر)، 8443 UDP و TCP (مکالمه‌ها).
  • حالت محلی (ServiceSettings.EnableLocalMode) فعال است، بنابراین amctl --local داخل کانتینر کار می‌کند. بررسی سلامت (health check) دستور amctl system status --local را اجرا می‌کند.
  • اپلیکیشن‌های همراه (bundled) در مسیر /antimatter/prepackaged_plugins قرار دارند و با کلید امضای اپلیکیشن‌های Antimatter امضا شده‌اند.
  • ابزارهای استخراج متن (pdftotext، wvText، unrtf، tidy) نیز شامل شده‌اند، بنابراین می‌توان محتوای اسناد بارگذاری‌شده را جستجو کرد.

فایل‌های compose دیگر

مخزن antimatter-docker یک تنظیمات تولید در مسیر deploy/compose/ دارد: nginx با گواهی‌های شما یا Let's Encrypt (certbot)، PostgreSQL، سرویس اختیاری GIF (پروفایل gifs) و حجم‌های نام‌گذاری‌شده (named volumes) برای پیکربندی، داده و لاگ‌های سرور که در README آن مستند شده است. این تنظیمات به‌طور پیش‌فرض از تصویر پایدار استفاده می‌کند و فایل‌ها را روی یک حجم محلی ذخیره می‌کند به‌جای ذخیره‌سازی S3. اگر ترجیح می‌دهید به‌جای Caddy از nginx استفاده کنید یا از قبل گواهی‌های خود را دارید، از این تنظیمات استفاده کنید.

ایجاد اولین مدیر سیستم

SITE_URL را در مرورگر خود باز کنید و یک حساب کاربری بسازید. اولین حسابی که روی یک سرور جدید ایجاد می‌شود، مدیر سیستم (system administrator) می‌شود و سپس فرآیند راه‌اندازی شما را در ایجاد اولین جامعه (community) (نام Antimatter برای تیم یا فضای کاری) راهنمایی می‌کند.

این کار را بلافاصله پس از اولین راه‌اندازی انجام دهید: تا آن زمان، هر کسی که اولین بار به سرور دسترسی پیدا کند، مدیر آن خواهد شد. برای ایجاد حساب از طریق خط فرمان به‌جای مرورگر، پیش از آنکه سرور از بیرون قابل دسترس باشد:

docker compose exec antimatter amctl --local user create --system-admin --email-verified \
    --email admin@example.com --username admin --password 'a-long-password'
docker compose exec antimatter amctl --local team create --name main --display-name "Main"
docker compose exec antimatter amctl --local team users add main admin

سپس در SITE_URL وارد شوید. برای جلوگیری از ثبت رمز عبور در تاریخچهٔ shell، دستور را با یک فاصله شروع کنید (با HISTCONTROL=ignorespace)، یا پس از ورود، رمز عبور را یک بار تغییر دهید.

گام‌های بعدی پس از ورود:

  1. برای یک شرکت یا سازمان، نوع جوامع جدید را روی محل کار تنظیم کنید و نوع جامعه‌ای که قبلاً ایجاد کرده‌اید را در تنظیمات آن تغییر دهید: محل کار یا جامعه.
  2. تعیین کنید چه کسانی می‌توانند حساب کاربری ایجاد کنند: ورود و حساب‌ها.
  3. ایمیل را پیکربندی کنید تا دعوت‌نامه‌ها و بازنشانی رمز عبور کار کنند: ایمیل و اعلان‌های push.
  4. پورت مکالمات را در فایروال خود باز کنید: مکالمات و صدا.
  5. بررسی کنید کدام اپلیکیشن‌ها فعال هستند: اپلیکیشن‌های همراه.

دانلود نسخه

بدون Docker، Antimatter را از فایل‌های یک نسخه در GitHub نصب کنید: github.com/AntimatterChat/antimatter/releases. هر نسخه دارای یک شماره نسخه مانند 0.9.0 است و تگ آن همان عدد با یک v در ابتدای آن است (v0.9.0).

Antimatter در حالت بتا است: نسخه‌های آن در سری 0.9.0 هستند. نسخه‌ای که پس از خط تیره در شماره نسخه، پسوندی دارد، مانند 0.9.0-rc.1، در GitHub با برچسب پیش‌نسخه مشخص شده است. این یک نسخه آزمایشی است که قبل از انتشار نهایی منتشر می‌شود.

هر نسخه دارای این فایل‌ها است، برای سرورهای amd64 و arm64:

فایلآن چیست
antimatter_<version>-1_amd64.deb, antimatter_<version>-1_arm64.debبسته برای Debian، Ubuntu و توزیع‌های مبتنی بر آن‌ها.
antimatter-<version>-1.x86_64.rpm, antimatter-<version>-1.aarch64.rpmبسته برای Fedora، RHEL و توزیع‌های سازگار با RHEL.
antimatter-<version>-linux-amd64.tar.gz, antimatter-<version>-linux-arm64.tar.gzبایگانی نسخه، برای هر توزیع لینوکس، با تنظیم دستی.
SHA256SUMSکد تأیید SHA-256 برای تمام فایل‌های نسخه.

بسته‌ها و بایگانی، برنامه یکسانی را در بر می‌گیرند: سرور (antimatter)، ابزار خط فرمان (amctl)، هر دو اپلیکیشن وب (رابط پیش‌فرض و کلاسیک)، اپلیکیشن‌های همراه، قالب‌های ایمیل و ترجمه‌ها. بسته‌ها یک سرویس systemd و یک فایل تنظیمات اضافه می‌کنند، بنابراین هر کدام یک نصب همه‌کاره است: شما فقط یک پایگاه داده PostgreSQL اضافه می‌کنید. دانلود جداگانه‌ای برای باینری‌ها وجود ندارد: باینری‌ها در بایگانی، در antimatter/bin/ قرار دارند. آن‌ها ایستا (static) هستند، بنابراین روی هر توزیع لینوکس با معماری مربوطه اجرا می‌شوند.

در نام بسته‌ها، خط تیرهٔ نسخهٔ پیش‌رелиز به علامت تیلدا تبدیل می‌شود تا مدیر بسته، نسخهٔ پیش‌رелиز را پیش از نسخهٔ نهایی مرتب کند: نسخهٔ 0.9.0-rc.1 به antimatter_0.9.0~rc.1-1_amd64.deb و antimatter-0.9.0~rc.1-1.x86_64.rpm تبدیل می‌شود. در آرشیو، خط تیره حفظ می‌شود.

antimatter version نسخهٔ انتشار را به‌عنوان شمارهٔ بیلد و کامیت ساخت را به‌عنوان هش ساخت نمایش می‌دهد. خط نسخه، نسخهٔ خط Mattermost است که Antimatter بر پایهٔ آن ساخته شده است.

بررسی دانلود

فایل مورد نیاز و SHA256SUMS را از صفحهٔ انتشار یا با curl در یک دایرکتوری مشترک دانلود کنید، سپس فایل را بررسی کنید:

curl -fLO https://github.com/AntimatterChat/antimatter/releases/download/v<version>/antimatter_<version>-1_amd64.deb
curl -fLO https://github.com/AntimatterChat/antimatter/releases/download/v<version>/SHA256SUMS
sha256sum --check --ignore-missing SHA256SUMS

هر فایل دانلودشده باید با OK فهرست شود. هر نتیجهٔ دیگر به معنای آسیب‌دیده یا ناقص بودن فایل است: دوباره دانلود کنید و آن را نصب نکنید. SHA256SUMS امضا نشده است: فقط دانلود آسیب‌دیده را شناسایی می‌کند و چیزی بیشتر از آنچه دانلود HTTPS از GitHub اثبات می‌کند، اثبات نمی‌کند.

نصب بستهٔ .deb یا .rpm

این بسته، Antimatter را به‌عنوان یک سرویس systemd نصب می‌کند که برای راه‌اندازی فقط به یک پایگاه داده نیاز دارد. از آن روی سرورهای ۶۴ بیتی سازگار با Debian، Ubuntu، Fedora یا RHEL که systemd دارند استفاده کنید.

محتوای نصب‌شده توسط بسته

مسیرمحتوا
/opt/antimatterبرنامه: bin/antimatter، bin/amctl، برنامه‌های وب (client/، client-fusion/)، برنامه‌های همراه (prepackaged_plugins/)، قالب‌ها، ترجمه‌ها و فونت‌ها. هر ارتقاء آن را جایگزین می‌کند.
/etc/antimatter/antimatter.envتنظیمات سرویس، به‌صورت متغیرهای AM_: پایگاه داده، آدرس سایت و سرویس GIF. فقط root می‌تواند آن را بخواند. ارتقاء‌ها آن را حفظ می‌کنند.
/etc/antimatter/config/config.jsonفایل پیکربندی، جایی که سرور تنظیمات تغییر‌یافته در کنسول سیستم را ذخیره می‌کند. در اولین نصب از /opt/antimatter/defaults/config.json ساخته می‌شود و پس از آن هرگز جایگزین نمی‌شود.
/var/lib/antimatterفایل‌های بارگذاری‌شده (data/) و برنامه‌های نصب‌شده (plugins/، client-plugins/).
/var/log/antimatterفایل‌های لاگ، اگر لاگ‌نویسی فایل را فعال کنید. این گزینه غیرفعال است: لاگ‌ها به ژورنال می‌روند.
/usr/lib/systemd/system/antimatter.serviceسرویس.
/usr/bin/amctlیک لینک به /opt/antimatter/bin/amctl.

دسته‌بندی‌هایی که سرور در مسیر /opt/antimatter به آن‌ها نوشت می‌کند (config، data، plugins، client/plugins و logs) پیوندهایی به /etc/antimatter، /var/lib/antimatter و /var/log/antimatter هستند. بنابراین یک ارتقا، که /opt/antimatter را جایگزین می‌کند، هرگز به داده‌های شما دست نمی‌زند. بسته همچنین کاربر سیستم antimatter را می‌سازد که سرور را اجرا می‌کند و مالک این دسته‌بندی‌هاست.

بسته به ca-certificates وابسته است. PostgreSQL (postgresql در Debian و Ubuntu، postgresql-server در Fedora و RHEL)، media-types (mailcap برای .rpm) و gifs-server، سرویس GIF که ریلیز مستقلی دارد (به زیر مراجعه کنید) را توصیه می‌کند. apt و dnf بسته‌های توصیه‌شده را در صورت یافتن نصب می‌کنند. poppler-utils، wv، unrtf و tidy (بدون wv برای .rpm) را پیشنهاد می‌کند: این‌ها متن اسناد بارگذاری‌شده را استخراج می‌کنند تا جستجو کلمات درون آن‌ها را پیدا کند. اگر این قابلیت را می‌خواهید، خودتان نصب کنید.

۱. نصب بسته‌ها

بسته Antimatter و بسته سرویس GIF معماری خود را دانلود کنید، آن‌ها را مانند بالا بررسی کنید و هر دو را در یک دستور نصب کنید تا توصیه gifs-server برآورده شود (این بسته در مخازن توزیع‌ها موجود نیست):

# Debian, Ubuntu
sudo apt install ./antimatter_<version>-1_amd64.deb ./gifs-server_*_amd64.deb
# Fedora, RHEL
sudo dnf install ./antimatter-<version>-1.x86_64.rpm ./gifs-server-*.x86_64.rpm

./ را نگه دارید: این به apt و dnf می‌گوید که یک فایل محلی را نصب کنند. برای نصب بدون سرویس GIF، بسته آن را حذف کنید. بسته سرویس antimatter را فعال می‌کند اما آن را شروع نمی‌کند و مراحل بعدی را چاپ می‌کند.

۲. ساخت پایگاه داده

Antimatter به PostgreSQL 15 یا جدیدتر نیاز دارد، روی این سرور یا سرور دیگری. نسخه PostgreSQL توزیع خود را با psql --version بررسی کنید. اگر قدیمی‌تر است، نسخه جدیدتر را از مخازن خود پروژه PostgreSQL نصب کنید یا از پایگاه داده روی سرور دیگری استفاده کنید. در Debian و Ubuntu، بسته postgresql پایگاه داده را شروع می‌کند. در Fedora و RHEL، ابتدا آن را بسازید و شروع کنید:

sudo postgresql-setup --initdb
sudo systemctl enable --now postgresql

سپس یک کاربر و یک پایگاه داده برای Antimatter بسازید:

sudo -u postgres psql -c "CREATE USER antimatter WITH PASSWORD 'a-long-password'"
sudo -u postgres psql -c "CREATE DATABASE antimatter OWNER antimatter"

PostgreSQL باید اتصالات با رمز عبور از 127.0.0.1 را بپذیرد: خطوط host در فایل pg_hba.conf آن، با روش scram-sha-256.

۳. تنظیم پایگاه داده و آدرس سایت

فایل /etc/antimatter/antimatter.env را ویرایش کنید (sudoedit /etc/antimatter/antimatter.env). علامت # را از جلوی خطوطی که استفاده می‌کنید حذف کنید و پایگاه داده و آدرسی که افراد برای دسترسی به آن استفاده می‌کنند را تنظیم کنید:

AM_SQLSETTINGS_DRIVERNAME=postgres
AM_SQLSETTINGS_DATASOURCE=postgres://antimatter:a-long-password@localhost:5432/antimatter?sslmode=disable&connect_timeout=10
AM_SERVICESETTINGS_SITEURL=https://chat.example.com

هر تنظیمی از پیکربندی می‌تواند در این فایل قرار گیرد، به صورت AM_<SECTION>_<SETTING>: برای مثال، SqlSettings.DataSource به صورت AM_SQLSETTINGS_DATASOURCE است. تنظیماتی که در اینجا انجام شود، نمی‌تواند در کنسول سیستم تغییر کند. برای جزئیات بیشتر به پیکربندی مراجعه کنید. پس از هر تغییر، سرور را مجدداً راه‌اندازی کنید: sudo systemctl restart antimatter.

این سرویس همچنین چند مقدار پیش‌فرض را تنظیم می‌کند که می‌تواند با یک خط در antimatter.env بازنویسی شود: ثبت رویدادها در فایل‌ها غیرفعال است (AM_LOGSETTINGS_ENABLEFILE=false, AM_NOTIFICATIONLOGSETTINGS_ENABLEFILE=false) و حالت محلی فعال است (AM_SERVICESETTINGS_ENABLELOCALMODE=true) تا دستور amctl --local روی سرور کار کند.

۴. راه‌اندازی

sudo systemctl start antimatter
journalctl -u antimatter -f
sudo -u antimatter amctl --local system status

در اولین راه‌اندازی، سرور جداول خود را ایجاد می‌کند و سپس روی پورت 8065 گوش می‌دهد. آدرس http://<server>:8065 را باز کنید، یا دامنه خود را پس از تنظیم یک پروکسی معکوس (برای جزئیات به دامنه و HTTPS مراجعه کنید) و بلافاصله اولین حساب را ایجاد کنید: این حساب به عنوان مدیر سیستم عمل خواهد کرد. برای ایجاد آن از خط فرمان، از دستورات amctl در بخش ایجاد اولین مدیر استفاده کنید، با جایگزینی sudo -u antimatter amctl --local به جای docker compose exec antimatter amctl --local.

۵. فعال‌سازی GIFها

اپلیکیشن GIFها همراه با نرم‌افزار ارائه شده و فعال است، و antimatter.env از قبل آن را به سرویس GIF روی همان سرور متصل کرده است (AM_GIFS_SERVICE_URL=http://127.0.0.1:8080/v2). اما هنوز به کلید API سرویس نیاز دارد. بسته gifs-server هنگام نصب یک کلید تولید کرده است:

sudo systemctl start gifs-server-stickers    # imports the sticker pack, about a minute and a half
sudo systemctl start gifs-server
sudo grep -v '^#' /etc/gifs-server/api-keys

کلید را در antimatter.env به صورت AM_GIFS_API_KEY=<key> قرار دهید و Antimatter را مجدداً راه‌اندازی کنید، یا آن را به عنوان کلید API در کنسول سیستم › پلاگین ها › GIFها وارد کنید. اگر سرویس GIF روی سرور دیگری اجرا شود، AM_GIFS_SERVICE_URL را به آدرس آن تنظیم کنید. برای اجازه دادن به افراد جهت افزودن GIFها و استیکرهای خودشان، به GIFها مراجعه کنید.

سرویس

  • این سرویس به‌عنوان کاربر antimatter در مسیر /opt/antimatter اجرا می‌شود و فایل /etc/antimatter/antimatter.env را می‌خواند. systemd هر بار که سرور متوقف شود، آن را مجدداً راه‌اندازی می‌کند و برای شروع تا یک ساعت زمان می‌دهد، زیرا مهاجرت‌های پایگاه داده در نسخه‌های جدید ممکن است طولانی باشد.
  • لاگ‌های آن در ژورنال ثبت می‌شوند: journalctl -u antimatter.
  • این سرویس ایمن‌سازی شده است: /usr و /etc برای سرور فقط‌خواندنی هستند، به‌جز /etc/antimatter/config، و دسترسی به /home، /root یا /run/user ندارد. اگر محل ذخیره‌سازی فایل‌ها (FileSettings.Directory) را تغییر می‌دهید، دایرکتوری‌ای خارج از این مسیرها انتخاب کنید که مالک آن کاربر antimatter باشد.
  • در هنگام ارتقاء، فایل سرویس جایگزین می‌شود. برای تغییر آن از sudo systemctl edit antimatter استفاده کنید تا تغییرات شما در یک فایل جداگانه حفظ شود.

ارتقاء یک بسته

  1. یک پشتیبان تهیه کنید (به پشتیبان‌گیری و ارتقاء مراجعه کنید).
  2. بسته و فایل SHA256SUMS جدید را دانلود کنید و صحت آن‌ها را بررسی کنید.
  3. سرور را متوقف کنید، بسته جدید را روی نسخه قدیمی نصب کنید و دوباره راه‌اندازی کنید: 
    sudo systemctl stop antimatter
sudo apt install ./antimatter_<new version>-1_amd64.deb     # or: sudo dnf install ./antimatter-<new version>-1.x86_64.rpm
sudo systemctl start antimatter
journalctl -u antimatter -f

بسته به‌تنهایی سرور را مجدداً راه‌اندازی نمی‌کند. پس از ارتقاء، پیام Antimatter was upgraded; restart it to run the new version: sudo systemctl restart antimatter را نمایش می‌دهد: اگر ابتدا سرور را متوقف نکرده‌اید، فوراً آن را مجدداً راه‌اندازی کنید. ارتقاء، /opt/antimatter و فایل سرویس را جایگزین می‌کند، اما antimatter.env، config.json، /var/lib/antimatter و لاگ‌ها را حفظ می‌کند. هنگام راه‌اندازی، سرور پایگاه داده را ارتقاء می‌دهد و نسخه‌های جدیدتر از برنامه‌های همراه را نصب می‌کند.

اگر نسخه جدید antimatter.env پیش‌فرض را تغییر دهد، apt از شما می‌پرسد که آیا نسخه خود را نگه دارید یا خیر: آن را نگه دارید. dnf نسخه شما را حفظ می‌کند و نسخه جدید را به‌عنوان /etc/antimatter/antimatter.env.rpmnew ذخیره می‌کند. ارتقاء فقط به جلو انجام می‌شود: نسخه قدیمی‌تر را روی نسخه جدیدتر نصب نکنید.

حذف یک بسته

sudo apt remove antimatter یا sudo dnf remove antimatter سرویس را متوقف و غیرفعال می‌کند و برنامه را حذف می‌نماید. اما داده‌ها (/var/lib/antimatter)، پیکربندی (/etc/antimatter)، پایگاه داده و کاربر antimatter را حفظ می‌کند: برای حذف کامل Antimatter، باید این موارد را خودتان حذف کنید.

برنامه‌ها در بسته‌ها و بایگانی

بسته‌ها و بایگانی، آخرین نسخهٔ امضاشدهٔ این برنامه‌ها را در prepackaged_plugins/ شامل می‌شوند: Agents، Calls، GIFs، Memes، Notes، Polls، Todo، Voice Channels و Whiteboard. برنامه‌ای که هنگام ساخت نسخهٔ سرور هنوز نسخه‌ای از آن منتشر نشده بود، حذف می‌شود: با اجرای ls /opt/antimatter/prepackaged_plugins می‌توانید ببینید نسخهٔ شما چه برنامه‌هایی را شامل می‌شود. Memes و Todo موجود هستند اما فعال نشده‌اند: برنامه‌های همراه توضیح می‌دهد که چگونه نصب و فعال‌سازی شوند.

سایر برنامه‌های موجود در تصاویر Docker در بسته‌ها یا بایگانی نیستند: Kanban، Playbooks، Mail، Calendar، GitHub، GitLab، Jira و Metrics. هر یک را از نسخه‌های منتشرشدهٔ خودشان نصب کنید:

هر نسخهٔ منتشرشدهٔ برنامه، باندل برنامه (یک فایل .tar.gz)، امضای آن (با نام یکسان به همراه پسوند .sig) و یک فایل SHA256SUMS را شامل می‌شود. برای نصب یک برنامه، بارگذاری را مجاز کنید، سپس باندل را با amctl اضافه کنید:

# 1. In /etc/antimatter/antimatter.env, add this line, then restart Antimatter
AM_PLUGINSETTINGS_ENABLEUPLOADS=true
sudo systemctl restart antimatter
# 2. Download the bundle where the antimatter user can read it, and install it
cd /tmp
curl -fLO https://github.com/AntimatterChat/antimatter-plugin-boards/releases/download/v<version>/<bundle>.tar.gz
sudo -u antimatter amctl --local plugin add <bundle>.tar.gz
sudo -u antimatter amctl --local plugin enable focalboard

برای ارتقاء برنامه‌ای که به این روش نصب شده، باندل جدید را با plugin add --force اضافه کنید: ارتقاء بسته‌ها فقط برنامه‌های همراه را ارتقاء می‌دهد. می‌توانید بعداً خط AM_PLUGINSETTINGS_ENABLEUPLOADS را دوباره حذف کنید. برای سایر روش‌های نصب برنامه‌ها، به نصب سایر برنامه‌ها مراجعه کنید.

امضای برنامه‌ها

باندل‌های برنامه با کلید امضای برنامه‌های Antimatter امضا شده‌اند: هر فایل .tar.gz.sig یک امضای GPG جداگانه برای باندل مربوطه است. سرور قبل از نصب یک برنامهٔ همراه، این امضاها را بررسی می‌کند. برای بررسی خودتان باندل:

curl -fsSLO https://raw.githubusercontent.com/AntimatterChat/antimatter-docker/main/keys/antimatter-plugin-signing.asc
gpg --import antimatter-plugin-signing.asc
gpg --verify <bundle>.tar.gz.sig <bundle>.tar.gz

gpg باید یک امضای معتبر از Antimatter Plugin Signing با اثر انگشت 06C8 1032 4677 0F08 BBA7 78B9 E69B 05C3 92A6 9A45 گزارش دهد. همچنین هشدار می‌دهد که این کلید با یک امضای مورد اعتماد تأیید نشده است؛ این برای کلیدی که خودتان امضا نکرده‌اید، طبیعی است. انتشاری از یک اپلیکیشن که فایل‌های .sig ندارد، بدون امضا است و در یادداشت‌های انتشار آن به این موضوع اشاره شده است.

نصب از بایگانی انتشار

بایگانی antimatter-<version>-linux-<arch>.tar.gz (برای مثال antimatter-0.9.0-linux-amd64.tar.gz) برای توزیع‌هایی که بسته‌های .deb یا .rpm ندارند، یا برای چیدمان‌های سفارشی شما مناسب است. این بایگانی شامل یک دایرکتوری واحد antimatter/ با bin/antimatter، bin/amctl، config/config.json، اپلیکیشن‌های وب (client/ و client-fusion/)، اپلیکیشن‌های همراه (prepackaged_plugins/، به بالا مراجعه کنید)، قالب‌های ایمیل و ترجمه‌ها است.

۱. آماده‌سازی PostgreSQL

Antimatter فقط از PostgreSQL نسخه ۱۵ یا جدیدتر پشتیبانی می‌کند (نسخه‌های قدیمی با خطایی در لاگ راه‌اندازی می‌شوند). یک کاربر و یک پایگاه داده ایجاد کنید:

sudo -u postgres psql <<'EOF'
CREATE USER antimatter WITH PASSWORD 'a-long-password';
CREATE DATABASE antimatter OWNER antimatter;
EOF

۲. استخراج و پیکربندی

sudo tar -xzf antimatter-<version>-linux-amd64.tar.gz -C /opt
sudo useradd --system --user-group antimatter
sudo mkdir -p /opt/antimatter/data
sudo chown -R antimatter:antimatter /opt/antimatter

سرور را به پایگاه داده متصل کنید، یا در /opt/antimatter/config/config.json (SqlSettings.DataSource) یا با متغیرهای محیطی، و آدرس سایت را تنظیم کنید:

AM_SQLSETTINGS_DRIVERNAME=postgres
AM_SQLSETTINGS_DATASOURCE=postgres://antimatter:a-long-password@localhost:5432/antimatter?sslmode=disable&connect_timeout=10
AM_SERVICESETTINGS_SITEURL=https://chat.example.com

فایل config.json موجود در بایگانی یک پیکربندی پیش‌فرض کامل است: تنظیماتی که در کنسول سیستم تغییر می‌دهید، دوباره در آن ذخیره می‌شوند. اگر می‌خواهید پیکربندی را به جای فایل در پایگاه داده نگه دارید، به پیکربندی مراجعه کنید.

۳. اجرای آن به عنوان یک سرویس

یک واحد systemd در /etc/systemd/system/antimatter.service:

[Unit]
Description=Antimatter
After=network.target postgresql.service

[Service]
Type=notify
User=antimatter
Group=antimatter
WorkingDirectory=/opt/antimatter
ExecStart=/opt/antimatter/bin/antimatter
EnvironmentFile=-/etc/antimatter.env
TimeoutStartSec=3600
Restart=always
RestartSec=10
LimitNOFILE=49152

[Install]
WantedBy=multi-user.target

متغیرهای AM_ خود را در /etc/antimatter.env (فقط خواندنی برای root) قرار دهید، سپس:

sudo systemctl daemon-reload
sudo systemctl enable --now antimatter
journalctl -u antimatter -f

سرور روی پورت ۸۰۶۵ گوش می‌دهد. http://<server>:8065 را باز کنید، یا دامنه خود را پس از راه‌اندازی یک پراکسی معکوس (به دامنه و HTTPS مراجعه کنید) و اولین حساب را ایجاد کنید: آن حساب به مدیر سیستم تبدیل می‌شود.

bin/amctl سرور در حال اجرا را از خط فرمان مدیریت می‌کند. روی خود سرور، بدون ورود از طریق حالت محلی کار می‌کند: AM_SERVICESETTINGS_ENABLELOCALMODE=true را تنظیم کنید، سپس sudo -u antimatter /opt/antimatter/bin/amctl --local system status را اجرا کنید.

برای GIFها، سرویس GIF را نصب کنید (در زیر توضیح داده شده) و همان‌طور که در مرحله ۵ بسته‌ها آمده است، AM_GIFS_SERVICE_URL و AM_GIFS_API_KEY را تنظیم کنید.

بسته‌های سرویس GIF و پروکسی push

سرویس GIF و پروکسی push هر کدام ریلیزهای مستقلی دارند که با همان قوانین سرور پیاده‌سازی شده‌اند: یک بایگانی .tar.gz، بسته‌های .deb و .rpm برای amd64 و arm64، و یک فایل SHA256SUMS. نسخه‌هایی که با خط تیره مشخص شده‌اند، پیش‌نسخه (prerelease) هستند. همان‌طور که برای سرور انجام می‌شود، دانلودها را با sha256sum --check --ignore-missing SHA256SUMS بررسی کنید.

سرویس GIF (gifs-server)

رلیزها: github.com/AntimatterChat/gifs-server/releases. بایگانی با نام gifs-server-<version>-linux-<arch>.tar.gz است و بسته‌ها با نام gifs-server شناخته می‌شوند.

sudo apt install ./gifs-server_*_amd64.deb      # Debian, Ubuntu
sudo dnf install ./gifs-server-*.x86_64.rpm     # Fedora, RHEL

بسته موارد زیر را نصب می‌کند:

  • /usr/bin/gifs-server و سرویس gifs-server که به‌عنوان کاربر gifs-server اجرا می‌شود و کاتالوگ خود را در /var/lib/gifs-server نگه می‌دارد؛
  • سرویس gifs-server-stickers که هنگام راه‌اندازی، بسته استیکرهای موجود در /usr/share/gifs-server/stickers را وارد یا به‌روزرسانی می‌کند و سپس متوقف می‌شود؛
  • تنظیمات آن در /etc/gifs-server/gifs-server.env (متغیرهای AM_GIFS_ که هنگام ارتقا حفظ می‌شوند) و /etc/gifs-server/api-keys که در هر خط یک کلید API دارد و در اولین نصب، یک کلید تصادفی تولید می‌شود.

این سرویس روی 127.0.0.1:8080 گوش می‌دهد، بنابراین فقط Antimatter روی همان سرور می‌تواند به آن دسترسی پیدا کند. اگر Antimatter در جای دیگری اجرا شود، AM_GIFS_LISTEN=:8080 را در gifs-server.env تنظیم کنید و دسترسی به پورت را با فایروال خود محدود کنید. این فایل سایر تنظیمات را نیز فهرست می‌کند: AM_GIFS_UPLOAD_KEYS (کلیدهایی که اجازه افزودن GIF و استیکر و حذف موارد اضافه‌شده با آن‌ها را دارند)، AM_GIFS_PUBLIC_URL، AM_GIFS_TRUST_PROXY و AM_GIFS_LOG_LEVEL. بسته به نصب ffmpeg، gifsicle، librsvg2-bin (برای .rpm: librsvg2-tools) و یک فونت DejaVu توصیه می‌کند: سرویس از این ابزارها برای ساخت فرمت‌های GIF، ویدیو و استیکر هنگام وارد کردن یا دریافت فایل‌ها استفاده می‌کند و بدون آن‌ها نیز اجرا می‌شود.

همان‌طور که برای سرور، سرویس در هنگام نصب فعال است اما اجرا نمی‌شود. آن را مطابق با مراحل ۵ بسته‌ها اجرا کنید. پس از ارتقا، آن را از نو راه‌اندازی کنید: sudo systemctl restart gifs-server. با حذف بسته، فهرست در /var/lib/gifs-server باقی می‌ماند.

پروکسی اعلان

نسخه‌ها: github.com/AntimatterChat/push-proxy/releases. بایگانی با نام antimatter-push-proxy-<version>-linux-<arch>.tar.gz است؛ بسته‌ها با نام antimatter-push-proxy شناخته می‌شوند. این بسته /usr/bin/antimatter-push-proxy و سرویس antimatter-push-proxy را نصب می‌کند که به‌عنوان کاربر antimatter-push-proxy اجرا می‌شود و /etc/antimatter-push-proxy/antimatter-push-proxy.json را می‌خواند (در ارتقاها حفظ می‌شود). گواهی‌های Apple و Firebase در /etc/antimatter-push-proxy/certs قرار می‌گیرند: اعلان‌های Push توضیح می‌دهد که این‌ها از کجا می‌آیند.

sudo apt install ./antimatter-push-proxy_*_amd64.deb      # or: sudo dnf install ./antimatter-push-proxy-*.x86_64.rpm
sudo install -o root -g antimatter-push-proxy -m 0640 \
    AuthKey_ABCDE12345.p8 firebase-service-account.json /etc/antimatter-push-proxy/certs/
sudoedit /etc/antimatter-push-proxy/antimatter-push-proxy.json
sudo systemctl start antimatter-push-proxy
journalctl -u antimatter-push-proxy -f

در فایل تنظیمات، مسیرها نسبت به /etc/antimatter-push-proxy هستند: برای مثال "AppleAuthKeyFile": "./certs/AuthKey_ABCDE12345.p8" و "ServiceFileLocation": "./certs/firebase-service-account.json". سپس Push Notification Server را در Antimatter روی http://<proxy host>:8066 تنظیم کنید. پس از ارتقا، آن را از نو راه‌اندازی کنید: sudo systemctl restart antimatter-push-proxy.

پروکسی اعلان روی پورت 8066 روی همه آدرس‌ها گوش می‌دهد و بررسی نمی‌کند که چه کسی به آن دسترسی دارد. پورت را در یک شبکه خصوصی نگه دارید، یا پشت یک پروکسی معکوس که دسترسی را محدود می‌کند قرار دهید.

دستورهای دیگر سرور

علاوه بر اجرای سرور (antimatter یا antimatter server)، باینری چند دستور نگهداری دارد. این دستورها همان پیکربندی سرور را می‌خوانند.

دستورعملکرد
antimatter versionنسخه، شماره بیلد، تاریخ بیلد و هش بیلد را چاپ می‌کند.
antimatter db pingبررسی می‌کند که پایگاه داده در دسترس است.
antimatter db initپیکربندی را در پایگاه داده ایجاد می‌کند (با تنظیم AM_CONFIG روی یک URL postgres://).
antimatter db migrateمهاجرت‌های پایگاه داده را اعمال می‌کند بدون اینکه سرور را راه‌اندازی کند.
antimatter db versionآخرین مهاجرت اعمال‌شده به پایگاه داده را چاپ می‌کند.
antimatter import bulk, antimatter export bulkداده را در قالب گروهی وارد یا خروجی می‌کند (ببینید پشتیبان‌گیری و ارتقا).
