Telepítés Docker Compose használatával

Ez a javasolt módszer. Egy compose-fájl futtatja az Antimattert, a PostgreSQLt, a fájl tárhelyet és a GIF-szolgáltatást. Ehhez Linux szerverre van szükség Docker Engine és Compose plugin (docker compose) telepítéssel, 2 CPU maggal és 4 GB memória vagy többel.

1. Töltse le a compose-fájlt

mkdir antimatter && cd antimatter
curl -fsSLO https://antimatter.chat/compose.yaml

2. Hozza létre a .env fájlt

A compose-fájl a beállításait egy ugyanabban a könyvtárban lévő .env fájlból olvassa be. Hozza létre véletlenszerű titkokkal:

cat > .env <<EOF
SITE_URL=http://localhost:8065
POSTGRES_PASSWORD=$(openssl rand -hex 24)
S3_SECRET_KEY=$(openssl rand -hex 24)
GIFS_API_KEY=$(openssl rand -hex 24)
EOF
chmod 600 .env

Állítsa be a SITE_URL értéket arra a címre, amelyet a felhasználók a böngészőjükbe írnak, például http://192.168.1.20:8065 helyi hálózaton, vagy https://chat.example.com domain névvel. Őrizze meg a .env fájlt: az adatbázis és a tárhely az első indítástól kezdve ezeket a jelszavakat használja, és a mentés visszaállításához is ugyanerre a fájlra van szükség.

3. Indítsa el

docker compose up -d
docker compose ps

Az első indítás egy-két percet vesz igénybe: a PostgreSQL létrehozza az adatbázist, egy egyszeri bucket szolgáltatás létrehozza a tárhely-kosarat, egy egyszeri gifs-stickers szolgáltatás importálja a kezdő matricacsomagot, az Antimatter pedig létrehozza a tábláit. Kövesse figyelemmel a docker compose logs -f antimatter paranccsal.

Ha domain nevet és HTTPS-t szeretne használni már az elején, lásd: Domain és HTTPS: a compose-fájllal ez mindössze két további sor a .env fájlban, valamint a https profil.

A PostgreSQL, a tárhely és a GIF-szolgáltatás egy belső hálózaton (private) fut, amelyhez nincs internetes hozzáférés, és ahhoz csak az Antimatter csatlakozik. Egyik sem publikál portot.

Az Antimatter-konténer nem tárol semmit a lemezen: a beállításai az adatbázisban vannak (erre mutat az AM_CONFIG), a fájlok és az alkalmazások pedig a tárhelyszolgáltatásban. A konténert bármikor törölheti és újrakészítheti. Minden, amit mentenie kell, a postgres, files és gifs kötetekben, valamint a .env fájlban található.

Válasszon egy képet

Két Antimatter-kép érhető el, mindkettő linux/amd64 és linux/arm64 architektúrára, és mindkettő minden repozitórium main ága alapján készül:

KépBeépített alkalmazásokCímkék
ghcr.io/antimatterchat/antimatterÜgynökök, Hívások, GitHub, GitLab, Jira, Kanban, Metriki és Playbookok.latest, X.Y.Z a kiadásokhoz, sha-<commit>
ghcr.io/antimatterchat/antimatter-nextUgyanezek, plusz Hangcsatornák, Szavazások, E-mail, Naptár, Megjegyzések, Fehértábla, GIF-ek, Teendők és Memek. Minden éjszaka újraépül.latest, nightly, nightly-<YYYYMMDD>, sha-<commit>

A weboldal compose-fájla az antimatter-next képet használja, mert a GIF-szolgáltatás és a weboldalon leírt alkalmazások többsége csak ebben a képből érhető el. A kép cseréjéhez állítsa be az ANTIMATTER_IMAGE változót a .env fájlban, majd futtassa a docker compose up -d parancsot.

A latest címke alatt a kép tartalma változhat. Éles környezetben rögzítsen egy címkét, például nightly-20261015 vagy sha-<commit>, és csak tudatosan módosítsa frissítéskor. A szerver induláskor frissíti az adatbázist, ezért nem térhet vissza régebbi képre, vagy nem válthat antimatter-next képről antimatter képre, hacsak nem állítja vissza egy korábban készített mentést. Lásd: Mentések és frissítések.

A kép belső felépítése

  • A szerver a /antimatter könyvtárban található, a antimatter és amctl binárisok pedig a /antimatter/bin könyvtárban (a PATH-on).
  • A nem jogosultsággal rendelkező antimatter felhasználóként (uid 2000) fut egy minimális, distroless alaprendszeren, shell nélkül.
  • Portok: 8065 (web és API), 8067 (metriki), 8074 (klaszter), 8443 UDP és TCP (hívások).
  • A helyi mód (ServiceSettings.EnableLocalMode) be van kapcsolva, ezért a amctl --local a konténeren belül is működik. Az egészségellenőrzés a amctl system status --local parancsot futtatja.
  • A beépített alkalmazások a /antimatter/prepackaged_plugins könyvtárban találhatók, és az Antimatter alkalmazás-aláíró kulcsával vannak aláírva.
  • A csomag tartalmaz szövegkivonási eszközöket (pdftotext, wvText, unrtf, tidy), így a feltöltött dokumentumok tartalma is kereshető.

Egyéb compose-fájlok

Az antimatter-docker tárhelyen egy éles környezetbe való telepítési beállítás található a deploy/compose/ könyvtárban: nginx saját tanúsítvánnyal vagy Let's Encrypt (certbot) használatával, PostgreSQL, a opcionális GIF-szolgáltatás (gifs profil) és nevezett kötetek a szerver konfigurációjához, adataihoz és naplófájljaihoz, mind a README-ben dokumentálva. Alapértelmezetten a stabil képet használja, és a fájlokat helyi köteten tárolja, nem S3-tárhelyen. Használd, ha a Caddy helyett a nginx-t preferálod, vagy már rendelkezned tanúsítványokkal.

Az első rendszergazda létrehozása

Nyisd meg a SITE_URL címet a böngésződben, és hozz létre egy fiókot. Az első, az új szerveren létrehozott fiók a rendszer rendszergazdája lesz, majd a beállítás útmutatást ad az első közösség (az Antimatterben a csapat vagy munkaterület megnevezése) létrehozásához.

Ezt a szerver első elindítása után azonnal végezd el: addig ugyanis bárki, aki előbb eléri a szerveret, annak rendszergazdája lesz. Ha a fiókot a parancssorból szeretnéd létrehozni, mielőtt a szerver kívülről elérhetővé válik:

docker compose exec antimatter amctl --local user create --system-admin --email-verified \
    --email admin@example.com --username admin --password 'a-long-password'
docker compose exec antimatter amctl --local team create --name main --display-name "Main"
docker compose exec antimatter amctl --local team users add main admin

Ezután jelentkezz be a SITE_URL címen. Írd a parancs elejére egy szóközt, hogy a jelszó ne kerüljön a parancssor naplódba (ha HISTCONTROL=ignorespace van beállítva), vagy a bejelentkezés után állítsd át a jelszót.

Következő lépések a bejelentkezés után:

  1. Döntsd el, ki hozhat létre fiókokat: Bejelentkezés és fiókok.
  2. Állítsd be az e-mailt, hogy a meghívók és a jelszó-visszaállítás működjenek: E-mail- és push-értesítések.
  3. Nyisd meg a hívásokhoz szükséges portot a tűzfaladban: Hívások és hang.
  4. Nézd meg, melyik alkalmazások vannak bekapcsolva: Beépített alkalmazások.

Telepítés kiadási archívumból

Docker nélkül a szerver egy antimatter-<os>-<arch>.tar.gz nevű archívumból fut (például antimatter-linux-amd64.tar.gz). Ez egyetlen antimatter/ könyvtárat tartalmaz, benne a bin/antimatter, a bin/amctl, a config/config.json, a webes alkalmazások (client/ és client-fusion/), valamint a e-mail sablonok és a fordítások.

1. PostgreSQL előkészítése

Az Antimatter kizárólag a PostgreSQL 15-ös vagy újabb verzióját támogatja (a régebbi verziók elindulnak, de hibát írnak a naplóba). Hozz létre egy felhasználót és egy adatbázist:

sudo -u postgres psql <<'EOF'
CREATE USER antimatter WITH PASSWORD 'a-long-password';
CREATE DATABASE antimatter OWNER antimatter;
EOF

2. Kibontás és konfigurálás

sudo tar -xzf antimatter-linux-amd64.tar.gz -C /opt
sudo useradd --system --user-group antimatter
sudo mkdir -p /opt/antimatter/data
sudo chown -R antimatter:antimatter /opt/antimatter

Állítsd be, hogy a szerver melyik adatbázist használja, vagy a /opt/antimatter/config/config.json (SqlSettings.DataSource) segítségével, vagy környezeti változókkal, és add meg a webhely URL-jét:

AM_SQLSETTINGS_DRIVERNAME=postgres
AM_SQLSETTINGS_DATASOURCE=postgres://antimatter:a-long-password@localhost:5432/antimatter?sslmode=disable&connect_timeout=10
AM_SERVICESETTINGS_SITEURL=https://chat.example.com

Az archívum config.json fájlja egy teljes alapértelmezett konfiguráció: a Rendszerkonzolban végzett módosítások ide mentődnek vissza. Ha az adatbázisban szeretnéd tárolni a konfigurációt, lásd: Konfiguráció.

3. Futtatás szolgáltatásként

Egy systemd egység, a /etc/systemd/system/antimatter.service fájlban:

[Unit]
Description=Antimatter
After=network.target postgresql.service

[Service]
Type=notify
User=antimatter
Group=antimatter
WorkingDirectory=/opt/antimatter
ExecStart=/opt/antimatter/bin/antimatter
EnvironmentFile=-/etc/antimatter.env
TimeoutStartSec=3600
Restart=always
RestartSec=10
LimitNOFILE=49152

[Install]
WantedBy=multi-user.target

A AM_ változókat tedd a /etc/antimatter.env fájlba (csak root olvashassa), majd:

sudo systemctl daemon-reload
sudo systemctl enable --now antimatter
journalctl -u antimatter -f

A szerver a 8065-ös porton figyel. Nyisd meg a http://<server>:8065 címet, vagy a saját domainedet, miután beállítottál egy reverse proxyt (lásd: Domain és HTTPS), és hozz létre egy első fiókot: ez lesz a rendszergazda.

A bin/amctl a futó szervert kezeli parancssorból. A szerveren magán, helyi módban működik bejelentkezés nélkül: állítsd be, hogy AM_SERVICESETTINGS_ENABLELOCALMODE=true, majd futtasd: sudo -u antimatter /opt/antimatter/bin/amctl --local system status.
