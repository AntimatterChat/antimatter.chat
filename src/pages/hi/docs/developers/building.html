आपको क्या चाहिए

  • जाना, server/go.mod में वर्जन (लेखन के समय 1.26.7)।
  • Node.js और npm, .nvmrc और webapp/package.json में उल्लिखित संस्करण (Node 24.11.1 with npm 11.6.2)। mise के साथ, रिपॉज़िटरी का mise.toml सही Node इंस्टॉल करता है।
  • Docker with Compose: डेवलपमेंट सेटअप PostgreSQL और कुछ अन्य सेवाओं को कंटेनरों में चलाता है।
  • make, git, और एक Linux या macOS मशीन।
  • मेमोरी: वेब इंटरफेसों को बिल्ड करना भारी हिस्सा है। 16 GB RAM की योजना बनाएं; देखें बिल्ड्स और मेमोरी।
git clone https://github.com/AntimatterChat/antimatter.git
cd antimatter

रिपॉज़िटरी सर्वर को server/ में, वेब इंटरफेसों को webapp/ में (Fusion in webapp/fusion, classic in webapp/channels, shared packages in webapp/platform), और एंड-टू-एंड टेस्ट्स को e2e-tests/ में रखती है।

एक डेवलपमेंट सर्वर चलाएं

cd server
make run

make run डेवलपमेंट कंटेनर (PostgreSQL, Redis, a mail catcher and monitoring tools) शुरू करता है, वेब ऐप बिल्ड्स को जगह पर जोड़ता है, सर्वर को बैकग्राउंड में go run के साथ शुरू करता है, और वेब ऐप के वॉचर को शुरू करता है, जो आपके संपादन के साथ क्लासिक इंटरफेस को पुनर्बिल्ड करता है। http://localhost:8065 खोलें और एक खाता बनाएं: पहला खाता सिस्टम एडमिन बन जाता है।

कमांड (in server/)यह क्या करता है
make run-server, make run-clientकेवल सर्वर, या केवल वेब ऐप वॉचर शुरू करें।
make restart-serverGo कोड बदलने के बाद सर्वर को पुनः शुरू करें।
make stopसर्वर, वॉचर और कंटेनरों को रोकें।
make debug-serverDelve डीबगर के तहत सर्वर चलाएं।
make run-cli ARGS="-version"एक सर्वर कमांड चलाएं।
make config-resetconfig/config.json को डिफ़ॉल्ट्स पर रीसेट करें।
make clean, make nukeबिल्ड फ़ाइलें हटाएं; nuke डेवलपमेंट डेटा को भी हटा देता है।

डेवलपमेंट डेटाबेस postgres://mmuser:mostest_password@localhost/mattermost_test है, जो सर्वर का डिफ़ॉल्ट डेटा सोर्स है। ENABLED_DOCKER_SERVICES के साथ चुनें कि कौन से कंटेनर शुरू हों, server/config.override.mk फ़ाइल में या आपके एनवायरनमेंट में (देखें server/config.mk)।

वेब इंटरफेस

webapp/ में:

npm install      # also builds the shared packages
npm run build    # the classic interface, then Fusion

बिल्ड्स webapp/channels/dist (क्लासिक) और webapp/fusion/dist (Fusion) में बनते हैं। server/ में make client इन्हें server/client और server/client-fusion के रूप में लिंक करता है, जहाँ सर्वर इन्हें सर्व करता है: क्लासिक /static/ के तहत, और Fusion /static/fusion/ के तहत।

  • npm run run (या webapp/ में make run) क्लासिक इंटरफेस को वॉच करता है और पुनर्निर्माण (rebuild) करता है। Fusion को भी पुनर्निर्माण करने के लिए WATCH_FUSION=true जोड़ें।
  • npm run dev-server (make dev) के बजाय webpack के डेवलपमेंट सर्वर को चलाता है: क्लासिक पोर्ट 9005 पर, और Fusion पोर्ट 9006 पर।
  • ब्राउज़र में एक इंटरफेस या दूसरा देखने के लिए, किसी भी पेज के पता (address) में ?webui=fusion या ?webui=classic जोड़ें।

रिलीज़ आर्काइव

cd webapp && npm run build && cd ..
cd server
make build-linux       # the antimatter and amctl binaries
make package-linux     # dist/antimatter-linux-amd64.tar.gz and -arm64

make build वेब इंटरफेस और Linux बाइनरी दोनों एक साथ बनाता है। आर्काइव में bin/antimatter, bin/amctl, डिफ़ॉल्ट config/config.json, दोनों वेब इंटरफेस, टेम्पलेट, फ़ॉन्ट और अनुवाद शामिल हैं। अन्य प्लेटफ़ॉर्म: make package-osx, make package-windows, make package-freebsd। आर्काइव में बंडल्ड ऐप्स शामिल नहीं हैं; Docker इमेज में शामिल हैं।

Docker इमेज

antimatter-docker रिपॉज़िटरी प्रकाशित इमेजों को बनाती है, सर्वर और उसके ऐप्स सहित, पूरी तरह Docker के अंदर:

git clone https://github.com/AntimatterChat/antimatter-docker.git
cd antimatter-docker
scripts/build-all.sh                     # from the main branches on GitHub
SOURCES=local scripts/build-all.sh       # from your checkouts next to this folder
VARIANT=next scripts/build-all.sh        # the "next" image, with every Antimatter app

इसके लिए Docker (buildx सहित), Python 3, git और gpg, लगभग 16 GB RAM और 30 GB डिस्क की ज़रूरत है। परिणाम को ghcr.io/antimatterchat/antimatter:dev के रूप में लोड किया जाता है; इसे ANTIMATTER_IMAGE=ghcr.io/antimatterchat/antimatter:dev docker compose -f compose.local.yml up -d के साथ आज़माएँ। plugins.json में बनाए गए ऐप्स और उनकी संस्करणों की सूची है, और रिपॉज़िटरी का README विभिन्न भेदों (variants) की व्याख्या करता है।

build-all.sh Antimatter signing key से bundled apps को sign करता है, और image build unsigned apps को अस्वीकार कर देता है। यदि आपके पास वह private key नहीं है, जो केवल maintainers के पास है, तो केवल प्रारंभिक चरणों को अलग-अलग चलाएँ: scripts/fetch-sources.sh, scripts/build-plugins.sh (out/plugins/ में app bundles) और scripts/build-server.sh (out/server/ में server archives)।

Builds और memory

वेब इंटरफेस बड़े webpack builds हैं, और memory की कमी सबसे आम build failure है।

  • npm run build classic interface और Fusion को एक के बाद एक build करता है, साथ में नहीं, ताकि peak memory कम रहे। इन्हें स्वयं parallel में न चलाएँ।
  • Minifier प्रत्येक processor के लिए एक worker शुरू करता है। यदि मशीन में बहुत सारे cores हैं लेकिन memory कम है, तो build के लिए उपलब्ध processors की संख्या सीमित करें: taskset -c 0-5 npm run build।
  • यदि Node के heap की memory खत्म हो जाती है, तो उसकी सीमा बढ़ाएँ: NODE_OPTIONS=--max-old-space-size=6144। Docker build इसी मान का उपयोग करता है (build.env में BUILD_NODE_OPTIONS)।
  • छोटी मशीन पर server का पूरा test suite, web build और Docker build एक साथ न चलाएँ।

Apps

प्रत्येक app (plugin) का अपना अलग repository और Makefile है; make dist इसका bundle build करता है। Build, install और debug देखें।

Desktop app

desktop app एक Electron app है। Node.js 24 या नवीनतम संस्करण के साथ:

npm install --allow-git=all
npm run build          # development build, into dist/
npm start              # run it
npm run package:linux  # packages into release/ (also package:windows, package:mac)

Build-time settings, जैसे कि preconfigure करने के लिए servers, src/common/config/buildConfig.ts में हैं।

Mobile app

mobile app एक React Native app है; इसके README में commands (npm run ios, npm run android) सूचीबद्ध हैं। अपनी खुद की copy build करने के लिए आपको अपनी signing keys, Android notifications के लिए एक Firebase project, iOS के लिए एक APNs key, और उन credentials को रखने वाला push proxy भी चाहिए।
