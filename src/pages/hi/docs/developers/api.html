मूल बातें

  • बेस URL: https://chat.example.com/api/v4। नीचे दिए गए सभी एंडपॉइंट्स इसके सापेक्ष हैं।
  • प्रारूप: इन और आउट दोनों में JSON, सिवाय फ़ाइल अपलोड (मल्टीपार्ट) के। Content-Type: application/json भेजें।
  • ID: हर ऑब्जेक्ट की एक 26-अक्षरों की id होती है। समय Unix epoch से मिलीसेकंड में होता है (create_at, update_at, delete_at; 0 का अर्थ है "हटाया नहीं गया")।
  • समुदाय टीमें हैं: API इन्हें teams कहता है, जिनके साथ team_id होता है।
  • आप स्वयं: जहाँ भी पाथ में user_id लिया जाता है, me का अर्थ है साइन-इन किया हुआ यूज़र, जैसे GET /users/me में।

एंडपॉइंट्स की पूरी सूची सर्वर के कोड में है: रूट्स server/channels/api4/*.go में घोषित हैं और टाइप्स server/public/model में। रिपॉज़िटरी के api/v4/source फ़ोल्डर में OpenAPI विवरण Mattermost से वारिस हुए एंडपॉइंट्स को कवर करता है, Antimatter के जोड़ों को नहीं।

प्रमाणीकरण

हर अनुरोध, सिवाय साइन-इन करने और कुछ सार्वजनिक एंडपॉइंट्स के, Authorization हेडर में टोकन की मांग करता है:

curl -H "Authorization: Bearer $TOKEN" https://chat.example.com/api/v4/users/me

वहाँ तीन प्रकार के टोकन स्वीकार किए जाते हैं: पर्सनल एक्सेस टोकन, सेशन टोकन और OAuth एक्सेस टोकन। Authorization: Token … भी स्वीकार किया जाता है। क्वेरी स्ट्रिंग (?access_token=) में टोकन केवल OAuth एक्सेस टोकन के लिए स्वीकार किए जाते हैं।

पर्सनल एक्सेस टोकन (स्क्रिप्ट्स के लिए अनुशंसित)

पर्सनल एक्सेस टोकन आपके रूप में कार्य करता है, जब तक आप उसे एक समाप्ति तिथि न दें तब तक समाप्त नहीं होता, और इसे किसी भी समय रद्द किया जा सकता है। पर्सनल एक्सेस टोकन डिफ़ॉल्ट रूप से बंद होते हैं:

  1. एक सिस्टम एडमिन सिस्टम कंसोल › इंटीग्रेशन › इंटीग्रेशन प्रबंधन में व्यक्तिगत एक्सेस टोकन सक्षम करें चालू करता है (ServiceSettings.EnableUserAccessTokens, AM_SERVICESETTINGS_ENABLEUSERACCESSTOKENS)।
  2. हर उस व्यक्ति के लिए जो टोकन बना सकता है, एक सिस्टम एडमिन सिस्टम कंसोल › यूज़र प्रबंधन › उपयोगकर्ता खोलता है, उस व्यक्ति के मेन्यू में भूमिकाओं का प्रबंधन करें चुनता है और इस अकाउंट को व्यक्तिगत एक्सेस टोकन जनरेट करने की अनुमति दें पर टिक लगाता है। सिस्टम एडमिन हमेशा उन्हें बना सकते हैं।
  3. व्यक्ति ऊपर दाईं ओर अपने अवतार पर क्लिक करता है, फिर प्रोफ़ाइल और सेटिंग्स › सुरक्षा खोलता है। पर्सनल एक्सेस टोकन के नीचे, वह टोकन किसके लिए है, इसका विवरण देता है और टोकन बनाएं चुनता है। टोकन केवल एक बार दिखाया जाता है: इसे कॉपी करें।

API के साथ: POST /users/{user_id}/tokens के साथ {"description": "backup script", "expires_at": 0} (expires_at मिलीसेकंड में; 0 का अर्थ है कोई नहीं)। प्रतिक्रिया के token फ़ील्ड में रहस्य है; इसका id वह है जिसे आप रिवोक करने के लिए उपयोग करते हैं (POST /users/tokens/revoke के साथ {"token_id": "…"})। कमांड लाइन से: amctl token generate <user> <description>।

एक सिस्टम एडमिन उसी सिस्टम कंसोल पेज पर अधिकतम व्यक्तिगत एक्सेस टोकन वैधता (दिन) से टोकन की वैधता की सीमा लगा सकता है।

सेशन टोकन

पासवर्ड के साथ साइन इन करने पर Token प्रतिक्रिया हेडर में एक सेशन टोकन लौटता है, जो ऐप्स द्वारा उपयोग किए जाने वाले सेशन के उसी प्रकार का होता है:

curl -i -X POST https://chat.example.com/api/v4/users/login \
  -H 'Content-Type: application/json' \
  -d '{"login_id": "maya", "password": "…"}'

मल्टी-फैक्टर ऑथेंटिकेशन वाले अकाउंट के लिए "token": "123456" जोड़ें। सेशन सर्वर के सेशन सेटिंग्स के अनुसार समाप्त हो जाते हैं, और लॉगिन एंडपॉइंट रेट लिमिटेड है (5 अनुरोध प्रति सेकंड)। POST /users/logout सेशन समाप्त करता है।

ब्राउज़र एक कुकी के साथ प्रमाणीकरण करते हैं। कुकी द्वारा प्रमाणित अनुरोध को GET के अलावा किसी भी चीज़ के लिए X-CSRF-Token हेडर भी भेजना होगा; Authorization हेडर में टोकन के लिए कोई CSRF हेडर आवश्यक नहीं है।

OAuth 2.0 ऐप्स

अपने एप्लिकेशन में लोगों को उनके Antimatter अकाउंट के साथ साइन इन करने देने के लिए, एक OAuth 2.0 ऐप पंजीकृत करें। Antimatter तब OAuth प्रोवाइडर होता है:

  1. OAuth 2.0 सर्विस प्रोवाइडर सक्षम करें चालू होना चाहिए (सिस्टम कंसोल › इंटीग्रेशन › इंटीग्रेशन प्रबंधन, ServiceSettings.EnableOAuthServiceProvider, डिफ़ॉल्ट रूप से चालू)।
  2. OAuth ऐप्स को मैनेज करने का अधिकार रखने वाला कोई व्यक्ति (डिफ़ॉल्ट रूप से सिस्टम एडमिन) अपने अवतार पर क्लिक करता है, फिर इंटीग्रेशन › OAuth 2.0 ऐप्स खोलता है, और ऐप को उसके कॉलबैक URL के साथ जोड़ता है। उन्हें एक क्लाइंट ID और एक क्लाइंट सीक्रेट मिलता है।
  3. आपका एप्लिकेशन लोगों को https://chat.example.com/oauth/authorize पर भेजता है, जिसमें response_type=code, client_id, redirect_uri और state शामिल होते हैं। code_challenge_method=S256 के साथ PKCE का समर्थन उपलब्ध है।
  4. यह कोड को POST https://chat.example.com/oauth/access_token पर बदलता है (पहले grant_type=authorization_code, फिर नवीनीकरण के लिए refresh_token), और API को Authorization: Bearer <access token> के साथ कॉल करता है।

लोग प्रोफ़ाइल और सेटिंग्स › सुरक्षा › आपके द्वारा अधिकृत ऐप में वे ऐप देखते हैं जिनकी उन्होंने अनुमति दी है।

संदेश पोस्ट करें

curl -X POST https://chat.example.com/api/v4/posts \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"channel_id": "'$CHANNEL_ID'", "message": "Backup finished: **42 GB** in 3 min"}'

संदेश Markdown होते हैं। थ्रेड में उत्तर देने के लिए "root_id" (थ्रेड का पहला पोस्ट) जोड़ें, फ़ाइलों के लिए "file_ids" और अटैचमेंट और अन्य अतिरिक्त सामग्री के लिए "props" (देखें अटैचमेंट)।

चैनल का ID खोजें

curl -H "Authorization: Bearer $TOKEN" \
  https://chat.example.com/api/v4/teams/name/lumen-labs/channels/name/ops-alerts

नाम चैनल के लिंक में दिए गए हैं: /lumen-labs/channels/ops-alerts।

पेजिनेशन

सूची एंडपॉइंट page (0 से) और per_page (डिफ़ॉल्ट रूप से 60, अधिकतम 200) लेते हैं। अगला पेज मांगते रहें जब तक कि per_page से छोटा पेज न लौटे।

एक चैनल के संदेश (GET /channels/{channel_id}/posts) भी since (एक समय: तब से सब कुछ जो बदला) या before और after (एक पोस्ट ID) लेते हैं। वे एक पोस्ट सूची के रूप में लौटते हैं: {"order": [IDs, newest first], "posts": {ID: post}, "next_post_id", "prev_post_id"}।

त्रुटियां

त्रुटियां सामान्य HTTP स्थिति कोड (400 गलत इनपुट, 401 साइन इन नहीं किया गया, 403 अनुमत नहीं, 404 नहीं मिला, 501 सुविधा बंद) और एक JSON बॉडी का उपयोग करती हैं:

{
  "id": "api.context.permissions.app_error",
  "message": "You do not have the appropriate permissions.",
  "detailed_error": "",
  "request_id": "jz8zm5nunpbt8f3gpqsz5dq6so",
  "status_code": 403
}

अपने कोड में id का उपयोग करें: message उपयोगकर्ता की भाषा में अनुवादित किया जाता है। detailed_error तब तक खाली रहता है जब तक सर्वर डेवलपर मोड (ServiceSettings.EnableDeveloper) में चालू न हो। request_id को सर्वर के एडमिन को उद्धृत करें: यह लॉग्स में उपलब्ध है।

रेट लिमिट्स

रेट लिमिटिंग डिफ़ॉल्ट रूप से बंद है। जब एक सिस्टम एडमिन इसे चालू करता है (सिस्टम कंसोल › पर्यावरण › रेट लिमिटिंग), तो डिफ़ॉल्ट रूप से हर क्लाइंट को 100 की बर्स्ट के साथ प्रति सेकंड 10 अनुरोध मिलते हैं, जिन्हें IP पता या उपयोगकर्ता के आधार पर गिना जाता है। प्रतिसाव X-RateLimit-Limit, X-RateLimit-Remaining और X-RateLimit-Reset ले जाते हैं; सीमा से ऊपर, सर्वर Retry-After हेडर (सेकंड में) के साथ 429 का जवाब देता है। कुछ एंडपॉइंट, जैसे साइन इन, किसी भी सेटिंग के बावजूद अपनी अलग सीमा रखते हैं।

429 पर प्रतीक्षा करें और पुनः प्रयास करने वाले स्क्रिप्ट लिखें, और पॉलिंग से बचें: इसके बजाय WebSocket का पालन करें।

WebSocket इवेंट स्ट्रीम

wss://chat.example.com/api/v4/websocket से कनेक्ट करें। कनेक्शन अनुरोध पर Authorization: Bearer हेडर के साथ प्रमाणीकरण करें, या इसे पहला संदेश भेजकर करें:

{"seq": 1, "action": "authentication_challenge", "data": {"token": "…"}}

सर्वर एक hello इवेंट भेजता है, फिर आपके देखने की अनुमति वाले हर चीज़ के लिए एक इवेंट भेजता है:

{
  "event": "posted",
  "data": {"channel_id": "…", "channel_type": "O", "post": "{\"id\":\"…\",\"message\":\"Hello\",…}"},
  "broadcast": {"channel_id": "…", "team_id": "", "user_id": "", "omit_users": null},
  "seq": 4
}

ध्यान दें कि data.post एक JSON स्ट्रिंग के रूप में पोस्ट है। सामान्य इवेंट्स: posted, post_edited, post_deleted, reaction_added, reaction_removed, typing, status_change, user_added, direct_added। ऐप्स अपने स्वयं के इवेंट्स भेजते हैं, जिन्हें custom_<app id>_<event> नाम दिया जाता है।

आप एक्शन भी भेज सकते हैं, प्रत्येक में बढ़ता हुआ seq के साथ: user_typing के साथ {"channel_id", "parent_id"}, या get_statuses। जब कनेक्शन टूट जाए तो दोबारा कनेक्ट करें, और since के साथ जो आपने मिस किया है उसे प्राप्त करें (देखें Pagination)।

Antimatter इन इवेंट्स को जोडता है: community_attributes_updated, member_timeouts_updated, post_put_on_top, post_removed_from_top, server_categories_updated, channel_overrides_updated और category_overrides_updated.

क्लाइंट लाइब्रेरी

  • जाना: server/public/model में model.Client4 (import github.com/mattermost/mattermost/server/public/model)। model.NewAPIv4Client(url), फिर client.SetToken(token); model.NewWebSocketClient4(wsURL, token) इवेंट्स को फॉलो करता है। Antimatter की कॉपी अपने एंडपॉइंट्स के लिए विधियाँ जोड़ती है, जैसे UpdateMessageRequest, PutPostOnTop और ExportChannel।
  • TypeScript: webapp/platform/client में @mattermost/client की Client4 क्लास, जिसके टाइप्स webapp/platform/types में हैं। Antimatter के रिपॉज़िटरी में मौजूद कॉपी Antimatter के एंडपॉइंट्स को शामिल करती है; Mattermost द्वारा npm पर प्रकाशित पैकेज में वे नहीं हैं।
package main

import (
	"context"
	"log"

	"github.com/mattermost/mattermost/server/public/model"
)

func main() {
	client := model.NewAPIv4Client("https://chat.example.com")
	client.SetToken("…")
	post, _, err := client.CreatePost(context.Background(), &model.Post{
		ChannelId: "…",
		Message:   "Hello from Go",
	})
	if err != nil {
		log.Fatal(err)
	}
	log.Println("posted", post.Id)
}

नए फ़ील्ड

  • समुदाय (Team, और PUT /teams/{team_id}/patch): all_channels_membership (हर सदस्य हर उस चैनल में शामिल है जिसे वह देख सकता है), default_channel_id (नए सदस्यों का प्रवेश बिंदु; खाली होने पर Town Square), hide_role_colors, require_team_badges, onboarding और autolinks (दोनों JSON स्ट्रिंग्स हैं)।
  • इनलाइन उत्तर: "props": {"reply_to": "<post id>"} वाला पोस्ट उसी चैनल के उस सन्देश का उद्धरण करता है। "reply_to_mention": false जोड़ने से उसके लेखक को सूचित नहीं किया जाता। सर्वर metadata.reply_to में उद्धृत सन्देश का संक्षिप्त विवरण भरता है।
  • स्पोइलर: "props": {"spoiler": true} पाठ और फ़ाइलों को छिपाता है, जब तक पाठक उन्हें देखने का निर्णय न ले।
  • नज़रअंदाज़ करना और ब्लॉक करना प्राथमिकताएँ हैं: श्रेणी user_block, दूसरे व्यक्ति की ID के नाम पर, जिसकी मूल्य ignore या block है। डायरेक्ट मैसेज अनुरोध के रूप में रुकता है या नहीं, यह आपके चैनल सदस्य के notify_props.dm_request में निर्धारित होता है (pending, accepted या dismissed)।
