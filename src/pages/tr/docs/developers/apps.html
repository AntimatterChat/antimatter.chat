Bir uygulamanın çalışma şekli

  • Sunucu kısmı bir Go programıdır. Sunucu, bunu ayrı bir süreç olarak başlatır ve RPC üzerinden iletişim kurar: uygulamanın kancalarını (bir iletinin gönderilmek üzere olması, bir komutun çalıştırılması…) çağırır ve uygulama, sunucunun eklenti API'sini (bir iletinin oluşturulması, bir kullanıcının okunması, veri depolanması…) çağırır. Ayrıca /plugins/<app id>/ altında HTTP yolları da sunabilir.
  • Web uygulaması kısmı, web uygulamasıyla birlikte tarayıcıya yüklenen bir JavaScript paketidir. registrant (kayıt defteri) ile React bileşenleri ve geri çağırma işlevleri (callback) kaydeder: bir menüdeki düğme, bir panel, bir ileti türünü çizme yöntemi.
  • Herhangi bir kısım isteğe bağlıdır. Bir uygulama, .tar.gz paketi olarak kurulur ve sistem yöneticileri onu etkinleştirir, devre dışı bırakır ve yapılandırır.
Sunucu kısmı, sunucunun verilerine tam erişimle çalışır. Bir uygulamayı, sunucuya dağıttığınız kod gibi ele alın.

Antimatter, Mattermost için yazılmış uygulamaları ve tersi, bir uygulama yalnızca her ikisinin de sahip olduğu kancaları kullandığı sürece çalıştırır. Yalnızca Antimatter'in sahip olduğu kancalar bölümüne bakın.

Paket düzeni

Ayrı bir başlangıç şablonu yoktur: antimatter-plugin-polls veya antimatter-plugin-todo gibi küçük bir paketlenmiş uygulamadan başlayın ve kimliğini (ID) ve kodunu değiştirin. Polls şu şekilde düzenlenmiştir:

antimatter-plugin-polls/
├── plugin.json            the manifest
├── Makefile               build, test, bundle, deploy
├── build/                 the manifest and pluginctl helper tools (Go), setup.mk
├── assets/icon.svg        files shipped with the bundle
├── go.mod
├── server/
│   ├── main.go            plugin.ClientMain(&Plugin{})
│   ├── plugin.go          the Plugin type, OnActivate, ServeHTTP
│   ├── manifest.go        generated from plugin.json
│   ├── api.go, command.go, hooks.go, store.go …
│   └── dist/              compiled binaries, one per platform
└── webapp/
    ├── package.json, webpack.config.js, tsconfig.json
    ├── i18n/              en.json and one file per language
    ├── src/index.tsx      registers the app with the web app
    ├── src/manifest.ts    generated from plugin.json
    ├── src/translations.ts
    └── dist/main.js       the bundle

İsteğe bağlı: /plugins/<app id>/public/ adresinde olduğu gibi sunulan bir public/ klasörü.

{
  "id": "com.example.weather",
  "name": "Weather",
  "description": "Forecasts in the chat.",
  "homepage_url": "https://github.com/example/weather",
  "support_url": "https://github.com/example/weather/issues",
  "icon_path": "assets/icon.svg",
  "version": "1.0.0",
  "min_server_version": "12.0.0",
  "server": {
    "executables": {
      "linux-amd64": "server/dist/plugin-linux-amd64",
      "linux-arm64": "server/dist/plugin-linux-arm64",
      "darwin-amd64": "server/dist/plugin-darwin-amd64",
      "darwin-arm64": "server/dist/plugin-darwin-arm64",
      "windows-amd64": "server/dist/plugin-windows-amd64.exe"
    }
  },
  "webapp": {"bundle_path": "webapp/dist/main.js"},
  "settings_schema": {"settings": []}

  • id: benzersiz ve kalıcı; genellikle tersine çevrilmiş bir alan adı kullanılır. Yolları, depolanan ayarları ve WebSocket olaylarını adlandırır.
  • version: anlamsal sürüm (semantic version). Paketlenmiş uygulamalar bunu plugin.json dosyasından hariç tutar; sürüm bilgilerini en son v* git etiketinden alır.
  • min_server_version: Antimatter 12.0.0 sürümünü bildirir.
  • settings_schema: Sistem Konsolu'ndaki uygulamanın ayarlar sayfası (bkz. Ayarlar).

make apply, manifest dosyasını server/manifest.go ve webapp/src/manifest.ts dosyalarına kopyalar; make manifest-check ise doğrular.

Sunucu bölümü

Sunucu bölümü, Mattermost uygulamalarıyla aynı Go modülünü, github.com/mattermost/mattermost/server/public modülünü, Go modül vekili (proxy) üzerinden alır. main fonksiyonu yalnızca uygulamayı başlatır:

package main

import "github.com/mattermost/mattermost/server/public/plugin"

func main() {
	plugin.ClientMain(&Plugin{})
}

Plugin tipi, plugin.MattermostPlugin tipini gömerek p.API erişimi sağlar ve ihtiyaç duyduğu kancaları (hooks) uygular:

type Plugin struct {
	plugin.MattermostPlugin
	router *mux.Router
}

func (p *Plugin) OnActivate() error {
	p.router = p.newRouter()
	return p.API.RegisterCommand(&model.Command{
		Trigger:          "weather",
		AutoComplete:     true,
		AutoCompleteDesc: "Show the forecast",
		AutoCompleteHint: "[city]",
	})
}

func (p *Plugin) ExecuteCommand(c *plugin.Context, args *model.CommandArgs) (*model.CommandResponse, *model.AppError) {
	city := strings.TrimSpace(strings.TrimPrefix(args.Command, "/weather"))
	return &model.CommandResponse{
		ResponseType: model.CommandResponseTypeEphemeral,
		Text:         "Forecast for " + city + ": sunny",
	}, nil
}

func (p *Plugin) ServeHTTP(c *plugin.Context, w http.ResponseWriter, r *http.Request) {
	p.router.ServeHTTP(w, r)
}

Yararlı API çağrıları

  • CreatePost, UpdatePost, SendEphemeralPost: uygulamanın botu veya bir kullanıcı adına ileti gönderin.
  • EnsureBotUser(&model.Bot{Username, DisplayName}): uygulamanın botunu bir kez oluşturun ve kimliğini (ID) alın.
  • PublishWebSocketEvent("poll_updated", payload, &model.WebsocketBroadcast{ChannelId: id}): web uygulamasına bir olay gönderin. Olay, custom_<app id>_poll_updated olarak ulaşır.
  • OpenInteractiveDialog: bir dialog açın.
  • LogInfo, LogError ve benzerleri: sunucu günlüğüne, uygulamanın kimliğiyle (ID) etiketlenmiş olarak yazın.
  • GetUser, GetChannel, HasPermissionToChannel: bir kullanıcı adına işlem yapmadan önce, kimin ne yapabileceğini kontrol edin.

Bir uygulama, kümenin her sunucusunda çalışır. Durumu yalnızca bellekte değil, anahtar-değer deposunda veya veritabanında saklayın.

Yapay zeka servisi

Antimatter sunucusu, yöneticinin kurduğu model bağlantıları aracılığıyla (yönetici kılavuzundaki Yapay Zeka bölümüne bakın) uygulamalar için yapay zeka modellerini çağırır. Bir uygulama asla sağlayıcının anahtarını tutmaz: hangi kişi adına ve nerede hareket ettiğini belirtir; sunucu, bu kişinin orada bağlantıyı kullanıp kullanamayacağını kontrol eder, sınırlarını ve bütçelerini uygular, jetonları kişi ve uygulama adına sayar ve içeriği denetlemeden çağrıyı denetler.

YöntemNe işe yarar
AIChat(actingUserID, channelID, teamID, *ai.ChatRequest)Sohbet tamamlama: iletiler, araçlar, yapılandırılmış çıktı (JSONSchema).
AIChatStream(…)Aynı işlem, akışlı olarak: kanal kapanana kadar akışın Events değerlerini okuyun veya çağrıyı durdurmak için Close metoduyla kapatın.
AIEmbed(…, *ai.EmbedRequest)Metinlerin gömme (embedding) değerleri.
AITranscribe(…, *ai.TranscribeRequest)Sesin metne dönüştürülmesi.
AIDecide(…, *ai.DecideRequest)Bir metin hakkında karar modeline (evet veya hayır, bir seçim, bir puan) yöneltilen tiplemiş sorular.
AIConnectionsForUser(userID, channelID, teamID)Bir kişinin orada kullanabileceği bağlantılar, modelleri ve yetenekleriyle birlikte; anahtarları asla dahil edilmez.

Her isteğin ConnectionID değeri bağlantıyı, Model değeri ise bu bağlantının modellerinden birini seçer (boş bırakılırsa bağlantının varsayılanı kullanılır). Operation, kullanım ve denetim kayıtları için kısa bir etikettir, içerik değildir. Bunların minimum sunucu sürümü 11.11'dir.

actingUserID değerini yalnızca sunucunun doğruladığı bir kaynaktan alın: ServeHTTP adresinize gelen isteğin Mattermost-User-Id başlığı veya bir kancanın bağlamındaki kullanıcı (bir gönderinin yazarı, bir komutu çalıştıran kullanıcı). Asla bir iletiden, webhook yükünden, bir URL'den veya başka bir uygulamanın isteğinden almayın: uygulamanız başkasının erişimini harcar.

Bu yöntemler ve ai paketi (server/public/ai), yalnızca Antimatter'in modül kopyasında mevcuttur, Mattermost tarafından yayınlanan sürümde değil. Bunları kullanmak için, go.mod dosyanızda bir replace satırıyla Antimatter'in server/public dizinine karşı derleyin; örneğin replace github.com/mattermost/mattermost/server/public => ../antimatter/server/public. Böyle bir uygulama yalnızca Antimatter üzerinde çalışır.

Veri saklama

Her uygulamanın, sunucunun veritabanında kendi anahtar-değer deposu vardır:

  • KVSet(key, value), KVGet(key), KVDelete(key): değerler bayt olarak, genellikle JSON biçimindedir. Anahtarlar en fazla 150 karakter olabilir.
  • KVSetWithExpiry(key, value, seconds): değer bu süre dolunca silinir.
  • KVCompareAndSet(key, old, new) ve Atomic ile KVSetWithOptions: birden fazla istek veya sunucu aynı anahtarı yazarken güvenli güncellemeler sağlar. Anket, her oyu bu şekilde kaydeder ve çakışma durumunda yeniden dener.
  • KVList(page, perPage): anahtarlar, sayfa sayfa listelenir.

Web uygulaması bölümü

Yığın (bundle), window.registerPlugin ile bir sınıf kaydeder. initialize metodu kayıt defterini (registry) ve Redux deposunu alır:

import manifest from './manifest';

class Plugin {
    initialize(registry, store) {
        registry.registerTranslations((locale) => translationsFor(locale));
        registry.registerPostTypeComponent('custom_poll', PollPost);
        registry.registerWebSocketEventHandler(`custom_${manifest.id}_poll_updated`, (msg) => {
            store.dispatch(pollUpdated(JSON.parse(msg.data.poll)));
        });
        registry.registerReconnectHandler(() => store.dispatch(reloadPolls()));
    }
}

window.registerPlugin(manifest.id, new Plugin());
  • Paylaşılan kütüphaneler. Web uygulaması React, ReactDOM, Redux, React Redux ve React Intl sağlar: bunları kendi kopyalarınızı yığmak (bundle) yerine webpack externals olarak listeleyin (React, ReactDOM, Redux, ReactRedux, ReactIntl). Anket'in webpack.config.js dosyasına bakın.
  • Sunucu bölümünüzü çağırma. ${window.basename}/plugins/<app id>/… adresini, Client4.getOptions() (kaynağı mattermost-redux/client) ile gelen seçenekleri kullanarak getirin (fetch): bu seçenekler, sunucunun tarayıcıdan gelen isteği kabul etmesi için gereken başlıkları taşır.
  • Kendi durumunuz. registerReducer bir reducer ekler; bu, state['plugins-<app id>'] altında saklanır.
  • Tipler. Antimatter'in ek kayıt defteri (registry) yöntemleri, Mattermost'un yayımladığı tiplerde yer almaz: Anket, kullandığı kayıt defterini webapp/src/types/host.ts dosyasında tanımlar.

Kayıt defterinin (registry) yöntemleri ve parametreleri, webapp/fusion/src/plugins/registry.ts (Fusion) ve webapp/channels/src/plugins/registry.ts (klasik) dosyalarındaki kodda belgelenmiştir.

Fusion arayüzünü destekleme

Antimatter'in iki web arayüzü vardır: varsayılan olan Fusion ve klasik arayüz. İkisi de aynı uygulama yığınlarını (bundle) yükler ve aynı kayıt defterine (registry) sahiptir, ancak Fusion birçok öğeyi kendisi çizer ve eklenti bileşenlerini kendi yöntemine göre yerleştirir. Uygulamanızı her iki arayüzde de test edin.

Arayüzü algılama

Herhangi bir uygulama yüklenmeden önce, her iki arayüz de window.antimatterWebUI değerini 'fusion' veya 'classic' olarak ayarlar ve aynı değeri sayfanın kök öğesinde data-am-web-ui olarak belirler. Mattermost'ta bu değerlerden hiçbiri ayarlanmaz.

export function isFusionUI(): boolean {
    return window.antimatterWebUI === 'fusion' || document.documentElement.dataset.amWebUi === 'fusion';
}

Paket uygulamalar, arayüzü farklı şekilde çizmek için bunu kullanır. Anketler, anket kartlarını ve oluşturma iletişim kutusunu Fusion stiline göre çizer ve Fusion'daki /poll komutu için kendi iletişim kutusunu açar. Aramalar ve Ses kanalları, Fusion'un kendi arama arayüzüyle değiştirdiği kenar çubuğu ve bildirim bileşenlerini hariç tutar. Ajanlar uygulaması, yapay zeka işlemlerini, Diğer işlemler altında bir grup olarak, imleçle üzerine gelme araç çubuğu yerine ileti menüsüne yerleştirir. Fusion'un kendi CSS sınıfları (am- önekiyle) ve iletişim kutusu katmanı (am-layer öğesi), bu uygulamaların arayüzle uyumlu olması için kullandığı unsurlardır; bunlar belgelenmiş ve kararlı bir API değildir.

Yalnızca Antimatter'da bulunan kancalar

Bu kayıt yöntemleri Mattermost'ta mevcut değildir. Uygulamanın orada da çalışabilmesi için bir yöntemi çağırmadan önce mevcut olup olmadığını kontrol edin:

if (typeof registry.registerComposerMenuItem === 'function') {
    registry.registerComposerMenuItem({
        text: 'Create a poll',
        icon: <i className='icon icon-chart-bar'/>,
        fusionIcon: 'poll',
        action: ({channelId, rootId}) => openPollCreation(channelId, rootId),
    });
} else {
    registry.registerChannelHeaderButtonAction(icon, (channel) => openPollCreation(channel.id), 'Create a poll', 'Create a poll');
}

registerEmojiPickerTab({id, label, icon, fusionIcon, order, component, shouldRender, replacesGifPicker})İleti kutusunun emoji seçicisindeki bir sekme, örneğin GIF'ler veya çıkartmalar. Fusion'da, order değeri 10'dan düşük olan sekmeler Emoji sekmesinden önce gelir. Bileşen, channelId, rootId, filter, onFilterChange, onSelectDone, insertText, isFusion ve Fusion'da pickerKit (aşağıda) parametrelerini alır.
registerChannelViewPanel({matcher, component})Kanal başlığı ile iletiler arasında, matcher(state, channel) tarafından seçilen kanallar için bir panel. Ses kanallarının yaptığı gibi iletileri ve yazma alanını gizleyebilir (setMessagesVisible).
registerSidebarChannelFooterComponent(component)Kenar çubuğundaki bir kanalın altındaki satır, örneğin arama içindeki kişiler. channel değerini alır.
registerIntegrationsOption({title, description, fusionIcon, action, shouldRender})Yalnızca Fusion: Bütünleştirmeler sayfalarındaki bir giriş, özel emojilerin yanında. GIF uygulaması özel GIF'lerini ve çıkartmalarını oraya ekler.

Emoji seçicisinde görünümleri ekleyin ve yönetin

Fusion'da bir emoji seçici sekmesi pickerKit özelliği alır: Emoji sekmesinin kendi ekleme ve yönetme görünümleri için kullandığı bileşenler, böylece bir sekmenin görünümleri aynı görünür ve seçici içinde kalır. GIF ve Meme uygulamaları GIF'leri, çıkartmaları ve meme şablonlarını eklemek ve yönetmek için bunu kullanır. İçinde version (1), usePickerView ve useOnEscape kancaları ile PickerViewButtons (arama kutusunun yanındaki + ve yönetme düğmeleri), PickerViewFrame (geri oku olan bir görünüm), PickerNotice, PickerField, PickerSearch, PickerDropZone ve PickerManageList bileşenleri bulunur. Escape tuşu, bir görünümden sekmenin ızgarasına geri döner. Özelliğin orada olduğundan emin olun: diğer konaklar bunu hariç tutar ve o zaman sekme kendi iletişim kutularını korur. Tipler webapp/fusion/src/types/store/plugins.ts (EmojiPickerTabProps) ve bileşenler webapp/fusion/src/fusion/popovers/picker_views.tsx dosyasındadır.

Yeni penceredeki panel

Fusion, registerRightHandSidebarComponent bileşenine iki ek özellik verir, böylece Yeni pencerede aç paneli uygulamanın ana sayfasında değil, bulunduğu yerde açar:

  • setPanelState(state): panel yer değiştirdiğinde, uygulamanızın tanımladığı kısa bir dize ile (örneğin 'note/<id>' veya 'board/<id>/card/<id>') veya ana sayfasında null ile çağırın. Pencerenin adresine girdiği için asla gizli bilgi koymayın. 512 karakterden uzun veya denetim karakterleri içeren bir durum düşürülür.
  • initialPanelState: yeni pencerede, panelin sahip olduğu durum veya undefined. Bunu güvensiz girdi olarak ele alın: öğeyi oturum açan kişi olarak yeniden getirin ve açamazlarsa uygulamanın ana sayfasını veya bulunamadı görünümünü gösterin.

Panel kapatıldığında veya başka bir uygulamanın paneli yerini aldığında durum unutulur. Bir panelin penceresini kendiniz açmak için, popoutRhsPlugin (aynı zamanda window.WebappUtils.popouts içinde) durumu isteğe bağlı beşinci argüman olarak alır. Notlar, Beyaz Tahta, Yapılacaklar, Kanban ve Playbook'lar bunu kullanır.

fusionIcon, Fusion'un simge setindeki bir simgeyi belirtir (örneğin poll, sticker, calendar veya image; bkz. webapp/fusion/src/fusion/components/icon). Fusion, icon yerine bunu gösterir, böylece öğe diğerleriyle uyumlu olur.

Ayarlar

plugin.json içindeki settings_schema, uygulamanın Sistem Konsolu › Uygulama ekleri sayfasını açıklar:

"settings_schema": {
  "header": "Forecasts come from the weather service below.",
  "settings": [
    {"key": "ServiceURL", "display_name": "Service URL", "type": "text", "default": "https://api.example.com"},
    {"key": "Units", "display_name": "Units", "type": "dropdown", "default": "metric",
     "options": [{"display_name": "Celsius", "value": "metric"}, {"display_name": "Fahrenheit", "value": "imperial"}]},
    {"key": "EnableAlerts", "display_name": "Severe weather alerts", "type": "bool", "default": false,
     "help_text": "Post alerts in the channels that follow a city."}
  ]
}

Ayar türleri: bool, text, longtext, number, dropdown, radio, generated (rastgele bir gizli anahtar), username ve custom (web uygulaması bölümünün registerAdminConsoleCustomSetting ile kaydettiği bir bileşen tarafından çizilir). Ayarlar sections içinde gruplandırılabilir.

Sunucu bölümü, alanları anahtarlarla eşleşen bir yapıya (struct) okur:

type configuration struct {
	ServiceURL   string
	Units        string
	EnableAlerts bool
}

func (p *Plugin) OnConfigurationChange() error {
	var cfg configuration
	if err := p.API.LoadPluginConfiguration(&cfg); err != nil {
		return err
	}
	p.setConfiguration(&cfg)
	return nil
}

Yöneticiler, bunları yapılandırmada, PluginSettings.Plugins.<app id> altında, küçük harfli anahtarlarla da ayarlayabilir (bkz. yönetici kılavuzu).

Çeviriler

Antimatter 37 dile çevrilmiştir ve paketlenen uygulamalar da öyle. Web uygulaması bölümü bunu şu şekilde yapar:

  1. Tüm dizeleri React Intl ile, bir kimlik (ID) ve İngilizce metniyle yazın: <FormattedMessage id='polls.create' defaultMessage='Create a poll'/> veya defineMessages. Kimliklerin başına uygulamanızın adını ekleyin.
  2. İngilizce dizeleri webapp/i18n/en.json dosyasına çıkarın (paketlenen uygulamalar formatjs extract kullanır).
  3. Yanına, aynı kimliklere sahip her dil için bir dosya ekleyin: fr.json, de.json, pt-BR.json, zh-CN.json…
  4. Bunları web uygulamasına verin; kullanıcıdan dilini ister: 
    import fr from '../i18n/fr.json';
import ptBR from '../i18n/pt-BR.json';

const catalogs = {fr, 'pt-BR': ptBR};

export function translationsFor(locale) {
    return catalogs[locale] || catalogs[locale.split('-')[0]] || {};
}

registry.registerTranslations(translationsFor);

Eksik bir dize, İngilizce defaultMessage değerine geri düşer. Sunucu tarafının gönderdiği dizeler için (komut yanıtları, bot iletileri) pluginapi/i18n paketi, paketle birlikte gelen çeviri dosyalarını (örneğin assets/i18n) yükler ve her kullanıcı için kendi dilinde bir yerelleştirici sağlar.

Go ve Node.js (uygulamanın .nvmrc dosyasındaki sürüm) gerekir. Uygulamanın klasöründe:

Bir paketi elle kurun

  • Bir sistem yöneticisi, AM_PLUGINSETTINGS_ENABLEUPLOADS=true ayarıyla yüklemelere izin verir (varsayılan olarak kapalıdır; Sistem Konsolu'nda bir anahtarı yoktur).
  • Ardından Sistem Konsolu › Uygulama ekleri › Uygulama eki yönetimi › Uygulama eki yükle veya amctl plugin add weather.tar.gz ardından amctl plugin enable com.example.weather.

Geliştirme sunucusunda hızlı tekrarlar için sunucuda AM_SERVICESETTINGS_ENABLEDEVELOPER=true ayarını yapın: hatalar bu durumda ayrıntılarını taşır. Paketlenmiş uygulamaların Makefile'ları, kabuğunuzda MM_SERVICESETTINGS_ENABLEDEVELOPER ayarlıysa sunucu tarafını yalnızca sizin platformunuz için derler.
