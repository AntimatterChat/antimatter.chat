Mitä tarvitset

  • Siirry versioon, joka on määritetty tiedostossa server/go.mod (kirjoitushetkellä 1.26.7).
  • Node.js ja npm, versiot, jotka on määritelty tiedostoissa .nvmrc ja webapp/package.json (Node 24.11.1 ja npm 11.6.2). mise-työkalun avulla varaston mise.toml-tiedosto asenta oikean Node-version.
  • Docker Compose-työkalulla: kehitysympäristössä PostgreSQL ja muutamat muut palvelut ajetaan konteinereissa.
  • make, git sekä Linux- tai macOS-kone.
  • Muisti: verkkokäyttöliittymien kääntäminen on raskain vaihe. Varaa 16 Gt RAM-muistia; katso osio Käännökset ja muisti.
git clone https://github.com/AntimatterChat/antimatter.git
cd antimatter

Varastossa palvelin sijaitsee hakemistossa server/, verkkokäyttöliittymät hakemistossa webapp/ (Fusion hakemistossa webapp/fusion, klassinen hakemistossa webapp/channels ja yhteiset paketit hakemistossa webapp/platform) sekä päästä päähän -testit hakemistossa e2e-tests/.

Kehityspalvelimen käynnistys

cd server
make run

make run käynnistää kehityskontainerit (PostgreSQL, Redis, sähköpostinsäätäjän ja valvontatyökalut), asettaa verkkosovelluksen käännökset paikoilleen, käynnistää palvelimen taustalle komennolla go run ja käynnistää verkkosovelluksen seurantatyökalun, joka kääntää klassisen käyttöliittymän uudelleen, kun sitä muokataan. Avaa osoite http://localhost:8065 ja luo tili: ensimmäinen tili on järjestelmän ylläpitäjä.

make restart-serverKäynnitä palvelin uudelleen Go-koodin muuttamisen jälkeen.

Kehitystietokanta on postgres://mmuser:mostest_password@localhost/mattermost_test, joka on palvelimen oletusdatasäiliö. Valitse, mitkä kontainerit käynnistetään, muuttujalla ENABLED_DOCKER_SERVICES tiedostossa server/config.override.mk tai ympäristömuuttujana (katso server/config.mk).

Verkkokäyttöliittymät

Hakemistossa webapp/:

npm install      # also builds the shared packages
npm run build    # the classic interface, then Fusion

Käännökset sijoittuvat hakemistoihin webapp/channels/dist (klassinen) ja webapp/fusion/dist (Fusion). make client -komento hakemistossa server/ linkkaa ne poluille server/client ja server/client-fusion, josta palvelin palvelee niitä: klassinen rajapinta polulla /static/ ja Fusion polulla /static/fusion/.

  • npm run run (tai make run hakemistossa webapp/) seuraa muutoksia ja kääntää klassisen rajapinnan uudelleen. Lisää WATCH_FUSION=true -muuttuja, jotta myös Fusion käännetään uudelleen.
  • npm run dev-server (make dev) ajaa webpackin kehityspalvelimen: klassinen rajapinta portissa 9005 ja Fusion portissa 9006.
  • Näet selaimessa toisen tai toisen rajapinnan lisäämällä osoitteen loppuun ?webui=fusion tai ?webui=classic.

Julkaisuarkistot

cd webapp && npm run build && cd ..
cd server
make build-linux       # the antimatter and amctl binaries
make package-linux     # dist/antimatter-linux-amd64.tar.gz and -arm64

make build kääntää verkkokeskukset ja Linuxin binäärit yhdessä. Arkisto sisältää bin/antimatter- ja bin/amctl-tiedostot, oletusarvoiset config/config.json-asetukset, ohjeet asetusten muuttamiseen README.md-tiedostossa, molemmat verkkokeskukset, mallit, fontit ja käännökset. Muut alustat: make package-osx, make package-windows, make package-freebsd.

Sisällytetyt sovellukset

Tavallinen make package-linux kääntää arkiston ilman sovelluksia. Sisällyttääksesi sovellukset, kuten julkaisuversiot tekevät, hae ensin allekirjoitetut sovelluspaketit ja anna niiden hakemisto:

build/package/fetch-apps.sh "$HOME/release-apps"   # needs gh, python3 and gpg
make package-linux PREPACKAGED_PLUGINS_DIR="$HOME/release-apps"

fetch-apps.sh ladataa antimatter-dockerin plugins.json-tiedostossa lueteltujen sovellusten uusimmat GitHub-julkaisut, allekirjoituksineen, ja tarkistaa allekirjoituksen Antimatterin liitännäisavainta vasten. Oletuksena se hakee Valkotaulun, Äänikanavat, Puhelut, Agentit, Tehtävälistat, Kyselyt, Muistiinpanot, GIFit ja Memet; AM_BUNDLED_APPS (varaston nimet, välilyönnein eroteltu) muuttaa listaa. Sovellukset, joilla ei ole julkaisua tai allekirjoitusta, ohitetaan varoituksen kera. Paketit sijoitetaan arkiston prepackaged_plugins/-hakemistoon.

.deb- ja .rpm-paketit

build/package/build-packages.sh <archive> <amd64|arm64> <version> <out-dir> muuntaa julkaisuarkiston yhdistetyiksi .deb- ja .rpm-paketeiksi, nfpm:n avulla. Ylläpitäjän opas kuvaa, mitä paketit asettavat: katso .deb- tai .rpm-paketin asennus.

Julkaisuprosessi

Palvelinvaraston antimatter-release.yml-työvirta hoitaa kaiken tämän GitHubissa: v*-merkinnällä se kääntää arkistot ja paketit amd64- ja arm64-arkkitehtuureille, SHA256SUMS-tiedostoineen, ja julkaisee ne merkinnän GitHub-julkaisuna (esijulkaisuna, jos versiossa on -). Käynnistettynä manuaalisesti se numeroi käännöksen 0.9.0-dev.<run> ja säilyttää tiedostot työvirran artefakteina. Jokaisella sovellusvarastolla on release.yml-työvirta, joka julkaisee allekirjoitetun paketin samalla tavalla.

Docker-kuvio

antimatter-docker-varastossa luodaan julkaistavat kiot, palvelin ja sen sovellukset, kokonaan Dockerin sisällä:

git clone https://github.com/AntimatterChat/antimatter-docker.git
cd antimatter-docker
scripts/build-all.sh                     # from the main branches on GitHub
SOURCES=local scripts/build-all.sh       # from your checkouts next to this folder
VARIANT=next scripts/build-all.sh        # the "next" image, with every Antimatter app

Tarvitaan Docker buildx-työkalulla, Python 3, git ja gpg, noin 16 Gt RAM-muistia ja 30 Gt levystiivistä. Tulos ladataan nimellä ghcr.io/antimatterchat/antimatter:dev; kokeile sitä komennolla ANTIMATTER_IMAGE=ghcr.io/antimatterchat/antimatter:dev docker compose -f compose.local.yml up -d. Tiedostossa plugins.json luetellaan sovellukset ja käännetyt versiot, ja varaston README-tiedosto selittää eri vaihtoehdot.

build-all.sh allekirjoittaa mukana toimitetut sovellukset Antimatterin allekirjoitustavalla, ja kuvan rakennus hylkää allekirjoittamattomat sovellukset. Ilman tätä yksityistä avainta, josta vain ylläpitäjillä on kopio, aja ensimmäiset vaiheet erikseen: scripts/fetch-sources.sh, scripts/build-plugins.sh (sovelluspaketit hakemistossa out/plugins/) ja scripts/build-server.sh (palvelimen arkistot hakemistossa out/server/).

Rakennus ja muisti

Verkkokeskkusien käyttöliittymät ovat suuria webpack-rakennuksia, ja muistin loppuminen on yleisin rakennusvirhe.

  • npm run build rakentaa klassisen käyttöliittymän ja Fusionin peräkkäin, ei samanaikaisesti, jotta huippukäyttö pysyy matalana. Älä aja niitä itse samanaikaisesti.
  • Pienentäjä käynnistää yhden työntekijän perä prosessori. Jos koneella on paljon ytimiä, mutta vähän muistia, rajaa rakennuksen näkemät prosessorit: taskset -c 0-5 npm run build.
  • Jos Node loppuu heap-muistista, nosta sen raja: NODE_OPTIONS=--max-old-space-size=6144. Docker-rakennus käyttää tätä arvoa (BUILD_NODE_OPTIONS -muuttuja build.env-tiedostossa).
  • Vältä palvelimen koko testisuiten, verkkorakennuksen ja Docker-rakennuksen ajamista samanaikaisesti pienellä koneella.

Sovellukset

Jokaisella sovelluksella (liitännäisellä) on oma varastonsa ja Makefile-ohjelmisto; make dist rakentaa sen paketin. Katso Rakennus, asennus ja vianetsintä.

Työpöytäsovellus

Työpöytäsovellus on Electron-sovellus. Node.js 24 tai uudempi vaaditaan:

npm install --allow-git=all
npm run build          # development build, into dist/
npm start              # run it
npm run package:linux  # packages into release/ (also package:windows, package:mac)

Käännösaikaiset asetukset, kuten ennakkoon määritettävät palvelimet, löytyvät tiedostosta src/common/config/buildConfig.ts. Ilman Applen sertifikaattia aseta AM_MAC_ADHOC_SIGN=true, jotta macOS-sovellus allekirjoitetaan ad hoc -menetelmällä ilman notarisaatiota: Apple-silikonilla varustetut Macit hylkäävät allekirjoittamattoman koodin. Varaston release.yml-työvirta luo allekirjoittamattomat pakkausversiot Linuxille, Windowsille ja macOS:lle, kun lyhyt tunniste on v*.

Mobiilisovellus

Mobiilisovellus on React Native -sovellus, jonka README-tiedostossa luetellaan komennot (npm run ios, npm run android). Oman kopion kääntämiseen tarvitset myös omat allekirjoitustavut, Firebase-projektin Android-ilmoituksia varten, APNs-avaimen iOS:lle sekä push-välityspalvelimen, joka säilyttää näiden tunnus tiedot. Varaston release.yml-työvirta luo Android-APK:n ja AAB:n sekä allekirjoittamattoman iOS-.ipa-tiedoston, kun lyhyt tunniste on v*, ilman kaupunkitilejä. README-tiedostossa luetellaan salaisuudet, joilla Android-rakennus allekirjoitetaan ja Firebase asetetaan.
