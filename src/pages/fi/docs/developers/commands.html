Näin kauttaviivakomento toimii

  1. Joku syöttää /weather Paris ja lähettää sen. Tekstiä ei julkaista.
  2. Antimatter lähettää HTTP-pyyntö komennon URL:iin, jossa on tiedot syöttäjästä, sijainnista ja triggerisanan jälkeisestä tekstistä.
  3. Palvelusi vastaa viestillä pyynnön aikakatkaisun (oletus 30 sekuntia) sisällä.
  4. Antimatter näyttää vastauksen: vain kyseiselle henkilölle (tilapäinen) tai kanavalla kaikille.

Komennot kuuluvat yhteisöön, ja triggerisana on yksilöllinen sen sisällä. Sisäisiä komentoja, kuten /join, /msg tai /away, ei voi korvata. Sovellukset (liitännäiset) voivat rekisteröidä komentoja; ks. Palvelinosa.

Luo komento

Mukautetut kauttaviivakomennot ovat oletuksena käytössä (Salli mukautetut kauttaviivakomennot kohdassa Järjestelmäkonsoli › Integraatiot › Integraatioiden hallinta, ServiceSettings.EnableCommands). Yhteisöjen ylläpitäjät ja järjestelmän ylläpitäjät voivat luoda niitä oletuksena.

  1. Avaa profiilisi yläoikealla, valitse Integraatiot › Kauttaviivakomennot ja sen jälkeen Lisää kauttaviivakomento.
  2. Täytä Otsikko ja Kuvaus (näytetään integraatioiden sivuilla).
  3. Syötä Komentotriggersana ilman kauttaviivaa ja välilyöntejä, esimerkiksi weather.
  4. Syötä Pyyntö-URL ja valitse Pyyntömenetelmä: POST (oletus) tai GET.
  5. Aseta valinnaisesti Vastauksen käyttäjänimi ja Vastauksen kuvake. Niitä käytetään vain, jos palvelin sallii integraatioiden yliajaa nimet ja kuvakkeet (ks. Nimi ja kuvake).
  6. Valitse Automaattitäydennys, jolloin komento luetellaan, kun ihmiset syöttävät /, yhdessä Automaattitäydön vihjeen (argumentit, kuten [city]) ja Automaattitäydön kuvauksen kanssa.
  7. Valitse Tallenna ja kopioi näytetty token. Palvelusi käyttää sitä varmistaakseen, että pyynnöt tulevat palvelimeltasi.

API:n avulla: POST /api/v4/commands {"team_id", "trigger", "url", "method": "P", "display_name", "description", "auto_complete": true, "auto_complete_hint", "auto_complete_desc", "username", "icon_url"}:lla. Metodi on P POST-pyyntöille ja G GET-pyyntöille. PUT /api/v4/commands/{command_id}/regen_token luo uuden tunnuksen.

Palvelusi vastaanottama pyyntö

POST-komento lähettää lomakekoodatetun ruumiin (application/x-www-form-urlencoded); GET-komento lähettää samat kentät kyselymerkkijonossa. Token löytyy myös Authorization: Token <token> -otsakkeesta.

KenttäArvo
tokenKomenton token. Tarkista se jokaisessa pyyntössä.
commandTrigger kauttaviivalla, esimerkiksi /weather.
textKaikki triggerin jälkeen, esimerkiksi Paris.
user_id, user_nameKuka ajoi komennon.
channel_id, channel_nameMissä komento ajettiin.
team_id, team_domainYhteisön ID ja URL-nimi.
root_idKetju, jos komento ajettiin ketjun vastausruudussa.
trigger_idSallii vastauksen avata dialogin (ks. Dialogit). Voimassa vain lyhyen aikaa.
response_urlURL, jolla voi lähettää lisää vastauksia myöhemmin (ks. Viivästyneet vastaukset).
user_mentions, user_mentions_ids, channel_mentions, channel_mentions_idsTekstissä mainitut henkilöt ja julkiset kanavat, jos sellaisia on.
Palvelimen Sivuston URL-osoite on asetettava, jotta mukautetut komennot toimivat: Antimatter rakentaa response_url:n siitä.

Vastaus

Vastaa 200 JSON:lla (Content-Type: application/json):

{
  "response_type": "in_channel",
  "text": "Paris: 18 °C, light rain",
  "attachments": []
}
KenttäMerkitseminen
response_typeephemeral (oletus): vain komennon ajaja näkee vastauksen, ja se ei säilyy sivun latauksen jälkeen. in_channel: vastaus lähetetään kanavaan.
text, attachmentsViesti, kuten webhookeissa: Markdown-teksti ja liitteet, painikkeet ja valikot mukaan lukien.
username, icon_urlNäytettävä nimi ja kuva, jos yliajot ovat sallittu. Komenton omat asetukset voittavat nämä.
channel_idLähetä vastaus toiseen kanavaan, jonka jäsenen käyttäjän on oltava.
goto_locationURL, joka avataan, kun komento on suoritettu.
props, typeLisäominaisuudet ja mukautettu lähetystyyppi, kuten webhookeissa.
extra_responsesLisävastaukset, joilla on samat kentät, lähetetään ensimmäisen jälkeen.
skip_slack_parsingtrue jättää tekstin muuttumattomaksi, ilman Slack-tyylisten linkkien ja mainintojen muuntamista.

Vastaus, joka ei ole JSON, näytetään tilapäisviestinä, jossa ruumis on tekstinä. 204 No Content ei näytä mitään. Mikä tahansa tila 200–299 -väliltä näyttää käyttäjälle virheen.

Palvelun esimerkki

Minimaalinen komento-palvelu Pythonilla, vain standardikirjastolla:

import hmac
import json
from http.server import BaseHTTPRequestHandler, HTTPServer
from urllib.parse import parse_qs

TOKEN = "the token shown when you saved the command"

class Handler(BaseHTTPRequestHandler):
    def do_POST(self):
        body = self.rfile.read(int(self.headers["Content-Length"])).decode()
        form = {key: values[0] for key, values in parse_qs(body).items()}
        if not hmac.compare_digest(form.get("token", ""), TOKEN):
            self.send_response(401)
            self.end_headers()
            return
        answer = {
            "response_type": "ephemeral",
            "text": f"Hello @{form['user_name']}, you asked for: {form.get('text', '')}",
        }
        data = json.dumps(answer).encode()
        self.send_response(200)
        self.send_header("Content-Type", "application/json")
        self.end_headers()
        self.wfile.write(data)

HTTPServer(("0.0.0.0", 8080), Handler).serve_forever()

Jos palvelu toimii yksityisellä verkkosoitteella, järjestelmän ylläpitäjän on sallittava se kohdassa Salli luottamattomat sisäiset yhteydet osoitteisiin (ServiceSettings.AllowedUntrustedInternalConnections).

Viivästyneet vastaukset

Työhön, joka kestää kauemmin kuin aikakatkaisu, vastaa heti (esimerkiksi tilapäisellä viestillä ”Työskentelemme asiaa…”), ja lähetä sitten todellinen vastaus osoitteeseen response_url. Vastaukseen käytetään samaa JSON-muotoa kuin tavalliseen vastaukseen, ja toiminto on käytettävissä enintään viisi kertaa 30 minuutin aikana komennon suorituksen jälkeen.

curl -X POST "$RESPONSE_URL" -H 'Content-Type: application/json' \
  -d '{"response_type": "in_channel", "text": "Report ready: https://reports.example.com/42"}'

Komentojen suoritus API:lla

Skriptit ja botit voivat suorittaa minkä tahansa komennon, olipa se sisäänrakennettu tai mukautettu, aivan kuin ne olisivat kirjoittaneet sen:

curl -X POST https://chat.example.com/api/v4/commands/execute \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"channel_id": "'$CHANNEL_ID'", "command": "/weather Paris"}'

GET /api/v4/teams/{team_id}/commands/autocomplete -päätepiste luetteloii komennot, joita käyttäjät voivat täydentää yhteisössä.

Automaattitäydennys

Integraatioiden sivuilla luodut komennot täydentyvät automaattisesti laukaisunsa, vihjeensä ja kuvauksensa perusteella. Sovellusten rekisteröimät komennot voivat kuvata alikomennot ja argumentit tarkasti AutocompleteData-rakenteella, joka luodaan kutsulla model.NewAutocompleteData(trigger, hint, helpText):

  • AddCommand(sub) lisää alikomennon, joka on itse AutocompleteData-rakenne.
  • AddTextArgument(helpText, hint, pattern) lisää vapaata tekstiä.
  • AddStaticListArgument(helpText, required, items) tarjoaa kiinteän luettelon AutocompleteListItem{Item, Hint, HelpText}-olioista.
  • AddDynamicListArgument(helpText, url, required) hakee ehdotukset sovelluksestasi, kun käyttäjä kirjoittaa. URL on sovelluksesi reitti, esimerkiksi /plugins/com.example.weather/cities. Reittiin siirretään käyttäjä, kanava ja yhteisö, ja se palauttaa JSON-luettelon {"Item", "Hint", "HelpText"}-olioista.

Named…-muodot (kuten AddNamedTextArgument ja muut) lisäävät --name value-lippuja. Molemmissa käyttöliittymissä näytetään nämä ehdotukset.
