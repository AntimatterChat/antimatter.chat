Perusasiat

  • Perus-URL: https://chat.example.com/api/v4. Kaikki alla olevat loput ovat suhteessa tähän.
  • Muoto: JSON sisäänpäin ja ulospäin, paitsi tiedostolähetykset (multipart). Lähetä Content-Type: application/json.
  • Tunnistekoodit: jokaisella objektilla on 26 merkin id. Aikaleimat ovat millisekunteja Unix-epokista (create_at, update_at, delete_at; 0 tarkoittaa "ei poistettu").
  • Yhteisöt ovat tiimejä: API kutsuu niitä teams-resursseiksi, joilla on team_id.
  • Sinä: missä tahansa polussa, joka ottaa user_id-parametrin, me tarkoittaa kirjautunutta käyttäjää, kuten GET /users/me.

Täydellinen lista lopuista on palvelimen koodissa: reitit on määritelty tiedostossa server/channels/api4/*.go ja tyyppitiedot hakemistossa server/public/model. OpenAPI-kuvauksessa, joka sijaitsee repon api/v4/source-hakemistossa, on lueteltu Mattermostista periytetyt loput, ei Antimatterin lisäyksiä.

Tunnistautuminen

Jokainen pyyntö, paitsi kirjautuminen ja muutama julkinen loppu, vaatii tunnuksen Authorization-otsakkeessa:

curl -H "Authorization: Bearer $TOKEN" https://chat.example.com/api/v4/users/me

Siellä hyväksytään kolme tyyppiä tunnusta: henkilökohtaiset pääsytunnukset, istuntotunnukset ja OAuth-pääsytunnukset. Myös Authorization: Token … hyväksytään. Tunnukset kyselymerkkijonossa (?access_token=) hyväksytään vain OAuth-pääsytunnuksille.

Henkilökohtaiset pääsytunnukset (suositellaan skripteille)

Henkilökohtainen pääsytunnus toimii puolestasi, ei vanhene, ellei sinä aseta sille vanhenemispäivää, ja se voi peruutua milloin tahansa. Henkilökohtaiset pääsytunnukset ovat oletusarvoisesti poissa käytöstä:

  1. Järjestelmän ylläpitäjä ottaa Ota henkilökohtaiset pääsytunnustiedot käyttöön-asetuksen käyttöön kohdassa Järjestelmäkonsoli › Integraatiot › Integraatioiden hallinta (ServiceSettings.EnableUserAccessTokens, AM_SERVICESETTINGS_ENABLEUSERACCESSTOKENS).
  2. Jokaiselle käyttäjälle, joka voi luoda avaimia, järjestelmän ylläpitäjä avaa Järjestelmäkonsoli › Käyttäjien hallinta › Käyttäjät, valitsee Hallitse rooleja käyttäjän valikosta ja valitsee Salli tämän tilin luoda henkilökohtaisia API-avaimia. Järjestelmän ylläpitäjät voivat aina luoda avaimia.
  3. Käyttäjä avaa profiilinsa yläoikeasta kulmasta ja siirtyy kohtaan Profiili & asetukset › Turva. Kohdassa Henkilökohtaiset pääsytunnisteet hän kuvaa, mihin tunnistetta tarvitaan, ja valitsee Luo tunnus. Tunnus näytetään vain kerran: kopioi se.

API:lla: POST /users/{user_id}/tokens parametrina {"description": "backup script", "expires_at": 0} (expires_at millisekunteina; 0, jos ei eräpäivää). Vastauksen token-kenttä on avain; sen id käytetään avaimen peruuttamiseen (POST /users/tokens/revoke parametrina {"token_id": "…"}). Komentoriviltä: amctl token generate <user> <description>.

Järjestelmän ylläpitäjä voi asettaa tunnisteen enimmäiskäyttöajan kohdassa Henkilökohtaisen pääsytunnisteen enimmäiskäyttöaika (päivää) samalla Järjestelmäkonsolin sivulla.

Istuntoavaimet

Kirjautuminen salasanalla palauttaa istuntoavaimen Token-vastausotsakkeessa. Istunto on sama tyyppi, jota sovellukset käyttävät:

curl -i -X POST https://chat.example.com/api/v4/users/login \
  -H 'Content-Type: application/json' \
  -d '{"login_id": "maya", "password": "…"}'

Lisää "token": "123456" tilille, jolla on monitahoinen tunnistautuminen. Istunnot erääntyvät palvelimen istuntoasetusten mukaan, ja kirjautumispisteellä on nopeusrajoitus (5 pyyntöä sekunnissa). POST /users/logout päättää istunnon.

Selaimet tunnistautuvat eväkeellä. Pyyntö, joka on tunnistautettu eväkeellä, vaatii X-CSRF-Token-otsakkeen kaikkeen lukuun ottamatta GET-pyyntöjä; Authorization-otsakkeessa oleva avain ei vaadi CSRF-otsaketta.

OAuth 2.0 -sovellukset

Jotta käyttäjät voivat kirjautua sovellukseesi Antimatter-tilillään, rekisteröi OAuth 2.0 -sovellus. Antimatter toimii silloin OAuth-palveluntarjoajana:

  1. Ota OAuth 2.0 -palveluntarjoaja käyttöön on oltava päällä (Järjestelmäkonsoli › Integraatiot › Integraatioiden hallinta, ServiceSettings.EnableOAuthServiceProvider, oletuksena päällä).
  2. Käyttäjä, jolla on oikeus hallita OAuth-sovelluksia (oletuksena järjestelmän ylläpitäjät), avaa oman profiilinsa kuvan ja siirtyy kohtaan Integraatiot › OAuth 2.0 -sovellukset ja lisää sovelluksen sen kutsutakaisin-URL:ien kanssa. Hän saa asiakas-ID:n ja asiakasavaimen.
  3. Sovellus ohjaa käyttäjät osoitteeseen https://chat.example.com/oauth/authorize parametreilla response_type=code, client_id, redirect_uri ja state. PKCE-tuki code_challenge_method=S256 -menetelmällä on käytettävissä.
  4. Koodi vaihdetaan osoitteessa POST https://chat.example.com/oauth/access_token (grant_type=authorization_code, sen jälkeen refresh_token uudistamiseksi), ja API:ta kutsutaan otsakkeella Authorization: Bearer <access token>.

Käyttäjät näkevät valtuuttamansa sovellukset kohdassa Profiili ja asetukset › Tietoturva › Valtuuttamasi sovellukset.

Viestin julkaiseminen

curl -X POST https://chat.example.com/api/v4/posts \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"channel_id": "'$CHANNEL_ID'", "message": "Backup finished: **42 GB** in 3 min"}'

Viestit ovat Markdown-muodossa. Lisää "root_id" (ketjun ensimmäinen viesti) vastaamaan ketjussa, "file_ids" tiedostoille ja "props" liitteille ja muille lisäyksille (katso Liitteet).

Kanavan ID:n etsiminen

curl -H "Authorization: Bearer $TOKEN" \
  https://chat.example.com/api/v4/teams/name/lumen-labs/channels/name/ops-alerts

Nimet ovat kanavan linkissä: /lumen-labs/channels/ops-alerts.

Sivutus

Listaloppupisteet ottavat vastaan page (alkaen 0) ja per_page (oletus 60, enintään 200). Pyydä seuraavaa sivua, kunnes palautettu sivu on lyhyempi kuin per_page.

Kanavan viestit (GET /channels/{channel_id}/posts) hyväksyvät myös since-parametrin (aika: kaikki siitä hetkestä lähtien muuttuneet) tai before- ja after-parametrin (viestin tunnistekoodi). Vastaus on viestilista: {"order": [IDs, newest first], "posts": {ID: post}, "next_post_id", "prev_post_id"}.

Virheet

Virheet käyttävät tavallisia HTTP-tilakoodia (400 virheellinen syöte, 401 ei kirjautunut, 403 ei sallittu, 404 ei löytynyt, 501 ominaisuus poistettu käytöstä) ja JSON-viestin:

{
  "id": "api.context.permissions.app_error",
  "message": "You do not have the appropriate permissions.",
  "detailed_error": "",
  "request_id": "jz8zm5nunpbt8f3gpqsz5dq6so",
  "status_code": 403
}

Käytä id:tä koodissasi: message käännetään käyttäjän kielelle. detailed_error on tyhjä, ellei palvelin aja kehittäjätilassa (ServiceSettings.EnableDeveloper). Mainitse request_id palvelimen ylläpitäjälle: se näkyy lokitiedostoissa.

Nopeusrajoitukset

Käyttörajoitukset ovat oletusarvoinen poissa. Kun järjestelmän ylläpitäjä ottaa ne käyttöön (Järjestelmäkonsoli › Ympäristö › Käyttörajoitukset), jokainen asiakas saa oletusarvona 10 pyyntöä sekunnissa, ja burstin koko on 100. Laskenta perustuu IP-osoitteeseen tai käyttäjään. Vastaukset sisältävät X-RateLimit-Limit, X-RateLimit-Remaining ja X-RateLimit-Reset-otsakkeet. Rajoituksen ylittyessä palvelin vastaa 429-koodilla ja Retry-After-otsakkeella, joka ilmaisee sekundeissa, milloin uusia pyyntöjä voi lähettää. Joillakin loputuspisteillä, kuten kirjautumisella, on omat rajoituksensa riippumatta asetuksista.

Kirjoita skriptejä, jotka odottavat ja yrittävät uudelleen 429-virheen kohdalla, ja vältä kyselyitä: seuraa WebSocket-yhteyttä sen sijaan.

WebSocket-tapahtumavirta

Yhdistä osoitteeseen wss://chat.example.com/api/v4/websocket. Todennä itsesi joko Authorization: Bearer-otsakkeella yhteydenpyynnössä tai lähettämällä tämä ensimmäisenä viestinä:

{"seq": 1, "action": "authentication_challenge", "data": {"token": "…"}}

Palvelin lähettää hello-tapahtuman, sitten tapahtuman kaikesta, mitä sinulla on oikeus nähdä:

{
  "event": "posted",
  "data": {"channel_id": "…", "channel_type": "O", "post": "{\"id\":\"…\",\"message\":\"Hello\",…}"},
  "broadcast": {"channel_id": "…", "team_id": "", "user_id": "", "omit_users": null},
  "seq": 4
}

Huomaa, että data.post on viesti JSON-muotoisena merkkijonona. Yleisiä tapahtumia ovat: posted, post_edited, post_deleted, reaction_added, reaction_removed, typing, status_change, user_added, direct_added. Sovut lähettävät omia tapahtumiaan, nimettyinä custom_<app id>_<event>.

Voit myös lähettää toimintoja, joista jokaisella on kasvava seq: user_typing arvolla {"channel_id", "parent_id"} tai get_statuses. Yhdistä uudelleen, jos yhteys katkeaa, ja hae puuttuvat tiedot since-parametrilla (ks. Sivutus).

Antimatter lisää nämä tapahtumat: community_attributes_updated, member_timeouts_updated, post_put_on_top, post_removed_from_top, server_categories_updated, channel_overrides_updated ja category_overrides_updated.

Asiakasohjelmistokirjastot

  • Siirry: model.Client4 -luokka sijaitsee hakemistossa server/public/model (import github.com/mattermost/mattermost/server/public/model). Luo asiakas model.NewAPIv4Client(url) -metodilla ja aseta tunnus client.SetToken(token) -metodilla. model.NewWebSocketClient4(wsURL, token) seuraa tapahtumia. Antimatterin kopio lisää metodeja omille loputuspisteilleen, kuten UpdateMessageRequest, PutPostOnTop ja ExportChannel.
  • TypeScript: Client4 -luokka @mattermost/client -paketista, joka sijaitsee hakemistossa webapp/platform/client, ja tyyppimääritykset hakemistossa webapp/platform/types. Antimatterin varastossa oleva kopio sisältää Antimatterin päätepisteet; Mattermostin npm:ssä julkaisema paketti ei sisällä niitä.
package main

import (
	"context"
	"log"

	"github.com/mattermost/mattermost/server/public/model"
)

func main() {
	client := model.NewAPIv4Client("https://chat.example.com")
	client.SetToken("…")
	post, _, err := client.CreatePost(context.Background(), &model.Post{
		ChannelId: "…",
		Message:   "Hello from Go",
	})
	if err != nil {
		log.Fatal(err)
	}
	log.Println("posted", post.Id)
}

Uudet kentät

  • Yhteisöt (Team ja PUT /teams/{team_id}/patch): all_channels_membership (kaikki ovat kaikissa näkyvissä olevissa kanavissa, kuten Discordissa), default_channel_id (mihin uudet käyttäjät sijoitetaan; tyhjä tarkoittaa Town Square -kanavaa), hide_role_colors, require_team_badges, onboarding ja autolinks (molemmat JSON-merkkijonoja).
  • Sisäiset vastaukset: viesti, jossa on "props": {"reply_to": "<post id>"}, lainaa kyseisen kanavan viestin. Lisää "reply_to_mention": false, jotta viestin kirjoittajaa ei ilmoiteta. Palvelin täyttää metadata.reply_to -kentän lainatun viestin lyhyellä kuvauksella.
  • Spoilerit: "props": {"spoiler": true} piilottaa viestin tekstin ja liitetiedostot, kunnes lukija valitsee nähdä ne.
  • Ignoroiminen ja estäminen ovat asetuksia: kategoria user_block, nimetty toisen henkilun ID:n mukaan, arvo ignore tai block. Suoran viestin odottaminen pyyntönä näkyy kanavan jäsenen notify_props.dm_request -kentässä (pending, accepted tai dismissed).
  • Viestiliitteet voivat sisältää stages- ja chart-kentät: katso Kortit.
