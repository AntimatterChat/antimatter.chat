Asennus Docker Compose -työkalulla

Tämä on suositeltu tapa. Yksi compose-tiedosto ajaa Antimatterin, PostgreSQLin, tiedostovaraston ja GIF-palvelun. Sinulla tulee olla Linux-palvelin, jossa on Docker Engine ja sen Compose-liitännäinen (docker compose), kaksi CPU-ydintä ja vähintään 4 Gt muistia.

1. Lataa compose-tiedosto

mkdir antimatter && cd antimatter
curl -fsSLO https://antimatter.chat/compose.yaml

2. Luo .env-tiedosto

Compose-tiedosto lukee asetuksensa samassa hakemistossa olevasta .env-tiedostosta. Luo se satunnaisilla salaseitillä:

cat > .env <<EOF
SITE_URL=http://localhost:8065
POSTGRES_PASSWORD=$(openssl rand -hex 24)
S3_SECRET_KEY=$(openssl rand -hex 24)
GIFS_API_KEY=$(openssl rand -hex 24)
AM_AI_ENCRYPTION_KEY=$(openssl rand -base64 32)
EOF
chmod 600 .env

Aseta SITE_URL osoitteeksi, jonka ihmiset syöttävät selaimeensa, esimerkiksi http://192.168.1.20:8065 paikallisverkossa tai https://chat.example.com verkkonimellä. Säilytä .env-tiedosto: tietokanta ja varasto käyttävät näitä salasanoja ensimmäisestä käynnistyksestä lähtien, tekoälymallien yhteyksien API-avaimet salataan AM_AI_ENCRYPTION_KEY:llä, ja samaa tiedostoa tarvitaan varuksen palauttamiseen.

3. Käynnistä

docker compose up -d
docker compose ps

Ensimmäinen käynnistys kestää minuutin tai kaksi: PostgreSQL luo tietokannan, kertakäyttöinen bucket-palvelu luo varastokaukalon, kertakäyttöinen gifs-stickers-palvelu tuo aloitussetin ja Antimatter luo taulunsa. Seuraa käynnistystä komennolla docker compose logs -f antimatter.

Jos haluat käyttää verkkonimeä ja HTTPS:ää alusta alkaen, katso Verkkonimi ja HTTPS: compose-tiedostolla se vaatii vain kaksi lisäriviä .env-tiedostossa ja https-profiilin.

PostgreSQL, tallennus ja GIF-palvelu ovat sisäisessä verkossa (private) ilman Internet-yhteyttä, johon liittyy vain Antimatter. Mikään näistä ei julkaise porttia.

Antimatter-kontti ei säilytä mitään levylle: sen asetukset ovat tietokannassa (AM_CONFIG osoittaa siihen) ja sen tiedostot ja sovellukset tallennuspalvelussa. Kontti voidaan poistaa ja luoda uudelleen milloin tahansa. Sen data-levyalue sisältää vain tekoälyn salausavaintiedoston, jonka palvelin luo, kun AM_AI_ENCRYPTION_KEY on tyhjä. Kaikki, mitä on varattava, on postgres, files, gifs ja data-levyalueilla sekä .env-tiedostossasi.

Valitse kuvake

Julkaisetaan kaksi Antimatter-kuvaketta, molemmat linux/amd64- ja linux/arm64-arkkitehtuureille, ja molemmat on rakennettu jokaisen varaston main-haarakkeesta:

KuvaSisällytetyt sovelluksetTagit

Sivuston compose-tiedosto käyttää antimatter-next-kuvaketta, koska GIF-palvelu ja suurin osa täällä sivustolla kuvatuista sovelluksista ovat vain tuossa kuvakkeessa. Kuvakkeen vaihtamiseksi aseta ANTIMATTER_IMAGE .env-tiedostoon ja aja docker compose up -d.

latest-muutokset alla. Tuotantoympäristössä kiinnitä tagi, kuten nightly-20261015 tai sha-<commit>, ja muuta sitä tarkoituksella päivityksen yhteydessä. Palvelin päivittää tietokantansa käynnistyessään, joten et voi palata vanhempaan kuvaan tai siirtyä antimatter-next:stä antimatter:iin ilman varuukopion palauttamista, joka on otettu ennen päivitystä. Katso Varuuskopiot ja päivitykset.

Kuvan sisältö

  • Palvelin sijaitsee hakemistossa /antimatter, ja binääritiedostot antimatter ja amctl ovat hakemistossa /antimatter/bin (polulla PATH).
  • Se ajetaan etuoikeutettuna käyttäjänä antimatter (uid 2000) minimaalisella distroless-pohjalla, eikä siinä ole komentoriviä.
  • Portit: 8065 (web ja API), 8067 (metriikat), 8074 (klusteri), 8443 UDP ja TCP (puhelut).
  • Paikallinen tila (ServiceSettings.EnableLocalMode) on käytössä, joten amctl --local toimii kontinissa. Terveystarkistus suorittaa komennon amctl system status --local.
  • Sisällytetyt sovellukset ovat hakemistossa /antimatter/prepackaged_plugins, ja ne on allekirjoitettu Antimatter-sovellusten allekirjoitustsella.
  • Tekstin poimintatyökalut (pdftotext, wvText, unrtf, tidy) on sisällytetty, jotta lähetettyjen asiakirjojen sisältöä voidaan hakea.

Muut compose-tiedostot

antimatter-docker-varastossa on tuotantokonfiguraatio hakemistossa deploy/compose/: nginx omilla todennusnäytteilläsi tai Let's Encryptillä (certbot), PostgreSQL, valinnainen GIF-palvelu (profiili gifs) ja nimetyt volyymit palvelimen asetukset, tiedot ja lokit varten, jotka on dokumentoitu README-tiedostossa. Se käyttää oletuksena vakaa-kuvaa ja tallentaa tiedot paikalliselle volyymille S3-tallennuksen sijaan. Käytä tätä, jos偏好 nginx Caddyyn nähden tai jos sinulla on jo todennusnäytteet.

Luo ensimmäinen ylläpitäjä

Avaa SITE_URL selaimessasi ja luo tili. Uudella palvelimella luotu ensimmäinen tili tulee järjestelmän ylläpitäjäksi, ja asennusohjeistus vie sinut sitten ensimmäisen yhteisön (Antimatterin nimitys tiimille tai työtilalle) luonteen läpi.

Tee tämä heti ensimmäisen käynnistyksen jälkeen: siihen asti kuka tahansa, joka pääsee palvelimelle ensimmäisenä, tulee sen ylläpitäjäksi. Jos haluat luoda tilin komentoriviltä sen sijaan, ennen kuin palvelin on ulkoisesti tavoitettavissa:

docker compose exec antimatter amctl --local user create --system-admin --email-verified \
    --email admin@example.com --username admin --password 'a-long-password'
docker compose exec antimatter amctl --local team create --name main --display-name "Main"
docker compose exec antimatter amctl --local team users add main admin

Kirjaudu sitten sisään osoitteessa SITE_URL. Aloita komento välilyöntillä, jotta salasana ei jää shellin historiaan (kun HISTCONTROL=ignorespace), tai muuta salasana kirjautumisen jälkeen.

Seuraavat vaiheet, kun olet sisällä:

  1. Yrityksen tai järjestön tapauksessa aseta Uusien yhteisöjen tyyppi arvoksi Työpaikka ja muuta jo luodun yhteisön tyyppi sen asetuksissa: Työpaikka tai yhteisö.
  2. Päätä, kuka voi luoda tilejä: Kirjautuminen ja tilet.
  3. Määritä sähköposti, jotta kutsut ja salasanojen nollaukset toimivat: Sähköposti ja push-ilmoitukset.
  4. Avaa puhelinten portti palomuurissasi: Puhelut ja ääni.
  5. Tarkista, mitkä sovellukset ovat käytössä: Sisällytetyt sovellukset.

Lataa julkaisu

Ilman Dockeria asenna Antimatter GitHubin julkaisutiedostoista: github.com/AntimatterChat/antimatter/releases. Jokaisella julkaisulla on versionsnumero, kuten 0.9.0, ja sen tagi on sama numero v-etuliitteen kanssa (v0.9.0).

Antimatter on beetaversiossa: sen julkaisut ovat 0.9.0-sarjassa. Julkaisu, jonka versiossa on liitteenä viivasta jälkeinen lisä, kuten 0.9.0-rc.1, on merkitty GitHubissa Pre-release:ksi. Se on testiversio, joka on julkaistu ennen lopullista julkaisua.

Jokaisella julkaisulla on nämä tiedostot amd64- ja arm64-palvelimille:

TiedostoMikä se on
antimatter_<version>-1_amd64.deb, antimatter_<version>-1_arm64.debPaketti Debianille, Ubuntuille ja niille perustuville jakeluversioille.
antimatter-<version>-1.x86_64.rpm, antimatter-<version>-1.aarch64.rpmPaketti Fedoralle, RHELille ja RHEL-yhteensopiville jakeluversioille.
antimatter-<version>-linux-amd64.tar.gz, antimatter-<version>-linux-arm64.tar.gzJulkaisupaketti, joka soveltuu mihin tahansa Linux-jakeluversioon ja jonka asennus tehdään manuaalisesti.
SHA256SUMSSHA-256-tarkaussumma julkaisun kaikista tiedostoista.

Paketit ja paketti sisältävät saman ohjelman: palvelimen (antimatter), komentorakennustyökalun (amctl), molemmat verkkosovellukset (oletusliittymä ja klassinen), sisällytetyt sovellukset, sähköpostimallit ja käännökset. Paketteihin lisätään systemd-palvelu ja asetustiedosto, joten jokainen on valmis asennuspaketti: sinun tarvitsee vain lisätä PostgreSQL-tietokanta. Erillisiä binääritiedostoja ei ole: binäärit ovat pakkissa, hakemistossa antimatter/bin/. Ne ovat staattisia, joten ne toimivat minkä tahansa arkkitehtuurinsa Linux-jakeluversiossa.

Pakettien nimissä esijulkaisun version viiva muuttuu tildemerkiksi, jotta pakettihallinta järjestää esijulkaisun ennen varsinaista julkaisua: versio 0.9.0-rc.1 tuottaa paketit antimatter_0.9.0~rc.1-1_amd64.deb ja antimatter-0.9.0~rc.1-1.x86_64.rpm. Arkistossa viiva säilyy.

antimatter version tulostaa julkaisun version kenttään Rakennusnumero ja sen lähteenä käytetyn commitin kenttään Rakennusnro. Rivillä Versio näkyy Mattermost-pohjan, johon Antimatter perustuu, versio.

Tarkista lataus

Lataa tarvittava tiedosto ja SHA256SUMS-tiedosto samaan hakemistoon julkaisusivulta tai curl-komentoa käyttäen, ja tarkista sitten tiedosto:

curl -fLO https://github.com/AntimatterChat/antimatter/releases/download/v<version>/antimatter_<version>-1_amd64.deb
curl -fLO https://github.com/AntimatterChat/antimatter/releases/download/v<version>/SHA256SUMS
sha256sum --check --ignore-missing SHA256SUMS

Jokaisen lataamasi tiedoston vieressä on oltava OK. Mikä tahansa muu tulos tarkoittaa, että tiedosto on vaurioitunut tai puuttuu: lataa se uudelleen, älä asenna sitä. SHA256SUMS-tiedostoa ei ole allekirjoitettu: se havaitsee vaurioituneen latauksen, mutta ei todista enempää kuin HTTPS-lataus GitHubista.

Asenna .deb- tai .rpm-paketti

Paketti asenna Antimatterin systemd-palveluna, joka tarvitsee käynnistymiselle vain tietokannan. Käytä sitä 64-bittisellä Debian-, Ubuntu-, Fedora- tai RHEL-yhteensopivalla palvelimella, jossa on systemd.

Mikä paketti asennetaan

PolkuSisältö
/opt/antimatterOhjelma: bin/antimatter, bin/amctl, web-sovellukset (client/, client-fusion/), mukana toimitetut sovellukset (prepackaged_plugins/), mallit, käännökset ja fontit. Jokainen päivitys korvaa sen.
/etc/antimatter/antimatter.envPalvelun asetukset AM_-muuttujina: tietokanta, sivuston URL ja GIF-palvelu. Vain root-käyttäjä voi lukea sitä. Päivitykset säilyttävät sen.
/etc/antimatter/config/config.jsonAsetustiedosto, johon palvelin tallentaa Järjestelmäkonsolissa muuttamasi asetukset. Se luodaan ensimmäisen asennuksen yhteydessä polusta /opt/antimatter/defaults/config.json eikä sitä koskaan korvata sen jälkeen.
/var/lib/antimatterLähetetyt tiedostot (data/) ja asennetut sovellukset (plugins/, client-plugins/).
/var/log/antimatterLokitiedostot, jos otat tiedostolokituksen käyttöön. Se on oletusarvoisesti poissa käytöstä: lokit ohjataan journaliin.
/usr/lib/systemd/system/antimatter.servicePalvelu.
/usr/bin/amctlLyhene polkuun /opt/antimatter/bin/amctl.

Hakemistot, joihin palvelin kirjoittaa hakemistossa /opt/antimatter (config, data, plugins, client/plugins ja logs), ovat lyhenteitä hakemistoihin /etc/antimatter, /var/lib/antimatter ja /var/log/antimatter. Näin päivitys, joka korvaa hakemiston /opt/antimatter, ei koskaan kosketa tietoja. Paketti luo myös järjestelmän käyttäjän antimatter, joka ajaa palvelimen ja omistaa nämä hakemistot.

Paketti riippuu paketista ca-certificates. Se suosittelee PostgreSQL-pakettia (postgresql Debian- ja Ubuntu-jakeluissa, postgresql-server Fedorassa ja RHEL:ssä), media-types-pakettia (mailcap .rpm-paketissa) ja gifs-server-paketin, joka on GIF-palvelu ja jolla on oma julkaisunsa (ks. tässä alla). apt ja dnf asettavat suositellut paketit, jos ne löytyvät. Paketti ehdottaa paketteja poppler-utils, wv, unrtf ja tidy (ei wv:tä .rpm-paketissa): ne poimivat tekstin lähetetyistä dokumenteista, jotta haku löytää sanat niiden sisältä. Asenna ne itse, jos haluat tämän toiminnon.

1. Asenna paketit

Lataa Antimatter-paketti ja GIF-palvelun paketti arkkitehtuurillesi, tarkista ne yllä esitettyjen ohjeiden mukaan ja asenna molemmat yhdellä komennolla, jotta gifs-server-paketin suositus täyttyy (se ei ole jakelujen pakettivarastoissa):

# Debian, Ubuntu
sudo apt install ./antimatter_<version>-1_amd64.deb ./gifs-server_*_amd64.deb
# Fedora, RHEL
sudo dnf install ./antimatter-<version>-1.x86_64.rpm ./gifs-server-*.x86_64.rpm

Jätä ./ mukaan: se kertoo aptille ja dnf:lle, että asennetaan paikallinen tiedosto. Asennus ilman GIF-palvelua tehdään jättämällä sen paketti pois. Paketti ottaa antimatter-palvelun käyttöön, mutta ei käynnistä sitä, ja tulostaa seuraavat vaiheet.

2. Luo tietokanta

Antimatter vaatii PostgreSQL 15 -tietokannan tai uudemman, joko tässä palvelimessa tai toisessa. Tarkista jakelusi PostgreSQL-version komennolla psql --version. Jos versio on vanhempi, asenna uudempi versio PostgreSQL-projektin omista pakettivarastoista tai käytä tietokantaa toisessa palvelimessa. Debian- ja Ubuntu-jakeluissa postgresql-paketti käynnistää tietokannan. Fedorassa ja RHEL:ssä luo ja käynnistä se ensin:

sudo postgresql-setup --initdb
sudo systemctl enable --now postgresql

Luo sitten käyttäjä ja tietokanta Antimatteria varten:

sudo -u postgres psql -c "CREATE USER antimatter WITH PASSWORD 'a-long-password'"
sudo -u postgres psql -c "CREATE DATABASE antimatter OWNER antimatter"

PostgreSQLin on hyväksyttävä salasanasuunnat osoitteesta 127.0.0.1: pg_hba.conf-tiedoston host-rivit, joissa on scram-sha-256-menetelmä.

3. Määritä tietokanta ja sivuston osoite

Muokkaa tiedostoa /etc/antimatter/antimatter.env (sudoedit /etc/antimatter/antimatter.env). Poista #-merkki käytettyjen rivien edestä ja aseta tietokannan sekä käyttäjien avaaman osoitteen arvot:

AM_SQLSETTINGS_DRIVERNAME=postgres
AM_SQLSETTINGS_DATASOURCE=postgres://antimatter:a-long-password@localhost:5432/antimatter?sslmode=disable&connect_timeout=10
AM_SERVICESETTINGS_SITEURL=https://chat.example.com

Konfiguraation kaikki asetukset voi määrittää tässä tiedostossa muodossa AM_<SECTION>_<SETTING>: esimerkiksi SqlSettings.DataSource on AM_SQLSETTINGS_DATASOURCE. Tässä tiedostossa asetettua arvoa ei voi muuttaa Järjestelmäkonsolissa. Katso Konfiguraatio. Käynnitä palvelin uudelleen jokaisen muutoksen jälkeen: sudo systemctl restart antimatter.

Palvelu määrittää myös oletusarvoja, joita antimatter.env-tiedoston rivi voi ohittaa: lokitus tiedostoihin on poissa käytöstä (AM_LOGSETTINGS_ENABLEFILE=false, AM_NOTIFICATIONLOGSETTINGS_ENABLEFILE=false) ja paikallinen tila on käytössä (AM_SERVICESETTINGS_ENABLELOCALMODE=true), jotta amctl --local toimii palvelimella.

4. Käynnitä

sudo systemctl start antimatter
journalctl -u antimatter -f
sudo -u antimatter amctl --local system status

Ensimmäisellä käynnistyksellä palvelin luo taulunsa ja kuuntelee sitten porttia 8065. Avaa http://<server>:8065 tai verkkotunnuksesi, kun väliovien (reverse proxy) asennus on valmis (katso Verkkotunnus ja HTTPS), ja luo heti ensimmäinen tili: se tulee järjestelmän ylläpitäjäksi. Jos haluat luoda tilin komentoriviltä, käytä Ensimmäisen ylläpitäjän luominen-osion amctl-komentoja, mutta korvaa docker compose exec antimatter amctl --local komennolla sudo -u antimatter amctl --local.

5. Ota GIF:t käyttöön

GIF:t -sovellus on mukana ja käytössä, ja antimatter.env osoittaa jo GIF-palveluun samalla palvelimella (AM_GIFS_SERVICE_URL=http://127.0.0.1:8080/v2). Palvelun API-avain puuttuu vielä. gifs-server-paketti loi avaimen asennuksen yhteydessä:

sudo systemctl start gifs-server-stickers    # imports the sticker pack, about a minute and a half
sudo systemctl start gifs-server
sudo grep -v '^#' /etc/gifs-server/api-keys

Syötä avain antimatter.env-tiedostoon muodossa AM_GIFS_API_KEY=<key> ja käynnitä Antimatter uudelleen, tai syötä se API-avain-kenttään kohdassa Järjestelmäkonsoli › Liiteohjelmat › GIF:t. Jos GIF-palvelu toimii toisella palvelimella, aseta AM_GIFS_SERVICE_URL sen osoitteeksi. Jos haluat, että käyttäjät voivat lisätä omia GIF:ejä ja tarrakuvia, katso GIF:t.

Palvelu

  • Palvelu ajetaan antimatter-käyttäjänä hakemistossa /opt/antimatter ja lukee tiedoston /etc/antimatter/antimatter.env. systemd käynnistää palvelimen uudelleen, jos se päättyy, ja antaa sille tunti aikaa käynnistyä, koska uuden version tietokantamigraatiot voivat kestää kauan.
  • Palvelun lokit löytyvät journalista: journalctl -u antimatter.
  • Palvelu on turvattu: hakemistot /usr ja /etc ovat palvelimelle vain luetta, paitsi /etc/antimatter/config, ja palvelin ei näe hakemistoja /home, /root tai /run/user. Jos siirrät tiedostovaraston (FileSettings.Directory), valitse hakemisto, joka on näiden ulkopuolella ja jonka omistaja on antimatter.
  • Päivitykset korvaavat palvelutiedoston. Voit muokata sitä komennolla sudo systemctl edit antimatter, joka säilyttää muutoksesi erillisessä tiedostossa.

Päkitä paketti

  1. Ota varuuskopiota (katso Varuuskopiot ja päivitykset).
  2. Lataa uusi paketti ja SHA256SUMS-tiedosto ja tarkista ne.
  3. Sammuta palvelin, asenna uusi paketti vanhan päälle ja käynnistä se uudelleen: 
    sudo systemctl stop antimatter
sudo apt install ./antimatter_<new version>-1_amd64.deb     # or: sudo dnf install ./antimatter-<new version>-1.x86_64.rpm
sudo systemctl start antimatter
journalctl -u antimatter -f

Paketti ei käynnistä palvelinta itse. Päivityksen jälkeen se tulostaa viestin Antimatter was upgraded; restart it to run the new version: sudo systemctl restart antimatter: jos et sammuttanut palvelinta etukäteen, käynnistä se heti. Päivitys korvaa hakemiston /opt/antimatter ja palvelutiedoston, mutta säilyttää tiedostot antimatter.env, config.json, hakemiston /var/lib/antimatter ja lokit. Käynnistyessään palvelin päivittää tietokannan ja asennaa mukana toimitettujen sovellusten uudemmat versiot.

Jos uuden version oletusarvoinen antimatter.env on muuttunut, apt kysyy, haluatko säilyttää oman versiosi: säilytä se. dnf säilyttää oman versiosi ja tallentaa uuden tiedostoon /etc/antimatter/antimatter.env.rpmnew. Päivitykset tehdään vain eteenpäin: älä asenna vanhemman versiota uuden päälle.

Poista paketti

Komento sudo apt remove antimatter tai sudo dnf remove antimatter sammuttaa ja poistaa palvelun käytöstä sekä poistaa ohjelman. Se säilyttää tiedot (/var/lib/antimatter), asetukset (/etc/antimatter), tietokannan ja antimatter-käyttäjän: poista nämä itse, jos haluat poistaa Antimatterin kokonaan.

Pakettien ja arkiston sovellukset

Paketeissa ja arkistossa on näiden sovellusten uusin allekirjoitettu julkaisu hakemistossa prepackaged_plugins/: Agents, Calls, GIFs, Memes, Notes, Polls, Todo, Voice Channels ja Whiteboard. Sovellus, jolla ei ollut julkaisua palvelimen julkaisun luontiaikaan, jätetään pois: komento ls /opt/antimatter/prepackaged_plugins näyttää, mitä julkaisusi sisältää. Memes ja Todo sisältyvät, mutta eivät ole otettu käyttöön: osio Sisällytetyt sovellukset kertoo, miten ne asennetaan ja otetaan käyttöön.

Docker-kuvien muut sovellukset eivät sisälly paketteihin tai arkistoon: Kanban, Playbooks, Mail, Calendar, GitHub, GitLab, Jira ja Metrics. Asenna jokainen sovellus omasta julkaisustaan:

Jokaisella sovelluksen julkaisulla on sovelluksen paketti (.tar.gz-tiedosto), sen allekirjoitus (sama nimi, johon on lisätty .sig) sekä SHA256SUMS-tiedosto. Sovelluksen asennus vaatii, että lähetysten lähetys on sallittu, minkä jälkeen paketti lisätään komennolla amctl:

# 1. In /etc/antimatter/antimatter.env, add this line, then restart Antimatter
AM_PLUGINSETTINGS_ENABLEUPLOADS=true
sudo systemctl restart antimatter
# 2. Download the bundle where the antimatter user can read it, and install it
cd /tmp
curl -fLO https://github.com/AntimatterChat/antimatter-plugin-boards/releases/download/v<version>/<bundle>.tar.gz
sudo -u antimatter amctl --local plugin add <bundle>.tar.gz
sudo -u antimatter amctl --local plugin enable focalboard

Tällä tavalla asennetun sovelluksen päivitys tehdään lisäämällä uusi paketti komennolla plugin add --force: pakettipäivitykset päivittävät vain sisällytetyt sovellukset. Voit poistaa AM_PLUGINSETTINGS_ENABLEUPLOADS-rivin myöhemmin. Katso osio Muiden sovellusten asennus muista asennustavoista.

Sovellusten allekirjoitukset

Sovelluspaketit on allekirjoitettu Antimatterin sovellusallekirjoitustavalla: jokainen .tar.gz.sig-tiedosto on sen paketin irrotettu GPG-allekirjoitus. Palvelin tarkistaa nämä allekirjoitukset ennen sisällytetyn sovelluksen asennusta. Paketin voi tarkistaa itse näin:

curl -fsSLO https://raw.githubusercontent.com/AntimatterChat/antimatter-docker/main/keys/antimatter-plugin-signing.asc
gpg --import antimatter-plugin-signing.asc
gpg --verify <bundle>.tar.gz.sig <bundle>.tar.gz

gpg:nin on raportoitava hyväksytty allekirjoitus Antimatter Plugin Signing-avaimelta, jonka sormenjälki on 06C8 1032 4677 0F08 BBA7 78B9 E69B 05C3 92A6 9A45. Ohjelma varoittaa myös, ettei avainta ole todistettu luotettavalla allekirjoituksella: tämä on normaalia, jos et ole allekirjoittanut avainta itse. Järjestelmä, jossa ei ole .sig-tiedostoja, on allekirjoittamaton, ja sen julkaisutiedoissa näin mainitaan.

Asennus julkaisupakettista

Paketti antimatter-<version>-linux-<arch>.tar.gz (esimerkiksi antimatter-0.9.0-linux-amd64.tar.gz) sopii jakeluun, jossa ei ole .deb- tai .rpm-paketteja, tai omatekoon asennusasetukseen. Paketti sisältää yhden antimatter/-hakemiston, jossa ovat bin/antimatter, bin/amctl, config/config.json, web-sovellukset (client/ ja client-fusion/), mukana toimitetut sovellukset (prepackaged_plugins/, ks. yllä), sähköpostimallit ja käännökset.

1. PostgreSQLin valmistelu

Antimatter tukee ainoastaan PostgreSQLiä, versio 15 tai uudempi (vanhemmat versiot käynnistyvät, mutta virhe näkyy lokissa). Luo käyttäjä ja tietokanta:

sudo -u postgres psql <<'EOF'
CREATE USER antimatter WITH PASSWORD 'a-long-password';
CREATE DATABASE antimatter OWNER antimatter;
EOF

2. Pakkauksen purkaminen ja asetukset

sudo tar -xzf antimatter-<version>-linux-amd64.tar.gz -C /opt
sudo useradd --system --user-group antimatter
sudo mkdir -p /opt/antimatter/data
sudo chown -R antimatter:antimatter /opt/antimatter

Määritä palvelimen tietokanta joko tiedostossa /opt/antimatter/config/config.json (SqlSettings.DataSource) tai ympäristömuuttujilla, ja aseta sivuston URL-osoite:

AM_SQLSETTINGS_DRIVERNAME=postgres
AM_SQLSETTINGS_DATASOURCE=postgres://antimatter:a-long-password@localhost:5432/antimatter?sslmode=disable&connect_timeout=10
AM_SERVICESETTINGS_SITEURL=https://chat.example.com

Paketin config.json on täydellinen oletusasetustiedosto: Järjestelmäkonsolissa muuttamasi asetukset tallennetaan takaisin tähän tiedostoon. Jos haluat pitää asetukset tietokannassa, katso Asetukset.

3. Käynnistys palveluna

systemd-yksikkö tiedostossa /etc/systemd/system/antimatter.service:

[Unit]
Description=Antimatter
After=network.target postgresql.service

[Service]
Type=notify
User=antimatter
Group=antimatter
WorkingDirectory=/opt/antimatter
ExecStart=/opt/antimatter/bin/antimatter
EnvironmentFile=-/etc/antimatter.env
TimeoutStartSec=3600
Restart=always
RestartSec=10
LimitNOFILE=49152

[Install]
WantedBy=multi-user.target

Aseta AM_-ympäristömuuttujat tiedostoon /etc/antimatter.env (luettavissa vain root-käyttäjälle), sitten:

sudo systemctl daemon-reload
sudo systemctl enable --now antimatter
journalctl -u antimatter -f

Palvelin kuuntelee porttia 8065. Avaa http://<server>:8065 tai oma verkkotunnuksesi, kun väliovettimeen on asennettu (ks. Verkkotunnus ja HTTPS), ja luo ensimmäinen tili: siitä tulee järjestelmän ylläpitäjä.

bin/amctl hallinnoi käynnissä olevaa palvelinta komentoriviltä. Palvelimella se toimii ilman kirjautumista paikallisessa tilassa: aseta AM_SERVICESETTINGS_ENABLELOCALMODE=true ja aja sudo -u antimatter /opt/antimatter/bin/amctl --local system status.

GIF-tiedostojen osalta asenna GIF-palvelu (katso alla) ja määritä AM_GIFS_SERVICE_URL ja AM_GIFS_API_KEY samalla tavalla kuin pakettien vaiheessa 5.

GIF-palvelun ja push-välityspalvelimen paketit

GIF-palvelu ja push-välityspalvelin julkaisivat omat versiot samoin säännöin kuin palvelin: .tar.gz-arkisto, .deb- ja .rpm-paketti amd64- ja arm64-arkkitehtuureille sekä SHA256SUMS-tiedosto. Versiot, joissa on väliviiva, ovat esijulkaisuja. Tarkista lataukset komennolla sha256sum --check --ignore-missing SHA256SUMS samalla tavalla kuin palvelimen osalta.

GIF-palvelu (gifs-server)

Julkaisut: github.com/AntimatterChat/gifs-server/releases. Arkiston nimi on gifs-server-<version>-linux-<arch>.tar.gz ja pakettien nimi gifs-server.

sudo apt install ./gifs-server_*_amd64.deb      # Debian, Ubuntu
sudo dnf install ./gifs-server-*.x86_64.rpm     # Fedora, RHEL

Paketti asettaa:

  • /usr/bin/gifs-server-ohjelman ja gifs-server-palvelun, joka ajetaan gifs-server-käyttäjänä ja ylläpitää kataloogiaan hakemistossa /var/lib/gifs-server;
  • gifs-server-stickers-palvelun, joka tuottaa tai päivittää /usr/share/gifs-server/stickers-hakemistossa olevan tarrapaketin käynnistyessään ja pysähtyy sen jälkeen;
  • asetustensa, /etc/gifs-server/gifs-server.env (AM_GIFS_-muuttujat, jotka säilyvät päivitysten aikana) ja /etc/gifs-server/api-keys, jossa on yksi API-avain per rivi ja jossa ensimmäisellä asennuksella luodaan satunnainen avain.

Palvelu kuuntelee osoitteessa 127.0.0.1:8080, joten vain samalla palvelimella oleva Antimatter voi käyttää sitä. Jos Antimatter ajetaan jossain muualla, määritä AM_GIFS_LISTEN=:8080 tiedostoon gifs-server.env ja rajaa porttiin pääsy palomuurillasi. Tiedostossa luetellaan myös muut asetukset: AM_GIFS_UPLOAD_KEYS (avaimet, joilla GIF- ja tarratiedostoja voi lisätä ja niillä lisätyt poistaa), AM_GIFS_PUBLIC_URL, AM_GIFS_TRUST_PROXY ja AM_GIFS_LOG_LEVEL. Paketti suosittelee ffmpeg:ää, gifsicle:ää, librsvg2-bin:iä (librsvg2-tools .rpm-paketille) ja DejaVu-fonttia: palvelu käyttää näitä GIF-, video- ja tarratiedostomuotojen luomiseen, kun se tuottaa tai vastaanottaa tiedostoja, ja toimii ilman niitä.

Kuten palvelin, palvelu on asennuksen jälkeen käytössä, mutta se ei ole käynnistetty. Käynnistä se pakettien vaiheessa 5 esitetyn mukaisesti. Päivityksen jälkeen käynnistä se uudelleen: sudo systemctl restart gifs-server. Pakettia poistettaessa katalogi säilyy hakemistossa /var/lib/gifs-server.

Push-välityspalvelin

Julkaisut: github.com/AntimatterChat/push-proxy/releases. Paketti on nimeltään antimatter-push-proxy-<version>-linux-<arch>.tar.gz; paketin nimi on antimatter-push-proxy. Paketti asentaa ohjelman /usr/bin/antimatter-push-proxy ja palvelun antimatter-push-proxy, joka ajetaan käyttäjänä antimatter-push-proxy ja lukee tiedoston /etc/antimatter-push-proxy/antimatter-push-proxy.json (säilyy päivityksissä). Appletin ja Firebase-tunnukset sijoitetaan hakemistoon /etc/antimatter-push-proxy/certs: Push-ilmoitukset -osiossa kerrotaan, mistä ne tulevat.

sudo apt install ./antimatter-push-proxy_*_amd64.deb      # or: sudo dnf install ./antimatter-push-proxy-*.x86_64.rpm
sudo install -o root -g antimatter-push-proxy -m 0640 \
    AuthKey_ABCDE12345.p8 firebase-service-account.json /etc/antimatter-push-proxy/certs/
sudoedit /etc/antimatter-push-proxy/antimatter-push-proxy.json
sudo systemctl start antimatter-push-proxy
journalctl -u antimatter-push-proxy -f

Asetustiedostossa polut ovat suhteellisia hakemistoon /etc/antimatter-push-proxy: esimerkiksi "AppleAuthKeyFile": "./certs/AuthKey_ABCDE12345.p8" ja "ServiceFileLocation": "./certs/firebase-service-account.json". Määritä sitten Antimatterissa Push-ilmoituspalvelin osoitteeksi http://<proxy host>:8066. Päivityksen jälkeen käynnistä se uudelleen: sudo systemctl restart antimatter-push-proxy.

Push-välityspalvelin kuuntelee porttia 8066 kaikilla osoitteilla eikä tarkista, kuka sitä kutsuu. Pidä portti yksityisessä verkossa tai sen takana olevan reverse proxy -palvelimen takana, joka rajoittaa pääsyn.
