Asennus Docker Compose -ohjelmalla

Tämä on suositeltu tapa. Yksi compose-tiedosto ajaa Antimatterin, PostgreSQLin, tiedostovaraston ja GIF-palvelun. Tarvitaan Linux-palvelin, jossa on Docker Engine ja sen Compose-liitännäinen (docker compose), kaksi suoritinydintä ja vähintään 4 Gt muistia.

1. Lataa compose-tiedosto

mkdir antimatter && cd antimatter
curl -fsSLO https://antimatter.chat/compose.yaml

2. Luo .env-tiedosto

Compose-tiedosto lukee asetukset samassa hakemistossa olevasta .env-tiedostosta. Luo se satunnaisilla salaseitillä:

cat > .env <<EOF
SITE_URL=http://localhost:8065
POSTGRES_PASSWORD=$(openssl rand -hex 24)
S3_SECRET_KEY=$(openssl rand -hex 24)
GIFS_API_KEY=$(openssl rand -hex 24)
EOF
chmod 600 .env

Aseta SITE_URL osoitteeksi, jonka ihmiset syöttävät selaimeensa, esimerkiksi http://192.168.1.20:8065 paikallisverkossa tai https://chat.example.com verkkonimellä. Säilytä .env-tiedosto: tietokanta ja varasto käyttävät näitä salasanoja ensimmäisestä käynnistyksestä lähtien, ja samaa tiedostoa tarvitaan varuksen palauttamiseen.

3. Käynnistä

docker compose up -d
docker compose ps

Ensimmäinen käynnistys kestää minuutin tai kaksi: PostgreSQL luo tietokannan, kertakäyttöinen bucket-palvelu luo varastokaukalin, kertakäyttöinen gifs-stickers-palvelu tuomaa alkuperäisen tarrapaketin ja Antimatter luo taulunsa. Seuraa käynnistystä komennolla docker compose logs -f antimatter.

Jos haluat käyttää verkkonimeä ja HTTPS:ää alusta alkaen, katso Verkkonimi ja HTTPS: compose-tiedostolla se vaatii vain kaksi lisäriviä .env-tiedostossa ja https-profiilin.

PostgreSQL, tallennus ja GIF-palvelu ovat sisäisellä verkolla (private), jolla ei ole Internet-yhteyttä. Vain Antimatter liittyy tähän verkkoon. Mikään näistä ei julkista porttia.

Antimatter-kontineri ei säilytä mitään levylle: sen asetukset ovat tietokannassa (AM_CONFIG osoittaa siihen) ja sen tiedostot ja sovellukset tallennuspalvelussa. Kontinerin voi poistaa ja luoda uudelleen milloin tahansa. Kaikki, mitä on varattava, on postgres, files ja gifs -volyymeissa sekä .env-tiedostossasi.

Valitse kuva

Julkaisetaan kaksi Antimatter-kuvaa, molemmat linux/amd64- ja linux/arm64-arkkitehtuureille, ja molemmat on rakennettu jokaisen varaston main-haarasta:

KuvaSisällytetyt sovelluksetTagit
ghcr.io/antimatterchat/antimatterAgentit, Puhelut, GitHub, GitLab, Jira, Kanban, Metriikat ja Ohjekirjat.latest, X.Y.Z julkaisuille, sha-<commit>
ghcr.io/antimatterchat/antimatter-nextSama, lisäksi Äänikanavat, Kyselyt, Sähköposti, Kalenteri, Muistiinpanot, Valkotaulu, GIFit, Tehtävälistat ja Memet. Rakennetaan uudelleen joka yö.latest, nightly, nightly-<YYYYMMDD>, sha-<commit>

Sivuston compose-tiedosto käyttää antimatter-next-kuvaa, koska GIF-palvelu ja suurin osa tässä sivustossa kuvatuista sovelluksista ovat vain tuossa kuvassa. Muuta kuvaa asettamalla ANTIMATTER_IMAGE .env-tiedostoon ja aja docker compose up -d.

latest muuttuu jalkojesi alla. Tuotannossa kiinnitä tagi, kuten nightly-20261015 tai sha-<commit>, ja muuta sitä tarkoituksella päivityksen yhteydessä. Palvelin päivittää tietokantansa käynnistyessään, joten et voi palata vanhempaan kuvaan, tai siirtyä antimatter-next:stä antimatter:iin, ilman varmuuskopiota, joka on otettu ennen päivitystä. Katso Varmuuskopiot ja päivitykset.

Kuvan sisällä

  • Palvelin sijaitsee hakemistossa /antimatter, ja binääritiedostot antimatter ja amctl ovat hakemistossa /antimatter/bin (polulla PATH).
  • Se ajetaan etuoikeutettuna käyttäjänä antimatter (uid 2000) minimaalisella distroless-pohjalla, ilman komentoriviä.
  • Portit: 8065 (web ja API), 8067 (metriikat), 8074 (klusteri), 8443 UDP ja TCP (puhelut).
  • Paikallinen tila (ServiceSettings.EnableLocalMode) on käytössä, joten amctl --local toimii kontin sisällä. Terveystarkistus suorittaa komennon amctl system status --local.
  • Sisällytetyt sovellukset sijaitsevät hakemistossa /antimatter/prepackaged_plugins ja ne on allekirjoitettu Antimatter-sovellusten allekirjoitustsella.
  • Tekstin poimintatyökalut (pdftotext, wvText, unrtf, tidy) ovat mukana, jotta lähetettyjen dokumenttien sisältöä voidaan hakea.

Muut compose-tiedostot

Repositoriosta antimatter-docker löytyy tuotantoympäristön asennus hakemistosta deploy/compose/: nginx omilla todennusnäytöilläsi tai Let's Encryptin (certbot) avulla, PostgreSQL, valinnainen GIF-palvelu (profiili gifs) sekä nimetyt tilavuot palvelimen asetusten, tietojen ja lokien tallennusta varten. Asennus on dokumentoitu repositorion README-tiedostossa. Se käyttää oletuksena vakaa-kuvaa ja tallentaa tiedot paikalliselle tilavuolle S3-tallennuksen sijaan. Käytä tätä, jos suositu nginxin Caddyyn verrattuna tai jos sinulla on jo todennusnäytöt.

Luo ensimmäinen ylläpitäjä

Avaa SITE_URL selaimessasi ja luo tili. Uudella palvelimella luotu ensimmäinen tili saa järjestelmän ylläpitäjän oikeudet, ja asennusohjeistus vie sinut sitten ensimmäisen yhteisön (Antimatterin nimitys tiimille tai työtilalle) luonteen läpi.

Tee tämä heti ensimmäisen käynnistyksen jälkeen: siihen asti kuka tahansa, joka pääsee palvelimelle ensimmäisenä, sen ylläpitäjä. Jos haluat luoda tilin komentoriviltä, tee se ennen kuin palvelin on ulkoisesti tavoitettavissa:

docker compose exec antimatter amctl --local user create --system-admin --email-verified \
    --email admin@example.com --username admin --password 'a-long-password'
docker compose exec antimatter amctl --local team create --name main --display-name "Main"
docker compose exec antimatter amctl --local team users add main admin

Kirjaudu sitten sisään osoitteessa SITE_URL. Aloita komento välilyönnillä, jotta salasana ei jää shell-historiaasi (kun HISTCONTROL=ignorespace on asetettu), tai muuta salasana kirjautumisen jälkeen.

Seuraavat vaiheet, kun olet sisällä:

  1. Päätä, ketkä voivat luoda tilejä: Kirjautuminen ja tilet.
  2. Määritä sähköposti, jotta kutsut ja salasanojen nollaukset toimivat: Sähköposti ja push-ilmoitukset.
  3. Avaa puhelinten portti palomuurissasi: Puhelut ja ääni.
  4. Tarkista, mitkä sovellukset ovat käytössä: Sisällytetyt sovellukset.

Asennus julkaisupakista

Ilman Dockeria palvelin ajetaan arkistosta, jonka nimi on antimatter-<os>-<arch>.tar.gz (esimerkiksi antimatter-linux-amd64.tar.gz). Se sisältää yhden antimatter/ -hakemiston, jossa ovat bin/antimatter, bin/amctl, config/config.json, web-sovellukset (client/ ja client-fusion/), sähköpostimallit ja käännökset.

1. Valmistele PostgreSQL

Antimatter tukee vain PostgreSQLiä, versio 15 tai uudempi (vanhemmat versiot käynnistyvät, mutta virhe näkyy lokissa). Luo käyttäjä ja tietokanta:

sudo -u postgres psql <<'EOF'
CREATE USER antimatter WITH PASSWORD 'a-long-password';
CREATE DATABASE antimatter OWNER antimatter;
EOF

2. Pakkaa ja määritä

sudo tar -xzf antimatter-linux-amd64.tar.gz -C /opt
sudo useradd --system --user-group antimatter
sudo mkdir -p /opt/antimatter/data
sudo chown -R antimatter:antimatter /opt/antimatter

Osoita palvelin tietokantaan joko tiedostossa /opt/antimatter/config/config.json (SqlSettings.DataSource) tai ympäristömuuttujilla, ja aseta sivuston URL-osoite:

AM_SQLSETTINGS_DRIVERNAME=postgres
AM_SQLSETTINGS_DATASOURCE=postgres://antimatter:a-long-password@localhost:5432/antimatter?sslmode=disable&connect_timeout=10
AM_SERVICESETTINGS_SITEURL=https://chat.example.com

Arkiston config.json on täydellinen oletusasetustiedosto: Järjestelmäkonsolissa tekemäsi muutokset tallennetaan siihen. Jos haluat pitää asetukset tietokannassa, katso Asetukset.

3. Aja palveluna

systemd-yksikkö, tiedostossa /etc/systemd/system/antimatter.service:

[Unit]
Description=Antimatter
After=network.target postgresql.service

[Service]
Type=notify
User=antimatter
Group=antimatter
WorkingDirectory=/opt/antimatter
ExecStart=/opt/antimatter/bin/antimatter
EnvironmentFile=-/etc/antimatter.env
TimeoutStartSec=3600
Restart=always
RestartSec=10
LimitNOFILE=49152

[Install]
WantedBy=multi-user.target

Aseta AM_ -ympäristömuuttujat tiedostoon /etc/antimatter.env (luettavissa vain root-käyttäjälle), sitten:

sudo systemctl daemon-reload
sudo systemctl enable --now antimatter
journalctl -u antimatter -f

Palvelin kuuntelee porttia 8065. Avaa http://<server>:8065 tai verkkotunnuksesi, kun välityspalvelin on asennettu (katso Verkkotunnus ja HTTPS), ja luo ensimmäinen tili: se tulee järjestelmän ylläpitäjäksi.

bin/amctl hallitsee käynnissä olevaa palvelinta komentoriviltä. Palvelimella se toimii ilman kirjautumista paikallisessa tilassa: aseta AM_SERVICESETTINGS_ENABLELOCALMODE=true ja aja sudo -u antimatter /opt/antimatter/bin/amctl --local system status.
