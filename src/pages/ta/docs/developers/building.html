உங்களுக்குத் தேவையானவை

  • Go, server/go.mod-ல் உள்ள பதிப்பில் (எழுதும் நேரத்தில் 1.26.7).
  • Node.js மற்றும் npm, .nvmrc மற்றும் webapp/package.json-ல் உள்ள பதிப்புகளில் (Node 24.11.1 மற்றும் npm 11.6.2). mise மூலம், repozitory-யின் mise.toml சரியான Node-ஐ நிறுவும்.
  • Docker Compose உடன்: வளர்ச்சி அமைப்பு PostgreSQL மற்றும் சில பிற சேவைகளை கண்டெய்னர்களில் இயக்குகிறது.
  • make, git, மற்றும் Linux அல்லது macOS இயந்திரம்.
  • நினைவகம்: வலை இடைமுகங்களை உருவாக்குவது மிகவும் கடினமான பகுதி. 16 GB RAM-க்கு திட்டமிடுங்கள்; உருவாக்கம் மற்றும் நினைவகம் பகுதியைப் பார்க்கவும்.
git clone https://github.com/AntimatterChat/antimatter.git
cd antimatter

Repozitory சர்வரை server/-ல், வலை இடைமுகங்களை webapp/-ல் (Fusion webapp/fusion-ல், கிளாசிக் webapp/channels-ல், பகிர்வு தொகுப்புகள் webapp/platform-ல்), மற்றும் முழு-முனை சோதனைகளை e2e-tests/-ல் கொண்டுள்ளது.

ஒரு வளர்ச்சி சர்வரை இயக்குதல்

cd server
make run

make run வளர்ச்சி கண்டெய்னர்களை (PostgreSQL, Redis, மின்னஞ்சல் பிடிப்பான் மற்றும் கண்காணிப்பு கருவிகள்) தொடங்குகிறது, வலை ஆப் உருவாக்கங்களை இடத்தில் இணைக்கிறது, go run மூலம் சர்வரை பின்னணியில் இயக்குகிறது, மற்றும் வலை ஆப்-ன் வாட்சரை (watcher) இயக்குகிறது, இது நீங்கள் திருத்தும்போது கிளாசிக் இடைமுகத்தை மறுஉருவாக்குகிறது. http://localhost:8065-ஐ திறந்து ஒரு கணக்கை உருவாக்குங்கள்: முதல் கணக்கு அமைப்பு நிர்வாகியாக (system admin) மாறும்.

கட்டளை (server/-ல்)இது என்ன செய்கிறது
make run-server, make run-clientசர்வரை மட்டும், அல்லது வலை ஆப் வாட்சரை மட்டும் இயக்குங்கள்.
make restart-serverGo குறியீட்டை மாற்றிய பிறகு சர்வரை மறுதொடக்கம் செய்யுங்கள்.
make stopசர்வரை, வாட்சரை மற்றும் கண்டெய்னர்களை நிறுத்துங்கள்.
make debug-serverDelve டிப்யூகரின் கீழ் சர்வரை இயக்குங்கள்.
make run-cli ARGS="-version"ஒரு சர்வர் கட்டளையை இயக்குங்கள்.
make config-resetconfig/config.json-ஐ இயல்புநிலைக்கு (defaults) மீட்டமைக்கவும்.
make clean, make nukeஉருவாக்கக் கோப்புகளை அழிக்கவும்; nuke வளர்ச்சி தரவுகளையும் அழிக்கும்.

வளர்ச்சி தரவுத்தளம் postgres://mmuser:mostest_password@localhost/mattermost_test, இது சர்வரின் இயல்புநிலை தரவு மூலம். ENABLED_DOCKER_SERVICES மூலம் எந்த கண்டெய்னர்கள் தொடங்க வேண்டும் என்பதைத் தேர்ந்தெடுக்கவும், server/config.override.mk கோப்பில் அல்லது உங்கள் சூழலில் (environment) (பார்க்க server/config.mk).

வலை இடைமுகங்கள்

webapp/-ல்:

npm install      # also builds the shared packages
npm run build    # the classic interface, then Fusion

பிளட்ஸ் webapp/channels/dist (கிளாசிக்) மற்றும் webapp/fusion/dist (Fusion) இல் இடம்பெறுகின்றன. server/ இல் make client இயக்கினால், அவை server/client மற்றும் server/client-fusion என இணைக்கப்படுகின்றன; சர்வர் அவற்றை வழங்குகிறது: கிளாசிக் /static/ கீழ், Fusion /static/fusion/ கீழ்.

  • npm run run (அல்லது webapp/ இல் make run) கிளாசிக் இன்டர்ஃபேஸை கண்காணித்து மறுபிளட் செய்யும். Fusion-ஐயும் மறுபிளட் செய்ய WATCH_FUSION=true சேர்க்கவும்.
  • npm run dev-server (make dev) webpack-இன் டெவலப்மெண்ட் சர்வரை இயக்குகிறது: கிளாசிக் 9005 போர்ட்டில், Fusion 9006 போர்ட்டில்.
  • பிரவுசரில் ஒரு இன்டர்ஃபேஸை அல்லது மற்றொன்றைப் பார்க்க, எந்தப் பக்கத்தின் முகவரியிலும் ?webui=fusion அல்லது ?webui=classic சேர்க்கவும்.

தெஸ்ட்கள் மற்றும் சோதனைகள்

கட்டளைஇடம்இது என்ன செய்கிறது
make test-serverserver/டெவலப்மெண்ட் கண்டெய்னர்களுக்கு எதிரான சர்வரின் தெஸ்ட் சூட். இது நீண்ட நேரம் எடுக்கும்.
make test-server-quickserver/குறுகிய தெஸ்ட்கள் மட்டும்.
go test ./channels/app/... -run TestNameserver/ஒரு பாகேஜ் அல்லது தெஸ்ட், கண்டெய்னர்கள் இயங்கும் நிலையில் (make start-docker).
make check-styleserver/go vet, golangci-lint மற்றும் மற்ற Go சோதனைகள்.
make testwebapp/வெப் ஆப்-இன் யூனிட் தெஸ்ட்கள் (Jest), ஒவ்வொரு பாகேஜிலும்.

make i18n-extractserver/ மற்றும் webapp/நீங்கள் சரிகளைச் சேர்த்து அல்லது மாற்றிய பிறகு ஆங்கில சரிக்குறிப்பு கோப்புகளை புதுப்பிக்கிறது (காண்க மொழிபெயர்ப்புகள்).

server/ இல் go mod tidy ஐ விட make modules-tidy ஐ இயக்குங்கள்.

ரிளீஸ் ஆர்கைவ்கள்

cd webapp && npm run build && cd ..
cd server
make build-linux       # the antimatter and amctl binaries
make package-linux     # dist/antimatter-linux-amd64.tar.gz and -arm64

make build வெப் இன்டர்ஃபேஸ்களையும் லினக்ஸ் பைனரிகளையும் ஒரே நேரத்தில் பிளட் செய்கிறது. ஆர்கைவில் bin/antimatter, bin/amctl, டிஃபால்ட் config/config.json, இரண்டு வெப் இன்டர்ஃபேஸ்கள், டெம்பிளேட்கள், ஃபாண்டுகள் மற்றும் மொழிபெயர்ப்புகள் உள்ளன. மற்ற பிளாட்ஃபார்ம்கள்: make package-osx, make package-windows, make package-freebsd. ஆர்கைவ்களில் பண்டிள் ஆப்ஸ் இல்லை; Docker இமேஜில் உள்ளன.

Docker இமேஜ்

antimatter-docker ரிபாசிட்டரி வெளியிடப்பட்ட இமேஜ்களை, அதன் ஆப்ஸுடன் சர்வரை, முழுக்க முழுக்க Docker-இல் பிளட் செய்கிறது:

git clone https://github.com/AntimatterChat/antimatter-docker.git
cd antimatter-docker
scripts/build-all.sh                     # from the main branches on GitHub
SOURCES=local scripts/build-all.sh       # from your checkouts next to this folder
VARIANT=next scripts/build-all.sh        # the "next" image, with every Antimatter app

இதற்கு buildx உடன் Docker, Python 3, git, gpg, சுமார் 16 GB RAM மற்றும் 30 GB டிஸ்க் தேவை. முடிவு ghcr.io/antimatterchat/antimatter:dev என லோட் செய்யப்படுகிறது; ANTIMATTER_IMAGE=ghcr.io/antimatterchat/antimatter:dev docker compose -f compose.local.yml up -d மூலம் முயற்சிக்கவும். plugins.json பாகேஜ்களையும் பதிப்புகளையும் பட்டியலிடுகிறது, ரிபாசிட்டரியின் README விளக்கங்கள் மாறுபாடுகளை விளக்குகிறது.

build-all.sh Antimatter சைனிங் கீயால் பட்டியில் சேர்க்கப்பட்ட செயல்களை சைன் செய்கிறது, மேலும் இமேஜ் பிளட் அசைன் சைன் செய்யப்படாத செயல்களை நிராகரிக்கிறது. அதன் தனியார் கீயை (private key) நிரவாகிகள் மட்டுமே வைத்திருப்பதால், முதல் படிகளை மட்டும் தனித்தனியாக இயக்குங்கள்: scripts/fetch-sources.sh, scripts/build-plugins.sh (out/plugins/ இல் செயல் பட்டிகள்) மற்றும் scripts/build-server.sh (out/server/ இல் சர்வர் ஆர்கைவ்கள்).

பிளட் மற்றும் நினைவகம்

வெப் இன்டர்ஃபேஸ்கள் பெரிய webpack பிள்ட்கள்; நினைவகம் தீர்மானமாகும் (running out of memory) என்பது மிகவும் பொதுவான பிளட் தோல்வி.

  • npm run build கிளாசிக் இன்டர்ஃபேஸை முதலில், பின்னர் Fusion-ஐ தனித்தனியாக (ஒன்றாக இல்லாமல்) பிளட் செய்கிறது, உச்ச மதிப்பை (peak) குறைவாக வைத்திருக்க. நீங்களும் அவற்றை இணை (parallel) இயக்க வேண்டாம்.
  • மினிஃபையர் (minifier) ஒவ்வொரு புரோசஸருக்கும் ஒரு வேர்கரை (worker) தொடங்குகிறது. அதிக கோர்ஸ் (cores) கொண்ட ஆனால் குறைந்த நினைவகம் கொண்ட மெஷினில், பிளட் பார்க்கும் புரோசஸர்களைக் கட்டுப்படுத்தவும்: taskset -c 0-5 npm run build.
  • Node-க்கு ஹீப் (heap) நினைவகம் தீர்மானமாகும்போது, அதன் எல்லை (limit) ஐ உயர்த்தவும்: NODE_OPTIONS=--max-old-space-size=6144. Docker பிளட் இந்த மதிப்பைப் பயன்படுத்துகிறது (build.env இல் BUILD_NODE_OPTIONS).
  • சிறிய மெஷினில், சர்வரின் முழு டெஸ்ட் சூட், ஒரு வெப் பிளட் மற்றும் ஒரு Docker பிளட் ஆகியவற்றை ஒரே நேரத்தில் இயக்குவதைத் தவிர்க்கவும்.

பிரயோகங்கள்

ஒவ்வொரு செயலுக்கும் (plugin) தனி ரிபாசிட்டரி (repository) மற்றும் Makefile உண்டு; make dist அதன் பட்டியை (bundle) பிளட் செய்க. பிளட், நிறுவல் மற்றும் டிபகிங் பற்றி பார்க்கவும்.

டெஸ்க்டாப் செயல்

டெஸ்க்டாப் செயல் ஒரு Electron செயல். Node.js 24 அல்லது அதற்குப் பின்னான பதிப்புகளுடன்:

npm install --allow-git=all
npm run build          # development build, into dist/
npm start              # run it
npm run package:linux  # packages into release/ (also package:windows, package:mac)

பிளட் நேர அமைப்புகள் (build-time settings), முன்-அமைக்க (preconfigure) வேண்டிய சர்வர்கள் போன்றவை, src/common/config/buildConfig.ts இல் உள்ளன.

மொபைல் செயல்

மொபைல் செயல் ஒரு React Native செயல்; அதன் README-ல் கட்டளைகள் (npm run ios, npm run android) பட்டியலிடப்பட்டுள்ளன. உங்கள் சொந்த நகல் (copy) ஐ பிளட் செய்ய, உங்கள் சொந்த சைனிங் கீஸ், Android அறிவிப்புகளுக்கான Firebase திட்டம், iOS-க்கான APNs கீ, மற்றும் அந்த அங்கீகாரங்களை (credentials) வைத்திருக்கும் push proxy ஆகியவை தேவை.
