உங்களுக்குத் தேவையானவை

  • Go, server/go.mod-ல் உள்ள பதிப்பில் (எழுதும் நேரத்தில் 1.26.7).
  • Node.js மற்றும் npm, .nvmrc மற்றும் webapp/package.json-ல் உள்ள பதிப்புகளில் (Node 24.11.1, npm 11.6.2 உடன்). mise மூலம், repozitory-யின் mise.toml சரியான Node-ஐ நிறுவும்.
  • Docker Compose உடன்: வளர்ச்சி அமைப்பு PostgreSQL மற்றும் சில பிற சேவைகளை கண்டெய்னர்களில் இயக்குகிறது.
  • make, git, மற்றும் ஒரு Linux அல்லது macOS இயந்திரம்.
  • நினைவகம்: வலை இடைமுகங்களை உருவாக்குவது மிகவும் கடினமான பகுதி. 16 GB RAM-க்கு திட்டமிடுங்கள்; உருவாக்கங்கள் மற்றும் நினைவகம் பகுதியைப் பாருங்கள்.
git clone https://github.com/AntimatterChat/antimatter.git
cd antimatter

Repozitory சர்வரை server/-ல், வலை இடைமுகங்களை webapp/-ல் (Fusion webapp/fusion-ல், கிளாசிக் webapp/channels-ல், பகிரப்பட்ட தொகுப்புகள் webapp/platform-ல்), மற்றும் முழு-முனை சோதனைகளை e2e-tests/-ல் கொண்டுள்ளது.

ஒரு வளர்ச்சி சர்வரை இயக்கு

cd server
make run

make run வளர்ச்சி கண்டெய்னர்களை (PostgreSQL, Redis, மின்னஞ்சல் பிடிப்பான் மற்றும் கண்காணிப்பு கருவிகள்) தொடங்குகிறது, வலை ஆப் உருவாக்கங்களை இடத்தில் இணைக்கிறது, go run மூலம் சர்வரை பின்னணியில் இயக்குகிறது, மற்றும் வலை ஆப்பின் கண்காணிப்பானை (watcher) இயக்குகிறது, இது நீங்கள் திருத்தும்போது கிளாசிக் இடைமுகத்தை மறுஉருவாக்குகிறது. http://localhost:8065-ஐ திறந்து ஒரு கணக்கை உருவாக்குங்கள்: முதல் கணக்கு அமைப்பு நிர்வாகியாக (system admin) மாறும்.

கட்டளை (server/-ல்)இது என்ன செய்கிறது
make run-server, make run-clientசர்வரை மட்டும் அல்லது வலை ஆப் கண்காணிப்பானை மட்டும் இயக்கு.
make restart-serverGo குறியீட்டை மாற்றிய பிறகு சர்வரை மறுதொடங்கு.
make stopசர்வரை, கண்காணிப்பானையும், கண்டெய்னர்களையும் நிறுத்து.
make debug-serverDelve டிப்யூகரில் சர்வரை இயக்கு.
make run-cli ARGS="-version"ஒரு சர்வர் கட்டளையை இயக்கு.
make config-resetconfig/config.json-ஐ இயல்புநிலைக்கு (defaults) மீட்டமை.
make clean, make nukeஉருவாக்கக் கோப்புகளை அழி; nuke வளர்ச்சி தரவுகளையும் அழிக்கும்.

வளர்ச்சி தரவுத்தளம் postgres://mmuser:mostest_password@localhost/mattermost_test, சர்வரின் இயல்புநிலை தரவு ஆதாரம். server/config.override.mk கோப்பில் அல்லது உங்கள் சூழலில் ENABLED_DOCKER_SERVICES மூலம் எந்த கண்டெய்னர்கள் தொடங்க வேண்டும் என்பதைத் தேர்ந்தெடுக்கவும் (server/config.mk-ஐப் பாருங்கள்).

வலை இடைமுகங்கள்

webapp/-ல்:

npm install      # also builds the shared packages
npm run build    # the classic interface, then Fusion

பிளட்ஸ் webapp/channels/dist (கிளாசிக்) மற்றும் webapp/fusion/dist (Fusion) இல் சேமிக்கப்படும். server/ இல் make client இயக்கினால், அவை server/client மற்றும் server/client-fusion ஆக இணைக்கப்படுகின்றன; சர்வர் அவற்றை வழங்குகிறது: கிளாசிக் /static/ கீழ், Fusion /static/fusion/ கீழ்.

  • npm run run (அல்லது webapp/ இல் make run) கிளாசிக் இன்டர்ஃபேஸை கண்காணித்து மறுபிளட் செய்கிறது. Fusion-ஐயும் மறுபிளட் செய்ய WATCH_FUSION=true சேர்க்கவும்.
  • npm run dev-server (make dev) webpack-இன் டெவலப்மெண்ட் சர்வரை இயக்குகிறது: கிளாசிக் 9005 போர்ட்டில், Fusion 9006 போர்ட்டில்.
  • பிரவுசரில் ஒரு இன்டர்ஃபேஸை மட்டும் காண, எந்தப் பக்கத்தின் முகவரியிலும் ?webui=fusion அல்லது ?webui=classic சேர்க்கவும்.

தெஸ்ட்கள் மற்றும் சோதனைகள்

கட்டளைஇடம்இது என்ன செய்கிறது
make test-serverserver/டெவலப்மெண்ட் கண்டெய்னர்களுக்கு எதிரான சர்வரின் தெஸ்ட் சூட். இது நீண்ட நேரம் எடுக்கும்.
make test-server-quickserver/குறுகிய தெஸ்ட்கள் மட்டும்.

make check-styleserver/go vet, golangci-lint மற்றும் மற்ற Go சோதனைகள்.
make testwebapp/வெப் ஆப்-இன் யூனிட் தெஸ்ட்கள் (Jest), ஒவ்வொரு பாகேஜிலும்.

server/ இல் go mod tidy ஐ விட make modules-tidy ஐ இயக்குங்கள்.

ரிளீஸ் ஆர்கைவ்கள்

cd webapp && npm run build && cd ..
cd server
make build-linux       # the antimatter and amctl binaries
make package-linux     # dist/antimatter-linux-amd64.tar.gz and -arm64

make build வெப் இன்டர்ஃபேஸ்களையும் லினக்ஸ் பினாரிகளையும் ஒரே நேரத்தில் பிளட் செய்கிறது. ஆர்கைவில் bin/antimatter, bin/amctl, டிஃபால்ட் config/config.json, இரண்டு வெப் இன்டர்ஃபேஸ்கள், டெம்பிளேட்கள், ஃபாண்டுகள் மற்றும் பெயர்ப்புகள் உள்ளன. மற்ற பிளாட்ஃபார்ம்கள்: make package-osx, make package-windows, make package-freebsd. ஆர்கைவ்களில் பண்டிள்ட ஆப்ஸ்கள் இல்லை; Docker இமேஜில் உள்ளன.

Docker இமேஜ்

antimatter-docker ரிபாசிட்டரி வெளியிடப்பட்ட இமேஜ்களை, அதன் ஆப்ஸுடன் சர்வரை, முழுக்க முழுக்க Docker-இல் பிளட் செய்கிறது:

git clone https://github.com/AntimatterChat/antimatter-docker.git
cd antimatter-docker
scripts/build-all.sh                     # from the main branches on GitHub
SOURCES=local scripts/build-all.sh       # from your checkouts next to this folder
VARIANT=next scripts/build-all.sh        # the "next" image, with every Antimatter app

இதற்கு buildx உடன் Docker, Python 3, git, gpg, சுமார் 16 GB RAM மற்றும் 30 GB டிஸ்க் தேவை. முடிவு ghcr.io/antimatterchat/antimatter:dev ஆக லோட் செய்யப்படுகிறது; ANTIMATTER_IMAGE=ghcr.io/antimatterchat/antimatter:dev docker compose -f compose.local.yml up -d மூலம் முயற்சிக்கவும். plugins.json பாகேஜ்களையும் பிளட் செய்யப்பட்ட பதிப்புகளையும் பட்டியலிடுகிறது, ரிபாசிட்டரியின் README வேரியண்டுகளை விளக்குகிறது.

build-all.sh Antimatter சைனிங் கீயால் (signing key) இணைக்கப்பட்ட ஆப்ஸ்களை (apps) சைன் (sign) செய்கிறது, மேலும் இமேஜ் பில்ட் (image build) சைன் செய்யப்படாத ஆப்ஸ்களை நிராகரிக்கிறது. அதன் தனியார் கீ (private key) மட்டும் மெண்டைனர்களிடம் (maintainers) இருப்பதால், முதல் படிகளை மட்டும் தனித்தனியாக இயக்குங்கள்: scripts/fetch-sources.sh, scripts/build-plugins.sh (out/plugins/ இல் ஆப் பண்டிள்கள்) மற்றும் scripts/build-server.sh (out/server/ இல் சர்வர் ஆர்கைவ்கள்).

பில்ட் மற்றும் நினைவகம்

வெப் இன்டர்ஃபேஸ்கள் பெரிய webpack பில்ட்கள்; நினைவகம் (memory) தீர்மானமாகும் (running out of memory) என்பது மிகவும் பொதுவான பில்ட் தோல்வி.

  • npm run build கிளாசிக் இன்டர்ஃபேஸை (classic interface) முதலில், பின்னர் Fusion-ஐ தனித்தனியாக (ஒன்றாக இல்லாமல்) பில்ட் செய்கிறது, உச்சத்தை (peak) குறைவாக வைத்திருக்க. நீங்களும் அவற்றை இணை (parallel) இயக்க வேண்டாம்.
  • மினீஃபையர் (minifier) ஒவ்வொரு புரொசஸருக்கும் (processor) ஒரு வேர்கரை (worker) தொடங்குகிறது. அதிக கோர்கள் (cores) கொண்ட ஆனால் குறைந்த நினைவகம் கொண்ட மெஷினில், பில்ட் பார்க்கும் புரொசஸர்களைக் கட்டுப்படுத்தவும்: taskset -c 0-5 npm run build.
  • Node-க்கு ஹீப் (heap) தீர்மானமாகினால், அதன் எல்லை (limit) ஐ உயர்த்தவும்: NODE_OPTIONS=--max-old-space-size=6144. Docker பில்ட் இந்த மதிப்பைப் பயன்படுத்துகிறது (build.env இல் BUILD_NODE_OPTIONS).
  • சிறிய மெஷினில், சர்வரின் முழு டெஸ்ட் சூட் (test suite), ஒரு வெப் பில்ட் மற்றும் ஒரு Docker பில்ட் ஆகியவற்றை ஒரே நேரத்தில் இயக்குவதைத் தவிர்க்கவும்.

பிரயோகங்கள்

ஒவ்வொரு ஆப் (plugin) க்கும் தனி ரிபாசிட்டரி (repository) மற்றும் Makefile உள்ளது; make dist அதன் பண்டிளை (bundle) பில்ட் செய்கிறது. பில்ட், நிறுவல் மற்றும் டிபகிங் ஐப் பார்க்கவும்.

டெஸ்க்டாப் ஆப்

டெஸ்க்டாப் ஆப் ஒரு Electron ஆப். Node.js 24 அல்லது அதற்குப் பின்னான பதிப்புகளுடன்:

npm install --allow-git=all
npm run build          # development build, into dist/
npm start              # run it
npm run package:linux  # packages into release/ (also package:windows, package:mac)

பில்ட் நேர அமைப்புகள் (build-time settings), முன்-அமைக்க (preconfigure) வேண்டிய சர்வர்கள் போன்றவை, src/common/config/buildConfig.ts இல் உள்ளன.

மொபைல் ஆப்

மொபைல் ஆப் ஒரு React Native ஆப்; அதன் README-ல் கட்டளைகள் (npm run ios, npm run android) பட்டியலிடப்பட்டுள்ளன. உங்கள் சொந்த நகலை (copy) பில்ட் செய்ய, உங்கள் சொந்த சைனிங் கீஸ் (signing keys), Android அறிவிப்புகளுக்கு ஒரு Firebase project, iOS-க்கு ஒரு APNs key, மற்றும் அந்த அங்கீகாரங்களை (credentials) வைத்திருக்கும் push proxy ஆகியவை தேவை.
