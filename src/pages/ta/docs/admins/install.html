Docker Compose மூலம் நிறுவல்

இது பரிந்துரைக்கப்படும் முறை. ஒரு compose file மூலம் Antimatter, PostgreSQL, file storage மற்றும் GIF service ஐ இயக்கலாம். Docker Engine மற்றும் அதன் Compose plugin (docker compose) உடன் கூடிய ஒரு Linux server, 2 CPU cores மற்றும் 4 GB memory அல்லது அதற்கு மேல் தேவை.

1. compose file ஐ பதிவிறக்கவும்

mkdir antimatter && cd antimatter
curl -fsSLO https://antimatter.chat/compose.yaml

2. .env file ஐ உருவாக்கவும்

compose file அதன் அமைப்புகளை அதே directory இல் உள்ள .env file இலிருந்து படிக்கிறது. random secrets உடன் அதை உருவாக்கவும்:

cat > .env <<EOF
SITE_URL=http://localhost:8065
POSTGRES_PASSWORD=$(openssl rand -hex 24)
S3_SECRET_KEY=$(openssl rand -hex 24)
GIFS_API_KEY=$(openssl rand -hex 24)
AM_AI_ENCRYPTION_KEY=$(openssl rand -base64 32)
EOF
chmod 600 .env

பயனர்கள் தங்கள் உலாவியில் உள்ளிடும் முகவரியை SITE_URL என அமைக்கவும், உதாரணமாக உள்ளூர் நெட்வொர்க்கில் http://192.168.1.20:8065 அல்லது டொமைனுடன் https://chat.example.com. .env கோப்பை வைத்திருங்கள்: முதல் இயக்கத்திலிருந்து தரவுத்தளம் மற்றும் சேமிப்பு இந்த கடவுச்சொற்களைப் பயன்படுத்துகின்றன, AI மாதிரி இணைப்புகளின் API விசைகள் AM_AI_ENCRYPTION_KEY மூலம் குறியாக்கம் செய்யப்படுகின்றன, மேலும் பின்புலப் பிரதியை மீட்டெடுக்க இந்த அதே கோப்பு தேவை.

3. இயக்கவும்

docker compose up -d
docker compose ps

முதல் start இல் ஒரு நிமிடம் அல்லது இரண்டு நிமிடங்கள் ஆகும்: PostgreSQL database ஐ உருவாக்குகிறது, one-shot bucket service storage bucket ஐ உருவாக்குகிறது, one-shot gifs-stickers service starter sticker pack ஐ import செய்கிறது, Antimatter அதன் tables ஐ உருவாக்குகிறது. docker compose logs -f antimatter மூலம் அதைப் பின்தொடரவும்.

domain name மற்றும் HTTPS ஐ முதலில் பயன்படுத்த, Domain மற்றும் HTTPS ஐப் பார்க்கவும்: compose file உடன் .env இல் இரண்டு கூடுதல் lines மற்றும் https profile போதும்.

PostgreSQL, சேமிப்பும் GIF சேவாவும் இணையத்திற்கு அணுகல் இல்லாத ஒரு உள்நெட்வொர்க்கில் (private) உள்ளன; Antimatter மட்டுமே அதில் இணைகிறது. அவற்றில் எதுவும் ஒரு போர்ட்டை வெளியிடவில்லை.

Antimatter கண்டெய்னரில் டிஸ்கில் எதுவும் வைக்கப்படுவதில்லை: அதன் அமைப்புகள் தரவுத்தளத்தில் (AM_CONFIG அதைக் குறிக்கிறது) மற்றும் அதன் கோப்புகள் மற்றும் செயலிகள் சேமிப்பு சேவையில் உள்ளன. நீங்கள் எப்போது வேண்டுமானாலும் கண்டெய்னரை அகற்றி மீண்டும் உருவாக்கலாம். அதன் data வாலியூம் AM_AI_ENCRYPTION_KEY காலியாக இருக்கும்போது சர்வர் உருவாக்கும் AI குறியாக்க விசை கோப்பை மட்டுமே கொண்டுள்ளது. பின்புலப் பிரதி எடுக்க வேண்டிய எல்லாம் postgres, files, gifs மற்றும் data வாலியூம்களிலும், உங்கள் .env கோப்பிலும் உள்ளன.

ஒரு இமேஜைத் தேர்ந்தெடுக்கவும்

இரண்டு Antimatter இமேஜ்கள் வெளியிடப்பட்டுள்ளன; இரண்டும் linux/amd64 மற்றும் linux/arm64 ஆகியவற்றுக்காகவும், எல்லா ரிபொசிட்டரிகளின் main கிளாஞ்சிலிருந்தும் உருவாக்கப்பட்டுள்ளன:

படம்உள்ளடக்கப்பட்ட செயலிகள்டேக்ஸ்
ghcr.io/antimatterchat/antimatterAgents, Calls, GitHub, GitLab, Jira, Kanban, Metrics மற்றும் Playbooks.latest, வெளியீடுகளுக்கு X.Y.Z, sha-<commit>
ghcr.io/antimatterchat/antimatter-nextஅதே, மேலும் குரல் சேனல்கள், கருத்துக் கணிப்புகள், மின்னஞ்சல், நாட்காட்டி, குறிப்புகள், வெள்ளை பலகை, GIFs, Todo மற்றும் Memes. ஒவ்வொரு இரவும் மீண்டும் உருவாக்கப்படுகிறது.latest, nightly, nightly-<YYYYMMDD>, sha-<commit>

இந்த இணையத்தளத்தின் compose கோப்பு antimatter-next ஐப் பயன்படுத்துகிறது, ஏனெனில் GIF சேவையும் இந்த இணையத்தளத்தில் விவரிக்கப்பட்ட பெரும்பாலான செயலிகளும் அந்த இமேஜில் மட்டுமே உள்ளன. இமேஜை மாற்ற, .env இல் ANTIMATTER_IMAGE ஐ அமைத்து docker compose up -d ஐ இயக்கவும்.

latest உங்கள் கீழே மாறுகிறது. உற்பத்தியில், nightly-20261015 அல்லது sha-<commit> போன்ற ஒரு டேக்கை பினிட்டு (pin) வைக்கவும், மேம்படுத்தும்போது உள்நோக்கமாக அதை மாற்றவும். சர்வர் தனது தரவுத்தளத்தை இயக்கும்போது மேம்படுத்துகிறது, எனவே முந்தைய காப்பிடினை மீட்டெடுக்காமல் பழைய இமேஜிற்கு அல்லது antimatter-next இலிருந்து antimatter க்கு திரும்ப முடியாது. காப்பிடுகள் மற்றும் மேம்பாடுகள் ஐப் பார்க்கவும்.

இமேஜின் உள்ளே

  • சர்வர் /antimatter இல் உள்ளது; antimatter மற்றும் amctl பைனரிகள் /antimatter/bin இல் (PATH இல்).
  • அது உரிமைகள் இல்லாத antimatter பயனராக (uid 2000) ஷெல் இல்லாத ஒரு குறைந்தபட்ச distroless அடிப்படையில் இயங்குகிறது.
  • போர்ட்கள்: 8065 (வெப் மற்றும் API), 8067 (மெட்ரிக்ஸ்), 8074 (கிளஸ்டர்), 8443 UDP மற்றும் TCP (அழைப்புகள்).
  • உள்ளூர் முறை (ServiceSettings.EnableLocalMode) இயக்கப்பட்டுள்ளதால், amctl --local கன்டெய்னரின் (container) உள்ளே வேலை செய்யும். ஆரோக்கியச் சோதனை (health check) amctl system status --local ஐ இயக்குகிறது.
  • இணைக்கப்பட்ட செயலிகள் (bundled apps) /antimatter/prepackaged_plugins இல் உள்ளன; அவை Antimatter செயலி கையொப்ப விசையால் (app signing key) கையொப்பம் செய்யப்பட்டுள்ளன.
  • உரை அகற்றும் கருவிகள் (pdftotext, wvText, unrtf, tidy) சேர்க்கப்பட்டுள்ளன; இதனால் பதிவேற்றப்பட்ட ஆவணங்களின் உள்ளடக்கத்தைத் தேட முடியும்.

மற்ற compose கோப்புகள்

antimatter-docker சேமிப்பகத்தில் (repository), deploy/compose/ இல் உற்பத்தி அமைப்பு (production setup) உள்ளது: உங்கள் சொந்த சான்றிதழ்கள் அல்லது Let's Encrypt (certbot) உடன் nginx, PostgreSQL, விருப்ப GIF சேவை (profile gifs) மற்றும் சேவையகத்தின் அமைப்புகள், தரவு மற்றும் பதிவுகள் (logs) ஆகியவற்றிற்கான பெயரிடப்பட்ட தொகுதிகள் (named volumes); இவை அதன் README இல் ஆவணப்படுத்தப்பட்டுள்ளன. இது இயல்பாக நிலையான (stable) இமேஜைப் பயன்படுத்துகிறது, S3 சேமிப்பகத்திற்குப் பதிலாக உள்ளூர் தொகுதியில் (local volume) கோப்புகளை சேமிக்கிறது. Caddy-க்குப் பதிலாக nginx ஐ விரும்பினால் அல்லது ஏற்கனவே சான்றிதழ்கள் இருந்தால் இதைப் பயன்படுத்தவும்.

முதல் நிர்வாகியை உருவாக்குதல்

உங்கள் உலாவினில் (browser) SITE_URL ஐத் திறந்து ஒரு கணக்கை உருவாக்குங்கள். புதிய சேவையகத்தில் உருவாக்கப்படும் முதல் கணக்கு அமைப்பு நிர்வாகியாக (system administrator) மாறும், பின்னர் அமைப்பு உங்கள் முதல் சமூகத்தை (Antimatter-இன் குழு அல்லது பணிப்பரப்புக்கான பெயர்) உருவாக்குவதில் உங்களை வழிநடத்துகிறது.

முதல் இயக்கத்திற்கு உடனடியாக இதைச் செய்யுங்கள்: அதுவரை, சேவையகத்தை முதலில் அடையும் யாரும் அதன் நிர்வாகியாக மாறுவார்கள். சேவையகம் வெளியிலிருந்து அணுக முடியும் என்பதற்கு முன், கட்டளை வரிசையிலிருந்து (command line) கணக்கை உருவாக்க:

docker compose exec antimatter amctl --local user create --system-admin --email-verified \
    --email admin@example.com --username admin --password 'a-long-password'
docker compose exec antimatter amctl --local team create --name main --display-name "Main"
docker compose exec antimatter amctl --local team users add main admin

பின்னர் SITE_URL இல் உள்நுழையவும். கடவுச்சொல்லை உங்கள் shell வரலாற்றில் (shell history) இருந்து நீக்க, கட்டளையை ஒரு இடையூறால் (space) தொடங்கவும் (HISTCONTROL=ignorespace உடன்), அல்லது உள்நுழைந்த பிறகு கடவுச்சொல்லை ஒருமுறை மாற்றவும்.

உள்நுழைந்த பிறகு அடுத்த படிகள்:

  1. நிறுவனம் அல்லது நிறுவனத்திற்கு, புதிய சமூகங்களின் வகை ஐ பணியிடம் என அமைக்கவும், மற்றும் ஏற்கனவே உருவாக்கிய சமூகத்தின் வகையை அதன் அமைப்புகளில் மாற்றவும்: பணியிடம் அல்லது சமூகம்.
  2. யார் கணக்குகளை உருவாக்க முடியும் என்பதைத் தீர்மானிக்கவும்: உள்நுழைவு மற்றும் கணக்குகள்.
  3. அழைப்புகள் (invitations) மற்றும் கடவுச்சொல் மீட்டமைப்புகள் (password resets) வேலை செய்ய, மின்னஞ்சலை அமைக்கவும்: மின்னஞ்சல் மற்றும் தள்ளு அறிவிப்புகள் (push notifications).
  4. உங்கள் தீச்சுவரில் (firewall) அழைப்புகள் (calls) துறையை (port) திறக்கவும்: அழைப்புகள் மற்றும் குரல்.
  5. எந்த செயலிகள் இயக்கப்பட்டுள்ளன என்பதைச் சரிபார்க்கவும்: இணைக்கப்பட்ட செயலிகள்.

வெளியீட்டை பதிவிறக்கவும்

Docker இல்லாமல், GitHub-இல் உள்ள வெளியீட்டின் கோப்புகளில் இருந்து Antimatter-ஐ நிறுவவும்: github.com/AntimatterChat/antimatter/releases. ஒவ்வொரு வெளியீட்டும் 0.9.0 போன்ற ஒரு பதிப்பு எண்ணைக் கொண்டுள்ளது, அதன் டேக் அதே எண்ணின் முன் v உடன் (v0.9.0) இருக்கும்.

Antimatter இது beta நிலையில் உள்ளது: இதன் வெளியீடுகள் 0.9.0 தொடரில் உள்ளன. ஹைபன் பின்னொரு சட்டகம் (suffix) கொண்ட பதிப்பு எண் கொண்ட வெளியீடு, எடுத்துக்காட்டாக 0.9.0-rc.1, GitHub-ல் Pre-release என்று குறிக்கப்படுகிறது. இது ஒரு சோதனை பதிப்பு, இறுதி வெளியீட்டிற்கு முன் வெளியிடப்படுகிறது.

ஒவ்வொரு வெளியீட்டும் amd64 மற்றும் arm64 சர்வர்களிற்கான பின்வரும் கோப்புகளைக் கொண்டுள்ளது:

கோப்புஇது என்ன
antimatter_<version>-1_amd64.deb, antimatter_<version>-1_arm64.debDebian, Ubuntu மற்றும் அவற்றின் அடிப்படையில் அமைந்த பிற பகிர்வுகளுக்கான பாகேஜ்.
antimatter-<version>-1.x86_64.rpm, antimatter-<version>-1.aarch64.rpmFedora, RHEL மற்றும் RHEL-உடன் இணைந்த பிற பகிர்வுகளுக்கான பாகேஜ்.
antimatter-<version>-linux-amd64.tar.gz, antimatter-<version>-linux-arm64.tar.gzஎந்தவொரு Linux பகிர்வுக்கும், கைமுறையாக அமைக்கப்படும் வெளியீட்டு ஆர்கைவ்.
SHA256SUMSவெளியீட்டின் ஒவ்வொரு கோப்பின் SHA-256 சோதனைத்தொகை (checksum).

பாகேஜ்கள் மற்றும் ஆர்கைவ் ஒரே நிரலைக் கொண்டுள்ளன: சர்வர் (antimatter), கமாண்ட்-லைன் கருவி (amctl), இரண்டு வெப் செயலிகள் (இயல்பான இடைமுகம் மற்றும் பழையது), இணைக்கப்பட்ட செயலிகள், மின்னஞ்சல் டெம்பிளேட்கள் மற்றும் மொழிபெயர்ப்புகள். பாகேஜ்கள் ஒரு systemd சேவை மற்றும் அமைப்பு கோப்பைச் சேர்த்துள்ளன, எனவே ஒவ்வொன்றும் அனைத்தையும் உள்ளடக்கிய நிறுவல் ஆகும்: நீங்கள் PostgreSQL தரவுத்தளத்தை மட்டுமே சேர்க்க வேண்டும். தனித்தனி பைனரி பதிவிறக்கங்கள் இல்லை: பைனரிகள் ஆர்கைவ்-ல், antimatter/bin/ இல் உள்ளன. அவை நிலையானவை (static), எனவே அவற்றின் அமைப்புக்கேற்ப எந்தவொரு Linux பகிர்விலும் இயங்குகின்றன.

பாகேஜ் பெயர்களில், முன்-வெளியீட்டு (prerelease) பதிப்பின் ஹைபன் ஒரு டில்டாக் (tilde) ஆக மாற்றப்படுகிறது, இதனால் பாகேஜ் மேனேஜர் முன்-வெளியீட்டை இறுதி வெளியீட்டிற்கு முன் வரிசைப்படுத்தும்: பதிப்பு 0.9.0-rc.1 என்பது antimatter_0.9.0~rc.1-1_amd64.deb மற்றும் antimatter-0.9.0~rc.1-1.x86_64.rpm ஆகும். ஆர்கைவ் ஹைபனை வைத்திருக்கிறது.

antimatter version வெளியீட்டு பதிப்பை பதிப்பு எண் என்று, அது உருவாக்கப்பட்ட கமிட்டை பதிப்பு ஹாஷ் என்று காட்டுகிறது. அதன் பதிப்பு வரி, Antimatter அடிப்படையாகக் கொண்ட Mattermost வரிசையின் பதிப்பாகும்.

பதிவிறக்கத்தைச் சரிபார்க்க

நீங்கள் தேவையான கோப்பையும் SHA256SUMS கோப்பையுமே ஒரே கோப்புறைக்கு, வெளியீட்டு பக்கத்திலிருந்து அல்லது curl மூலமாகப் பதிவிறக்கவும், பின்னர் கோப்பைச் சரிபார்க்கவும்:

curl -fLO https://github.com/AntimatterChat/antimatter/releases/download/v<version>/antimatter_<version>-1_amd64.deb
curl -fLO https://github.com/AntimatterChat/antimatter/releases/download/v<version>/SHA256SUMS
sha256sum --check --ignore-missing SHA256SUMS

நீங்கள் பதிவிறக்கிய ஒவ்வொரு கோப்பும் OK என்று பட்டியலிடப்பட வேண்டும். வேறு எந்த முடிவும் கோப்பு சேதமடைந்தது அல்லது முழுமையற்றது என்பதைக் குறிக்கிறது: அதை மீண்டும் பதிவிறக்கவும், நிறுவ வேண்டாம். SHA256SUMS கையொப்பமிடப்படவில்லை: இது சேதமடைந்த பதிவிறக்கத்தைக் கண்டறியும், GitHub-லிருந்து HTTPS மூலம் பதிவிறக்குவதால் நிரூபிக்கப்படுவதை விட அதிகம் நிரூபிக்காது.

.deb அல்லது .rpm பாகேஜை நிறுவ

பாகேஜ் Antimatter-ஐ systemd சேவையாக நிறுவும், இது தொடங்க ஒரு தரவுத்தளத்தை மட்டுமே தேவைப்படுகிறது. systemd உடன் 64-பிட் Debian, Ubuntu, Fedora அல்லது RHEL-உடன் இணைந்த சர்வரில் இதைப் பயன்படுத்தவும்.

பாகேஜ் நிறுவும் விஷயங்கள்

பாதைஅதில் உள்ளவை
/opt/antimatterநிரல்: bin/antimatter, bin/amctl, வலை பயன்பாடுகள் (client/, client-fusion/), இணைக்கப்பட்ட பயன்பாடுகள் (prepackaged_plugins/), வடிவங்கள், மொழிபெயர்ப்புகள் மற்றும் எழுத்துருக்கள். ஒவ்வொரு மேம்படுத்தலும் இதை மாற்றுகிறது.
/etc/antimatter/antimatter.envசேவையின் அமைப்புகள், AM_ மாறிகளாக: தரவுத்தளம், தள URL, GIF சேவை. root மட்டுமே படிக்க முடியும். மேம்படுத்தல்கள் இதை வைத்திருக்கும்.
/etc/antimatter/config/config.jsonஅமைப்பு கோப்பு, அமைப்பு கனசோலில் மாற்றப்பட்ட அமைப்புகளை சேவையாளர் சேமிக்கும் இடம். முதல் நிறுவலில் /opt/antimatter/defaults/config.json இலிருந்து இது உருவாக்கப்படுகிறது, அதற்குப் பிறகு ஒருபோதும் மாற்றப்படாது.
/var/lib/antimatterபதிவேற்றப்பட்ட கோப்புகள் (data/) மற்றும் நிறுவப்பட்ட பயன்பாடுகள் (plugins/, client-plugins/).
/var/log/antimatterகோப்பு பதிவு இயக்கப்பட்டால் பதிவு கோப்புகள். இது இயக்கப்படவில்லை: பதிவுகள் journal-க்கு செல்கின்றன.
/usr/lib/systemd/system/antimatter.serviceசேவை.
/usr/bin/amctl/opt/antimatter/bin/amctl க்கான இணைப்பு.

/opt/antimatter இல் சேவையாளர் எழுதும் இயல்புகள் (config, data, plugins, client/plugins மற்றும் logs) /etc/antimatter, /var/lib/antimatter மற்றும் /var/log/antimatter க்கான இணைப்புகள் ஆகும். எனவே, /opt/antimatter ஐ மாற்றும் ஒரு மேம்படுத்தல் உங்கள் தரவை ஒருபோதும் தொடாது. தொகுப்பும் antimatter அமைப்பு பயனரையும் உருவாக்குகிறது, இது சேவையாளரை இயக்குகிறது மற்றும் இந்த இயல்புகளின் உரிமையாளராக உள்ளது.

இந்தப் பாகேஜ் ca-certificates மீது சார்புடையது. இது PostgreSQL-ஐ (postgresql என்பது Debian மற்றும் Ubuntu-க்கு, postgresql-server என்பது Fedora மற்றும் RHEL-க்கு), media-types-ஐ (.rpm-க்கு mailcap) மற்றும் GIF சேவையான gifs-server-ஐ (இதற்கு தனி ரிலீஸ் உள்ளது; கீழே பார்க்கவும்) பரிந்துரைக்கிறது. apt மற்றும் dnf, அவை இவற்றைக் கண்டால் பரிந்துரைக்கப்பட்ட பாகேஜ்களை நிறுவும். இது poppler-utils, wv, unrtf மற்றும் tidy-ஐ (.rpm-க்கு wv இல்லை) பரிந்துரைக்கிறது: இவை பதிவேற்றப்பட்ட ஆவணங்களின் உரையைப் பிரித்தெடுக்கின்றன, இதனால் தேடல் அவற்றின் உள்ளே உள்ள சொற்களைக் கண்டறியும். நீங்கள் இதை விரும்பினால், இவற்றை உங்களுக்கே நிறுவவும்.

1. தொகுப்புகளை நிறுவவும்

உங்கள் கட்டமைப்பிற்கான Antimatter தொகுப்பையும் GIF சேவை தொகுப்பையும் பதிவிறக்கவும், மேலே காட்டப்பட்டபடி அவற்றை சரிபார்க்கவும், gifs-server இன் பரிந்துரையை நிறைவேற்ற (அது விநியோகங்களின் சேமிப்பகங்களில் இல்லை) ஒரு கட்டளையில் இரண்டையும் நிறுவவும்:

# Debian, Ubuntu
sudo apt install ./antimatter_<version>-1_amd64.deb ./gifs-server_*_amd64.deb
# Fedora, RHEL
sudo dnf install ./antimatter-<version>-1.x86_64.rpm ./gifs-server-*.x86_64.rpm

./ ஐ வைத்திருங்கள்: இது apt மற்றும் dnf-க்கு உள்ளூர் கோப்பை நிறுவ வேண்டும் என்று தெரிவிக்கிறது. GIF சேவையுடன் இல்லாமல் நிறுவ, அதன் பாகத்தை விட்டுவிடவும். இந்த பாகம் antimatter சேவையை இயக்குகிறது, ஆனால் அதைத் தொடங்காது, அடுத்த படிகளை அச்சுக்கு எடுக்கிறது.

2. தரவுத்தளத்தை உருவாக்கு

Antimatter-க்கு PostgreSQL 15 அல்லது அதற்குப் புதிய பதிப்பு தேவை, இந்த சர்வரில் அல்லது வேறு சர்வரில். உங்கள் விநியோகத்தின் PostgreSQL பதிப்பை psql --version மூலம் சரிபார்க்கவும். அது பழையதாக இருந்தால், PostgreSQL திட்டத்தின் சொந்த சேமிப்பகங்களிலிருந்து புதிய பதிப்பை நிறுவவும், அல்லது வேறு சர்வரில் உள்ள தரவுத்தளத்தைப் பயன்படுத்தவும். Debian மற்றும் Ubuntu-இல், postgresql பாகம் தரவுத்தளத்தைத் தொடங்குகிறது. Fedora மற்றும் RHEL-இல், முதலில் அதை உருவாக்கித் தொடங்கவும்:

sudo postgresql-setup --initdb
sudo systemctl enable --now postgresql

பின்னர் Antimatter-க்கு ஒரு பயனரையும் ஒரு தரவுத்தளத்தையும் உருவாக்கவும்:

sudo -u postgres psql -c "CREATE USER antimatter WITH PASSWORD 'a-long-password'"
sudo -u postgres psql -c "CREATE DATABASE antimatter OWNER antimatter"

PostgreSQL 127.0.0.1 இலிருந்து கடவுச்சொல் இணைப்புகளை ஏற்க வேண்டும்: அதன் pg_hba.conf கோப்பையின் host வரிசைகள், scram-sha-256 முறையுடன்.

3. தரவுத்தளத்தையும் தள URL-யையும் அமை

/etc/antimatter/antimatter.env ஐத் திருத்து (sudoedit /etc/antimatter/antimatter.env). நீங்கள் பயன்படுத்தும் வரிசைகளின் முன் உள்ள # ஐ அகற்றுங்கள், தரவுத்தளத்தையும் மக்கள் திறக்கும் முகவரியையும் அமைக்கவும்:

AM_SQLSETTINGS_DRIVERNAME=postgres
AM_SQLSETTINGS_DATASOURCE=postgres://antimatter:a-long-password@localhost:5432/antimatter?sslmode=disable&connect_timeout=10
AM_SERVICESETTINGS_SITEURL=https://chat.example.com

அமைப்புகளின் எந்த அமைப்பையும் இந்த கோப்பில் AM_<SECTION>_<SETTING> ஆக வைக்கலாம்: எடுத்துக்காட்டாக, SqlSettings.DataSource என்பது AM_SQLSETTINGS_DATASOURCE. இங்கு அமைக்கப்பட்ட அமைப்பை அமைப்பு கனசோலில் மாற்ற முடியாது. அமைப்புகள் ஐப் பார்க்கவும். ஒவ்வொரு மாற்றத்திற்கும் பிறகு சர்வரை மீண்டும் தொடங்கவும்: sudo systemctl restart antimatter.

சேவையும் சில இயல்புநிலை அமைப்புகளை அமைக்கிறது, அவற்றை antimatter.env இல் ஒரு வரி மாற்றுகிறது: கோப்புகளுக்குப் பதிவு செய்வது அணைக்கப்பட்டுள்ளது (AM_LOGSETTINGS_ENABLEFILE=false, AM_NOTIFICATIONLOGSETTINGS_ENABLEFILE=false), உள்ளூர் முறை இயக்கப்பட்டுள்ளது (AM_SERVICESETTINGS_ENABLELOCALMODE=true), இதனால் amctl --local சர்வரில் வேலை செய்கிறது.

4. இயக்கு

sudo systemctl start antimatter
journalctl -u antimatter -f
sudo -u antimatter amctl --local system status

முதல் இயக்கத்தில், சர்வர் தனது டேபிள்களை உருவாக்கி, பின்னர் 8065 போர்டில் கேட்கிறது. http://<server>:8065 ஐத் திறக்கவும், அல்லது ரிவர்ஸ் ப்ராக்ஸி அமைக்கப்பட்ட பிறகு உங்கள் டொமைனைத் திறக்கவும் (டொமைன் மற்றும் HTTPS காண்க), பின்னர் உடனடியாக முதல் கணக்கை உருவாக்கவும்: அது அமைப்பு நிர்வாகியாக மாறும். அதற்குப் பதிலாக கமாண்ட் லைனில் இருந்து உருவாக்க, முதல் நிர்வாகியை உருவாக்குதல் பகுதியில் உள்ள amctl கமாண்டுகளைப் பயன்படுத்தவும்; docker compose exec antimatter amctl --local ஐப் பதிலாக sudo -u antimatter amctl --local ஐப் பயன்படுத்தவும்.

5. GIFகளை இயக்கு

GIFகள் ஆப் பட்டியில் சேர்க்கப்பட்டுள்ளது மற்றும் இயங்குகிறது, மேலும் antimatter.env அதை அதே சர்வரில் உள்ள GIF சேவைக்கு (AM_GIFS_SERVICE_URL=http://127.0.0.1:8080/v2) குறிக்கிறது. இன்னும் சேவையின் API விசை தேவை. gifs-server பாகேஜ் அதன் நிறுவல் போது ஒன்றை உருவாக்கியது:

sudo systemctl start gifs-server-stickers    # imports the sticker pack, about a minute and a half
sudo systemctl start gifs-server
sudo grep -v '^#' /etc/gifs-server/api-keys

அந்த விசையை antimatter.env-ல் AM_GIFS_API_KEY=<key> என வைத்து Antimatter-ஐ மறுஇயக்குங்கள், அல்லது அமைப்பு கன்சோல் › பிளக்-இன்கள் › GIFகள் இல் API விசை என உள்ளிடவும். GIF சேவை வேறு சர்வரில் இயங்கினால், AM_GIFS_SERVICE_URL-ஐ அதன் முகவரிக்கு அமைக்கவும். மக்கள் தங்கள் சொந்த GIFகள் மற்றும் ஸ்டிகர்களை சேர்க்க அனுமதிக்க, GIFகள் பகுதியை பார்க்கவும்.

சேவை

  • அது antimatter பயனராக, /opt/antimatter-ல் இயங்குகிறது, மேலும் /etc/antimatter/antimatter.env-ஐ படிக்கிறது. சர்வர் வெளியேறும்போதெல்லாம் systemd அதை மறுஇயக்கும், புதிய பதிப்பின் தரவுத்தள மாற்றங்கள் நீண்ட நேரம் எடுக்கக்கூடியதால், இயங்கத் தொடங்குவதற்கு அதற்கு அதிகபட்சம் ஒரு மணி நேரம் அளிக்கிறது.
  • அதன் பதிவுகள் (logs) ஜர்னலில் உள்ளன: journalctl -u antimatter.
  • அது பாதுகாக்கப்பட்டுள்ளது: சர்வருக்கு /usr மற்றும் /etc படிக்க மட்டும் (read-only) உள்ளன, /etc/antimatter/config தவிர, மேலும் /home, /root அல்லது /run/user ஆகியவற்றை அது காண முடியாது. நீங்கள் கோப்பு சேமிப்பை (FileSettings.Directory) நகர்த்தினால், இந்தப் பட்டியல்களுக்கு வெளியே, antimatter உரிமையாளராக உள்ள ஒரு டிரிக்டரீயை தேர்ந்தெடுக்கவும்.
  • பட்டிப்படுத்தல்கள் (Upgrades) சேவை கோப்பை மாற்றும். அதை மாற்ற, sudo systemctl edit antimatter பயன்படுத்தவும், இது உங்கள் மாற்றங்களை தனித்தனி கோப்பில் வைத்திருக்கும்.

பாகேஜை பட்டிப்படுத்துதல்

  1. பேக்அப் எடுக்கவும் (பேக்அப்கள் மற்றும் பட்டிப்படுத்தல்கள் பார்க்கவும்).
  2. புதிய பாகேஜையும் SHA256SUMS-ஐயும் பதிவிறக்கி, அவற்றை சரிபார்க்கவும்.
  3. சர்வரை நிறுத்தி, பழையது மீது புதிய பாகேஜை நிறுவி, மீண்டும் இயக்கவும்: 
    sudo systemctl stop antimatter
sudo apt install ./antimatter_<new version>-1_amd64.deb     # or: sudo dnf install ./antimatter-<new version>-1.x86_64.rpm
sudo systemctl start antimatter
journalctl -u antimatter -f

பாக்கேஜ் சர்வரையே மீண்டும் இயக்காது. மேம்படுத்தலுக்குப் பிறகு Antimatter was upgraded; restart it to run the new version: sudo systemctl restart antimatter என்று அச்சுப்படுகிறது: நீங்கள் முதலில் சர்வரை நிறுத்தவில்லை என்றால், உடனே அதை மீண்டும் இயக்குங்கள். மேம்படுத்தல் /opt/antimatter மற்றும் சர்வீஸ் கோப்பை மாற்றிவிட்டு, antimatter.env, config.json, /var/lib/antimatter மற்றும் பதிவுகளை (logs) வைத்திருக்கும். இயங்கும்போது, சர்வர் தரவுத்தளத்தை மேம்படுத்தி, இணைக்கப்பட்ட ஆப்ஸ்களின் புதிய பதிப்புகளை நிறுவும்.

புதிய பதிப்பு antimatter.env இன் மூலநிலை (default) மதிப்புகளை மாற்றினால், apt உங்கள் பதிப்பை வைத்திருக்கவா என்று கேட்கும்: வைத்திருங்கள். dnf உங்கள் பதிப்பை வைத்திருத்து, புதியதை /etc/antimatter/antimatter.env.rpmnew என சேமிக்கிறது. மேம்படுத்தல்கள் முன்னோக்கி மட்டுமே செல்கின்றன: புதிய பதிப்பின் மீது பழைய பதிப்பை நிறுவ வேண்டாம்.

பாக்கேஜை அகற்றுதல்

sudo apt remove antimatter அல்லது sudo dnf remove antimatter சர்வீஸை நிறுத்தி முடக்குகிறது, மேலும் நிரலை அகற்றுகிறது. தரவு (/var/lib/antimatter), அமைப்புகள் (/etc/antimatter), தரவுத்தளம் மற்றும் antimatter பயனரினை அது வைத்திருக்கும்: Antimatter ஐ முழுமையாக அகற்ற, அவற்றை நீங்களே நீக்குங்கள்.

பாக்கேஜ்களிலும் காப்பகத்திலும் உள்ள ஆப்ஸ்கள்

பாக்கேஜ்களும் காப்பகமும் (archive) இந்த ஆப்ஸ்களின் சமீபத்திய கையொப்பமிட்ட வெளியீட்டை (signed release) prepackaged_plugins/ இல் கொண்டுள்ளன: Agents, Calls, GIFs, Memes, Notes, Polls, Todo, Voice Channels மற்றும் Whiteboard. சர்வர் வெளியீடு உருவாக்கப்பட்டபோது வெளியீடு இல்லாத ஆப்ஸ் விடுபட்டுவிடும்: ls /opt/antimatter/prepackaged_plugins உங்கள் வெளியீட்டில் என்ன உள்ளது என்பதைக் காட்டும். Memes மற்றும் Todo சேர்க்கப்பட்டுள்ளன, ஆனால் இயக்கப்படவில்லை: இணைக்கப்பட்ட ஆப்ஸ்கள் அவற்றை எப்படி நிறுவவும் இயக்கவும் என்பதை விளக்குகிறது.

ஒவ்வொரு ஆப் வெளியீட்டிலும், அந்த ஆப்பின் பண்டிள் (.tar.gz கோப்பு), அதன் கையொப்பம் (அதே பெயருக்கு .sig சேர்க்கப்பட்டது) மற்றும் SHA256SUMS கோப்பு உள்ளன. ஒரு ஆப்பை நிறுவ, பதிவேற்றம்களை அனுமதித்து, பின்னர் amctl மூலம் பண்டிளை சேர்க்கவும்:

# 1. In /etc/antimatter/antimatter.env, add this line, then restart Antimatter
AM_PLUGINSETTINGS_ENABLEUPLOADS=true
sudo systemctl restart antimatter
# 2. Download the bundle where the antimatter user can read it, and install it
cd /tmp
curl -fLO https://github.com/AntimatterChat/antimatter-plugin-boards/releases/download/v<version>/<bundle>.tar.gz
sudo -u antimatter amctl --local plugin add <bundle>.tar.gz
sudo -u antimatter amctl --local plugin enable focalboard

இந்த முறையில் நிறுவப்பட்ட ஒரு ஆப்பை புதுப்பிக்க, plugin add --force மூலம் புதிய பண்டிளை சேர்க்கவும்: பாக்ஜேஜ் புதுப்பிப்புகள் பண்டிள் ஆப்புகளை மட்டுமே புதுப்பிக்கும். பின்னர் AM_PLUGINSETTINGS_ENABLEUPLOADS வரிசையை மீண்டும் நீக்கலாம். ஆப்புகளை நிறுவும் மற்ற முறைகள் பற்றி மற்ற ஆப்புகளை நிறுவுதல் பகுதியை பார்க்கவும்.

ஆப் கையொப்பங்கள்

ஆப் பண்டிள்கள் Antimatter ஆப் கையொப்ப விசையால் கையொப்பம் செய்யப்படுகின்றன: ஒவ்வொரு .tar.gz.sig கோப்பும் அதன் பண்டிளின் தனித்தனியான GPG கையொப்பம் ஆகும். ஒரு பண்டிள் ஆப்பை நிறுவும் முன் சர்வர் இந்த கையொப்பங்களை சரிபார்த்து. ஒரு பண்டிளை நீங்களே சரிபார்க்க:

curl -fsSLO https://raw.githubusercontent.com/AntimatterChat/antimatter-docker/main/keys/antimatter-plugin-signing.asc
gpg --import antimatter-plugin-signing.asc
gpg --verify <bundle>.tar.gz.sig <bundle>.tar.gz

அரக்கை, antimatter-<version>-linux-<arch>.tar.gz (உதாரணமாக antimatter-0.9.0-linux-amd64.tar.gz), .deb அல்லது .rpm பாக்ஜேஜ்கள் இல்லாத ஒரு விநியோகத்திற்கு, அல்லது உங்களுடைய சொந்த அமைப்பிற்கு பொருத்தமானது. இது bin/antimatter, bin/amctl, config/config.json, வலை ஆப்புகள் (client/ மற்றும் client-fusion/), பண்டிள் ஆப்புகள் (prepackaged_plugins/, மேலே பார்க்கவும்), மின்னஞ்சல் டெம்பிள்கள் மற்றும் மொழிபெயர்ப்புகளைக் கொண்ட ஒரு தனி antimatter/ கோப்புறையை உள்ளடக்கியது.

1. PostgreSQL-ஐ தயார் செய்யுங்கள்

Antimatter PostgreSQL-ஐ மட்டுமே ஆதரிக்கிறது; பதிப்பு 15 அல்லது அதற்குப் புதியது (பழைய பதிப்புகள், பதிவுப் பதிவில் (log) ஒரு பிழையுடன் தொடங்குகின்றன). ஒரு பயனரையும் (user) ஒரு தரவுத்தளத்தையும் (database) உருவாக்குங்கள்:

sudo -u postgres psql <<'EOF'
CREATE USER antimatter WITH PASSWORD 'a-long-password';
CREATE DATABASE antimatter OWNER antimatter;
EOF

2. பிரித்து (unpack) அமைவு செய்யுங்கள்

sudo tar -xzf antimatter-<version>-linux-amd64.tar.gz -C /opt
sudo useradd --system --user-group antimatter
sudo mkdir -p /opt/antimatter/data
sudo chown -R antimatter:antimatter /opt/antimatter

தரவுத்தளத்தைச் சேர்ந்த சர்வரை /opt/antimatter/config/config.json (SqlSettings.DataSource) அல்லது சூழல் மாறிகளால் (environment variables) குறிப்பிடவும், மேலும் தள URL-ஐ அமைக்கவும்:

AM_SQLSETTINGS_DRIVERNAME=postgres
AM_SQLSETTINGS_DATASOURCE=postgres://antimatter:a-long-password@localhost:5432/antimatter?sslmode=disable&connect_timeout=10
AM_SERVICESETTINGS_SITEURL=https://chat.example.com

ஆர்கைவின் config.json ஒரு முழுமையான இயல்புநிலை அமைவு (default configuration): System Console-ல் நீங்கள் மாற்றும் அமைவுகள் அதில் மீண்டும் சேமிக்கப்படுகின்றன. மாற்றாக அமைவை தரவுத்தளத்தில் வைக்க விரும்பினால், அமைவு பக்கத்தைப் பார்க்கவும்.

3. சேவையாக (service) இயக்குங்கள்

systemd அலகு (unit), /etc/systemd/system/antimatter.service இல்:

[Unit]
Description=Antimatter
After=network.target postgresql.service

[Service]
Type=notify
User=antimatter
Group=antimatter
WorkingDirectory=/opt/antimatter
ExecStart=/opt/antimatter/bin/antimatter
EnvironmentFile=-/etc/antimatter.env
TimeoutStartSec=3600
Restart=always
RestartSec=10
LimitNOFILE=49152

[Install]
WantedBy=multi-user.target

உங்கள் AM_ மாறிகளை /etc/antimatter.env இல் வைக்கவும் (root மட்டுமே படிக்கக்கூடியதாக), பின்னர்:

sudo systemctl daemon-reload
sudo systemctl enable --now antimatter
journalctl -u antimatter -f

சர்வர் 8065 துறையில் (port) கேட்கிறது. http://<server>:8065-ஐ திறக்கவும், அல்லது ஒரு reverse proxy அமைக்கப்பட்ட பிறகு உங்கள் domain-ஐத் திறக்கவும் (Domain மற்றும் HTTPS பார்க்கவும்), முதல் கணக்கை உருவாக்குங்கள்: அது அமைப்பு நிர்வாகியாக (system administrator) மாறும்.

bin/amctl இயங்கும் சர்வரை கட்டளை வரிசையிலிருந்து (command line) நிர்வகிக்கிறது. சர்வரில் தானாகவே, உள்ளூர் முறையில் (local mode) உள்நுழைவின் (sign in) மூலம் இது வேலை செய்கிறது: AM_SERVICESETTINGS_ENABLELOCALMODE=true என அமைத்து, பின்னர் sudo -u antimatter /opt/antimatter/bin/amctl --local system status இயக்குங்கள்.

GIF-களுக்கு, GIF சேவை (கீழே பார்க்கவும்) நிறுவ, AM_GIFS_SERVICE_URL மற்றும் AM_GIFS_API_KEY ஐ பாக்ஜேஜ்களின் படி 5 போல அமைக்கவும்.

GIF சேவை மற்றும் push proxy பாக்ஜேஜ்கள்

GIF சேவை மற்றும் push proxy தங்கள் சொந்த வெளியீடுகளைக் கொண்டுள்ளன; சர்வரின் விதிகளுடன் ஒத்தவாறு: .tar.gz ஆர்கைவ், amd64 மற்றும் arm64 க்கான .deb மற்றும் .rpm பாக்கேஜ்கள், மேலும் SHA256SUMS கோப்பு. ஹைபன் (-) கொண்ட பதிப்புகள் முன்வெளியீடுகள் (prereleases). சர்வரின் போலவே, sha256sum --check --ignore-missing SHA256SUMS மூலம் பதிவிறக்கங்களைச் சரிபார்க்கவும்.

GIF சேவை (gifs-server)

வெளியீடுகள்: github.com/AntimatterChat/gifs-server/releases. ஆர்கைவ் gifs-server-<version>-linux-<arch>.tar.gz எனவும், பாக்கேஜ்கள் gifs-server எனவும் பெயரிடப்பட்டுள்ளன.

sudo apt install ./gifs-server_*_amd64.deb      # Debian, Ubuntu
sudo dnf install ./gifs-server-*.x86_64.rpm     # Fedora, RHEL

பாக்கேஜ் பின்வருவனவற்றை நிறுவும்:

  • /usr/bin/gifs-server, மற்றும் gifs-server சேவை; இது gifs-server பயனராக இயங்கி, அதன் காட்டலாக்கை (catalogue) /var/lib/gifs-server இல் வைத்திருக்கும்;
  • gifs-server-stickers சேவை; இது இயக்கப்படும்போது /usr/share/gifs-server/stickers இல் உள்ள ஸ்டிக்கர் பாக்கை (sticker pack) ஐ இறக்குமதி செய்யும் அல்லது புதுப்பித்து, பின்னர் நிறுத்தப்படும்;
  • அதன் அமைப்புகள், /etc/gifs-server/gifs-server.env (AM_GIFS_ மாறிகள், புதுப்பிப்புகளில் வைத்திருக்கப்படும்) மற்றும் /etc/gifs-server/api-keys (ஒரு வரிக்கு ஒரு API key, முதல் நிறுவலில் ஒரு சீரற்ற key உருவாக்கப்படும்).

இது 127.0.0.1:8080 இல் கேட்கிறது (listens), எனவே அதே சர்வரில் உள்ள Antimatter மட்டுமே இதை அணுக முடியும். Antimatter வேறு இடத்தில் இயங்கினால், gifs-server.env இல் AM_GIFS_LISTEN=:8080 என அமைத்து, உங்கள் fire wall மூலம் அந்த port க்கான அணுகலைக் கட்டுப்படுத்தவும். கோப்பில் மற்ற அமைப்புகளும் பட்டியலிடப்பட்டுள்ளன: AM_GIFS_UPLOAD_KEYS (GIF மற்றும் ஸ்டிக்கர்களைச் சேர்ப்பதற்கும், அவற்றை நீக்குவதற்கும் அனுமதிக்கப்பட்ட keys), AM_GIFS_PUBLIC_URL, AM_GIFS_TRUST_PROXY மற்றும் AM_GIFS_LOG_LEVEL. பாக்கேஜ் ffmpeg, gifsicle, librsvg2-bin (.rpm க்கு librsvg2-tools) மற்றும் ஒரு DejaVu font ஐ பரிந்துரைக்கிறது: கோப்புகளை இறக்குமதி செய்யும் அல்லது பெறும்போது GIF, வீடியோ மற்றும் ஸ்டிக்கர் வடிவங்களை உருவாக்க இவை பயன்படுத்தப்படுகின்றன; இல்லாமலும் சேவை இயங்கும்.

சர்வரின் போலவே, நிறுவலில் சேவை இயக்கப்படுகிறது (enabled) ஆனால் இயக்கப்படவில்லை (not started). பாக்கேஜ்களின் படி 5 இல் காட்டப்பட்டுள்ளபடி இயக்கவும். புதுப்பித்த பிறகு மீண்டும் இயக்கவும்: sudo systemctl restart gifs-server. பாக்கேஜை நீக்கினாலும் /var/lib/gifs-server இல் உள்ள காட்டலாக்க் (catalogue) வைத்திருக்கப்படும்.

Push proxy

வெளியீடுகள்: github.com/AntimatterChat/push-proxy/releases. ஆர்கைவ் antimatter-push-proxy-<version>-linux-<arch>.tar.gz எனவும், பாக்கேஜ்கள் antimatter-push-proxy எனவும் பெயரிடப்பட்டுள்ளன. இந்த பாக்கேஜ் /usr/bin/antimatter-push-proxy மற்றும் antimatter-push-proxy சேவையை நிறுவும்; இது antimatter-push-proxy பயனராக இயங்கி, /etc/antimatter-push-proxy/antimatter-push-proxy.json கோப்பை படிக்கிறது (புதுப்பிப்புகளில் இது பாதுகாக்கப்படுகிறது). Apple மற்றும் Firebase நிரூபனங்கள் /etc/antimatter-push-proxy/certs இல் வைக்கப்பட வேண்டும்: புஷ் அறிவிப்புகள் பகுதியில் அவை எங்கிருந்து பெறப்படுகின்றன என்பது விளக்கப்பட்டுள்ளது.

sudo apt install ./antimatter-push-proxy_*_amd64.deb      # or: sudo dnf install ./antimatter-push-proxy-*.x86_64.rpm
sudo install -o root -g antimatter-push-proxy -m 0640 \
    AuthKey_ABCDE12345.p8 firebase-service-account.json /etc/antimatter-push-proxy/certs/
sudoedit /etc/antimatter-push-proxy/antimatter-push-proxy.json
sudo systemctl start antimatter-push-proxy
journalctl -u antimatter-push-proxy -f

அமைப்பு கோப்பில், பாதைகள் /etc/antimatter-push-proxy உடன் தொடர்புடையவை: எடுத்துக்காட்டாக "AppleAuthKeyFile": "./certs/AuthKey_ABCDE12345.p8" மற்றும் "ServiceFileLocation": "./certs/firebase-service-account.json". பின்னர், Antimatter இல் புஷ் அறிவிப்பு சேவையகம் ஐ http://<proxy host>:8066 என அமைக்கவும். புதுப்பித்த பிறகு, அதை மீண்டும் இயக்கவும்: sudo systemctl restart antimatter-push-proxy.

புஷ் புராக்ஸி 8066 துறையில் அனைத்து முகவரிகளிலும் கேட்கிறது (listens) மற்றும் அதை அழைப்பவரை சரிபார்க்காது. இந்த துறையை தனியார் நெட்வொர்க்கில் வைக்கவும், அல்லது அணுகலை கட்டுப்படுத்தும் ஒரு ரிவர்ஸ் புராக்ஸியின் பின்னால் வைக்கவும்.
