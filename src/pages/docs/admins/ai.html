"OpenAI-compatible" means a server that offers the same HTTP API as OpenAI. Most model servers you can run yourself do (for example Ollama, vLLM, llama.cpp's server, or Whisper and text-to-speech servers), as do many cloud providers. No licence is needed for any of these features.

AI agents

The Agents app (id mattermost-ai) is on by default. Setting it up takes two steps: add a service (a connection to a model provider), then create agents (bots that use a service).

1. Add a service

Go to System Console › Plugins › Agents and, under AI Services, click Add an AI Service. Choose the Service type:

  • OpenAI Compatible: for a model server you run yourself, or any provider with an OpenAI-style API. Fill in API URL (for example http://ollama:11434/v1 or http://vllm.internal:8000/v1), and API Key only if the server needs one. If the server only supports the Chat Completions API, turn Use Responses API off.
  • OpenAI, Anthropic, Google Gemini, Google Vertex AI, AWS Bedrock, Azure, Cohere, Mistral: hosted providers. Each needs its API Key (Bedrock: an AWS region and credentials or an IAM role; Vertex AI: a project, region and service account; Azure: the API URL too).

Then set the Default model (a list when the provider can report its models, otherwise type the name), and, if the provider doesn't report them, the Input token limit and Output token limit. A Fallback Service can take over when this one fails. Save.

The server makes these requests itself, so it must reach the API: a model server in the same compose project, on your network, or on the Internet. Outgoing requests honour the HTTP_PROXY and HTTPS_PROXY variables.

2. Create agents

Agents are created on the Agents page of the web app: open it from the product menu, or with Manage in the agent selector of the Agents panel. Its address is https://chat.example.com/plug/mattermost-ai/agents. Each agent has a Display Name, an Agent Username (how people mention it), a Service and optionally a model, Custom Instructions, and switches for Enable Vision (images) and Enable Tools. Its Access tab limits which channels it can be used in and which users can use it. Under AI Functions in the System Console, Default bot chooses the agent used when none is picked, for example for call summaries.

By default, every user may create their own agents, with the services you configured. To keep that for administrators, remove the permission Manage own AI agents from the members' role in System Console › User Management › Permissions.

Optional features of the Agents app

  • Embedding search (experimental, off): semantic search over messages. It needs PostgreSQL with the pgvector extension and an embedding model (OpenAI or OpenAI-compatible). It sends every message to the embedding model, private channels and direct messages included.
  • Web search (off): lets agents search the web through Google, Brave or a SearXNG server you run.
  • Native tools: with providers that offer them, agents can use the provider's own web search (on by default for new agents, where supported), web fetch and code execution. These run at the provider. Turn them off per agent.
  • Model Context Protocol (MCP): connect agents to MCP servers you trust, for extra tools.
  • Debug: Trace Output (off, server logs or an OpenTelemetry endpoint) and Enable Token Usage Logging, which writes token counts to logs/agents/token_usage.log.

Speech-to-text: call transcripts and captions

Calls can be transcribed, with live captions, by a speech-to-text server that offers an OpenAI-compatible /v1/audio/transcriptions endpoint. The setup is in Calls and voice. With Summarize transcriptions on, the default agent also posts a summary of each transcript.

Text-to-speech: read aloud

With text-to-speech on, every message's menu has Read aloud: the server sends the message's text to a text-to-speech API and plays the audio. Settings, in System Console › Integrations › Text to speech:

SettingKey and variableWhat to put
Read messages aloudTextToSpeechSettings.Enable, AM_TEXTTOSPEECHSETTINGS_ENABLEtrue (off by default)
API base URLTextToSpeechSettings.URL, AM_TEXTTOSPEECHSETTINGS_URLThe base URL up to and including /v1, for example http://tts.internal:8000/v1. The server calls its /audio/speech endpoint.
ModelTextToSpeechSettings.Model, AM_TEXTTOSPEECHSETTINGS_MODELThe model as the API names it, for example tts-1. Required.
VoiceTextToSpeechSettings.Voice, AM_TEXTTOSPEECHSETTINGS_VOICEOne of the model's voices, or empty for its default.
API keyTextToSpeechSettings.APIKey, AM_TEXTTOSPEECHSETTINGS_APIKEYSent as a bearer token. Empty if the API needs none.

Before sending, the server removes code blocks, links, emoji codes and formatting, and keeps at most 4000 characters. It asks for MP3 audio and keeps the last 64 results in memory, so a message read twice is only sent once.

Automatic translation

Automatic translation shows the messages of a channel in each reader's own language. Configure it in System Console › Site Configuration › Localization, under Auto-translation:

SettingKeyDefault
EnableAutoTranslationSettings.Enableoff
Translation providerAutoTranslationSettings.Providerlibretranslate, openai (shown as "OpenAI-compatible API") or agents (a service of the Agents app)
Languages allowedAutoTranslationSettings.TargetLanguagesen: the languages messages can be translated into
Translation timeout (ms)AutoTranslationSettings.TimeoutMs5000
Restrict auto-translation on direct messages and group messagesAutoTranslationSettings.RestrictDMAndGMoff

Each provider has its own fields:

  • LibreTranslate: LibreTranslate API Endpoint and LibreTranslate API Key (AutoTranslationSettings.LibreTranslate.URL, .APIKey). A LibreTranslate server can run on your own network.
  • OpenAI-compatible API: API base URL (up to and including /v1; the server uses its chat completions endpoint), Model and API key (AutoTranslationSettings.OpenAI.URL, .Model, .APIKey). A small translation model run locally works well.
  • Agents: AI Service, one of the services configured in the Agents app.

Once it is on, channel admins turn translation on for a channel in its settings (Auto-translation), and each member can opt out from the channel menu (Translate messages). In direct and group messages any member can turn it on; with the restriction on, translation isn't available there. Translated messages show "Translated from …" with a link to the original.

Code, links, mentions and emoji are replaced by placeholders before the text is sent, and put back afterwards.

To keep all of it on your network, point every feature at servers you run yourself. With a cloud provider, check its data retention terms, and tell your users which features send their messages out.

Turning AI off

There is no single switch: each feature has its own.

  • Agents: disable the Agents app in System Console › Plugins › Plugin Management. This also removes call summaries and the Agents translation provider.
  • Transcription and captions: AM_CALLS_ENABLE_TRANSCRIPTIONS=false and AM_CALLS_ENABLE_LIVE_CAPTIONS=false (the defaults).
  • Read aloud: Read messages aloud off (AM_TEXTTOSPEECHSETTINGS_ENABLE=false, the default).
  • Translation: auto-translation off (AM_AUTOTRANSLATIONSETTINGS_ENABLE=false, the default).

Disabling the Agents app does not turn off the other three: they call their own APIs directly.
