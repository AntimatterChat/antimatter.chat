Install with Docker Compose

This is the recommended way. One compose file runs Antimatter, PostgreSQL, the file storage and the GIF service. You need a Linux server with Docker Engine and its Compose plugin (docker compose), 2 CPU cores and 4 GB of memory or more.

1. Download the compose file

mkdir antimatter && cd antimatter
curl -fsSLO https://antimatter.chat/compose.yaml

2. Create the .env file

The compose file reads its settings from a .env file in the same directory. Create it with random secrets:

cat > .env <<EOF
SITE_URL=http://localhost:8065
POSTGRES_PASSWORD=$(openssl rand -hex 24)
S3_SECRET_KEY=$(openssl rand -hex 24)
GIFS_API_KEY=$(openssl rand -hex 24)
EOF
chmod 600 .env

Set SITE_URL to the address people will type in their browser, for example http://192.168.1.20:8065 on a local network or https://chat.example.com with a domain. Keep the .env file: the database and the storage use these passwords from the first start, and you need the same file to restore a backup.

3. Start it

docker compose up -d
docker compose ps

The first start takes a minute or two: PostgreSQL creates the database, a one-shot bucket service creates the storage bucket, a one-shot gifs-stickers service imports the starter sticker pack, and Antimatter creates its tables. Follow it with docker compose logs -f antimatter.

To use a domain name and HTTPS from the start, see Domain and HTTPS: with the compose file it is two more lines in .env and the https profile.

What runs

PostgreSQL, the storage and the GIF service are on an internal network (private) with no Internet access, which only Antimatter joins. None of them publishes a port.

The Antimatter container keeps nothing on disk: its settings are in the database (AM_CONFIG points at it) and its files and apps are in the storage service. You can remove and recreate the container at any time. Everything to back up is in the postgres, files and gifs volumes, plus your .env.

Choose an image

Two Antimatter images are published, both for linux/amd64 and linux/arm64, and both built from the main branch of every repository:

ImageBundled appsTags
ghcr.io/antimatterchat/antimatterAgents, Calls, GitHub, GitLab, Jira, Kanban, Metrics and Playbooks.latest, X.Y.Z for releases, sha-<commit>
ghcr.io/antimatterchat/antimatter-nextThe same, plus Voice channels, Polls, Mail, Calendar, Notes, Whiteboard, GIFs, Todo and Memes. Rebuilt every night.latest, nightly, nightly-<YYYYMMDD>, sha-<commit>

The site's compose file uses antimatter-next, because the GIF service and most of the apps described on this site are only in that image. To change image, set ANTIMATTER_IMAGE in .env and run docker compose up -d.

latest changes under you. In production, pin a tag such as nightly-20261015 or sha-<commit>, and change it on purpose when you upgrade. The server upgrades its database when it starts, so you can't go back to an older image, or from antimatter-next to antimatter, without restoring a backup taken before. See Backups and upgrades.

Inside the image

  • The server lives in /antimatter, with the binaries antimatter and amctl in /antimatter/bin (on the PATH).
  • It runs as the unprivileged user antimatter (uid 2000) on a minimal distroless base, with no shell.
  • Ports: 8065 (web and API), 8067 (metrics), 8074 (cluster), 8443 UDP and TCP (calls).
  • Local mode (ServiceSettings.EnableLocalMode) is on, so amctl --local works inside the container. The health check runs amctl system status --local.
  • The bundled apps are in /antimatter/prepackaged_plugins, signed with the Antimatter app signing key.
  • Text extraction tools (pdftotext, wvText, unrtf, tidy) are included, so the content of uploaded documents can be searched.

Other compose files

The antimatter-docker repository has a production setup in deploy/compose/: nginx with your own certificates or Let's Encrypt (certbot), PostgreSQL, the optional GIF service (profile gifs) and named volumes for the server's configuration, data and logs, documented in its README. It uses the stable image by default and stores files on a local volume instead of S3 storage. Use it if you prefer nginx to Caddy, or already have certificates.

Create the first administrator

Open SITE_URL in your browser and create an account. The first account created on a new server becomes the system administrator, and the setup then guides you through creating your first community (Antimatter's name for a team or workspace).

Do it right after the first start: until then, anyone who reaches the server first becomes its administrator. To create the account from the command line instead, before the server is reachable from outside:

docker compose exec antimatter amctl --local user create --system-admin --email-verified \
    --email admin@example.com --username admin --password 'a-long-password'
docker compose exec antimatter amctl --local team create --name main --display-name "Main"
docker compose exec antimatter amctl --local team users add main admin

Then sign in at SITE_URL. Start the command with a space to keep the password out of your shell history (with HISTCONTROL=ignorespace), or change the password once signed in.

Next steps once you are in:

  1. Decide who can create accounts: Sign-in and accounts.
  2. Configure email, so invitations and password resets work: Email and push notifications.
  3. Open the calls port in your firewall: Calls and voice.
  4. Check which apps are on: Bundled apps.

Install from a release archive

Without Docker, the server runs from an archive named antimatter-<os>-<arch>.tar.gz (for example antimatter-linux-amd64.tar.gz). It contains a single antimatter/ directory with bin/antimatter, bin/amctl, config/config.json, the web apps (client/ and client-fusion/), the email templates and the translations.

1. Prepare PostgreSQL

Antimatter only supports PostgreSQL, version 15 or newer (older versions start, with an error in the log). Create a user and a database:

sudo -u postgres psql <<'EOF'
CREATE USER antimatter WITH PASSWORD 'a-long-password';
CREATE DATABASE antimatter OWNER antimatter;
EOF

2. Unpack and configure

sudo tar -xzf antimatter-linux-amd64.tar.gz -C /opt
sudo useradd --system --user-group antimatter
sudo mkdir -p /opt/antimatter/data
sudo chown -R antimatter:antimatter /opt/antimatter

Point the server at the database, either in /opt/antimatter/config/config.json (SqlSettings.DataSource) or with environment variables, and set the site URL:

AM_SQLSETTINGS_DRIVERNAME=postgres
AM_SQLSETTINGS_DATASOURCE=postgres://antimatter:a-long-password@localhost:5432/antimatter?sslmode=disable&connect_timeout=10
AM_SERVICESETTINGS_SITEURL=https://chat.example.com

The archive's config.json is a complete default configuration: settings you change in the System Console are saved back to it. To keep the configuration in the database instead, see Configuration.

3. Run it as a service

A systemd unit, in /etc/systemd/system/antimatter.service:

[Unit]
Description=Antimatter
After=network.target postgresql.service

[Service]
Type=notify
User=antimatter
Group=antimatter
WorkingDirectory=/opt/antimatter
ExecStart=/opt/antimatter/bin/antimatter
EnvironmentFile=-/etc/antimatter.env
TimeoutStartSec=3600
Restart=always
RestartSec=10
LimitNOFILE=49152

[Install]
WantedBy=multi-user.target

Put your AM_ variables in /etc/antimatter.env (readable by root only), then:

sudo systemctl daemon-reload
sudo systemctl enable --now antimatter
journalctl -u antimatter -f

The server listens on port 8065. Open http://<server>:8065, or your domain once a reverse proxy is in place (see Domain and HTTPS), and create the first account: it becomes the system administrator.

bin/amctl manages the running server from the command line. On the server itself, it works without signing in through local mode: set AM_SERVICESETTINGS_ENABLELOCALMODE=true, then run sudo -u antimatter /opt/antimatter/bin/amctl --local system status.

Other server commands

Besides running the server (antimatter, or antimatter server), the binary has a few maintenance commands. They read the same configuration as the server.

CommandWhat it does
antimatter versionPrints the version, build number, build date and build hash.
antimatter db pingChecks that the database is reachable.
antimatter db initCreates the configuration in the database (with AM_CONFIG set to a postgres:// URL).
antimatter db migrateApplies the database migrations without starting the server.
antimatter db versionPrints the last migration applied to the database.
antimatter import bulk, antimatter export bulkImports or exports data in the bulk format (see Backups and upgrades).
