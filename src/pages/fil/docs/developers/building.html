Ang mga kailangan mo

  • Go, sa bersyon na nakasa sa server/go.mod (1.26.7 noong panahong ito).
  • Node.js at npm, sa mga bersyon na nakasa sa .nvmrc at webapp/package.json (Node 24.11.1 kasama ang npm 11.6.2). Gamit ang mise, ang mise.toml ng repository ang nag-i-install ng tamang Node.
  • Docker na may Compose: ang setup para sa development ay nagpapatakbo ng PostgreSQL at ilang ibang serbisyo sa mga container.
  • make, git, at isang makina na Linux o macOS.
  • Memory: ang pagbuo ng mga web interface ang pinakamabigat na bahagi. Magplano ng 16 GB ng RAM; tingnan ang Mga Build at Memory.
git clone https://github.com/AntimatterChat/antimatter.git
cd antimatter

Nasa server/ ang server, nasa webapp/ ang mga web interface (Fusion sa webapp/fusion, classic sa webapp/channels, at mga shared package sa webapp/platform), at nasa e2e-tests/ ang mga end-to-end test.

Pagpapatakbo ng development server

cd server
make run

Ang make run ay nagpapa-start ng mga development container (PostgreSQL, Redis, mail catcher, at mga monitoring tool), nag-uugnay ng mga build ng web app sa tamang lugar, nagpapa-start ng server sa background gamit ang go run, at nagpapa-start ng watcher ng web app, na nagre-rebuild ng classic interface habang inu-edit ito. Buksan ang http://localhost:8065 at gumawa ng account: ang unang account ang maging system admin.

Command (sa server/)Ginagawa nito

make restart-serverI-restart ang server pagkatapos magbago ng Go code.
make stopI-stop ang server, ang watcher, at ang mga container.
make debug-serverPumunta sa server gamit ang Delve debugger.
make run-cli ARGS="-version"Pumunta sa command ng server.
make config-resetI-reset ang config/config.json sa mga default.
make clean, make nukeAlisin ang mga build file; ang nuke ay pinaputol din ang mga development data.

Ang development database ay postgres://mmuser:mostest_password@localhost/mattermost_test, ang default na data source ng server. Piliin kung alin sa mga container ang magsisimula gamit ang ENABLED_DOCKER_SERVICES, sa isang server/config.override.mk file o sa iyong environment (tingnan ang server/config.mk).

Ang mga web interface

Sa webapp/:

npm install      # also builds the shared packages
npm run build    # the classic interface, then Fusion

Ang mga build ay nakalagay sa webapp/channels/dist (classic) at webapp/fusion/dist (Fusion). Ang make client sa server/ ay nag-uugnay sa kanila bilang server/client at server/client-fusion, kung saan ipinapasa ng server ang mga ito: ang classic ay nasa /static/, at ang Fusion ay nasa /static/fusion/.

  • Ang npm run run (o make run sa webapp/) ay nagbabantay at nagre-rebuild ng classic interface. Idagdag ang WATCH_FUSION=true upang ma-rebuild din ang Fusion.
  • Ang npm run dev-server (make dev) ay nagpapatakbo ng development server ng webpack sa halip: ang classic ay nasa port 9005, at ang Fusion ay nasa port 9006.
  • Upang makita ang isa sa mga interface sa browser, idagdag ang ?webui=fusion o ?webui=classic sa address ng anumang pahina.

Mga release archive

cd webapp && npm run build && cd ..
cd server
make build-linux       # the antimatter and amctl binaries
make package-linux     # dist/antimatter-linux-amd64.tar.gz and -arm64

Ang make build ay nagbu-build ng mga web interface at Linux binaries sa isang pag-ayos. Ang archive ay naglalaman ng bin/antimatter, bin/amctl, isang default config/config.json, ang dalawang web interface, ang mga template, font, at pagsasalin. Iba pang platform: make package-osx, make package-windows, make package-freebsd. Ang mga archive ay hindi kasama ang mga bundled apps; ang Docker image naman ay kasama.

Ang Docker image

Ang antimatter-docker repository ay nagbu-build ng mga published image, ang server kasama ang mga app, buong-buo sa loob ng Docker:

git clone https://github.com/AntimatterChat/antimatter-docker.git
cd antimatter-docker
scripts/build-all.sh                     # from the main branches on GitHub
SOURCES=local scripts/build-all.sh       # from your checkouts next to this folder
VARIANT=next scripts/build-all.sh        # the "next" image, with every Antimatter app

Kailangan nito ng Docker na may buildx, Python 3, git, at gpg, tungkol sa 16 GB ng RAM at 30 GB ng disk. Ang resulta ay niluload bilang ghcr.io/antimatterchat/antimatter:dev; subukan ito gamit ang ANTIMATTER_IMAGE=ghcr.io/antimatterchat/antimatter:dev docker compose -f compose.local.yml up -d. Ang plugins.json ay naglilista ng mga app at bersyon na nabu-build, at ang README ng repository ay nagpapaliwanag ng mga variant.

Ang build-all.sh ay nagpapa-sign ng mga kasamang app gamit ang Antimatter signing key, at ang image build ay tumatanggi sa mga app na walang sign. Kung wala ang private key na iyon, na mayroon lamang ang mga maintainer, patakbuhin ang mga unang hakbang nang mag-isa: scripts/fetch-sources.sh, scripts/build-plugins.sh (mga app bundle sa out/plugins/) at scripts/build-server.sh (mga server archive sa out/server/).

Mga build at memory

Ang mga web interface ay malalaking webpack build, at ang pagkaubos ng memory ang pinakakaraniwang dahilan ng pagkabigo ng build.

  • Ang npm run build ay nagbu-build ng classic interface at Fusion nang isa-isa, hindi sabay-sabay, upang mabawasan ang peak. Huwag nilang sabay-sabay na patakbuhin.
  • Ang minifier ay nagpapa-start ng isang worker bawat processor. Sa isang makina na maraming core ngunit kaunting memory, limitahan ang mga processor na nakikita ng build: taskset -c 0-5 npm run build.
  • Kung ang Node ay nagkaubos ng heap, itaas ang limit nito: NODE_OPTIONS=--max-old-space-size=6144. Ginagamit ng Docker build ang halong ito (BUILD_NODE_OPTIONS sa build.env).
  • Iwasan ang sabay-sabay na pagtaas ng buong test suite ng server, isang web build, at isang Docker build sa isang maliit na makina.

Mga App

Bawat app (plugin) ay may sariling repository at Makefile; ang make dist ay nagbu-build ng bundle nito. Tingnan ang Build, install at debug.

Desktop app

Ang desktop app ay isang Electron app. Gamit ang Node.js 24 o higit pa:

npm install --allow-git=all
npm run build          # development build, into dist/
npm start              # run it
npm run package:linux  # packages into release/ (also package:windows, package:mac)

Ang mga setting sa oras ng build, tulad ng mga server na preconfigure, ay nasa src/common/config/buildConfig.ts.

Mobile app

Ang mobile app ay isang React Native app; nakatala sa README nito ang mga command (npm run ios, npm run android). Upang mag-build ng sariling kopya, kailangan mo rin ng sariling signing keys, isang Firebase project para sa Android notifications, isang APNs key para sa iOS, at isang push proxy na naglalaman ng mga credential na iyon.
