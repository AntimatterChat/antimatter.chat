Mga paraan upang palawakin ang Antimatter

Piliin ang pinakamagaan na tool na sapat sa gawain. Ang unang apat ay hindi nangangailangan ng access sa server mismo; ang mga app naman ay tumatakbo sa loob nito.

Sa interface, tinatawag ng mga tao ang mga plugin bilang "apps". Sinasabi ng gabay na ito "apps (plugins)" kung saan kapareha ang kapaki-pakinabang ng dalawang salita, dahil ang code, API, at configuration ay nananatiling "plugin".

Pagkakapareho sa Mattermost

Ang Antimatter ay isang fork ng Mattermost. Karamihan sa mga gumagana sa isang Mattermost server ay gumagana rin sa Antimatter.

Ano ang pare-pareho

  • Ang REST API sa ilalim ng /api/v4, ang authentication nito, ang WebSocket, at ang format ng error. Ipinapahiwatig ng server na ang version ay 12.0.0, kaya ang mga client at app na tumitingin sa version ng server ay makikita ang isang makabagong Mattermost.
  • Mga Webhook at slash command, kasama ang kanilang Slack-compatible payloads.
  • Ang server plugin API at hooks: Pinapanatili ng Antimatter ang mga ito sa kanilang kasalukuyang anyo. Ang server code ay nakabuo batay sa parehong Go module, github.com/mattermost/mattermost/server/public. Ang Antimatter lamang ang nagdadagdag ng mga method, para sa kanyang AI service (tingnan ang The AI service).
  • Ang web app plugin registry: bawat register… method ng registry ng Mattermost ay umiiral sa parehong web interface ng Antimatter.
  • Mga client library: ang Go client model.Client4 at ang TypeScript client @mattermost/client (tingnan ang Mga client library).
  • Mga plugin bundle: isang .tar.gz na may plugin.json manifest. Ang mga plugin na firmahan ng key ng Mattermost ay maia-install, pati na rin ang mga firmahan ng key ng Antimatter.

Ang mga pagkakaiba

  • Dalawang web interface. Ang bagong interface, ang Fusion, ang default; ang klasikong interface ng Mattermost ay available pa rin. Ang Fusion ay nagre-render ng karamihan sa mga plugin component, ngunit ilang bahagi nito ay nakalagay sa ibang lugar at may ilang hindi isinasaad. Makakakilala ng app kung alin ang interface ang tumatakbo. Tingnan ang Suporta sa Fusion interface.
  • Extra API. Nagdadagdag ang Antimatter ng mga endpoint para sa kanyang mga sariling feature: community attributes, timeouts, messages on top, message requests, channel at category overrides, channel export, paglipat ng mga thread, model connections, message actions, at mga bagong field sa mga community. Tingnan ang What Antimatter adds to the API.
  • Karagdagang feature ng mensahe. Ang mga attachment ng mensahe ay maaaring ipakita ang mga stage ng pipeline at isang maliit na chart; ang mga post ay maaaring maging inline reply o spoiler.
  • Extra web app hooks para sa mga app: isang "+" menu item sa composer, mga tab sa emoji picker, isang panel sa channel view, isang footer sa ilalim ng mga channel sa sidebar, isang entry sa mga integrations pages, ang add at manage views ng emoji picker, at isang side panel na muling bumubukas sa kung saan ito nasa bagong window. Tingnan ang Hooks only Antimatter has.
  • Walang lisensya. Ang bawat feature ay available nang walang lisensya key. Ang mga endpoint para sa lisensya, trial, at enterprise upgrade ay nawala; ang GET /api/v4/license/client ay nanatili para sa mga client na humihingi. Ang ilang app na nakabuo para sa mga bayad na edisyon ng Mattermost ay nagbabasa ng lisensya sa kanilang sarili at tumatanggi na tumakbo.
  • Mga pangalan. Ang mga Team ay tinatawag na community sa interface, ngunit ang API at ang code ay nananatiling team. Ang mga environment variable ay gumagamit ng AM_ prefix, ang command-line tool ay amctl at ang server binary ay antimatter.

Bago magsimula

  • Kumuha ng test server. Ang pinakamabilis ay ang Docker image: tingnan ang Pag-install ng Antimatter. Para magtrabaho sa Antimatter mismo, tingnan ang Pag-build mula sa source.
  • Suriin kung ano ang pinapayagan ng server. Ilang integration feature ay off sa default at nangangailangan ng system admin: personal access tokens, bot accounts, username at icon overrides, at pag-upload ng mga app. Bawat page ay nagpapakita ng kailangang setting.
  • Alamin ang URL ng iyong site. Ginagamit ng mga halimbawa ang https://chat.example.com. Palitan ito ng address ng iyong server.

Sa gabay na ito

  • Ang REST API: authentication, pangunahing resources, pagination, errors, rate limits, ang WebSocket, client libraries, at mga dagdag ng Antimatter.
  • Mga Webhook: incoming at outgoing webhooks, payloads, attachments at cards.
  • Mga Slash command: custom commands, ang kanilang request at response, autocomplete.
  • Mga Bot at interactive messages: bot accounts, buttons, menus at dialogs.
  • Pagsulat ng mga app: layout ng plugin, server hooks, web app registry, Fusion, mga setting, storage, translations at packaging.
  • Pag-build mula sa source: ang server, mga web interface, ang Docker image at mga app.
  • Pag-contribute: issues, pull requests, style, translations, security at licenses.
Malugod ang mga tanong sa community discussions. I-report ang mga bug sa community issues.
