Saan pamahalaan ang mga webhook

Buksan ang iyong avatar sa itaas na kanang sulok, tapos pindutin ang Mga Integration. Sa mga pahina ng integration ng kasalukuyang community, nakalista ang mga Mga Incoming Webhook at Mga Outgoing Webhook. Bawat webhook ay kabilang sa isang community.

Sa default, ang mga admin ng community at system admin ang makagawa ng webhook. Maaaring bigyan ng karapatan ang ibang mga role ng isang system admin sa mga setting ng permission ng System Console. Maaari ring patayin ng isang system admin ang bawat uri sa System Console › Mga Integration › Pamamahala ng Integration: ang Paganahin ang Incoming Webhooks at Pahintulutan ang mga Outgoing Webhooks ay naka-on sa default.

Paggawa ng incoming webhook

  1. Sa Mga Integration, piliin ang Mga Incoming Webhook, tapos pindutin ang Magdagdag ng Incoming Webhook.
  2. Punan ang Pamagat at Paglalarawan: ito ay ipapakita lamang sa mga pahina ng integration.
  3. Piliin ang Channel na default na destinasyon ng mga mensahe. Para sa pribadong channel, dapat ka ay miyembro nito.
  4. Tikman ang I-lock sa channel na ito kung hindi dapat makapag-post ang mga nagpapadala sa ibang lugar.
  5. Pangalawang, itakda ang Username at Larawan sa Profile URL para sa mga mensahe nito (tingnan ang Pangalan at icon).
  6. Piliin ang I-save. Kopiyahin ang URL na ipinakita: https://chat.example.com/hooks/<key>.
Ang URL ang tanging sekreto: kahit sino na may hawak nito ay makapag-post sa channel. Iwasan ang paglalagay nito sa mga pampublikong repository, at burahin ang webhook kung nalaglag.

Gamit ang API: POST /api/v4/hooks/incoming na may {"channel_id", "display_name", "description", "username", "icon_url", "channel_locked"}; ang id ng tugon ang key. Mula sa command line: amctl webhook create-incoming --channel <channel id> --user <user> --display-name "CI".

Pagpadala ng mensahe sa incoming webhook

curl -X POST https://chat.example.com/hooks/xgh5ycrx1jf7mbs9w8z4c8e7ho \
  -H 'Content-Type: application/json' \
  -d '{"text": "Deploy of **api 2.4.0** finished :white_check_mark:"}'

Sasagutin ng server ang 200 na may body na ok. Tinatanggap din nito ang application/x-www-form-urlencoded na may JSON sa isang payload field, gaya ng ginagawa ng mga webhook ng Slack, kaya karaniwang gumagana ang mga tool na gawa para sa Slack nang walang pagbabago.

FieldKahulugan
textAng mensahe, sa Markdown. Kinakailangan maliban kung may attachments. Ang mas mahaba sa limitasyon ng mensahe ng server ay hahatiin sa ilang mensahe.
channelIba pang channel ng community ng webhook, ayon sa pangalan (ops-alerts o #ops-alerts), o @username para sa Direct Message mula sa may-ari ng webhook. Itatanggihan kung naka-lock ang webhook sa kanyang channel.
username, icon_url, icon_emojiAng pangalan at larawan na ipapakita, kapag pinapayagan ng server ang mga override.
attachmentsMga attachment ng mensahe, na ipinapakita bilang mga card (sa ibaba).
propsMga karagdagang property na nakatago sa mensahe, para sa mga app na babasahin ito.
typeIsang custom na uri ng post, tulad ng custom_poll, para sa isang app na ipinapakita ito. Ang mga uri na nagsisimula sa system_ ay itatanggihan.
root_idAng ID ng unang mensahe ng isang thread, upang sumagot sa thread na iyon.
priorityAng priyoridad ng mensahe, halimbawa {"priority": "urgent"}.
silentAng true ay nagpapadala ng mensahe nang walang push notification.

Ang mga mensahe na ipinapakita sa ilalim ng isang na-override na pangalan ay may BOT tag sa tabi nito, upang maibigay-iba ito mula sa mga tunay na account. Ang mga mensahe ng webhook ay hindi kailanman nagpapatuloy ng outgoing webhooks.

Pangalan at icon

Ang webhook ay nagpo-post bilang ang tao na gumawa nito, maliban kung pinapayagan ng server ang mga override. Dalawang setting sa System Console › Mga Integration › Pamamahala ng Integration, parehong naka-off sa default, ang nagbabago nito:

  • Pahintulutan ang mga integration na palitan ang mga username (ServiceSettings.EnablePostUsernameOverride): ipapakita ang Username ng webhook o ang username ng request; kung wala ang alinman, ang pangalan ay webhook.
  • Pahintulutan ang mga integrations na palitan ang mga profile picture icons (ServiceSettings.EnablePostIconOverride): ipapakita ang Larawan sa Profile ng webhook, o ang icon_url o icon_emoji ng request.

Ang halaga sa request ay mananalo kaysa sa nakatago sa webhook.

Mga Attachment

Ang mga attachment ay nagdaragdag ng structured content sa ilalim ng teksto. Sumusunod sila sa format ng message attachment ng Slack:

{
  "text": "Build failed on `main`",
  "attachments": [{
    "fallback": "main #1902 failed",
    "color": "#d24b4e",
    "author_name": "GitHub Actions",
    "author_icon": "https://chat.example.com/static/ci.png",
    "title": "main #1902 failed",
    "title_link": "https://ci.example.com/runs/1902",
    "text": "Commit `0f4d8e2` by Jonas Weber",
    "fields": [
      {"title": "Branch", "value": "zephyr-3.7", "short": true},
      {"title": "Duration", "value": "3m 40s", "short": true}
    ],
    "footer": "Lumen CI",
    "ts": 1760000000
  }]
}
FieldKahulugan
fallbackPlain text para sa mga lugar na hindi maipakita ang card, tulad ng mga notisikasyon.
colorAng kulay na bar: isang hex color, o good, warning, danger.
pretextTeksto sa itaas ng card.
author_name, author_link, author_iconIsang maliit na header line.
title, title_linkAng pamagat ng card, opsyonal na link.
textAng katawan ng card, sa Markdown.
fieldsIsang listahan ng {"title", "value", "short"}; ang mga short field ay naka-parallel.
image_url, thumb_urlIsang malaking larawan sa ibaba, o isang maliit sa gilid.
footer, footer_icon, tsIsang footer line at oras (Unix seconds).
actionsMga button at menu: tingnan ang Interactive messages.

Mga Card: mga stage at chart

Idinagdag ng Antimatter ang dalawang field sa mga attachment, na ipinapakita ng default interface:

  • stages: ang mga hakbang ng isang pipeline bilang pills, hanggang 20. Ang bawat isa ay {"name", "status"}, na may status na passed, failed, running, pending, skipped o canceled.
  • chart: isang maliit na line chart ng mga kamakailang value, {"values": [2 to 200 numbers], "threshold": number, "label": "…"}. Ang threshold ay ipinapakita bilang dashed line, para sa limit ng isang alert.
{
  "attachments": [{
    "color": "danger",
    "title": "main #1902 failed",
    "stages": [
      {"name": "build", "status": "failed"},
      {"name": "unit", "status": "skipped"},
      {"name": "publish", "status": "skipped"}
    ]
  }, {
    "color": "warning",
    "title": "API latency above 400 ms",
    "chart": {"values": [210, 230, 260, 390, 450, 470], "threshold": 400, "label": "p95 latency, ms"}
  }]
}

Iniiwasan ng classic interface at ibang client ang dalawang field na ito, kaya ilagay ang mga pangunahing impormasyon sa text o fields din.

Gumawa ng outgoing webhook

Sinusubaybayan ng outgoing webhook ang mga pampublikong channel ng isang community. Kapag ang unang salita ng isang mensahe ay tumutugma sa isa sa mga trigger word nito, ipinapadala ng Antimatter ang mensahe sa iyong URL.

  1. Sa Mga Integration, piliin ang Mga Outgoing Webhook, tapos pindutin ang Magdagdag ng Outgoing Webhook.
  2. Punan ang Pamagat at Paglalarawan.
  3. Piliin ang Content Type ng request: application/x-www-form-urlencoded o application/json.
  4. Piliin ang Channel, ilagay ang Mga Trigger Word (Isa Bawat Linya), o pareho. Kung may channel at walang trigger words, ang bawat mensahe ng channel na iyon ay ipapadala. Kung may pareho, ang mensahe ay dapat tumugma sa pareho.
  5. Sa ilalim ng Paggamit ng trigger words, piliin ang Ang unang salita ay eksaktong tumutugma sa trigger word o Nagsisimula ang unang salita sa trigger word.
  6. Ilagay ang Mga Callback URL (Isa sa Bawat Linya). Bawat URL ay makakatanggap ng bawat tumutugmang mensahe.
  7. Pangalawang, itakda ang Username at Larawan sa Profile na gagamitin para sa mga sagot.
  8. Piliin ang I-save at kopiyahin ang token na ipinakita. Ginagamit nito ng iyong service upang suriin na mula sa iyong server ang mga request.

Gamit ang API: POST /api/v4/hooks/outgoing na may {"team_id", "channel_id", "trigger_words", "trigger_when", "callback_urls", "content_type", "display_name"} (trigger_when: 0 para sa exact match, 1 para sa "starts with").

Kung nasa pribadong network ang iyong service, dapat pahintulutan ng system admin ang address nito sa Pahintulutan ang mga untrusted internal connections sa (ServiceSettings.AllowedUntrustedInternalConnections). Hindi tinatawag ng server ang mga pribadong address kung wala ito.

Ang outgoing request

Ipinapadala ng Antimatter ang isang POST na may mga field na ito, bilang JSON o form-encoded depende sa content type:

{
  "token": "6kd1ofo5ojr5zgu5ipfipybgnc",
  "team_id": "…",
  "team_domain": "lumen-labs",
  "channel_id": "…",
  "channel_name": "ops-alerts",
  "timestamp": 1760010000000,
  "user_id": "…",
  "user_name": "priya",
  "post_id": "…",
  "text": "deploy api 2.4.0",
  "trigger_word": "deploy",
  "file_ids": ""
}

Ihambing ang token sa token ng webhook bago gawin ang anumang bagay. Sa form-encoded na bersyon, ang timestamp ay nasa segundo hindi sa millisecond. Hihintayin ng server ang iyong sagot hangga't hihintayin ng Integration request timeout (30 segundo ang default, ServiceSettings.OutgoingIntegrationRequestsTimeout).

Sumagot sa isang outgoing webhook

Para mag-post ng sagot, sagutin gamit ang JSON. Para hindi mag-post ng anumang bagay, sagutin gamit ang empty body.

{
  "text": "Deploying **api 2.4.0** to staging…",
  "response_type": "comment",
  "username": "deploy-bot",
  "icon_url": "https://chat.example.com/static/deploy.png"
}
  • text at attachments: ang sagot. Kung wala ang alinman, hindi magkakaroon ng post.
  • response_type: ang comment ay nagpo-post ng sagot sa thread ng trigger message; kung hindi, ito ay pumapasok sa channel.
  • username, icon_url: ipapakita kapag pinapayagan ng server ang mga override; kung hindi, gagamitin ang sariling values ng webhook.
  • props, type, priority: katulad ng sa mga incoming webhook.

Ang sagot ay nagpo-post bilang tagapaglikha ng webhook, sa ilalim ng overridden na pangalan kung mayroon. Para sa anumang mas mahaba kaysa mabilis na sagot, sagutin agad at mag-post nang huli gamit ang incoming webhook o ang API.

Kapag hindi gumagana ang webhook

  • 501 mula sa hook URL: patay ang mga incoming webhook sa server.
  • 400 "Failed to decode the payload…": hindi valid ang JSON, o hindi tinatawag na payload ang form field. Ang "No text specified." ay nangangahulugang wala sa request ang text o attachments.
  • 403: naka-lock ang webhook sa ibang channel, o hindi na mababasa ng kanyang may-ari ang channel.
  • Hindi kailanman nag-fire ang isang outgoing webhook: pribado ang channel, hindi ang unang salita ang trigger, o mula sa webhook ang nanggaling ng mensahe.
  • Mga Log: kapag naka-on ang Paganahin ang Webhook Debugging (LogSettings.EnableWebhookDebugging) at nasa DEBUG ang log level, naglala-log ang server ng mga payload ng mga nabigong incoming requests. Ang mga nabigong outgoing calls ay nalala-log bilang Outgoing Webhook POST failed.
