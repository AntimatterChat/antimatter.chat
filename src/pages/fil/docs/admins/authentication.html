Sino ang makagawa ng account

Pagkatapos i-install, suriin ang System Console › Authentication › Signup. Sa mga default, ang sinumang may invitation link sa isang community ay makakagawa ng account, ngunit walang makakapag-sign up nang walang ito.

SettingSusiDefaultGinagawa nito
Pahintulutan ang Paglikha ng AccountTeamSettings.EnableUserCreationonKung off, hindi na makakagawa ng account ang sinuman sa anumang paraan; ang mga administrator lang ang makakagawa (System Console o amctl user create).
Pahintulutan ang Open ServerTeamSettings.EnableOpenServerOffKung on, ang sinumang makakarating sa server ay makakapag-sign-up gamit ang email address, nang walang imbitasyon. Gamitin ito lamang para sa mga pampublikong community.
Restrict new system and team members to specified email domainsTeamSettings.RestrictCreationToDomainswalang lamanMga domain na hiwalay sa comma, halimbawa example.com, example.org: ang mga address ng mga domain na ito lamang ang makakagawa ng account.
Pahintulutan ang Email InvitationsServiceSettings.EnableEmailInvitationsoff sa bagong serverPinapayagan ang mga miyembro na mag-imbita ng mga tao gamit ang email (kailangan ng SMTP). Ang I-invalidate ang mga pending na email invitation ay pumuputol sa mga imbitasyon na hindi pa tinatanggap; sa anyo, mag-e-expire ito pagkatapos ng 48 oras.

Ang mga admin ng community ay kontrolin din kung sino ang sumasali sa kanilang community, gamit ang mga invitation link at kanilang sariling pinapayagang domain: tingnan ang Running a community guide.

Mula sa command line: amctl user create (dagdagan ng --system-admin o --guest), amctl user invite, amctl user deactivate, amctl roles system-admin <user> upang gawing system administrator ang isang tao, at amctl roles member <user> upang ibalik ito.

Email at password

Sa System Console › Authentication › Email:

SettingSusiDefault
Paganahin ang paglikha ng account gamit ang emailEmailSettings.EnableSignUpWithEmailon. I-off ito kapag ang lahat ay nag-sign-in gamit ang single sign-on.
Kinakailangan ng Email VerificationEmailSettings.RequireEmailVerificationoff. I-on ito kapag gumagana na ang email: pinapatunayan ng mga tao ang kanilang address bago sila makapag-sign-in.
Paganahin ang sign-in gamit ang emailEmailSettings.EnableSignInWithEmailon
Paganahin ang sign-in gamit ang usernameEmailSettings.EnableSignInWithUsernameon

Sa System Console › Authentication › Password:

SettingSusiDefault
Minimum na haba ng PasswordPasswordSettings.MinimumLength8 (5 hanggang 72)
Mga Kinakailangan ng Password: lowercase, uppercase, numero, simboloPasswordSettings.Lowercase, .Uppercase, .Number, .Symbollahat ay patay
Maximum Login AttemptsServiceSettings.MaximumLoginAttempts10: pagkatapos ng ganitong maraming pagkakamali, nalulock ang account hangga't hindi na-reset ang password nito sa pamamagitan ng email
Pahintulutan ang Forgot Password LinkPasswordSettings.EnableForgotLinkon

Ang haba na 12 o higit pa ay mas epektibo para sa seguridad kaysa sa mga patakaran sa mga karakter. Para i-reset ang password ng isang tao: System Console › User Management › Users, o amctl user change-password <user> --password <new>.

Multi-factor authentication

Ang multi-factor authentication (MFA) ay nagdadagdag ng code mula sa isang authenticator app sa password. Ito ay nakakaapekto sa mga account na nag-sign in gamit ang email o AD/LDAP; sa single sign-on, gamitin ang MFA ng identity provider. Sa System Console › Authentication › MFA:

  • Pahintulutan ang Multi-factor Authentication (ServiceSettings.EnableMultifactorAuthentication, off): maaaring i-on ng mga tao ang MFA sa kanilang mga security settings.
  • Patupad ang Multi-factor Authentication (ServiceSettings.EnforceMultifactorAuthentication, off): dapat itong itakda ng lahat, sa pag-sign up o sa kanilang susunod na sign-in.

Kung nawala ang device ng isang tao: amctl user resetmfa <user>, o i-reset ito mula sa kanilang page sa System Console › User Management › Users.

Single sign-on

Maaaring i-sign in ng Antimatter ang mga tao sa pamamagitan ng iyong identity provider. Sa unang pag-sign in, nililikha nito ang account nila (kung pinapayagan ang paglikha ng account) mula sa pangalan, email, at username na ipinadala ng provider.

OpenID Connect, GitLab, Google, at Entra ID

Pumunta sa System Console › Authentication › OpenID Connect, at piliin sa ilalim ng Piliin ang service provider: GitLab, Google Apps, Entra ID (Office 365) o OpenID Connect (Iba pa) para sa anumang ibang provider (Keycloak, Authentik, Zitadel, Okta, Auth0…).

  1. Sa iyong provider, lumikha ng isang application (isang "client") ng web type, gamit ang redirect URI na ito, para sa URL ng iyong site:
    ProviderRedirect URI
    OpenID Connect (Iba pa)https://chat.example.com/signup/openid/complete
    GitLabhttps://chat.example.com/signup/gitlab/complete
    Googlehttps://chat.example.com/signup/google/complete
    Entra IDhttps://chat.example.com/signup/office365/complete
  2. Sa Antimatter, punan ang Discovery Endpoint (ang /.well-known/openid-configuration URL ng provider; para sa GitLab, ang GitLab Site URL sa halip), ang Client ID at ang Client Secret. Para sa ibang mga provider, pati na rin ang Pangalan ng Button at Kulay ng Button ng sign-in button.
  3. Ang Gumamit ng Preferred Username (GitLab at iba pang provider) ay tumatanggap ng Antimatter username mula sa preferred_username claim ng provider.
  4. I-save, mag-sign out, at subukan ang bagong button sa sign-in page.

Nakala ang mga setting sa OpenIdSettings, GitLabSettings, GoogleSettings o Office365Settings (halimbawa, AM_OPENIDSETTINGS_ENABLE, AM_OPENIDSETTINGS_DISCOVERYENDPOINT, AM_OPENIDSETTINGS_ID, AM_OPENIDSETTINGS_SECRET). Lumalabas lamang ang lumang pahina ng OAuth 2.0 sa mga server na mayroon pa ring OAuth 2.0 GitLab, Google, o Entra ID configuration.

SAML 2.0

Sa System Console › Pagpapatunay › SAML 2.0, i-on ang Paggamitan ang Login gamit ang SAML 2.0 (SamlSettings.Enable) at punan ang mga ibinigay ng iyong identity provider: ang Identity Provider Metadata URL, o ang SAML SSO URL, ang Identity Provider Issuer URL, at ang Identity Provider Public Certificate. Sa side ng identity provider:

  • Service Provider Login URL (assertion consumer service): https://chat.example.com/login/sso/saml;
  • Metadata ng Antimatter, para sa mga provider na nag-i-import nito: https://chat.example.com/api/v4/saml/metadata.

I-map ang mga attribute na ipinapadala ng iyong provider: kahit ang Email Attribute at Username Attribute, at opsyonal ang ID, first at last name, nickname, position, language, guest, at admin attributes. Ang I-verify ang Signature at Paggamitan ang Encryption ay on nang default (kailangan ng encryption ng service provider key at certificate; suportado lamang ang RSA keys); ang I-sign ang Request ay off. Ang default na signature algorithm ay RSAwithSHA256.

AD/LDAP

Sa System Console › Pagpapatunay › AD/LDAP, may step-by-step na pahina na nagkokonekta ng Antimatter sa Active Directory o ibang LDAP server: ang server at port (LdapSettings.LdapServer, LdapSettings.LdapPort, 389 nang default), ang kaligtasan ng koneksyon (wala, TLS, o STARTTLS), ang base DN at isang bind account (BaseDN, BindUsername, BindPassword), mga filter para sa mga user, bisita, admin, at grupo, at ang mga attribute para sa email, username, ID, mga pangalan, at larawan. Ang mga tao ay pumapasok gamit ang kanilang directory login.

May synchronisation job na tumatakbo tuwing 60 minuto (LdapSettings.SyncIntervalMinutes) upang i-update ang mga pangalan at i-deactivate ang mga tao na tinanggal sa directory; patakbun ito ngayon gamit ang amctl ldap sync. Ang mga LDAP group ay maaaring i-link sa mga community at channel sa System Console › Pamamahala ng Mga User › Mga Grupo. Ang mga SAML account ay maaari ring panatilihing naka-sync sa AD/LDAP (Paggamitan ang Synchronizing ng mga SAML Account sa AD/LDAP).

Paglipat ng mga existing na account

Upang palitan ang mga umiiral na email account sa single sign-on, ang amctl user migrate-auth email saml users.json (o ldap) ay naglilipat sa kanila nang bulk. Maaari ring palitan ng isang user ang sarili nilang paraan ng pagpasok sa kanilang mga security setting kapag on ang Pahintulutan ang Paglipat ng Authentication (ServiceSettings.ExperimentalEnableAuthenticationTransfer, sa System Console › Pang-eksperimento › Mga Feature).

Mga Guest account

Ang mga bisita ay mga tao mula sa labas ng iyong organisasyon na nakikita lamang ng mga channel na kanilang inimbitahan. I-enable ang mga ito sa System Console › Pagpapatunay › Access ng Bisita:

SettingSusiDefault
I-enable ang Guest AccessGuestAccountsSettings.EnableOff
Mga Pinapayagang Guest DomainGuestAccountsSettings.RestrictCreationToDomainswalang laman: maaaring mayroong anumang email domain ang mga Bisita
Patupad ang Multi-factor AuthenticationGuestAccountsSettings.EnforceMultifactorAuthenticationoff; available lamang kapag naka-enable at naka-enforce ang MFA para sa lahat
Itago ang guest tagGuestAccountsSettings.HideTagsoff: ipapakita ang "guest" tag sa tabi ng pangalan nila

Kapag naka-on na, imbitahan ng mga community admin ang mga Bisita sa partikular na mga Channel. Maaaring palitan ng Administrators ang isang Miyembro na Bisita gamit ang amctl user demote, at ang isang Bisita na Miyembro gamit ang amctl user promote.

Mga Session

Ang haba ng panahon na mananatili ang mga tao na naka-sign in ay nakabatay sa System Console › Environment › Habang ng Sesyon:

SettingSusiDefault sa isang bagong server
Palawakin ang haba ng session sa pamamagitan ng aktibidadServiceSettings.ExtendSessionLengthWithActivityon: ipapa-update ang mga session habang ginagamit ng mga tao ang Antimatter
Habang ng Sesyon para sa AD/LDAP at Email (oras)ServiceSettings.SessionLengthWebInHours720 oras (30 araw)
Session Length Mobile (oras)ServiceSettings.SessionLengthMobileInHours720 oras
Habang ng SSO Session (oras)ServiceSettings.SessionLengthSSOInHours720 oras
Session Idle Timeout (minuto)ServiceSettings.SessionIdleTimeoutInMinutes43200 minuto (30 araw); ipapakita lamang kapag hindi ipinapa-extend ang mga session gamit ang activity
Tapusin ang mga Session kapag Nagbago ang PasswordServiceSettings.TerminateSessionsOnPasswordChangeon

Para i-sign out ang lahat nang sabay-sabay, gamitin ang Burahin ang Lahat ng Session sa System Console › Pamamahala ng Mga User › Mga User. Para i-sign out ng isang tao, buksan ang kanilang pahina doon.
