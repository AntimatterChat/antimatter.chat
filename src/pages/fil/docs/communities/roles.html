Ang mga built-in na role

Ang bawat community ay may parehong built-in na role. Ang kanilang permiso ay galing sa permission scheme ng server, na maaari lamang baguhin ng system admin.

TungkulinIpinapakita bilangAng maaari nito sa default

Community adminCommunity Admin chipMga setting, mga role, onboarding, layout, at mga koneksyon ng model ng komunidad; pamamahala at pagtanggal ng mga miyembro; pagtanggal ng mga mensahe ng sinumang tao at paglalagay ng mga mensahe sa itaas; pagpapalit ng mga channel sa pribado; pag-archive ng anumang channel ng komunidad, kasama ang mga default na channel; mga webhook at slash command.

Hindi nag-a-archive ng mga channel ang mga miyembro o naglalagay ng mga mensahe sa itaas, maliban kung sila ay mga admin ng channel (tingnan sa ibaba).
BisitaBisita chip at tagLahat ng mga channel na idinagdag sila.
Channel adminChannel Admin chipPamamahala ng isang channel, mga permiso nito, at banner, at paglalagay ng mga mensahe nito sa itaas. Sa isang workplace na komunidad, nag-a-archive din nito. Ang naglikha ng channel ay unang admin nito.

Ang ilang default ay nakadepende sa uri ng komunidad, na pinili ng mga admin ng komunidad sa Mga setting ng team › Mga Channel (tingnan ang Uri ng komunidad):

  • Sa isang Komunidad, ang default na uri, ang mga admin ng komunidad at mga role na may Pamahalaan ang mga channel lamang ang nag-a-archive ng mga channel. Hindi nag-a-archive ang mga miyembro, kahit sa mga channel na kanilang nilikha.
  • Sa isang Workplace, ang workspace ng isang kumpanya o organisasyon, ang mga admin ng channel din ang nag-a-archive nito: ang naglikha nito at ang mga taong ginawa nilang admin nito.
  • Sa parehong uri, ang mga admin ng channel, mga admin ng komunidad, at mga moderator na may Pamahalaan ang mga mensahe lamang ang naglalagay ng mga mensahe sa itaas o tinatanggal ang mga ito.

Sa parehong uri, nagpapalit pa rin ng pangalan ng mga channel na kanilang nasa loob ang mga miyembro at nagpapa-mane ng mga miyembro nito. Kung gusto mong mas mababa ang gawain ng mga miyembro, humingi sa iyong system admin na i-ajust ang mga permiso ng iyong komunidad sa System Console › Pamamahala ng Mga User › Mga Permiso, kung saan maaaring mag-apply ang Team Override Scheme sa iyong komunidad lamang.

Gawing community admin ang isang tao

  1. Buksan ang menu ng community at piliin ang Pamahalaan ang mga miyembro.
  2. Hanapin ang tao, buksan ang menu sa tabi ng kanyang role, at piliin ang Gawing Team Admin. (Ang dialog na ito ay nananatiling nagsasabi ng "team" para sa community.)

Upang kunin ang role, piliin ang Gawing Miyembro ng Team. Ang mga community admin at system admin lamang ang maaari gawin ito: walang custom role na maaaring gawing community admin ang isang tao.

Panatilihin ang hindi bababa sa dalawang community admin, upang hindi mahina ang community kung ang isa sa kanila ay aalis.

Mga custom role

Ang mga custom role ay mga role na nilikha mo para sa iyong komunidad, tulad ng "Moderators", "Staff", "Beta testers", at "Contributors". Maaaring bigyan ng isang kulay, sariling grupo sa listahan ng mga miyembro, at mga permiso ang isang role. Maaari ring ma-mention ang bawat role, na nagpapahiwatig sa lahat ng mayroon rito.

Ang mga role ay pinapa-mane sa tab ng Mga role… ng mga setting ng komunidad. Para buksan ito, buksan ang menu ng komunidad, piliin ang Setup ng team, tapos ang Mga role…; maaari ring buksan ng mga admin ng komunidad ang Mga setting ng team at piliin ang tab ng Mga role…. Nakikita ang item na ito ng mga admin ng komunidad at mga taong may permiso ng Pamahalaan ang mga role; nakikita ng mga taong nagpapa-mane ng mga role ngunit hindi ng komunidad ang tab ng Mga role… lamang. Ang mga pagbabago sa tab na ito ay na-save habang ginagawa nila, na may I-save at Kanselahin sa editor ng role; ang Isara ay nagse-close ng mga setting.

Gumawa ng role

  1. Sa tab ng Mga role…, piliin ang Gumawa ng role.
  2. Maglagay ng Pangalan.
  3. Pumili ng Kulay, o mag-type ng kulay code.
  4. Iwanan ang Ipakita ang mga miyembro nang hiwalay kung ang mga online na miyembro ng role ay dapat may sariling grupo sa listahan ng miyembro.
  5. I-on ang Maaaring kunin ng sinuman kung maaari ng mga miyembro na bigyan ang sarili ng role na ito (tingnan ang Mga role na maaaring kunin ng sinuman).
  6. I-on ang mga Mga Permiso na ibibigay ng role (tingnan ang talahanan sa ibaba).
  7. Sa ilalim ng Mga Miyembro, magdagdag ng mga tao gamit ang Magdagdag ng mga tao mula sa team….
  8. Piliin ang Gumawa ng role.

Sa listahan ng mga role, ang Ilipat pataas at Ilipat pababa ay nagtatakda ng pagkakasunod. Mahalaga ang pagkakasunod: ang pinakamataas na role ng isang tao ang nagtatakda ng kulay ng pangalan nito, at ito ang nagdedesisyon kung sino ang maaari niyang pamahalaan (tingnan ang Ang pagkakasunod ng mga role). Ang Burahin ang role ay agad na nagbubura nito, nang walang hinihingi na pagpapatibay.

  • Kapag ino-on ang Administrator, ipapakita ng role editor ang ibang mga switch: ang role ay makakatanggap ng lahat ng hawak ng mga admin ng komunidad, kabilang ang Pamahalaan ang mga role, Mag-alis ng mga tao, at Pamahalaan ang mga koneksyon ng model. Hindi ito ibibigay ang mga maaari lamang gawin ng mga system admin, tulad ng pagbabago ng mga permission scheme. Ang mga role na may Administrator bago ang upgrade sa 0.9.0 ay nakatanggap ng parehong mga pahintulot nang isang beses.
  • Ang role ay maaari lamang magdagdag ng mga permiso. Ang Mag-imbita ng mga Tao at ang dalawang Gumawa switches ay bigyan na sa bawat miyembro sa default, kaya mahalaga lamang ito kung inalis ng system admin ang mga ito mula sa mga miyembro.
  • Ang hindi admin ng team ay maaari lamang bigyan ng role ang mga permiso na mayroon sila mismo.

Isang role ng moderator

Para sa isang pampublikong komunidad, ang karaniwang role na "Moderators" ay may Pamahalaan ang mga mensahe, Mag-alis ng mga tao, at Pamahalaan ang mga channel, at ipinapakita nang hiwalay na may sariling kulay. Ang role na "Moderators" na nilikha ng mga layout preset ay maaaring mag-edit at mag-delete ng mga mensahe ng ibang tao, ilagay ang mga mensahe sa itaas, palitan ang pangalan ng mga channel, pamahalaan ang kanilang mga miyembro, at alisin at i-time out ang mga tao. Hindi ito nag-a-archive ng mga channel: i-on ang Pamahalaan ang mga channel kung gusto mong gawin ito ng mga moderator. Ang mga preset role na nilikha bago ang upgrade sa 0.9.0 ay kulang sa Mag-alis ng mga tao; idinagdag nito ito nang isang beses sa mga hindi pa binago ang mga pahintulot.

Ang pagkakasunod-sunod ng mga role

Ang mga role ay nakasunod-sunod ayon sa kanilang posisyon sa listahan, ang pinakamataas muna:

  • Ang mga may Pamahalaan ang mga role ay maaari lamang mag-edit, mag-move, at magbigay ng mga role na nasa ilalim ng kanilang pinakamataas na role, at lumikha ng mga bagong role sa ilalim nito.
  • Ang mga may Mag-alis ng mga tao ay maaari lamang mag-time out ng mga tao na ang pinakamataas na role ay nasa ilalim ng kanilang sarili.
  • Ang mga role na maaaring kunin ng sinuman ay hindi binibigyan ng rank.
  • Nasa itaas ng lahat ng role ang mga admin ng komunidad. Hindi sila maaaring ma-time out.
Ang rank ay tumutukoy din sa pag-aalis: ang may Mag-alis ng mga tao ay maaari lamang mag-alis ng mga tao na nasa mas mababang role kaysa sa kanilang pinakamataas na role, mula sa komunidad o mula sa channel, at hindi kailanman ang admin ng komunidad.

Pagbibigay ng role sa isang tao

May tatlong paraan:

  • Sa tab na Mga Role, i-edit ang role at dagdagan ang tao sa ilalim ng Mga Miyembro.
  • Sa mod view ng tao, sa seksyon ng Mga Role, gamitin ang Magdagdag ng role, o ang × sa isang role upang alisin ito (tingnan ang The mod view).
  • Sa pamamagitan ng onboarding, para sa mga role na maaaring kunin ng sinuman (tingnan ang Onboarding).

Ang mga miyembro ng komunidad lamang ang maaaring magkaroon ng mga role nito. Ang taong umalis sa komunidad ay mawawala ang mga role nito, at hindi na naman ito makuha ulit kapag bumalik.

Mga role na maaaring kunin ng sinuman

Ang role na may Maaaring kunin ng sinuman ay bukas sa lahat: ang mga miyembro ay magpapa-apply nito sa kanilang sarili, o aalisin ito, mula sa menu ng komunidad sa ilalim ng Ang iyong mga role…. Lumalabas lamang ang item na ito kapag may mga ganitong role ang komunidad. Gamitin ito para sa mga interes o grupo ng notisikasyon, halimbawa "Announcements", "Linux users", o "Paris meetups", na maaaring ma-mention ng mga tao.

Ang role na maaaring kunin ng sinuman ay nagbibigay pa rin ng mga permission nito sa sinumang kukuha nito. Huwag i-on ang mga permission sa ganitong role maliban kung gusto mong may mga iton ang bawat miyembro.

Mga kulay, grupo, at badge

Sa tab na Mga Role, ang mga admin ng komunidad ay may mga opsyon na ito para sa buong komunidad:

  • Mga kulay ng role: ang mga pangalan ay kinukuha ang kulay ng pinakamataas na role ng tao. On ito nang default.
  • Nagpapakita ang lahat ng badge ng team: ang mga taong hindi nagpili ng badge ay ipinapakita ang tag ng kanilang unang team sa komunidad na ito. Off ito nang default; makatutulong ito sa isang kumpanya, kung saan ang badge ay nagpapakita kung saang departamento ang nagtatrabaho ng tao.
  • Listahan ng mga miyembro: kung paano pinag-uugnay ng listahan ng miyembro ang mga miyembro ng komunidad: Ayon sa mga role, Ayoon sa team, o Bigyan ang mga miyembro ng pagpili (default).

Sa listahan ng mga miyembro, ang bawat role na ipinapakita nang hiwalay ay may sariling pangkat ng mga online na miyembro, ang pinakamataas na role muna. Kapag walang role ang ipinapakita nang hiwalay, ang listahan ay nagpapakalat ng mga admin at moderator sa ilalim ng Admin at Mga Moderator. Sa pamamagitan ng Bigyan ang mga miyembro ng pagpili, maaaring palitan ng mga miyembro ang listahan mula sa Mga Role patungo sa Mga Team; sa ibang dalawang opsyon, walang switch sa listahan. Maaaring patayin ng isang system admin ang pagpapakalat ayon sa role sa buong server, gamit ang Iugnay ang mga miyembro ayon sa role sa System Console, at ang setting na ito ang may pinakamataas na awtoridad.

Mga team sa loob ng isang community

Sa Antimatter, ang team ay isang pangkat ng mga tao sa loob ng isang community, tulad ng isang departamento, proyekto, o pangkat ng trabaho. May pangalan ang team na maaaring ma-mention, maikling tag (hanggang 8 karakter, halimbawa "DET"), lead, deskripsyon, at channel ng team. Maaaring ipakita ng mga miyembro ang tag ng isa sa kanilang mga team sa tabi ng kanilang pangalan.

Gumawa ng team

  1. Buksan ang menu ng community at piliin ang Mga grupo ng user…. Ang dialog na bumubukas ay nananatiling "User Groups".
  2. Piliin ang Gumawa ng Group, ilagay ang pangalan ng team at ang pangalan para sa mention, dagdagan ang mga miyembro nito, at gumawa nito.
  3. Upang itakda ang tag, lead, at channel nito, pindutin ang tag ng team sa tabi ng pangalan ng isa sa mga miyembro nito upang buksan ang card nito, tapos piliin ang I-edit ang team. Punan ang Tag, Lead, Channel ng team, at Ang ginagawa ng team, at i-save.

Ang mga admin ng community at mga taong may Pamahalaan ang mga role ang gumagawa at nag-e-edit ng mga team. Walang karagdagang karapatan ang lead: pangkalimbagan lamang ang titulo. Ang bawat miyembro ang pumipili kung aling team badge ang ipapakita, sa mga setting nito sa ilalim ng Ang aking account, Team badge.

Maaaring i-group ng listahan ng mga miyembro ang mga tao ayon sa team: piliin ang Mga Team sa ilalim ng Ipangkat ang mga miyembro ayon sa sa itaas ng listahan, maliban kung nakafix na ng mga community admin ang pagpapakalat sa tab ng Mga Role.

Mga karapatan sa isang channel

Ang mga role ay nakaka-apply sa bawat channel ng community. Para bigyan ang isang role ng mas marami o mas kaunting karapatan sa isang channel o isang kategorya, gamitin ang mga karapatan ng channel: tingnan ang Mga karapatan ng channel. Maaari ring panatilihin ang isang pribadong channel para sa ilang role lamang: ang mga miyembro nito ay masusunod ang mga role nang awtomatiko.
