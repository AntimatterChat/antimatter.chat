Ang mga app ng iyong mga miyembro

May kasamang set ng apps ang Antimatter. Maliban kung pinatanggal ng isang system admin ang ilang bahagi, bawat komunidad sa server ay may mga ito:

AppGinagawa nito
Tawag at Voice ChannelsTawag sa anumang channel, at voice channels: palaging bukas na tawag na pumasok at lumabas ang mga tao.
PollPoll sa usapan, na may live results, anonymous votes at end time. Ang /poll ang gumagawa nito.
To-doMga to-do list na nakabahagi sa bawat channel at usapan, gaano karami man ang kailangan, at mga personal na listahan.
TalaMga dokumentong pinagsasama-samang in-edit sa real time, na ibinabahagi sa isang channel o pinapanatili bilang personal.
WhiteboardMga whiteboard na ibinabahagi sa isang channel o pinapanatili bilang personal.
KanbanMga board ng mga card sa mga column, naka-link sa mga channel. Ang Kanban ay buksan sa kanyang side panel; ang isang board ay palawakin ang panel.
PlaybooksMga checklist para sa mga paulit-ulit na proseso, na ginagawa sa isang channel, sa side panel ng Playbooks.
GIF at MemesIsang GIF at sticker picker, at mga memes na gawa mula sa mga template, sa emoji picker.
Kalendaryo at MailAng sariling kalendaryo at mailbox ng bawat tao, na nakakonekta sa kanilang sariling mga account.
Mga AgentMga AI assistant, kapag may naka-setup na AI model ang server.
GitHub, GitLab, at JiraMga notisikasyon at mga utos para sa mga serbisyo na ito, pagkatapos ito ay nakakonekta.

Karamihan ng mga app ay binubuksan mula sa app bar, ang hanay ng mga icon sa kanang gilid ng window. I-on o i-off ang mga app para sa buong server sa System Console › Mga Plugin: hindi maaaring i-on o i-off ng isang community admin ang isang app para sa iisang community lang. Server-wide din ang mga setting nito, maliban kung sinasabi ng pahinang ito na hindi. Para magdagdag ng app o baguhin ang mga setting nito, humingi ng tulong sa inyong system admin.

Sa loob ng isang community, sumusunod ang mga app sa mga permiso ng mga channel: halimbawa, ang mga taong mababasa lamang ng isang channel ay makikita ang mga to-do list at tala nito ngunit hindi nila maaaring baguhin, at ang mga admin ng channel ay maaaring burahin ang mga tala nito. Ang mga admin at mga taong may Pamahalaan ang mga mensahe ay maaaring isara ang anumang poll sa channel.

Ang mga to-do list ng isang channel ay pag-aari ng mga miyembro nito: ang bawat taong maaaring mag-post sa channel ay magdadagdag at markahan ang mga to-do, at gagawan ng bagong pangalan o i-archive ang isang listahan. Ang listahan ay baburahin ng naglikha nito, at ang isang to-do ay ng nagdagdag nito, o ng mga admin ng channel, ng mga admin ng community, at ng mga system admin: hindi mabubura ng ibang miyembro, kahit maaari nilang palitan ang pangalan ng channel. Sa isang archived o read-only channel, mababasa lamang ang mga listahan. Ang mga bisita ay magpadala ng to-do lamang sa mga taong may kasamang channel.

Custom emoji

Ang mga custom emoji ay mga larawang ginagamit ng mga tao sa mga mensahe at reaksyon tulad ng anumang ibang emoji, sa pamamagitan ng pag-type ng pangalan nito sa pagitan ng mga colon, tulad ng :party_parrot:.

  1. Buksan ang emoji picker (sa message box, sa mga reaksyon ng isang mensahe, o para sa iyong status).
  2. Piliin ang + (Magdagdag ng custom emoji) sa tabi ng search box. Ipinapakita ng picker ang kanyang add view.
  3. I-drop, i-paste, o piliin ang isang imahe: PNG, GIF (animado rin), JPEG, o WebP, hanggang 512 KB at 1028 × 1028 pixels. Ipinapakita ng picker ang preview nito sa mga sukat na ipinapakita ang mga emoji.
  4. Bigyan ito ng pangalan: lowercase na mga letra, numero, at -, +, o _, hanggang 64 na karakter. Sabihin agad ng picker kung kinuha na ang pangalan o standard na emoji.
  5. Piliin ang I-save. Ang bagong emoji ay nasa unahan sa picker, sa ilalim ng Just added.

Ang Custom emoji button sa tabi ng + ay nakalista ang mga custom emoji ng server, na may search box, sinuman ang nagdagdag ng bawat isa at kailan, at isang delete button sa mga maaari mong burahin. Ang parehong listahan ay nasa Integrations › Custom emoji.

  • Ang custom emoji ay para sa buong server, hindi sa isang community: maaari silang gamitin ng lahat sa server. Pumili ng mga pangalan na hindi magkakaroon ng pagkakasalo sa emoji ng ibang community.
  • Sa pamamagitan ng default, ang bawat miyembro ay maaaring magdagdag ng custom emoji; hindi maaaring magdagdag o mabura ng mga bisita. Maaaring burahin ng mga tao ang kanilang sarili; ang mga system admin lamang ang maaaring burahin ang emoji ng ibang tao, kaya humingi sa isa para alisin ang hindi gustong emoji. Maaaring baguhin ng isang system admin ito sa mga permiso ng server, o patayin ang custom emoji gamit ang Pahintulutan ang Custom Emoji sa System Console.

Mga GIF, sticker, at meme

May mga tab para sa GIFs, Stickers, at Memes ang emoji picker kapag aktibo ang mga app na ito.

  • Ang GIF at stickers ay mula sa GIF service na pinili ng system admin, na may content rating na itinakda ng system admin. Kapag pinayagan ng system admin, maaaring magdagdag ng sarili nilang GIF at stickers ang mga tao. Sa default, ang mga system admin lang ang maaari; maaaring buksan ng system admin ito sa lahat maliban sa mga bisita (Ang maaaring magdagdag ng GIF at stickers). Sa mga tab ng GIF at Stickers, ang + sa tabi ng search box ay buksan ang add view (Magdagdag ng GIF, Magdagdag ng sticker) at ang manage button (Mag-manage ng GIF, Mag-manage ng stickers) ay maglilista ng mga naidagdag, kasama kung sino at kailan. Ang Custom GIF at Custom stickers sa mga integrations pages ay gumagana rin. Ang mga naidagdag na GIF at stickers ay available sa lahat sa server; ang nagdagdag, at ang mga system admin, ay maaari itong burahin.
  • Memes: pumipili ng template sa Memes tab ang sinumang tao, sumusulat ng captions, at nagpo-post ng meme. Gumagana rin ang /meme. Sa default, maaaring magdagdag ng meme template ang lahat maliban sa mga bisita gamit ang + sa tabi ng search box ng Memes tab, at ang manage button ay maglilista ng mga custom template kasama kung sino ang nagdagdag at kailan. Maaaring limitahan ng system admin ito sa mga system admin, o pumili ng Wala (custom templates off): ang mga template na naidagdag na ay mananatiling gamitin. Ang mga template ay ibinahagi ng buong server, at ang mga tagalikha at system admin lang ang maaari itong burahin.

Sa isang pampublikong community, isipin ang paghingi sa iyong system admin na panatilihing para sa mga admin lamang ang mga upload ng GIFs at meme templates.

Mga library ng Whiteboard

Maaari ng mga community admin magdagdag ng mga shape library para sa lahat sa community: sa isang whiteboard, buksan ang menu ng board o ang library panel at piliin ang Manage libraries. Ang isang library ay isang .excalidrawlib file na hanggang 5 MB.

Mga Webhook, slash command, at bot

Pinag-uugnay ng mga integrations ang iyong community sa ibang mga tool: isang monitoring system na nagpo-post ng mga alert, isang form na nagpo-post ng mga sagot, isang command na naglilingkod ng impormasyon. Upang itayo, i-click ang iyong avatar at piliin ang Integrations. Makikita mo ang mga uri ng integrations na karapatan mong pamahalaan:

IntegrationsGinagawa nitoSino ang maaaring lumikha nito, sa default
Mga Incoming WebhookI-post ng ibang serbisyo ang mga mensahe sa isang channel sa pamamagitan ng pagtawag sa isang secret URL.Mga community admin
Mga Outgoing WebhookAng mga mensahe na may trigger word sa isang channel ay ipinapadala sa ibang service, na maaaring sumagot. O isang message action: ipinapadala ng mga tao ang isang mensahe sa service mula sa menu ng mensahe.Mga community admin
Mga Slash CommandAng isang command tulad ng /weather ay tumatawag sa ibang serbisyo, na sumasagot sa channel.Mga community admin
Mga Bot accountMga account para sa mga program, na nagpo-post gamit ang kanilang sariling pangalan at may Bot tag.Mga system admin
Mga OAuth 2.0 appMga app na pumapasok ng mga tao gamit ang kanilang Antimatter account.Mga system admin

Mga aksyon sa mensahe

Ang isang outgoing webhook na Paggamit ng trigger words ay Mula sa menu ng mensahe ay hindi tumutugon sa mga na-post na mensahe. Nagiging aksyon ito sa menu ng mga mensahe, sa ilalim ng Mga Karagdagang Aksyon, sa isang Mga Integration group: kapag pinili, ipinapadala ang iisang mensahong iyon sa service, na maaaring sagutin sa channel o sa tao lang. Bigyan ito ng title (pangalan ng aksyon sa menu) at, kung gusto, isang Icon: isang image URL o isang na-upload na image, na ipinapakita sa kulay abo. I-bind ito sa isang pampublikong channel, o iwan ang channel na walang laman upang ipakita ito sa bawat pampublikong channel ng community. Kapag na-archive ang isang channel, mabubura ang mga webhook na nakabind dito, kaya ang archived channel ay mananatili lamang sa mga community-wide na aksyon. Nakikita ng mga bisita lamang ang mga aksyon na nakabind sa isang channel na sila ay nasa loob.

Ang custom role na may Pamahalaan ang mga integration ay nagpapahintulot sa iba na pamahalaan din ang mga webhook at slash command (tingnan ang Roles and permissions). Ang mga webhook at slash command ay kinalaman ng community kung saan nila ito nilikha.

Kailangang i-on ng system admin ang bawat uri ng integration sa System Console › Mga Integration › Pamamahala ng Integration. On sa default ang mga incoming at outgoing webhook at slash command; off ang paglikha ng bot accounts. Gamitin ang URL ng webhook at token ng command bilang password: ang sinumang may mga ito ay maaaring mag-post sa inyong community.

Para gumawa ng integration, bot, o app, tingnan ang Building on Antimatter.

Autolinks

Ang mga autolink ay nagbabago ng text tulad ng mga issue number na naging link sa bawat mensahe ng inyong community, nang walang app na kailangang i-install. Ipinapatakbo ng mga community admin sa Mga setting ng team › Mga autolink; tingnan ang Mga autolink.

Playbooks

Ang playbook ay isang checklist para sa isang proseso na paulit-ulit: paghahanda ng isang incident, onboarding ng bagong kasamahan, paghahanda ng isang release. Bawat pagsimula ng proseso, pinapa-run ang playbook: nililikha o ginagamit ng Antimatter ang isang channel para sa run, kung saan nakatira ang checklist, ang kanyang may-ari, at ang mga update ng status.

Buksan ang mga Playbook mula sa app bar: ang side panel nito ay nagpapakita ng mga run at checklist ng channel. Ang button sa itaas ng panel (Browse runs, playbooks and tasks) ay nagbubukas ng browse view, na may All runs, All playbooks, at Your tasks, kung saan maaari mong gumawa ng playbook (Create playbook) o mag-import ng isa. Naglalaan ang playbook editor ng panel habang bukas ito. Ang Channel automation… entry ng isang channel, sa menu nito, ay nagse-set ng welcome message, kategorya para sa mga bagong sumali, at mga mungkahi ng playbook base sa mga keyword.

Ang mga Playbook ay kinalakihan ng isang community. Sa default, ang sinumang makagawa ng channel ay makagawa rin ng playbook, kaya sa praktikal na antas, ang bawat miyembro ay maaari. Maaaring pampubliko sa community ang isang playbook o itago lamang para sa mga miyembro nito.

Mga magandang playbook para sa isang community: pagpapagandang ng bagong moderator, paglilipat ng isang report, paghahanda ng isang kaganapan. Para sa isang organisasyon: incident response, pagdating at pag-alis ng isang empleyado.
