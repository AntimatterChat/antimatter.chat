Buksan ang mga setting ng komunidad

Buksan ang menu ng community: i-click ang pangalan ng community sa itaas ng listahan ng mga channel, o i-right-click ang icon nito sa community rail. Pagkatapos, piliin ang Mga setting ng team. Nakikita lamang ang item na ito ng mga admin ng community, mga taong may role na may Administrator, at mga system admin.

Ang mga entry sa ilalim ng Setup ng team sa menu ng community (Mga role…, Onboarding…, Layout ng team…, Mga attribute ng miyembro…, at Mga koneksyon ng model…) ay buksan ang parehong dialog sa angkop na tab. Nakikita lamang ng mga taong nagmamanihala lamang ng mga role, o ng mga koneksyon ng model ng community, ang mga tab na iyon lamang.

May mga tab na ito ang dialog ng mga setting:

Ang tab na Onboarding ay may sariling I-save at Kanselahin na pindutan. Sa mga tab na Mga role, Mga attribute ng miyembro, at Layout ng team, ang mga pagbabago ay naa-save habang ginagawa mo, may I-save at Kanselahin sa kanilang mga editor, at ang Isara ang nagse-seseal ng dialog. Kung may hindi naa-save na pagbabago sa isang tab, bababala ka ng Antimatter bago ka magpalit ng tab o isara ang dialog.

May mga tab na galing sa classic interface at nananatiling nagsasabi ng "team": "Team Name", "Public Team", "Team Icon". Sa Antimatter, pareho ang team at komunidad.

Pangalan, deskripsyon at icon

Sa tab na Pangkalahatang-ideya:

  • Ang Pangalan ng Team ay ang pangalan na ipinapakita sa community rail at sa itaas ng listahan ng mga channel. Maaari itong magkaroon ng 2 hanggang 64 na karakter.
  • Ang Paglalarawan ay tumutulong sa mga tao na piliin ang tamang community kapag tinatadpo nila ang mga makakapag-join. Maaari itong magkaroon ng hanggang 50 na karakter.
  • Ang Team Icon ang larawan sa community rail: isang BMP, JPG, o PNG file. Kung wala ito, ipapakita ng rail ang mga initial ng community. Tinatanggal agad nito ng Alisin ang larawan ito.

I-save ang iyong mga pagbabago gamit ang bar sa ibaba ng dialog. Ang address ng komunidad (ang bahagi ng URL pagkatapos ng pangalan ng server) ay napipili kapag nilikha ang komunidad at hindi na maaaring baguhin pagkatapos.

Sino ang makakapag-join

Sa tab na Access:

  • Pagkakakilanlan: Ang Pampublikong Team ay lumalabas sa listahan ng mga community na maaaring tingnan at sumali ng sinumang may account sa server. Ang Pribadong Team ay maaari lang sumali gamit ang imbitasyon. Kapag nagbago mula pampubliko tungo sa pribado, lumilikha ng bagong invitation link at nawawala ang epekto ng lumang isa.
  • Allow only users with a specific email domain to join this team: kapag nakacheck ito, maaari lamang pumasali ang mga taong ang kanilang email address ay nagtatapos sa isa sa mga domain na iyong nakalista, halimbawa example.org. Hiwalayin ang maraming domain gamit ang puwang o koma. Angkop ito sa workspace ng kumpanya; iwan itong off para sa pampublikong komunidad.
  • Invite Code: ang code sa invitation link ng community. Lumilikha ng bagong link ang I-regenerate at nawawala ang epekto ng nakaraang isa. Gawin ito kung na-share ang invitation link sa lugar na hindi dapat.

Kung ang mga miyembro ng komunidad ay galing sa mga linked group (isang directory tulad ng LDAP, na inu-setup ng isang system admin), sinasabi nito ng Access tab, at ang mga pagpipilian na ito ay pinapalit ng group sync.

Ang pagpapasali ay nakadepende rin sa paraan ng pag-configure ng server: kung maaari man ng mga tao na gumawa ng account, at mula sa aling mga domain ng email. Ang mga ito ay mga setting ng server; tanungin ang iyong system admin (tingnan ang What to ask your system admin).

Wala sa mga community ang limitasyon sa bilang ng miyembro sa default. Maaari ng system admin na itakda ito para sa bawat community sa server (Pinakamataas na Miyembro Bawat Community, nasa System Console › Konfigurasyon ng Site › Mga User at Team); kapag naabot na ng community ang limit, hindi na maaari ang iba na sumali hangga't may umalis.

Uri ng community

Sa tab ng Mga Channel, ipinapaliwanag ng Uri ng community sa Antimatter kung paano pinamamahalaan ang iyong community. Ito ay na-save agad pagbaguhin mo ito.

UriPara saAnong nagbabago
KomunidadIsang pampubliko o hobby community.Ang mga admin ng community, at mga role na may Pamahalaan ang mga channel lamang, ang nag-a-archive ng mga channel. Ang mga tawag ay off sa default sa mga channel nito: ang mga voice channel ay para sa pag-usap.
WorkplaceWorkspace ng isang kumpanya o organisasyon.Ang mga admin ng channel (ang naglikha nito, at ang mga tao na ginawa nilang admin) ay nag-a-archive din nito. Ang mga tawag sa mga channel nito ay sumusunod sa default ng Calls sa server, na on maliban kung binago ito ng iyong system admin.

Sa parehong uri, ang mga admin ng channel, mga admin ng community, at mga moderator na may Pamahalaan ang mga mensahe lamang ang nagpapatong ng mga mensahe. Ang channel na may sariling setting sa Calls ay pananatili ito, at hindi naaapektuhan ng uri ang mga direct at group messages.

Ang mga bagong community ay ng uri na pinili ng system admin para sa server (Uri ng mga bagong community, na Komunidad maliban kung binago). Ang pag-apply ng layout preset ay nagtatakda rin ng uri: ang Hybrid at Komunidad ay nagkakaroon ng community, ang Workplace ay nagkakaroon ng workplace (tingnan ang Community layout). Ang template ay nagdadala ng uri ng community na galing sa export nito.

Lahat sa bawat channel

Sa tab ng Mga Channel, ang Nasa lahat ng channel ang mga miyembro ang nagdedesisyon kung paano gumagana ang pagkakaroon ng miyembro sa channel sa iyong community.

  • Naka-on: nasa bawat pampublikong channel ang bawat miyembro, at nasa mga pribadong channel na binubuksan ng kanilang mga role. Walang sumasali o umuulit sa mga channel: i-mute lang ng mga tao ang mga channel na hindi nila gustong sundan. Sa menu ng channel, makikita ang I-mute ang Channel kung saan dati ay Umalis sa Channel, at hindi maaari ng mga moderator na alisin ang sinuman sa isang channel. Para maiwasan ang pagpasok ng isang tao, alisin siya sa community, i-time out siya, o baguhin ang mga permissions ng channel.
  • Patay: sumasali ang mga tao sa mga channel na gusto nila, maaari silang umalis, at maaari ng mga admin ng channel na magdagdag at alisin ang mga miyembro.

Hindi laging awtomatikong idinadagdag ang mga bisita at bot: nasa mga channel lamang sila na idinagdag sila. Ang mga pribadong channel na hindi binubuksan ng role (invite-only channels) ay hindi rin naaapektuhan.

Naka-save agad ang switch kapag binago mo ito. Kapag naka-on, idadagdag ang lahat sa mga channel na makikita nila; sa malaking community, may kaunting oras na kailangan para magawa ito. Kapag naka-off, mananatili sa kanilang kasalukuyang posisyon ang lahat, at malaya silang umalis.

Naka-on ito sa mga bagong community, maliban kung binago ng system admin ang default na iyon (Ang mga bagong community ay ilalagay ang lahat sa bawat channel sa System Console). Ang mga community na nabuo bago pa dumating ang setting na ito ay naka-off hangga't naka-on nito.

Sa isang workspace ng kumpanya na maraming team at proyekto, mas maganda kadalasan ang naka-off: nakikita lang ng mga tao ang mga channel ng kanilang trabaho. Sa isang maliit na pampublikong community, naka-on ito upang manatili ang lahat sa usapan.

Ang default na channel

Ang default channel ang lugar kung saan lumalabas ang mga bagong miyembro, at kung saan pumapasok ang mga mensahe ng pagpasok at pag-alis ng community. Nasa loob nito ang lahat at hindi sila maaaring umalis. Kapag nabuo ang isang community, ang default channel nito ay General (ang address nito ay general).

Ang mga lumang community ay may Town Square. Sa upgrade sa Antimatter 0.9.0, binago ito sa General, na may address na general, maliban kung mayroon na ang community ng channel na may address na iyon; ang pangalan na iyong ibinigay naman ay mananatili. Ang mga lumang link sa town-square ay patuloy pa rin na dahan sa default channel ng community.

Para pumili ng ibang channel, gamitin ang Default channel sa tab ng Mga Channel, o buksan ang menu ng isang pampublikong channel at piliin ang Gawing default channel. Dapat ang default channel ay isang pampublikong channel na hindi archived. Idadagdag ang lahat sa bagong default channel.

Ang General, Off-Topic, at ang default channel ay maaaring i-archive, ngunit lamang ng mga admin ng community. Kung archived ang default channel, wala na ang community ng default channel: ipapakita ng setting ang Isang archived channel, at lalabas ang mga tao sa unang channel na nasa loob sila hangga't pipiliin mo ang ibang channel. Kapag nawala ang General, ang listahan ay mag-aalok ng Wala: ang unang channel ng bawat tao.

Autolinks

Ginagawa ng Autolinks na maging link ang teksto sa mga mensahe habang ipinopost. Isang karaniwang gamit ay ang mga issue key: ang LUM-12 ay maging link sa issue na iyon sa tracker ninyo. Ito ay nakaka-apply sa mga mensahe na ipinopost sa community ninyo, sa bawat app, notisikasyon, at search, dahil binubuhay muli ng server ang mensahe bago ito i-save. Ang code, links, at mga larawan ay hindi binabago.

Sa tab ng Mga autolink:

  1. Piliin ang Magdagdag ng autolink. Magsimula mula sa isang handa nang pattern (issue keys, pull requests, merge requests, CVE identifiers) o mula sa Blangko.
  2. Bigyan ito ng pangalan, halimbawa "Jira issues".
  3. Sa Pattern, isulat ang isang regular expression, halimbawa (PROJ-\d+).
  4. Sa Magiging, isulat kung ano ang magiging resulta ng match. Ang $0 ay ang buong text na tumugma, at ang $1, $2, at iba pa ay ang mga group ng pattern. Halimbawa: [$1](https://issues.example.com/browse/$1).
  5. Piliin kung saan ito gagamitin: Lahat ng channel, o ilang channel lamang.
  6. Maaari ring i-check ang Buong salita lamang, at Pati mga mensahe ng bot kung ang mga mensahe na ipinost ng mga bot ay dapat ding ma-link.
  7. Mag-type ng halimbawa sa Subukan sa isang mensahe upang makita ang resulta, tapus piliin ang I-save.

Bawat autolink ay may Naka-on na kahon upang itigil ito nang hindi ito tinatanggal. Ang I-link din ang mga na-edit na mensahe ay nag-a-apply ng mga autolink sa mga mensahe kapag na-edit; kung hindi, ang mga bagong mensahe lamang ang ma-link. Ang isang community ay maaaring magkaroon ng hanggang 100 autolinks.

Mga koneksyon ng model

Ang model connection ay isang AI provider, tulad ng OpenAI-compatible na serbisyo o Anthropic, kasama ang kanyang address at key. Ang system admin ang nagse-setup ng mga server-wide na connection. Maaari ring magkaroon ng sarili ang community, na maaaring gamitin ng mga app ng mga tao nito sa mga channel ng community. Ang mga built-in na AI feature ng Antimatter (rewriting, recaps, auto-translation, text to speech) ay gumagamit ng mga server-wide na connection na napili ng system admin, hindi ng community.

Ang mga community admin at mga role na may Manage model connections ay nagmamanehe nito sa tab ng Model connections, o mula sa community menu sa ilalim ng Setup ng team, Model connections…. Piliin ang Magdagdag ng connection, tapos punan ang:

  • Pangalan, at ang Provider: OpenAI-compatible (karamihan sa mga provider at gateway) o Anthropic. Ang Presets ay nagpupunan ng mga karaniwang halaga.
  • Base URL at API key. Ang key ay naka-encrypt at hindi na ipapakita ulit, maliban sa huling apat na karakter nito. Ang Extra headers ay para sa mga gateway na nangangailangan nito.
  • Models: ang model na gagamitin para sa bawat capability kapag hindi tinatawag ng app. Ang Load models ay naglilista ng mga model na inaalok ng endpoint.
  • Limits: mga request bawat minuto at tokens bawat buwan, para sa connection at bawat tao. Ang blangko o 0 ay nangangahulugang walang limit.
  • Sino ang maaari itong gamitin: Lahat sa community, o lamang ang mga team, role, at admin na piliin mo. Ang mga Bisita ay maaari itong gamitin lamang kung naka-on ang Guests too, na naka-off sa default.

Ang Test ng Connection ay sinusubok ito bago o pagkatapos i-save. Ang bawat connection ay nagpapakita ng paggamit ng buwan na ito, at ang Usage ay nagbibigay ng mga detalye. Ang pagtanggal ng connection ay kalimutan ang key nito, at ang mga gumamit nito ay titigil na sa paggamit ng AI.

Layout, presets, at templates ng community

Ang layout ay ang istruktura ng isang community: ang mga kategorya nito para sa lahat at ang mga channel sa loob nito, ang mga channel nito, ang mga role nito at ang mga karapatan nila, ang onboarding nito, at ang uri nito. Buksan ang tab ng Layout ng team… ng mga setting ng community, o sa community menu piliin ang Setup ng team, tapos Layout ng team….

Tatlong presets ang iniaalok:

PresetAng itinatag nito
Hybrid (inirerekomenda)Isang naka-lock na kategorya na "Information" na may General, isang bukas na kategorya na "Community" na may Off-Topic kung saan nag-file ang mga miyembro ng kanilang sariling mga channel, at isang role na "Moderators." Ang kind ay inilala bilang Komunidad.
KomunidadMga kategorya na inuusad lamang ng mga admin ("Information" na may General, at "Channels" na may Off-Topic), at isang role na "Moderators." Ang kind ay inilala bilang Komunidad.
WorkplaceSinusuod ng bawat isa ang kanilang sariling mga kategorya, at in-archive ang mga channel na nilikha nila. Tinatanggal nito ang mga kategorya para sa lahat; nananatili ang mga role. Ang kind ay inilala bilang Workplace.

Ang role na "Moderators" ng mga preset ay maaaring mag-edit at mag-delete ng mga mensahe ng ibang tao, ilagay ang mga mensahe sa itaas, palitan ang pangalan ng mga channel at pamahalaan ang kanilang mga miyembro, at tanggalin o i-time out ang mga tao. Hindi ito nag-a-archive ng mga channel (tingnan ang Isang role ng moderator).

Sa unang pagbukas ng isang bagong community ng isang community admin na walang mga kategorya para sa lahat at walang mga role, nag-aalok ang Antimatter ng mga presets nang isang beses, sa ilalim ng Set up na sinundan ng pangalan ng community. Piliin ang Hindi ngayon upang kalimutan.

Kopyahin ang layout sa ibang community

  1. Sa community na gusto mong kopyahin, buksan ang Layout ng team… at piliin ang I-export bilang template. I-download ng iyong browser ang isang JSON file.
  2. Sa ibang community, buksan ang Layout ng team…, piliin ang Mag-apply ng template… at piliin ang file.

Ang pag-apply ng isang preset o template ay nagdadagdag ng mga channel at role na wala, nag-u-update ng mga role na may parehong pangalan, nag-file ng mga channel sa mga kategorya, nagpapalit ng onboarding, at nagse-set ng kind ng community. Hindi ito nagtatanggal ng anumang bagay maliban sa mga kategorya para sa lahat na hindi kasama sa template. Kasama sa export lamang ang mga channel na miyembro ka, at walang mga mensahe. Ang mga template na in-export bago ang upgrade sa 0.9.0 na nagpapakita ng Town Square ay nagpapatong ng General sa kanyang lugar.

Mga setting na hindi ng community

  • Mga Direct Message at mga hiling sa mensahe: ang bawat miyembro ang nagpili kung ang mga Direct Message mula sa mga hindi kilala ay darating nang normal o bilang hiling. Ito ay maaaring baguhin ng bawat miyembro para sa bawat community sa kanilang mga setting, ilalim ng Privacy & safety. Hindi maaaring itakda ito ng mga admin ng community (tingnan ang Pag-iignore at pag-block).
  • Ang Custom emoji, ang mga app, ang limit ng mga miyembro at ang kind ng mga bagong community ay inilala para sa buong server ng isang system admin. Maaari ring patayin ng isang system admin ang pag-uusap ng mga miyembro ayon sa role para sa buong server, na nangunguna sa pagpili ng iyong community sa Listahan ng mga miyembro.

Pag-uwala at pagtanggal ng isang community

Ang sinumang tao ay maaaring umalis sa isang community gamit ang Umalis sa team sa ibaba ng community menu. Hindi maaari ng mga community admin na i-archive o tanggalin ang isang community mula sa interface ng Antimatter: ginagawa ito ng isang system admin sa System Console › Pamamahala ng Mga User › Mga team, sa pamamagitan ng pagbubukas ng community at pagpili ng I-archive ang Team.
