Sino ang nagdedesisyon

Sa isang organisasyon, karaniwang pinangangalagaan ng mga community admin ang workspace araw-araw, at pinangangalagaan ng isang IT team ang server. Ang pagkakaiba ay ganito:

  • Iyong sarili, bilang community admin: mga setting ng community, mga channel at kategorya, mga role, onboarding, mga attribute ng miyembro, mga channel ng mga bisita, moderation at mga integrasyon. Lahat nito ay nakasalaysay sa gabay na ito.
  • Ang system admin: sino ang makagawa ng account at paano nag-sign-in ang mga tao, mga guest account, mga server-wide na permissions, retention ng mga mensahe, compliance exports, mga privacy setting at mga app. Nakalagay ito sa System Console.

Kung ang iyong server ay para lamang sa iyong organisasyon, hilingin sa iyong system admin na ilagay ang Kind of new communities sa Workplace (System Console › Konfigurasyon ng Site › Mga User at Team), upang bawat bagong community ay maging isang workplace. Kung ito ay na-set bago ang pag-upgrade sa Antimatter 0.9.0 (gamit ang environment variable AM_TEAMSETTINGS_DEFAULTCOMMUNITYKIND=workplace), ito ay mag-applicate din sa mga community na mayroon na; pagkatapos nito, ang mga admin ng bawat community ang magbabago ng kind nito.

Sa isang maliit na organisasyon, karaniwang isang tao lamang ang gumagawa ng pareho. Kung ikaw ay system admin, makikita mo ang System Console mula sa iyong avatar menu; ang mga setting mismo ay ipinaliwanag sa Pagpapatakbo ng server.

Kontrollin kung sino ang makapasok

Sa community:

  • Gawing pribado ang community (Pribadong Team sa Mga setting ng team › Access), upang hindi makapasok ang sinuman nang walang imbitasyon.
  • Payagan lamang ang mga email domain ng iyong organisasyon na sumali (tingnan ang Sino ang makapasok).
  • I-regenerate ang invitation link kapag may umalis na maaaring may hawak pa rito.

Sa server, magtanong sa iyong system admin tungkol sa:

  • Sign-in gamit ang mga account ng kumpanya: Pwede ng Antimatter na i-sign-in ang mga tao gamit ang AD/LDAP, SAML 2.0, OpenID Connect, Google o Office 365, sa System Console › Pagpapatunay. Gamit nila ang account na mayroon na sila, at kapag umalis sila sa kumpanya, sarado ang access nila.
  • Group sync: gamit ang AD/LDAP, ang mga group ng iyong directory ay maaaring pamahalaan kung sino ang nasa community at sa mga private channel nito. Sabi ng Access tab ng community na ang mga miyembro ay idinadagdag at tinatanggal ng mga linked groups.
  • Paglikha ng account: Pahintulutan ang Paglikha ng Account at Restrict new system and team members to specified email domains, sa System Console › Pagpapatunay › Pagparehistro.
  • Mga patakaran sa kasapihan base sa attribute: gamit ang attribute-based access control (System Console › Mga Attributo ng Sistema › Access Base sa Attribute), maaaring panatilihin ang isang community o channel para sa mga tao na ang mga attribute nila ay tumutugma, tulad ng departamento o antas ng clearance. Kapag naka-on na ito, ang mga setting ng community ay magpapakita ng mga tab na Kasapihan sa Team at Kasapihan sa Channel, at ang mga setting ng channel ay magpapakita ng tab na Membership Policy.

Mga bisita mula sa labas

Ang mga Bisita ay nagpapahintulot sa iyo na makipagtrabaho sa mga kliyente, kontraktor, at partner sa ilang channel, nang hindi ibinibigay sa kanila ang natitirang bahagi ng workspace (tingnan ang Mga Bisita). Ang mga account ng Bisita ay naka-off hangga't hindi nila na-on ng isang system admin sa System Console › Pagpapatunay › Access ng Bisita, kung saan maaari nila ring:

  • mag-lista ng mga email domain na maaaring galingan ng mga Bisita (Mga Pinapayagang Guest Domain);
  • manghikayat ng two-factor authentication para sa mga Bisita (Patupad ang Multi-factor Authentication);
  • payagan ang mga bisita na mag-sign in gamit ang link na ipinadala sa email, nang walang password.

Mabuting gawi: bigyan ang bawat organisasyon ng kasosyo ng sariling pribadong channel, at suriin ang mga bisita sa iyong community mula panahon sa panahon. Ang mga channel na may bisita ay ipinapahiwatig nito sa kanilang header, kaya't hindi nakakalimutan kung sino ang nagbabasa.

Mga channel at istruktura

  • Ilagay ang Kind of community sa Workplace (Mga setting ng team › Mga Channel): ang mga tao na nagkaka-channel ay maaari na ring i-archive ito, at naka-on ang mga Tawag sa mga channel. Tingnan ang Kind of community.
  • I-off ang Nasa lahat ng channel ang mga miyembro (Mga setting ng team › Mga Channel): sa isang workplace, sumasali ang mga tao sa mga channel ng kanilang trabaho at umalis sa iba.
  • Gumamit ng Workplace o Hybrid layout, at kategorya para sa lahat para sa mga channel na mahalaga sa lahat (mga anunsyo, tulong sa IT, opisina). Ang Workplace preset ay nagse-set ng kind sa Workplace; ang Hybrid ay nagse-set nito sa Community, kaya ibalik ito sa Workplace pagkatapos.
  • Gumawa ng mga team para sa iyong mga departamento, kasama ang kanilang tag, lead, at channel, at i-on ang Nagpapakita ang lahat ng badge ng team upang makita ng mga tao sa isang tingin kung saan sila nagtatrabaho (tingnan ang Mga Team sa loob ng community).
  • Gumamit ng mga attribute ng miyembro na itinatag ng mga admin para sa mga detalye tulad ng site, kumpanya ng isang subcontractor, o uri ng kontrata (tingnan ang Mga attribute ng miyembro).
  • Panatilihing pribado ang mga sensitibong channel, at kung kinakailangan, panatilihing para sa ilang roles lamang (tingnan ang Mga permiso ng channel).

Pribasiya sa pagitan ng mga kapwa-kaibigan

Ito ay mga setting ng server, nasa System Console › Konfigurasyon ng Site › Mga User at Team:

  • Ipakita ang Email Address at Ipakita ang Buong Pangalan: kung nakikita ng mga tao ang email address at buong pangalan ng isa’t isa. Ipinapakita ang pare-pareho nang default.
  • Pahintulutan ang mga user na buksan ang mga Direct Message channel sa: Anumang user sa Antimatter server, o lamang Anumang miyembro ng team, ibig sabihin ang mga tao na may iisang community.
  • Paganahin ang pag-i-ignore, pag-block, at mga message request: on nang default. Maraming workplace ang pinita nito upang laging maabot ang mga kapwa trabahador; pinapanatili ang mga desisyon ng mga tao sa kasong ibabalik ito sa on.
  • Limitahan ang export ng channel sa mga admin: sa default, ang sinumang mababasa ang channel ay maaaring i-export ang mga mensahe nito sa isang CSV file. I-on ito upang panatilihin ang mga export para sa mga channel, community, at system admin.

Gaano katagal pinapanatili ang mga mensahe

Nang default, pinapanatili ng Antimatter ang bawat mensahe at file nang walang hanggan. Maaaring mag-set ng data retention policy ang isang system admin sa System Console › Pagkakaunawa › Mga Data Retention Policy:

  • isang Global retention policy, na pinapaalisan ang mga mensahe at file matapos ang isang tiyak na panahon sa buong server;
  • Mga custom retention policy, para sa partikular na community at channel, halimbawa upang mas matagal na panatilihin ang isang legal channel o mas maikli ang isang social channel.

Ang mga pinapaalisan na mensahe ay permanenteng tinatanggal. Tumawag ng kasunduan sa mga tagal ng panahon sa inyong legal o compliance team bago humingi ng isang policy.

Pag-archive at compliance

  • Pag-export ng Compliance (System Console › Pagkakaunawa › Pag-export ng Compliance): regular na export ng lahat ng mensahe sa CSV, Actiance XML o Global Relay EML, para sa isang archiving system. Off ito nang default.
  • Channel export: upang ipasa ang history ng isang channel, i-export ninyo ito sa CSV mula sa menu nito (tingnan ang Export a channel).
  • Edit time limit: sa mga permissions ng server, ang isang system admin ay maaaring limitahan kung gaano katagal pagkatapos ng pag-post maaari ng mga tao na i-edit ang kanilang sariling mensahe.
  • Mga ulat ng sensitibong impormasyon: maaaring ulatin ng mga miyembro ang isang mensahe na hindi dapat naroon, halimbawa personal na datos na ipost sa maling channel. Itinatago ito habang nagdedesisyon ang mga reviewer. Ipinag-on ito ng isang system admin at pumipili ng mga reviewer sa System Console › Konfigurasyon ng Site › Paglilinis ng Data Spillage (tingnan ang Mga Ulat).
  • Mga Marka ng Klasipikasyon (System Console › Konfigurasyon ng Site › Mga Marka ng Klasipikasyon): banner na may antas ng klasipikasyon sa itaas at ibaba ng app, at isang antas bawat channel.
  • Custom na Terms of Service (System Console › Pagkakaunawa): mga tuntunin na dapat tanggapin ng lahat bago gamitin ang server.
  • Audit log: Inirekord ng server ang mga aksyon ng administrasyon at moderasyon sa audit log nito, na mababasa ng mga system admin.
