Installazione con Docker Compose

Questo è il metodo consigliato. Un file compose avvia Antimatter, PostgreSQL, lo storage dei file e il servizio GIF. È necessario un server Linux con Docker Engine e il plugin Compose (docker compose), 2 core CPU e 4 GB di memoria o più.

1. Scarica il file compose

mkdir antimatter && cd antimatter
curl -fsSLO https://antimatter.chat/compose.yaml

2. Crea il file .env

Il file compose legge le sue impostazioni da un file .env nella stessa directory. Crealo con segreti casuali:

cat > .env <<EOF
SITE_URL=http://localhost:8065
POSTGRES_PASSWORD=$(openssl rand -hex 24)
S3_SECRET_KEY=$(openssl rand -hex 24)
GIFS_API_KEY=$(openssl rand -hex 24)
EOF
chmod 600 .env

Imposta SITE_URL sull'indirizzo che le persone digiteranno nel browser, ad esempio http://192.168.1.20:8065 su una rete locale o https://chat.example.com con un dominio. Conserva il file .env: il database e lo storage utilizzano queste password dal primo avvio e lo stesso file è necessario per ripristinare un backup.

3. Avvialo

docker compose up -d
docker compose ps

Il primo avvio richiede uno o due minuti: PostgreSQL crea il database, un servizio one-shot bucket crea il bucket di storage, un servizio one-shot gifs-stickers importa il pacchetto di adesivi iniziale e Antimatter crea le sue tabelle. Segui il processo con docker compose logs -f antimatter.

Per utilizzare un nome di dominio e HTTPS fin dall'inizio, consulta Dominio e HTTPS: con il file compose si tratta di due righe aggiuntive in .env e del profilo https.

PostgreSQL, l'archiviazione e il servizio GIF sono su una rete interna (private) senza accesso a Internet, alla quale si unisce solo Antimatter. Nessuno di questi servizi pubblica una porta.

Il contenitore Antimatter non conserva nulla su disco: le sue impostazioni sono nel database (AM_CONFIG punta ad esso) e i suoi file e app sono nel servizio di archiviazione. Puoi rimuovere e ricreare il contenitore in qualsiasi momento. Tutto ciò che è necessario fare il backup si trova nei volumi postgres, files e gifs, oltre al tuo .env.

Scegli un'immagine

Sono pubblicate due immagini Antimatter, entrambe per linux/amd64 e linux/arm64, e entrambe costruite dalla branch main di ogni repository:

ImmagineApp integrateTag
ghcr.io/antimatterchat/antimatterAgenti, Chiamate, GitHub, GitLab, Jira, Kanban, Metriche e Playbook.latest, X.Y.Z per le release, sha-<commit>
ghcr.io/antimatterchat/antimatter-nextLe stesse, più Canali vocali, Sondaggi, Posta, Calendario, Note, Lavagna, GIF, Da fare e Meme. Ricostruita ogni notte.latest, nightly, nightly-<YYYYMMDD>, sha-<commit>

Il file compose del sito utilizza antimatter-next, perché il servizio GIF e la maggior parte delle app descritte su questo sito sono presenti solo in quell'immagine. Per cambiare immagine, imposta ANTIMATTER_IMAGE in .env ed esegui docker compose up -d.

latest cambia sotto i tuoi piedi. In produzione, fissa un tag come nightly-20261015 o sha-<commit>, e cambialo deliberatamente quando esegui un aggiornamento. Il server aggiorna il database all'avvio, quindi non è possibile tornare a un'immagine precedente, o passare da antimatter-next a antimatter, senza ripristinare un backup effettuato in precedenza. Vedi Backup e aggiornamenti.

All'interno dell'immagine

  • Il server si trova in /antimatter, con i binari antimatter e amctl in /antimatter/bin (nella PATH).
  • Viene eseguito come utente non privilegiato antimatter (uid 2000) su una base distroless minima, senza shell.
  • Porte: 8065 (web e API), 8067 (metriche), 8074 (cluster), 8443 UDP e TCP (chiamate).
  • La modalità locale (ServiceSettings.EnableLocalMode) è attiva, quindi amctl --local funziona all'interno del contenitore. Il controllo di integrità esegue amctl system status --local.
  • Le app integrate si trovano in /antimatter/prepackaged_plugins e sono firmate con la chiave di firma delle app Antimatter.
  • Sono inclusi strumenti per l'estrazione del testo (pdftotext, wvText, unrtf, tidy), in modo da poter cercare nel contenuto dei documenti caricati.

Altri file compose

Il repository antimatter-docker contiene una configurazione di produzione in deploy/compose/: nginx con certificati propri o Let's Encrypt (certbot), PostgreSQL, il servizio GIF opzionale (profilo gifs) e volumi denominati per la configurazione, i dati e i log del server, documentati nel relativo README. Utilizza di default l'immagine stabile e archivia i file su un volume locale anziché su storage S3. Usalo se preferisci nginx a Caddy o se disponi già di certificati.

Creare il primo amministratore

Apri SITE_URL nel browser e crea un account. Il primo account creato su un server nuovo diventa amministratore di sistema e la procedura di configurazione ti guiderà poi nella creazione della tua prima community (il termine usato da Antimatter per team o area di lavoro).

Esegui questa operazione subito dopo il primo avvio: fino a quel momento, chiunque raggiunga il server per primo ne diventa l'amministratore. Per creare l'account da riga di comando, prima che il server sia raggiungibile dall'esterno:

docker compose exec antimatter amctl --local user create --system-admin --email-verified \
    --email admin@example.com --username admin --password 'a-long-password'
docker compose exec antimatter amctl --local team create --name main --display-name "Main"
docker compose exec antimatter amctl --local team users add main admin

Quindi accedi a SITE_URL. Inizia il comando con uno spazio per evitare che la password venga salvata nella cronologia della shell (con HISTCONTROL=ignorespace), oppure cambia la password dopo l'accesso.

Passi successivi una volta effettuato l'accesso:

  1. Decidi chi può creare account: Accesso e account.
  2. Configura la posta elettronica, in modo che funzionino inviti e ripristino delle password: Posta elettronica e notifiche push.
  3. Apri la porta delle chiamate nel firewall: Chiamate e voce.
  4. Verifica quali app sono attive: App integrate.

Installazione da un archivio di rilascio

Senza Docker, il server viene eseguito da un archivio denominato antimatter-<os>-<arch>.tar.gz (ad esempio antimatter-linux-amd64.tar.gz). Contiene un'unica directory antimatter/ con bin/antimatter, bin/amctl, config/config.json, le app web (client/ e client-fusion/), i modelli di email e le traduzioni.

1. Preparare PostgreSQL

Antimatter supporta solo PostgreSQL, versione 15 o successiva (le versioni precedenti si avviano, ma restituiscono un errore nel log). Crea un utente e un database:

sudo -u postgres psql <<'EOF'
CREATE USER antimatter WITH PASSWORD 'a-long-password';
CREATE DATABASE antimatter OWNER antimatter;
EOF

2. Estrai e configura

sudo tar -xzf antimatter-linux-amd64.tar.gz -C /opt
sudo useradd --system --user-group antimatter
sudo mkdir -p /opt/antimatter/data
sudo chown -R antimatter:antimatter /opt/antimatter

Indica al server il database, sia in /opt/antimatter/config/config.json (SqlSettings.DataSource) sia tramite variabili di ambiente, e imposta l'URL del sito:

AM_SQLSETTINGS_DRIVERNAME=postgres
AM_SQLSETTINGS_DATASOURCE=postgres://antimatter:a-long-password@localhost:5432/antimatter?sslmode=disable&connect_timeout=10
AM_SERVICESETTINGS_SITEURL=https://chat.example.com

Il file config.json dell'archivio è una configurazione predefinita completa: le impostazioni modificate nella Console di Sistema vengono salvate in questo file. Per mantenere la configurazione nel database, consulta Configurazione.

3. Esegui come servizio

Un'unità systemd, in /etc/systemd/system/antimatter.service:

[Unit]
Description=Antimatter
After=network.target postgresql.service

[Service]
Type=notify
User=antimatter
Group=antimatter
WorkingDirectory=/opt/antimatter
ExecStart=/opt/antimatter/bin/antimatter
EnvironmentFile=-/etc/antimatter.env
TimeoutStartSec=3600
Restart=always
RestartSec=10
LimitNOFILE=49152

[Install]
WantedBy=multi-user.target

Inserisci le tue variabili AM_ in /etc/antimatter.env (leggibile solo da root), quindi:

sudo systemctl daemon-reload
sudo systemctl enable --now antimatter
journalctl -u antimatter -f

Il server ascolta sulla porta 8065. Apri http://<server>:8065, oppure il tuo dominio una volta configurato un reverse proxy (vedi Dominio e HTTPS), e crea il primo account: questo diventerà l'amministratore di sistema.

bin/amctl gestisce il server in esecuzione dalla riga di comando. Sul server stesso, funziona senza accesso tramite modalità locale: imposta AM_SERVICESETTINGS_ENABLELOCALMODE=true, quindi esegui sudo -u antimatter /opt/antimatter/bin/amctl --local system status.

Altri comandi del server

Oltre all'esecuzione del server (antimatter, oppure antimatter server), il binario dispone di alcuni comandi di manutenzione. Questi leggono la stessa configurazione del server.

ComandoFunzione
antimatter versionStampa la versione, il numero di build, la data di build e l'hash di build.
antimatter db pingVerifica che il database sia raggiungibile.
antimatter db initCrea la configurazione nel database (con AM_CONFIG impostato su un URL postgres://).
antimatter db migrateApplica le migrazioni del database senza avviare il server.
antimatter db versionStampa l'ultima migrazione applicata al database.
antimatter import bulk, antimatter export bulkImporta o esporta dati nel formato bulk (vedi Backup e aggiornamenti).
