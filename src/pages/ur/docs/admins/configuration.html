ترتیبات کہاں موجود ہیں

ہر سرور سیٹنگ کا نام ایک سیکشن اور ایک کی سے بنایا گیا ہے، جیسے ServiceSettings.SiteURL یا EmailSettings.SMTPServer۔ یہ مل کر ایک ترتیب بناتے ہیں جو دو مقامات میں سے کسی ایک میں محفوظ ہوتی ہے:

  • ڈیٹا بیس میں۔ سائٹ کا کمپوز فائل AM_CONFIG کو PostgreSQL کنیکشن URL پر سیٹ کرتا ہے، اس لیے ترتیب ڈیٹا بیس کی ایک قطار ہے اور کنٹینر ڈسک پر کچھ نہیں رکھتا۔ ایک ہی ڈیٹا بیس شیئر کرنے والے کئی سرور اپنی ترتیب بھی شیئر کرتے ہیں۔
  • فائل میں۔ AM_CONFIG کے بغیر، سرور اپنے bin/ ڈائریکٹری کے ساتھ config/config.json پڑھتا ہے (Docker امیج میں /antimatter/config/config.json)۔ antimatter-docker کے ریلیس آرکائیو اور پروڈکشن کمپوز فائلز اسی طرح کام کرتی ہیں۔ اس فائل کو صرف سرور کے صارف کے لیے قابلِ مطالعہ رکھیں: اس میں پاس ورڈز اور کلوز موجود ہیں۔

AM_CONFIG (یا antimatter کمانڈ کا --config فلگ) فائل کے راستے یا postgres:// URL کو قبول کرتا ہے۔ وہ سیٹنگز جو آپ چھوڑ دیں، ان کی ڈیفالٹ ویلیو استعمال ہوتی ہے۔

موجودہ ترتیب کو فائل سے ڈیٹا بیس میں منتقل کرنے کے لیے، اسے سرور پر چلائیں، پھر AM_CONFIG کو اسی URL پر سیٹ کر کے سرور شروع کریں:

amctl --local config migrate /opt/antimatter/config/config.json \
    "postgres://antimatter:PASSWORD@localhost:5432/antimatter?sslmode=disable&connect_timeout=10"

ماحولی متغیرات

کسی بھی سیٹنگ کو ماحولی متغیر کے طور پر بھی دیا جا سکتا ہے۔ متغیرات محفوظ شدہ ترتیب پر برتری حاصل کرتے ہیں، جو انہیں ڈپلائمنٹ سے تعلق رکھنے والی چیزوں کے لیے موزوں بناتا ہے: ڈیٹا بیس، سائٹ URL، فائل اسٹوریج، پورٹس۔

نام دینے کا اصول

AM_ لکھیں، پھر سیکشن، پھر کی، بڑے حروف میں اور انڈرسکورز سے الگ۔ سیکشن یا کی کے نام کے اندر الفاظ الگ نہیں کیے جاتے:

ترتیبمتغیر
ServiceSettings.SiteURLAM_SERVICESETTINGS_SITEURL
SqlSettings.DataSourceAM_SQLSETTINGS_DATASOURCE
EmailSettings.SMTPServerAM_EMAILSETTINGS_SMTPSERVER
PrivacySettings.EnableUserBlockingAM_PRIVACYSETTINGS_ENABLEUSERBLOCKING
  • سچ اور جھوٹی سیٹنگز true یا false لیتی ہیں؛ نمبر سادہ نمبر ہیں۔
  • فہرست سیٹنگز اپنے اقدار کو خلا سے الگ لیتی ہیں، مثال کے طور پر AM_SERVICESETTINGS_TRUSTEDPROXYIPHEADER="X-Forwarded-For X-Real-IP"۔
  • آبجیکٹ سیٹنگز JSON لیتی ہیں۔ ایپس کے لیے ایسا واحد متغیر AM_PLUGINSETTINGS_PLUGINS ہے، اور یہ ہر ایپ کی ترتیب کو ایک ساتھ بدل دیتا ہے: ایپ کی ترتیبات سسٹم کنسول یا amctl کے ذریعے سیٹ کریں (نیچے دیکھیں)۔
  • پرانے Mattermost سیٹ اپز MM_ پری فکس استعمال کرتے ہیں، مثال کے طور پر MM_SQLSETTINGS_DATASOURCE۔ یہ اب بھی ایک لیگی ایلیس کے طور پر کام کرتا ہے۔ جب دونوں سیٹ ہوں، تو AM_ ویری ایبل غالب آتا ہے۔

ویری ایبل کے ذریعے دی گئی ترتیب سسٹم کنسول میں لاک ہو جاتی ہے، اور ساتھ یہ نوٹ ہوتا ہے: "یہ ترتیب ایک environment variable کے ذریعے سیٹ کی گئی ہے۔ اسے سسٹم کنسول کے ذریعے تبدیل نہیں کیا جا سکتا۔" یہ محفوظ شدہ کنفیگریشن میں لکھی نہیں جاتی: ویری ایبل ہٹا دیں اور محفوظ شدہ ویلیو دوبارہ لاگو ہو جائے گی۔

Docker Compose کے ساتھ

antimatter سروس کے environment: کے نیچے ویری ایبلز شامل کریں، یا compose.yaml کے ساتھ compose.override.yaml میں (Compose خودکار طور پر اسے پڑھتا ہے، اور یہ ڈاؤن لوڈ شدہ فائل کے اپڈیٹس کے بعد بھی برقرار رہتا ہے):

services:
  antimatter:
    environment:
      AM_EMAILSETTINGS_SMTPSERVER: smtp.example.com
      AM_EMAILSETTINGS_SMTPPORT: "587"
      AM_LOGSETTINGS_CONSOLELEVEL: INFO

تبدیلیوں کو لاگو کرنے کے لیے docker compose up -d چلائیں، جو کہ کنٹینر کو دوبارہ بناتا ہے۔

ایپس کے ذریعے پڑھے جانے والے ویری ایبلز

کچھ ایپس اپنے اپنے ویری ایبلز پڑھتی ہیں، جو antimatter سروس پر سیٹ ہوتے ہیں: Calls ایپ AM_CALLS_* پڑھتی ہے (دیکھیں Calls and voice)، اور GIFs ایپ AM_GIFS_SERVICE_URL، AM_GIFS_API_KEY اور AM_GIFS_UPLOAD_KEY پڑھتی ہے (دیکھیں Bundled apps)۔

سسٹم کنسول

سسٹم کنسول ویب ایپ کا انتظامی حصہ ہے، جو سسٹم ایڈمنسٹریٹرز کے لیے ہے۔ اسے کھولنے کے لیے اپنے پروفائل کی تصویر پر کلک کریں اور سسٹم کنسول منتخب کریں، یا https://chat.example.com/admin_console پر جائیں۔ اس کے سائیڈ بار میں ترتیبات تلاش کریں باکس ہے جو ہر صفحے کو تلاش کرتا ہے۔

اس کے سیکشنز یہ ہیں:

  • رپورٹنگ: اعداد و شمار اور سرور کے لاگز۔
  • صارفین کا انتظام: صارفین، گروپس، کمیونٹیز (جو ٹیمز کے طور پر درج ہیں)، چینلز، اجازتیں اور تفویض شدہ انتظام۔
  • سسٹم اٹری بیوٹس: کسٹم پروفائل اٹری بیوٹس اور اٹری بیوٹ پر مبنی رسائی۔
  • ماحول: ویب سرور، ڈیٹا بیس، فائل اسٹوریج، امیج پروکسی، SMTP، پش اطلاعات، ریٹ لیمٹنگ، لاگنگ، سیشن کی لمبائی، اور کارکردگی کی نگرانی۔
  • سائٹ کی ترتیبات: برانڈنگ، صارفین اور ٹیمز، اطلاعات، پوسٹس، فائل شیئرنگ اور دیگر سرور-وائیڈ رویے۔
  • تصدیق: سائن اپ، ای میل اور پاس ورڈ سائن ان، MFA، AD/LDAP، SAML 2.0، OAuth 2.0، OpenID Connect اور مہمان رسائی۔
  • پلگ انز: ایپس کا انتظام اور ہر انسٹال شدہ ایپ کی ترتیبات۔
  • انضمامات: ویب ہکس، سلاش کمانڈز، بوٹ اکاؤنٹس، GIFs، ٹیکسٹ ٹو اسپیک، CORS۔
  • مطابقت: ڈیٹا کی تحفظ مدت، مطابقت کی برآمد اور نگرانی، آڈٹ لاگنگ، اور کسٹم ٹرمز آف سروس۔
  • تجرباتی: خصوصیات جو تبدیل ہو سکتی ہیں۔

اس گائیڈ میں، کوئی بھی سیٹنگ اس کے سسٹم کنسول میں موجود راستے کے طور پر لکھی گئی ہے، پھر اس کا لیبل، اور پھر اس کی کنفیگریشن کی، مثال کے طور پر سسٹم کنسول › سائٹ کی ترتیبات › صارفین اور ٹیمز › نظراندازی، بلاکنگ اور پیغام کی درخواستیں فعال کریں (PrivacySettings.EnableUserBlocking)۔

زیادہ تر تبدیلیاں اس وقت لاگو ہو جاتی ہیں جب آپ محفوظ کریں پر کلک کرتے ہیں۔ کچھ (جیسے لسن ایڈریس، کچھ ڈیٹا بیس اور کیچ کی ترتیبات) کو ری اسٹارت کی ضرورت ہوتی ہے، اور صفحہ اس بات کا ذکر کرتا ہے۔

amctl کمانڈ لائن ٹول

amctl کمانڈ لائن سے سرور کو منظم کرتا ہے: صارفین، کمیونٹیز، چینلز، ایپس، کنفیگریشن، جابز اور بہت کچھ۔ یہ سرور سے دو طریقوں میں سے کسی ایک کے ذریعے بات چیت کرتا ہے۔

لوکل موڈ، سرور پر

لوکل موڈ amctl کو یونیکس سوکٹ کے ذریعے سرور سے بات کرنے کی اجازت دیتا ہے، بغیر سائن ان کے۔ یہ ڈاکر امیج میں فعال ہوتا ہے۔ آرکائیو سے انسٹال شدہ سرور پر، اسے ServiceSettings.EnableLocalMode (AM_SERVICESETTINGS_ENABLELOCALMODE=true) کے ذریعے فعال کریں۔ سوکٹ بطور ڈیفالٹ /var/tmp/antimatter_local.socket ہوتا ہے (ServiceSettings.LocalModeSocketLocation)۔

# with Docker Compose
docker compose exec antimatter amctl --local system status
# with a release archive
sudo -u antimatter /opt/antimatter/bin/amctl --local system status
جو بھی اس سوکٹ کا استعمال کر سکے، یا ہوسٹ پر docker compose exec چلا سکے، اس کے پاس مکمل سسٹم ایڈمنسٹریٹر کے اختیارات ہوں گے۔

ریموٹ، اکاؤنٹ کے ساتھ

کسی بھی مشین سے، سسٹم ایڈمنسٹریٹر اکاؤنٹ (یا پرسنل ایکسیس ٹوکن) کے ساتھ سائن ان کریں، پھر اس سرور کے خلاف کمانڈز چلائیں:

amctl auth login https://chat.example.com --name prod --username admin
amctl system status

کنفیگریشن کمانڈز

کمانڈیہ کیا کرتا ہے
amctl config get ServiceSettings.SiteURLایک سیٹنگ کو پرنٹ کرتا ہے۔
amctl config set TeamSettings.EnableOpenServer falseایک سیٹنگ کو تبدیل کرتا ہے۔ لسٹ سیٹنگز کئی ویلیوز لیتی ہیں۔
amctl config patch settings.jsonکنفیگریشن میں سیٹنگز کا ایک JSON فائل ملا دیتا ہے۔
amctl config showپوری کنفیگریشن کو JSON کے طور پر پرنٹ کرتا ہے۔
amctl config editکنفیگریشن کو آپ کے ایڈیٹر ($EDITOR) میں کھولتا ہے۔
amctl config resetسیٹنگز کو ان کی ڈیفالٹ ویلیوز پر ری سیٹ کرتا ہے۔
amctl config reloadسرور کے باہر کی تبدیلی کے بعد، کنفیگریشن کو اس جگہ سے دوبارہ لوڈ کرتا ہے جہاں یہ محفوظ ہے۔

ایپ کی سیٹنگز PluginSettings.Plugins.<app id> کے تحت موجود ہیں، اور کیز چھوٹے حروف میں ہوتے ہیں۔ مثال کے طور پر، ڈاکر ہوسٹ سے GIFs ایپ کی سروس URL اور کی سیٹ کرنے کے لیے:

docker compose exec -T antimatter amctl --local config patch /dev/stdin <<'EOF'
{"PluginSettings": {"Plugins": {"com.antimatterchat.gifs": {
  "serviceurl": "http://gifs:8080/v2",
  "apikey": "the GIFS_API_KEY of your .env"
}}}}
EOF

دیگر مفید کمانڈز: amctl user create, amctl user deactivate, amctl team create, amctl plugin list, amctl plugin enable, amctl system supportpacket اور amctl logs۔ ہر ایک کے آپشنز کے لیے amctl help <command> چلائیں۔

لاگز

سرور اپنے لاگز دو مقامات پر لکھتا ہے، ہر ایک کا اپنا لیول (DEBUG، INFO، WARN یا ERROR) ہوتا ہے، جو سسٹم کنسول › ماحول › لاگنگ میں سیٹ کیا جاتا ہے:

مقصدترتیباتڈیفالٹس
کنسول (اسٹینڈرڈ آؤٹ پٹ)لاگز کو کنسول پر آؤٹ پٹ کریں (LogSettings.EnableConsole)، کنسول لاگ لیول (LogSettings.ConsoleLevel)، کنسول لاگز کو JSON کے طور پر آؤٹ پٹ کریں (LogSettings.ConsoleJson)آن، DEBUG، JSON
فائل، antimatter.logلاگز کو فائل میں آؤٹ پٹ کریں (LogSettings.EnableFile)، فائل لاگ لیول (LogSettings.FileLevel)، فائل لاگ ڈائریکٹری (LogSettings.FileLocation)آن، INFO، bin/ کے ساتھ logs/ ڈائریکٹری

لاگ فائلز 100 میگا بائٹ پر روٹیٹ ہوتی ہیں اور پرانی فائلز کمپریس کر دی جاتی ہیں۔

سائٹ کا کمپوز فائل فائل لاگنگ بند کر دیتا ہے (AM_LOGSETTINGS_ENABLEFILE=false)، اس لیے لاگز صرف کنٹینر کے آؤٹ پٹ میں ہوتے ہیں:

docker compose logs -f antimatter
docker compose logs --since 1h antimatter | grep -i error

کنسول لیول کا ڈیفالٹ DEBUG ہے، جو بہت تفصیلی ہے۔ مصروف سرور پر AM_LOGSETTINGS_CONSOLELEVEL=INFO سیٹ کریں۔ systemd کے تحت ریلیس آرکائیو کے ساتھ، کنسول آؤٹ پٹ جرنل (journalctl -u antimatter) میں جاتا ہے اور فائل /opt/antimatter/logs/antimatter.log میں۔

جب فائل لاگنگ آن ہو، تو سسٹم ایڈمنسٹریٹرز سسٹم کنسول › رپورٹنگ › سرور لاگز میں بھی تازہ ترین لاگ لائنز پڑھ سکتے ہیں، یا amctl logs کے ذریعے۔
