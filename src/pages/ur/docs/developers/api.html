بنیادی باتیں

  • بنیادی URL: https://chat.example.com/api/v4۔ نیچے دیے گئے تمام اینڈ پوائنٹس اس کے حوالے سے ہیں۔
  • فارمیٹ: اندر اور باہر JSON، سوائے فائل اپ لوڈز (multipart) کے۔ Content-Type: application/json بھیجیں۔
  • آئی ڈیز: ہر آبجیکٹ کے پاس ایک 26 حروف پر مشتمل id ہوتا ہے۔ اوقات Unix epoch کے بعد کے ملی سیکنڈز میں ہوتے ہیں (create_at، update_at، delete_at؛ 0 کا مطلب ہے "حذف نہیں کیا گیا")۔
  • کمیونٹیز ٹیمز ہیں: API انہیں teams کہتا ہے، جن کے ساتھ team_id ہوتا ہے۔
  • آپ خود: جہاں بھی پاتھ user_id لیتا ہے، me کے مطلب ہیں سائنڈ ان صارف، جیسے GET /users/me۔

اینڈ پوائنٹس کی مکمل فہرست سرور کے کوڈ میں موجود ہے: روٹس server/channels/api4/*.go میں اعلان کیے گئے ہیں اور ٹائپس server/public/model میں۔ ریپوزٹری کے api/v4/source فولڈر میں موجود OpenAPI وضاحت Mattermost سے وراثت میں ملے اینڈ پوائنٹس کو کور کرتی ہے، Antimatter کے اضافوں کو نہیں۔

تصدیق (Authentication)

ہر درخواست، سوائے سائن ان کرنے اور کچھ عوامی اینڈ پوائنٹس کے، Authorization ہیڈر میں ٹوکن کی ضرورت ہوتی ہے:

curl -H "Authorization: Bearer $TOKEN" https://chat.example.com/api/v4/users/me

وہاں تین قسم کے ٹوکنز قبول کیے جاتے ہیں: ذاتی رسائی ٹوکنز، سیشن ٹوکنز اور OAuth رسائی ٹوکنز۔ Authorization: Token … بھی قبول کیا جاتا ہے۔ کوئری سٹرنگ (?access_token=) میں ٹوکنز صرف OAuth رسائی ٹوکنز کے لیے قبول کیے جاتے ہیں۔

ذاتی رسائی ٹوکنز (اسکرپٹس کے لیے سفارش کردہ)

ذاتی رسائی ٹوکن آپ کی طرح کام کرتا ہے، جب تک آپ اسے ایک میعادِ ختم نہ دیں، اس کی میعاد ختم نہیں ہوتی، اور اسے کسی بھی وقت منسوخ کیا جا سکتا ہے۔ ذاتی رسائی ٹوکنز پہلے سے بند ہوتے ہیں:

  1. سسٹم ایڈمن سسٹم کنسول › انضمامات › انٹیگریشن مینجمنٹ میں پرسونل ایکسس ٹوکنز فعال کریں کو آن کرتا ہے (ServiceSettings.EnableUserAccessTokens، AM_SERVICESETTINGS_ENABLEUSERACCESSTOKENS)۔
  2. ہر اس شخص کے لیے جو ٹوکنز بنانے کا حق رکھتا ہے، سسٹم ایڈمن سسٹم کنسول › صارفین کا انتظام › صارفین کھولتا ہے، اس شخص کے مینیو میں کرداروں کا انتظام منتخب کرتا ہے اور اس اکاؤنٹ کو پرسونل ایکسس ٹوکنز بنانے کی اجازت دیں پر ٹک لگاتا ہے۔ سسٹم ایڈمنز ہمیشہ انہیں بنا سکتے ہیں۔
  3. شخص اپنا ایواٹار (avatar) اوپر دائیں جانب کھولتا ہے، پھر پروفائل اور ترتیبات › سیکیورٹی پر جاتا ہے۔ ذاتی رسائی ٹوکنز کے تحت، وہ ٹوکن کے مقصد کی وضاحت کرتا ہے اور ٹوکن بنائیں منتخب کرتا ہے۔ ٹوکن صرف ایک بار دکھایا جاتا ہے: اسے کاپی کریں۔

API کے ذریعے: POST /users/{user_id}/tokens کے ساتھ {"description": "backup script", "expires_at": 0} (expires_at ملی سیکنڈ میں؛ 0 کے لیے کوئی مدت نہیں)۔ جواب کے token فیلڈ میں راز (secret) ہوتا ہے؛ اس کا id وہ ہے جسے آپ اسے منسوخ کرنے کے لیے استعمال کرتے ہیں (POST /users/tokens/revoke کے ساتھ {"token_id": "…"})۔ کمانڈ لائن سے: amctl token generate <user> <description>۔

سسٹم ایڈمن اسی سسٹم کنسول پیج پر زیادہ سے زیادہ پرسونل ایکسس ٹوکن کی مدت (دن) کے ذریعے ٹوکنز کی مدت کو محدود کر سکتا ہے۔

سیشن ٹوکنز

پاس ورڈ کے ساتھ سائن ان کرنے پر Token ریسپانس ہیڈر میں ایک سیشن ٹوکن واپس آتا ہے، جو اسی قسم کا سیشن ہے جو ایپس استعمال کرتی ہیں:

curl -i -X POST https://chat.example.com/api/v4/users/login \
  -H 'Content-Type: application/json' \
  -d '{"login_id": "maya", "password": "…"}'

ملٹی فیکٹر اتھنٹیکیشن والا اکاؤنٹ کے لیے "token": "123456" شامل کریں۔ سیشنز سرور کے سیشن ترتیبات کے مطابق ختم ہوتے ہیں، اور لاگین انڈپوائنٹ ریٹ لیمٹڈ ہے (فی سیکنڈ 5 درخواستیں)۔ POST /users/logout سیشن کو ختم کرتا ہے۔

براؤزرز کوکیز کے ذریعے اتھنٹیکیشن کرتے ہیں۔ کوکیز کے ذریعے اتھنٹیکٹڈ درخواست کو GET کے علاوہ کسی بھی چیز کے لیے X-CSRF-Token ہیڈر بھی بھیجنا ہوگا؛ Authorization ہیڈر میں موجود ٹوکن کو CSRF ہیڈر کی ضرورت نہیں ہوتی۔

OAuth 2.0 ایپس

لوگوں کو اپنے Antimatter اکاؤنٹ کے ساتھ اپنی ایپلیکیشن میں سائن ان کرنے کی اجازت دینے کے لیے، ایک OAuth 2.0 ایپ رجسٹر کریں۔ Antimatter پھر OAuth پرووائڈر بن جاتا ہے:

  1. OAuth 2.0 سروس پرووائیڈر فعال کریں کو آن ہونا ضروری ہے (سسٹم کنسول › انضمامات › انٹیگریشن مینجمنٹ، ServiceSettings.EnableOAuthServiceProvider، جو پہلے سے آن ہے)۔
  2. جس شخص کے پاس OAuth ایپس کو منظم کرنے کا حق ہے (پہلے سے سسٹم ایڈمنز)، وہ اپنا ایواٹار کھولتا ہے، پھر انضمامات › OAuth 2.0 ایپس پر جاتا ہے، اور اپنی callback URLs کے ساتھ ایپ شامل کرتا ہے۔ اسے client ID اور client secret ملتا ہے۔
  3. آپ کی ایپ لوگوں کو https://chat.example.com/oauth/authorize پر بھیجتی ہے، جہاں response_type=code، client_id، redirect_uri اور state شامل ہوتے ہیں۔ code_challenge_method=S256 کے ساتھ PKCE کی حمایت کی جاتی ہے۔
  4. یہ کوڈ کو POST https://chat.example.com/oauth/access_token پر تبدیل کرتی ہے (پہلے grant_type=authorization_code، پھر تجدید کے لیے refresh_token)، اور API کو Authorization: Bearer <access token> کے ساتھ کال کرتی ہے۔

صارفین پروفائل اور ترتیبات › سیکیورٹی › آپ کی تصدیق شدہ ایپس میں وہ ایپس دیکھتے ہیں جنہیں انہوں نے تصدیق دی ہے۔

پیغام بھیجیں

curl -X POST https://chat.example.com/api/v4/posts \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"channel_id": "'$CHANNEL_ID'", "message": "Backup finished: **42 GB** in 3 min"}'

پیغامات Markdown میں ہوتے ہیں۔ سلسلے میں جواب دینے کے لیے "root_id" (سلسلے کا پہلا پیغام) شامل کریں، فائلوں کے لیے "file_ids" اور منسلک فائلوں اور دیگر اضافی چیزوں کے لیے "props" (دیکھیں منسلک فائلیں)۔

curl -H "Authorization: Bearer $TOKEN" \

نام چینل کے لنک میں موجود ہیں: /lumen-labs/channels/ops-alerts۔

صفحات کی تقسیم

فہرست کے اِنڈ پوائنٹس page (0 سے) اور per_page (ڈیفالٹ 60، زیادہ سے زیادہ 200) لیتے ہیں۔ اگلے صفحے کے لیے پوچھتے رہیں جب تک کہ کوئی صفحہ per_page سے چھوٹا نہ آ جائے۔

کسی چینل کے پیغامات (GET /channels/{channel_id}/posts) بھی since (وقت: اس وقت کے بعد ہر تبدیلی) یا before اور after (پوسٹ ID) قبول کرتے ہیں۔ یہ ایک پوسٹ فہرست کے طور پر واپس آتے ہیں: {"order": [IDs, newest first], "posts": {ID: post}, "next_post_id", "prev_post_id"}۔

غلطیاں

غلطیاں عام HTTP اسٹیٹس کوڈز (400 غلط ان پٹ، 401 سائن ان نہیں کیا، 403 اجازت نہیں، 404 نہیں ملا، 501 فیچر بند) اور ایک JSON باڈی استعمال کرتی ہیں:

{
  "id": "api.context.permissions.app_error",
  "message": "You do not have the appropriate permissions.",
  "detailed_error": "",
  "request_id": "jz8zm5nunpbt8f3gpqsz5dq6so",
  "status_code": 403
}

اپنے کوڈ میں id استعمال کریں: message صارف کی زبان میں ترجمہ کیا جاتا ہے۔ detailed_error خالی رہتا ہے جب تک کہ سرور ڈویلپر موڈ (ServiceSettings.EnableDeveloper) میں چل رہا ہو۔ سرور کے ایڈمن کو request_id کا حوالہ دیں: یہ لاگز میں موجود ہے۔

ریٹ لمٹس

ریٹ لیمٹنگ پہلے سے بند ہے۔ جب سسٹم ایڈمن اسے آن کرتا ہے (سسٹم کنسول › ماحول › ریٹ لیمٹنگ)، تو پہلے سے ہر کلائنٹ کو 100 کے بارسٹس کے ساتھ فی سیکنڈ 10 درخواستیں ملتی ہیں، جو IP ایڈریس یا صارف کی بنیاد پر گنئی جاتی ہیں۔ جوابات میں X-RateLimit-Limit، X-RateLimit-Remaining اور X-RateLimit-Reset شامل ہوتے ہیں؛ حد سے اوپر، سرور 429 کے ساتھ Retry-After ہیڈر (سیکنڈز میں) جواب دیتا ہے۔ کچھ endpoints، جیسے سائن ان کرنا، ترتیب سے قطع نظر اپنی الگ حد رکھتے ہیں۔

اسکرپٹس لکھیں جو 429 پر انتظار کریں اور دوبارہ کوشش کریں، اور پولنگ سے بچیں: WebSocket کو فولو کریں۔

WebSocket ایونٹ اسٹریم

wss://chat.example.com/api/v4/websocket سے منسلک ہوں۔ تصدیق کے لیے یا تو کنکشن درخواست پر Authorization: Bearer ہیڈر استعمال کریں، یا اسے پہلا پیغام بھیجیں:

{"seq": 1, "action": "authentication_challenge", "data": {"token": "…"}}

سرور ایک hello ایونٹ بھیجتا ہے، پھر ہر چیز کے لیے ایک ایونٹ جو آپ دیکھنے کی اجازت رکھتے ہیں:

{
  "event": "posted",
  "data": {"channel_id": "…", "channel_type": "O", "post": "{\"id\":\"…\",\"message\":\"Hello\",…}"},
  "broadcast": {"channel_id": "…", "team_id": "", "user_id": "", "omit_users": null},
  "seq": 4
}

نوٹ کریں کہ data.post پوسٹ JSON اسٹرنگ کے طور پر ہے۔ عام ایونٹس: posted، post_edited، post_deleted، reaction_added، reaction_removed، typing، status_change، user_added، direct_added۔ ایپس اپنے اپنے ایونٹس بھیجتی ہیں، جن کے نام custom_<app id>_<event> ہوتے ہیں۔

آپ ایکشنز بھی بھیج سکتے ہیں، ہر ایک میں بڑھتا ہوا seq: user_typing کے ساتھ {"channel_id", "parent_id"}، یا get_statuses۔ جب کنکشن ٹوٹے تو دوبارہ منسلک ہوں، اور since کے ساتھ وہ چیزیں لائیں جو آپ نے چھوڑ دی (دیکھیں Pagination)۔

Antimatter ان ایونٹس کو شامل کرتا ہے: community_attributes_updated، member_timeouts_updated، post_put_on_top، post_removed_from_top، server_categories_updated، channel_overrides_updated اور category_overrides_updated۔

کلائنٹ لائبریریز

  • جائیں: server/public/model میں model.Client4 (import github.com/mattermost/mattermost/server/public/model)۔ model.NewAPIv4Client(url)، پھر client.SetToken(token)؛ model.NewWebSocketClient4(wsURL, token) events کو فالو کرتا ہے۔ Antimatter کی کاپی اپنے endpoints کے لیے طریقے شامل کرتی ہے، جیسے UpdateMessageRequest، PutPostOnTop اور ExportChannel۔
  • TypeScript: webapp/platform/client میں @mattermost/client کا Client4 کلاس، جس کے ٹائپس webapp/platform/types میں ہیں۔ Antimatter کے ریپوزٹری میں موجود کاپی Antimatter کے اندروپوائنٹس کو شامل کرتی ہے؛ Mattermost کے ذریعے npm پر شائع شدہ پیکج میں یہ شامل نہیں ہیں۔
package main

import (
	"context"
	"log"

	"github.com/mattermost/mattermost/server/public/model"
)

func main() {
	client := model.NewAPIv4Client("https://chat.example.com")
	client.SetToken("…")
	post, _, err := client.CreatePost(context.Background(), &model.Post{
		ChannelId: "…",
		Message:   "Hello from Go",
	})
	if err != nil {
		log.Fatal(err)
	}
	log.Println("posted", post.Id)
}
