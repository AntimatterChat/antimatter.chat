ایپ کیسے کام کرتی ہے

  • سرور کا حصہ ایک Go پروگرام ہے۔ سرور اسے ایک الگ پروسیس کے طور پر شروع کرتا ہے اور اس کے ساتھ RPC کے ذریعے بات چیت کرتا ہے: یہ ایپ کے ہکس کو کال کرتا ہے (ایک پیغام پوسٹ ہونے والا ہے، ایک کمانڈ چلائی گئی ہے…)، اور ایپ سرور کے پلگ ان API کو کال کرتی ہے (پوسٹ بنائیں، صارف پڑھیں، ڈیٹا محفوظ کریں…)۔ یہ /plugins/<app id>/ کے تحت HTTP روٹس بھی فراہم کر سکتی ہے۔
  • ویب ایپ کا حصہ ایک JavaScript بंडل ہے جو ویب ایپ کے ساتھ براؤزر میں لوڈ ہوتا ہے۔ یہ رجسٹری کے ساتھ React اجزاء اور کال بیکس رجسٹر کرتا ہے: مینو میں بٹن، پینل، یا پیغام کے کسی قسم کو ڈرا کرنے کا طریقہ۔
  • دونوں حصے اختیاری ہیں۔ ایک ایپ .tar.gz بंडل کے طور پر انسٹال ہوتی ہے، اور سسٹم ایڈمنز اسے فعال، غیر فعال اور ترتیب دیتے ہیں۔
سرور کا حصہ سرور کے ڈیٹا تک مکمل رسائی کے ساتھ چلتا ہے۔ ایپ کو اس طرح سمجھیں جیسے آپ سرور پر ڈپلوائے ہونے والا کوڈ۔

Antimatter Mattermost کے لیے لکھی گئی ایپس کو چلاتا ہے، اور اس کے برعکس بھی، بشرطیکہ ایپ صرف ان ہکس کا استعمال کرے جو دونوں میں موجود ہیں۔ دیکھیں صرف Antimatter کے ہکس۔

بंडل کی ترتیب

کوئی الگ اسٹارٹر ٹیمپلیٹ موجود نہیں ہے: ایک چھوٹی شامل شدہ ایپ جیسے antimatter-plugin-polls یا antimatter-plugin-todo سے شروع کریں، اور اس کا ID اور کوڈ تبدیل کریں۔ Polls کی ترتیب اس طرح ہے:

antimatter-plugin-polls/
├── plugin.json            the manifest
├── Makefile               build, test, bundle, deploy
├── build/                 the manifest and pluginctl helper tools (Go), setup.mk
├── assets/icon.svg        files shipped with the bundle

سرور کا حصہ

سرور کا حصہ Mattermost ایپس کے جیسا ہی Go ماڈیول، github.com/mattermost/mattermost/server/public، Go ماڈیول پروکسی سے امپورٹ کرتا ہے۔ اس کا main صرف ایپ کو شروع کرتا ہے:

package main

import "github.com/mattermost/mattermost/server/public/plugin"

func main() {
	plugin.ClientMain(&Plugin{})
}

Plugin ٹائپ plugin.MattermostPlugin کو ایمبیڈ کرتا ہے، جس سے اسے p.API ملتا ہے، اور وہ ہکس (hooks) کو نافذ کرتا ہے جو اسے درکار ہیں:

type Plugin struct {
	plugin.MattermostPlugin
	router *mux.Router
}

func (p *Plugin) OnActivate() error {
	p.router = p.newRouter()
	return p.API.RegisterCommand(&model.Command{
		Trigger:          "weather",
		AutoComplete:     true,
		AutoCompleteDesc: "Show the forecast",
		AutoCompleteHint: "[city]",
	})
}

func (p *Plugin) ExecuteCommand(c *plugin.Context, args *model.CommandArgs) (*model.CommandResponse, *model.AppError) {
	city := strings.TrimSpace(strings.TrimPrefix(args.Command, "/weather"))
	return &model.CommandResponse{
		ResponseType: model.CommandResponseTypeEphemeral,
		Text:         "Forecast for " + city + ": sunny",
	}, nil
}

func (p *Plugin) ServeHTTP(c *plugin.Context, w http.ResponseWriter, r *http.Request) {
	p.router.ServeHTTP(w, r)
}

عام ہکس

ہککب چلتا ہے
OnActivate, OnDeactivateجب ایپ کو فعال یا غیر فعال کیا جائے، اور جب سرور شروع ہو یا بند ہو۔ OnActivate میں کمانڈز اور بوٹس رجسٹر کریں۔
OnConfigurationChangeجب اس کی ترتیبات تبدیل ہوں؛ انہیں p.API.LoadPluginConfiguration(&cfg) کے ذریعے لوڈ کریں۔
ServeHTTP/plugins/<app id>/… کی درخواستیں۔ جب درخواست سائنڈ ان صارف سے آتی ہے تو سرور Mattermost-User-Id ہیڈر سیٹ کرتا ہے؛ اس کے بغیر درخواستوں کو مسترد کریں، مگر یہ سوائے اس کے کہ وہ عوامی ہونے کا مقصد رکھتی ہوں۔
ExecuteCommandایپ نے رجسٹر کی ہوئی کمانڈ چلا دی گئی۔
MessageWillBePosted, MessageWillBeUpdatedپیغام محفوظ ہونے سے پہلے: تبدیل شدہ پوسٹ واپس کریں، یا اسے مسترد کرنے کی وجہ دیں۔
MessageHasBeenPosted, MessageHasBeenUpdated, MessageHasBeenDeletedبعد ازاں، جانبی اثرات کے لیے۔
ReactionHasBeenAdded, ReactionHasBeenRemovedردعمل۔
UserHasJoinedChannel, UserHasLeftChannel, UserHasJoinedTeam, UserHasLeftTeam, ChannelHasBeenCreatedرکنیت اور چینلز میں تبدیلیاں۔ ٹیم ایک کمیونٹی ہے۔
FileWillBeUploadedفائل محفوظ ہونے سے پہلے: اسے تبدیل کریں یا مسترد کریں۔
OnPluginClusterEventکلسٹر کے دوسرے سرور پر موجود اسی ایپ سے پیغام۔

مکمل فہرست، بالکل درست سائنچرز کے ساتھ، server/public/plugin/hooks.go میں ہے؛ API server/public/plugin/api.go میں ہے۔ pluginapi پیکیج (server/public/pluginapi) API کو دوستانہ ہیلپرز میں لفٹ کرتا ہے۔

مفید API کالز

  • CreatePost، UpdatePost، SendEphemeralPost: ایپ کے بوٹ کے طور پر یا کسی صارف کے طور پر پوسٹ کریں۔
  • EnsureBotUser(&model.Bot{Username, DisplayName}): ایپ کا بوٹ ایک بار بنائیں اور اس کا ID حاصل کریں۔
  • PublishWebSocketEvent("poll_updated", payload, &model.WebsocketBroadcast{ChannelId: id}): ویب ایپ کو ایونٹ بھیجیں۔ یہ custom_<app id>_poll_updated کے طور پر پہنچتا ہے۔
  • OpenInteractiveDialog: ڈائیلاگ کھولیں۔
  • LogInfo، LogError اور اسی طرح کے: سرور لاگ میں لکھیں، ایپ کے ID کے ساتھ ٹیگ شدہ۔
  • GetUser، GetChannel، HasPermissionToChannel: کسی صارف کے لیے عمل کرنے سے پہلے چیک کریں کہ کس کو کیا کرنے کی اجازت ہے۔

ایپ کلسٹر کے ہر سرور پر چلتی ہے۔ اسٹیٹ کو کیو وی اسٹور یا ڈیٹا بیس میں رکھیں، صرف میموری میں نہیں۔

ڈیٹا کا ذخیرہ

ہر ایپ کے لیے سرور کے ڈیٹا بیس میں اپنا الگ کیو وی اسٹور ہوتا ہے:

  • KVSet(key, value), KVGet(key), KVDelete(key): ویلیوز بائٹس ہوتی ہیں، عموماً JSON۔ کیز زیادہ سے زیادہ 150 حروف کے ہو سکتے ہیں۔
  • KVSetWithExpiry(key, value, seconds): ویلیو اس وقت کے بعد غائب ہو جاتی ہے۔
  • KVCompareAndSet(key, old, new) اور KVSetWithOptions کے ساتھ Atomic: جب کئی درخواستیں یا سرورز ایک ہی کی پر لکھتے ہوں تو محفوظ اپڈیٹس۔ پولز اس طریقے سے ہر ووٹ محفوظ کرتا ہے اور تصادم پر دوبارہ کوشش کرتا ہے۔
  • KVList(page, perPage): کیز، صفحہ بہ صفحہ۔

ویب ایپ کا حصہ

بندل window.registerPlugin کے ذریعے ایک کلاس رجسٹر کرتا ہے۔ اس کا initialize رجسٹری اور Redux اسٹور وصول کرتا ہے:

import manifest from './manifest';

class Plugin {
    initialize(registry, store) {
        registry.registerTranslations((locale) => translationsFor(locale));
        registry.registerPostTypeComponent('custom_poll', PollPost);
        registry.registerWebSocketEventHandler(`custom_${manifest.id}_poll_updated`, (msg) => {
            store.dispatch(pollUpdated(JSON.parse(msg.data.poll)));
        });
        registry.registerReconnectHandler(() => store.dispatch(reloadPolls()));
    }
}

window.registerPlugin(manifest.id, new Plugin());
  • مشترک لائبریریاں۔ ویب ایپ React، ReactDOM، Redux، React Redux اور React Intl فراہم کرتی ہے: انہیں webpack externals (React, ReactDOM, Redux, ReactRedux, ReactIntl) کے طور پر درج کریں، اپنے کاپیوں کو بندل کرنے کے بجائے۔ Polls کے webpack.config.js کو دیکھیں۔
  • اپنے سرور حصے کو کال کرنا۔ ${window.basename}/plugins/<app id>/… کو Client4.getOptions() (جو mattermost-redux/client سے آتا ہے) کے آپشنز کے ساتھ Fetch کریں: یہ وہ ہیڈرز ہیں جو سرور کو براؤزر سے آنے والی درخواست کو قبول کرنے کے لیے درکار ہوتی ہیں۔
  • آپ کا اپنا اسٹیٹ۔ registerReducer ایک ریڈیوسر شامل کرتا ہے، جو state['plugins-<app id>'] کے تحت محفوظ ہوتا ہے۔
  • ٹائپس۔ Antimatter کے اضافی رجسٹری طریقے Mattermost کے شائع شدہ ٹائپس میں شامل نہیں ہیں: Polls webapp/src/types/host.ts میں وہ رجسٹری اعلان کرتا ہے جسے استعمال کرتا ہے۔

رجسٹری کے طریقے اور ان کے پیرامیٹرز کوڈ میں دستاویزات کے طور پر موجود ہیں، webapp/fusion/src/plugins/registry.ts (Fusion) اور webapp/channels/src/plugins/registry.ts (classic) میں۔

Fusion انٹرفیس کی معاونت

Antimatter کے دو ویب انٹرفیس ہیں: Fusion، جو ڈیفالٹ ہے، اور کلاسیکی۔ دونوں ایک جیسے ایپ بندلز لوڈ کرتے ہیں اور ایک جیسی رجسٹری رکھتے ہیں، لیکن Fusion کئی چیزیں خود بناتا ہے اور پلگ ان اجزاء کو اپنی طرز پر رکھتا ہے۔ اپنی ایپ کو دونوں میں ٹیسٹ کریں۔

انٹرفیس کی شناخت

کسی بھی ایپ کے لوڈ ہونے سے پہلے، دونوں انٹرفیس window.antimatterWebUI کو 'fusion' یا 'classic' پر سیٹ کرتے ہیں، اور اسی ویلیو کو صفحے کے روٹ عنصر پر data-am-web-ui کے طور پر۔ Mattermost پر، نہ تو یہ سیٹ ہوتا ہے۔

export function isFusionUI(): boolean {
    return window.antimatterWebUI === 'fusion' || document.documentElement.dataset.amWebUi === 'fusion';
}

بندل شدہ ایپس اس کے ذریعے مختلف انداز میں ڈرائے کرتی ہیں۔ پولز اپنی پول کارڈز اور تخلیق کے ڈائیلاگ کو فیوژن کے انداز میں ڈرائے کرتی ہے، اور فیوژن میں /poll کے لیے اپنا الگ ڈائیلاگ کھولتی ہے۔ کالز اور وائس چینلز سائیڈ بار اور ٹوسٹ کمپوننٹس کو چھوڑ دیتی ہیں، جو فیوژن اپنی کال انٹرفیس کے ساتھ تبدیل کر دیتا ہے۔ ایجنٹس ایپ اپنے AI ایکشنز کو ہاور ٹول بار کے بجائے میسج مینیو کے ذریعہ (submenu) میں رکھتی ہے۔ فیوژن کی اپنی CSS classes (جو am- سے شروع ہوتی ہیں) اور اس کا ڈائیلاگ لیئر (am-layer عنصر) وہ چیزیں ہیں جن کا ان ایپس نے انٹرفیس کو مماثل بنانے کے لیے استعمال کیا ہے؛ یہ کوئی دستاویزی شدہ یا مستحکم API نہیں ہیں۔

جہاں فیوژن پلگ ان کمپوننٹس دکھاتا ہے

ہکس جو صرف Antimatter میں ہیں

یہ رجسٹری طریقے Mattermost پر موجود نہیں ہیں۔ کال کرنے سے پہلے چیک کریں کہ طریقہ موجود ہے، تاکہ ایپ وہاں بھی کام کرے:

if (typeof registry.registerComposerMenuItem === 'function') {

طریقہیہ کیا شامل کرتا ہے

fusionIcon Fusion کے آئیکن سیٹ میں سے ایک آئیکن کا نام ہے (مثلاً poll، sticker، calendar یا image؛ دیکھیں webapp/fusion/src/fusion/components/icon)۔ Fusion اسے icon کی جگہ دکھاتا ہے، تاکہ یہ آئیٹم دوسروں کے مطابق ہو۔

ترتیبات

plugin.json میں settings_schema سسٹم کنسول › پلگ انز میں ایپ کا صفحہ بیان کرتا ہے:

"settings_schema": {
  "header": "Forecasts come from the weather service below.",
  "settings": [
    {"key": "ServiceURL", "display_name": "Service URL", "type": "text", "default": "https://api.example.com"},
    {"key": "Units", "display_name": "Units", "type": "dropdown", "default": "metric",
     "options": [{"display_name": "Celsius", "value": "metric"}, {"display_name": "Fahrenheit", "value": "imperial"}]},
    {"key": "EnableAlerts", "display_name": "Severe weather alerts", "type": "bool", "default": false,
     "help_text": "Post alerts in the channels that follow a city."}
  ]
}

ترتیبات کی اقسام: bool، text، longtext، number، dropdown، radio، generated (ایک رینڈم سیکرٹ)، username، اور custom (جو ایک کمپوننٹ سے بنایا جاتا ہے جو ویب ایپ حصہ registerAdminConsoleCustomSetting کے ساتھ رجسٹر کرتا ہے)۔ ترتیبات کو sections میں گروپ کیا جا سکتا ہے۔

سرور کا حصہ انہیں ایک سٹرکٹ میں پڑھتا ہے جس کے فیلڈز کیز کے مطابق ہوتے ہیں:

type configuration struct {
	ServiceURL   string
	Units        string
	EnableAlerts bool
}

func (p *Plugin) OnConfigurationChange() error {
	var cfg configuration
	if err := p.API.LoadPluginConfiguration(&cfg); err != nil {
		return err
	}
	p.setConfiguration(&cfg)
	return nil
}

ایڈمنز انہیں کنفیگریشن میں بھی سیٹ کر سکتے ہیں، PluginSettings.Plugins.<app id> کے تحت، چھوٹے حروف میں کیز کے ساتھ (دیکھیں ایڈمن گائیڈ)۔

ترجمے

Antimatter کو 37 زبانوں میں ترجمہ کیا گیا ہے، اور شامل ایپس بھی۔ ویب ایپ کا حصہ اسے اس طرح کرتا ہے:

  1. ہر سٹرنگ کو React Intl کے ساتھ لکھیں، ایک ID اور اس کے انگریزی متن کے ساتھ: <FormattedMessage id='polls.create' defaultMessage='Create a poll'/> یا defineMessages۔ IDs کو اپنی ایپ کے نام سے پیش کریں۔
  2. انگریزی سٹرنگز کو webapp/i18n/en.json میں نکالیں (شامل ایپس formatjs extract استعمال کرتی ہیں)۔
  3. اس کے ساتھ ہر زبان کے لیے ایک فائل شامل کریں، ایک ہی IDs کے ساتھ: fr.json، de.json، pt-BR.json، zh-CN.json…
  4. انہیں ویب ایپ کو دیں، جو صارف کی زبان پوچھتی ہے: 
    import fr from '../i18n/fr.json';
import ptBR from '../i18n/pt-BR.json';

const catalogs = {fr, 'pt-BR': ptBR};

export function translationsFor(locale) {
    return catalogs[locale] || catalogs[locale.split('-')[0]] || {};
}

registry.registerTranslations(translationsFor);

اگر کوئی سٹرنگ موجود نہ ہو تو اس کی انگریزی defaultMessage استعمال ہوتی ہے۔ ان سٹرنگز کے لیے جو سرور حصہ بھیجتا ہے (کمانڈ کے جوابات، بوٹ پیغامات)، pluginapi/i18n پیکج بنڈل میں شامل ترجمہ فائلز (مثلاً assets/i18n) لوڈ کرتا ہے اور ہر صارف کی زبان میں لوکلائزر فراہم کرتا ہے۔

بنائیں، انسٹال کریں اور ڈیبگ کریں

آپ کو Go اور Node.js (ایپ کے .nvmrc میں دی گئی ورژن) درکار ہیں۔ ایپ کے فولڈر میں:

کمانڈیہ کیا کرتا ہے
make distہر پلیٹ فارم کے لیے سرور حصہ اور ویب ایپ حصہ بناتا ہے، اور بنڈل کو dist/<app id>-<version>.tar.gz میں لکھتا ہے۔
make testGo اور JavaScript ٹیسٹ چلاتا ہے۔
make check-styleکوڈ کو لِنٹ کرتا ہے (golangci-lint, ESLint) اور TypeScript کی قسموں کی جانچ کرتا ہے۔
make deployبناتا ہے، پھر سرور پر بنڈل کو انسٹال اور فعال کرتا ہے۔
make watch, make deploy-from-watchپہلا ہر بار آپ کے سیو کرنے پر ویب ایپ حصہ دوبارہ بناتا ہے؛ دوسرا جو کچھ بنایا اسے بنڈل کر کے سرور پر انسٹال کرتا ہے۔
make enable, make disable, make resetسرور پر ایپ کو فعال، غیر فعال یا دوبارہ شروع کریں۔
make logs, make logs-watchسرور لاگ میں ایپ کی لائنز دکھائیں۔
make attachچل رہے سرور حصے کے ساتھ Delve ڈیبگر کو منسلک کرتا ہے (پہلے AM_DEBUG=1 کے ساتھ بنائیں)۔

make deploy اور دیگر سرور کمانڈز جب ایک مقامی موڈ سوکیٹ پاتے ہیں (/var/tmp/antimatter_local.socket، یا AM_LOCALSOCKETPATH) تو اسے استعمال کرتے ہیں: انہیں مقامی موڈ آن ہو کر سرور کی مشین پر چلائیں۔ ورنہ وہ MM_SERVICESETTINGS_SITEURL سے دیے گئے سرور پر AM_ADMIN_TOKEN، یا AM_ADMIN_USERNAME اور AM_ADMIN_PASSWORD کے ساتھ سائن ان کرتے ہیں۔ بلڈ ٹولز ابھی سائٹ URL کے لیے AM_ نام نہیں پڑھتے۔

بنڈل کو دستی طور پر انسٹال کریں

  • سسٹم ایڈمن AM_PLUGINSETTINGS_ENABLEUPLOADS=true کے ساتھ اپ لوڈز کی اجازت دیتا ہے (ڈیفالٹ طور پر بند؛ سسٹم کنسول میں کوئی سوئچ نہیں ہے)۔
  • پھر سسٹم کنسول › پلگ انز › پلگ ان مینجمنٹ › پلگ ان اپ لوڈ کریں، یا amctl plugin add weather.tar.gz کے بعد amctl plugin enable com.example.weather۔
  • اگر سروسرور پر پلگ ان سائنچر کو لازمی قرار دیں آن ہے، تو یہ صرف ان باندلز کو قبول کرتا ہے جو اس کے اعتماد کے ساتھ سائن شدہ ہوں؛ دیکھیں دیگر ایپس کی تنصیب۔
ڈویلپمنٹ سرور پر تیز دہائیوں کے لیے، سرور پر AM_SERVICESETTINGS_ENABLEDEVELOPER=true سیٹ کریں: اس صورت میں غلطیاں اپنے تفصیلی معلومات کے ساتھ آتی ہیں۔ بنڈل شدہ ایپس کے Makefiles صرف تب آپ کے پلیٹ فارم کے لیے سرور حصہ بناتے ہیں جب آپ کے شیل میں MM_SERVICESETTINGS_ENABLEDEVELOPER سیٹ ہو۔
