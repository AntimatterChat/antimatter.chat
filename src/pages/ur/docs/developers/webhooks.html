ویب ہکس کا انتظام کہاں کریں

اوپر دائیں جانب اپنے ایواٹار پر کلک کریں، پھر انضمامات پر جائیں۔ موجودہ کمیونٹی کے انضمامات کے صفحات پر ان کمنگ ویب ہکس اور آؤٹ گوئیگ ویب ہکس درج ہیں۔ ہر ویب ہک ایک کمیونٹی سے تعلق رکھتا ہے۔

ڈیفالٹ طور پر، کمیونٹی ایڈمنز اور سسٹم ایڈمنز ویب ہکس بنا سکتے ہیں۔ سسٹم ایڈمن سسٹم کنسول کی پرمیشن ترتیبات میں دوسرے رولز کو یہ حق دے سکتا ہے۔ سسٹم ایڈمن سسٹم کنسول › انضمامات › انٹیگریشن مینجمنٹ میں ہر قسم کو بند بھی کر سکتا ہے: انکمنگ ویب ہکس فعال کریں اور Outgoing Webhooks فعال کریں دونوں ڈیفالٹ طور پر آن ہیں۔

ایک داخلہ ویب ہک بنائیں

  1. انضمامات میں، ان کمنگ ویب ہکس منتخب کریں، پھر ان کمنگ ویب ہک شامل کریں پر کلک کریں۔
  2. عنوان اور تفصیل درج کریں: یہ صرف انضمامات کے صفحات پر دکھائی دیتے ہیں۔
  3. وہ چینل منتخب کریں جس میں پیغامات ڈیفالٹ طور پر جائیں گے۔ ایک ذاتی چینل کے لیے، آپ کو اس کا رکن ہونا ضروری ہے۔
  4. اگر بھیجنے والوں کو کہیں اور پوسٹ کرنے کی اجازت نہیں ہونی چاہیے، تو اس چینل کو لاک کریں پر ٹک کریں۔
  5. اختیاری طور پر اس کے پیغامات کے لیے صارف نام اور پروفائل تصویر URL مقرر کریں (دیکھیں نام اور آئیکن)۔
  6. محفوظ کریں منتخب کریں۔ دکھائی دینے والا URL کاپی کریں: https://chat.example.com/hooks/<key>۔
URL واحد راز ہے: جو اسے رکھتا ہے وہ چینل میں پوسٹ کر سکتا ہے۔ اسے عوامی repositories سے دور رکھیں، اور اگر یہ لیک ہو جائے تو ویب ہک حذف کر دیں۔

API کے ذریعے: POST /api/v4/hooks/incoming کے ساتھ {"channel_id", "display_name", "description", "username", "icon_url", "channel_locked"}؛ response کے id کو key کے طور پر استعمال کریں۔ command line سے: amctl webhook create-incoming --channel <channel id> --user <user> --display-name "CI"۔

ایک داخلہ ویب ہک کو پیغام بھیجیں

curl -X POST https://chat.example.com/hooks/xgh5ycrx1jf7mbs9w8z4c8e7ho \
  -H 'Content-Type: application/json' \
  -d '{"text": "Deploy of **api 2.4.0** finished :white_check_mark:"}'

سرور 200 کے ساتھ ok body کے جواب دیتا ہے۔ یہ application/x-www-form-urlencoded کو بھی قبول کرتا ہے جس میں JSON ایک payload field میں ہوتا ہے، جیسا کہ Slack کے ویب ہکس کرتے ہیں، اس لیے Slack کے لیے بنائے گئے tools عام طور پر بغیر تبدیلی کے کام کرتے ہیں۔

فیلڈمعنی
textپیغام، Markdown میں۔ اگر attachments موجود نہ ہوں تو یہ لازمی ہے۔ اگر متن سرور کے پیغام کی حد سے طویل ہو تو اسے کئی پیغامات میں تقسیم کر دیا جاتا ہے۔
channelویب ہک کی کمیونٹی کا کوئی اور چینل، نام کے ذریعے (ops-alerts یا #ops-alerts)، یا ویب ہک کے مالک کے براہِ راست پیغام کے لیے @username۔ اگر ویب ہک اپنے چینل پر قفل ہو تو یہ مسترد کر دیا جاتا ہے۔
username, icon_url, icon_emojiنام اور تصویر، جب سرور تبدیلیوں کی اجازت دے۔
attachmentsپیغام کے منسلک فائل، جو کارڈز کی صورت میں دکھائے جاتے ہیں (نیچے)۔
propsپیغام پر محفوظ اضافی خصوصیات، ایپس کے لیے جو انہیں پڑھتی ہیں۔
typeایک کسٹم پوسٹ قسم، جیسے custom_poll، کسی ایپ کے لیے جو اسے دکھاتی ہے۔ system_ سے شروع ہونے والی اقسام مسترد کر دی جاتی ہیں۔
root_idکسی سلسلے کے پہلے پیغام کی ID، تاکہ اسی سلسلے میں جواب دیا جا سکے۔
priorityپیغام کی ترجیح، مثال کے طور پر {"priority": "urgent"}۔
silenttrue پیغام کو پش اطلاعات کے بغیر بھیجتا ہے۔

اگر کوئی پیغام اوور رائڈ شدہ نام کے تحت دکھایا جائے، تو اس کے ساتھ بوٹ ٹگ لگایا جاتا ہے تاکہ لوگ اسے حقیقی اکاؤنٹس سے پہچان سکیں۔ ویب ہک کے پیغامات کبھی بھی آؤٹ گوئیگ ویب ہکس کو ٹریگر نہیں کرتے۔

نام اور آئیکن

ویب ہک اس شخص کے طور پر پوسٹ کرتا ہے جس نے اسے بنایا، سوائے اس کے کہ سرور اوور رائڈز کی اجازت دے۔ سسٹم کنسول › انضمامات › انٹیگریشن مینجمنٹ میں دو ترتیبات، جو دونوں ڈیفالٹ طور پر آف ہیں، اسے تبدیل کرتی ہیں:

  • انٹیگریشنز کو یوزرنیمز کو اوور رائڈ کرنے کی اجازت دیں (ServiceSettings.EnablePostUsernameOverride): ویب ہک کا صارف نام یا درخواست کا username دکھایا جاتا ہے؛ اگر نہ کوئی صارف نام ہو نہ درخواست میں، تو نام webhook ہوگا۔
  • انٹیکریشنز کو پروفائل تصویر آئیکنز اوور رائڈ کرنے کی اجازت دیں (ServiceSettings.EnablePostIconOverride): ویب ہک کی پروفائل تصویر، یا درخواست کا icon_url یا icon_emoji دکھایا جاتا ہے۔

درخواست میں موجود قدر ویب ہک پر محفوظ شدہ قدر پر برتری حاصل کرتی ہے۔

منسلک فائل

منسلک فائل متن کے نیچے منظم مواد شامل کرتی ہیں۔ یہ Slack کے پیغام منسلک فائل فارمیٹ کی پیروی کرتی ہیں:

{
  "text": "Build failed on `main`",
  "attachments": [{
    "fallback": "main #1902 failed",
    "color": "#d24b4e",
    "author_name": "GitHub Actions",
    "author_icon": "https://chat.example.com/static/ci.png",
    "title": "main #1902 failed",
    "title_link": "https://ci.example.com/runs/1902",

فیلڈمعنی
fallbackسادہ متن، ان مقامات کے لیے جو کارڈ دکھا نہیں سکتے، جیسے اطلاعات۔
colorرنگین بار: ایک hex رنگ، یا good، warning، danger۔
pretextکارڈ کے اوپر متن۔
author_name, author_link, author_iconایک چھوٹی ہیڈر لائن۔
title, title_linkکارڈ کا عنوان، اختیاری طور پر لنک کے ساتھ۔
textکارڈ کا جسم، Markdown میں۔
fields{"title", "value", "short"} کی فہرست؛ short فیلڈز ایک دوسرے کے ساتھ ساتھ بیٹھی ہوتی ہیں۔
image_url, thumb_urlنیچے ایک بڑی تصویر، یا کنارے پر ایک چھوٹی۔
footer, footer_icon, tsفوٹر لائن اور وقت (Unix سیکنڈز)۔
actionsبٹن اور مینو: دیکھیں Interactive messages۔

کارڈز: مراحل اور چارٹس

Antimatter منسلک فائلوں میں دو فیلڈز شامل کرتا ہے، جو ڈیفالٹ انٹرفیس کے ذریعے دکھائی جاتی ہیں:

  • stages: پائپ لائن کے مراحل، جو پیلز (pills) کی صورت میں، زیادہ سے زیادہ 20 تک۔ ہر ایک {"name", "status"} ہوتا ہے، جس میں اسٹیٹس passed، failed، running، pending، skipped یا canceled ہو سکتا ہے۔
  • chart: حالیہ اقدار کا ایک چھوٹا لائن چارٹ، {"values": [2 to 200 numbers], "threshold": number, "label": "…"}۔ تھری شولڈ کو ایک ڈیشڈ لائن کے طور پر دکھایا جاتا ہے، جو الرٹ کی حد کے لیے استعمال ہوتا ہے۔
{
  "attachments": [{
    "color": "danger",
    "title": "main #1902 failed",
    "stages": [
      {"name": "build", "status": "failed"},
      {"name": "unit", "status": "skipped"},
      {"name": "publish", "status": "skipped"}
    ]
  }, {
    "color": "warning",
    "title": "API latency above 400 ms",
    "chart": {"values": [210, 230, 260, 390, 450, 470], "threshold": 400, "label": "p95 latency, ms"}
  }]
}

کلاسیکی انٹرفیس اور دیگر کلائنٹس ان دو فیلڈز کو نظرانداز کرتے ہیں، اس لیے بنیادی معلومات کو text یا fields میں بھی شامل کریں۔

آؤٹ گوئنگ ویب ہک بنائیں

آؤٹ گوئنگ ویب ہک کمیونٹی کے عوامی چینلز کی نگرانی کرتا ہے۔ جب کسی پیغام کا پہلا لفظ اس کے ٹریگر ورڈز میں سے کسی ایک سے مطابقت رکھتا ہے، Antimatter اس پیغام کو آپ کے URL پر بھیجتا ہے۔

  1. انضمامات میں، آؤٹ گوئیگ ویب ہکس منتخب کریں، پھر آؤٹ گوئنگ ویب ہک شامل کریں پر کلک کریں۔
  2. عنوان اور تفصیل درج کریں۔
  3. درخواست کے Content Type کا انتخاب کریں: application/x-www-form-urlencoded یا application/json۔
  4. چینل منتخب کریں، Trigger Words (ہر ایک ایک لائن پر) درج کریں، یا دونوں۔ اگر چینل ہو اور ٹریگر ورڈز نہ ہوں، تو اس چینل کے تمام پیغامات بھیجے جائیں گے۔ اگر دونوں ہوں، تو پیغام دونوں سے مماثل ہونا چاہیے۔
  5. Trigger جب کے تحت، پہلا لفظ ٹریگر ورڈ سے بالکل مماثل ہو یا پہلا لفظ ٹریگر ورڈ سے شروع ہو منتخب کریں۔
  6. کی بیک URLs (ہر لائن پر ایک) درج کریں۔ ہر URL کو ہر مماثل پیغام ملے گا۔
  7. اختیاری طور پر صارف نام اور پروفائل تصویر مقرر کریں جو جوابات کے لیے استعمال ہوں گی۔
  8. محفوظ کریں منتخب کریں اور دکھایے گئے ٹوکن کو کاپی کریں۔ آپ کا سروس اس ٹوکن کا استعمال کرتا ہے تاکہ تصدیق کر سکے کہ درخواستیں آپ کے سرور سے آ رہی ہیں۔

API کے ذریعے: POST /api/v4/hooks/outgoing کے ساتھ {"team_id", "channel_id", "trigger_words", "trigger_when", "callback_urls", "content_type", "display_name"} (trigger_when: مکمل مطابقت کے لیے 0، "starts with" کے لیے 1)۔

اگر آپ کا سروس ایک پرائیویٹ نیٹ ورک پر ہے، تو سسٹم ایڈمن کو غیر مستند اندرونی کنکشنز کی اجازت دیں (ServiceSettings.AllowedUntrustedInternalConnections) میں اس کا پتہ شامل کرنا ہوگا۔ ورنہ سرور پرائیویٹ پتوں کو کال نہیں کرتا۔

آؤٹ گوئنگ درخواست

Antimatter ان فیلڈز کے ساتھ ایک POST بھیجتا ہے، جو JSON یا فارم-اینکوڈڈ ہوتی ہے، معیاری قسم کے مطابق:

{
  "token": "6kd1ofo5ojr5zgu5ipfipybgnc",
  "team_id": "…",
  "team_domain": "lumen-labs",
  "channel_id": "…",
  "channel_name": "ops-alerts",
  "timestamp": 1760010000000,
  "user_id": "…",
  "user_name": "priya",
  "post_id": "…",
  "text": "deploy api 2.4.0",
  "trigger_word": "deploy",
  "file_ids": ""
}

کچھ بھی کرنے سے پہلے token کو ویب ہک کے ٹوکن کے ساتھ موازنہ کریں۔ فارم-اینکوڈڈ ورژن میں timestamp سیکنڈز میں ہوتا ہے، ملی سیکنڈز میں نہیں۔ سرور آپ کے جواب کے انتظار میں انٹیکریشن درخواست ٹائم آؤٹ کی حد تک (ڈیفالٹ طور پر 30 سیکنڈ، ServiceSettings.OutgoingIntegrationRequestsTimeout) رکتا ہے۔

آؤٹ گوئنگ ویب ہک کا جواب

جواب پوسٹ کرنے کے لیے JSON کے ساتھ جواب دیں۔ کچھ بھی پوسٹ نہ کرنے کے لیے خالی باڈی کے ساتھ جواب دیں۔

{
  "text": "Deploying **api 2.4.0** to staging…",
  "response_type": "comment",
  "username": "deploy-bot",
  "icon_url": "https://chat.example.com/static/deploy.png"
}
  • text اور attachments: جواب۔ دونوں کے بغیر، کچھ بھی پوسٹ نہیں ہوگا۔
  • response_type: comment جواب کو اس چینل میں پوسٹ کرتا ہے جہاں ٹریگر پیغام تھا؛ ورنہ یہ چینل میں جاتا ہے۔
  • username، icon_url: جب سروسر اوور رائڈ کی اجازت دیتا ہے تو یہ دکھائے جاتے ہیں؛ ورنہ ویب ہک کے اپنے اقدار استعمال ہوتی ہیں۔
  • props، type، priority: آئنگوئنگ ویب ہکس کی طرح۔

جواب ویب ہک کے بنانے والے کے نام سے پوسٹ ہوتا ہے، جب اوور رائڈ شدہ نام موجود ہو تو اس کے نام سے۔ تیز جواب سے طویل کچھ کے لیے، فوراً جواب دیں اور بعد میں آئنگوئنگ ویب ہک یا API کے ذریعے پوسٹ کریں۔

جب ویب ہک کام نہ کرے

  • 501 from the hook URL: سروسر پر آئنگوئنگ ویب ہکس بند ہیں۔
  • 400 "Failed to decode the payload…": JSON درست نہیں ہے، یا فارم فیلڈ کا نام payload نہیں ہے۔ "No text specified." کا مطلب ہے کہ درخواست میں نہ تو text ہے اور نہ attachments۔
  • 403: ویب ہک کسی اور چینل کے لیے لاک ہے، یا اس کے مالک اب چینل نہیں پڑھ سکتے۔
  • آؤٹ گوئنگ ویب ہک کبھی فائر نہیں ہوتا: چینل ذاتی ہے، ٹریگر پہلا لفظ نہیں ہے، یا پیغام کسی ویب ہک سے آیا ہے۔
  • لاگز: ویب ہک ڈیبگنگ کو فعال کریں (LogSettings.EnableWebhookDebugging) کو آن کرنے پر، اور لاگ لیول کو DEBUG پر رکھنے پر، سرور ناکام داخلہ طلبیوں کے پیلوڈز کو لاگ کرتا ہے۔ ناکام خارجہ کالز کو Outgoing Webhook POST failed کے طور پر لاگ کیا جاتا ہے۔
