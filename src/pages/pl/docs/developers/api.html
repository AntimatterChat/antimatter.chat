Podstawy

  • Adres URL bazowy: https://chat.example.com/api/v4. Wszystkie poniższe punkty końcowe są względne wobec tego adresu.
  • Format: dane wejściowe i wyjściowe w formacie JSON, z wyjątkiem przesyłania plików (multipart). Wysłanie nagłówka Content-Type: application/json jest wymagane.
  • Identyfikatory: każdy obiekt ma 26-znakowy id. Czas jest wyrażony w milisekundach od epoki Unix (create_at, update_at, delete_at; wartość 0 oznacza „nie usunięto”).
  • Wspólnoty to zespoły: interfejs API nazywa je teams i używa identyfikatora team_id.
  • sam: wszędzie tam, gdzie ścieżka przyjmuje user_id, me oznacza zalogowanego użytkownika, np. GET /users/me.

Pełna lista punktów końcowych znajduje się w kodzie serwera: trasy są zadeklarowane w server/channels/api4/*.go, a typy w server/public/model. Opis OpenAPI w folderze api/v4/source w repozytorium obejmuje punkty końcowe dziedziczone z Mattermost, a nie dodatki Antimatter.

Uwierzytelnianie

Każde żądanie, z wyjątkiem logowania i kilku publicznych punktów końcowych, wymaga tokena w nagłówku Authorization:

curl -H "Authorization: Bearer $TOKEN" https://chat.example.com/api/v4/users/me

Akceptowane są trzy rodzaje tokenów: osobiste tokeny dostępu, tokeny sesji i tokeny dostępu OAuth. Akceptowany jest również format Authorization: Token …. Tokeny w parametrach zapytania (?access_token=) są akceptowane wyłącznie dla tokenów dostępu OAuth.

Osobiste tokeny dostępu (zalecane dla skryptów)

Osobisty token dostępu działa w Twoim imieniu, nie wygasa, chyba że ustawisz dla niego datę wygaśnięcia, i może zostać odwołany w dowolnym momencie. Osobiste tokeny dostępu są domyślnie wyłączone:

  1. Administrator systemu włącza Włącz osobiste tokeny dostępu w Konsola systemu › Integracje › Zarządzanie Integracjami (ServiceSettings.EnableUserAccessTokens, AM_SERVICESETTINGS_ENABLEUSERACCESSTOKENS).
  2. Dla każdej osoby, która może tworzyć tokeny, administrator systemu otwiera Konsola systemu › Zarządzanie użytkownikiem › Użytkownicy, wybiera Zarządzanie rolami w menu danej osoby i zaznacza Allow this account to generate personal access tokens. Administratorzy systemu mogą zawsze je tworzyć.
  3. Osoba otwiera swój awatar w prawym górnym rogu, a następnie Profil i ustawienia › Bezpieczeństwo. W sekcji Personalne tokeny dostępu opisuje, do czego służy token, i wybiera Utwórz nowy token. Token jest wyświetlany tylko raz: skopiuj go.

Z użyciem API: POST /users/{user_id}/tokens z {"description": "backup script", "expires_at": 0} (expires_at w milisekundach; 0 oznacza brak wygaśnięcia). Pole token w odpowiedzi to sekret; jego id służy do odwołania tokena (POST /users/tokens/revoke z {"token_id": "…"}). Z wiersza poleceń: amctl token generate <user> <description>.

Administrator systemu może ustawić limit czasu ważności tokenów za pomocą Maksymalny okres ważności osobistego tokenu dostępu (dni) na tej samej stronie Konsoli systemu.

Tokeny sesji

Logowanie hasłem zwraca token sesji w nagłówku odpowiedzi Token, będący tego samego rodzaju sesją, której używają aplikacje:

curl -i -X POST https://chat.example.com/api/v4/users/login \
  -H 'Content-Type: application/json' \
  -d '{"login_id": "maya", "password": "…"}'

Dodaj "token": "123456" dla konta z uwierzytelnianiem wieloskładnikowym. Sesje wygaszają zgodnie z ustawieniami sesji serwera, a punkt końcowy logowania jest ograniczany (5 żądań na sekundę). POST /users/logout kończy sesję.

Przeglądarki uwierzytelniają się za pomocą ciasteczka. Żądanie uwierzytelnione za pomocą ciasteczka musi również wysyłać nagłówek X-CSRF-Token dla wszystkich metod innych niż GET; token w nagłówku Authorization nie wymaga nagłówka CSRF.

Aplikacje OAuth 2.0

Aby umożliwić użytkownikom logowanie do Twojej aplikacji za pomocą konta Antimatter, zarejestruj aplikację OAuth 2.0. Antimatter staje się wtedy dostawcą OAuth:

  1. Opcja Włącz dostawcę usługi OAuth 2.0 musi być włączona (Konsola systemu › Integracje › Zarządzanie integracjami, ServiceSettings.EnableOAuthServiceProvider, domyślnie włączona).
  2. Osoba z odpowiednimi uprawnieniami do zarządzania aplikacjami OAuth (domyślnie administratorzy systemu) otwiera swój awatar, a następnie Integracje › Aplikacje OAuth 2.0 i dodaje aplikację wraz z adresami URL wywołań zwrotnych. Otrzymuje identyfikator klienta (client ID) i sekret klienta (client secret).
  3. Twoja aplikacja przekierowuje użytkowników na https://chat.example.com/oauth/authorize z parametrami response_type=code, client_id, redirect_uri oraz state. Obsługiwane jest PKCE z code_challenge_method=S256.
  4. Wymienia kod na POST https://chat.example.com/oauth/access_token (najpierw grant_type=authorization_code, a następnie refresh_token do odnowienia) i wywołuje API z nagłówkiem Authorization: Bearer <access token>.

Użytkownicy mogą zobaczyć aplikacje, którym udzielili dostępu, w sekcji Profil i ustawienia › Bezpieczeństwo › Autoryzowane aplikacje.

Odesłanie wiadomości

curl -X POST https://chat.example.com/api/v4/posts \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"channel_id": "'$CHANNEL_ID'", "message": "Backup finished: **42 GB** in 3 min"}'

Wiadomości są formatowane w Markdown. Aby odpowiedzieć w wątku, dodaj "root_id" (identyfikator pierwszej wiadomości wątku), "file_ids" dla plików oraz "props" dla załączników i innych dodatków (patrz Załączniki).

Znajdowanie identyfikatora kanału

curl -H "Authorization: Bearer $TOKEN" \
  https://chat.example.com/api/v4/teams/name/lumen-labs/channels/name/ops-alerts

Nazwy to te z linku do kanału: /lumen-labs/channels/ops-alerts.

Paginacja

Punkty końcowe zwracające listy akceptują parametry page (od 0) i per_page (domyślnie 60, maksymalnie 200). Kontynuuj żądanie kolejnych stron, dopóki zwrócona strona nie będzie krótsza niż per_page.

Wiadomości w kanale (GET /channels/{channel_id}/posts) akceptują również since (czas: wszystko zmienione od tego momentu) lub before i after (ID wiadomości). Zwracane są jako lista wiadomości: {"order": [IDs, newest first], "posts": {ID: post}, "next_post_id", "prev_post_id"}.

Błędy

Błędy używają standardowych kodów statusu HTTP (400 błędne dane wejściowe, 401 brak zalogowania, 403 brak uprawnień, 404 nie znaleziono, 501 funkcja wyłączona) oraz treści JSON:

{
  "id": "api.context.permissions.app_error",
  "message": "You do not have the appropriate permissions.",
  "detailed_error": "",
  "request_id": "jz8zm5nunpbt8f3gpqsz5dq6so",
  "status_code": 403
}

Używaj id w swoim kodzie: message jest tłumaczone na język użytkownika. detailed_error jest puste, chyba że serwer działa w trybie deweloperskim (ServiceSettings.EnableDeveloper). Podaj request_id administratorowi serwera: znajduje się on w logach.

Ograniczenia przepustowości

Ograniczenia prędkości są domyślnie wyłączone. Gdy administrator systemu je włączy (Konsola systemu › Środowisko › Ograniczenia Prędkości), każdy klient otrzymuje domyślnie 10 żądań na sekundę z limitami do 100, liczonymi według adresu IP lub użytkownika. Odpowiedzi zawierają X-RateLimit-Limit, X-RateLimit-Remaining i X-RateLimit-Reset; przy przekroczeniu limitu serwer zwraca 429 z nagłówkiem Retry-After w sekundach. Niektóre punkty końcowe, takie jak logowanie, mają własne limity niezależnie od ustawień.

Pisz skrypty, które czekają i ponawiają żądania przy 429, oraz unikaj odpytywania: korzystaj z WebSocket.

Strumień zdarzeń WebSocket

Połącz się z wss://chat.example.com/api/v4/websocket. Uwierzytelnij się za pomocą nagłówka Authorization: Bearer w żądaniu połączenia lub wysyłając to jako pierwsze wiadomość:

{"seq": 1, "action": "authentication_challenge", "data": {"token": "…"}}

Serwer wysyła zdarzenie hello, a następnie zdarzenia dla wszystkiego, co masz uprawnienie zobaczyć:

{
  "event": "posted",
  "data": {"channel_id": "…", "channel_type": "O", "post": "{\"id\":\"…\",\"message\":\"Hello\",…}"},
  "broadcast": {"channel_id": "…", "team_id": "", "user_id": "", "omit_users": null},
  "seq": 4
}

Zauważ, że data.post to post jako ciąg JSON. Częste zdarzenia: posted, post_edited, post_deleted, reaction_added, reaction_removed, typing, status_change, user_added, direct_added. Aplikacje wysyłają własne zdarzenia, nazwane custom_<app id>_<event>.

Możesz również wysyłać akcje, każda z rosnącym seq: user_typing z {"channel_id", "parent_id"} lub get_statuses. Połącz się ponownie, gdy połączenie się zerwie, i pobierz to, co przegapiłeś, za pomocą since (patrz Paginacja).

Antimatter dodaje te zdarzenia: community_attributes_updated, member_timeouts_updated, post_put_on_top, post_removed_from_top, server_categories_updated, channel_overrides_updated oraz category_overrides_updated.

Biblioteki klienckie

  • Przejdź: model.Client4 w server/public/model (import github.com/mattermost/mattermost/server/public/model). model.NewAPIv4Client(url), a następnie client.SetToken(token); model.NewWebSocketClient4(wsURL, token) śledzi zdarzenia. Kopia Antimattera dodaje metody dla własnych punktów końcowych, takich jak UpdateMessageRequest, PutPostOnTop i ExportChannel.
  • TypeScript: klasa Client4 pakietu @mattermost/client w webapp/platform/client, z typami w webapp/platform/types. Kopia w repozytorium Antimattera zawiera punkty końcowe Antimattera; pakiet opublikowany na npm przez Mattermosta ich nie zawiera.
package main

import (
	"context"
	"log"

	"github.com/mattermost/mattermost/server/public/model"
)

func main() {
	client := model.NewAPIv4Client("https://chat.example.com")
	client.SetToken("…")
	post, _, err := client.CreatePost(context.Background(), &model.Post{
		ChannelId: "…",
		Message:   "Hello from Go",
	})
	if err != nil {
		log.Fatal(err)
	}
	log.Println("posted", post.Id)
}

Nowe pola

  • Społeczności (Team, oraz PUT /teams/{team_id}/patch): all_channels_membership (każdy jest członkiem każdego kanału, do którego ma dostęp, podobnie jak w Discord), default_channel_id (miejsce, w którym lądują nowi użytkownicy; puste oznacza Town Square), hide_role_colors, require_team_badges, onboarding oraz autolinks (oba jako ciągi JSON).
  • Odpowiedzi inline: wiadomość z "props": {"reply_to": "<post id>"} cytuje wskazaną wiadomość z tego samego kanału. Dodaj "reply_to_mention": false, aby nie powiadamiać autora cytowanej wiadomości. Serwer wypełnia pole metadata.reply_to krótkim opisem cytowanej wiadomości.
  • Ujawnienia (spoilers): "props": {"spoiler": true} ukrywa tekst i pliki wiadomości, aż czytelnik zdecyduje się je wyświetlić.
  • Ignorowanie i blokowanie to preferencje: kategoria user_block, nazwana według identyfikatora drugiej osoby, z wartością ignore lub block. Czy wiadomość bezpośrednia czeka jako żądanie, zależy od pola notify_props.dm_request w profilu członka kanału (pending, accepted lub dismissed).
  • Załączniki do wiadomości mogą zawierać stages oraz chart: zobacz Karty.
