On viuen els paràmetres

Cada paràmetre del servidor té un nom format per una secció i una clau, com ara ServiceSettings.SiteURL o EmailSettings.SMTPServer. Junts formen una configuració, emmagatzemada en un dels dos llocs següents:

  • A la base de dades. El fitxer de composició del lloc estableix AM_CONFIG a l'URL de connexió de PostgreSQL, de manera que la configuració és una fila a la base de dades i el contenidor no guarda res al disc. Diversos servidors que comparteixen una mateixa base de dades també comparteixen la seva configuració.
  • A un fitxer. Sense AM_CONFIG, el servidor llegeix config/config.json al costat del seu directori bin/ (/antimatter/config/config.json a la imatge de Docker). L'arxiu de la versió i els fitxers de composició de producció d'antimatter-docker funcionen d'aquesta manera. Mantingueu aquest fitxer llegible només per l'usuari del servidor: conté contrasenyes i claus.

AM_CONFIG (o el paràmetre --config de la comanda antimatter) accepta una ruta de fitxer o una URL postgres://. Els paràmetres que ometeu prenen el seu valor per defecte.

Per moure una configuració existent d'un fitxer a la base de dades, executeu això al servidor i, a continuació, inicieu el servidor amb AM_CONFIG establert a la mateixa URL:

amctl --local config migrate /opt/antimatter/config/config.json \
    "postgres://antimatter:PASSWORD@localhost:5432/antimatter?sslmode=disable&connect_timeout=10"

Variables d'entorn

Qualsevol paràmetre també es pot donar com a variable d'entorn. Les variables tenen prioritat sobre la configuració emmagatzemada, cosa que les fa adequades per al que pertany a la implementació: la base de dades, l'URL del lloc, l'emmagatzematge de fitxers, els ports.

Regla de nomenament

Escriviu AM_, després la secció, després la clau, en majúscules i separades per guions baixos. Les paraules dins d'un nom de secció o clau no es separen:

ParàmetreVariable
ServiceSettings.SiteURLAM_SERVICESETTINGS_SITEURL
SqlSettings.DataSourceAM_SQLSETTINGS_DATASOURCE
EmailSettings.SMTPServerAM_EMAILSETTINGS_SMTPSERVER
PrivacySettings.EnableUserBlockingAM_PRIVACYSETTINGS_ENABLEUSERBLOCKING
  • Els paràmetres de veritat i fals prenen true o false; els números són números senzills.
  • Els paràmetres de llista prenen els seus valors separats per espais, per exemple AM_SERVICESETTINGS_TRUSTEDPROXYIPHEADER="X-Forwarded-For X-Real-IP".
  • Els paràmetres que són objectes prenen JSON. L'única variable d'aquest tipus per a les aplicacions és AM_PLUGINSETTINGS_PLUGINS, i substitueix els paràmetres de totes les aplicacions alhora: establiu els paràmetres de l'aplicació a la Consola del sistema o amb amctl en lloc d'això (vegeu més avall).
  • Les instal·lacions antigues de Mattermost utilitzen el prefix MM_, per exemple MM_SQLSETTINGS_DATASOURCE. Encara funciona com a alias de llegat. Quan es defineixen ambdós, la variable AM_ té prioritat.

Una configuració definida per una variable queda bloquejada al Consola del sistema, amb la nota «Aquesta configuració s'ha establert mitjançant una variable d'entorn. No es pot canviar des de la Consola del sistema». No s'escriu a la configuració emmagatzemada: si elimineu la variable, s'aplica de nou el valor emmagatzemat.

Amb Docker Compose

Afegiu les variables sota environment: del servei antimatter, o bé en un compose.override.yaml al costat de compose.yaml (Compose el llegeix automàticament i sobreviu a les actualitzacions del fitxer descarregat):

services:
  antimatter:
    environment:
      AM_EMAILSETTINGS_SMTPSERVER: smtp.example.com
      AM_EMAILSETTINGS_SMTPPORT: "587"
      AM_LOGSETTINGS_CONSOLELEVEL: INFO

Apliqueu els canvis amb docker compose up -d, que recrea el contenidor.

Variables lligues per les aplicacions

Algunes aplicacions llegeixen les seves pròpies variables, establertes al servei antimatter: l'aplicació de trucades llegeix AM_CALLS_* (vegeu Trucades i veu), i l'aplicació de GIFs llegeix AM_GIFS_SERVICE_URL, AM_GIFS_API_KEY i AM_GIFS_UPLOAD_KEY (vegeu Aplicacions integrades).

La Consola del sistema

La Consola del sistema és l'àrea d'administració de l'aplicació web, destinada als administradors del sistema. Per obrir-la, feu clic a la imatge del vostre perfil i trieu Consola del sistema, o bé aneu a https://chat.example.com/admin_console. La seva barra lateral té una caixa Troba configuracions que busca a totes les pàgines.

Les seves seccions són:

  • Informes: estadístiques i els registres del servidor.
  • Gestió d'usuaris: usuaris, grups, comunitats (llistades com a Equips), canals, permisos i administració delegada.
  • Attributs del sistema: atributs de perfil personalitzats i accés basat en atributs.
  • Entorn: servidor web, base de dades, emmagatzematge de fitxers, proxy d'imatges, SMTP, notificacions push, limitació de freqüència, registres, durada de les sessions i monitoratge de rendiment.
  • Configuració del lloc: marca, usuaris i equips, notificacions, publicacions, compartició de fitxers i altres comportaments de tot el servidor.
  • Autenticació: registre, inici de sessió amb correu i contrasenya, MFA, AD/LDAP, SAML 2.0, OAuth 2.0, OpenID Connect i accés d'invitats.
  • Connectors: gestió de les aplicacions i la configuració de cada aplicació instal·lada.
  • Integracions: webhooks, comandes amb barra, comptes de bot, GIFs, text a veu, CORS.
  • Conformitat: retenció de dades, exportació i supervisió de la conformitat, registres d'auditoria i condicions d'ús personalitzades.
  • Experimental: funcions que poden canviar.

En aquesta guia, una configuració s'escriu com el seu camí a la Consola del sistema, després la seva etiqueta i, finalment, la seva clau de configuració, per exemple Consola del sistema › Configuració del lloc › Usuaris i equips › Activa ignorar, bloquejar i sol·licituds de missatge (PrivacySettings.EnableUserBlocking).

La majoria de canvis s'apliquen en clicar Desa. Pocs (l'adreça d'escolta, algunes configuracions de base de dades i memòria cau) requereixen un reinici, i la pàgina ho indica.

L'eina de línia d'ordres amctl

amctl gestiona un servidor des de la línia d'ordres: usuaris, comunitats, canals, aplicacions, configuració, tasques i més. Es comunica amb el servidor de dues maneres.

Mode local, al servidor

El mode local permet a amctl comunicar-se amb el servidor a través d'un socket Unix, sense iniciar sessió. Està activat a la imatge Docker. En un servidor instal·lat des d'un arxiu, activa'l amb ServiceSettings.EnableLocalMode (AM_SERVICESETTINGS_ENABLELOCALMODE=true). El socket és /var/tmp/antimatter_local.socket per defecte (ServiceSettings.LocalModeSocketLocation).

# with Docker Compose
docker compose exec antimatter amctl --local system status
# with a release archive
sudo -u antimatter /opt/antimatter/bin/amctl --local system status
Qualsevol persona que pugui utilitzar el socket, o executar docker compose exec a l'amfitrió, té drets complets d'administrador del sistema.

Remot, amb un compte

Des de qualsevol màquina, inicia sessió amb un compte d'administrador del sistema (o un token d'accés personal) i, a continuació, executa ordres contra aquest servidor:

amctl auth login https://chat.example.com --name prod --username admin
amctl system status

Ordres de configuració

OrdreQuè fa
amctl config get ServiceSettings.SiteURLImprimeix una configuració.
amctl config set TeamSettings.EnableOpenServer falseCanvia una configuració. Les configuracions de llista accepten diversos valors.
amctl config patch settings.jsonFusiona un fitxer JSON de configuracions a la configuració.
amctl config showImprimeix tota la configuració com a JSON.
amctl config editObre la configuració al teu editor ($EDITOR).
amctl config resetRestableix les configuracions als valors per defecte.
amctl config reloadRecarrega la configuració des del lloc on està emmagatzemada, després d'un canvi fet fora del servidor.

Les configuracions de les aplicacions es troben sota PluginSettings.Plugins.<app id>, amb claus en minúscules. Per exemple, per establir l'URL del servei i la clau de l'aplicació GIFs des de l'amfitrió Docker:

docker compose exec -T antimatter amctl --local config patch /dev/stdin <<'EOF'
{"PluginSettings": {"Plugins": {"com.antimatterchat.gifs": {
  "serviceurl": "http://gifs:8080/v2",
  "apikey": "the GIFS_API_KEY of your .env"
}}}}
EOF

Altres ordres útils: amctl user create, amctl user deactivate, amctl team create, amctl plugin list, amctl plugin enable, amctl system supportpacket i amctl logs. Executa amctl help <command> per veure les opcions de cadascuna.

Registres

El servidor escriu el seu registre en dos llocs, cadascun amb el seu propi nivell (DEBUG, INFO, WARN o ERROR), configurat a Consola del sistema › Entorn › Registre:

DestinacióConfiguracióValors per defecte
La consola (sortida estàndard)Emissió dels registres a la consola (LogSettings.EnableConsole), Nivell de registre de consola (LogSettings.ConsoleLevel), Emissió dels registres de la consola en format JSON (LogSettings.ConsoleJson)activat, DEBUG, JSON
Un fitxer, antimatter.logSortida dels registres a fitxer (LogSettings.EnableFile), Nivell de registre de fitxer (LogSettings.FileLevel), Directori de registres de fitxer (LogSettings.FileLocation)activat, INFO, el directori logs/ al costat de bin/

Els fitxers de registre es roden a 100 MB i els antics es comprimeixen.

El fitxer compose del lloc desactiva el registre en fitxer (AM_LOGSETTINGS_ENABLEFILE=false), de manera que els registres només es troben a la sortida del contenidor:

docker compose logs -f antimatter
docker compose logs --since 1h antimatter | grep -i error

El nivell de la consola és DEBUG per defecte, que és molt detallat. En un servidor amb molta activitat, establiu AM_LOGSETTINGS_CONSOLELEVEL=INFO. Amb un arxiu de publicació sota systemd, la sortida de la consola va al diari (journalctl -u antimatter) i el fitxer a /opt/antimatter/logs/antimatter.log.

Quan el registre en fitxer està activat, els administradors del sistema també poden llegir les últimes línies del registre a Consola del sistema › Informes › Registres del servidor, o bé amb amctl logs.
