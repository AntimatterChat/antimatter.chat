Descarrega l'aplicació

Les versions de l'aplicació d'escriptori estan a GitHub, a github.com/AntimatterChat/desktop-app/releases. Com el servidor, l'aplicació és en beta: una versió amb un sufix després d'un guionet està marcada com a Pre-release. Cada versió té un arxiu SHA256SUMS amb la suma de verificació de cada fitxer. Comprova una descàrrega amb sha256sum --check --ignore-missing SHA256SUMS a Linux, o compara la sortida de Get-FileHash <file> -Algorithm SHA256 a PowerShell amb la seva línia a SHA256SUMS.

  • Windows (x64 i arm64): l'instal·lador .exe, el paquet .msi o un arxiu .zip. Per exemple, antimatter-desktop-<version>-win-x64.exe i antimatter-desktop-<version>-win-x64.msi.
  • macOS: una imatge de disc .dmg o un .zip, per a Apple silicon (arm64), Macs Intel (x64) o tots dos (universal).
  • Linux (x64 i arm64): un paquet .deb o .rpm, un AppImage, un paquet Flatpak o un arxiu .tar.gz.

L'aplicació comprova si hi ha noves versions a GitHub, cada hora mentre s'executa, i només veu les versions estables, no les versions preliminars. Quan en troba una, n'informa l'usuari i li ofereix un enllaç per descarregar-la. Una còpia instal·lada amb el MSI no fa aquestes comprovacions per defecte, perquè les persones que l'utilitzen normalment no poden instal·lar programari. Pots activar les comprovacions per a aquesta còpia amb la configuració EnableAutoUpdater: la descàrrega que s'ofereix serà llavors el nou .msi, que requereix drets d'administrador.

Utilitza el MSI per a un desplegament gestionat amb SCCM (Configuration Manager), Intune o la instal·lació de programari per política de grup. La instal·lació del MSI elimina la còpia .exe del compte que executa la instal·lació, si n'hi ha.

Les configuracions que pots gestionar

Les mateixes configuracions existeixen en tots els sistemes. A Windows són valors del registre sota SOFTWARE\Policies\Antimatter, a HKEY_LOCAL_MACHINE (per a l'ordinador) o a HKEY_CURRENT_USER (per a un sol usuari). A macOS i Linux són claus de les preferències gestionades o del fitxer de política.

ParàmetreA WindowsA macOS i LinuxQuè fa
DefaultServerListUna subclau amb un valor de cadena per servidor: el nom del valor és el nom de la seva pestanya, i les dades són la seva URLUn array de diccionaris (objectes a Linux) amb name i urlAfegeix servidors a l'aplicació. Les persones no poden editar-los ni eliminar-los.

EnableAutoUpdaterUn DWORD, 0 o 1Un booleà0 o false: l'aplicació mai no comprova si hi ha noves versions, i amaga Comprova actualitzacions. 1 o true: fa les comprovacions, fins i tot quan està instal·lada amb el MSI. No establert: la còpia .exe fa les comprovacions, la còpia MSI no.
TrustedEmbeddedMediaOriginsUna subclau amb valors de cadena, cadascun un objecte JSON amb serverOrigin i embeddedOriginUn array de diccionaris amb serverOrigin i embeddedOriginPermet que el contingut incrustat a les pàgines d'un servidor, com ara una pàgina de reunió de vídeo, utilitzi els permisos de càmera i micròfon atorgats a aquest servidor.
  • El nom d'usuari només s'omple a la pàgina d'inici de sessió dels servidors establerts per la política, mai en un servidor que algú hagi afegit i mai per sobre del que algú hagi escrit. Les persones encara poden canviar-lo. Les variables d'entorn entre signes de percentatge es substitueixen, de manera que un sol valor serveix per a tothom: %USERNAME% a Windows o %USER% a macOS i Linux dona el nom del compte, i %USERNAME%@example.com una adreça de correu electrònic que segueix aquest patró. Si una variable no està establerta, l'aplicació no omple res.
  • Si desactiveu la gestió del servidor, establiu com a mínim un servidor a DefaultServerList.
  • A Windows, una política d'ordinador (HKEY_LOCAL_MACHINE) té prioritat sobre una política d'usuari (HKEY_CURRENT_USER). Les llistes de servidors de totes dues es combinen.
  • L'aplicació llegeix la configuració quan s'obre: després d'un canvi, les persones han de tancar-la i tornar-la a obrir.

Windows: instal·lació silenciosa amb el MSI

El MSI accepta propietats públiques que escriuen la configuració com a polítiques d'ordinador, a HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Antimatter. Utilitzeu-les en una aplicació d'SCCM, una aplicació d'Intune o un script. A PowerShell:

msiexec /i antimatter-desktop-<version>-win-x64.msi /qn SERVERURL=https://chat.example.com SERVERNAME=Chat DEFAULTUSERNAME='%USERNAME%' AUTOUPDATE=0 SERVERMANAGEMENT=0
PropietatEscriuSi no es proporciona
SERVERURLUn servidor a DefaultServerList, amb aquesta URLCap servidor
SERVERNAMEEl nom de la pestanya d'aquest servidorAntimatter
DEFAULTUSERNAMEDefaultUsernameRes
AUTOUPDATEEnableAutoUpdater, 0 o 1Res: la còpia del MSI no busca actualitzacions
SERVERMANAGEMENTEnableServerManagement, 0 o 1Res: les persones poden afegir servidors
  • Una propietat que no es proporciona no escriu res, de manera que no sobreescriu un valor establert per la Política de grup. AUTOUPDATE i SERVERMANAGEMENT només accepten 0 o 1. El MSI estableix un sol servidor: utilitzeu la Política de grup per a més.
  • DEFAULTUSERNAME ha d'arribar a l'instal·lador com el text %USERNAME%, perquè l'aplicació el substitueixi per a cada persona. En cas contrari, la shell que executa la instal·lació el substitueix pel nom del seu propi compte. A PowerShell, mantingueu les cometes simples. En un fitxer .bat, escriviu %%USERNAME%%. Després d'una instal·lació de prova, comproveu al registre que DefaultUsername conté %USERNAME%.
  • Transmeteu les propietats de nou en cada actualització. L'instal·lació d'una nova versió del MSI elimina l'antiga, amb els valors que va escriure, i després escriu els valors de la nova línia d'ordres. SCCM i Intune mantenen la línia d'ordres d'una aplicació: reutilitzeu-la per a cada nova versió. O establiu les polítiques amb la Política de grup o Intune, que les actualitzacions no toquen.
  • L'MSI i la Directiva de grup escriuen els mateixos valors del registre. Per a cada configuració, utilitzeu l'un o l'altre: si desinstal·leu l'MSI, s'eliminen els valors que va escriure, fins i tot si la Directiva de grup també els havia establert.
  • L'MSI també registra la seva carpeta d'instal·lació a HKEY_LOCAL_MACHINE\SOFTWARE\Antimatter\Desktop (InstallDir). Així és com l'aplicació sap que s'ha instal·lat amb l'MSI.

Per desinstal·lar: msiexec /x antimatter-desktop-<version>-win-x64.msi /qn. A Intune, el tipus «Windows app (Win32)» accepta les mateixes línies d'ordres. Per al tipus «Line-of-business app», afegiu les propietats als arguments de la línia d'ordres.

Windows: Directiva de grup i Intune

Les plantilles administratives, antimatter.admx i en-US\antimatter.adml, es troben a la carpeta gpo de l'aplicació instal·lada (C:\Program Files\Antimatter\gpo per a l'MSI) i a la carpeta resources/windows/gpo del repositori de l'aplicació. Mostren aquestes polítiques, sota Administrative Templates › Antimatter:

PolíticaValor del registreConfiguració
Servers (DefaultServerList)Subclau DefaultServerListordinador i usuari
Username to prefill (DefaultUsername)DefaultUsernameordinador i usuari
Let people add and remove servers (EnableServerManagement)EnableServerManagementordinador i usuari
Notify about new versions (EnableAutoUpdater)EnableAutoUpdaternomés ordinador
Trusted embedded media origins (TrustedEmbeddedMediaOrigins)Subclau TrustedEmbeddedMediaOriginsordinador i usuari

Directiva de grup en un domini

  1. Copieu antimatter.admx a l'emmagatzematge central, \\<domain>\SYSVOL\<domain>\Policies\PolicyDefinitions, i antimatter.adml a la seva carpeta en-US.
  2. A l'Editor de gestió de Directives de grup, obriu Computer Configuration (o User Configuration) › Policies › Administrative Templates › Antimatter.
  3. Editeu una política, trieu Activat i ompliu-la. Per a Servers, feu clic a Mostra i afegiu una línia per servidor: el nom del valor és el nom de la pestanya i el valor és l'URL del servidor, com ara https://chat.example.com.

Si activeu Let people add and remove servers o Notify about new versions, s'escriu 1; si les desactiveu, s'escriu 0.

Intune

A Dispositius › Configuració, utilitzeu Importa ADMX per importar antimatter.admx amb en-US\antimatter.adml. A continuació, creeu un perfil des de Plantilles › Plantilles administratives importades i establiu-hi les polítiques d'Antimatter.

Un sol ordinador, o un script

Copieu les plantilles a C:\Windows\PolicyDefinitions per utilitzar-les a gpedit.msc (Windows Pro i Enterprise). O bé escriviu els valors del registre directament, amb un fitxer .reg importat com a administrador (reg import antimatter-policies.reg), com ara aquest. El fitxer example-policies.reg de la mateixa carpeta conté aquests valors, amb comentaris.

REGEDIT4

[HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Antimatter]
"EnableServerManagement"=dword:00000000
"EnableAutoUpdater"=dword:00000000
"DefaultUsername"="%USERNAME%"

[HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Antimatter\DefaultServerList]
"Chat"="https://chat.example.com"

macOS: un perfil de configuració

A macOS, l'aplicació llegeix la seva configuració des de les preferències gestionades del seu identificador de paquet, chat.antimatter.desktop, amb les claus de la taula de configuració. Desplegueu-les amb el vostre MDM (Jamf, Intune, Kandji, Mosyle i altres) com a perfil de configuració.

  • La carpeta resources/mac/mdm del repositori de l'aplicació conté un perfil d'exemple, antimatter.mobileconfig. Editeu-ne els valors, assigneu-li els vostres propis valors de PayloadIdentifier i PayloadUUID (uuidgen crea nous UUID) i pugeu-lo com a perfil personalitzat.
  • La majoria dels MDM també accepten les claus per separat, com a càrrega de "configuració personalitzada" o "domini de preferències" per a chat.antimatter.desktop. La mateixa carpeta les conté a example-managed-preferences.plist.

La configuració dins de la càrrega del perfil:

<key>PayloadType</key>
<string>chat.antimatter.desktop</string>
<key>DefaultServerList</key>
<array>
    <dict>
        <key>name</key>
        <string>Chat</string>
        <key>url</key>
        <string>https://chat.example.com</string>
    </dict>
</array>
<key>DefaultUsername</key>
<string>%USER%</string>
<key>EnableServerManagement</key>
<false/>
<key>EnableAutoUpdater</key>
<false/>

Els valors booleans també es poden indicar com a enters 0 i 1.

Linux: el fitxer de polítiques

A Linux, l'aplicació llegeix /etc/antimatter-desktop/policies.json, un objecte JSON amb les claus de la taula de configuració:

{
    "DefaultServerList": [
        {"name": "Chat", "url": "https://chat.example.com"}
    ],
    "DefaultUsername": "%USER%",
    "EnableServerManagement": false,
    "EnableAutoUpdater": false,
    "TrustedEmbeddedMediaOrigins": []
}

Desplegueu-lo amb la vostra eina de gestió de configuració (Ansible, Puppet, Salt i altres), propietat de root, llegible per tothom i escriptible només per root:

sudo install -d /etc/antimatter-desktop
sudo install -m 644 policies.json /etc/antimatter-desktop/policies.json

Un fitxer que no sigui un JSON vàlid s'ignora, amb un avís al registre de l'aplicació. La versió Flatpak no veu el /etc de l'host: doneu-li accés de lectura i llegeix el fitxer des de /run/host/etc/antimatter-desktop/policies.json:

sudo flatpak override --system --filesystem=host-etc:ro chat.antimatter.desktop

Polítiques establertes per a l'aplicació d'escriptori de Mattermost

A Windows, l'aplicació també llegeix les polítiques establertes per a l'aplicació d'escriptori de Mattermost, sota SOFTWARE\Policies\Mattermost, com a recurs de reserva. Les llegeix per ubicació: els valors directament sota la clau de la política, la subclau DefaultServerList i la subclau TrustedEmbeddedMediaOrigins. Per a cadascuna d'aquestes tres ubicacions, només llegeix la clau de Mattermost quan la clau d'Antimatter no tingui valors allà, en qualsevol dels dos registres. Així, un cop s'ha establert un valor directament sota la clau d'Antimatter, per exemple mitjançant la propietat AUTOUPDATE de l'MSI, no es llegeix cap dels valors directament sota la clau de Mattermost. Mou totes les teves polítiques a la clau d'Antimatter de cop.

A macOS, no es llegeixen les preferències gestionades de l'aplicació d'escriptori de Mattermost (com.mattermost.desktop): establiu-les per a chat.antimatter.desktop.

Compilacions sense signar

Les compilacions de l'aplicació d'escriptori encara no estan signades amb un certificat d'editor.

  • Windows. Quan una persona obre un .exe o .msi descarregat, Microsoft Defender SmartScreen indica que Windows ha protegit l'ordinador i nomena un editor desconegut. La persona tria Més informació i després Executa de totes maneres. SmartScreen comprova els fitxers que les persones obren després d'una descàrrega, de manera que no veuran aquest avís quan desplegueu l'aplicació mitjançant SCCM, Intune o Directiva de grup. Si els vostres ordinadors només executen programari d'editors aprovats (regles d'AppLocker o App Control for Business), permeteu l'aplicació mitjançant la seva ruta d'instal·lació o el seu hash de fitxer.
  • macOS. L'aplicació està signada ad hoc, però no està notariada per Apple. La primera vegada que una persona obre una còpia descarregada, macOS indica que no pot verificar que l'aplicació estigui lliure de programari maliciós i no l'obre. A macOS 15 i versions posteriors, la persona obre Configuració del sistema › Privadesa i seguretat i tria Obre de totes maneres. A versions anteriors, fa clic amb el botó de control a l'aplicació i tria Obre. Gatekeeper només comprova els fitxers marcats com a descarregats (amb l'atribut de quarantena): quan instal·leu l'aplicació amb les vostres pròpies eines, elimineu la marca al vostre script d'instal·lació, amb xattr -dr com.apple.quarantine /Applications/Antimatter.app.
