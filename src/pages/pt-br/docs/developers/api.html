Fundamentos

  • URL base: https://chat.example.com/api/v4. Todos os endpoints abaixo são relativos a ela.
  • Formato: JSON na entrada e na saída, exceto para envio de arquivos (multipart). Envie Content-Type: application/json.
  • IDs: cada objeto tem um id de 26 caracteres. Os tempos são em milissegundos desde a época Unix (create_at, update_at, delete_at; 0 significa "não excluído").
  • Comunidades são equipes: a API as chama de teams, com um team_id.
  • Você mesmo: sempre que um caminho aceita um user_id, me significa o usuário conectado, como em GET /users/me.

A lista completa de endpoints está no código do servidor: as rotas são declaradas em server/channels/api4/*.go e os tipos em server/public/model. A descrição OpenAPI na pasta api/v4/source do repositório cobre os endpoints herdados do Mattermost, não as adições do Antimatter.

Autenticação

Cada solicitação, exceto o login e alguns endpoints públicos, requer um token no cabeçalho Authorization:

curl -H "Authorization: Bearer $TOKEN" https://chat.example.com/api/v4/users/me

Três tipos de token são aceitos lá: tokens de acesso pessoal, tokens de sessão e tokens de acesso OAuth. Authorization: Token … também é aceito. Tokens na string de consulta (?access_token=) são aceitos apenas para tokens de acesso OAuth.

Tokens de acesso pessoal (recomendados para scripts)

Um token de acesso pessoal age em seu nome, não expira, a menos que você defina uma data de expiração, e pode ser revogado a qualquer momento. Os tokens de acesso pessoal estão desativados por padrão:

  1. Um administrador do sistema ativa Ativar Tokens de Acesso Individual em Console do Sistema › Integrações › Gerenciamento de Integração (ServiceSettings.EnableUserAccessTokens, AM_SERVICESETTINGS_ENABLEUSERACCESSTOKENS).
  2. Para cada pessoa que pode criar tokens, um administrador do sistema abre Console do Sistema › Gestão de Usuários › Usuários, escolhe Gerenciar funções no menu da pessoa e marca Allow this account to generate personal access tokens. Os administradores do sistema sempre podem criá-los.
  3. A pessoa abre seu avatar no canto superior direito, depois Perfil & configurações › Segurança. Em Tokens de Acesso Individual, descreve para que o token será usado e escolhe Criar Token. O token é exibido apenas uma vez: copie-o.

Pela API: POST /users/{user_id}/tokens com {"description": "backup script", "expires_at": 0} (expires_at em milissegundos; 0 para nenhum). O campo token da resposta é o segredo; seu id é o que você usa para revogá-lo (POST /users/tokens/revoke com {"token_id": "…"}). Da linha de comando: amctl token generate <user> <description>.

Um administrador do sistema pode limitar a duração dos tokens com Tempo de vida máximo do token de acesso pessoal (dias) na mesma página do Console do Sistema.

Tokens de sessão

Fazer login com uma senha retorna um token de sessão no cabeçalho de resposta Token, o mesmo tipo de sessão usado pelos aplicativos:

curl -i -X POST https://chat.example.com/api/v4/users/login \
  -H 'Content-Type: application/json' \
  -d '{"login_id": "maya", "password": "…"}'

Adicione "token": "123456" para uma conta com autenticação de múltiplos fatores. As sessões expiram conforme as configurações de sessão do servidor, e o endpoint de login tem limite de taxa (5 requisições por segundo). POST /users/logout encerra a sessão.

Os navegadores autenticam com um cookie. Uma requisição autenticada pelo cookie também deve enviar o cabeçalho X-CSRF-Token para qualquer coisa que não seja GET; um token no cabeçalho Authorization não precisa de cabeçalho CSRF.

Aplicativos OAuth 2.0

Para permitir que as pessoas façam login no seu aplicativo com sua conta do Antimatter, registre um aplicativo OAuth 2.0. O Antimatter será então o provedor OAuth:

  1. Ativar Provedor de Serviço OAuth 2.0 deve estar ativado (Console do Sistema › Integrações › Gerenciamento de Integração, ServiceSettings.EnableOAuthServiceProvider, ativado por padrão).
  2. Alguém com o direito de gerenciar aplicativos OAuth (administradores do sistema por padrão) abre seu avatar, depois Integrações › Aplicativos OAuth 2.0, e adiciona o aplicativo com suas URLs de callback. Eles recebem um ID de cliente e um segredo de cliente.
  3. Seu aplicativo envia as pessoas para https://chat.example.com/oauth/authorize com response_type=code, client_id, redirect_uri e state. O PKCE com code_challenge_method=S256 é suportado.
  4. Ele troca o código em POST https://chat.example.com/oauth/access_token (grant_type=authorization_code, depois refresh_token para renovar) e chama a API com Authorization: Bearer <access token>.

As pessoas veem os aplicativos que autorizaram em Perfil e configurações › Segurança › Aplicativos autorizados.

Publicar uma mensagem

curl -X POST https://chat.example.com/api/v4/posts \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"channel_id": "'$CHANNEL_ID'", "message": "Backup finished: **42 GB** in 3 min"}'

As mensagens são em Markdown. Adicione "root_id" (a primeira mensagem de um tópico) para responder em um tópico, "file_ids" para arquivos e "props" para anexos e outros extras (veja Anexos).

Encontrar o ID de um canal

curl -H "Authorization: Bearer $TOKEN" \
  https://chat.example.com/api/v4/teams/name/lumen-labs/channels/name/ops-alerts

Os nomes são aqueles no link do canal: /lumen-labs/channels/ops-alerts.

Paginação

Os endpoints de lista aceitam page (a partir de 0) e per_page (60 por padrão, no máximo 200). Continue pedindo a próxima página até que uma página volte mais curta que per_page.

As mensagens de um canal (GET /channels/{channel_id}/posts) também aceitam since (um horário: tudo que mudou desde então) ou before e after (um ID de publicação). Elas retornam como uma lista de publicações: {"order": [IDs, newest first], "posts": {ID: post}, "next_post_id", "prev_post_id"}.

Erros

Os erros usam os códigos de status HTTP habituais (400 entrada inválida, 401 não autenticado, 403 não permitido, 404 não encontrado, 501 recurso desativado) e um corpo JSON:

{
  "id": "api.context.permissions.app_error",
  "message": "You do not have the appropriate permissions.",
  "detailed_error": "",
  "request_id": "jz8zm5nunpbt8f3gpqsz5dq6so",
  "status_code": 403
}

Use id no seu código: message é traduzido para o idioma do usuário. detailed_error fica vazio, a menos que o servidor esteja em modo de desenvolvedor (ServiceSettings.EnableDeveloper). Informe o request_id ao administrador do servidor: ele está nos logs.

Limites de taxa

O limite de velocidade está desativado por padrão. Quando um administrador do sistema o ativa (Console do Sistema › Ambiente › Limite de Velocidade), cada cliente recebe 10 requisições por segundo com picos de 100 por padrão, contado por endereço IP ou por usuário. As respostas incluem X-RateLimit-Limit, X-RateLimit-Remaining e X-RateLimit-Reset; acima do limite, o servidor responde 429 com um cabeçalho Retry-After em segundos. Alguns endpoints, como o de login, têm seu próprio limite independentemente da configuração.

Escreva scripts que aguardam e tentam novamente em caso de 429, e evite consultas repetidas: use o WebSocket em vez disso.

O fluxo de eventos do WebSocket

Conecte-se a wss://chat.example.com/api/v4/websocket. Autentique-se com o cabeçalho Authorization: Bearer na requisição de conexão, ou enviando isto como a primeira mensagem:

{"seq": 1, "action": "authentication_challenge", "data": {"token": "…"}}

O servidor envia um evento hello, seguido por um evento para tudo que você tem permissão para ver:

{
  "event": "posted",
  "data": {"channel_id": "…", "channel_type": "O", "post": "{\"id\":\"…\",\"message\":\"Hello\",…}"},
  "broadcast": {"channel_id": "…", "team_id": "", "user_id": "", "omit_users": null},
  "seq": 4
}

Observe que data.post é a mensagem como uma string JSON. Eventos comuns: posted, post_edited, post_deleted, reaction_added, reaction_removed, typing, status_change, user_added, direct_added. Os aplicativos enviam seus próprios eventos, nomeados custom_<app id>_<event>.

Você também pode enviar ações, cada uma com um seq crescente: user_typing com {"channel_id", "parent_id"}, ou get_statuses. Reconecte-se quando a conexão cair e recupere o que perdeu com since (veja Paginação).

O Antimatter adiciona os seguintes eventos: community_attributes_updated, member_timeouts_updated, post_put_on_top, post_removed_from_top, server_categories_updated, channel_overrides_updated e category_overrides_updated.

Bibliotecas de cliente

  • Ir: model.Client4 em server/public/model (importar github.com/mattermost/mattermost/server/public/model). model.NewAPIv4Client(url), depois client.SetToken(token); model.NewWebSocketClient4(wsURL, token) segue os eventos. A cópia do Antimatter adiciona métodos para seus próprios endpoints, como UpdateMessageRequest, PutPostOnTop e ExportChannel.
  • TypeScript: a classe Client4 do @mattermost/client, em webapp/platform/client, com seus tipos em webapp/platform/types. A cópia no repositório do Antimatter inclui os endpoints do Antimatter; o pacote publicado no npm pela Mattermost não.
package main

import (
	"context"
	"log"

	"github.com/mattermost/mattermost/server/public/model"
)

func main() {
	client := model.NewAPIv4Client("https://chat.example.com")
	client.SetToken("…")
	post, _, err := client.CreatePost(context.Background(), &model.Post{
		ChannelId: "…",
		Message:   "Hello from Go",
	})
	if err != nil {
		log.Fatal(err)
	}
	log.Println("posted", post.Id)
}

O que o Antimatter adiciona à API

Estes endpoints e campos não existem em um servidor Mattermost. Todos eles exigem uma sessão.

Novos campos

  • Comunidades (Team, e PUT /teams/{team_id}/patch): all_channels_membership (todos estão em todos os canais que podem ver), default_channel_id (onde os novos membros chegam; vazio significa Town Square), hide_role_colors, require_team_badges, onboarding e autolinks (ambas strings JSON).
  • Respostas inline: uma publicação com "props": {"reply_to": "<post id>"} cita aquela mensagem do mesmo canal. Adicione "reply_to_mention": false para não notificar seu autor. O servidor preenche metadata.reply_to com uma breve descrição da mensagem citada.
  • Spoilers: "props": {"spoiler": true} oculta o texto e os arquivos de uma publicação até que o leitor escolha vê-los.
  • Ignorar e bloquear são preferências: categoria user_block, nomeada com o ID da outra pessoa, com o valor ignore ou block. Se uma mensagem direta espera como uma solicitação está no notify_props.dm_request do seu membro de canal (pending, accepted ou dismissed).
  • Anexos de mensagem podem carregar stages e um chart: veja Cartões.
