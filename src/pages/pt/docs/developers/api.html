Fundamentos

  • URL base: https://chat.example.com/api/v4. Todos os pontos de acesso abaixo são relativos a este.
  • Formato: JSON na entrada e na saída, exceto para carregamentos de ficheiros (multipart). Envie Content-Type: application/json.
  • ID: cada objeto tem um id de 26 caracteres. Os tempos são em milissegundos desde a época Unix (create_at, update_at, delete_at; 0 significa "não eliminado").
  • As comunidades são equipas: a API chama-lhes teams, com um team_id.
  • si próprio: sempre que um caminho requer um user_id, me significa o utilizador autenticado, como em GET /users/me.

A lista completa de pontos de acesso está no código do servidor: as rotas são declaradas em server/channels/api4/*.go e os tipos em server/public/model. A descrição OpenAPI na pasta api/v4/source do repositório cobre os pontos de acesso herdados do Mattermost, não as adições do Antimatter.

Autenticação

Cada pedido, exceto o de iniciar sessão e alguns pontos de acesso públicos, necessita de um token no cabeçalho Authorization:

curl -H "Authorization: Bearer $TOKEN" https://chat.example.com/api/v4/users/me

São aceites três tipos de token: tokens de acesso pessoal, tokens de sessão e tokens de acesso OAuth. Authorization: Token … também é aceite. Tokens na cadeia de consulta (?access_token=) só são aceites para tokens de acesso OAuth.

Tokens de acesso pessoal (recomendados para scripts)

Um token de acesso pessoal atua em seu nome, não expira, a menos que lhe defina uma data de expiração, e pode ser revogado a qualquer momento. Os tokens de acesso pessoal estão desativados por omissão:

  1. Um administrador do sistema ativa Ativar fichas de acesso pessoal em Consola do sistema › Integrações › Gestão de integrações (ServiceSettings.EnableUserAccessTokens, AM_SERVICESETTINGS_ENABLEUSERACCESSTOKENS).
  2. Para cada pessoa que pode criar fichas, um administrador do sistema abre Consola do sistema › Gestão de utilizadores › Utilizadores, escolhe Gerir funções no menu da pessoa e marca Permitir que esta conta gere fichas de acesso pessoal. Os administradores do sistema podem sempre criá-las.
  3. A pessoa abre o seu avatar no canto superior direito, depois Perfil & definições › Segurança. Em Tokens de acesso pessoal, descreve para que serve o token e escolhe Criar token. O token é mostrado apenas uma vez: copie-o.

Com a API: POST /users/{user_id}/tokens com {"description": "backup script", "expires_at": 0} (expires_at em milissegundos; 0 para nenhum). O campo token da resposta é o segredo; o seu id é o que usa para o revogar (POST /users/tokens/revoke com {"token_id": "…"}). A partir da linha de comandos: amctl token generate <user> <description>.

Um administrador do sistema pode limitar a duração de validade das fichas com Duração máxima de validade do token de acesso pessoal (dias) na mesma página da Consola do sistema.

Tokens de sessão

Iniciar sessão com uma palavra-passe devolve um token de sessão no cabeçalho de resposta Token, o mesmo tipo de sessão que as aplicações usam:

curl -i -X POST https://chat.example.com/api/v4/users/login \
  -H 'Content-Type: application/json' \
  -d '{"login_id": "maya", "password": "…"}'

Adicione "token": "123456" para uma conta com autenticação multifator. As sessões expiram conforme as definições de sessão do servidor, e o ponto de entrada de login tem limite de taxa (5 pedidos por segundo). POST /users/logout termina a sessão.

Os navegadores autenticam com um cookie. Um pedido autenticado pelo cookie deve também enviar o cabeçalho X-CSRF-Token para qualquer coisa que não seja GET; um token no cabeçalho Authorization não precisa de cabeçalho CSRF.

Aplicações OAuth 2.0

Para permitir que as pessoas iniciem sessão na sua aplicação com a sua conta Antimatter, registe uma aplicação OAuth 2.0. O Antimatter passa então a ser o provedor OAuth:

  1. Ativar Provedor de Serviços OAuth 2.0 tem de estar ativado (Consola do sistema › Integrações › Gestão de integrações, ServiceSettings.EnableOAuthServiceProvider, ativado por omissão).
  2. Alguém com o direito de gerir aplicações OAuth (administradores do sistema por omissão) abre o seu avatar, depois Integrações › Aplicações OAuth 2.0, e adiciona a aplicação com as suas URLs de callback. Recebe um ID de cliente e um segredo de cliente.
  3. A sua aplicação envia as pessoas para https://chat.example.com/oauth/authorize com response_type=code, client_id, redirect_uri e state. O PKCE com code_challenge_method=S256 é suportado.
  4. Troca o código em POST https://chat.example.com/oauth/access_token (grant_type=authorization_code, depois refresh_token para renovar) e chama a API com Authorization: Bearer <access token>.

As pessoas veem as aplicações que autorizaram em Perfil e definições › Segurança › Aplicações autorizadas.

Publicar uma mensagem

curl -X POST https://chat.example.com/api/v4/posts \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"channel_id": "'$CHANNEL_ID'", "message": "Backup finished: **42 GB** in 3 min"}'

As mensagens são em Markdown. Adicione "root_id" (a primeira mensagem de um tópico) para responder num tópico, "file_ids" para ficheiros e "props" para anexos e outros extras (veja Anexos).

Encontrar o ID de um canal

curl -H "Authorization: Bearer $TOKEN" \
  https://chat.example.com/api/v4/teams/name/lumen-labs/channels/name/ops-alerts

Os nomes são os que aparecem no link do canal: /lumen-labs/channels/ops-alerts.

Paginação

Os endpoints de listas aceitam page (a partir de 0) e per_page (60 por omissão, no máximo 200). Continue a pedir a página seguinte até uma página vir mais curta do que per_page.

As mensagens de um canal (GET /channels/{channel_id}/posts) também aceitam since (um tempo: tudo o que foi alterado desde então) ou before e after (um ID de publicação). São devolvidas como uma lista de publicações: {"order": [IDs, newest first], "posts": {ID: post}, "next_post_id", "prev_post_id"}.

Erros

Os erros utilizam os códigos de estado HTTP habituais (400 entrada inválida, 401 não autenticado, 403 não autorizado, 404 não encontrado, 501 funcionalidade desativada) e um corpo JSON:

{
  "id": "api.context.permissions.app_error",
  "message": "You do not have the appropriate permissions.",
  "detailed_error": "",
  "request_id": "jz8zm5nunpbt8f3gpqsz5dq6so",
  "status_code": 403
}

Utilize id no seu código: message é traduzido para a língua do utilizador. detailed_error fica vazio, exceto se o servidor estiver em modo de desenvolvimento (ServiceSettings.EnableDeveloper). Indique request_id ao administrador do servidor: ele está nos registos.

Limites de taxa

A limitação de taxa está desativada por omissão. Quando um administrador do sistema a ativa (Consola do sistema › Ambiente › Limitação de taxa), cada cliente recebe 10 pedidos por segundo, com rajadas de 100 por omissão, contados por endereço IP ou por utilizador. As respostas incluem X-RateLimit-Limit, X-RateLimit-Remaining e X-RateLimit-Reset; quando o limite é excedido, o servidor responde com 429 e um cabeçalho Retry-After em segundos. Alguns pontos de acesso, como a autenticação, têm o seu próprio limite, independentemente da configuração.

Escreva scripts que esperem e repitam em caso de 429, e evite a consulta periódica: siga o WebSocket em vez disso.

O fluxo de eventos do WebSocket

Ligue-se a wss://chat.example.com/api/v4/websocket. Autentique-se com o cabeçalho Authorization: Bearer no pedido de ligação, ou enviando isto como a primeira mensagem:

{"seq": 1, "action": "authentication_challenge", "data": {"token": "…"}}

O servidor envia um evento hello, seguido de um evento para tudo o que lhe é permitido ver:

{
  "event": "posted",
  "data": {"channel_id": "…", "channel_type": "O", "post": "{\"id\":\"…\",\"message\":\"Hello\",…}"},
  "broadcast": {"channel_id": "…", "team_id": "", "user_id": "", "omit_users": null},
  "seq": 4
}

Note que data.post é a publicação como uma string JSON. Eventos comuns: posted, post_edited, post_deleted, reaction_added, reaction_removed, typing, status_change, user_added, direct_added. As aplicações enviam os seus próprios eventos, nomeados custom_<app id>_<event>.

Também pode enviar ações, cada uma com um seq crescente: user_typing com {"channel_id", "parent_id"}, ou get_statuses. Reconecte-se quando a ligação cair e obtenha o que perdeu com since (ver Paginação).

O Antimatter adiciona estes eventos: community_attributes_updated, member_timeouts_updated, post_put_on_top, post_removed_from_top, server_categories_updated, channel_overrides_updated e category_overrides_updated.

Bibliotecas de cliente

  • Ir: model.Client4 em server/public/model (importar github.com/mattermost/mattermost/server/public/model). model.NewAPIv4Client(url), depois client.SetToken(token); model.NewWebSocketClient4(wsURL, token) segue os eventos. A cópia do Antimatter adiciona métodos para os seus próprios pontos de entrada, como UpdateMessageRequest, PutPostOnTop e ExportChannel.
  • TypeScript: a classe Client4 de @mattermost/client, em webapp/platform/client, com os seus tipos em webapp/platform/types. A cópia no repositório do Antimatter inclui os endpoints do Antimatter; o pacote publicado no npm pela Mattermost não.
package main

import (
	"context"
	"log"

	"github.com/mattermost/mattermost/server/public/model"
)

func main() {
	client := model.NewAPIv4Client("https://chat.example.com")
	client.SetToken("…")
	post, _, err := client.CreatePost(context.Background(), &model.Post{
		ChannelId: "…",
		Message:   "Hello from Go",
	})
	if err != nil {
		log.Fatal(err)
	}
	log.Println("posted", post.Id)
}

O que o Antimatter adiciona à API

Estes endpoints e campos não existem num servidor Mattermost. Todos eles exigem uma sessão.

GET /teams/{team_id}/members/{user_id}/user_attributes

GET /teams/{team_id}/timeouts

Novos campos

  • Comunidades (Team, e PUT /teams/{team_id}/patch): all_channels_membership (todos estão em todos os canais que podem ver), default_channel_id (onde os novos membros aterram; vazio significa Town Square), hide_role_colors, require_team_badges, onboarding e autolinks (ambos strings JSON).
  • Respostas em linha: uma publicação com "props": {"reply_to": "<post id>"} cita essa mensagem do mesmo canal. Adicione "reply_to_mention": false para não notificar o autor. O servidor preenche metadata.reply_to com uma breve descrição da mensagem citada.
  • Alertas de conteúdo: "props": {"spoiler": true} oculta o texto e os ficheiros de uma publicação até o leitor escolher vê-los.
  • Ignorar e bloquear são preferências: categoria user_block, nomeada com o ID da outra pessoa, com o valor ignore ou block. Se uma mensagem direta fica pendente como pedido, isso está nos notify_props.dm_request do seu membro do canal (pending, accepted ou dismissed).
  • Anexos de mensagem podem ter stages e um chart: veja Cartões.
