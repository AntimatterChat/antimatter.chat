Kde spravovat webhooks

Otevřete svůj avatar v pravém horním rohu a poté Integrace. Stránky integrací aktuální komunity obsahují Příchozí webhooks a Odchozí webhooks. Každý webhook patří do jedné komunity.

Ve výchozím nastavení mohou webhooks vytvářet administrátoři komunity a systémoví administrátoři. Systémový administrátor může toto oprávnění udělit i jiným rolím v nastaveních oprávnění Systémové konzole. Systémový administrátor může také v Systémová konzole › Integrace › Správa integrací vypnout každý typ: Povolit příchozí webhooks i Povolit odchozí webhooks jsou ve výchozím nastavení zapnuté.

Vytvoření příchozího webhooku

  1. V Integrace vyberte Příchozí webhooks a poté Přidat příchozí webhook.
  2. Vyplňte Název a Popis: zobrazí se pouze na stránkách integrací.
  3. Vyberte Kanál, do kterého se zprávy odesílají ve výchozím nastavení. U soukromého kanálu musíte být jeho členem.
  4. Zaškrtněte Zamknout na tento kanál, pokud by odesílatelé neměli mít možnost publikovat jinde.
  5. Volitelně nastavte Uživatelské jméno a URL Profilového obrázku pro jeho zprávy (viz Jméno a ikona).
  6. Vyberte Uložit. Zkopírujte zobrazené URL: https://chat.example.com/hooks/<key>.
URL je jediným tajemstvím: kdokoli, kdo ji má, může publikovat v kanálu. Nechávejte ji mimo veřejná úložiště a pokud se ztratí, webhook smažte.

Přes API: POST /api/v4/hooks/incoming s {"channel_id", "display_name", "description", "username", "icon_url", "channel_locked"}; id v odpovědi je klíč. Z příkazového řádku: amctl webhook create-incoming --channel <channel id> --user <user> --display-name "CI".

Odeslání zprávy do příchozího webhooku

curl -X POST https://chat.example.com/hooks/xgh5ycrx1jf7mbs9w8z4c8e7ho \
  -H 'Content-Type: application/json' \
  -d '{"text": "Deploy of **api 2.4.0** finished :white_check_mark:"}'

Server odpoví 200 s tělem ok. Přijímá také application/x-www-form-urlencoded s JSONem v poli payload, stejně jako webhooks Slacku, takže nástroje vytvořené pro Slack obvykle fungují bez změn.

PoleVýznam
textZpráva v Markdownu. Povinné, pokud nejsou attachments. Text delší než povolená délka zprávy na serveru se rozdělí do více zpráv.
channelJiný kanál komunity webhooku, podle jména (ops-alerts nebo #ops-alerts), nebo @username pro přímou zprávu od vlastníka webhooku. Odmítnuto, pokud je webhook uzamčen na svůj kanál.
username, icon_url, icon_emojiJméno a obrázek, které se zobrazí, pokud to server umožňuje.
attachmentsPřílohy zprávy, vykreslené jako karty (viz níže).
propsDalší vlastnosti uložené na zprávu, které čtou aplikace.
typeVlastní typ zprávy, např. custom_poll, pro aplikaci, která ho vykreslí. Typy začínající na system_ jsou odmítnuty.
root_idID první zprávy vlákna, do kterého se má odpovědět.
priorityPriorita zprávy, např. {"priority": "urgent"}.
silenttrue odešle zprávu bez push oznámení.

Zprávy zobrazené pod přepsaným jménem nesou vedle něj štítek BOT, aby je lidé mohli rozlišit od skutečných účtů. Zprávy webhooků nikdy nevyvolávají odchozí webhooks.

Jméno a ikona

Webhook publikuje jako osoba, která ho vytvořila, pokud to server neumožňuje jinak. Dvě nastavení v Systémová konzole › Integrace › Správa integrací, obě výchozí vypnutá, to mění:

  • Povolit integracím přepis uživatelských jmen (ServiceSettings.EnablePostUsernameOverride): místo jména se zobrazí Uživatelské jméno webhooku nebo username z požadavku; pokud ani jedno není, je jméno webhook.
  • Povolit integracím přepisovat ikony profilových obrázků (ServiceSettings.EnablePostIconOverride): zobrazí se Profilový obrázek webhooku, nebo icon_url nebo icon_emoji z požadavku.

Hodnota z požadavku má přednost před hodnotou uloženou na webhooku.

Přílohy

Přílohy přidávají strukturovaný obsah pod text. Sledují formát příloh zpráv Slack:

{
  "text": "Build failed on `main`",
  "attachments": [{
    "fallback": "main #1902 failed",
    "color": "#d24b4e",
    "author_name": "GitHub Actions",
    "author_icon": "https://chat.example.com/static/ci.png",
    "title": "main #1902 failed",
    "title_link": "https://ci.example.com/runs/1902",
    "text": "Commit `0f4d8e2` by Jonas Weber",
    "fields": [
      {"title": "Branch", "value": "zephyr-3.7", "short": true},
      {"title": "Duration", "value": "3m 40s", "short": true}
    ],
    "footer": "Lumen CI",
    "ts": 1760000000
  }]
}
PoleVýznam
fallbackČistý text pro místa, kde se karta nezobrazí, např. v oznámeních.
colorBareva: šestnácková barva, nebo good, warning, danger.
pretextText nad kartou.
author_name, author_link, author_iconMalá záhlaví.
title, title_linkNázev karty, volitelně odkaz.
textTělo karty, v Markdownu.
fieldsSeznam {"title", "value", "short"}; pole short se zobrazí vedle sebe.
image_url, thumb_urlVelký obrázek dole, nebo malý po boku.
footer, footer_icon, tsPatička a čas (Unixové sekundy).
actionsTlačítka a nabídky: viz Interaktivní zprávy.

Karty: fáze a grafy

Antimatter přidává k přílohám dvě pole, která zobrazuje výchozí rozhraní:

  • stages: kroky potrubí ve formě štítků, nejvýše 20. Každý má tvar {"name", "status"}, kde stav je passed, failed, running, pending, skipped nebo canceled.
  • chart: malý čárový graf nedávných hodnot, {"values": [2 to 200 numbers], "threshold": number, "label": "…"}. Práh je vykreslen jako přerušovaná čára, představující limit upozornění.
{
  "attachments": [{
    "color": "danger",
    "title": "main #1902 failed",
    "stages": [
      {"name": "build", "status": "failed"},
      {"name": "unit", "status": "skipped"},
      {"name": "publish", "status": "skipped"}
    ]
  }, {
    "color": "warning",
    "title": "API latency above 400 ms",
    "chart": {"values": [210, 230, 260, 390, 450, 470], "threshold": 400, "label": "p95 latency, ms"}
  }]
}

Klasické rozhraní a ostatní klienty tato dvě pole ignorují, proto vložte podstatné informace i do text nebo fields.

Vytvoření odchozího webhooku

Odchozí webhook sleduje Veřejný kanály komunity. Když se první slovo zprávy shoduje s jedním z jeho spouštěcích slov, Antimatter pošle zprávu na vaši URL.

  1. V Integrace zvolte Odchozí webhooks a poté Přidat odchozí webhook.
  2. Vyplňte Název a Popis.
  3. Zvolte Typ obsahu požadavku: application/x-www-form-urlencoded nebo application/json.
  4. Vyberte Kanál, zadejte Spouštěcí slova (jedno na řádek) nebo obojí. S kanálem a bez spouštěcích slov se pošle každá zpráva z tohoto kanálu. S oběma musí zpráva odpovídat oběma podmínkám.
  5. V sekci Spustit, když zvolte První slovo přesně odpovídá spouštěcímu slovu nebo První slovo začíná na spouštěcí slovo.
  6. Zadejte Callback URL (jedna na řádek). Každá URL obdrží každou odpovídající zprávu.
  7. Volitelně nastavte Uživatelské jméno a Profilový obrázek používané pro odpovědi.
  8. Zvolte Uložit a zkopírujte zobrazený token. Vaše služba ho použije k ověření, že požadavky pocházejí z vašeho serveru.

Přes API: POST /api/v4/hooks/outgoing s {"team_id", "channel_id", "trigger_words", "trigger_when", "callback_urls", "content_type", "display_name"} (trigger_when: 0 pro přesné shodování, 1 pro "začíná na").

Pokud je vaše služba v soukromé síti, musí administrátor systému povolit její adresu v Povolit nespolehlivé interní připojení k (ServiceSettings.AllowedUntrustedInternalConnections). Server jinak soukromé adresy nezavolá.

Odchozí požadavek

Antimatter odešle POST s těmito poli, jako JSON nebo form-encoded podle typu obsahu:

{
  "token": "6kd1ofo5ojr5zgu5ipfipybgnc",
  "team_id": "…",
  "team_domain": "lumen-labs",
  "channel_id": "…",
  "channel_name": "ops-alerts",
  "timestamp": 1760010000000,
  "user_id": "…",
  "user_name": "priya",
  "post_id": "…",
  "text": "deploy api 2.4.0",
  "trigger_word": "deploy",
  "file_ids": ""
}

Před jakýmkoli dalším krokem porovnejte token s tokenem webhooku. Ve verzi kódované jako formulář je timestamp v sekundách, ne v milisekundách. Server na vaši odpověď počítá tak dlouho, jak to dovoluje Časový limit požadavků integrací (výchozí hodnota je 30 sekund, ServiceSettings.OutgoingIntegrationRequestsTimeout).

Odpověď na odchozí webhook

Chcete-li odpovědět, pošlete JSON. Chcete-li neposlat nic, pošlete prázdné tělo.

{
  "text": "Deploying **api 2.4.0** to staging…",
  "response_type": "comment",
  "username": "deploy-bot",
  "icon_url": "https://chat.example.com/static/deploy.png"
}
  • text a attachments: obsah odpovědi. Pokud chybí oba, nic se nepublikuje.
  • response_type: comment publikuje odpověď do vlákna spouštěcí zprávy; jinak se publikuje do kanálu.
  • username, icon_url: zobrazí se, pokud to server dovoluje; jinak se použijí vlastní hodnoty webhooku.
  • props, type, priority: stejně jako u příchozích webhooků.

Odpověď se publikuje jako autor webhooku, případně pod přepsaným jménem. Pro delší odpovědi odpovídejte okamžitě a publikujte je později pomocí příchozího webhooku nebo API.

Když webhook nefunguje

  • 501 z URL webhooku: příchozí webhooks jsou na serveru vypnuté.
  • 400 "Failed to decode the payload…": JSON je neplatný, nebo pole formuláře se jmenuje jinak než payload. "No text specified." znamená, že požadavek neobsahuje ani text, ani attachments.
  • 403: webhook je uzamčen pro jiný kanál, nebo jeho vlastník už nemůže kanál číst.
  • Odchozí webhook se nikdy nespustí: kanál je soukromý, spouštěcí slovo není první, nebo zpráva pochází z webhooku.
  • Logy: s povoleným Povolit ladění webhooků (LogSettings.EnableWebhookDebugging) a úrovní logování DEBUG server loguje obsah neúspěšných příchozích požadavků. Neúspěšné odchozí volání se loguje jako Outgoing Webhook POST failed.
