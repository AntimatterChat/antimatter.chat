พื้นฐาน

  • URL ฐาน: https://chat.example.com/api/v4 ปลายทางทั้งหมดด้านล่างนี้จะเป็นค่าสัมพัทธ์จาก URL นี้
  • ฟอร์แมต: รับและส่งออกข้อมูลเป็น JSON ยกเว้นการอัปโหลดไฟล์ (multipart) ส่ง Content-Type: application/json
  • ID: ทุกออบเจกต์จะมี id ยาว 26 ตัวอักษร เวลาจะเป็นมิลลิวินาทีนับตั้งแต่ Unix epoch (create_at, update_at, delete_at; 0 หมายถึง "ไม่ถูกลบ")
  • ชุมชนคือทีม: API เรียกสิ่งเหล่านี้ว่า teams พร้อม team_id
  • ตัวคุณเอง: ในทุกเส้นทางที่รับ user_id คำว่า me หมายถึงผู้ใช้ที่เข้าสู่ระบบ เช่น GET /users/me

รายการปลายทางทั้งหมดอยู่ในโค้ดของเซิร์ฟเวอร์: เส้นทางถูกประกาศใน server/channels/api4/*.go และประเภทข้อมูลอยู่ใน server/public/model คำอธิบาย OpenAPI ในโฟลเดอร์ api/v4/source ของรีพอสิทอรีครอบคลุมปลายทางที่สืบทอดมาจาก Mattermost ไม่ใช่ส่วนที่ Antimatter เพิ่มเข้ามา

การยืนยันตัวตน

ทุกคำขอ ยกเว้นการเข้าสู่ระบบและปลายทางสาธารณะบางรายการ ต้องมีโทเคนในหัว Authorization:

curl -H "Authorization: Bearer $TOKEN" https://chat.example.com/api/v4/users/me

ยอมรับโทเคนสามประเภท: โทเคนการเข้าถึงส่วนบุคคล, โทเคนเซสชัน และโทเคนการเข้าถึง OAuth Authorization: Token … ก็ถูกยอมรับเช่นกัน โทเคนในสตริงคำขอ (?access_token=) จะถูกยอมรับเฉพาะสำหรับโทเคนการเข้าถึง OAuth เท่านั้น

โทเคนการเข้าถึงส่วนบุคคล (แนะนำสำหรับสคริปต์)

โทเคนการเข้าถึงส่วนบุคคลจะทำงานในนามของคุณ ไม่หมดอายุเว้นแต่คุณกำหนดวันหมดอายุ และสามารถเพิกถอนได้ตลอดเวลา โทเคนการเข้าถึงส่วนบุคคลจะปิดอยู่เป็นค่าเริ่มต้น:

  1. ผู้ดูแลระบบเปิดใช้งาน เปิดใช้งานโทเคนการเข้าถึงส่วนตัว ใน คอนโซลระบบ › อินทิเกรชัน › การจัดการอินทิเกรชัน (ServiceSettings.EnableUserAccessTokens, AM_SERVICESETTINGS_ENABLEUSERACCESSTOKENS)
  2. สำหรับแต่ละบุคคลที่อาจสร้างโทเคน ผู้ดูแลระบบเปิด คอนโซลระบบ › การจัดการผ้้ใช้ › ผู้ใช้งาน เลือก จัดการบทบาท ในเมนูของบุคคลนั้น และทำเครื่องหมาย Allow this account to generate personal access tokens ผู้ดูแลระบบสามารถสร้างโทเคนได้เสมอ
  3. บุคคลนั้นเปิดอวตารที่มุมขวาบน จากนั้นไปที่ Profile & settings › ความปลอดภัย ภายใต้ โทเคนการเข้าถึงส่วนตัว ระบุวัตถุประสงค์ของโทเคนและเลือก สร้างโทเคน โทเคนจะแสดงเพียงครั้งเดียว: คัดลอกไว้

ผ่าน API: POST /users/{user_id}/tokens พร้อม {"description": "backup script", "expires_at": 0} (expires_at เป็นมิลลิวินาที; 0 สำหรับไม่หมดอายุ) ฟิลด์ token ในคำตอบคือความลับ; id ของมันคือสิ่งที่ใช้เพิกถอน (POST /users/tokens/revoke พร้อม {"token_id": "…"}) จากบรรทัดคำสั่ง: amctl token generate <user> <description>.

ผู้ดูแลระบบสามารถกำหนดอายุการใช้งานสูงสุดของโทเคนด้วย อายุการใช้งานสูงสุดของโทเคนการเข้าถึงส่วนบุคคล (วัน) ในหน้าคอนโซลระบบเดียวกัน

โทเคนเซสชัน

การเข้าสู่ระบบด้วยรหัสผ่านจะคืนค่าโทเคนเซสชันในหัวตอบกลับ Token ซึ่งเป็นเซสชันประเภทเดียวกับที่แอปพลิเคชันใช้:

curl -i -X POST https://chat.example.com/api/v4/users/login \
  -H 'Content-Type: application/json' \
  -d '{"login_id": "maya", "password": "…"}'

เพิ่ม "token": "123456" สำหรับบัญชีที่มีการยืนยันตัวตนหลายปัจจัย เซสชันจะหมดอายุตามที่การตั้งค่าเซสชันของเซิร์ฟเวอร์ระบุ และจุดสิ้นสุดการเข้าสู่ระบบมีการจำกัดอัตรา (5 คำขอต่อวินาที) POST /users/logout สิ้นสุดเซสชัน

เบราว์เซอร์ยืนยันตัวตนด้วยคุกกี้แทน คำขอที่ยืนยันตัวตนด้วยคุกกี้ต้องส่งหัว X-CSRF-Token ด้วยสำหรับทุกสิ่งที่ไม่ใช่ GET; โทเคนในหัว Authorization ไม่ต้องการหัว CSRF

แอปพลิเคชัน OAuth 2.0

เพื่อให้ผู้คนสามารถเข้าสู่ระบบแอปพลิเคชันของคุณด้วยบัญชี Antimatter ของพวกเขา จดทะเบียนแอปพลิเคชัน OAuth 2.0 Antimatter จะเป็นผู้ให้บริการ OAuth:

  1. ต้องเปิดใช้งาน เปิดใช้งานผู้ให้บริการ OAuth 2.0 (คอนโซลระบบ › อินทิเกรชัน › การจัดการอินทิเกรชัน, ServiceSettings.EnableOAuthServiceProvider, เปิดใช้งานโดยค่าเริ่มต้น)
  2. บุคคลที่มีสิทธิ์จัดการแอป OAuth (ผู้ดูแลระบบโดยค่าเริ่มต้น) เปิดอวตาร จากนั้นไปที่ อินทิเกรชัน › แอป OAuth 2.0 และเพิ่มแอปพร้อม URL สำหรับ callback พวกเขาจะได้รับ client ID และ client secret
  3. แอปพลิเคชันของคุณจะส่งผู้ใช้ไปยัง https://chat.example.com/oauth/authorize พร้อม response_type=code, client_id, redirect_uri และ state ระบบรองรับ PKCE โดยใช้ code_challenge_method=S256
  4. จากนั้นจะแลกเปลี่ยน code ที่ POST https://chat.example.com/oauth/access_token (ใช้ grant_type=authorization_code และใช้ refresh_token เพื่อต่ออายุ) และเรียกใช้ API ด้วย Authorization: Bearer <access token>

ผู้ใช้สามารถดูแอปที่พวกเขาอนุญาตใน Profile & settings › ความปลอดภัย › แอปที่คุณให้สิทธิ์

โพสต์ข้อความ

curl -X POST https://chat.example.com/api/v4/posts \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"channel_id": "'$CHANNEL_ID'", "message": "Backup finished: **42 GB** in 3 min"}'

ข้อความใช้รูปแบบ Markdown เพิ่ม "root_id" (โพสต์แรกของเธรด) เพื่อตอบกลับในเธรด, "file_ids" สำหรับไฟล์ และ "props" สำหรับไฟล์แนบและข้อมูลอื่น ๆ (ดู ไฟล์แนบ)

ค้นหา ID ของช่อง

curl -H "Authorization: Bearer $TOKEN" \
  https://chat.example.com/api/v4/teams/name/lumen-labs/channels/name/ops-alerts

ชื่อเหล่านี้คือชื่อที่อยู่ในลิงก์ของช่อง: /lumen-labs/channels/ops-alerts

การแบ่งหน้า

Endpoints แบบรายการจะรับ page (เริ่มจาก 0) และ per_page (ค่าเริ่มต้น 60 สูงสุด 200) ให้ขอหน้าถัดไปเรื่อย ๆ จนกว่าหน้าที่ได้รับกลับมามีจำนวนน้อยกว่า per_page

ข้อความในช่อง (GET /channels/{channel_id}/posts) รับพารามิเตอร์ since (เวลา: ทุกสิ่งทุกอย่างที่เปลี่ยนแปลงตั้งแต่นั้นมา) หรือ before และ after (ID ของโพสต์) ผลลัพธ์จะกลับมาเป็นรายการโพสต์: {"order": [IDs, newest first], "posts": {ID: post}, "next_post_id", "prev_post_id"}

ข้อผิดพลาด

ข้อผิดพลาดใช้รหัสสถานะ HTTP มาตรฐาน (400 ข้อมูลไม่ถุกต้อง, 401 ยังไม่ได่ลงน้าม, 403 ไม่ได้รับอนุญาต, 404 ไม่พบ, 501 ฟีเจอร์ถูกปิด) และเนื้อหา JSON:

{
  "id": "api.context.permissions.app_error",
  "message": "You do not have the appropriate permissions.",
  "detailed_error": "",
  "request_id": "jz8zm5nunpbt8f3gpqsz5dq6so",
  "status_code": 403
}

ใช้ id ในโค้ดของคุณ: message จะถุกแปลเป็นภาษาของผู้ใช้ detailed_error จะว่างเว้นจากเนื้ือหา เว้นแต่เซิร์ฟเวอร์จะทำงานในโหมดนักพัฒนา (ServiceSettings.EnableDeveloper) ระบุ request_id ให้แก่ผู้ดูแลระบบของเซิร์ฟเวอร์: มันอยู่ในบันทึกเหตุการณ์ (logs).

การจำกัดอัตรา

การจำกัดอัตรามีค่าเริ่มต้นเป็นปิด เมื่อผู้ดูแลระบบเปิดใช้งาน (คอนโซลระบบ › สภาพแวดล้อม › การจำกัดอัตร) แต่ละไคลเอนต์จะได้รับ 10 คำขอต่อวินาทีพร้อมการกระแทก (bursts) 100 ครั้งโดยค่าเริ่มต้น นับตามที่อยู่ IP หรือตามผู้ใช้ คำตอบจะประกอบด้วย X-RateLimit-Limit, X-RateLimit-Remaining และ X-RateLimit-Reset; เมื่อเกินขีดจำกัด เซิร์ฟเวอร์จะตอบกลับด้วย 429 พร้อม header Retry-After ในหน่วยวินาที บาง endpoint เช่น การเข้าสู่ระบบ มีขีดจำกัดของตัวเองไม่ว่าการตั้งค่าจะเป็นอย่างไร

เขียนสคริปต์ที่รอและลองใหม่เมื่อได้รับ 429 และหลีกเลี่ยงการโพล (polling): ใช้การติดตาม WebSocket แทน

สตรีมเหตุการณ์ WebSocket

เชื่อมต่อกับ wss://chat.example.com/api/v4/websocket ยืนยันตัวตนด้วยหัว Authorization: Bearer ในคำขอเชื่อมต่อ หรือด้วยการส่งสิ่งน้ีเป็นข้อความแรก:

{"seq": 1, "action": "authentication_challenge", "data": {"token": "…"}}

เซิร์ฟเวอร์จะส่งเหตุการณ์ hello แล้วตามด้วยเหตุการณ์สำหรับทุกสิ่่งท่ีคุณได้รับอนุญาตให้ดู:

{
  "event": "posted",
  "data": {"channel_id": "…", "channel_type": "O", "post": "{\"id\":\"…\",\"message\":\"Hello\",…}"},
  "broadcast": {"channel_id": "…", "team_id": "", "user_id": "", "omit_users": null},
  "seq": 4
}

สังเกตว่า data.post เป็นข้อความในรู่ปแบบสตริง JSON เหตุการณ์ที่พบบ่อย: posted, post_edited, post_deleted, reaction_added, reaction_removed, typing, status_change, user_added, direct_added แอพจะส่งเหตุการณ์ของตัวเอง โดยตั้งชื่ือว่า custom_<app id>_<event>.

คุณยังสามารถส่งการกระทำ (actions) ได้ด้วย แต่ละอย่างมี seq ที่เพิ่่มขึ้้น: user_typing พร้อม {"channel_id", "parent_id"} หรือ get_statuses เชื่อมต่อใหม่เมื่อการเชื่อมต่อหลุด และดึงสิ่่งท่ีคุณพลาดไปโดยใช้ since (ดู การแบ่งหน้า).

Antimatter เพิ่มเหตุการณ์เหล่านี้: community_attributes_updated, member_timeouts_updated, post_put_on_top, post_removed_from_top, server_categories_updated, channel_overrides_updated และ category_overrides_updated.

ไลบรารีไคลเอนต์

  • ไป: model.Client4 ใน server/public/model (import github.com/mattermost/mattermost/server/public/model). model.NewAPIv4Client(url), แล้ว client.SetToken(token); model.NewWebSocketClient4(wsURL, token) ติดตามเหตุการณ์ Antimatter เพิ่มเมธอดสำหรับ endpoint ของตัวเอง เช่น UpdateMessageRequest, PutPostOnTop และ ExportChannel.
  • TypeScript: คลาส Client4 ของ @mattermost/client ใน webapp/platform/client พร้อม type ใน webapp/platform/types คัดลอกในคลัง Antimatter รวม endpoint ของ Antimatter ไว้ด้วย แต่แพ็กเกจที่ Mattermost เผยแพร่บน npm ไม่มี
package main

import (
	"context"
	"log"

	"github.com/mattermost/mattermost/server/public/model"
)

func main() {
	client := model.NewAPIv4Client("https://chat.example.com")
	client.SetToken("…")
	post, _, err := client.CreatePost(context.Background(), &model.Post{
		ChannelId: "…",
		Message:   "Hello from Go",
	})
	if err != nil {
		log.Fatal(err)
	}
	log.Println("posted", post.Id)
}

ฟิลด์ใหม่

  • ชุมชน (Team, และ PUT /teams/{team_id}/patch): all_channels_membership (ทุกคนอยู่ในทุกช่องที่พวกเขาสามารถมองเห็นได้), default_channel_id (ที่สมาชิกใหม่จะมาถึง; ว่างหมายถึง Town Square), hide_role_colors, require_team_badges, onboarding และ autolinks (ทั้งสองเป็นสตริง JSON)
  • การตอบกลบในบรรทัดเดยวกน: โพสต์ท่ีมี "props": {"reply_to": "<post id>"} จะอ้างถึงข้อความในช่องเดยวกนนั้น เพิ่ม "reply_to_mention": false เพอไมแจ้งเตือนผ้ท่ีโพสต์ข้อความท่ีถูกอ้างถึง เซิร์ฟเวอร์จะเติม metadata.reply_to ดวยคำอธิบายสั้นๆ ของข้อความท่ีถูกอ้างถึง
  • สปอยเลอร์: "props": {"spoiler": true} จะซ่อนข้อความและไฟล์ของโพสต์จนกว่าผ้อ่านจะเลือกท่ีจะดู
  • การเพิกเฉยและการบล็อก เป็นความชอบส่วนตัว: หมวดหมู่ user_block, ท่ีตั้งช่อดวย ID ของอีกฝายหนึ่ง ดวยค่า ignore หรือ block. ท่ีท่ีข้อความส่วนตัวจะรอเป็นคำขออนุญาตอยู่ใน notify_props.dm_request ของสมาชิกช่องของคุณ (pending, accepted หรือ dismissed).
  • ไฟล์แนบของข้อความ สามารถมมี stages และ chart ได้: ดู Cards.
