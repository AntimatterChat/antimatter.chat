สิ่งที่คุณต้องมี

  • ไป ในเวอร์ชันท่ีระบุนใน server/go.mod (1.26.7 ณ เวลาท่ีเขียน)
  • Node.js และ npm ในเวอร์ชันที่ระบุใน .nvmrc และ webapp/package.json (Node 24.11.1 พร้อม npm 11.6.2) หากใช้ mise ไฟล์ mise.toml ในรีพอสิทอรีจะติดตั้ง Node เวอร์ชันที่ถูกต้องให้อัตโนมัติ
  • Docker พร้อม Compose: การตั้งค่าสำหรับพัฒนาจะรัน PostgreSQL และบริการอื่นๆ อีกเล็กน้อยในคอนเทนเนอร์
  • make, git และเครื่องคอมพิวเตอร์ที่รันระบบปฏิบัติการ Linux หรือ macOS
  • หน่วยความจำ: การคอมไพล์อินเทอร์เฟซเว็บเป็นขั้นตอนที่ใช้ทรัพยากรมาก ควรเตรียม RAM ไว้ที่ 16 GB ดูข้อมูลเพิ่มเติมได้ที่ การคอมไพล์และหน่วยความจำ
git clone https://github.com/AntimatterChat/antimatter.git
cd antimatter

รีพอสิทอรีเก็บเซิร์ฟเวอร์ไว้ใน server/, อินเทอร์เฟซเว็บไว้ใน webapp/ (Fusion อยู่ใน webapp/fusion, แบบคลาสสิกอยู่ใน webapp/channels, แพ็กเกจที่ใช้ร่วมกันอยู่ใน webapp/platform) และการทดสอบ end-to-end อยู่ใน e2e-tests/

การรันเซิร์ฟเวอร์สำหรับพัฒนา

cd server
make run

make run จะเริ่มคอนเทนเนอร์สำหรับพัฒนา (PostgreSQL, Redis, เครื่องดักอีเมล และเครื่องมือตรวจสอบ), เชื่อมต่อไฟล์ที่คอมไพล์แล้วของเว็บแอปเข้าที่, รันเซิร์ฟเวอร์ในพื้นหลังด้วย go run, และเริ่มตัวเฝ้าดู (watcher) ของเว็บแอป ซึ่งจะคอมไพล์อินเทอร์เฟซแบบคลาสสิกใหม่ทุกครั้งที่คุณแก้ไขโค้ด เปิด http://localhost:8065 และสร้างบัญชี: บัญชีแรกจะเป็นผู้ดูลำดับ (system admin)

คำสั่ง (ใน server/)สิ่งที่ทำ
make run-server, make run-clientรันเฉพาะเซิร์ฟเวอร์ หรือเฉพาะตัวเฝ้าดูของเว็บแอป
make restart-serverรีสตาร์ทเซิร์ฟเวอร์หลังจากแก้ไขโค้ด Go
make stopหยุดเซิร์ฟเวอร์ ตัวเฝ้าดู และคอนเทนเนอร์
make debug-serverรันเซิร์ฟเวอร์ภายใต้ Delve debugger
make run-cli ARGS="-version"รันคำสั่งของเซิร์ฟเวอร์
make config-resetรีเซ็ต config/config.json กลับเป็นค่าเริ่มต้น
make clean, make nukeลบไฟล์ที่คอมไพล์แล้ว; คำสั่ง nuke จะลบข้อมูลสำหรับพัฒนาด้วย

ฐานข้อมูลสำหรับพัฒนาคือ postgres://mmuser:mostest_password@localhost/mattermost_test ซึ่งเป็นแหล่งข้อมูลเริ่มต้นของเซิร์ฟเวอร์ คุณสามารถเลือกคอนเทนเนอร์ที่จะเริ่มทำงานได้ผ่าน ENABLED_DOCKER_SERVICES ในไฟล์ server/config.override.mk หรือในตัวแปรสภาพแวดล้อม (ดู server/config.mk สำหรับรายละเอียด)

อินเทอร์เฟซเว็บ

ใน webapp/:

npm install      # also builds the shared packages
npm run build    # the classic interface, then Fusion

ไฟล์ที่สร้างเสร็จจะอยู่ที่ webapp/channels/dist (classic) และ webapp/fusion/dist (Fusion) การรัน make client ใน server/ จะเชื่อมโยงไฟล์เหล่านี้เป็น server/client และ server/client-fusion ซึ่งเซิร์ฟเวอร์จะให้บริการไฟล์เหล่านี้โดย classic จะอยู่ภายใต้ /static/ และ Fusion จะอยู่ภายใต้ /static/fusion/

  • npm run run (หรือ make run ใน webapp/) จะเฝ้าดูและสร้างอินเทอร์เฟซ classic ใหม่ เพิ่ม WATCH_FUSION=true เพื่อสร้าง Fusion ใหม่ด้วย
  • npm run dev-server (make dev) จะรันเซิร์ฟเวอร์พัฒนาของ webpack แทน: classic บนพอร์ต 9005 และ Fusion บนพอร์ต 9006
  • เพื่อดูอินเทอร์เฟซแบบใดแบบหนึ่งในเบราว์เซอร์ ให้เพิ่ม ?webui=fusion หรือ ?webui=classic ต่อท้ายที่อยู่ของหน้าเว็บ

การทดสอบและการตรวจสอบ

คำสั่งตำแหน่งสิ่งที่ทำ
make test-serverserver/ชุดการทดสอบของเซิร์ฟเวอร์ โดยทดสอบกับคอนเทนเนอร์สำหรับพัฒนา ซึ่งใช้เวลาค่อนข้างนาน
make test-server-quickserver/เฉพาะการทดสอบแบบสั้น
go test ./channels/app/... -run TestNameserver/แพ็กเกจหรือการทดสอบหนึ่งรายการ โดยรันขณะที่คอนเทนเนอร์ทำงานอยู่ (make start-docker)
make check-styleserver/go vet, golangci-lint และการตรวจสอบ Go อื่นๆ
make testwebapp/การทดสอบหน่วย (Jest) ของเว็บแอป ในทุกแพ็กเกจ
npm run test -- <pattern>webapp/fusionการทดสอบบางส่วนของ Fusion
make check-style, make check-typeswebapp/ESLint และ TypeScript
make i18n-extractserver/ และ webapp/อัปเดตไฟล์สตริงภาษาอังกฤษหลังจากที่คุณเพิ่มหรือแก้ไขสตริง (ดู การแปล)

ให้รัน make modules-tidy แทน go mod tidy ใน server/

ไฟล์อาร์ไคฟ์สำหรับเผยแพร่

cd webapp && npm run build && cd ..
cd server
make build-linux       # the antimatter and amctl binaries
make package-linux     # dist/antimatter-linux-amd64.tar.gz and -arm64

make build จะสร้างอินเทอร์เฟซเว็บและไบนารีสำหรับ Linux ในครั้งเดียว อาร์ไคฟ์จะประกอบด้วย bin/antimatter, bin/amctl, config/config.json ค่าเริ่มต้น อินเทอร์เฟซเว็บทั้งสอง เทมเพลต ฟอนต์ และการแปล สำหรับแพลตฟอร์มอื่น: make package-osx, make package-windows, make package-freebsd อาร์ไคฟ์เหล่านี้ไม่รวมแอปที่ฝังไว้ แต่ Docker image จะรวมไว้

Docker image

รีพอสิทอรี antimatter-docker สร้าง image ที่เผยแพร่ ซึ่งประกอบด้วยเซิร์ฟเวอร์และแอปทั้งหมดภายใน Docker:

git clone https://github.com/AntimatterChat/antimatter-docker.git
cd antimatter-docker
scripts/build-all.sh                     # from the main branches on GitHub
SOURCES=local scripts/build-all.sh       # from your checkouts next to this folder
VARIANT=next scripts/build-all.sh        # the "next" image, with every Antimatter app

ต้องใช้ Docker ที่รองรับ buildx, Python 3, git และ gpg พร้อม RAM ประมาณ 16 GB และพื้นที่ดิสก์ 30 GB ผลลัพธ์จะถูกโหลดเป็น ghcr.io/antimatterchat/antimatter:dev; ลองใช้ด้วย ANTIMATTER_IMAGE=ghcr.io/antimatterchat/antimatter:dev docker compose -f compose.local.yml up -d plugins.json จะระบุรายการแอปและเวอร์ชันที่สร้าง และ README ของรีพอสิทอรีจะอธิบายถึงตัวแปรต่างๆ

build-all.sh ทำลายลายเซ็นแอปที่รวมอยู่ในแพ็กเกจด้วยคีย์ลายเซ็นของ Antimatter และกระบวนการสร้างภาพ (image build) จะปฏิเสธแอปที่ไม่มีลายเซ็น หากไม่มีคีย์ส่วนตัว (private key) ซึ่งเฉพาะผู้ดูแลระบบ (maintainers) เท่านั้นที่มี ให้รันขั้นตอนแรกๆ แยกกัน: scripts/fetch-sources.sh, scripts/build-plugins.sh (แอปใน out/plugins/) และ scripts/build-server.sh (ไฟล์เซิร์ฟเวอร์ใน out/server/)

การสร้างและหน่วยความจำ

อินเทอร์เฟซเว็บเป็นการสร้าง (build) ด้วย webpack ขนาดใหญ่ และการหมดหน่วยความจำ (out of memory) เป็นสาเหตุที่พบบ่อยที่สุดของการสร้างล้มเหลว

  • npm run build สร้างอินเทอร์เฟซแบบคลาสสิกและ Fusion ไล่ตามลำดับทีละตัว ไม่ใช่พร้อมกัน เพื่อลดจุดสูงสุด (peak) ของการใช้หน่วยความจำ อย่ารันทั้งสองอย่างพร้อมกันด้วยตนเอง
  • ตัวลดขนาด (minifier) จะเริ่ม worker หนึ่งตัวต่อโปรเซสเซอร์ หากเครื่องมีหลายคอร์แต่หน่วยความจำน้อย ให้จำกัดจำนวนโปรเซสเซอร์ที่การสร้างมองเห็น: taskset -c 0-5 npm run build
  • หาก Node หมดพื้นที่ heap ให้เพิ่มขีดจำกัด: NODE_OPTIONS=--max-old-space-size=6144 การสร้าง Docker ใช้ค่านี้ (BUILD_NODE_OPTIONS ใน build.env)
  • หลีกเลี่ยงการรันชุดทดสอบ (test suite) ทั้งหมดของเซิร์ฟเวอร์ การสร้างเว็บ และการสร้าง Docker พร้อมกันบนเครื่องขนาดเล็ก

แอปพลิเคชัน

แต่ละแอป (plugin) มีรีพอสิทอรี (repository) และ Makefile ของตัวเอง; make dist สร้าง bundle ของแอปนั้น ดู การสร้าง การติดตั้ง และการดีบัก

แอปเดสก์ท็อป

แอปเดสก์ท็อป เป็นแอป Electron โดยใช้ Node.js 24 หรือสูงกว่า:

npm install --allow-git=all
npm run build          # development build, into dist/
npm start              # run it
npm run package:linux  # packages into release/ (also package:windows, package:mac)

การตั้งค่าตอนสร้าง (build-time settings) เช่น เซิร์ฟเวอร์ที่จะตั้งค่าล่วงหน้า อยู่ใน src/common/config/buildConfig.ts

แอปมือถือ

แอปมือถือ เป็นแอป React Native; README ของแอประบุคำสั่ง (npm run ios, npm run android) เพื่อสร้างสำเนาของคุณเอง คุณยังต้องการคีย์ลายเซ็นของคุณเอง โปรเจกต์ Firebase สำหรับการแจ้งเตือนบน Android คีย์ APNs สำหรับ iOS และ push proxy ที่เก็บข้อมูลรับรองเหล่านั้น
