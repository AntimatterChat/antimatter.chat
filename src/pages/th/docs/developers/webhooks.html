ท่ีจัดการเว็บฮุค

เปิดอวตารของคุณที่มุมบนขวา จากนั้นเลือก อินทิเกรชัน หน้าออินทิเกรชันของชุมชนปัจจุบันจะแสดงรายการ เว็บฮุคขาเข้า และ เว็บฮุคทิศทางออก โดยแต่ละเว็บฮุคจะสังกัดชุมชนหนึ่งชุมชน

โดยค่าเริ่มต้น ผู้ดูแลชุมชนและผู้ดูแลระบบสามารถสร้างเว็บฮุคได้ ผู้ดูแลระบบสามารถให้อำนาจแก่บทบาทอื่่นในการตั้่งค่าสิทธิ์ในคอนโซลระบบ › อินทิเกรชัน › การจัดการอินทิเกรชัน: เปิดใช้งานเว็บฮุคขาเข้า และ เปิิด Outgoing Webhooks เปิิดใช้อยู่โดยค่าเริ่มต้นทั้่งสอง

สร้างเว็บฮุคเข้า

  1. ใน ออินทิเกรชัน เลือก เว็บฮุคขาเข้า จากนั้นเลือก เพิ่มเว็บฮุคเข้า
  2. กรอก ชื่อ และ คำอธิบาย: ข้อมูลเหล่านี้จะแสดงเฉพาะในหน้าออินทิเกรชันเท่านั้น
  3. เลืก Channel (ช่อง) ท่ีข้อความจะไปโดยค่าเริ่มต้น สำหรับช่องส่วนตัว (private channel), ต้องเป็นสมาชิกของช่องนั้่น
  4. ทำเครื่องหมายที่ ล็อกไว้กับช่องนี้ หากต้องการไม่ให้อื่นสามารถโพสต์ไปยังที่อื่นได้
  5. กำหนด ชื่อผู้ใช้ และ URL ของ รูปภาพโปรไฟล์ สำหรับข้อความของเว็บฮุค (ดู ชื่อและไอคอน)
  6. เลืก Save (บันทึก) คัดลอก URL ท่ีแสดง: https://chat.example.com/hooks/<key>
URL นั้่นเป็นความลับอยู้่ตัวเดียว: ใค้ท่ีมี URL นั้่นสามารถโพสต์ในช่องได้ อย่าเก็บใน repository ท่ีสาธารณะ, และลบเว็บฮุคนั้่นหาก URL รั่วไหล

ด้วย API: POST /api/v4/hooks/incoming พร้อม {"channel_id", "display_name", "description", "username", "icon_url", "channel_locked"}; id ใน response คือ key จาก command line: amctl webhook create-incoming --channel <channel id> --user <user> --display-name "CI"

ส่งข้อความไปยังเว็บฮุคเข้า

curl -X POST https://chat.example.com/hooks/xgh5ycrx1jf7mbs9w8z4c8e7ho \
  -H 'Content-Type: application/json' \
  -d '{"text": "Deploy of **api 2.4.0** finished :white_check_mark:"}'

เซิร์ฟเวอร์ตอบกลับ 200 พร้อม body ok ยังยอมรับ application/x-www-form-urlencoded ท่ีมี JSON ในฟิลด์ payload เหมืนเว็บฮุคของ Slack, ซึ่่งทำให้อุปกรณ์ท่ีสร้างสำหรับ Slack ใช้อยู้่แล้วโดยไมต่้องเปลี่่ยน

ฟิลด์ความหมาย
textข้อความใน Markdown ต้องมียกเว้นว่ามี attachments ข้อความที่ยาวกว่่าขั้้นพิกัดข้อความของเซิร์ฟเวอร์จะถกแบ่งออกเป็นข้อความหลายข้้อ
channelช่องอืน่ ๆ ของชุมชนท่ีเว็บฮุคอยู่ โดยชื่่อ (ops-alerts หรือ #ops-alerts) หรือ @username สำหรบั ข้อความส่วนตัวจากผู้ครอบครองเว็บฮุค ถกปัดถ่าเม่ือเว็บฮุคถกล็อกไว้กบั ช่องของตัวเอง
username, icon_url, icon_emojiชื่่อและรูปท่ีจะแสดง เม่ือเซิร์ฟเวอร์อนุญาติให้อัปเดต
attachmentsไฟล์แนบของข้อความ ท่ีถกแสดงในรู่ปของการ์ด (ข้่าล่่าง)
propsคุณสมบัตติ์เพิ่่มท่ีถกเก็บไว้กบั ข้อความ สำหรบั แอปท่ีอ่านข้้อมูลเหล่าน้ี
typeประเภทข้อความพเิ ศษ เชน่ custom_poll สำหรบั แอปท่ีจะแสดงข้้อมูลน้ี ประเภทท่ีตองด้วย system_ จะถกปัดถ่า
root_idID ของข้อความแรกในเธรด เพ่ือตอบกลับในเธรดนั้ น
priorityความสำคญั ของข้อความ เชน่ {"priority": "urgent"}
silenttrue ส่งข้อความโดยไม่มี push notifications

ข้อความท่ีแสดงภายใตช้ ื่่อท่ีถกเปล่ียนไปจะมตี ัวเอยี ง BOT อยูด่ ้านข้าง เพ่ือให้อายิ่ แยกออกได้กบั บัญชีจริง ข้อความจากเว็บฮุคจะไม่ทริกเกอร์เว็บฮุคออกเลย

ชื่่อและไอคอน

เว็บฮุคจะโพสต์ในนามของบุคคลที่สร้าง เว้นแต่เซิร์ฟเวอร์จะอนุญาตให้แทนที่ ค่าการตั้งค่าสองรายการใน คอนโซลระบบ › ออินทิเกรชัน › การจัดการออินทิเกรชัน ซึ่งปิดใช้งานอยู่เป็นค่าเริ่มต้น สามารถเปลี่ยนแปลงพฤติกรรมนี้ได้:

  • เปิดใช้งานการอินทิเกรตเพื่อแทนที่ชื่อผู้ใช้ (ServiceSettings.EnablePostUsernameOverride): จะแสดง ชื่อผู้ใช้ ของเว็บฮุค หรือ username จากคำขอแทน หากไม่มีทั้งสองอย่าง ชื่อจะแสดงเป็น webhook
  • เปิดใช้งานให้อินทิเกรชันทับไอคอนรูปโปรไฟล์ (ServiceSettings.EnablePostIconOverride): จะแสดง รูปภาพโปรไฟล์ ของเว็บฮุค หรือ icon_url หรือ icon_emoji จากคำขอ

ค่าน์ อกจากคำขอร้ องจะชนะค่าท่ีเก็บไว้กบั เว็บฮุค

ไฟล์แนบ

ไฟล์แนบเพิ่ มเนื้ อหาท่ีมีโครงสร้างไว้ข้่าล่่างข้ อความ ท่ีตามรูปแบบ attachment ของข้ อความ Slack:

{
  "text": "Build failed on `main`",
  "attachments": [{
    "fallback": "main #1902 failed",
    "color": "#d24b4e",
    "author_name": "GitHub Actions",
    "author_icon": "https://chat.example.com/static/ci.png",
    "title": "main #1902 failed",
    "title_link": "https://ci.example.com/runs/1902",
    "text": "Commit `0f4d8e2` by Jonas Weber",
    "fields": [
      {"title": "Branch", "value": "zephyr-3.7", "short": true},
      {"title": "Duration", "value": "3m 40s", "short": true}
    ],
    "footer": "Lumen CI",
    "ts": 1760000000
  }]
}
ฟิลด์ความหมาย
fallbackข้ อความธรรมดา สำหรบั ท่ีท่ีไม่สามารถแสดงการ์ดได้ เชน่ การแจ้ งเตื อน
colorแถบส่ี: ส่ี hex หรือ good, warning, danger
pretextข้ อความข้ ้าบนการ์ด
author_name, author_link, author_iconบรรทัดหัวข้ อขนาดเลก็
title, title_linkชื่ อข้ อของการ์ด อาจเป็ นลิ้ นก์ได้
textเนื้ อหาของการ์ด ใน Markdown
fieldsรายชื่ อของ {"title", "value", "short"}; ฟิลด์ short จะอยูด่ ้านข้ างกนั
image_url, thumb_urlภาพขนาดใหญ่ ข้ ้าล่ ่าง หรือภาพขนาดเลก็ ด้า นข้ าง
footer, footer_icon, tsบรรทัดท้ายข้ อและเวลา (Unix seconds)
actionsป่ มและเมนู: ดู Interactive messages

การ์ด: ส่ วนประกอบและกราฟ

Antimatter เพิ่มฟิลด์สองอย่างในไฟล์แนบ ซึ่งอินเทอร์เฟซเริ่มต้นจะแสดง:

  • stages: ขั้นตอนของ pipeline ในรูปแบบ pill สูงสุด 20 ขั้น แต่ละขั้นเป็น {"name", "status"} โดยมีสถานะเป็น passed, failed, running, pending, skipped หรือ canceled.
  • chart: กราฟเส้นขนาดเล็กแสดงค่าล่าสุด {"values": [2 to 200 numbers], "threshold": number, "label": "…"} เส้นเกณฑ์จะถูกระบุเป็นเส้นประ เพื่อแสดงขีดจำกัดของคำเตือน
{
  "attachments": [{
    "color": "danger",
    "title": "main #1902 failed",
    "stages": [
      {"name": "build", "status": "failed"},
      {"name": "unit", "status": "skipped"},
      {"name": "publish", "status": "skipped"}
    ]
  }, {
    "color": "warning",
    "title": "API latency above 400 ms",
    "chart": {"values": [210, 230, 260, 390, 450, 470], "threshold": 400, "label": "p95 latency, ms"}
  }]
}

อินเทอร์เฟซคลาสสิกและไคลเอนต์อื่นๆ จะเพิกเฉยต่อฟิลด์สองนี้ ดังนั้นควรใส่ข้อมูลสำคัญใน text หรือ fields ด้วย

สร้างเว็บฮุคขาออก

เว็บฮุคทิศทางออกจะเฝ้าดู สาธารณะ ของชุมชน เมื่อคำแรกของข้อความตรงกับคำกระตุ้นใดคำหนึ่งของเว็บฮุค Antimatter จะส่งข้อความไปยัง URL ของคุณ

  1. ใน ออินทิเกรชัน เลือก เว็บฮุคทิศทางออก จากนั้นเลือก เพิ่มเว็บฮุคแบบ Outgoing
  2. กรอก ชื่อ และ คำอธิบาย
  3. เลือก ประเภทเนื้อหา ของคำขอ: application/x-www-form-urlencoded หรือ application/json
  4. เลือก ช่อง กรอก คำกระตุ้น (1 คำต่อ 1 บรรทัด) หรือทำทั้งสองอย่าง หากเลือกช่องแต่ไม่มีคำกระตุ้น ทุกข้อความในช่องนั้นจะถูกส่ง หากเลือกทั้งสองอย่าง ข้อความต้องตรงกับทั้งสองเงื่อนไข
  5. ภายใต้ กระตุ้้นเมื่อ เลือก คำแรกตรงกับคำกระตุ้้นอย่างแม่นยำ หรือ คำแรกขึ้้นต้นด้วยคำกระตุ้้น.
  6. กรอก URLs สำหรับ Callback (หนึ่่ง URL ต่อหนึ่่งบรรทัด) แต่ละ URL จะได้รับข้้อความท่ีตรงกัับเงื่่อนไขทังหมด.
  7. ตั้่ง ชื่่อผ้้ใช้ และ รู่ปภาพโปรไฟล์ ท่ีใช้สำหร้ับข้้อความตอบกล้ับ (ไม่บังคับ).
  8. เลือก บันทึึก แล้้วคัดลอกโทเคนท่ีแสดงขึ้้นมา เซอร์วิสของคุณจะใช้โทเคนน้ีเพื่่อตรวจสอบว่่าข้้อความข้้อขอมาจากเซิร์ฟเวอร์ของคุณ.

ผ่าน API: POST /api/v4/hooks/outgoing พร้อม {"team_id", "channel_id", "trigger_words", "trigger_when", "callback_urls", "content_type", "display_name"} (trigger_when: 0 สำหรับตรงกันเป๊ะ, 1 สำหรับ "starts with")

หากเซอร์วิสของคุณอย่ืนในเนทเวอร์คส่ว่นต้ว ผ้้ด่แลระบบต้อองอนุญาติให้อ้ินทราสท่ีอย่ืนใน อนุญาติการเช่ือมต่อนภายในท่ีไม่ไว้วางใจถิง (ServiceSettings.AllowedUntrustedInternalConnections) เซิร์ฟเวอร์จะไม่เช่ือมต้อองกัับอ้ินทราสส่ว่นต้วถ้่าไม่ได้อนุญาติ.

คำขอขาออก

Antimatter ส่ง POST พร้อมฟิลด์เหล่านี้ เป็น JSON หรือ form-encoded ขึ้นอยู่กับ content type:

{
  "token": "6kd1ofo5ojr5zgu5ipfipybgnc",
  "team_id": "…",
  "team_domain": "lumen-labs",
  "channel_id": "…",
  "channel_name": "ops-alerts",
  "timestamp": 1760010000000,
  "user_id": "…",
  "user_name": "priya",
  "post_id": "…",
  "text": "deploy api 2.4.0",
  "trigger_word": "deploy",
  "file_ids": ""
}

เทียบ token กัับโทเคนของเว็บฮุคก่่อนท่ีจะทำสิ่่งอื่่น ในข้้อความท่ีเอนโค้ดแบบฟอร์ม timestamp จะอย่ืนในหน่วยเซค้อนด์ไม่ใช่มิลลเซค้อนด์ เซิร์ฟเวอร์จะรอกคำตอบจากคุณได้นานเท่านั้้นตาม Timeout สำหร้ับข้้อขอ Integration (ค่าต้้นต้้น 30 เซค้อนด์, ServiceSettings.OutgoingIntegrationRequestsTimeout).

ตอบกลับเว็บฮุคขาออก

เพื่อโพสต์คำตอบ ให้ตอบกลับด้วย JSON หากต้องการโพสต์อะไรเลย ให้ตอบกลับด้วย body ที่ว่างเปล่า

{
  "text": "Deploying **api 2.4.0** to staging…",
  "response_type": "comment",
  "username": "deploy-bot",
  "icon_url": "https://chat.example.com/static/deploy.png"
}
  • text และ attachments: คำตอบ หากไม่มีทั้งสองอย่าง จะไม่มีการโพสต์ใดๆ
  • response_type: comment จะโพสต์คำตอบในเธรดของข้อความที่กระตุ้น; ในกรณีอื่นจะโพสต์ในช่อง
  • username, icon_url: แสดงเมื่อเซิร์ฟเวอร์อนุญาตให้แทนที่ค่า; ในกรณีอื่นจะใช้ค่าของเว็บฮุคเอง
  • props, type, priority: เหมือนกับเว็บฮุคขาเข้า

คำตอบจะถูกโพสต์ในนามของผู้สร้างเว็บฮุค ภายใต้ชื่อที่แทนที่ (ถ้ามี) สำหรับเนื้อหาที่ยาวกว่าคำตอบสั้นๆ ให้ตอบกลับทันทีและโพสต์ทีหลังด้วยเว็บฮุคขาเข้าหรือ API

เมื่อเว็บฮุคไม่ทำงาน

  • 501 จาก URL ของเว็บฮุค: เว็บฮุคขาเข้าถูกปิดใช้งานบนเซิร์ฟเวอร์
  • 400 "Failed to decode the payload…": JSON ไม่ถูกต้อง หรือฟิลด์ฟอร์มไม่ได้ตั้งชื่อว่า payload "No text specified." หมายความว่าคำขอไม่มีทั้ง text และ attachments
  • 403: เว็บฮุคถูกล็อกไว้กับช่องอื่น หรือผู้ครอบครองไม่สามารถอ่านช่องนั้นได้อีกต่อไป
  • เว็บฮุคขาออกไม่ทำงานเลย: ช่องเป็นช่องส่วนตัว คำกระตุ้นไม่ใช่คำแรก หรือข้อความมาจากเว็บฮุค
  • Logs: เมื่่อเปิิด เปิิด Webhook Debugging (LogSettings.EnableWebhookDebugging) และตั้่งระดบั้ล๊อกท่ี DEBUG เซิร์ฟเวอร์จะบันทึึก payload ของข้้อขอท่ีเข้้ามาท่ีไม่สำเร็จ การโทรออกท่ีไม่สำเร็จจะถูึกบันทึึกในล๊อกในชื่่อ Outgoing Webhook POST failed.
