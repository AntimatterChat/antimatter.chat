วิธีขยาย Antimatter

เลือกเครื่องมือที่เบาที่สุดที่ทำงานได้ 4 ข้อแรกไม่จำเป็นต้องเข้าถึงตัวเซิร์ฟเวอร์ ส่วนแอปจะทำงานภายในเซิร์ฟเวอร์

เครื่องมือสิ่งที่ทำเหมาะสำหรับ
REST APIทุกอย่างที่แอปทำได้: ข้อความ, ช่อง, ผู้ใช้, ไฟล์, การตั้งค่า WebSocket จะส่งเหตุการณ์เมื่อเกิดขึ้นสคริปต์, การซิงค์กับระบบอื่น, คลाइเอนต์แบบกำหนดเอง
Incoming webhooksURL ลับที่โพสต์ข้อความไปยังช่องเมื่อมีใครส่ง JSON มาการแจ้งเตือน, ผลลัพธ์ CI, การตรวจสอบระบบ, การแจ้งเตือนจากเครื่องมืออื่น
Outgoing webhooksAntimatter จะเรียก URL ของคุณเมื่อข้อความในช่องสาธารณะขึ้นต้นด้วยคำกระตุ้น (trigger word) และจะโพสต์คำตอบของคุณกลับระบบอัตโนมัติที่ขับเคลื่อนด้วยแชทอย่างง่าย
คำสั่งสแลชผู้ใช้พิมพ์ /something; Antimatter จะเรียก URL ของคุณและแสดงคำตอบของคุณให้ผู้ใช้หรือให้ทั้งช่องเห็นการค้นข้อมูล, การดำเนินการที่เริ่มจากแชท
บอทบัญชีที่สร้างสำหรับโปรแกรม พร้อมโทเคนของตัวเอง, แท็ก BOT, และข้อความและไดอะล็อกแบบโต้ตอบผู้ช่วย, ระบบแจ้งเตือน, หรือสิ่งใดก็ตามที่ต้องสนทนากับผู้ใช้
แอป (ปลั๊กอิน)โค้ดที่ทำงานภายในเซิร์ฟเวอร์ (Go) และในแอปบนเว็บ (React): ฮุคสำหรับทุกข้อความ, เมนูใหม่, แผง, ประเภทข้อความ, หน้าฟีเจอร์: โพล, โน้ต, ปฏิทิน, การบูรณาการที่ต้องการส่วนติดต่อผู้ใช้

ในอินเทอร์เฟซ ผู้ใช้เรียกปลั๊กอินว่า "แอป" คู่มือนี้จะใช้คำว่า "แอป (ปลั๊กอิน)" ในจุดที่ทั้งสองคำช่วยให้เข้าใจได้ เนื่องจากโค้ด, API และการตั้งค่ายังคงใช้คำว่า "plugin" อยู่

ความเข้ากันได้กับ Mattermost

Antimatter เป็นฟอร์กของ Mattermost สิ่งส่วนใหญ่ที่ทำงานกับเซิร์ฟเวอร์ Mattermost จะทำงานกับ Antimatter ได้

สิ่งที่เป็นเหมือนเดิม

  • REST API ภายใต้ /api/v4, การยืนยันตัวตน, WebSocket และรูปแบบข้อผิดพลาด เซิร์ฟเวอร์รายงานเวอร์ชัน 12.0.0 ดังนั้นคลाइเอนต์และแอปที่ตรวจสอบเวอร์ชันเซิร์ฟเวอร์จะเห็นว่าเป็น Mattermost เวอร์ชันล่าสุด
  • เว็บฮุคและคำสั่งสแลช รวมถิง payload ที่เข้ากัย Slack
  • API และ hooks ของ server plugin: Antimatter ไหม่ได่เปลี่นแปลงสิ่่งเหล่านี้ โค้ดของ server ไดน้ั่่งหน้างกัย Go module เดิม, github.com/mattermost/mattermost/server/public
  • registry ของ web app plugin: ทุกระหัต register… ของ registry Mattermost ปรากฏในอินเทอร์เฟซเว็บทังสองของ Antimatter
  • ไลบรารีไคลเอนต์: Go client model.Client4 และ TypeScript client @mattermost/client (ดู ไลบรารีไคลเอนต์)
  • plugin bundles: ไฟล์ .tar.gz ทมี่ี manifest plugin.json Plugin ที่ลงนามดวยคีย์ของ Mattermost ไดน้ั่่งหน้างกัยการติดตั้ง เช่นเดียวกัยท่ีลงนามดวยคีย์ของ Antimatter

สิ่่งท่ีแตกต่าง

  • อินเทอร์เฟซเว็บสองชนิ อินเทอร์เฟซใหม่ Fusion เปนค่าเริ่มต้น อินเทอร์เฟซ Mattermost แบบคลาสสิกยังใชไ้ ด้อยู่ Fusion แสดงผลคอมโพเนนต์ของ plugin ส่วนใหญ่ แต่วางบางสิ่่งในตำแหน่งท่ีแตกต่างและไม่แสดงบางสิ่่ง แอพสามารถตรวจสอบไดว้ ่าอินเทอร์เฟซใดกำลงั ใชง้ านอยู่ ดู การสนับสนุอินเทอร์เฟซ Fusion
  • API เพิ่มเติม Antimatter เพิ่ม endpoints สำหรบั ฟีเจอร์ของตัวมันเอง: community attributes, timeouts, messages on top, message requests, channel and category overrides, channel export และฟิลด์ใหม่บน communities ดู สิ่่งท่ี Antimatter เพิ่มใน API
  • ฟีเจอร์ข้อความเพิ่่มเติม ไฟล์แนบของข้อความสามารถแสดง pipeline stages และกราฟขนาดเลก็; โพสต์สามารถเปน inline replies หรือ spoilers
  • web app hooks เพิ่่มเติม สำหรบั แอพ: รายการในเมนู "+" ของ composer, แท็บใน emoji picker, panel ในช่อง, footer ใต้ช่องในแถบด้านข้าง และรายการในหน้าง integrations ดู Hooks ท่ี Antimatter มีเพิ่่ง
  • ไม่มี่ี licences ทุกระบบทำงานไดโ์ ดยไมต่้องใช้ licence key endpoints สำหรบั licence, trial และ enterprise upgrade ไดม้ ีแลว้; GET /api/v4/license/client ยังอยู่สำหรบั ไคลเอนต์ท่ีถาม บางแอพท่ีสร้างสำหรบั Mattermost edition ท่ีตองเสยเงินจะตรวจสอบ licence เองและปฏิเสธรัน
  • ชื่่อ Teams ใหม้ ีชื่่อว่่า communities ในอินเทอร์เฟซ แต API และโค้ดยังใชค้ ำว่่า team Environment variables ใชป้ ระกอบ AM_, เครื่องมือ command-line เปน amctl และ server binary เปน antimatter

ทุกสิ่่งเป็็นโอเพนซอร์ส อยู้ใน AntimatterChat บน GitHub ทุกระบบเรพสิทอรี่ทำงานบน main branch

ก่อนที่คุณจะเริ่่ม

  • เตรียมเซิร์ฟเวอร์สำหรับทดสอบ. วิธีที่เร็วที่สุดคือใช้ Docker image: ดูที่ การติดตั้ง Antimatter. หากต้องการพัฒนา Antimatter เอง ดูที่ การสร้างจากซอร์สโค้ด.
  • ตรวจสอบว่าเซิร์ฟเวอร์อนุญาตอะไรบ้าง. ฟีเจอร์การเชื่อมต่อหลายอย่างถูกปิดไว้เป็นค่าเริ่มต้นและต้องอาศัยผู้ดูแลระบบ: personal access tokens, บอท, การเปลี่ยนชื่อผู้ใช้งานและไอคอน, และการอัปโหลดแอป. แต่ละหน้าจะระบุว่าการตั้งค่าใดที่จำเป็น.
  • จดจำ URL ของเว็บไซต์. ตัวอย่างใช้ https://chat.example.com. ให้แทนที่ด้วยที่อยู่ของเซิร์ฟเวอร์ของคุณ.

ในคู่มือนี้

  • REST API: การยืนยันตัวตน, ทรัพยากรหลัก, การแบ่งหน้า, ข้อผิดพลาด, ข้อจำกัดของอัตรา, WebSocket, ไลบรารีไคลเอนต์, และส่วนเพิ่มเติมของ Antimatter.
  • เว็บฮุค: เว็บฮุคขาเข้าและขาออก, payloads, ไฟล์แนบ และการ์ด.
  • คำสั่งสแลช: คำสั่งแบบกำหนดเอง, คำขอและคำตอบ, การเติมอัตโนมัติ.
  • บอทและข้อความแบบอินเทอร์แอคทีฟ: บอท, ปุ่ม, เมนู และไดอะล็อก.
  • การเขียนแอป: โครงสร้างของปลั๊กอิน, server hooks, web app registry, Fusion, การตั้งค่า, การเก็บข้อมูล, การแปลภาษา และการแพ็กเกจ.
  • การสร้างจากซอร์สโค้ด: เซิร์ฟเวอร์, อินเทอร์เฟซเว็บ, Docker image และแอป.
  • การมีส่วนร่วม: issues, pull requests, สไตล์, การแปลภาษา, ความปลอดภัย และลิขสิทธิ์.
