ติดตั้งด้วย Docker Compose

นี่คือวิธีที่แนะนำ ไฟล์ compose เดียวรัน Antimatter, PostgreSQL, ที่เก็บไฟล์ และบริการ GIF คุณต้องมีเซิร์ฟเวอร์ Linux ที่มี Docker Engine และปลั๊กอิน Compose (docker compose), 2 คอร์ CPU และหน่วยความจำ 4 GB ขึ้นไป

1. ดาวน์โหลดไฟล์ compose

mkdir antimatter && cd antimatter
curl -fsSLO https://antimatter.chat/compose.yaml

2. สร้างไฟล์ .env

ไฟล์ compose อ่านค่าการตั้งค่าจากไฟล์ .env ในไดเรกทอรีเดียวกัน สร้างไฟล์นี้พร้อมรหัสลับแบบสุ่ม:

cat > .env <<EOF
SITE_URL=http://localhost:8065
POSTGRES_PASSWORD=$(openssl rand -hex 24)
S3_SECRET_KEY=$(openssl rand -hex 24)
GIFS_API_KEY=$(openssl rand -hex 24)
EOF
chmod 600 .env

ตั้งค่า SITE_URL เป็นที่อยู่ที่จะพิมพ์ในเบราว์เซอร์ เช่น http://192.168.1.20:8065 บนเครือข่ายภายใน หรือ https://chat.example.com พร้อมโดเมนเนม เก็บไฟล์ .env ไว้: ฐานข้อมูลและที่เก็บไฟล์ใช้รหัสผ่านเหล่านี้ตั้งแต่ครั้งแรกที่เริ่มใช้งาน และคุณต้องการไฟล์เดียวกันนี้เพื่อสำรองข้อมูล

3. เริ่มใช้งาน

docker compose up -d
docker compose ps

การเริ่มใช้งานครั้งแรกใช้เวลาประมาณ 1-2 นาที: PostgreSQL สร้างฐานข้อมูล, บริการ bucket แบบใช้ครั้งเดียวสร้างที่เก็บข้อมูล, บริการ gifs-stickers แบบใช้ครั้งเดียวนำเข้าชุดสติกเกอร์เริ่มต้น และ Antimatter สร้างตาราง ติดตามด้วย docker compose logs -f antimatter

หากต้องการใช้โดเมนเนมและ HTTPS ตั้งแต่เริ่มต้น ดู โดเมนและ HTTPS: ด้วยไฟล์ compose เป็นเพียงอีก 2 บรรทัดใน .env และโปรไฟล์ https

ตัวแปรในไฟล์ .env

ตัวแปรค่าเริ่มต้นสิ่งที่ทำ
SITE_URLจำเป็นที่อยู่สาธารณะของ Antimatter (ServiceSettings.SiteURL).
POSTGRES_PASSWORDจำเป็นรหัสผ่านของผู้ใช้ฐานข้อมูล antimatter.
S3_SECRET_KEYจำเป็นคีย์ลับของที่เก็บไฟล์.
GIFS_API_KEYจำเป็นคีย์ที่ Antimatter ใช้เรียกใช้บริการ GIF.
GIFS_UPLOAD_KEYว่างอนุญาตให้ผู้ใช้เพิ่ม GIF และสติกเกอร์ของตัวเองจากตัวเลือก หากเว้นว่างจะปิดการอัปโหลด
DOMAINว่างโดเมนเนมของคุณ สำหรับโปรไฟล์ https.
HTTP_PORT8065พอร์ตโฮสต์ของเซิร์ฟเวอร์เว็บของ Antimatter.
CALLS_PORT8443พอร์ต UDP และ TCP สำหรับเสียงและวิดีโอในการโทร.
EDGE_SUBNET172.29.71.0/28ซับเน็ตของเครือข่ายระหว่าง Caddy และ Antimatter เปลี่ยนหากทับซ้อนกับเครือข่ายของคุณ
TZUTCเขตเวลาของคอนเทนเนอร์.
ANTIMATTER_IMAGEghcr.io/antimatterchat/antimatter-next:latestอิมเมจ Antimatter ที่จะรัน (ดูด้านล่าง).

httpscaddy:2-alpineเฉพาะโปรไฟล์ https: HTTPS บนพอร์ต 80 และ 443

PostgreSQL, ที่เก็บข้อมูล และบริการ GIF อยู่บนเครือข่ายภายใน (private) ที่ไม่มีอินเทอร์เน็ต ซึ่ง Antimatter เท่านั้นที่เข้าร่วม ไม่มีบริการใดเปิดพอร์ตออก

คอนเทนเนอร์ Antimatter ไม่เก็บข้อมูลใด ๆ บนดิสก์: การตั้งค่าอยู่ในฐานข้อมูล (AM_CONFIG ชี้ไปที่ฐานข้อมูล) และไฟล์และแอปอยู่ในบริการที่เก็บข้อมูล คุณสามารถลบและสร้างคอนเทนเนอร์ใหม่ได้ตลอดเวลา สิ่งที่ต้องสำรองข้อมูลทั้งหมดอยู่ในโวลุ่ม postgres, files และ gifs รวมถึงไฟล์ .env ของคุณ

เลือกภาพ

มีภาพ Antimatter ที่เผยแพร่สองภาพ ทั้งสองรองรับ linux/amd64 และ linux/arm64 และทั้งสองสร้างจากสาขา main ของทุกคลังข้อมูล:

ภาพแอปที่รวมมาให้แท็ก
ghcr.io/antimatterchat/antimatterAgents, Calls, GitHub, GitLab, Jira, Kanban, Metrics และ Playbooks.latest, X.Y.Z สำหรับเวอร์ชันที่เผยแพร่, sha-<commit>
ghcr.io/antimatterchat/antimatter-nextเหมือนด้านบน แต่เพิ่ม Voice channels, Polls, Mail, Calendar, Notes, Whiteboard, GIFs, Todo และ Memes. สร้างใหม่ทุกคืนlatest, nightly, nightly-<YYYYMMDD>, sha-<commit>

ไฟล์ compose ของเว็บไซต์ใช้ antimatter-next เนื่องจากบริการ GIF และแอปส่วนใหญ่ที่อธิบายไว้ในเว็บไซต์นี้มีเฉพาะในภาพนี้ หากต้องการเปลี่ยนภาพ ให้ตั้งค่า ANTIMATTER_IMAGE ใน .env แล้วรัน docker compose up -d

latest เปลี่ยนแปลงอยู่ตลอดเวลา ในสภาพแวดล้อมการผลิต ให้ตรึงแท็ก เช่น nightly-20261015 หรือ sha-<commit> และเปลี่ยนเมื่อตั้งใจอัปเกรดเท่านั้น เซิร์ฟเวอร์จะอัปเกรดฐานข้อมูลเมื่อเริ่มทำงาน ดังนั้นคุณจึงไม่สามารถย้อนกลับไปยังภาพเวอร์ชันเก่า หรือจาก antimatter-next กลับไป antimatter ได้ เว้นแต่จะกู้คืนข้อมูลสำรองที่สร้างไว้ก่อนหน้า ดู การสำรองข้อมูลและการอัปเกรด

ภายในภาพ

  • เซิร์ฟเวอร์อยู่ใน /antimatter โดยมีไฟล์ไบนารี antimatter และ amctl ใน /antimatter/bin (บน PATH)
  • ทำงานด้วยผู้ใช้ที่ไม่ใช่ผู้ดูแลระบบ antimatter (uid 2000) บนฐาน distroless แบบมินิมอล โดยไม่มี shell
  • พอร์ต: 8065 (เว็บและ API), 8067 (เมตริก), 8074 (คลัสเตอร์), 8443 UDP และ TCP (การโทร)
  • โหมดโลคอล (ServiceSettings.EnableLocalMode) เปิดอยู่ ดังนั้น amctl --local จึงทำงานได้ภายในคอนเทนเนอร์ การตรวจสอบสถานะระบบ (health check) จะรันคำสั่ง amctl system status --local
  • แอปที่มากับระบบจะอยู่ที่ /antimatter/prepackaged_plugins และถูกเซ็นด้วยคีย์เซ็นแอปของ Antimatter
  • เครื่องมือสำหรับดึงข้อความ (pdftotext, wvText, unrtf, tidy) ถูกติดตั้งมาให้แล้ว จึงสามารถค้นหาเนื้อหาในเอกสารที่อัปโหลดได้

ไฟล์ compose อื่น ๆ

รีพอสิทอรี antimatter-docker มีชุดการตั้งค่าสำหรับใช้งานจริง (production) อยู่ที่ deploy/compose/ ซึ่งประกอบด้วย nginx พร้อมใบรับรองของคุณเองหรือ Let's Encrypt (certbot), PostgreSQL, บริการ GIF (โปรไฟล์ gifs) และ named volumes สำหรับค่าการตั้งค่า ข้อมูล และบันทึกการทำงานของเซิร์ฟเวอร์ โดยมีรายละเอียดใน README ของรีพอสิทอรีนั้น ชุดการตั้งค่านี้ใช้ภาพ (image) เวอร์ชันเสถียร (stable) เป็นค่าเริ่มต้น และจัดเก็บไฟล์บน volume ปลายทาง (local volume) แทน S3 storage คุณสามารถใช้ชุดนี้ได้หากคุณชอบ nginx มากกว่า Caddy หรือหากคุณมีใบรับรองอยู่แล้ว

สร้างผู้ดูแลระบบคนแรก

เปิด SITE_URL ในเบราว์เซอร์ของคุณแล้วสร้างบัญชี บัญชีแรกที่ถูกสร้างบนเซิร์ฟเวอร์ใหม่จะกลายเป็นผู้ดูแลระบบ (system administrator) จากนั้นระบบจะแนะนำคุณในการสร้างชุมชน (community) แรก (ซึ่งเป็นชื่อที่ Antimatter ใช้เรียกทีมหรือพื้นที่ทำงาน)

ควรทำทันทีหลังจากเริ่มระบบครั้งแรก: จนกว่าจะถึงเวลานั้น ใครก็ตามที่เข้าถึงเซิร์ฟเวอร์ก่อนจะกลายเป็นผู้ดูแลระบบของมัน หากต้องการสร้างบัญชีผ่านบรรทัดคำสั่ง (command line) แทน ให้ทำก่อนที่เซิร์ฟเวอร์จะเข้าถึงได้จากภายนอก:

docker compose exec antimatter amctl --local user create --system-admin --email-verified \
    --email admin@example.com --username admin --password 'a-long-password'
docker compose exec antimatter amctl --local team create --name main --display-name "Main"
docker compose exec antimatter amctl --local team users add main admin

จากนั้นเข้าสู่ระบบที่ SITE_URL เริ่มคำสั่งด้วยช่องว่าง (space) เพื่อป้องกันไม่ให้รหัสผ่านถูกบันทึกในประวัติ shell (เมื่อตั้งค่า HISTCONTROL=ignorespace) หรือเปลี่ยนรหัสผ่านหลังจากเข้าสู่ระบบแล้ว

ขั้นตอนถัดไปเมื่อคุณเข้าสู่ระบบแล้ว:

  1. กำหนดว่าใครสามารถสร้างบัญชีได้: การเข้าสู่ระบบและบัญชี
  2. ตั้งค่าอีเมล เพื่อให้การเชิญและการรีเซ็ตรหัสผ่านทำงานได้: อีเมลและการแจ้งเตือนแบบ push
  3. เปิดพอร์ตสำหรับโทรในไฟร์วอลล์ของคุณ: การโทรและเสียง
  4. ตรวจสอบว่าแอปใดเปิดอยู่: แอปที่มากับระบบ

ติดตั้งจากอาร์ไคฟ์เวอร์ชันที่ปล่อยออกมา (release archive)

เมื่อไม่มี Docker เซิร์ฟเวอร์จะทำงานจากไฟล์อาร์ไคฟ์ชื่อ antimatter-<os>-<arch>.tar.gz (เช่น antimatter-linux-amd64.tar.gz) ซึ่งประกอบด้วยไดเรกทอรี antimatter/ เดียวที่มี bin/antimatter, bin/amctl, config/config.json, แอปพลิเคชันเว็บ (client/ และ client-fusion/), เทมเพลตอีเมล และไฟล์แปลภาษา

1. เตรียม PostgreSQL

Antimatter รองรับเฉพาะ PostgreSQL เวอร์ชัน 15 ขึ้นไป (เวอร์ชันเก่ากว่าจะเริ่มต้นทำงานได้แต่มีข้อผิดพลาดในบันทึกเหตุการณ์) สร้างผู้ใช้และฐานข้อมูล:

sudo -u postgres psql <<'EOF'
CREATE USER antimatter WITH PASSWORD 'a-long-password';
CREATE DATABASE antimatter OWNER antimatter;
EOF

2. แตกไฟล์และตั้งค่า

sudo tar -xzf antimatter-linux-amd64.tar.gz -C /opt
sudo useradd --system --user-group antimatter
sudo mkdir -p /opt/antimatter/data
sudo chown -R antimatter:antimatter /opt/antimatter

กำหนดให้เซิร์ฟเวอร์เชื่อมต่อกับฐานข้อมูล ผ่าน /opt/antimatter/config/config.json (SqlSettings.DataSource) หรือผ่านตัวแปรสภาพแวดล้อม และตั้งค่า URL ของเว็บไซต์:

AM_SQLSETTINGS_DRIVERNAME=postgres
AM_SQLSETTINGS_DATASOURCE=postgres://antimatter:a-long-password@localhost:5432/antimatter?sslmode=disable&connect_timeout=10
AM_SERVICESETTINGS_SITEURL=https://chat.example.com

ไฟล์ config.json ในอาร์ไคฟ์คือค่าเริ่มต้นที่สมบูรณ์: การตั้งค่าที่คุณเปลี่ยนในคอนโซลระบบจะถูกบันทึกกลับลงในไฟล์นี้ หากต้องการเก็บการตั้งค่าในฐานข้อมูลแทน ดู การตั้งค่า

3. รันเป็นบริการ

หน่วย systemd ใน /etc/systemd/system/antimatter.service:

[Unit]
Description=Antimatter
After=network.target postgresql.service

[Service]
Type=notify
User=antimatter
Group=antimatter
WorkingDirectory=/opt/antimatter
ExecStart=/opt/antimatter/bin/antimatter
EnvironmentFile=-/etc/antimatter.env
TimeoutStartSec=3600
Restart=always
RestartSec=10
LimitNOFILE=49152

[Install]
WantedBy=multi-user.target

ใส่ตัวแปร AM_ ของคุณใน /etc/antimatter.env (อ่านได้โดย root เท่านั้น) จากนั้น:

sudo systemctl daemon-reload
sudo systemctl enable --now antimatter
journalctl -u antimatter -f

เซิร์ฟเวอร์จะรับฟังบนพอร์ต 8065 เปิด http://<server>:8065 หรือโดเมนของคุณเมื่อมี reverse proxy แล้ว (ดู โดเมนและ HTTPS) และสร้างบัญชีแรก: บัญชีนี้จะกลายเป็นผู้ดูแลระบบ

bin/amctl ใช้จัดการเซิร์ฟเวอร์ที่กำลังทำงานอยู่จากบรรทัดคำสั่ง บนเซิร์ฟเวอร์เอง มันทำงานได้โดยไม่ต้องเข้าสู่ระบบผ่านโหมดท้องถิ่น: ตั้งค่า AM_SERVICESETTINGS_ENABLELOCALMODE=true จากนั้นรัน sudo -u antimatter /opt/antimatter/bin/amctl --local system status

คำสั่งเซิร์ฟเวอร์อื่นๆ

นอกเหนือจากการรันเซิร์ฟเวอร์ (antimatter หรือ antimatter server) แล้ว ไบนารีนี้ยังมีคำสั่งบำรุงรักษาสองสามคำสั่ง ซึ่งอ่านการตั้งค่าเดียวกันกับเซิร์ฟเวอร์

คำสั่งสิ่งที่ทำ
antimatter versionแสดงเวอร์ชัน, หมายเลขการสร้าง, วันที่สร้าง และแฮชของการสร้าง
antimatter db pingตรวจสอบว่าฐานข้อมูลสามารถเข้าถึงได้
antimatter db initสร้างการตั้งค่าในฐานข้อมูล (โดยตั้งค่า AM_CONFIG เป็น URL แบบ postgres://)
