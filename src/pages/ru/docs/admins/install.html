Установка с помощью Docker Compose

Это рекомендуемый способ. Один файл compose запускает Antimatter, PostgreSQL, хранилище файлов и службу GIF. Вам понадобится сервер на Linux с Docker Engine и его плагином Compose (docker compose), 2 ядра CPU и 4 ГБ оперативной памяти или больше.

1. Скачайте файл compose

mkdir antimatter && cd antimatter
curl -fsSLO https://antimatter.chat/compose.yaml

2. Создайте файл .env

Файл compose читает свои настройки из файла .env в той же директории. Создайте его со случайными секретами:

cat > .env <<EOF
SITE_URL=http://localhost:8065
POSTGRES_PASSWORD=$(openssl rand -hex 24)
S3_SECRET_KEY=$(openssl rand -hex 24)
GIFS_API_KEY=$(openssl rand -hex 24)
EOF
chmod 600 .env

Укажите в SITE_URL адрес, который пользователи будут вводить в браузере, например http://192.168.1.20:8065 в локальной сети или https://chat.example.com с доменным именем. Сохраните файл .env: база данных и хранилище используют эти пароли с первого запуска, и вам понадобится тот же файл для восстановления из резервной копии.

3. Запустите

docker compose up -d
docker compose ps

Первый запуск занимает минуту-две: PostgreSQL создаёт базу данных, одноразовая служба bucket создаёт хранилище, одноразовая служба gifs-stickers импортирует стартовый набор стикеров, а Antimatter создаёт свои таблицы. Следите за процессом с помощью docker compose logs -f antimatter.

Чтобы использовать доменное имя и HTTPS с самого начала, см. Домен и HTTPS: с файлом compose это всего две дополнительные строки в .env и профиль https.

PostgreSQL, хранилище и сервис GIF находятся во внутренней сети (private) без доступа в Интернет, к которой присоединяется только Antimatter. Ни один из них не публикует порты.

Контейнер Antimatter ничего не хранит на диске: его параметры находятся в базе данных (AM_CONFIG указывает на неё), а файлы и приложения — в сервисе хранилища. Вы можете удалить и пересоздать контейнер в любой момент. Всё, что нужно резервировать, находится в томах postgres, files и gifs, а также в вашем файле .env.

Выберите образ

Опубликованы два образа Antimatter, оба для linux/amd64 и linux/arm64, и оба собраны из ветки main каждого репозитория:

ОбразВстроенные приложенияТеги
ghcr.io/antimatterchat/antimatterАгенты, звонки, GitHub, GitLab, Jira, Kanban, метрики и плейбуки.latest, X.Y.Z для релизов, sha-<commit>
ghcr.io/antimatterchat/antimatter-nextТо же самое, плюс голосовые каналы, опросы, почта, календарь, заметки, доски для рисования, GIF, списки дел и мемы. Пересобирается каждую ночь.latest, nightly, nightly-<YYYYMMDD>, sha-<commit>

Файл compose сайта использует antimatter-next, потому что сервис GIF и большинство приложений, описанных на этом сайте, доступны только в этом образе. Чтобы сменить образ, задайте ANTIMATTER_IMAGE в .env и выполните docker compose up -d.

Содержимое тега latest может измениться. В продакшене закрепляйте за собой конкретный тег, например nightly-20261015 или sha-<commit>, и меняйте его осознанно при обновлении. Сервер обновляет свою базу данных при запуске, поэтому вы не сможете вернуться к более старому образу или перейти с antimatter-next на antimatter, не восстановив резервную копию, сделанную до этого. См. Резервное копирование и обновления.

Внутри образа

  • Сервер находится в /antimatter, бинарные файлы antimatter и amctl — в /antimatter/bin (в PATH).
  • Он работает от имени непривилегированного пользователя antimatter (uid 2000) на минималистичном distroless-базовом образе, без оболочки.
  • Порты: 8065 (веб и API), 8067 (метрики), 8074 (кластер), 8443 UDP и TCP (звонки).
  • Режим локального хранилища (ServiceSettings.EnableLocalMode) включён, поэтому amctl --local работает внутри контейнера. Проверка работоспособности выполняется с помощью команды amctl system status --local.
  • Встроенные приложения находятся в /antimatter/prepackaged_plugins и подписаны ключом подписи приложений Antimatter.
  • Инструменты для извлечения текста (pdftotext, wvText, unrtf, tidy) включены в состав, что позволяет искать по содержимому загруженных документов.

Другие файлы compose

В репозитории antimatter-docker есть конфигурация для продакшена в deploy/compose/: nginx с собственными сертификатами или Let's Encrypt (certbot), PostgreSQL, опциональный сервис GIF (профиль gifs) и именованные тома для конфигурации, данных и журналов сервера, описанные в README. По умолчанию используется стабильный образ, а файлы хранятся на локальном томе, а не в S3. Используйте этот вариант, если предпочитаете nginx Caddy или уже имеете сертификаты.

Создание первого администратора

Откройте SITE_URL в браузере и создайте аккаунт. Первый аккаунт, созданный на новом сервере, становится системным администратором, после чего мастер настройки проведёт вас через создание первого сообщества (так в Antimatter называются команды или рабочие пространства).

Сделайте это сразу после первого запуска: до этого момента любой, кто первым достигнет сервера, станет его администратором. Чтобы создать аккаунт из командной строки, пока сервер недоступен извне:

docker compose exec antimatter amctl --local user create --system-admin --email-verified \
    --email admin@example.com --username admin --password 'a-long-password'
docker compose exec antimatter amctl --local team create --name main --display-name "Main"
docker compose exec antimatter amctl --local team users add main admin

Затем войдите на SITE_URL. Начните команду с пробела, чтобы пароль не попал в историю команд (при HISTCONTROL=ignorespace), либо смените пароль после входа.

Дальнейшие шаги после входа:

  1. Определите, кто может создавать аккаунты: Вход и аккаунты.
  2. Настройте электронную почту, чтобы приглашения и сброс пароля работали: Электронная почта и push-уведомления.
  3. Откройте порт для звонков в файрволе: Звонки и голосовые каналы.
  4. Проверьте, какие приложения включены: Встроенные приложения.

Установка из архива релиза

Без Docker сервер запускается из архива с именем antimatter-<os>-<arch>.tar.gz (например, antimatter-linux-amd64.tar.gz). Он содержит единственный каталог antimatter/ с файлами bin/antimatter, bin/amctl, config/config.json, веб-приложениями (client/ и client-fusion/), шаблонами электронной почты и переводами.

1. Подготовка PostgreSQL

Antimatter поддерживает только PostgreSQL версии 15 и новее (более старые версии запускаются, но в журнале появляется ошибка). Создайте пользователя и базу данных:

sudo -u postgres psql <<'EOF'
CREATE USER antimatter WITH PASSWORD 'a-long-password';
CREATE DATABASE antimatter OWNER antimatter;
EOF

2. Распаковка и настройка

sudo tar -xzf antimatter-linux-amd64.tar.gz -C /opt
sudo useradd --system --user-group antimatter
sudo mkdir -p /opt/antimatter/data
sudo chown -R antimatter:antimatter /opt/antimatter

Укажите серверу базу данных, либо в /opt/antimatter/config/config.json (SqlSettings.DataSource), либо с помощью переменных окружения, и задайте URL сайта:

AM_SQLSETTINGS_DRIVERNAME=postgres
AM_SQLSETTINGS_DATASOURCE=postgres://antimatter:a-long-password@localhost:5432/antimatter?sslmode=disable&connect_timeout=10
AM_SERVICESETTINGS_SITEURL=https://chat.example.com

Файл config.json в архиве — это полная конфигурация по умолчанию: изменения, внесённые в Системной консоли, сохраняются обратно в этот файл. Чтобы хранить конфигурацию в базе данных, см. Конфигурация.

3. Запуск как службы

Единица systemd, файл /etc/systemd/system/antimatter.service:

[Unit]
Description=Antimatter
After=network.target postgresql.service

[Service]
Type=notify
User=antimatter
Group=antimatter
WorkingDirectory=/opt/antimatter
ExecStart=/opt/antimatter/bin/antimatter
EnvironmentFile=-/etc/antimatter.env
TimeoutStartSec=3600
Restart=always
RestartSec=10
LimitNOFILE=49152

[Install]
WantedBy=multi-user.target

Разместите переменные AM_ в файле /etc/antimatter.env (доступном только для root), затем выполните:

sudo systemctl daemon-reload
sudo systemctl enable --now antimatter
journalctl -u antimatter -f

Сервер слушает порт 8065. Откройте http://<server>:8065 или ваш домен, если настроен обратный прокси (см. Домен и HTTPS), и создайте первый аккаунт: он станет системным администратором.

Утилита bin/amctl управляет работающим сервером из командной строки. На самом сервере она работает без входа через локальный режим: установите AM_SERVICESETTINGS_ENABLELOCALMODE=true, затем выполните sudo -u antimatter /opt/antimatter/bin/amctl --local system status.

Другие команды сервера

Помимо запуска сервера (antimatter или antimatter server), бинарный файл содержит несколько служебных команд. Они читают ту же конфигурацию, что и сервер.

КомандаНазначение
antimatter versionВыводит версию, номер сборки, дату сборки и хэш сборки.
antimatter db pingПроверяет доступность базы данных.
antimatter db initСоздаёт конфигурацию в базе данных (при установленном AM_CONFIG с URL в формате postgres://).
antimatter db migrateПрименяет миграции базы данных без запуска сервера.
antimatter db versionВыводит последнюю применённую миграцию базы данных.
antimatter import bulk, antimatter export bulkИмпортирует или экспортирует данные в пакетном формате (см. Резервные копии и обновления).
