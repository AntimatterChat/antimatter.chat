Как работают звонки

Звонки обеспечиваются приложением Звонки (id com.mattermost.calls), которое установлено и включено по умолчанию. Голосовые каналы (приложение Голосовые каналы, образ antimatter-next) — это постоянные комнаты для звонков, построенные на базе приложения «Звонки»: для их работы необходимо, чтобы приложение «Звонки» было включено, и они используют те же параметры, порты и серверы.

Приложение «Звонки» запускает медиа-сервер внутри Antimatter. Веб-приложение, настольное приложение и мобильные приложения подключаются к нему с помощью WebRTC:

  • сигнализация проходит через обычное веб-соединение (ваш HTTPS-прокси);
  • медиа (аудио, видео, демонстрация экрана) не проходит через него: оно направляется напрямую на сервер через порт для звонков, по умолчанию 8443 UDP и TCP.

Параметры находятся в разделе Системная консоль › Плагины › Звонки. Каждый из них также можно настроить с помощью переменной окружения AM_CALLS_ для сервиса antimatter, которая в этом случае имеет приоритет над Системной консолью и блокирует изменение параметра в ней. Также работают устаревшие имена MM_CALLS_.

Проверьте это после установки

  1. Откройте порт для звонков. Разрешите 8443/udp и 8443/tcp в файрволе сервера и вашего облачного провайдера.
  2. Отключите тестовый режим. Тестовый режим (DefaultEnabled) включен по умолчанию: только системные администраторы могут начинать звонки в каналах, что позволяет проверить, что звонки работают, прежде чем все начнут их использовать. Установите значение Выкл в разделе Системная консоль › Плагины › Звонки или задайте AM_CALLS_DEFAULT_ENABLED=true.
  3. Решите вопрос с видео. Параметр Включить видеозвонки в личных сообщениях (экспериментально) (EnableVideo, AM_CALLS_ENABLE_VIDEO) выключен по умолчанию. Пока он выключен, никто не может включить камеру, даже в голосовых каналах. Когда он включен, камеры работают в звонках личных сообщений и в голосовых каналах (если в приложении «Голосовые каналы» параметр Разрешить видео в голосовых каналах не выключен).
  4. За NAT задайте публичный адрес (следующий раздел).

Порты должны быть в диапазоне от 80 до 49151. В файле compose сайта измените CALLS_PORT в .env: он задает обе переменные и публикует порт, один и тот же номер на хосте и в контейнере. Клиенты сначала пробуют UDP, а при неудаче переключаются на TCP на том же порту.

Адрес, на который клиенты отправляют медиа

Сервер сообщает каждому клиенту адрес, на который нужно отправлять медиа (его «кандидат хоста»). По умолчанию он определяет свой публичный адрес, запрашивая его у STUN-сервера — публичной службы, которая отвечает адресом и портом, с которых поступил запрос. По умолчанию используется публичный STUN-сервер Cloudflare, stun:stun.cloudflare.com:3478. Сервер — не единственный, кто им пользуется: каждый клиент, присоединяющийся к звонку, тоже запрашивает у него свой публичный адрес. STUN-сервер видит только IP-адреса и порты, но никогда не получает аудио, видео или сообщения из звонка.

Сервер, в Конфигурациях серверов ICE которого по-прежнему сохранен STUN-сервер Mattermost (stun.global.calls.mattermost.com), например после перехода с Mattermost, использует вместо него сервер Cloudflare. Сохраненная настройка не изменяется.

Задать адрес вручную необходимо, если:

  • сервер находится за NAT или имеет несколько публичных адресов: задайте Переопределение хоста ICE публичным IP-адресом (или именем хоста, которое разрешается в него);
  • NAT сопоставляет с 8443 другой публичный порт: также задайте Переопределение порта хоста ICE этим публичным портом;
  • сервер не имеет доступа в Интернет, или вы не хотите, чтобы сервер и клиенты обращались к внешнему STUN-серверу: задайте Переопределение хоста ICE и очистите список STUN с помощью AM_CALLS_ICE_SERVERS_CONFIGS=[]. Если задано Переопределение хоста ICE, сервер больше не запрашивает свой адрес у STUN-сервера; пустой список не дает клиентам делать то же самое.
services:
  antimatter:
    environment:
      AM_CALLS_ICE_HOST_OVERRIDE: 203.0.113.10
      AM_CALLS_ICE_SERVERS_CONFIGS: "[]"

Чтобы использовать STUN без сторонних служб, запустите собственный STUN-сервер (TURN-сервер, например coturn, тоже отвечает на STUN-запросы) и укажите его в Конфигурациях серверов ICE вместо стороннего, как в примере с TURN ниже.

В локальной сети используйте LAN-адрес сервера. После изменения портов, адресов или настроек ICE перезапустите сервер, либо отключите и снова включите приложение Calls: медиа-сервер настраивается при запуске приложения.

TURN для строгих файрволов

Некоторые сети блокируют как UDP, так и исходящие соединения на нестандартные TCP-порты. Пользователям таких сетей нужен сервер TURN, который передаёт медиаданные через порт, к которому у них есть доступ (часто 443). Antimatter не включает такой сервер в свой состав; запустите сервер TURN, например coturn, и добавьте его в ICE Servers Configurations — JSON-список:

[
  {"urls": ["stun:turn.example.com:3478"]},
  {"urls": ["turn:turn.example.com:3478?transport=udp", "turns:turn.example.com:443?transport=tcp"]}
]
  • При использовании общего секрета (параметр use-auth-secret в coturn) укажите тот же секрет в TURN Static Auth Secret (AM_CALLS_TURN_STATIC_AUTH_SECRET): сервер выдаёт каждому клиенту временные учётные данные, действительные в течение TURN Credentials Expiration (minutes) (по умолчанию 240 минут).
  • При использовании фиксированных учётных данных добавьте "username" и "credential" в запись TURN.
  • Server Side TURN (отключено по умолчанию) также использует серверы TURN для соединений, которые инициирует сервер.

Крупные серверы: внешний rtcd

По умолчанию один сервер Antimatter обрабатывает все медиаданные звонков. Для множества одновременных звонков или для разгрузки сервера чата от медиапотока приложение Calls может передавать медиаданные на rtcd — отдельный медиасервер (open-source rtcd от Mattermost, версия 0.17 или новее). Укажите RTCD service URL (AM_CALLS_RTCD_SERVICE_URL), например https://rtcd.example.com: тогда все звонки будут проходить через него, а клиенты будут отправлять свои медиаданные на собственный порт rtcd, а не на порт Antimatter. Учётные данные можно передать с помощью AM_CALLS_RTCD_CLIENT_ID и AM_CALLS_RTCD_AUTH_KEY; если они не заданы, приложение само зарегистрируется в rtcd. Лицензия не требуется. Приложение Calls показывает администраторам предупреждение с рекомендацией использовать rtcd, если на сервере одновременно в звонках находится более 50 человек.

Транскрипция и субтитры в реальном времени

Antimatter может транскрибировать звонки с помощью модели преобразования речи в текст, которую вы запускаете самостоятельно, и показывать субтитры в реальном времени, пока люди говорят. Antimatter поддерживает любой сервер, предоставляющий эндпоинт /v1/audio/transcriptions, совместимый с OpenAI, например сервер Whisper в вашей сети. Дополнительные сервисы от Antimatter не требуются.

Как это работает

  • Хост звонка запускает транскрипцию с помощью Транскрибировать звонок в элементах управления звонком. Бейдж Идёт транскрипция уведомляет всех участников.
  • Приложение каждого участника слушает его собственный микрофон, разбивает речь на короткие фрагменты (до 12 секунд, никогда во время заглушения) и отправляет их в Antimatter, который пересылает их на ваш сервер преобразования речи в текст.
  • Если включены субтитры в реальном времени, текст каждого фрагмента сразу отображается участникам в виде субтитра.
  • Когда транскрипция останавливается или звонок завершается, бот Calls публикует транскрипт в виде текстового файла и файла субтитров WebVTT в обсуждении звонка (в голосовых каналах — в канале).
  • Если включён параметр Summarize transcriptions, агент по умолчанию из приложения Agents также публикует краткое содержание в обсуждении (см. AI).

Настройка

Установите следующие параметры для сервиса antimatter:

services:
  antimatter:
    environment:
      AM_CALLS_ENABLE_TRANSCRIPTIONS: "true"
      AM_CALLS_TRANSCRIBE_API: openai
      AM_CALLS_TRANSCRIBE_API_OPEN_AIURL: http://stt.internal:8000/v1
      AM_CALLS_TRANSCRIBE_API_OPEN_AI_MODEL: whisper-1
      AM_CALLS_TRANSCRIBE_API_OPEN_AI_KEY: ""
      AM_CALLS_ENABLE_LIVE_CAPTIONS: "true"
      AM_CALLS_LIVE_CAPTIONS_LANGUAGE: en

В Системной консоли параметры транскрипции появляются только после включения Включить запись звонков, хотя для этого типа транскрипции запись не требуется. Настройка этих параметров с помощью переменных выше позволяет избежать этой проблемы. Не включайте запись одновременно с транскриптором openai: при начале записи будет предпринята попытка запустить транскриптор job-service, что приведет к ошибке.

Аудио всех, кто говорит во время включения транскрипции, передается на сервер распознавания речи, который вы настроили, а транскрипт публикуется там, где его могут прочитать все участники канала. Сообщите об этом пользователям и, если звонки конфиденциальны, размещайте этот сервер в собственной сети.

Запись

Запись звонков (а также транскрипция с помощью встроенных транскрипторов whisper.cpp или Azure) выполняется в отдельных контейнерах, запускаемых службой заданий — open-source-решением Mattermost calls-offloader, которое вы развертываете самостоятельно рядом с Antimatter. Параметры: Включить запись звонков (AM_CALLS_ENABLE_RECORDINGS, по умолчанию выключено), URL службы заданий (AM_CALLS_JOB_SERVICE_URL), Максимальная длительность записи звонка (по умолчанию 60 минут, от 15 до 180) и Качество записи звонка (низкое, среднее или высокое; по умолчанию среднее). Лицензия не требуется. Для только транскрипции и субтитров настройка распознавания речи, описанная выше, проще: она не требует службы заданий.
