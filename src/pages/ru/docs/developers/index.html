Способы расширения Antimatter

Выберите самый простой инструмент, который справится с задачей. Первые четыре не требуют доступа к самому серверу; приложения работают внутри него.

ИнструментНазначениеПодходит для
REST APIВсё, что делают приложения: сообщения, каналы, пользователи, файлы, параметры. WebSocket отправляет события по мере их возникновения.Скрипты, синхронизация с другими системами, собственные клиенты.
Входящие вебхукиСекретный URL, который публикует сообщение в канал, когда что-то отправляет ему JSON.Оповещения, результаты CI, мониторинг, уведомления из других инструментов.
Исходящие вебхукиAntimatter обращается к вашему URL, когда сообщение в публичном канале начинается с триггерного слова, и публикует ваш ответ.Простые автоматизации, управляемые из чата.
Команды с косой чертойПользователи вводят /something; Antimatter обращается к вашему URL и показывает ваш ответ им или в канал.Поиск информации, действия, инициированные из чата.
БотыАккаунты, созданные для программ, с собственными токенами, меткой БОТ, интерактивными сообщениями и диалогами.Ассистенты, средства оповещения, всё, что взаимодействует с людьми.
Приложения (плагин)Код, работающий внутри сервера (Go) и в веб-приложении (React): хуки на каждое сообщение, новые меню, панели, типы сообщений, страницы.Функции: опросы, заметки, календари, интеграции, требующие пользовательского интерфейса.

В интерфейсе пользователи называют плагины «приложениями». В этом руководстве используется формулировка «приложения (плагин)» там, где оба термина уместны, поскольку код, API и конфигурация по-прежнему используют слово «плагин».

Совместимость с Mattermost

Antimatter — форк Mattermost. То, что работает с сервером Mattermost, в большинстве случаев работает и с Antimatter.

Что совпадает

  • REST API по адресу /api/v4, его аутентификация, WebSocket и формат ошибок. Сервер сообщает версию 12.0.0, поэтому клиенты и приложения, проверяющие версию сервера, видят актуальную версию Mattermost.
  • Вебхуки и команды с косой чертой, включая их совместимые с Slack данные.
  • API и хуки серверных плагинов: Antimatter не вносила в них изменений. Серверный код компилируется с тем же Go-модулем github.com/mattermost/mattermost/server/public.
  • Реестр плагинов веб-приложения: все методы register… реестра Mattermost присутствуют в обоих веб-интерфейсах Antimatter.
  • Клиентские библиотеки: Go-клиент model.Client4 и TypeScript-клиент @mattermost/client (см. Клиентские библиотеки).
  • Сборки плагинов: файл .tar.gz с манифестом plugin.json. Устанавливаются плагины, подписанные ключом Mattermost, а также те, что подписаны ключом Antimatter.

Чем Antimatter отличается

  • Два веб-интерфейса. Новый интерфейс Fusion используется по умолчанию; классический интерфейс Mattermost по-прежнему доступен. Fusion отображает большинство компонентов плагинов, но размещает некоторые из них иначе и не поддерживает отдельные. Приложение может определить, какой интерфейс запущен. См. Поддержка интерфейса Fusion.
  • Дополнительный API. Antimatter добавляет конечные точки для собственных функций: атрибуты сообществ, тайм-ауты, сообщения сверху, запросы сообщений, переопределения каналов и категорий, экспорт каналов и новые поля сообществ. См. Что Antimatter добавляет в API.
  • Дополнительные возможности сообщений. Вложения к сообщениям могут отображать этапы конвейера и небольшую диаграмму; сообщения могут быть встроенными ответами или спойлерами.
  • Дополнительные хуки веб-приложения для приложений: пункт меню «+» в поле ввода, вкладки в пикере эмодзи, панель в представлении канала, нижняя часть под каналами в боковой панели и запись на страницах интеграций. См. Хуки, доступные только в Antimatter.
  • Отсутствие лицензий. Все функции доступны без лицензионного ключа. Конечные точки для лицензий, пробных периодов и корпоративных обновлений удалены; GET /api/v4/license/client сохранён для клиентов, которые его запрашивают. Некоторые приложения, созданные для платных версий Mattermost, сами проверяют наличие лицензии и отказываются работать.
  • Названия. В интерфейсе команды называются сообществами, но в API и коде по-прежнему используется термин team. Переменные окружения используют префикс AM_, инструмент командной строки называется amctl, а исполняемый файл сервера — antimatter.

Где находится код

Всё открытое программное обеспечение находится в организации AntimatterChat на GitHub. Каждый репозиторий работает на ветке main.

Перед началом

  • Получите тестовый сервер. Самый быстрый способ — образ Docker: см. Установка Antimatter. Чтобы работать с самим Antimatter, см. Сборка из исходного кода.
  • Проверьте, что разрешает сервер. Некоторые функции интеграции отключены по умолчанию и требуют прав системного администратора: персональные токены доступа, аккаунты ботов, переопределение имени пользователя и значка, а также загрузка приложений. На каждой странице указано, какой параметр для этого нужен.
  • Знайте URL вашего сайта. В примерах используется https://chat.example.com. Замените его на адрес вашего сервера.

В этом руководстве

  • REST API: аутентификация, основные ресурсы, постраничная навигация, ошибки, лимиты частоты запросов, WebSocket, клиентские библиотеки и расширения Antimatter.
  • Вебхуки: входящие и исходящие вебхуки, полезные нагрузки, вложения и карточки.
  • Команды с косой чертой: пользовательские команды, их запросы и ответы, автодополнение.
  • Боты и интерактивные сообщения: аккаунты ботов, кнопки, меню и диалоги.
  • Создание приложений: структура плагина, серверные хуки, реестр веб-приложений, Fusion, параметры, хранилище, переводы и упаковка.
  • Сборка из исходного кода: сервер, веб-интерфейсы, образ Docker и приложения.
  • Вклад в проект: проблемы, pull request'ы, стиль, переводы, безопасность и лицензии.
Вопросы приветствуются в обсуждениях сообщества. Сообщайте об ошибках в проблемах сообщества.
