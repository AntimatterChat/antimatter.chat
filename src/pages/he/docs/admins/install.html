התקנה באמצעות Docker Compose

זוהי הדרך המומלצת. קובץ compose אחד מריץ את Antimatter, PostgreSQL, אחסון הקבצים ושירות ה-GIF. נדרש שרת Linux עם Docker Engine ותוסף Compose שלו (docker compose), 2 ליבות CPU ו-4 GB זיכרון לפחות.

1. הורדת קובץ ה-compose

mkdir antimatter && cd antimatter
curl -fsSLO https://antimatter.chat/compose.yaml

2. יצירת קובץ .env

קובץ ה-compose קורא את ההגדרות מקובץ .env באותו תיקייה. יש ליצור אותו עם סיסמאות אקראיות:

cat > .env <<EOF
SITE_URL=http://localhost:8065
POSTGRES_PASSWORD=$(openssl rand -hex 24)
S3_SECRET_KEY=$(openssl rand -hex 24)
GIFS_API_KEY=$(openssl rand -hex 24)
EOF
chmod 600 .env

יש להגדיר את SITE_URL לכתובת שישקלו המשתמשים להקליד בדפדפן, למשל http://192.168.1.20:8065 ברשת מקומית או https://chat.example.com עם דומיין. יש לשמור את קובץ ה-.env: בסיס הנתונים והאחסון משתמשים בסיסמאות האלה מההרצה הראשונה, ואת אותו קובץ יש להשתמש בו לשחזור גיבוי.

3. הרצה

docker compose up -d
docker compose ps

ההרצה הראשונה נמשכת דקה או שתיים: PostgreSQL יוצר את בסיס הנתונים, שירות חד-פעמי בשם bucket יוצר את מיכל האחסון, שירות חד-פעמי בשם gifs-stickers יבוא את חבילת המדבקות הראשונית, ו-Antimatter יוצר את הטבלאות. ניתן לעקוב אחרי התהליך עם docker compose logs -f antimatter.

כדי להשתמש בשם דומיין וב-HTTPS מההתחלה, ראו דומיין ו-HTTPS: עם קובץ ה-compose מדובר בשני שורות נוספות ב-.env ובפרופיל https.

PostgreSQL, האחסון ושירות GIF נמצאים ברשת פנימית (private) ללא גישה לאינטרנט, אליה מצטרף רק Antimatter. אף אחד מהם לא מפרסם פורט.

מיכל Antimatter אינו שומר כלום על הדיסק: ההגדרות שלו נמצאות במסד הנתונים (AM_CONFIG מצביע אליו) והקבצים והאפליקציות שלו נמצאים בשירות האחסון. ניתן להסיר ולעצב מחדש את המיכל בכל עת. כל מה שצריך לגיבוי נמצא בנפחים postgres, files ו-gifs, בנוסף לקובץ .env שלך.

בחירת תמונה

פורסמו שתי תמונות Antimatter, שתיהן עבור linux/amd64 ו-linux/arm64, ושתיהן נבנו מהענף main של כל אחסון:

תמונהאפליקציות מובנותתגיות
ghcr.io/antimatterchat/antimatterסוכנים, שיחות, GitHub, GitLab, Jira, Kanban, מדדים ו-Playbooks.latest, X.Y.Z לגרסאות, sha-<commit>
ghcr.io/antimatterchat/antimatter-nextאותו דבר, בתוספת ערוצי קול, סקרים, דוא"ל, לוח שנה, פתקים, לוח לבן, GIF, משימות וממס. נבנה מחדש כל לילה.latest, nightly, nightly-<YYYYMMDD>, sha-<commit>

קובץ compose של האתר משתמש ב-antimatter-next, משום ששירות GIF ורוב האפליקציות המתוארות באתר נמצאות רק בתמונה זו. כדי לשנות תמונה, הגדירו ANTIMATTER_IMAGE ב-.env והריצו docker compose up -d.

latest משתנה מתחת לרגליים. בייצור, צמדו תגית כמו nightly-20261015 או sha-<commit>, ושינו אותה בכוונה בעת שדרוג. השרת שודרג את מסד הנתונים שלו בעת ההתחלה, כך שאי אפשר לחזור לתמונה ישנה, או מ-antimatter-next ל-antimatter, בלי לשחזר גיבוי שנלקח לפני כן. ראו גיבויים ושדרוגים.

בתוך התמונה

  • השרת נמצא ב-/antimatter, עם הקבצים antimatter ו-amctl ב-/antimatter/bin (ב-PATH).
  • הוא רץ כמשתמש לא-מורשה antimatter (uid 2000) על בסיס distroless מינימלי, ללא shell.
  • פורטים: 8065 (אתר ו-API), 8067 (מדדים), 8074 (קלאסטר), 8443 UDP ו-TCP (שיחות).
  • מצב מקומי (ServiceSettings.EnableLocalMode) מופעל, ולכן amctl --local פועל בתוך המיכל. בדיקת הבריאות מריצה את amctl system status --local.
  • האפליקציות המצורפות נמצאות ב-/antimatter/prepackaged_plugins, חתומות עם מפתח החתימה של אפליקציות Antimatter.
  • כלי חילוץ טקסט (pdftotext, wvText, unrtf, tidy) כלולים, כך שאפשר לחפש בתוכן המסמכים שהועלו.

קבצי compose נוספים

מאגר ה-antimatter-docker כולל הגדרה לייצור ב-deploy/compose/: nginx עם תעודות משלך או Let's Encrypt (certbot), PostgreSQL, שירות ה-GIF האופציונלי (פרופיל gifs) ונפחי שם (named volumes) להגדרות, נתונים ויומנים של השרת, כמתואר ב-README שלו. ברירת המחדל היא להשתמש בתמונה היציבה ולשמור קבצים בנפח מקומי במקום באחסון S3. השתמשו בו אם מעדיפים nginx על פני Caddy, או אם כבר יש לכם תעודות.

יצירת המנהל הראשון

פתחו את SITE_URL בדפדפן וצרו חשבון. החשבון הראשון שנוצר על שרת חדש הופך למנהל המערכת, ואז ההגדרה מלווה אתכם ביצירת הקהילה הראשונה (השם שנתנה Antimatter לצוות או למרחב עבודה).

עשו זאת מיד אחרי ההפעלה הראשונה: עד אז, כל מי שמגיע לשרת ראשון הופך למנהל שלו. כדי ליצור את החשבון משורת הפקודה במקום, לפני שהשרת נגיש מבחוץ:

docker compose exec antimatter amctl --local user create --system-admin --email-verified \
    --email admin@example.com --username admin --password 'a-long-password'
docker compose exec antimatter amctl --local team create --name main --display-name "Main"
docker compose exec antimatter amctl --local team users add main admin

לאחר מכן, התחברו ב-SITE_URL. התחילו את הפקודה עם רווח כדי שהסיסמה לא תישאר בהיסטוריית ה-shell (עם HISTCONTROL=ignorespace), או שנו את הסיסמה אחרי ההתחברות.

שלבים הבאים אחרי שהתחברתם:

  1. החליטו谁能 יצור חשבונות: התחברות וחשבונות.
  2. הגדירו דוא"ל, כדי שהזמנות ואפסות סיסמאות יעבדו: דוא"ל והתראות דחיפה.
  3. פתחו את פורט השיחות ב-firewall: שיחות וקול.
  4. בדקו אילו אפליקציות מופעלות: אפליקציות מצורפות.

התקנה מקובץ שחרור

ללא Docker, השרת רץ מתוך ארכיון בשם antimatter-<os>-<arch>.tar.gz (לדוגמה antimatter-linux-amd64.tar.gz). הארכיון מכיל תיקייה אחת בשם antimatter/ המכילה את bin/antimatter, bin/amctl, config/config.json, אפליקציות ה-Web (client/ ו-client-fusion/), תבניות המייל והתרגומים.

1. הכנת PostgreSQL

Antimatter תומך רק ב-PostgreSQL, גרסה 15 או חדש יותר (גרסאות ישנות יותר יתחילו, אך יופיע שגיאה ביומן). צרו משתמש ומסד נתונים:

sudo -u postgres psql <<'EOF'
CREATE USER antimatter WITH PASSWORD 'a-long-password';
CREATE DATABASE antimatter OWNER antimatter;
EOF

2. חילוץ והגדרה

sudo tar -xzf antimatter-linux-amd64.tar.gz -C /opt
sudo useradd --system --user-group antimatter
sudo mkdir -p /opt/antimatter/data
sudo chown -R antimatter:antimatter /opt/antimatter

כוונו את השרת אל מסד הנתונים, הן ב-/opt/antimatter/config/config.json (SqlSettings.DataSource) והן באמצעות משתני סביבה, והגדירו את כתובת האתר:

AM_SQLSETTINGS_DRIVERNAME=postgres
AM_SQLSETTINGS_DATASOURCE=postgres://antimatter:a-long-password@localhost:5432/antimatter?sslmode=disable&connect_timeout=10
AM_SERVICESETTINGS_SITEURL=https://chat.example.com

קובע ה-config.json בארכיון הוא הגדרת ברירת מחדל מלאה: הגדרות ששונות בקונסולת מערכת נשמרות שוב אליו. כדי לשמור את ההגדרות במסד הנתונים במקום, ראו הגדרות.

3. הרצה כשירות

יחידת systemd, ב-/etc/systemd/system/antimatter.service:

[Unit]
Description=Antimatter
After=network.target postgresql.service

[Service]
Type=notify
User=antimatter
Group=antimatter
WorkingDirectory=/opt/antimatter
ExecStart=/opt/antimatter/bin/antimatter
EnvironmentFile=-/etc/antimatter.env
TimeoutStartSec=3600
Restart=always
RestartSec=10
LimitNOFILE=49152

[Install]
WantedBy=multi-user.target

הניחו את משתני AM_ שלכם ב-/etc/antimatter.env (קריא על ידי root בלבד), ואז:

sudo systemctl daemon-reload
sudo systemctl enable --now antimatter
journalctl -u antimatter -f

השרת מאזין על פורט 8065. פתחו http://<server>:8065, או את הדומיין שלכם לאחר שפרוקסי הפוך מוכן (ראו דומיין ו-HTTPS), וצרו את החשבון הראשון: הוא יהפוך למנהל המערכת.

bin/amctl מנהל את השרת הפעיל משורת הפקודה. על השרת עצמו, הוא פועל ללא התחברות דרך מצב מקומי: הגדירו AM_SERVICESETTINGS_ENABLELOCALMODE=true, ואז הרצו sudo -u antimatter /opt/antimatter/bin/amctl --local system status.

פקודות שרת נוספות

מעבר להרצת השרת (antimatter, או antimatter server), לקובץ הבינארי יש מספר פקודות תחזוקה. הן קוראות את אותה הגדרה כמו השרת.

פקודהמה היא עושה
antimatter versionמציג את הגרסה, מספר הבנייה, תאריך הבנייה וה-hash של הבנייה.
antimatter db pingבדוק שהמסד הנתונים נגיש.
antimatter db initיוצר את ההגדרות במסד הנתונים (עם AM_CONFIG מוגדר לכתובת postgres://).
antimatter db migrateמחיל את המהגרות (migrations) של מסד הנתונים ללא הרצת השרת.
antimatter db versionמציג את המהגרת האחרונה שנוספה למסד הנתונים.
antimatter import bulk, antimatter export bulkיבוא או ייצוא נתונים בפורמט המוני (ראו גיוס גיבויים ושדרוגים).
