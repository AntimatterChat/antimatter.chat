Βασικά

  • Βασική διεύθυνση URL: https://chat.example.com/api/v4. Όλα τα τελικά σημεία (endpoints) που ακολουθούν είναι σχετικά με αυτήν.
  • Μορφή: JSON στην είσοδο και στην έξοδο, εκτός από τα ανέβασματα αρχείων (multipart). Στείλτε Content-Type: application/json.
  • Αναγνωριστικά (IDs): κάθε αντικείμενο έχει ένα id 26 χαρακτήρων. Οι χρόνοι είναι σε χιλιοστά του δευτερολέπτου από την εποχή Unix (create_at, update_at, delete_at· 0 σημαίνει «δεν έχει διαγραφεί»).
  • Οι κοινότητες είναι ομάδες: το API τα αποκαλεί teams, με team_id.
  • Εσάς: όπου μια διαδρομή απαιτεί user_id, το me σημαίνει τον συνδεδεμένο χρήστη, όπως στο GET /users/me.

Η πλήρης λίστα των endpoints βρίσκεται στον κώδικα του server: οι διαδρομές δηλώνονται στο server/channels/api4/*.go και οι τύποι στο server/public/model. Η περιγραφή OpenAPI στον φάκελο api/v4/source του αποθετηρίου καλύπτει τα endpoints που κληρονομούνται από το Mattermost, καθώς και ορισμένες προσθήκες του Antimatter: μετακίνηση νημάτων, συνδέσεις μοντέλων και ενέργειες μηνυμάτων. Τα υπόλοιπα υπάρχουν μόνο στον κώδικα.

Ελέγχος ταυτότητας

Κάθε αίτημα, εκτός από την σύνδεση και μερικά δημόσια τελικά σημεία, απαιτεί διακριτικό (token) στο πεδίο Authorization:

curl -H "Authorization: Bearer $TOKEN" https://chat.example.com/api/v4/users/me

Δεχόμαστε τρεις τύπους διακριτικών: προσωπικά διακριτικά πρόσβασης, διακριτικά συνεδρίας και διακριτικά πρόσβασης OAuth. Δεχόμαστε επίσης τη μορφή Authorization: Token …. Τα διακριτικά στην συμβολοσειρά ερωτήματος (?access_token=) δέχονται μόνο για διακριτικά πρόσβασης OAuth.

Προσωπικά διακριτικά πρόσβασης (συμβουλεύονται για σενάρια)

Ένα προσωπικό διακριτικό πρόσβασης δρα ως εσείς, δεν λήγει εκτός αν του ορίσετε ημερομηνία λήξης, και μπορεί να ανακληθεί ανά πάσα στιγμή. Τα προσωπικά διακριτικά πρόσβασης είναι απενεργοποιημένα από προεπιλογή:

  1. Ένας διαχειριστής συστήματος ενεργοποιεί την επιλογή Ενεργοποίηση προσωπικών διαπιστευτηρίων πρόσβασης στη Κονσόλα συστήματος › Ολοκληρώσεις › Διαχείριση ολοκληρώσεων (ServiceSettings.EnableUserAccessTokens, AM_SERVICESETTINGS_ENABLEUSERACCESSTOKENS).
  2. Για κάθε χρήστη που μπορεί να δημιουργήσει tokens, ένας διαχειριστής συστήματος ανοίγει το Κονσόλα συστήματος › Διαχείριση χρηστών › Χρήστες, επιλέγει Διαχείριση ρόλων από το μενού του χρήστη και επιλέγει Επιτρέπεται σε αυτόν τον λογαριασμό να δημιουργεί tokens πρόσβασης. Οι διαχειριστές συστήματος μπορούν πάντα να δημιουργούν tokens.
  3. Ο χρήστης ανοίγει το avatar του στην πάνω δεξιά γωνία και στη συνέχεια πηγαίνει στις Ρυθμίσεις προφίλ › Ασφάλεια. Κάτω από Προσωπικά Tokens Πρόσβασης, περιγράφει τη χρήση του token και επιλέγει Δημιουργία token. Το token εμφανίζεται μία φορά: αντιγράψτε το.

Μέσω της API: POST /users/{user_id}/tokens με {"description": "backup script", "expires_at": 0} (expires_at σε χιλιοστά του δευτερολέπτου· 0 για κανένα). Το πεδίο token στην απάντηση είναι το μυστικό· το id χρησιμοποιείται για την ακύρωσή του (POST /users/tokens/revoke με {"token_id": "…"}). Από τη γραμμή εντολών: amctl token generate <user> <description>.

Ένας διαχειριστής συστήματος μπορεί να ορίσει ένα όριο στη διάρκεια ζωής των tokens χρησιμοποιώντας την επιλογή Μέγιστη διάρκεια ζωής προσωπικού token πρόσβασης (ημέρες) στη σελίδα της Κονσόλας συστήματος.

Tokens συνεδρίας

Η σύνδεση με κωδικό επιστρέφει ένα token συνεδρίας στο πεδίο Token της κεφαλίδας της απάντησης, του ίδιου τύπου με τις συνεδρίες που χρησιμοποιούν οι εφαρμογές:

curl -i -X POST https://chat.example.com/api/v4/users/login \
  -H 'Content-Type: application/json' \
  -d '{"login_id": "maya", "password": "…"}'

Προσθέστε "token": "123456" για λογαριασμούς με πολυπαραγοντική ελέγχου. Οι συνεδρίες λήγουν σύμφωνα με τις ρυθμίσεις συνεδρίας του server, και το endpoint σύνδεσης έχει περιορισμό ρυθμού (5 αιτήματα ανά δευτερόλεπτο). Το POST /users/logout τερματίζει τη συνεδρία.

Οι περιηγητές ελέγχουν την ταυτότητα με cookie. Ένα αίτημα που ελέγχεται με cookie πρέπει επίσης να στέλνει την κεφαλίδα X-CSRF-Token για οτιδήποτε εκτός από GET· ένα token στην κεφαλίδα Authorization δεν χρειάζεται κεφαλίδα CSRF.

Εφαρμογές OAuth 2.0

Για να επιτρέψετε στους χρήστες να συνδέονται στην εφαρμογή σας με τον λογαριασμό Antimatter, καταχωρίστε μια εφαρμογή OAuth 2.0. Το Antimatter γίνεται τότε πάροχος OAuth:

  1. Η επιλογή Ενεργοποίηση παρόχου υπηρεσιών OAuth 2.0 πρέπει να είναι ενεργοποιημένη (Κονσόλα συστήματος › Ολοκληρώσεις › Διαχείριση ολοκληρώσεων, ServiceSettings.EnableOAuthServiceProvider, ενεργοποιημένη από προεπιλογή).
  2. Κάποιος με τα κατάλληλα δικαιώματα διαχείρισης εφαρμογών OAuth (από προεπιλογή, οι διαχειριστές συστήματος) ανοίγει το avatar του και στη συνέχεια πηγαίνει στις Ολοκληρώσεις › Εφαρμογές OAuth 2.0, προσθέτοντας την εφαρμογή με τις URL callback. Λαμβάνει ένα client ID και ένα client secret.
  3. Η εφαρμογή σας στέλνει τους χρήστες στο https://chat.example.com/oauth/authorize με response_type=code, client_id, redirect_uri και state. Υποστηρίζεται PKCE με code_challenge_method=S256.
  4. Εκτελεί την ανταλλαγή του κωδικού στο POST https://chat.example.com/oauth/access_token (grant_type=authorization_code, και στη συνέχεια refresh_token για ανανέωση) και καλεί το API με Authorization: Bearer <access token>.

Οι χρήστες βλέπουν τις εφαρμογές που έχουν εξουσιοδοτήσει στο Προφίλ & ρυθμίσεις › Ασφάλεια › Εφαρμογές που εξουσιοδοτήσατε.

Δημοσίευση μηνύματος

curl -X POST https://chat.example.com/api/v4/posts \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"channel_id": "'$CHANNEL_ID'", "message": "Backup finished: **42 GB** in 3 min"}'

Τα μηνύματα είναι σε Markdown. Προσθέστε "root_id" (την πρώτη δημοσίευση ενός νήματος) για να απαντήσετε σε ένα νήμα, "file_ids" για αρχεία και "props" για συνημμένα και άλλα πρόσθετα (βλ. Συνημμένα).

Εύρεση του αναγνωριστικού (ID) ενός καναλιού

curl -H "Authorization: Bearer $TOKEN" \
  https://chat.example.com/api/v4/teams/name/lumen-labs/channels/name/ops-alerts

Οι ονομασίες είναι αυτές που βρίσκονται στο σύνδεσμο του καναλιού: /lumen-labs/channels/ops-alerts.

Σελιδοποίηση

Τα τελικά σημεία που επιστρέφουν λίστες δέχονται page (από 0) και per_page (60 από προεπιλογή, έως 200). Συνεχίστε να ζητάτε την επόμενη σελίδα μέχρι να επιστραφεί μια σελίδα με λιγότερα στοιχεία από το per_page.

Τα μηνύματα ενός καναλιού (GET /channels/{channel_id}/posts) δέχονται επίσης since (χρονική στιγμή: όλα όσα άλλαξαν από τότε) ή before και after (ID μηνύματος). Επιστρέφονται ως λίστα μηνυμάτων: {"order": [IDs, newest first], "posts": {ID: post}, "next_post_id", "prev_post_id"}.

Σφάλματα

Τα σφάλματα χρησιμοποιούν τους συνηθισμένους κωδικούς κατάστασης HTTP (400 λανθασμένη είσοδος, 401 χωρίς σύνδεση, 403 μη επιτρεπόμενο, 404 μη βρεθέν, 501 λειτουργία απενεργοποιημένη) και ένα JSON σώμα:

{
  "id": "api.context.permissions.app_error",
  "message": "You do not have the appropriate permissions.",
  "detailed_error": "",
  "request_id": "jz8zm5nunpbt8f3gpqsz5dq6so",
  "status_code": 403
}

Χρησιμοποιήστε id στον κώδικά σας: το message μεταφράζεται στη γλώσσα του χρήστη. Το detailed_error είναι κενό εκτός αν ο διακομιστής εκτελεί σε λειτουργία προγραμματιστή (ServiceSettings.EnableDeveloper). Αναφέρετε το request_id στον διαχειριστή του διακομιστή: βρίσκεται στα αρχεία καταγραφής.

Περιορισμοί ρυθμού

Ο περιορισμός ρυθμού είναι απενεργοποιημένος από προεπιλογή. Όταν ένας διαχειριστής συστήματος τον ενεργοποιεί (Κονσόλα συστήματος › Περιβάλλον › Περιορισμός ρυθμού), κάθε client λαμβάνει 10 αιτήματα ανά δευτερόλεπτο με bursts των 100 από προεπιλογή, μετρώντας ανά διεύθυνση IP ή ανά χρήστη. Οι απαντήσεις περιέχουν τα X-RateLimit-Limit, X-RateLimit-Remaining και X-RateLimit-Reset. Αν ξεπεραστεί το όριο, ο server απαντά με 429 και ένα header Retry-After σε δευτερόλεπτα. Ορισμένα endpoints, όπως η σύνδεση, έχουν το δικό τους όριο ανεξάρτητα από τις ρυθμίσεις.

Γράψτε σενάρια που περιμένουν και επαναλαμβάνουν σε 429, και αποφύγετε την ερωτηματική αναζήτηση: ακολουθήστε το WebSocket.

Η ροή γεγονότων WebSocket

Συνδεθείτε στο wss://chat.example.com/api/v4/websocket. Επαληθεύστε είτε με την κεφαλίδα Authorization: Bearer στο αίτημα σύνδεσης, είτε στέλνοντας αυτό ως πρώτο μήνυμα:

{"seq": 1, "action": "authentication_challenge", "data": {"token": "…"}}

Ο διακομιστής στέλνει ένα γεγονός hello, και στη συνέχεια ένα γεγονός για όλα όσα έχετε άδεια να δείτε:

{
  "event": "posted",
  "data": {"channel_id": "…", "channel_type": "O", "post": "{\"id\":\"…\",\"message\":\"Hello\",…}"},
  "broadcast": {"channel_id": "…", "team_id": "", "user_id": "", "omit_users": null},
  "seq": 4
}

Σημειώστε ότι το data.post είναι το μήνυμα ως JSON string. Συνηθισμένα γεγονότα: posted, post_edited, post_deleted, reaction_added, reaction_removed, typing, status_change, user_added, direct_added. Οι εφαρμογές στέλνουν τα δικά τους γεγονότα, με ονομασία custom_<app id>_<event>.

Μπορείτε επίσης να στέλνετε ενέργειες, καθεμία με αυξανόμενο seq: user_typing με {"channel_id", "parent_id"}, ή get_statuses. Επανασυνδεθείτε όταν η σύνδεση χαθεί, και ανακτήστε ό,τι χάσατε με since (βλ. Σελιδοποίηση).

Το Antimatter προσθέτει τα εξής συμβάντα: community_attributes_updated, member_timeouts_updated, post_put_on_top, post_removed_from_top, server_categories_updated, channel_overrides_updated και category_overrides_updated.

Βιβλιοθήκες πελάτη

  • Go: model.Client4 στο server/public/model (import github.com/mattermost/mattermost/server/public/model). model.NewAPIv4Client(url), στη συνέχεια client.SetToken(token). Το model.NewWebSocketClient4(wsURL, token) παρακολουθεί τα συμβάντα. Η έκδοση του Antimatter προσθέτει μεθόδους για τα δικά του endpoints, όπως UpdateMessageRequest, PutPostOnTop και ExportChannel.
  • TypeScript: η κλάση Client4 του @mattermost/client, στο webapp/platform/client, με τους τύπους της στο webapp/platform/types. Το αντίγραφο στο αποθετήριο του Antimatter περιλαμβάνει τα τελεία του Antimatter· το πακέτο που δημοσιεύεται στο npm από το Mattermost δεν τα περιλαμβάνει.
package main

import (
	"context"
	"log"

	"github.com/mattermost/mattermost/server/public/model"
)

func main() {
	client := model.NewAPIv4Client("https://chat.example.com")
	client.SetToken("…")
	post, _, err := client.CreatePost(context.Background(), &model.Post{
		ChannelId: "…",
		Message:   "Hello from Go",
	})
	if err != nil {
		log.Fatal(err)
	}
	log.Println("posted", post.Id)
}

Νέα πεδία

  • Κοινότητες (Team, και PUT /teams/{team_id}/patch): all_channels_membership (όλοι βρίσκονται σε κάθε κανάλι που μπορούν να δουν), default_channel_id (ο προορισμός των νέων χρηστών· κενό σημαίνει Γενικό), kind (community ή workplace: σε ένα workplace, οι διαχειριστές καναλιών μπορούν να αρχειοθετήσουν και τα δικά τους κανάλια· οι νέες κοινότητες λαμβάνουν το TeamSettings.DefaultCommunityKind του server, προεπιλεγμένα community), member_list_view (πώς ομαδοποιείται η λίστα μελών: choice, η προεπιλογή, επιτρέπει σε κάθε μέλος να επιλέγει· roles ή teams το καθορίζουν), hide_role_colors, require_team_badges, onboarding και autolinks (και τα δύο JSON strings).
  • Το προεπιλεγμένο κανάλι μιας νέας κοινότητας είναι general (Γενικό), όχι town-square. Η αναβάθμιση 0.9.0 μετονομάζει το town-square κάθε κοινότητας σε general, διατηρώντας το ID, εκτός αν η κοινότητα έχει ήδη ένα κανάλι general. Τα παλιά ονόματα συνεχίζουν να λειτουργούν: GET /teams/{team_id}/channels/name/town-square, GET /teams/name/{team}/channels/name/town-square και το channel ενός εισερχόμενου webhook επιστρέφουν το προεπιλεγμένο κανάλι της κοινότητας όταν κανένα κανάλι δεν φέρει αυτό το όνομα. Χρησιμοποιήστε default_channel_id ή το όνομα general σε νέον κώδικα.
  • Σύνδεσμοι καναλιών: ο σύνδεσμος #channel-name συνδέει ένα κανάλι, όπως και ο ~channel-name. Η ιδιότητα channel_mentions της αναρτησης καταγράφει τα κανάλια που συνδέονται με τον έναν ή τον άλλο τρόπο. Ένα #word που δεν αντιστοιχεί σε κανένα κανάλι παραμένει hashtag. Η διαδικτυακή διεπαφή και η κινητή εφαρμογή του Antimatter γράφουν #name.
  • Τα Αρχειοθετημένα κανάλια αποδέχονται ακόμα νέα μέλη (POST /channels/{channel_id}/members), τα οποία μπορούν να διαβάσουν το ιστορικό τους. Κανείς δεν μπορεί να αναρτήσει, να αντιδράσει, να καρφιτσωθεί, να τοποθετήσει μήνυμα στην κορυφή, να μετονομάσει το κανάλι ή να αλλάξει τους ρόλους των μελών του εκεί.
  • Ενσωματωμένες απαντήσεις: μια ανάρτηση με "props": {"reply_to": "<post id>"} παραθέτει το μήνυμα του ίδιου καναλιού. Προσθέστε "reply_to_mention": false για να μην ειδοποιηθεί ο δημιουργός του. Ο διακομιστής γεμίζει το metadata.reply_to με μια σύντομη περιγραφή του παρατιθέμενου μηνύματος.
  • Σποίλερ: "props": {"spoiler": true} κρύβει το κείμενο και τα αρχεία μιας αναρτησης μέχρι ο αναγνώστης να επιλέξει να τα δει.
  • Αγνόηση και αποκλεισμός είναι προτιμήσεις: κατηγορία user_block, με το όνομα του ID του άλλου ατόμου, και τιμή ignore ή block. Αν ένα άμεσο μήνυμα περιμένει ως αίτημα, αυτό καθορίζεται στο notify_props.dm_request του μέλους του καναλιού σας (pending, accepted ή dismissed).
  • Συνημμένα μηνυμάτων μπορούν να φέρουν stages και chart: δείτε Κάρτες.

Μετακίνηση νήματος

Η POST /posts/{post_id}/move_to_channel μετακινεί ένα νήμα, το πρώτο του μήνυμα και όλες τις απαντήσεις του, σε άλλο κανάλι της ίδιας κοινότητας. Το post_id μπορεί να είναι το πρώτο μήνυμα ή οποιαδήποτε απάντηση.

curl -X POST https://chat.example.com/api/v4/posts/$POST_ID/move_to_channel \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"channel_id": "'$TARGET_CHANNEL_ID'", "flatten": false}'
  • channel_id (υποχρεωτικό): το κανάλι στο οποίο μετακινείται το νήμα.
  • flatten (προεπιλογή false): αν είναι true, οι απαντήσεις γίνονται απλά μηνύματα του προοριστικού καναλιού αντί για νήμα. Η λειτουργία Make it a channel του Fusion χρησιμοποιεί αυτή την παράμετρο.

Τα μηνύματα διατηρούν τους συγγραφείς, τις ώρες, τις αντιδράσεις και τα αρχεία τους. Τα αντίγραφα φέρουν την ιδιότητα silent_notification, οπότε δεν ειδοποιούν κανέναν. Τα αρχικά μηνύματα διαγράφονται. Η απάντηση είναι το μετακινημένο πρώτο μήνυμα, με το νέο του ID.

Ποιος μπορεί να μετακινήσει ένα νήμα

  • Πρέπει να μπορείτε να διαβάσετε το νήμα και να αναρτήσετε στο προοριστικό κανάλι.
  • Οι διαχειριστές του καναλιού, οι διαχειριστές της κοινότητας, οι χρήστες με Διαχείριση μηνυμάτων (delete_others_posts) στο κανάλι και οι συστημικοί διαχειριστές μπορούν να μετακινήσουν οποιοδήποτε νήμα.
  • Ο δημιουργός του νήματος μπορεί να το μετακινήσει όταν και τα δύο κανάλια είναι δημόσια, ή όταν όλα τα μηνύματα του νήματος είναι δικά του. Αλλιώς, η απάντηση είναι 403 με το ID api.post.move_thread.private_needs_moderator.app_error.
  • Και τα δύο κανάλια πρέπει να ανήκουν στην ίδια κοινότητα (δεν επιτρέπονται άμεσα ή ομαδικά μηνύματα), να είναι διαφορετικά και να μην είναι αρχειοθετημένα. Τα συστημικά μηνύματα και τα μηνύματα που διαγράφονται μετά την ανάγνωση δεν μπορούν να μετακινηθούν.
  • Ένα νήμα με μήκος μεγαλύτερο από WranglerSettings.MoveThreadMaxCount μηνύματα (100 από προεπιλογή; 0 για απεριόριστο) απορρίπτεται.

Ο δείκτης και η σημείωση

Η μετακίνηση αφήνει δύο συστημικά μηνύματα τύπου system_wrangler: έναν δείκτη στο παλιό κανάλι («Ένα νήμα με 13 μηνύματα μετακινήθηκε στο #target») και μια σημείωση στον προορισμό («Αυτό το νήμα μετακινήθηκε από το #source»), κάτω από το μετακινούμενο νήμα ή, με flatten, μετά τα μηνύματά του. Πέρα από το κείμενο του μηνύματος, οι ιδιότητές τους επιτρέπουν σε έναν πελάτη να αποτυπώνει το όνομα του καναλιού ως σύνδεσμο:

  • Ο δείκτης: MovedThreadPermalink, NumMessages, MovedThreadChannelId, MovedThreadTeamName, MovedThreadPostId και, για δημόσιο προορισμό, MovedThreadChannelName και MovedThreadChannelDisplayName.
  • Η σημείωση: MovedFromChannelId, MovedFromTeamName, MovedFromPostId (ο δείκτης), MovedFromPermalink και, για δημόσια πηγή, MovedFromChannelName και MovedFromChannelDisplayName.

Και τα δύο έχουν επίσης TranslationID. Το όνομα ενός ιδιωτικού καναλιού παραλείπεται: οι αναγνώστες βλέπουν «άλλο κανάλι». Η δική του POST /posts/{post_id}/move του Mattermost παραμένει απενεργοποιημένη στο Antimatter; χρησιμοποιήστε αυτό το endpoint.

Συνδέσεις μοντέλων

Μια σύνδεση μοντέλου είναι η διεύθυνση και το κλειδί ενός παρόχου Τέχνης, που ρυθμίζεται από έναν διαχειριστή. Οι λειτουργίες Τέχνης του διακομιστή και οι εφαρμογές που καλούν την υπηρεσία Τέχνης τις χρησιμοποιούν. Οι συστημικοί διαχειριστές διαχειρίζονται τις συνδέσεις σε επίπεδο διακομιστή (manage_ai_connections); οι διαχειριστές μιας κοινότητας διαχειρίζονται τις δικές τους (manage_team_ai_connections). Τα κλειδιά είναι μόνο για εγγραφή: καμία απάντηση δεν περιέχει ένα, μόνο api_key_set και api_key_last4.

ΤέλοςΛειτουργία
GET /ai/connections?scope=Οι συνδέσεις που διαχειρίζεστε. Το scope είναι server ή το ID μιας κοινότητας; χωρίς αυτό, κάθε πεδίο που διαχειρίζεστε.
POST /ai/connectionsΠροσθέτει μια σύνδεση (απαντά 201).
POST /ai/connections/test, POST /ai/connections/modelsΔοκιμάζει μια σύνδεση ή ελέγχει τα μοντέλα της, πριν αποθηκευτεί. Ίδιο σώμα με την προσθήκη; τίποτα δεν αποθηκεύεται.
GET, PATCH (ή PUT), DELETE /ai/connections/{connection_id}Αναγνέωση, αλλαγή ή διαγραφή μιας σύνδεσης. Ένα patch περιέχει μόνο τα πεδία που αλλάζουν; παραλείψτε το api_key για να διατηρήσετε το κλειδί.
POST /ai/connections/{connection_id}/testΔοκιμάζει μια αποθηκευμένη σύνδεση: {"ok", "error", "status_code", "latency_ms", "model_count"}.
GET /ai/connections/{connection_id}/modelsΤα μοντέλα που προσφέρει ο πάροχος.
GET /ai/connections/{connection_id}/usageΤα αιτήματα και τα tokens του τρέχοντος μήνα.
GET /ai/connections/usable?channel_id=&team_id=Για όποιον έχει συνδεθεί: οι συνδέσεις που μπορείτε να χρησιμοποιήσετε εκεί, με τα μοντέλα και τις δυνατότητές τους, ποτέ όμως όχι τα κλειδιά ή τις διευθύνσεις τους.

Το σώμα μιας νέας σύνδεσης:

{
  "name": "Local models",
  "scope": "server",
  "provider": "openai_compatible",
  "base_url": "http://llm.internal:8000/v1",
  "api_key": "…",
  "extra_headers": {},
  "models": {"chat": "qwen3-32b", "embeddings": "", "transcription": "", "decisions": ""},
  "limits": {"requests_per_minute": 0, "monthly_token_budget": 0, "per_user_requests_per_minute": 0, "per_user_monthly_token_budget": 0},
  "sharing": {"all_teams": true, "team_ids": []},
  "audience": {"everyone": true, "group_ids": [], "roles": [], "allow_guests": false}
}

provider είναι openai_compatible ή anthropic. Το scope είναι προεπιλεγμένο σε server· το ID μιας κοινότητας το καθιστά τη σύνδεση αυτής της κοινότητας. Στα limits, το 0 σημαίνει χωρίς όριο· τα αιτήματα ανά λεπτό μετρούνται σε κάθε server, ενώ τα προγράμματα tokens ανά ημερολογιακό μήνα (UTC) για ολόκληρο το cluster. Το sharing καθορίζει ποιες κοινότητες μπορούν να χρησιμοποιήσουν μια σύνδεση σε επίπεδο server (για άμεσα και ομαδικά μηνύματα απαιτείται all_teams), και το audience ποιοι μπορούν να την χρησιμοποιήσουν· επισκέπτες μόνο με allow_guests. Οι αλλαγές καταγράφονται στο αρχείο ελέγχου. Ο οδηγός διαχείρισης εξηγεί τις ρυθμίσεις: δείτε AI.
