Descărcați aplicația

Versiunile aplicației desktop se găsesc pe GitHub, la github.com/AntimatterChat/desktop-app/releases. La fel ca serverul, aplicația este în beta: o versiune ale cărei numere de versiune au un sufix după un cratimă este marcată cu Pre-release. Fiecare versiune are un fișier SHA256SUMS cu suma de control a fiecărui fișier. Verificați o descărcare cu sha256sum --check --ignore-missing SHA256SUMS pe Linux sau comparați ieșirea comenzii Get-FileHash <file> -Algorithm SHA256 în PowerShell cu linia corespunzătoare din SHA256SUMS.

  • Windows (x64 și arm64): instalatorul .exe, pachetul .msi sau un arhivă .zip. De exemplu, antimatter-desktop-<version>-win-x64.exe și antimatter-desktop-<version>-win-x64.msi.
  • macOS: o imagine de disc .dmg sau un arhivă .zip, pentru Apple silicon (arm64), Mac-uri Intel (x64) sau pentru ambele (universal).
  • Linux (x64 și arm64): un pachet .deb sau .rpm, un AppImage, un bundle Flatpak sau un arhivă .tar.gz.

Ce instalator Windows să folosiți

Instalatorul .exePachetul .msi
PentruPersoanele care instalează aplicația singureCompaniile care o desfac pe calculatoarele lor

ActualizăriAplicația verifică versiunile noi și oferă descărcarea noului .exe, care actualizează copia instalată pe locAplicația nu verifică versiunile noi: le desfaceți dumneavoastră

Aplicația verifică versiunile noi pe GitHub, în fiecare oră cât rulează, și vede doar versiunile finale, nu preversiunile. Când găsește una, îi anunță utilizatorul și îi oferă un link pentru descărcare. O copie instalată cu MSI nu verifică implicit, deoarece utilizatorii ei de obicei nu pot instala software. Puteți activa verificările pentru ea cu setarea EnableAutoUpdater: descărcarea oferită este atunci noul .msi, care necesită drepturi de administrator.

Folosiți MSI pentru o implementare gestionată cu SCCM (Configuration Manager), Intune sau instalarea de software prin Group Policy. Instalarea MSI elimină copia .exe a contului care rulează instalarea, dacă există.

Setările pe care le puteți gestiona

Aceleași setări există pe toate sistemele. Pe Windows sunt valori de registru sub SOFTWARE\Policies\Antimatter, în HKEY_LOCAL_MACHINE (pentru computer) sau HKEY_CURRENT_USER (pentru un singur utilizator). Pe macOS și Linux sunt chei ale preferințelor gestionate sau ale fișierului de politică.

SetarePe WindowsPe macOS și LinuxCe face
DefaultServerListO subcheie cu o valoare de șir per server: numele valorii este numele tabului, iar datele sunt URL-ul acestuiaUn array de dicționare (obiecte pe Linux) cu name și urlAdaugă servere în aplicație. Utilizatorii nu le pot edita sau elimina.
DefaultUsernameUn șirUn șirCompletează numele de utilizator pe pagina de autentificare a acestor servere.
EnableServerManagementUn DWORD, 0 sau 1Un boolean0 sau false: utilizatorii pot folosi doar serverele setate prin DefaultServerList, iar aplicația ascunde opțiunile de adăugare, editare și eliminare a serverelor. Neconfigurat: utilizatorii își pot adăuga propriile servere.
EnableAutoUpdaterUn DWORD, 0 sau 1Un boolean0 sau false: aplicația nu verifică niciodată versiunile noi și ascunde Check for Updates. 1 sau true: verifică, chiar dacă este instalată cu MSI. Neconfigurat: copia .exe verifică, copia MSI nu.
TrustedEmbeddedMediaOriginsO subcheie cu valori de șir, fiecare un obiect JSON cu serverOrigin și embeddedOriginUn array de dicționare cu serverOrigin și embeddedOriginPermite conținutul încorporat în paginile unui server, cum ar fi o pagină de convorbire video, să folosească permisiunile de cameră și microfon acordate acelui server.
  • Numele de utilizator este completat doar pe pagina de autentificare a serverelor definite prin politică, niciodată pe un server adăugat manual de o persoană și niciodată peste ce a tastat cineva. Persoanele își pot schimba totuși numele de utilizator. Variabilele de mediu dintre semnele de procent sunt înlocuite, astfel încât o singură valoare se potrivește tuturor: %USERNAME% pe Windows sau %USER% pe macOS și Linux oferă numele contului, iar %USERNAME%@example.com o adresă de e-mail care urmează acest model. Dacă o variabilă nu este definită, aplicația nu completează nimic.
  • Dacă dezactivați gestionarea serverelor, configurați cel puțin un server în DefaultServerList.
  • Pe Windows, o politică de calculator (HKEY_LOCAL_MACHINE) are prioritate față de o politică de utilizator (HKEY_CURRENT_USER). Listele de servere ale ambelor sunt combinate.
  • Aplicația citește setările la pornire: după o modificare, persoanele trebuie să o închidă și să o redeschidă.

Windows: instalare silențioasă cu MSI

MSI acceptă proprietăți publice care scriu setările ca politici de calculator, în HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Antimatter. Folosiți-le într-o aplicație SCCM, într-o aplicație Intune sau într-un script. În PowerShell:

msiexec /i antimatter-desktop-<version>-win-x64.msi /qn SERVERURL=https://chat.example.com SERVERNAME=Chat DEFAULTUSERNAME='%USERNAME%' AUTOUPDATE=0 SERVERMANAGEMENT=0
ProprietateScrieDacă nu este furnizată
SERVERURLUn server în DefaultServerList, cu acest URLNiciun server
SERVERNAMENumele tabului acelui serverAntimatter
DEFAULTUSERNAMEDefaultUsernameNimic
AUTOUPDATEEnableAutoUpdater, 0 sau 1Nimic: copia MSI nu verifică actualizările
SERVERMANAGEMENTEnableServerManagement, 0 sau 1Nimic: persoanele pot adăuga servere
  • O proprietate care nu este furnizată nu scrie nimic, deci nu suprascrie o valoare setată prin Group Policy. AUTOUPDATE și SERVERMANAGEMENT acceptă doar 0 sau 1. MSI configurează un singur server: folosiți Group Policy pentru mai multe.
  • DEFAULTUSERNAME trebuie să ajungă la instalator ca textul %USERNAME%, astfel încât aplicația să îl înlocuiască pentru fiecare persoană. În caz contrar, shell-ul care rulează instalarea îl înlocuiește cu numele contului propriu. În PowerShell, păstrați ghilimelele simple. Într-un fișier .bat, scrieți %%USERNAME%%. După o instalare de test, verificați în registru că DefaultUsername conține %USERNAME%.
  • Transmiteți proprietățile din nou la fiecare actualizare. Instalarea unei noi versiuni a MSI elimină pe cea veche, împreună cu valorile pe care le-a scris, apoi scrie valorile din noua linie de comandă. SCCM și Intune păstrează linia de comandă a unei aplicații: reutilizați-o pentru fiecare versiune nouă. Sau configurați politicile cu Group Policy sau Intune, care nu sunt afectate de actualizări.
  • MSI și Group Policy scriu aceleași valori de registru. Pentru fiecare setare, folosiți una sau cealaltă: dezinstalarea MSI-ului șterge valorile pe care le-a scris, chiar dacă Group Policy le-a setat și ele.
  • MSI înregistrează, de asemenea, folderul de instalare în HKEY_LOCAL_MACHINE\SOFTWARE\Antimatter\Desktop (InstallDir). Astfel, aplicația știe că a fost instalată cu MSI.

Pentru a dezinstala: msiexec /x antimatter-desktop-<version>-win-x64.msi /qn. În Intune, tipul „Windows app (Win32)” acceptă aceleași linii de comandă. Pentru tipul „Line-of-business app”, adăugați proprietățile la argumentele liniei de comandă.

Windows: Group Policy și Intune

Șabloanele administrative, antimatter.admx și en-US\antimatter.adml, se află în folderul gpo al aplicației instalate (C:\Program Files\Antimatter\gpo pentru MSI) și în folderul resources/windows/gpo din depozitul aplicației. Acestea afișează următoarele politici, sub Administrative Templates › Antimatter:

PoliticaValoare de registruConfigurație

Nume de utilizator de precompletat (DefaultUsername)DefaultUsernamecalculator și utilizator

Origini de media încorporate de încredere (TrustedEmbeddedMediaOrigins)subcheia TrustedEmbeddedMediaOriginscalculator și utilizator

Group Policy într-un domeniu

  1. Copiați antimatter.admx în stocul central, \\<domain>\SYSVOL\<domain>\Policies\PolicyDefinitions, și antimatter.adml în folderul său en-US.
  2. În Editorul de gestionare a Group Policy, deschideți Computer Configuration (sau User Configuration) › Policies › Administrative Templates › Antimatter.
  3. Editați o politică, alegeți Activat și completați-o. Pentru Servere, faceți clic pe Arată și adăugați o linie per server: numele valorii este numele tabului, iar valoarea este URL-ul serverului, de exemplu https://chat.example.com.

Activarea Permite adăugarea și eliminarea serverelor sau Notifică despre versiunile noi scrie 1; dezactivarea scrie 0.

Intune

În Dispozitive › Configurare, folosiți Import ADMX pentru a importa antimatter.admx împreună cu en-US\antimatter.adml. Apoi, creați un profil din Șabloane › Șabloane administrative importate și configurați politicile Antimatter în acesta.

Un singur computer, sau un script

Copiați șabloanele în C:\Windows\PolicyDefinitions pentru a le folosi în gpedit.msc (Windows Pro și Enterprise). Sau scrieți direct valorile de registru, cu un fișier .reg importat ca administrator (reg import antimatter-policies.reg), cum ar fi acesta. Fișierul example-policies.reg din același folder conține aceste valori, cu comentarii.

REGEDIT4

[HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Antimatter]
"EnableServerManagement"=dword:00000000
"EnableAutoUpdater"=dword:00000000
"DefaultUsername"="%USERNAME%"

[HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Antimatter\DefaultServerList]
"Chat"="https://chat.example.com"

macOS: un profil de configurare

Pe macOS, aplicația își citește setările din preferințele gestionate ale identificatorului de bundle, chat.antimatter.desktop, cu cheile din tabelul de setări. Distribuiți-le prin MDM-ul dvs. (Jamf, Intune, Kandji, Mosyle și altele) ca profil de configurare.

  • Folderul resources/mac/mdm din depozitul aplicației conține un profil de exemplu, antimatter.mobileconfig. Modificați valorile sale, atribuiți-i propriile valori PayloadIdentifier și PayloadUUID (uuidgen generează UUID-uri noi) și încărcați-l ca profil personalizat.
  • Majoritatea MDM-urilor acceptă și doar cheile, ca sarcină de „setări personalizate” sau „domeniu de preferințe” pentru chat.antimatter.desktop. Aceleași chei se găsesc în example-managed-preferences.plist din același folder.

Setările din sarcina profilului:

<key>PayloadType</key>
<string>chat.antimatter.desktop</string>
<key>DefaultServerList</key>
<array>
    <dict>
        <key>name</key>
        <string>Chat</string>
        <key>url</key>
        <string>https://chat.example.com</string>
    </dict>
</array>
<key>DefaultUsername</key>
<string>%USER%</string>
<key>EnableServerManagement</key>
<false/>
<key>EnableAutoUpdater</key>
<false/>

Valorile boolene pot fi date și ca întreguri 0 și 1.

Linux: fișierul de politici

Pe Linux, aplicația citește /etc/antimatter-desktop/policies.json, un obiect JSON cu cheile din tabelul de setări:

{
    "DefaultServerList": [
        {"name": "Chat", "url": "https://chat.example.com"}
    ],
    "DefaultUsername": "%USER%",
    "EnableServerManagement": false,
    "EnableAutoUpdater": false,
    "TrustedEmbeddedMediaOrigins": []
}

Distribuiți-l cu instrumentul dvs. de gestionare a configurației (Ansible, Puppet, Salt și altele), deținut de root, lizibil de toți și scriabil doar de root:

sudo install -d /etc/antimatter-desktop
sudo install -m 644 policies.json /etc/antimatter-desktop/policies.json

Un fișier care nu este JSON valid este ignorat, cu un avertisment în jurnalul aplicației. Versiunea Flatpak nu vede /etc al gazdei: acordați-i acces în lectură, și va citi fișierul din /run/host/etc/antimatter-desktop/policies.json:

sudo flatpak override --system --filesystem=host-etc:ro chat.antimatter.desktop

Politici configurate pentru aplicația desktop Mattermost

Pe Windows, aplicația citește și politicile configurate pentru aplicația desktop Mattermost, sub SOFTWARE\Policies\Mattermost, ca alternativă. Le citește după locație: valorile direct sub cheia de politică, subcheia DefaultServerList și subcheia TrustedEmbeddedMediaOrigins. Pentru fiecare dintre aceste trei locații, citește cheia Mattermost doar atunci când cheia Antimatter nu are valori acolo, în niciunul dintre registre. Astfel, odată ce o valoare este configurată direct sub cheia Antimatter, de exemplu prin proprietatea AUTOUPDATE a MSI, niciuna dintre valorile direct sub cheia Mattermost nu este citită. Mută toate politicile sub cheia Antimatter într-un singur pas.

Pe macOS, preferințele gestionate ale aplicației desktop Mattermost (com.mattermost.desktop) nu sunt citite: configurează-le pentru chat.antimatter.desktop.

Construcții nesemnate

Construcțiile aplicației desktop nu sunt încă semnate cu un certificat de editor.

  • Windows. Când o persoană deschide un .exe sau .msi descărcat, Microsoft Defender SmartScreen indică faptul că Windows a protejat calculatorul și menționează un editor necunoscut. Persoana alege Mai multe informații, apoi Rulează oricum. SmartScreen verifică fișierele pe care persoanele le deschid după o descărcare, astfel încât utilizatorii nu văd acest avertisment când aplicația este distribuită prin SCCM, Intune sau Group Policy. Dacă calculatoarele tale rulează doar software de la editori aprobați (reguli AppLocker sau App Control for Business), permite aplicația prin calea de instalare sau prin hash-ul fișierului.
  • macOS. Aplicația este semnată ad hoc, dar nu este notată de Apple. Prima dată când o persoană deschide o copie descărcată, macOS indică faptul că nu poate verifica dacă aplicația este liberă de malware și nu o deschide. Pe macOS 15 și versiunile ulterioare, persoana deschide System Settings › Privacy & Security și alege Open Anyway. Pe versiunile anterioare, face clic cu tasta Control pe aplicație și alege Open. Gatekeeper verifică doar fișierele marcate ca descărcate (cu atributul de carantină): când instalezi aplicația cu propriile instrumente, elimină marcajul în scriptul de instalare, cu xattr -dr com.apple.quarantine /Applications/Antimatter.app.
