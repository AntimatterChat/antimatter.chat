Cum funcționează o aplicație

  • Partea de server este un program Go. Serverul îl pornește ca un proces separat și comunică cu el prin RPC: apelează hook-urile aplicației (un mesaj este pe cale să fie publicat, o comandă a fost executată…) și aplicația apelează API-ul de plugin al serverului (creare de postări, citire de utilizatori, stocare de date…). Poate, de asemenea, servi rute HTTP sub /plugins/<app id>/.
  • Partea de aplicație web este un pachet JavaScript încărcat în browser împreună cu aplicația web. Înregistrează componente și callback-uri React în registrul: un buton într-un meniu, un panou, o metodă de a desena un tip de mesaj.
  • Orice parte este opțională. O aplicație este instalată ca un pachet .tar.gz, iar administratorii de sistem o activează, dezactivează și o configurează.
Partea de server rulează cu acces complet la datele serverului. Tratează o aplicație ca pe un cod pe care îl implementezi pe server.

Antimatter rulează aplicațiile scrise pentru Mattermost și invers, atâta timp cât o aplicație folosește doar hook-uri pe care le au ambele. Vezi Hook-uri doar în Antimatter.

Structura pachetului

Nu există un șablon de pornire separat: pornește de la o aplicație mică inclusă, cum ar fi antimatter-plugin-polls sau antimatter-plugin-todo, și modifică ID-ul și codul acesteia. Polls este structurat astfel:

antimatter-plugin-polls/
├── plugin.json            the manifest
├── Makefile               build, test, bundle, deploy
├── build/                 the manifest and pluginctl helper tools (Go), setup.mk
├── assets/icon.svg        files shipped with the bundle
├── go.mod
├── server/
│   ├── main.go            plugin.ClientMain(&Plugin{})
│   ├── plugin.go          the Plugin type, OnActivate, ServeHTTP
│   ├── manifest.go        generated from plugin.json
│   ├── api.go, command.go, hooks.go, store.go …
│   └── dist/              compiled binaries, one per platform
└── webapp/
    ├── package.json, webpack.config.js, tsconfig.json
    ├── i18n/              en.json and one file per language
    ├── src/index.tsx      registers the app with the web app
    ├── src/manifest.ts    generated from plugin.json
    ├── src/translations.ts
    └── dist/main.js       the bundle

Opțional: un folder public/, servit direct la /plugins/<app id>/public/.

plugin.json

{
  "id": "com.example.weather",
  "name": "Weather",
  "description": "Forecasts in the chat.",
  "homepage_url": "https://github.com/example/weather",

  "min_server_version": "12.0.0",
  "server": {
    "executables": {
      "linux-amd64": "server/dist/plugin-linux-amd64",
      "linux-arm64": "server/dist/plugin-linux-arm64",
      "darwin-amd64": "server/dist/plugin-darwin-amd64",
      "darwin-arm64": "server/dist/plugin-darwin-arm64",
      "windows-amd64": "server/dist/plugin-windows-amd64.exe"
    }
  },
  "webapp": {"bundle_path": "webapp/dist/main.js"},
  "settings_schema": {"settings": []}
}
  • id: unic și permanent; un nume de domeniu invers este uzual. Numește rutele, setările stocate și evenimentele WebSocket.
  • version: versiune semantică. Aplicațiile incluse lasă acest câmp din plugin.json; instrumentul de compilare îl preia din ultima etichetă git v*.
  • min_server_version: Antimatter raportează 12.0.0.
  • settings_schema: pagina de setări a aplicației în Consola de sistem (a se vedea Setări).

make apply copiază manifestul în server/manifest.go și webapp/src/manifest.ts; make manifest-check îl validează.

Partea de server

Partea de server importă același modul Go ca aplicațiile Mattermost, github.com/mattermost/mattermost/server/public, din proxiful de module Go. Funcția sa main doar pornește aplicația:

package main

import "github.com/mattermost/mattermost/server/public/plugin"

func main() {
	plugin.ClientMain(&Plugin{})
}

Tipul Plugin încorporează plugin.MattermostPlugin, ceea ce îi oferă p.API, și implementează hook-urile de care are nevoie:

type Plugin struct {
	plugin.MattermostPlugin
	router *mux.Router
}

func (p *Plugin) OnActivate() error {
	p.router = p.newRouter()
	return p.API.RegisterCommand(&model.Command{
		Trigger:          "weather",
		AutoComplete:     true,
		AutoCompleteDesc: "Show the forecast",
		AutoCompleteHint: "[city]",
	})
}

func (p *Plugin) ExecuteCommand(c *plugin.Context, args *model.CommandArgs) (*model.CommandResponse, *model.AppError) {
	city := strings.TrimSpace(strings.TrimPrefix(args.Command, "/weather"))
	return &model.CommandResponse{
		ResponseType: model.CommandResponseTypeEphemeral,
		Text:         "Forecast for " + city + ": sunny",
	}, nil
}

func (p *Plugin) ServeHTTP(c *plugin.Context, w http.ResponseWriter, r *http.Request) {
	p.router.ServeHTTP(w, r)
}

Hook-uri comune

HookCând se execută
OnActivate, OnDeactivateCând aplicația este activată sau dezactivată, și când serverul pornește și se oprește. Înregistrarea comenzilor și a bot-urilor se face în OnActivate.
OnConfigurationChangeCând setările se modifică; se încarcă cu p.API.LoadPluginConfiguration(&cfg).
ServeHTTPCereri către /plugins/<app id>/…. Serverul setează antetul Mattermost-User-Id când cererea vine de la un utilizator autentificat; refuzați cererile fără acest antet, cu excepția celor destinate publicului.
ExecuteCommandO comandă înregistrată de aplicație a fost executată.
MessageWillBePosted, MessageWillBeUpdatedÎnainte ca un mesaj să fie salvat: returnați un post modificat sau un motiv pentru respingerea sa.
MessageHasBeenPosted, MessageHasBeenUpdated, MessageHasBeenDeletedA posteriori, pentru efecte secundare.
ReactionHasBeenAdded, ReactionHasBeenRemovedReacții.
UserHasJoinedChannel, UserHasLeftChannel, UserHasJoinedTeam, UserHasLeftTeam, ChannelHasBeenCreatedModificări de apartenență și de canal. O echipă este o comunitate.
FileWillBeUploadedÎnainte ca un fișier să fie stocat: modificați-l sau respingeți-l.
OnPluginClusterEventUn mesaj de la aceeași aplicație de pe un alt server dintr-un cluster.

Lista completă, cu semnăturile exacte, se găsește în server/public/plugin/hooks.go; API-ul este în server/public/plugin/api.go. Pachetul pluginapi (server/public/pluginapi) împachetează API-ul în helper-e mai prietenoase.

Apeluri utile la API

  • CreatePost, UpdatePost, SendEphemeralPost: publicare în numele bot-ului aplicației sau în numele unui utilizator.
  • EnsureBotUser(&model.Bot{Username, DisplayName}): creează bot-ul aplicației o singură dată și obține ID-ul acestuia.
  • PublishWebSocketEvent("poll_updated", payload, &model.WebsocketBroadcast{ChannelId: id}): trimite un eveniment către aplicația web. Acesta sosește ca custom_<app id>_poll_updated.
  • OpenInteractiveDialog: deschide un dialog.
  • LogInfo, LogError și altele: scrie în jurnalul serverului, etichetat cu ID-ul aplicației.
  • GetUser, GetChannel, HasPermissionToChannel: verifică cine poate face ce înainte de a acționa în numele unui utilizator.

O aplicație rulează pe fiecare server din cluster. Păstrați starea în magazinul de perechi cheie-valoare sau în baza de date, nu doar în memorie.

Stocarea datelor

Fiecare aplicație are propriul magazin de perechi cheie-valoare în baza de date a serverului:

  • KVSet(key, value), KVGet(key), KVDelete(key): valorile sunt secvențe de octeți, de obicei JSON. Cheile au cel mult 150 de caractere.
  • KVSetWithExpiry(key, value, seconds): valoarea dispare după acest interval de timp.
  • KVCompareAndSet(key, old, new) și KVSetWithOptions cu Atomic: actualizări sigure atunci când mai multe cereri sau servere scriu aceeași cheie. Sondaj salvează fiecare vot în acest mod și reîncearcă în caz de conflict.
  • KVList(page, perPage): cheile, pagină cu pagină.

Partea de aplicație web

Pachetul înregistrează o clasă cu window.registerPlugin. Metoda sa initialize primește registrul și stocul Redux:

import manifest from './manifest';

class Plugin {
    initialize(registry, store) {
        registry.registerTranslations((locale) => translationsFor(locale));
        registry.registerPostTypeComponent('custom_poll', PollPost);
        registry.registerWebSocketEventHandler(`custom_${manifest.id}_poll_updated`, (msg) => {
            store.dispatch(pollUpdated(JSON.parse(msg.data.poll)));
        });
        registry.registerReconnectHandler(() => store.dispatch(reloadPolls()));
    }
}

window.registerPlugin(manifest.id, new Plugin());
  • Biblioteci partajate. Aplicația web oferă React, ReactDOM, Redux, React Redux și React Intl: enumerați-le ca externals în webpack (React, ReactDOM, Redux, ReactRedux, ReactIntl) în loc de a include copii proprii. Consultați webpack.config.js al Sondaj.
  • Apelarea părții de server. Folosiți Fetch pentru ${window.basename}/plugins/<app id>/… cu opțiunile din Client4.getOptions() (din mattermost-redux/client): acestea conțin anteturile de care serverul are nevoie pentru a accepta o cerere din browser.
  • Starea proprie. registerReducer adaugă un reducer, stocat sub state['plugins-<app id>'].
  • Tipuri. Metodele suplimentare ale registrului din Antimatter nu se află în tipurile publicate de Mattermost: Sondaj declară registrul pe care îl folosește în webapp/src/types/host.ts.

Metodele registrului și parametrii acestora sunt documentați în cod, în webapp/fusion/src/plugins/registry.ts (Fusion) și webapp/channels/src/plugins/registry.ts (clasic).

Suportul pentru interfața Fusion

Antimatter are două interfețe web: Fusion, cea implicită, și cea clasică. Ambele încarcă aceleași pachete de aplicații și au același registru, dar Fusion desenează multe elemente de sine și plasează componentele aplicațiilor în propriul mod. Testați aplicația în ambele.

Detectarea interfeței

Înainte de încărcarea oricărei aplicații, ambele interfețe setează window.antimatterWebUI la 'fusion' sau 'classic', și aceeași valoare pe elementul rădăcină al paginii, ca data-am-web-ui. În Mattermost, niciuna dintre ele nu este setată.

export function isFusionUI(): boolean {
    return window.antimatterWebUI === 'fusion' || document.documentElement.dataset.amWebUi === 'fusion';
}

Aplicațiile incluse folosesc acest lucru pentru a fi desenate diferit. Sondajele își desenează cardurile și dialogul de creare în stilul Fusion și își deschid propriul dialog pentru /poll în Fusion. Apelurile și canalele vocale omit componentele de bară laterală și toast pe care le înlocuiește Fusion cu propriul său interfață de apel. Aplicația Agenți își plasează acțiunile AI într-un submeniu al meniului mesaj, în loc de bara de instrumente la trecerea cu mouse-ul. Clasele CSS proprii ale Fusion (cu prefixul am-) și stratul său de dialog (elementul am-layer) sunt cele pe care aceste aplicații le folosesc pentru a se potrivi interfeței; ele nu constituie o API documentată și stabilă.

Ce nu afișează sau nu rulează Fusion

  • registerPostDropdownMenuComponent (un component din meniul mesajului), registerPostCardTypeComponent (un card al unui mesaj în panoul din dreapta) și registerProductSwitcherMenuItem nu sunt afișate în vederea principală a Fusion. Folosiți registerPostDropdownMenuAction în locul primului.
  • registerMessageWillBeUpdatedHook nu rulează când un mesaj este editat în Fusion. Verificați editările pe server cu hook-ul MessageWillBeUpdated în schimb.
  • registerActionAfterChannelCreation rulează doar din dialogul clasic de creare a canalului, pe care Fusion îl deschide din Mai multe opțiuni… în dialogul său Creează un canal.
  • Componentele barei de aplicații sunt afișate indiferent de supportedProductIds.
  • Rutele din registerNeedsTeamRoute și registerCustomRoute păstrează cadrul clasic al paginii, la fel ca produsele.

Hook-uri pe care le are doar Antimatter

Aceste metode de registru nu există în Mattermost. Verificați dacă o metodă există înainte de a o apela, astfel încât aplicația să funcționeze și acolo:

if (typeof registry.registerComposerMenuItem === 'function') {
    registry.registerComposerMenuItem({
        text: 'Create a poll',
        icon: <i className='icon icon-chart-bar'/>,
        fusionIcon: 'poll',
        action: ({channelId, rootId}) => openPollCreation(channelId, rootId),
    });
} else {
    registry.registerChannelHeaderButtonAction(icon, (channel) => openPollCreation(channel.id), 'Create a poll', 'Create a poll');
}
MetodăCe adaugă
registerComposerMenuItem({text, icon, fusionIcon, action, shouldRender})Un element din meniul + al casetei de mesaje, în ambele interfețe. action primește {channelId, rootId}.
registerEmojiPickerTab({id, label, icon, fusionIcon, order, component, shouldRender, replacesGifPicker})O filă a selectorului de emoji din caseta de mesaje, cum ar fi GIF-urile sau stickerele. În Fusion, fișele cu o valoare order mai mică de 10 apar înaintea filei Emoji. Componenta primește channelId, rootId, filter, onFilterChange, onSelectDone, insertText și isFusion.
registerChannelViewPanel({matcher, component})Un panou situat între antetul canalului și mesaje, destinat canalelor selectate de matcher(state, channel). Poate ascunde mesajele și compozitorul (setMessagesVisible), la fel cum fac canalele vocale.
registerSidebarChannelFooterComponent(component)O linie sub un canal din bara laterală, cum ar fi persoanele din apelul său. Primește channel.
registerIntegrationsOption({title, description, fusionIcon, action, shouldRender})Doar în Fusion: o intrare în paginile Integrări, lângă emoji-urile personalizate. Aplicația GIF adaugă acolo GIF-urile și stickerele sale personalizate.

fusionIcon numește o icoană din setul de iconițe al Fusion (de exemplu poll, sticker, calendar sau image; vezi webapp/fusion/src/fusion/components/icon). Fusion o afișează în locul icon, astfel încât elementul să fie coerent cu celelalte.

Setări

settings_schema din plugin.json descrie pagina aplicației în Consola de sistem › Plugin-uri:

"settings_schema": {
  "header": "Forecasts come from the weather service below.",
  "settings": [
    {"key": "ServiceURL", "display_name": "Service URL", "type": "text", "default": "https://api.example.com"},
    {"key": "Units", "display_name": "Units", "type": "dropdown", "default": "metric",
     "options": [{"display_name": "Celsius", "value": "metric"}, {"display_name": "Fahrenheit", "value": "imperial"}]},
    {"key": "EnableAlerts", "display_name": "Severe weather alerts", "type": "bool", "default": false,
     "help_text": "Post alerts in the channels that follow a city."}
  ]
}

Tipuri de setări: bool, text, longtext, number, dropdown, radio, generated (un secret aleatoriu), username și custom (desenată de o componentă înregistrată de partea de aplicație web prin registerAdminConsoleCustomSetting). Setările pot fi grupate în sections.

Partea de server le citește într-o structură ale cărei câmpuri corespund cheilor:

type configuration struct {
	ServiceURL   string
	Units        string
	EnableAlerts bool
}

func (p *Plugin) OnConfigurationChange() error {
	var cfg configuration
	if err := p.API.LoadPluginConfiguration(&cfg); err != nil {
		return err
	}
	p.setConfiguration(&cfg)
	return nil
}

Administratorii le pot configura și în configurație, sub PluginSettings.Plugins.<app id>, cu chei în litere mici (vezi ghidul pentru administratori).

Traduceri

Antimatter este tradusă în 37 de limbi, la fel și aplicațiile incluse. Partea de aplicație web face acest lucru astfel:

  1. Scrie fiecare șir de caractere cu React Intl, folosind un ID și textul în engleză: <FormattedMessage id='polls.create' defaultMessage='Create a poll'/> sau defineMessages. Prefixează ID-urile cu numele aplicației tale.
  2. Extrage șirurile în engleză în webapp/i18n/en.json (aplicațiile incluse folosesc formatjs extract).
  3. Adaugă un fișier pentru fiecare limbă lângă acesta, cu aceleași ID-uri: fr.json, de.json, pt-BR.json, zh-CN.json…
  4. Transmiteți-le aplicației web, care solicită limba utilizatorului: 
    import fr from '../i18n/fr.json';
import ptBR from '../i18n/pt-BR.json';

const catalogs = {fr, 'pt-BR': ptBR};

export function translationsFor(locale) {
    return catalogs[locale] || catalogs[locale.split('-')[0]] || {};
}

registry.registerTranslations(translationsFor);

Un șir lipsă revine la defaultMessage în limba engleză. Pentru șirurile trimise de partea de server (răspunsuri la comenzi, mesaje de bot), pachetul pluginapi/i18n încarcă fișierele de traducere incluse în bundle (de exemplu assets/i18n) și oferă un localizator în limba fiecărui utilizator.

Uneltele de construcție nu citesc încă un nume AM_ pentru URL-ul site-ului.

Instalați un bundle manual

  • Un administrator de sistem permite încărcările cu AM_PLUGINSETTINGS_ENABLEUPLOADS=true (dezactivat implicit; nu există un comutator în Consola de sistem).
  • Apoi Consola de sistem › Plugin-uri › Gestionare › Încărcați pluginul, sau amctl plugin add weather.tar.gz urmat de amctl plugin enable com.example.weather.
  • Dacă serverul are activată opțiunea Solicitați semnătură de plugin, acceptă doar bundle-uri semnate cu o cheie de care are încredere; consultați Instalarea altor aplicații.
Pentru iterații rapide pe un server de dezvoltare, setați AM_SERVICESETTINGS_ENABLEDEVELOPER=true pe server: erorile vor include apoi detaliile. Makefile-urile aplicațiilor incluse construiesc partea de server doar pentru platforma dvs. când MM_SERVICESETTINGS_ENABLEDEVELOPER este setat în shell-ul dvs.
