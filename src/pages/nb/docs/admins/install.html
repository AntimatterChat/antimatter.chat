Installer med Docker Compose

Dette er den anbefalte metoden. Én compose-fil kjører Antimatter, PostgreSQL, filopplagringen og GIF-tjenesten. Du trenger en Linux-server med Docker Engine og Compose-tillegget (docker compose), 2 CPU-kjerner og 4 GB minne eller mer.

1. Last ned compose-filen

mkdir antimatter && cd antimatter
curl -fsSLO https://antimatter.chat/compose.yaml

2. Opprett .env-filen

Compose-filen leser innstillingene sine fra en .env-fil i samme mappe. Opprett den med tilfeldige hemmeligheter:

cat > .env <<EOF
SITE_URL=http://localhost:8065
POSTGRES_PASSWORD=$(openssl rand -hex 24)
S3_SECRET_KEY=$(openssl rand -hex 24)
GIFS_API_KEY=$(openssl rand -hex 24)
EOF
chmod 600 .env

Sett SITE_URL til adressen folk skal skrive i nettleseren, for eksempel http://192.168.1.20:8065 på et lokalt nettverk eller https://chat.example.com med et domenenavn. Behold .env-filen: databasen og lagringen bruker disse passordene fra første start, og du trenger den samme filen for å gjenopprette en sikkerhetskopi.

3. Start det

docker compose up -d
docker compose ps

Første start tar ett til to minutter: PostgreSQL oppretter databasen, en engangs-bucket-tjeneste oppretter lagringsbeholderen, en engangs-gifs-stickers-tjeneste importerer startpakken med klistermerker, og Antimatter oppretter tabellene sine. Følg med på dette med docker compose logs -f antimatter.

For å bruke et domenenavn og HTTPS fra starten, se Domene og HTTPS: med compose-filen er det to linjer til i .env og https-profilen.

PostgreSQL, lagringen og GIF-tjenesten er på et internt nettverk (private) uten tilgang til internett, som bare Antimatter er med i. Ingen av dem publiserer en port.

Antimatter-beholderen lagrer ingenting på disken: innstillingene er i databasen (AM_CONFIG peker til den), og filene og appene er i lagringstjenesten. Du kan fjerne og opprette beholderen på nytt når som helst. Alt som skal sikkerhetskopieres, finnes i postgres, files og gifs-volumene, i tillegg til .env-filen din.

Velg et bilde

To Antimatter-bilder publiseres, begge for linux/amd64 og linux/arm64, og begge bygget fra main-greinen i alle repositorier:

BildeBundlete apperTags
ghcr.io/antimatterchat/antimatterAgenter, Samtaler, GitHub, GitLab, Jira, Kanban, Metrikker og Playbooks.latest, X.Y.Z for utgaver, sha-<commit>
ghcr.io/antimatterchat/antimatter-nextDet samme, pluss Talekanaler, Avstemninger, E-post, Kalender, Notater, Tavle, GIF-er, Gjøremål og Memes. Bygget på nytt hver natt.latest, nightly, nightly-<YYYYMMDD>, sha-<commit>

Nettsidens compose-fil bruker antimatter-next, fordi GIF-tjenesten og de fleste av appene som er beskrevet på denne nettsiden, kun finnes i det bildet. For å bytte bilde, angi ANTIMATTER_IMAGE i .env og kjør docker compose up -d.

latest endrer seg under deg. I produksjon, fest en tag som nightly-20261015 eller sha-<commit>, og endre den med hensikt når du oppgraderer. Serveren oppgraderer databasen sin når den starter, så du kan ikke gå tilbake til et eldre bilde, eller fra antimatter-next til antimatter, uten å gjenopprette en sikkerhetskopi tatt før. Se Sikkerhetskopier og oppgraderinger.

Inne i bildet

  • Serveren ligger i /antimatter, med binærfilene antimatter og amctl i /antimatter/bin (på PATH).
  • Den kjører som den uprivilegerte brukeren antimatter (uid 2000) på en minimal distroless-basis, uten skal.
  • Porter: 8065 (nett og API), 8067 (metrikker), 8074 (kluster), 8443 UDP og TCP (samtaler).
  • Lokal modus (ServiceSettings.EnableLocalMode) er slått på, så amctl --local fungerer inne i containeren. Helsekontrollen kjører amctl system status --local.
  • De medfølgende appene ligger i /antimatter/prepackaged_plugins og er signert med Antimatters app-signeringsnøkkel.
  • Verktøy for tekstuttrekk (pdftotext, wvText, unrtf, tidy) er inkludert, så innholdet i opplastede dokumenter kan søkes i.

Andre compose-filer

Lageret antimatter-docker har en produksjonsoppsett i deploy/compose/: nginx med dine egne sertifikater eller Let's Encrypt (certbot), PostgreSQL, den valgfrie GIF-tjenesten (profil gifs) og navngitte volumer for serverens konfigurasjon, data og logger, dokumentert i README-en. Den bruker standardbildeet som standard og lagrer filer på et lokalt volum i stedet for S3-lagring. Bruk den hvis du foretrekker nginx fremfor Caddy, eller allerede har sertifikater.

Opprett den første administratoren

Åpne SITE_URL i nettleseren din og opprett en konto. Den første kontoen som opprettes på en ny server blir systemadministratoren, og oppsettet veileder deg deretter gjennom opprettingen av din første fellesskap (Antimatters navn på et team eller arbeidsområde).

Gjør dette rett etter første oppstart: inntil da blir den som når serveren først, dens administrator. For å opprette kontoen fra kommandolinjen i stedet, før serveren er tilgjengelig fra utsiden:

docker compose exec antimatter amctl --local user create --system-admin --email-verified \
    --email admin@example.com --username admin --password 'a-long-password'
docker compose exec antimatter amctl --local team create --name main --display-name "Main"
docker compose exec antimatter amctl --local team users add main admin

Logg deretter inn på SITE_URL. Start kommandoen med et mellomrom for å holde passordet utenfor skallegjengen (med HISTCONTROL=ignorespace), eller endre passordet når du er logget inn.

Neste steg når du er inne:

  1. Bestem hvem som kan opprette kontoer: Innlogging og kontoer.
  2. Konfigurer e-post, slik at invitasjoner og passordresett fungerer: E-post og push-varsler.
  3. Åpne samtaleporten i brannmuren din: Samtaler og tale.
  4. Se hvilke apper som er slått på: Medfølgende apper.

Installer fra et utgavearkiv

Uten Docker kjører serveren fra et arkiv med navnet antimatter-<os>-<arch>.tar.gz (for eksempel antimatter-linux-amd64.tar.gz). Det inneholder én antimatter/-mappe med bin/antimatter, bin/amctl, config/config.json, nettappene (client/ og client-fusion/), e-postmalene og oversettelsene.

1. Forbered PostgreSQL

Antimatter støtter kun PostgreSQL, versjon 15 eller nyere (eldre versjoner starter, men gir en feil i loggen). Opprett en bruker og en database:

sudo -u postgres psql <<'EOF'
CREATE USER antimatter WITH PASSWORD 'a-long-password';
CREATE DATABASE antimatter OWNER antimatter;
EOF

2. Pakk ut og konfigurer

sudo tar -xzf antimatter-linux-amd64.tar.gz -C /opt
sudo useradd --system --user-group antimatter
sudo mkdir -p /opt/antimatter/data
sudo chown -R antimatter:antimatter /opt/antimatter

Pek serveren mot databasen, enten i /opt/antimatter/config/config.json (SqlSettings.DataSource) eller med miljøvariabler, og sett opp nettstedets URL:

AM_SQLSETTINGS_DRIVERNAME=postgres
AM_SQLSETTINGS_DATASOURCE=postgres://antimatter:a-long-password@localhost:5432/antimatter?sslmode=disable&connect_timeout=10
AM_SERVICESETTINGS_SITEURL=https://chat.example.com

Arkivets config.json er en komplett standardkonfigurasjon: innstillinger du endrer i Systemkonsollen lagres tilbake til den. Hvis du i stedet vil lagre konfigurasjonen i databasen, se Konfigurasjon.

3. Kjør som en tjeneste

En systemd-enhet, i /etc/systemd/system/antimatter.service:

[Unit]
Description=Antimatter
After=network.target postgresql.service

[Service]
Type=notify
User=antimatter
Group=antimatter
WorkingDirectory=/opt/antimatter
ExecStart=/opt/antimatter/bin/antimatter
EnvironmentFile=-/etc/antimatter.env
TimeoutStartSec=3600
Restart=always
RestartSec=10
LimitNOFILE=49152

[Install]
WantedBy=multi-user.target

Legg AM_-variablene dine i /etc/antimatter.env (kun lesbar for root), deretter:

sudo systemctl daemon-reload
sudo systemctl enable --now antimatter
journalctl -u antimatter -f

Serveren lytter på port 8065. Åpne http://<server>:8065, eller domenet ditt når en omvendt proxy er på plass (se Domena og HTTPS), og opprett den første kontoen: den blir systemadministrator.

bin/amctl administrerer den kjørende serveren fra kommandolinjen. På selve serveren fungerer den uten pålogging via lokal modus: sett AM_SERVICESETTINGS_ENABLELOCALMODE=true, deretter kjør sudo -u antimatter /opt/antimatter/bin/amctl --local system status.
