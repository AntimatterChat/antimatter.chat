Les applications intégrées

Les applications sont listées en tant que Plugins dans la Console système. Elles sont présentes dans l'image (dans /antimatter/prepackaged_plugins), signées avec la clé de signature des applications Antimatter, et s'installent donc sans connexion Internet.

Les applications activées par défaut sont installées à chaque démarrage si elles ne le sont pas encore, ou mises à niveau si l'image contient une version plus récente. Si vous désactivez une application, elle reste désactivée : la valeur par défaut ne s'applique qu'aux applications non encore mentionnées dans la configuration. Les applications qui conservent leur identifiant Mattermost (Agents, Appels, Kanban, Playbooks et les intégrations) sont des versions compilées par Antimatter.

Activer, désactiver et configurer les applications

Accédez à Console système › Plugins › Gestion des plugins. Sous Plugins installés, chaque application dispose des options Activer ou Désactiver, Paramètres et Retirer, et affiche son état (En cours d’exécution, Non démarré, Échec du démarrage…). Chaque application avec des paramètres possède également sa propre page sous Console système › Plugins.

Les applications intégrées désactivées par défaut sont installées à partir de la copie propre à l’image : ouvrez le Marché des applications depuis le menu du produit, trouvez l’application et cliquez sur Installer, puis activez-la dans la Gestion des plugins. Depuis la ligne de commande :

docker compose exec antimatter amctl --local plugin marketplace install github
docker compose exec antimatter amctl --local plugin enable github

Autres commandes : amctl plugin list, amctl plugin disable <id>, amctl plugin delete <id>.

Activer les applications via la configuration

Les applications activées sont définies par le paramètre PluginSettings.PluginStates, une carte d’identifiants d’applications. Vous pouvez fusionner des entrées avec amctl ; avec Activer les plugins automatiquement préemballés activé (par défaut), une application intégrée activée est installée au démarrage suivant :

docker compose exec -T antimatter amctl --local config patch /dev/stdin <<'EOF'
{"PluginSettings": {"PluginStates": {"com.mattermost.plugin-todo": {"Enable": true}}}}
EOF
docker compose restart antimatter

C'est aussi la méthode pour installer À faire, qui n'est pas proposée dans la boîte de dialogue du Marché d'applications. La variable AM_PLUGINSETTINGS_PLUGINSTATES fonctionne également, mais elle remplace la carte entière : listez toutes les applications que vous souhaitez activer.

Paramètres des applications

Les paramètres de l'application sont stockés sous PluginSettings.Plugins.<app id>, avec des clés en minuscules. Modifiez-les dans la page Console système de l'application, ou avec amctl config patch comme indiqué dans Configuration. AM_PLUGINSETTINGS_PLUGINS remplace les paramètres de toutes les applications d'un coup et les verrouille toutes, évitez donc de l'utiliser.

Le service conserve tout dans son répertoire de données (/data, le volume gifs) : un index de recherche et les médias. Ses principales variables :

Pour importer vos propres GIF en masse, utilisez un manifeste depuis un répertoire monté dans un conteneur éphémère :

docker compose run --rm -v "$PWD/my-gifs:/import:ro" gifs import -manifest /import/manifest.json

Pour réimporter les autocollants de démarrage après une mise à niveau : docker compose run --rm gifs stickers. Le format du manifeste et les autres commandes sont dans le README de gifs-server.

Courriel et Calendrier

Courriel et Calendrier relient chaque personne à sa propre boîte aux lettres (IMAP et SMTP) et à son propre calendrier (CalDAV). Les utilisateurs saisissent leur serveur et leur mot de passe dans l'application ; les mots de passe sont stockés de manière chiffrée. Vous ne configurez pas les serveurs de messagerie ou de calendrier pour eux, mais vous décidez à quoi ils peuvent se connecter :

ApplicationParamètreValeur par défautFonction
Courriel, CalendrierAutoriser les serveurs de messagerie sur les réseaux privés, Autoriser les serveurs de calendrier sur les réseaux privés (AllowPrivateNetworks)DésactivéDésactivé, le serveur refuse de se connecter aux adresses de boucle locale, privées et de lien local, de sorte que les applications ne peuvent pas être utilisées pour accéder à votre réseau interne. Activez cette option si votre serveur de messagerie ou de calendrier est sur une adresse privée.
Courriel, CalendrierAutoriser les connexions non chiffrées (AllowInsecureConnections)DésactivéDésactivé, les connexions doivent utiliser TLS (Courriel : TLS ou STARTTLS ; Calendrier : HTTPS).
CourrielIntervalle de vérification des messages non lus (minutes) (UnreadCheckMinutes)2 minutesFréquence à laquelle les compteurs de messages non lus sont vérifiés lorsque le serveur de messagerie ne peut pas les envoyer en temps réel.
CourrielTaille maximale des messages (Mo) (MaxMessageSizeMB)25 MoLimite de taille des messages envoyés et lus.
CalendrierEnvoyer des rappels (EnableReminders)activéLe bot Calendrier envoie un message personnel avant les événements (10 minutes avant, pour les événements sans alarme propre).

Pour permettre aux utilisateurs de se connecter à des boîtes Gmail ou Microsoft 365 avec leur compte au lieu d'un mot de passe, créez un client OAuth et remplissez les champs Google ou Microsoft de l'application Courriel :

  • Google : un client OAuth Web avec l'API Gmail et l'étendue https://mail.google.com/.
  • Microsoft : une application Entra ID avec les permissions déléguées IMAP.AccessAsUser.All, SMTP.Send, offline_access, openid, email et profile. Le locataire est common par défaut.
  • Dans les deux cas, l'URI de redirection est https://chat.example.com/plugins/com.antimatterchat.mail/oauth/callback (l'URL de votre site).

Kanban, Notes, Tableau blanc, Sondages et Playbooks

  • Kanban (focalboard) est accessible à /kanban (les anciens liens /boards y sont redirigés). Son unique paramètre, Enable Publicly-Shared Boards (EnablePublicSharedBoards, désactivé par défaut), permet aux éditeurs de tableau de partager un tableau avec quiconque possède le lien, sans avoir besoin de se connecter.
  • Notes et Sondages ne disposent d'aucun paramètre.
  • Tableau blanc : les administrateurs système peuvent envoyer des bibliothèques de formes (fichiers Excalidraw .excalidrawlib, 5 Mo maximum chacun) pour l'ensemble du serveur depuis sa page de paramètres. Les administrateurs de communauté gèrent les bibliothèques de leur propre communauté.
  • Playbooks dispose de quelques paramètres, principalement des fonctionnalités expérimentales ; les valeurs par défaut conviennent à la plupart des serveurs.
  • Mèmes : Who can add meme templates (tout le monde par défaut, ou uniquement les administrateurs).
  • À faire ne dispose d'aucun paramètre serveur.

GitHub, GitLab et Jira

Ces applications relient Antimatter à votre hébergement de code et à votre outil de suivi des problèmes. Chacune nécessite une application OAuth de l'autre côté et un webhook pointant vers Antimatter. Activez l'application, puis exécutez sa commande de configuration dans n'importe quel canal, qui vous guide étape par étape : /github setup, /gitlab setup ou /jira setup.

ApplicationURL de redirection OAuthURL du webhook
GitHubhttps://chat.example.com/plugins/github/oauth/completehttps://chat.example.com/plugins/github/webhook
GitLabhttps://chat.example.com/plugins/com.github.manland.mattermost-plugin-gitlab/oauth/completehttps://chat.example.com/plugins/com.github.manland.mattermost-plugin-gitlab/webhook
Jira/jira instance install server <url> ou /jira instance install cloud-oauth <url> ; /jira webhook affiche les URL des webhooks.
Laissez Use Preregistered OAuth Application désactivé dans les applications GitHub et GitLab : il s'appuie sur un service Mattermost dont Antimatter ne dispose pas, et l'application refuse de démarrer s'il est activé. Enregistrez votre propre application OAuth.

Les applications GitHub et GitLab génèrent leur secret de webhook et leur clé de chiffrement lors de la première sauvegarde. L'application GitHub peut être limitée à des organisations (GithubOrg) et l'application GitLab à un groupe (GitlabGroup) ; pour GitHub Enterprise ou un GitLab auto-hébergé, définissez son URL de base.

Métriques

L'application Metrics collecte les métriques de performance du serveur dans une petite base de données de séries temporelles intégrée à Antimatter, ce qui vous permet de les télécharger ou de les inclure dans un paquet de support sans avoir à exécuter Prometheus. Au démarrage, elle active le point de terminaison des métriques du serveur (MetricsSettings.Enable). Voir Opérations.

Installation d'autres applications

Antimatter exécute des applications Mattermost (plugins). Trois façons d'en ajouter une :

  • Depuis un marché distant. Activer le marché distant (PluginSettings.EnableRemoteMarketplace) est désactivé par défaut, et URL du marché (PluginSettings.MarketplaceURL) est vide : Antimatter n'utilise pas le marché de Mattermost et ignore son adresse si une configuration de Mattermost la contient encore. Pour lister les applications d'un serveur de marché auquel vous faites confiance, activez ce paramètre et définissez son URL. Les versions Marketplace des applications livrées avec Antimatter (Calls, Playbooks, Kanban et les autres) sont masquées, afin qu'elles ne puissent pas remplacer celles d'Antimatter : Autoriser les versions Marketplace des plugins Antimatter (PluginSettings.AllowMarketplaceToReplaceAntimatterPlugins) est désactivé par défaut.
  • Par l’envoi d’un bundle (.tar.gz). Les envois sont désactivés par défaut et n’ont pas d’interrupteur dans la Console système : définissez AM_PLUGINSETTINGS_ENABLEUPLOADS=true, puis utilisez Importer un plugin dans la Gestion des plugins, ou amctl --local plugin add app.tar.gz.
  • Depuis une URL : amctl plugin install-url <url>, également avec les téléversements activés.

Antimatter vérifie les signatures des applications par rapport aux clés auxquelles il fait confiance : la clé Antimatter, la clé avec laquelle Mattermost, Inc. signe ses applications publiées (afin qu’une application Mattermost téléchargée par vous-même s’installe) et toute clé que vous ajoutez dans PluginSettings.SignaturePublicKeyFiles. Avec Nécessite une signature de plugin (PluginSettings.RequirePluginSignature, désactivé par défaut) activé, les applications non signées sont refusées et les envois sont désactivés.

Une application s'exécute au sein du serveur avec un accès complet à ses données. N'installez que des applications auxquelles vous faites confiance.

Certaines applications conçues pour les éditions payantes de Mattermost vérifient elles-mêmes la présence d'une licence Mattermost et refusent de s'exécuter ; Antimatter ne prétend pas en posséder une pour elles.
