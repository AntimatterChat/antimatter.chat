Installation avec Docker Compose

C'est la méthode recommandée. Un seul fichier compose exécute Antimatter, PostgreSQL, le stockage de fichiers et le service GIF. Il vous faut un serveur Linux avec Docker Engine et son plugin Compose (docker compose), 2 cœurs CPU et 4 Go de mémoire ou plus.

1. Télécharger le fichier compose

mkdir antimatter && cd antimatter
curl -fsSLO https://antimatter.chat/compose.yaml

2. Créer le fichier .env

Le fichier compose lit ses paramètres dans un fichier .env situé dans le même répertoire. Créez-le avec des secrets aléatoires :

cat > .env <<EOF
SITE_URL=http://localhost:8065
POSTGRES_PASSWORD=$(openssl rand -hex 24)
S3_SECRET_KEY=$(openssl rand -hex 24)
GIFS_API_KEY=$(openssl rand -hex 24)
EOF
chmod 600 .env

Définissez SITE_URL avec l'adresse que les utilisateurs saisiront dans leur navigateur, par exemple http://192.168.1.20:8065 sur un réseau local ou https://chat.example.com avec un nom de domaine. Conservez le fichier .env : la base de données et le stockage utilisent ces mots de passe dès le premier démarrage, et vous en aurez besoin du même fichier pour restaurer une sauvegarde.

3. Démarrer

docker compose up -d
docker compose ps

Le premier démarrage prend une ou deux minutes : PostgreSQL crée la base de données, un service à exécution unique bucket crée le seau de stockage, un service à exécution unique gifs-stickers importe le pack d'autocollants de départ, et Antimatter crée ses tables. Suivez le processus avec docker compose logs -f antimatter.

Pour utiliser un nom de domaine et HTTPS dès le départ, consultez Nom de domaine et HTTPS : avec le fichier compose, il suffit d'ajouter deux lignes dans .env et d'activer le profil https.

PostgreSQL, le stockage et le service de GIF sont sur un réseau interne (private) sans accès à Internet, auquel seul Antimatter se connecte. Aucun d'entre eux ne publie de port.

Le conteneur Antimatter ne conserve rien sur le disque : ses paramètres sont dans la base de données (AM_CONFIG y pointe) et ses fichiers et applications sont dans le service de stockage. Vous pouvez supprimer et recréer le conteneur à tout moment. Tout ce qui doit être sauvegardé se trouve dans les volumes postgres, files et gifs, ainsi que dans votre .env.

Choisir une image

Deux images Antimatter sont publiées, toutes deux pour linux/amd64 et linux/arm64, et toutes deux construites à partir de la branche main de chaque dépôt :

ImageApplications intégréesÉtiquettes
ghcr.io/antimatterchat/antimatterAgents, Appels, GitHub, GitLab, Jira, Kanban, Métriques et Playbooks.latest, X.Y.Z pour les versions, sha-<commit>
ghcr.io/antimatterchat/antimatter-nextIdem, plus Canaux vocaux, Sondages, Mail, Calendrier, Notes, Tableau blanc, GIFs, À faire et Memes. Reconstruite chaque nuit.latest, nightly, nightly-<YYYYMMDD>, sha-<commit>

Le fichier compose du site utilise antimatter-next, car le service de GIF et la plupart des applications décrites sur ce site ne sont disponibles que dans cette image. Pour changer d'image, définissez ANTIMATTER_IMAGE dans .env et exécutez docker compose up -d.

latest évolue sous vos pieds. En production, fixez une étiquette telle que nightly-20261015 ou sha-<commit>, et modifiez-la intentionnellement lors d'une mise à niveau. Le serveur met à jour sa base de données au démarrage, il est donc impossible de revenir à une image plus ancienne, ou de passer d'antimatter-next à antimatter, sans restaurer une sauvegarde effectuée au préalable. Voir Sauvegardes et mises à niveau.

À l'intérieur de l'image

  • Le serveur se trouve dans /antimatter, avec les binaires antimatter et amctl dans /antimatter/bin (sur le PATH).
  • Il s'exécute en tant qu'utilisateur non privilégié antimatter (uid 2000) sur une base distroless minimale, sans shell.
  • Ports : 8065 (web et API), 8067 (métriques), 8074 (cluster), 8443 UDP et TCP (appels).
  • Le mode local (ServiceSettings.EnableLocalMode) est activé, donc amctl --local fonctionne à l'intérieur du conteneur. La vérification de l'état d'activité exécute amctl system status --local.
  • Les applications intégrées se trouvent dans /antimatter/prepackaged_plugins et sont signées avec la clé de signature des applications Antimatter.
  • Les outils d'extraction de texte (pdftotext, wvText, unrtf, tidy) sont inclus, ce qui permet de rechercher dans le contenu des documents envoyés.

Autres fichiers compose

Le dépôt antimatter-docker propose une configuration de production dans deploy/compose/ : nginx avec vos propres certificats ou Let's Encrypt (certbot), PostgreSQL, le service GIF facultatif (profil gifs) et des volumes nommés pour la configuration, les données et les journaux du serveur, le tout documenté dans son README. Il utilise par défaut l'image stable et stocke les fichiers sur un volume local au lieu d'un stockage S3. Utilisez-la si vous préférez nginx à Caddy, ou si vous disposez déjà de certificats.

Créer le premier administrateur

Ouvrez SITE_URL dans votre navigateur et créez un compte. Le premier compte créé sur un nouveau serveur devient administrateur système, puis l'installation vous guide pour créer votre première communauté (le nom donné par Antimatter à une équipe ou à un espace de travail).

Effectuez cette opération juste après le premier démarrage : jusqu'à ce moment, quiconque accède au serveur en premier devient son administrateur. Pour créer le compte depuis la ligne de commande, avant que le serveur ne soit accessible de l'extérieur :

docker compose exec antimatter amctl --local user create --system-admin --email-verified \
    --email admin@example.com --username admin --password 'a-long-password'
docker compose exec antimatter amctl --local team create --name main --display-name "Main"
docker compose exec antimatter amctl --local team users add main admin

Connectez-vous ensuite sur SITE_URL. Commencez la commande par un espace pour éviter que le mot de passe ne soit enregistré dans l'historique de votre shell (avec HISTCONTROL=ignorespace), ou modifiez le mot de passe une fois connecté.

Étapes suivantes une fois connecté :

  1. Décidez qui peut créer des comptes : Connexion et comptes.
  2. Configurez l'e-mail pour que les invitations et les réinitialisations de mot de passe fonctionnent : E-mails et notifications push.
  3. Ouvrez le port des appels dans votre pare-feu : Appels et voix.
  4. Vérifiez quelles applications sont activées : Applications intégrées.

Installation à partir d'une archive de version

Sans Docker, le serveur est exécuté à partir d'une archive nommée antimatter-<os>-<arch>.tar.gz (par exemple antimatter-linux-amd64.tar.gz). Elle contient un unique répertoire antimatter/ avec bin/antimatter, bin/amctl, config/config.json, les applications web (client/ et client-fusion/), les modèles d'e-mails et les traductions.

1. Préparer PostgreSQL

Antimatter ne prend en charge que PostgreSQL, version 15 ou plus récente (les versions antérieures démarrent, mais avec une erreur dans le journal). Créez un utilisateur et une base de données :

sudo -u postgres psql <<'EOF'
CREATE USER antimatter WITH PASSWORD 'a-long-password';
CREATE DATABASE antimatter OWNER antimatter;
EOF

2. Décompresser et configurer

sudo tar -xzf antimatter-linux-amd64.tar.gz -C /opt
sudo useradd --system --user-group antimatter
sudo mkdir -p /opt/antimatter/data
sudo chown -R antimatter:antimatter /opt/antimatter

Indiquez au serveur la base de données, soit dans /opt/antimatter/config/config.json (SqlSettings.DataSource), soit avec des variables d'environnement, et définissez l'URL du site :

AM_SQLSETTINGS_DRIVERNAME=postgres
AM_SQLSETTINGS_DATASOURCE=postgres://antimatter:a-long-password@localhost:5432/antimatter?sslmode=disable&connect_timeout=10
AM_SERVICESETTINGS_SITEURL=https://chat.example.com

Le fichier config.json de l'archive est une configuration par défaut complète : les paramètres modifiés dans la Console système sont enregistrés à nouveau dans ce fichier. Pour conserver la configuration dans la base de données à la place, voir Configuration.

3. L'exécuter en tant que service

Une unité systemd, dans /etc/systemd/system/antimatter.service :

[Unit]
Description=Antimatter
After=network.target postgresql.service

[Service]
Type=notify
User=antimatter
Group=antimatter
WorkingDirectory=/opt/antimatter
ExecStart=/opt/antimatter/bin/antimatter
EnvironmentFile=-/etc/antimatter.env
TimeoutStartSec=3600
Restart=always
RestartSec=10
LimitNOFILE=49152

[Install]
WantedBy=multi-user.target

Placez vos variables AM_ dans /etc/antimatter.env (lisible uniquement par root), puis :

sudo systemctl daemon-reload
sudo systemctl enable --now antimatter
journalctl -u antimatter -f

Le serveur écoute sur le port 8065. Ouvrez http://<server>:8065, ou votre domaine une fois un proxy inverse en place (voir Domaine et HTTPS), et créez le premier compte : il devient administrateur système.

bin/amctl gère le serveur en cours d'exécution depuis la ligne de commande. Sur le serveur lui-même, il fonctionne sans connexion via le mode local : définissez AM_SERVICESETTINGS_ENABLELOCALMODE=true, puis exécutez sudo -u antimatter /opt/antimatter/bin/amctl --local system status.

Autres commandes du serveur

En plus de l'exécution du serveur (antimatter, ou antimatter server), le binaire dispose de quelques commandes de maintenance. Elles lisent la même configuration que le serveur.

CommandeFonction
antimatter versionAffiche la version, le numéro de build, la date de build et l'empreinte de build.
antimatter db pingVérifie que la base de données est accessible.
antimatter db initCrée la configuration dans la base de données (avec AM_CONFIG défini sur une URL postgres://).
antimatter db migrateApplique les migrations de la base de données sans démarrer le serveur.
antimatter db versionAffiche la dernière migration appliquée à la base de données.
antimatter import bulk, antimatter export bulkImporte ou exporte des données au format par lot (voir Sauvegardes et mises à niveau).
