Как работи едно приложение

  • Сървърната част е програма на Go. Сървърът я стартира като отделен процес и комуникира с нея чрез RPC: той извиква хуковете на приложението (съобщение е на път да бъде публикувано, команда е била изпълнена…), а приложението извиква API-то на плъгините на сървъра (създаване на публикация, четене на потребител, съхранение на данни…). То може също да обслужва HTTP маршрути под /plugins/<app id>/.
  • Уеб частта е JavaScript пакет, зареден в браузъра заедно с уеб приложението. То регистрира React компоненти и обратни извиквания в регистъра: бутон в меню, панел, начин за изобразяване на тип съобщение.
  • И двете части са опционални. Приложението се инсталира като .tar.gz пакет, а системните администратори го активират, деактивират и конфигурират.
Сървърната част се изпълнява с пълен достъп до данните на сървъра. Отнасяйте се към приложението като към код, който разполагате на сървъра.

Antimatter изпълнява приложения, написани за Mattermost, и обратно, стига приложението да използва само хукове, които и двете имат. Вижте Хукове, които има само Antimatter.

Структура на пакета

Няма отделен стартов шаблон: започнете от малко вградено приложение като antimatter-plugin-polls или antimatter-plugin-todo и променете ID-то и кода му. Polls е структуриран по следния начин:

antimatter-plugin-polls/
├── plugin.json            the manifest
├── Makefile               build, test, bundle, deploy
├── build/                 the manifest and pluginctl helper tools (Go), setup.mk
├── assets/icon.svg        files shipped with the bundle
├── go.mod
├── server/
│   ├── main.go            plugin.ClientMain(&Plugin{})
│   ├── plugin.go          the Plugin type, OnActivate, ServeHTTP
│   ├── manifest.go        generated from plugin.json
│   ├── api.go, command.go, hooks.go, store.go …
│   └── dist/              compiled binaries, one per platform
└── webapp/
    ├── package.json, webpack.config.js, tsconfig.json
    ├── i18n/              en.json and one file per language
    ├── src/index.tsx      registers the app with the web app
    ├── src/manifest.ts    generated from plugin.json
    ├── src/translations.ts
    └── dist/main.js       the bundle

Опционално: папка public/, обслужвана такава каквато е на /plugins/<app id>/public/.

{

      "darwin-arm64": "server/dist/plugin-darwin-arm64",
      "windows-amd64": "server/dist/plugin-windows-amd64.exe"
    }
  },

  • id: уникално и постоянно; обичайно е обратното име на домейн. То определя маршрутите, съхранените настройки и WebSocket събитията.
  • version: семантична версия. Вградените приложения не го включват в plugin.json; инструментът за изграждане го взима от последния v* git таг.
  • min_server_version: Antimatter докладва 12.0.0.
  • settings_schema: страницата с настройки на приложението в Системната конзола (вижте Настройки).

make apply копира манифеста в server/manifest.go и webapp/src/manifest.ts; make manifest-check го валидира.

Сървърната част

Сървърната част импортира същия Go модул като приложението Mattermost, github.com/mattermost/mattermost/server/public, от Go модулния прокси. Неговият main само стартира приложението:

package main

import "github.com/mattermost/mattermost/server/public/plugin"

func main() {
	plugin.ClientMain(&Plugin{})
}

Типът Plugin вгражда plugin.MattermostPlugin, което му дава p.API, и реализира хуковете, от които има нужда:

type Plugin struct {
	plugin.MattermostPlugin
	router *mux.Router
}

func (p *Plugin) OnActivate() error {
	p.router = p.newRouter()
	return p.API.RegisterCommand(&model.Command{
		Trigger:          "weather",
		AutoComplete:     true,
		AutoCompleteDesc: "Show the forecast",
		AutoCompleteHint: "[city]",
	})
}

func (p *Plugin) ExecuteCommand(c *plugin.Context, args *model.CommandArgs) (*model.CommandResponse, *model.AppError) {
	city := strings.TrimSpace(strings.TrimPrefix(args.Command, "/weather"))
	return &model.CommandResponse{
		ResponseType: model.CommandResponseTypeEphemeral,
		Text:         "Forecast for " + city + ": sunny",
	}, nil
}

func (p *Plugin) ServeHTTP(c *plugin.Context, w http.ResponseWriter, r *http.Request) {
	p.router.ServeHTTP(w, r)
}

Общи хукове

ХукКога се изпълнява
OnActivate, OnDeactivateКогато приложението се активира или деактивира, както и при стартиране и спиране на сървъра. Регистрирайте команди и ботове в OnActivate.
OnConfigurationChangeКогато настройките му се променят; заредете ги с p.API.LoadPluginConfiguration(&cfg).
ServeHTTPЗаявки към /plugins/<app id>/…. Сървърът задава заглавието Mattermost-User-Id, когато заявката идва от влязъл потребител; отхвърляйте заявки без него, освен ако не са предназначени да са публични.
ExecuteCommandКоманда, регистрирана от приложението, е била изпълнена.
MessageWillBePosted, MessageWillBeUpdatedПреди съобщение да бъде записано: върнете променено съобщение или причина за отхвърляне.
MessageHasBeenPosted, MessageHasBeenUpdated, MessageHasBeenDeletedСлед събитието, за странични ефекти.
ReactionHasBeenAdded, ReactionHasBeenRemovedРеакции.
UserHasJoinedChannel, UserHasLeftChannel, UserHasJoinedTeam, UserHasLeftTeam, ChannelHasBeenCreatedПромени в членството и каналите. Екипът е общност.
FileWillBeUploadedПреди файл да бъде съхранен: променете го или го отхвърлете.
OnPluginClusterEventСъобщение от същото приложение на друг сървър в кластера.

Пълният списък, с точните сигнатури, е в server/public/plugin/hooks.go; API-то е в server/public/plugin/api.go. Пакетът pluginapi (server/public/pluginapi) обвива API-то в по-удобни помощни функции.

Полезни API извиквания

  • CreatePost, UpdatePost, SendEphemeralPost: публикуване от името на бота на приложението или от името на потребител.
  • EnsureBotUser(&model.Bot{Username, DisplayName}): създава бота на приложението веднъж и връща неговия ID.
  • PublishWebSocketEvent("poll_updated", payload, &model.WebsocketBroadcast{ChannelId: id}): изпраща събитие към уеб приложението. То пристига като custom_<app id>_poll_updated.
  • OpenInteractiveDialog: отваря диалог.
  • LogInfo, LogError и подобни: записва в сървърния журнал, маркиран с ID-то на приложението.
  • GetUser, GetChannel, HasPermissionToChannel: проверява кой може да направи какво, преди да действате от името на потребител.

Приложението се изпълнява на всеки сървър в кластера. Запазвайте състоянието в хранилището за ключ-стойност или в базата данни, а не само в паметта.

AI услугата

Сървърът на Antimatter извиква AI модели за приложенията чрез моделните връзки, които администраторът е конфигурирал (вижте AI в ръководството за администратори). Приложението никога не съхранява ключ на доставчик: то посочва за кого и къде действа, а сървърът проверява дали този човек може да използва връзката там, прилага лимитите и бюджетите ѝ, отчита токените спрямо човека и приложението и води одит на извикването без неговото съдържание.

МетодКакво прави
AIChat(actingUserID, channelID, teamID, *ai.ChatRequest)Chat завършване: съобщения, инструменти, структуриран изход (JSONSchema).
AIChatStream(…)Същото, но в поток: четете Events от потока, докато каналът се затвори, или го Close-нете, за да спрете извикването.
AIEmbed(…, *ai.EmbedRequest)Embeddings на текстове.
AITranscribe(…, *ai.TranscribeRequest)Говор в текст.
AIDecide(…, *ai.DecideRequest)Типизирани въпроси към модел за вземане на решения (да или не, избор, оценка) относно текст.
AIConnectionsForUser(userID, channelID, teamID)Връзките, които човек може да използва там, с техните модели и възможности, но никога с техните ключове.

ConnectionID на всяко запитване избира връзката, а Model – един от моделите ѝ (празно за модел по подразбиране на връзката). Operation е кратка етикета за записите за използване и одит, никога не е съдържание. Минималната версия на сървъра е 11.11.

Вземайте actingUserID само от източник, който сървърът е верифицирал: заглавието Mattermost-User-Id на запитване към вашия ServeHTTP, или потребителя от контекста на хук (автор на публикация, потребителят, който е изпълнил команда). Никога не го вземайте от съобщение, webhook payload, URL или запитване на друго приложение: приложението ви би разхарчило достъпа на някой друг.

Тези методи и пакетът ai (server/public/ai) съществуват само в копото на Antimatter от модула, а не в версията, публикувана от Mattermost. За да ги използвате, компилирайте спрямо server/public на Antimatter с ред replace във вашия go.mod, например replace github.com/mattermost/mattermost/server/public => ../antimatter/server/public. Такова приложение работи само на Antimatter.

Запазване на данни

Всяко приложение има собствено хранилище за ключ-стойност в базата данни на сървъра:

  • KVSet(key, value), KVGet(key), KVDelete(key): стойностите са байтове, обикновено JSON. Ключовете са най-много 150 символа.
  • KVSetWithExpiry(key, value, seconds): стойността изчезва след това време.
  • KVCompareAndSet(key, old, new) и KVSetWithOptions с Atomic: безопасни актуализации, когато няколко заявки или сървъра записват един и същ ключ. Polls запазва всеки глас по този начин и повтаря при конфликт.
  • KVList(page, perPage): ключовете, страница по страница.

Частта за уеб приложението

Бандлът регистрира клас чрез window.registerPlugin. Неговият initialize получава регистъра и Redux магазина:

import manifest from './manifest';

class Plugin {
    initialize(registry, store) {
        registry.registerTranslations((locale) => translationsFor(locale));
        registry.registerPostTypeComponent('custom_poll', PollPost);
        registry.registerWebSocketEventHandler(`custom_${manifest.id}_poll_updated`, (msg) => {
            store.dispatch(pollUpdated(JSON.parse(msg.data.poll)));
        });
        registry.registerReconnectHandler(() => store.dispatch(reloadPolls()));
    }
}

window.registerPlugin(manifest.id, new Plugin());
  • Споделени библиотеки. Уеб приложението осигурява React, ReactDOM, Redux, React Redux и React Intl: изреждайте ги като webpack externals (React, ReactDOM, Redux, ReactRedux, ReactIntl), вместо да опаковате собствени копия. Вижте webpack.config.js на Polls.
  • Извикване на сървърната ви част. Използвайте Fetch за ${window.basename}/plugins/<app id>/… с опциите от Client4.getOptions() (от mattermost-redux/client): те носят заглавията, от които сървърът се нуждае, за да приеме заявка от браузъра.
  • Собствено състояние. registerReducer добавя редюсер, запазен под state['plugins-<app id>'].
  • Типове. Допълнителните методи на регистъра на Antimatter не са в публикуваните типове на Mattermost: Polls декларира регистъра, който използва, в webapp/src/types/host.ts.

Методите на регистъра и техните параметри са документирани в кода, в webapp/fusion/src/plugins/registry.ts (Fusion) и webapp/channels/src/plugins/registry.ts (класически).

Поддръжка на интерфейса Fusion

Antimatter има два уеб интерфейса: Fusion, който е по подразбиране, и класическия. И двата зареждат одни и същи бандлове на приложенията и имат един и същ регистър, но Fusion чертае много неща сам и разполага компонентите на плъгините по свой начин. Тествайте приложението си и в двата.

Откриване на интерфейса

Преди зареждането на всяко приложение, и двата интерфейса задават window.antimatterWebUI на 'fusion' или 'classic', и същата стойност на коренния елемент на страницата като data-am-web-ui. В Mattermost нито едно от двете не е зададено.

export function isFusionUI(): boolean {
    return window.antimatterWebUI === 'fusion' || document.documentElement.dataset.amWebUi === 'fusion';
}

Вградените приложения използват това, за да се изобразяват по различен начин. Приложението за анкети изрисува картите си в стил Fusion, като в Fusion анкетата се пише в полето за въвеждане (един от режимите на полето за въвеждане), вместо в диалогов прозорец. Обажданията и гласовите канали пропускат страничната лента и компонентите за известия (toast), които Fusion замества със собствен интерфейс за обаждания. Приложението за чат с AI поставя своите AI действия в менюто на съобщението, като група под Още действия, вместо в лентата с инструменти при посочване с мишката. Собствените CSS класове на Fusion (с префикс am-) и неговият слой за диалогови прозорци (елементът am-layer) са това, което тези приложения използват, за да съответстват на интерфейса; те не са документиран, стабилен API.

Какво Fusion не показва или не изпълнява

  • registerPostDropdownMenuComponent (компонент в менюто на съобщението) и registerPostCardTypeComponent (картата на публикация в десния панел) не се показват в основните изгледи на Fusion. registerProductSwitcherMenuItem не прави нищо във Fusion, тъй като няма меню на продукта (записва предупреждение). Използвайте registerPostDropdownMenuAction вместо първия.
  • registerMessageWillBeUpdatedHook не се изпълнява, когато съобщение се редактира в Fusion. Проверете промените на сървъра с хука MessageWillBeUpdated вместо това.
  • registerActionAfterChannelCreation се изпълнява само от класическия диалог за създаване на канал, който Fusion отваря от Още опции… в диалога си за Създаване на канал.
  • Компонентите на лентата на приложенията се показват независимо от supportedProductIds.
  • Маршрутите от registerNeedsTeamRoute и registerCustomRoute запазват класическия рамка на страницата, както продуктите.

Добавяне и управление на изгледи в изборника за емоджи

В Fusion таблоидът за избор на емоджи получава свойството pickerKit: компонентите, които таблоидът Емоджи използва за собствените си изгледи за добавяне и управление, така че изгледите на таблоида да изглеждат еднакво и да остават в рамките на изборника. Режими на полето за въвеждане

В Fusion registerComposerMode({id, label, fusionIcon, placeholder, sendLabel, component, shouldRender}) добавя нов начин за изписване на съобщение в полето за въвеждане, подобно на това как приложението Анкети добавя възможност за създаване на анкета. Режимът се предлага в менюто + на полето за въвеждане под неговия label. След като бъде избран, полето за въвеждане запазва текстовото си поле (с placeholder на режима: въпроса на анкетата), показва вашия component под него и лента с името на режима и бутон Откажи; бутонът Изпращане приема sendLabel и изпълнява вашата функция за изпращане вместо да публикува текста.

  • Компонентът получава channelId, rootId (нишката, в полето за отговор), message (текста в полето за въвеждане), setSubmit и onCancel (връща се към обикновено съобщение, запазвайки текста).
  • Передайте на setSubmit функция, която се извиква с текста от полето за въвеждане и връща нищо (или празен низ) след изпращане: тогава полето за въвеждане се изчиства и се връща към обикновено съобщение. Върнете низ, за да го покажете като грешка на място.
  • placeholder и sendLabel са низове или функции на intl от react-intl. shouldRender(state, {channelId, rootId}) определя дали дадено поле за въвеждане предлага режима.
  • За да отворите режима от друго място, например чрез команда с наклонена черта без аргументи: window.dispatchEvent(new CustomEvent('am-composer-mode', {detail: {id, channelId, rootId}})).

Само Fusion поддържа режими за полето за въвеждане: проверете дали регистърът съдържа функцията и в противен случай използвайте собствен диалог. Методът връща идентификатора на режима, а режимът се премахва, когато приложението бъде премахнато.

Панелът в нов прозорец

Fusion предоставя на компонента на registerRightHandSidebarComponent два допълнителни пропса, така че Отваряне в нов прозорец да отваря панела там, където е бил, а не в началната страница на приложението:

  • setPanelState(state): извиквайте го, когато панелът смени местоположението си, с кратка низа, дефинирана от вашето приложение, например 'note/<id>' или 'board/<id>/card/<id>', или null на началната страница. Тази стойност се записва в адреса на прозореца, така че никога не поставяйте в нея поверителна информация. Състояние, по-дълго от 512 символа или съдържащо управляващи символи, се отхвърля.
  • initialPanelState: в новия прозорец това е състоянието, което панелът е имал, или undefined. Отнасяйте се към него като към ненадеен вход: заредете елемента отново като влязлия потребител и покажете началната страница на приложението или изглед „не е намерено“, ако потребителят не може да го отвори.

Състоянието се забравя, когато панелът се затвори или панел на друго приложение заеме неговото място. За да отворите прозореца на панел сам, popoutRhsPlugin (намира се и в window.WebappUtils.popouts) приема състоянието като опционален пети аргумент. Бележки, Бяла дъска, Задачи, Kanban и Наръчници използват това.

fusionIcon задава име на икона от набора икони на Fusion (напр. poll, sticker, calendar или image; вижте webapp/fusion/src/fusion/components/icon). Fusion я показва вместо icon, за да съвпада с останалите елементи.

Настройки

settings_schema в plugin.json описва страницата на приложението в Системна конзола › Приставка:

"settings_schema": {
  "header": "Forecasts come from the weather service below.",
  "settings": [
    {"key": "ServiceURL", "display_name": "Service URL", "type": "text", "default": "https://api.example.com"},
    {"key": "Units", "display_name": "Units", "type": "dropdown", "default": "metric",
     "options": [{"display_name": "Celsius", "value": "metric"}, {"display_name": "Fahrenheit", "value": "imperial"}]},
    {"key": "EnableAlerts", "display_name": "Severe weather alerts", "type": "bool", "default": false,
     "help_text": "Post alerts in the channels that follow a city."}
  ]

Типове настройки: bool, text, longtext, number, dropdown, radio, generated (случайна тайна), username и custom (рисува се от компонент, регистриран от веб частта на приложението чрез registerAdminConsoleCustomSetting). Настройките могат да се групират в sections.

Сървърната част ги прочита в структура, чиито полета съответстват на ключовете:

type configuration struct {
	ServiceURL   string
	Units        string
	EnableAlerts bool
}

func (p *Plugin) OnConfigurationChange() error {
	var cfg configuration
	if err := p.API.LoadPluginConfiguration(&cfg); err != nil {
		return err
	}
	p.setConfiguration(&cfg)
	return nil
}

Администраторите могат да ги задават и в конфигурацията, под PluginSettings.Plugins.<app id>, с ключове в малки букви (вижте ръководството за администратори).

Преводи

Antimatter е преведен на 37 езика, както и вградените приложения. Веб частта на приложението го прави по следния начин:

  1. Записвайте всяка низ с React Intl, с ID и английския ѝ текст: <FormattedMessage id='polls.create' defaultMessage='Create a poll'/> или defineMessages. Предоставете ID-тата с името на вашето приложение.
  2. Извличайте английските низове в webapp/i18n/en.json (вградените приложения използват formatjs extract).
  3. Добавете по един файл за всеки език до него, със същите ID-та: fr.json, de.json, pt-BR.json, zh-CN.json…
  4. Предоставяте ги на уеб приложението, което пита за езика на потребителя: 
    import fr from '../i18n/fr.json';
import ptBR from '../i18n/pt-BR.json';

const catalogs = {fr, 'pt-BR': ptBR};

export function translationsFor(locale) {
    return catalogs[locale] || catalogs[locale.split('-')[0]] || {};
}

registry.registerTranslations(translationsFor);

Липсващият текст се връща към английския defaultMessage. За текст, изпратен от сървърната част (отговори на команди, съобщения от ботове), пакетът pluginapi/i18n зарежда файловете за превод, доставени в пакета (напр. assets/i18n) и предоставя локализатор на езика на всеки потребител.

Ръчно инсталиране на пакет

  • Системен администратор разрешава качвания с AM_PLUGINSETTINGS_ENABLEUPLOADS=true (изключено по подразбиране; няма превключвател в Системната конзола).

  • Ако на сървъра е активирано Изисква се подпис на приставката, той приема само пакети, подписани с ключ, на който има доверие; вижте Инсталиране на други приложения.
