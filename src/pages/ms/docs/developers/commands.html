Cara arahan garis miring berfungsi

  1. Seseorang menaip /weather Paris dan menghantarnya. Teks tersebut tidak diposkan.
  2. Antimatter menghantar permintaan HTTP ke URL arahan, bersama maklumat tentang siapa yang menaipnya, di mana, dan teks selepas pemicu.
  3. Perkhidmatan anda menjawab dalam masa had permintaan (30 saat secara lalai) dengan satu mesej.
  4. Antimatter memaparkan jawapan: hanya kepada pengguna tersebut (sementara) atau dalam saluran untuk semua orang.

Arahan tergolong dalam komuniti, dan perkataan pemicu adalah unik dalam komuniti tersebut. Arahan terbina dalam seperti /join, /msg atau /away tidak boleh digantikan. Aplikasi (pelengkap) juga boleh mendaftarkan arahan; lihat Bahagian pelayan.

Cipta arahan

Arahan garis miring custom adalah dihidupkan secara lalai (Benarkan Arahan Garis Miring Custom dalam Konsol Sistem › Integrasi › Pengurusan Integrasi, ServiceSettings.EnableCommands). Pentadbir komuniti dan pentadbir sistem boleh menciptakannya secara lalai.

  1. Buka avatar anda di bahagian kanan atas, kemudian Integrasi › Arahan Garis Miring, kemudian Tambah Arahan Garis Miring.
  2. Isi Tajuk dan Penerangan (ditunjukkan pada halaman integrasi).
  3. Masukkan Perkataan Pencetus Arahan, tanpa garis miring dan tanpa ruang, sebagai contoh weather.
  4. Masukkan URL Permintaan dan pilih Kaedah Permintaan: POST (lalai) atau GET.
  5. Secara pilihan, tetapkan Nama Pengguna Respons dan Ikon Respons. Ia hanya digunakan apabila pelayan membenarkan integrasi untuk menggantikan nama dan ikon (lihat Nama dan ikon).
  6. Tandakan Lengkapkan Secara Automatik untuk menyenaraikan arahan apabila orang menaip /, dengan Petunjuk Autocomplete (argumennya, seperti [city]) dan Penerangan Autocomplete.
  7. Pilih Simpan, dan salin token yang dipaparkan. Perkhidmatan anda menggunakannya untuk memeriksa bahawa permintaan datang dari pelayan anda.

Dengan API: POST /api/v4/commands dengan {"team_id", "trigger", "url", "method": "P", "display_name", "description", "auto_complete": true, "auto_complete_hint", "auto_complete_desc", "username", "icon_url"}. Kaedah ialah P untuk POST atau G untuk GET. PUT /api/v4/commands/{command_id}/regen_token mengeluarkan token baharu.

Permintaan yang diterima perkhidmatan anda

Arahan POST menghantar badan yang dikodkan sebagai borang (application/x-www-form-urlencoded); arahan GET menghantar medan yang sama dalam strung kueri. Token juga terdapat dalam pengepala Authorization: Token <token>.

MedanNilai
tokenToken arahan. Semak ia pada setiap permintaan.
commandPemicu dengan garis miringnya, contohnya /weather.
textSemua teks selepas pemicu, contohnya Paris.
user_id, user_nameSiapa yang menjalankannya.
channel_id, channel_nameDi mana ia dijalankan.
team_id, team_domainID dan nama URL komuniti.
root_idBebenang, jika ia dijalankan dalam kotak balas bebenang.
trigger_idMembolehkan jawapan anda membuka dialog (lihat Dialog). Ia sah untuk tempoh masa yang singkat sahaja.
response_urlURL untuk menghantar lebih banyak jawapan kemudian (lihat Jawapan tertangguh).
user_mentions, user_mentions_ids, channel_mentions, channel_mentions_idsOrang dan saluran awam yang disebut dalam teks, jika ada.
URL Laman pelayan mesti ditetapkan untuk arahan khusus berfungsi: Antimatter membina response_url daripadanya.

Respons

Jawab 200 dengan JSON (Content-Type: application/json):

{
  "response_type": "in_channel",
  "text": "Paris: 18 °C, light rain",
  "attachments": []
}
MedanMaksud
response_typeephemeral (lalai): hanya orang yang menjalankan arahan melihat jawapan, dan ia tidak disimpan selepas dimuat semula. in_channel: jawapan diposkan dalam saluran.
text, attachmentsMesej, seperti untuk webhook: teks Markdown dan lampiran, termasuk butang dan menu.
username, icon_urlNama dan gambar untuk dipaparkan, jika penggantian dibenarkan. Tetapan arahan itu sendiri menang ke atas ini.
channel_idPoskan jawapan dalam saluran lain, yang orang tersebut mesti menjadi ahlinya.
goto_locationURL untuk dibuka setelah arahan dijalankan.
props, typeSifat tambahan dan jenis pos khusus, seperti untuk webhook.
extra_responsesJawapan tambahan, setiap satu dengan medan yang sama, diposkan setelah yang pertama.
skip_slack_parsingtrue mengekalkan teks seperti apa adanya, tanpa menukar pautan dan sebutan gaya Slack.

Respons yang bukan JSON dipaparkan sebagai mesej sementara dengan badan sebagai teksnya. 204 No Content tidak memaparkan apa-apa. Status apa pun di luar 200–299 memaparkan ralat kepada pengguna.

Perkhidmatan contoh

Perkhidmatan arahan minimum dalam Python, dengan hanya pustaka piawai:

import hmac
import json
from http.server import BaseHTTPRequestHandler, HTTPServer
from urllib.parse import parse_qs

TOKEN = "the token shown when you saved the command"

class Handler(BaseHTTPRequestHandler):
    def do_POST(self):
        body = self.rfile.read(int(self.headers["Content-Length"])).decode()
        form = {key: values[0] for key, values in parse_qs(body).items()}
        if not hmac.compare_digest(form.get("token", ""), TOKEN):
            self.send_response(401)
            self.end_headers()
            return
        answer = {
            "response_type": "ephemeral",
            "text": f"Hello @{form['user_name']}, you asked for: {form.get('text', '')}",
        }
        data = json.dumps(answer).encode()
        self.send_response(200)
        self.send_header("Content-Type", "application/json")
        self.end_headers()
        self.wfile.write(data)

HTTPServer(("0.0.0.0", 8080), Handler).serve_forever()

Jika perkhidmatan berjalan pada alamat rangkaian peribadi, pentadbir sistem mesti membenarkannya dalam Benarkan sambungan dalaman tidak dipercayai kepada (ServiceSettings.AllowedUntrustedInternalConnections).

Jawapan lewat

Untuk kerja yang mengambil masa lebih lama daripada had masa, jawab serta-merta (contohnya dengan mesej sementara "Sedang diproses…"), kemudian hantar jawapan sebenar ke response_url. Ia menerima JSON yang sama seperti respons, dan berfungsi sehingga 5 kali dalam tempoh 30 minit selepas arahan.

curl -X POST "$RESPONSE_URL" -H 'Content-Type: application/json' \
  -d '{"response_type": "in_channel", "text": "Report ready: https://reports.example.com/42"}'

Jalankan arahan dengan API

Skrip dan bot boleh menjalankan sebarang arahan, terbina dalam atau tersuai, seolah-olah mereka telah menaipnya:

curl -X POST https://chat.example.com/api/v4/commands/execute \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"channel_id": "'$CHANNEL_ID'", "command": "/weather Paris"}'

GET /api/v4/teams/{team_id}/commands/autocomplete senaraikan arahan yang boleh disempurnakan secara automatik oleh pengguna dalam komuniti.

Penyempurnaan automatik

Arahan yang dicipta pada halaman integrasi disempurnakan secara automatik dengan pencetus, petua dan penerangannya. Arahan yang didaftarkan oleh aplikasi boleh menerangkan subarahan dan argumennya secara terperinci dengan AutocompleteData, daripada model.NewAutocompleteData(trigger, hint, helpText):

  • AddCommand(sub) menambah subarahan, yang juga merupakan AutocompleteData.
  • AddTextArgument(helpText, hint, pattern) menambah teks bebas.
  • AddStaticListArgument(helpText, required, items) menawarkan senarai tetap AutocompleteListItem{Item, Hint, HelpText}.
  • AddDynamicListArgument(helpText, url, required) meminta aplikasi anda untuk cadangan semasa pengguna menaip. URL ialah laluan aplikasi anda, seperti /plugins/com.example.weather/cities. Ia menerima pengguna, saluran dan komuniti, dan mengembalikan senarai JSON {"Item", "Hint", "HelpText"}.

Variasi Named… (AddNamedTextArgument dan lain-lain) menambah bendera --name value. Kedua-dua antara muka web memaparkan cadangan ini.
