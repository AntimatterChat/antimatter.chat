Vad du behöver

  • Go, i den version som anges i server/go.mod (1.26.7 vid skrivningstillfället).
  • Node.js och npm, i de versioner som anges i .nvmrc och webapp/package.json (Node 24.11.1 med npm 11.6.2). Med mise installerar repositorys mise.toml rätt Node.
  • Docker med Compose: utvecklingsuppsättningen kör PostgreSQL och några andra tjänster i containrar.
  • make, git och en Linux- eller macOS-maskin.
  • Minne: att bygga webbgränssnitten är den tunga delen. Planera för 16 GB RAM; se Byggen och minne.
git clone https://github.com/AntimatterChat/antimatter.git
cd antimatter

Repositoryn innehåller servern i server/, webbgränssnitten i webapp/ (Fusion i webapp/fusion, klassisk i webapp/channels, gemensamma paket i webapp/platform) och end-to-end-test i e2e-tests/.

Köra en utvecklingsserver

cd server
make run

make run startar utvecklingscontainrarna (PostgreSQL, Redis, ett e-postfångstnät och övervakningsverktyg), länkar in webbappens byggen, startar servern i bakgrunden med go run och startar webbappens watcher, som bygger om det klassiska gränssnittet när du redigerar det. Öppna http://localhost:8065 och skapa ett konto: det första blir systemadministratör.

Utvecklingsdatabasen är postgres://mmuser:mostest_password@localhost/mattermost_test, serverns standard datakälla. Välj vilka containrar som startas med ENABLED_DOCKER_SERVICES, i en server/config.override.mk-fil eller i din miljö (se server/config.mk).

Webbgränssnitten

I webapp/:

npm install      # also builds the shared packages
npm run build    # the classic interface, then Fusion

Byggena hamnar i webapp/channels/dist (klassisk) och webapp/fusion/dist (Fusion). make client i server/ länkar dem som server/client och server/client-fusion, där servern serverar dem: klassisk under /static/, Fusion under /static/fusion/.

  • npm run run (eller make run i webapp/) övervakar och bygger om det klassiska gränssnittet. Lägg till WATCH_FUSION=true för att också bygga om Fusion.
  • npm run dev-server (make dev) kör istället webpacks utvecklingsserver: klassisk på port 9005, Fusion på port 9006.
  • För att se det ena eller det andra gränssnittet i webbläsaren, lägg till ?webui=fusion eller ?webui=classic till adressen för valfri sida.

Utgivningsarkiv

cd webapp && npm run build && cd ..
cd server
make build-linux       # the antimatter and amctl binaries
make package-linux     # dist/antimatter-linux-amd64.tar.gz and -arm64

make build bygger webbgränssnitten och Linux-binärfilerna i ett steg. Arkivet innehåller bin/antimatter, bin/amctl, en standard config/config.json, båda webbgränssnitten, mallarna, typsnitten och översättningarna. Andra plattformar: make package-osx, make package-windows, make package-freebsd. Arkiven innehåller inte de medföljande apparna; Docker-bilden gör det.

Docker-bilden

Repositoriet antimatter-docker bygger de publicerade bilderna, servern med dess appar, helt inom Docker:

git clone https://github.com/AntimatterChat/antimatter-docker.git
cd antimatter-docker
scripts/build-all.sh                     # from the main branches on GitHub
SOURCES=local scripts/build-all.sh       # from your checkouts next to this folder
VARIANT=next scripts/build-all.sh        # the "next" image, with every Antimatter app

Det kräver Docker med buildx, Python 3, git och gpg, cirka 16 GB RAM och 30 GB disk. Resultatet laddas som ghcr.io/antimatterchat/antimatter:dev; testa det med ANTIMATTER_IMAGE=ghcr.io/antimatterchat/antimatter:dev docker compose -f compose.local.yml up -d. plugins.json listar apparna och de versioner som byggs, och repositoriets README förklarar varianterna.

build-all.sh signar de medföljande apparna med Antimatters signeringsnyckel, och bildbyggeriet vägrar acceptera osignerade appar. Utan den privata nyckeln, som endast underhållarna har, kör du de första stegen separat: scripts/fetch-sources.sh, scripts/build-plugins.sh (appbundler i out/plugins/) och scripts/build-server.sh (serverarkiv i out/server/).

Byggen och minne

Webbgränssnitten är stora webpack-byggen, och att ta slut på minne är den vanligaste orsaken till att bygget misslyckas.

  • npm run build bygger det klassiska gränssnittet och Fusion efter varandra, inte samtidigt, för att hålla toppbelastningen nere. Kör dem inte parallellt själv.
  • Minifieraren startar en worker per processorkärna. På en maskin med många kärnor och lite minne, begränsa antalet processorer som bygget ser: taskset -c 0-5 npm run build.
  • Om Node tar slut på heap, höj dess gräns: NODE_OPTIONS=--max-old-space-size=6144. Docker-bygget använder detta värde (BUILD_NODE_OPTIONS i build.env).
  • Undvik att köra serverns fullständiga testsvit, ett webbbygge och ett Docker-bygge samtidigt på en liten maskin.

Apparna

Varje app (plugin) har sitt eget repository och sin egen Makefile; make dist bygger dess bundle. Se Bygg, installera och felsök.

Skrivbordsapp

Skrivbordsappen är en Electron-app. Med Node.js 24 eller senare:

npm install --allow-git=all
npm run build          # development build, into dist/
npm start              # run it
npm run package:linux  # packages into release/ (also package:windows, package:mac)

Byggtidsinställningar, såsom servrar som ska förkonfigureras, finns i src/common/config/buildConfig.ts.

Mobilapp

Mobilappen är en React Native-app; dess README listar kommandona (npm run ios, npm run android). För att bygga din egen kopia behöver du också egna signeringsnycklar, ett Firebase-projekt för Android-aviseringar, en APNs-nyckel för iOS och en push-proxy som förvarar dessa autentiseringsuppgifter.
