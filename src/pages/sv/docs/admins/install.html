Installera med Docker Compose

Detta är det rekommenderade sättet. En compose-fil kör Antimatter, PostgreSQL, filarkivet och GIF-tjänsten. Du behöver en Linux-server med Docker Engine och dess Compose-plugin (docker compose), 2 CPU-kärnor och 4 GB minne eller mer.

1. Ladda ner compose-filen

mkdir antimatter && cd antimatter
curl -fsSLO https://antimatter.chat/compose.yaml

2. Skapa .env-filen

Compose-filen läser sina inställningar från en .env-fil i samma katalog. Skapa den med slumpmässiga hemligheter:

cat > .env <<EOF
SITE_URL=http://localhost:8065
POSTGRES_PASSWORD=$(openssl rand -hex 24)
S3_SECRET_KEY=$(openssl rand -hex 24)
GIFS_API_KEY=$(openssl rand -hex 24)
EOF
chmod 600 .env

Sätt SITE_URL till adressen som folk ska skriva in i sin webbläsare, till exempel http://192.168.1.20:8065 på ett lokalt nätverk eller https://chat.example.com med ett domännamn. Spara .env-filen: databasen och lagringen använder dessa lösenord från första start, och du behöver samma fil för att återställa en säkerhetskopia.

3. Starta

docker compose up -d
docker compose ps

Första starten tar en eller två minuter: PostgreSQL skapar databasen, en engångstjänst bucket skapar lagringsbehållaren, en engångstjänst gifs-stickers importerar startstickersamlingen och Antimatter skapar sina tabeller. Följ med docker compose logs -f antimatter.

För att använda ett domännamn och HTTPS från början, se Domän och HTTPS: med compose-filen är det två rader till i .env och https-profilen.

PostgreSQL, lagringsutrymmet och GIF-tjänsten är på ett internt nätverk (private) utan internetåtkomst, som endast Antimatter är ansluten till. Ingen av dem publicerar en port.

Antimatter-containern lagrar inget på disk: dess inställningar finns i databasen (AM_CONFIG pekar på den) och dess filer och appar finns i lagringstjänsten. Du kan ta bort och återskapa containern när som helst. Allt som behöver säkerhetskopieras finns i volymerna postgres, files och gifs, samt din .env.

Välj en bild

Två Antimatter-bilder publiceras, båda för linux/amd64 och linux/arm64, och båda byggda från main-grenen i varje repository:

ImageMedföljande apparTaggar
ghcr.io/antimatterchat/antimatterAgenter, Samtal, GitHub, GitLab, Jira, Kanban, Metriker och Playbooks.latest, X.Y.Z för utgåvor, sha-<commit>
ghcr.io/antimatterchat/antimatter-nextSamma, plus Röstkanaler, Omröstningar, E-post, Kalender, Anteckningar, Whiteboard, GIF:er, Att göra och Memes. Byggs om varje natt.latest, nightly, nightly-<YYYYMMDD>, sha-<commit>

Webbplatsens compose-fil använder antimatter-next, eftersom GIF-tjänsten och de flesta appar som beskrivs på den här webbplatsen endast finns i den bilden. För att byta bild, sätt ANTIMATTER_IMAGE i .env och kör docker compose up -d.

latest ändras under dig. I produktion, fäst en tagg som nightly-20261015 eller sha-<commit>, och ändra den medvetet när du uppgraderar. Servern uppgraderar sin databas när den startar, så du kan inte gå tillbaka till en äldre bild, eller från antimatter-next till antimatter, utan att återställa en säkerhetskopia som togs tidigare. Se Säkerhetskopior och uppgraderingar.

Inuti bilden

  • Servern finns i /antimatter, med binärfilerna antimatter och amctl i /antimatter/bin (på PATH).
  • Den körs som den oprivilegierade användaren antimatter (uid 2000) på en minimal distroless-bas, utan shell.
  • Portar: 8065 (webb och API), 8067 (metriker), 8074 (cluster), 8443 UDP och TCP (samtal).
  • Lokalt läge (ServiceSettings.EnableLocalMode) är aktiverat, så amctl --local fungerar inuti containern. Hälsokontrollen kör amctl system status --local.
  • De medföljande apparna finns i /antimatter/prepackaged_plugins och är signerade med Antimatters app-signeringsnyckel.
  • Verktyg för textextraktion (pdftotext, wvText, unrtf, tidy) är medtagna, så innehållet i uppladdade dokument kan sökas.

Andra compose-filer

Repositoriet antimatter-docker har en produktionsuppsättning i deploy/compose/: nginx med egna certifikat eller Let's Encrypt (certbot), PostgreSQL, den valfria GIF-tjänsten (profil gifs) och namngivna volymer för serverns konfiguration, data och loggar, dokumenterat i dess README. Den använder standardbilden som standard och lagrar filer på en lokal volym istället för S3-lagring. Använd den om du föredrar nginx framför Caddy, eller redan har certifikat.

Skapa den första administratören

Öppna SITE_URL i webbläsaren och skapa ett konto. Det första kontot som skapas på en ny server blir systemadministratör, och uppsättningen leder dig sedan genom skapandet av din första community (Antimatters namn på ett team eller en arbetsyta).

Gör detta direkt efter första start: annars blir den som når servern först dess administratör. För att skapa kontot från kommandoraden istället, innan servern är åtkomlig från utomhus:

docker compose exec antimatter amctl --local user create --system-admin --email-verified \
    --email admin@example.com --username admin --password 'a-long-password'
docker compose exec antimatter amctl --local team create --name main --display-name "Main"
docker compose exec antimatter amctl --local team users add main admin

Logga sedan in på SITE_URL. Börja kommandot med ett mellanslag för att hålla lösenordet borta från skalhistoriken (med HISTCONTROL=ignorespace), eller ändra lösenordet när du är inloggad.

Nästa steg när du är inloggad:

  1. Bestäm vem som kan skapa konton: Inloggning och konton.
  2. Konfigurera e-post, så att inbjudningar och lösenordsåterställningar fungerar: E-post och push-aviseringar.
  3. Öppna samtalets port i din brandvägg: Samtal och röst.
  4. Kontrollera vilka appar som är aktiverade: Medföljande appar.

Installera från ett release-arkiv

Utan Docker körs servern från ett arkiv med namnet antimatter-<os>-<arch>.tar.gz (till exempel antimatter-linux-amd64.tar.gz). Det innehåller en enda katalog, antimatter/, med bin/antimatter, bin/amctl, config/config.json, webbapplikationerna (client/ och client-fusion/), e-postmallarna och översättningarna.

1. Förbered PostgreSQL

Antimatter stöder endast PostgreSQL, version 15 eller nyare (äldre versioner startar, men ger ett fel i loggen). Skapa en användare och en databas:

sudo -u postgres psql <<'EOF'
CREATE USER antimatter WITH PASSWORD 'a-long-password';
CREATE DATABASE antimatter OWNER antimatter;
EOF

2. Packa upp och konfigurera

sudo tar -xzf antimatter-linux-amd64.tar.gz -C /opt
sudo useradd --system --user-group antimatter
sudo mkdir -p /opt/antimatter/data
sudo chown -R antimatter:antimatter /opt/antimatter

Peaka servern mot databasen, antingen i /opt/antimatter/config/config.json (SqlSettings.DataSource) eller med miljövariabler, och ange webbadressen:

AM_SQLSETTINGS_DRIVERNAME=postgres
AM_SQLSETTINGS_DATASOURCE=postgres://antimatter:a-long-password@localhost:5432/antimatter?sslmode=disable&connect_timeout=10
AM_SERVICESETTINGS_SITEURL=https://chat.example.com

Arkivets config.json är en komplett standardkonfiguration: inställningar du ändrar i Systemkonsolen sparas tillbaka dit. För att i stället hålla konfigurationen i databasen, se Konfiguration.

3. Kör den som en tjänst

En systemd-enhet, i /etc/systemd/system/antimatter.service:

[Unit]
Description=Antimatter
After=network.target postgresql.service

[Service]
Type=notify
User=antimatter
Group=antimatter
WorkingDirectory=/opt/antimatter
ExecStart=/opt/antimatter/bin/antimatter
EnvironmentFile=-/etc/antimatter.env
TimeoutStartSec=3600
Restart=always
RestartSec=10
LimitNOFILE=49152

[Install]
WantedBy=multi-user.target

Placera dina AM_-variabler i /etc/antimatter.env (läsbar endast för root), och kör sedan:

sudo systemctl daemon-reload
sudo systemctl enable --now antimatter
journalctl -u antimatter -f

Servern lyssnar på port 8065. Öppna http://<server>:8065, eller din domän när en omvänd proxy är på plats (se Domän och HTTPS), och skapa det första kontot: det blir systemadministratören.

bin/amctl hanterar den körande servern från kommandoraden. På själva servern fungerar den utan inloggning via lokal läge: sätt AM_SERVICESETTINGS_ENABLELOCALMODE=true och kör sedan sudo -u antimatter /opt/antimatter/bin/amctl --local system status.

Övriga serverkommandon

Utöver att köra servern (antimatter, eller antimatter server) har binärfilen ett par underhållskommandon. De läser samma konfiguration som servern.

KommandoVad den gör
antimatter versionVisar version, byggnummer, byggdatum och bygghash.
antimatter db pingKontrollerar att databasen är nåbar.
antimatter db initSkapar konfigurationen i databasen (med AM_CONFIG satt till en postgres://-adress).
antimatter db migrateTillämpar databasmigrationer utan att starta servern.
antimatter db versionVisar den senaste migrationen som tillämpats på databasen.
antimatter import bulk, antimatter export bulkImporterar eller exporterar data i bulkformat (se Säkerhetskopior och uppgraderingar).
