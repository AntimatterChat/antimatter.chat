アプリのダウンロード

デスクトップアプリのリリースは github.com/AntimatterChat/desktop-app/releases にあります。サーバーと同様に、アプリはベータ版です。バージョンにハイフン後のサフィックスがあるリリースは Pre-release と表示されます。各リリースには、すべてのファイルのチェックサムを含む SHA256SUMS ファイルがあります。Linux では sha256sum --check --ignore-missing SHA256SUMS を実行してダウンロードを確認するか、PowerShell で Get-FileHash <file> -Algorithm SHA256 の出力を SHA256SUMS の該当行と比較してください。

  • Windows（x64 および arm64）：.exe インストーラー、.msi パッケージ、または .zip アーカイブ。例：antimatter-desktop-<version>-win-x64.exe および antimatter-desktop-<version>-win-x64.msi。
  • macOS：.dmg ディスクイメージまたは .zip。Apple silicon（arm64）、Intel Mac（x64）、または両方対応（universal）があります。
  • Linux（x64 および arm64）：.deb または .rpm パッケージ、AppImage、Flatpak バンドル、または .tar.gz アーカイブ。

アプリは実行中、1時間ごとに GitHub で新しいバージョンを確認します。確認対象は正式リリースのみで、プレリリースは対象外です。新しいバージョンが見つかった場合は、ユーザーに通知し、ダウンロードへのリンクを提供します。MSI でインストールしたコピーは、通常ソフトウェアのインストール権限がないユーザーが使用するため、デフォルトでは確認を行いません。EnableAutoUpdater 設定を有効にすると、確認が有効になります。この場合、提供されるダウンロードは新しい .msi ファイルであり、管理者権限が必要です。

SCCM (Configuration Manager)、Intune、またはグループポリシーによるソフトウェアインストールでの管理されたデプロイには MSI を使用してください。MSI のインストールにより、インストールを実行しているアカウントの .exe コピーが存在する場合、削除されます。

管理可能な設定

これらの設定はすべてのシステムに存在します。Windows では HKEY_LOCAL_MACHINE (コンピュータ全体) または HKEY_CURRENT_USER (単一のユーザー) の SOFTWARE\Policies\Antimatter 配下のレジストリ値です。macOS および Linux では、管理された環境設定またはポリシーファイルのキーです。

設定項目Windows の場合macOS および Linux の場合機能
DefaultServerListサーバーごとに1つの文字列値を持つサブキー: 値の名前はタブの名前、データはその URLname と url を持つ辞書 (Linux ではオブジェクト) の配列アプリにサーバーを追加します。ユーザーはこれらを編集したり削除したりできません。
DefaultUsername文字列文字列これらのサーバーのログインページにユーザー名を入力します。
EnableServerManagementDWORD、0 または 1ブール値0 または false: ユーザーは DefaultServerList で設定されたサーバーのみを使用でき、アプリはサーバーの追加、編集、削除オプションを非表示にします。未設定: ユーザーは独自のサーバーを追加できます。
EnableAutoUpdaterDWORD、0 または 1ブール値0 または false: アプリは新しいバージョンを確認せず、アップデートを確認 を非表示にします。1 または true: MSI でインストールされた場合でも確認します。未設定: .exe コピーは確認し、MSI コピーは確認しません。
TrustedEmbeddedMediaOrigins文字列値を持つサブキー、各値は serverOrigin と embeddedOrigin を持つ JSON オブジェクトserverOrigin と embeddedOrigin を持つ辞書の配列サーバーのページに埋め込まれたコンテンツ (ビデオ会議ページなど) が、そのサーバーに付与されたカメラとマイクの権限を使用できるようにします。
  • ユーザー名は、ポリシーで設定されたサーバーのログインページでのみ入力され、ユーザーが自分で追加したサーバーや、ユーザーが手動で入力した値の上書きは行われません。ユーザーはいつでも変更できます。パーセント記号で囲まれた環境変数は置き換えられるため、1つの値で全員に対応できます: Windows では %USERNAME%、macOS と Linux では %USER% がアカウント名を返し、%USERNAME%@example.com はこのパターンに従うメールアドレスになります。変数が設定されていない場合、アプリは何も入力しません。
  • サーバー管理を無効にする場合、DefaultServerList に少なくとも1つのサーバーを設定してください。
  • Windows では、コンピューターポリシー (HKEY_LOCAL_MACHINE) がユーザーポリシー (HKEY_CURRENT_USER) より優先されます。両方のサーバーリストは結合されます。
  • アプリは起動時に設定を読み取ります。変更後は、アプリを終了して再度開く必要があります。

Windows: MSI によるサイレントインストール

MSI は、HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Antimatter にコンピューターポリシーとして設定を書き込むパブリックプロパティを受け取ります。SCCM アプリケーション、Intune アプリ、またはスクリプトで使用できます。PowerShell の例:

msiexec /i antimatter-desktop-<version>-win-x64.msi /qn SERVERURL=https://chat.example.com SERVERNAME=Chat DEFAULTUSERNAME='%USERNAME%' AUTOUPDATE=0 SERVERMANAGEMENT=0
プロパティ書き込む内容指定しない場合
SERVERURLDefaultServerList にこの URL のサーバーサーバーなし
SERVERNAMEそのサーバーのタブ名Antimatter
DEFAULTUSERNAMEDefaultUsernameなし
AUTOUPDATEEnableAutoUpdater、0 または 1なし: MSI コピーは更新を確認しません
SERVERMANAGEMENTEnableServerManagement、0 または 1なし: ユーザーはサーバーを追加できます
  • 指定されないプロパティは何も書き込まないため、グループポリシーで設定された値を上書きしません。AUTOUPDATE と SERVERMANAGEMENT は 0 または 1 のみを受け入れます。MSI は1つのサーバーのみを設定します: 複数必要な場合はグループポリシーを使用してください。
  • DEFAULTUSERNAME は、アプリが各ユーザーに対して置き換えられるよう、インストーラーに %USERNAME% というテキストとして届く必要があります。そうでない場合、インストールを実行しているシェルが、それ自身のアカウント名で置き換えてしまいます。PowerShell では、シングルクォーテーションを維持してください。.bat ファイルでは %%USERNAME%% と記述します。テストインストール後、レジストリで DefaultUsername が %USERNAME% を保持していることを確認してください。
  • アップグレードのたびにプロパティを再渡してください。 MSI の新しいバージョンをインストールすると、古いバージョンが削除され、その際に書き込まれた値も消えます。その後、新しいコマンドラインの値が書き込まれます。SCCM と Intune はアプリケーションのコマンドラインを保持します: 各新しいバージョンで再利用してください。または、グループポリシーや Intune でポリシーを設定すると、アップグレードによって影響を受けません。
  • MSIとグループポリシーは同じレジストリ値を書き込みます。各設定については、どちらか一方を使用してください。MSIをアンインストールすると、グループポリシーでも設定されていた場合であっても、MSIが書き込んだ値が削除されます。
  • MSIは、インストール先フォルダーをHKEY_LOCAL_MACHINE\SOFTWARE\Antimatter\Desktop（InstallDir）にも記録します。これにより、アプリはMSIでインストールされたことを認識します。

アンインストールするには、msiexec /x antimatter-desktop-<version>-win-x64.msi /qnを使用します。Intuneでは、「Windows アプリ (Win32)」タイプに同じコマンドラインを指定します。「ラインオブビジネス アプリ」タイプの場合は、プロパティをコマンドライン引数に追加してください。

Windows: グループポリシーとIntune

管理用テンプレートであるantimatter.admxとen-US\antimatter.admlは、インストールされたアプリのgpoフォルダー（MSIの場合はC:\Program Files\Antimatter\gpo）およびアプリのリポジトリのresources/windows/gpoフォルダーにあります。これらのテンプレートは、管理用テンプレート › Antimatterの下に以下のポリシーを表示します。

ポリシーレジストリ値設定
サーバー (DefaultServerList)DefaultServerList サブキーコンピューターとユーザー
事前入力するユーザー名 (DefaultUsername)DefaultUsernameコンピューターとユーザー
サーバーの追加と削除を許可 (EnableServerManagement)EnableServerManagementコンピューターとユーザー
新しいバージョンの通知 (EnableAutoUpdater)EnableAutoUpdaterコンピューターのみ
信頼できる埋め込みメディアのオリジン (TrustedEmbeddedMediaOrigins)TrustedEmbeddedMediaOrigins サブキーコンピューターとユーザー

ドメインでのグループポリシー

  1. antimatter.admxを中央ストアの\\<domain>\SYSVOL\<domain>\Policies\PolicyDefinitionsに、antimatter.admlはそのen-USフォルダーにコピーします。
  2. グループポリシー管理エディターで、コンピューターの設定（またはユーザーの設定）› ポリシー › 管理用テンプレート › Antimatterを開きます。
  3. ポリシーを編集し、有効を選択して値を入力します。サーバーの場合は、表示をクリックして、サーバーごとに1行ずつ追加します。値の名前はタブ名、値はサーバーURL（例: https://chat.example.com）です。

サーバーの追加と削除を許可または新しいバージョンの通知を有効にすると1が書き込まれ、無効にすると0が書き込まれます。

Intune

デバイス › 設定で、ADMXのインポートを使用してantimatter.admxをen-US\antimatter.admlとインポートします。次に、テンプレート › インポートされた管理テンプレートからプロファイルを作成し、Antimatterのポリシーを設定します。

単一のコンピュータ、またはスクリプト

テンプレートをC:\Windows\PolicyDefinitionsにコピーすると、gpedit.msc（Windows ProおよびEnterprise）で使用できます。または、.regファイルを管理者としてインポートしてレジストリ値を直接書き込みます（reg import antimatter-policies.reg）。例は以下の通りです。同じフォルダにあるexample-policies.regファイルには、これらの値がコメント付きで含まれています。

REGEDIT4

[HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Antimatter]
"EnableServerManagement"=dword:00000000
"EnableAutoUpdater"=dword:00000000
"DefaultUsername"="%USERNAME%"

[HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Antimatter\DefaultServerList]
"Chat"="https://chat.example.com"

macOS：構成プロファイル

macOSでは、アプリはバンドル識別子chat.antimatter.desktopの管理設定から設定を読み取ります。キーは設定テーブルのものです。MDM（Jamf、Intune、Kandji、Mosyleなど）を使用して構成プロファイルとしてデプロイします。

  • アプリのリポジトリのresources/mac/mdmフォルダには、サンプルプロファイルantimatter.mobileconfigがあります。値を編集し、独自のPayloadIdentifierとPayloadUUID値（uuidgenで新しいUUIDを生成）を設定し、カスタムプロファイルとしてアップロードします。
  • ほとんどのMDMは、chat.antimatter.desktopの「カスタム設定」または「プリファレンスドメイン」ペイロードとして、キーのみを受け入れます。同じフォルダには、example-managed-preferences.plistにそれらが含まれています。

プロファイルのペイロード内の設定：

<key>PayloadType</key>
<string>chat.antimatter.desktop</string>
<key>DefaultServerList</key>
<array>
    <dict>
        <key>name</key>
        <string>Chat</string>
        <key>url</key>
        <string>https://chat.example.com</string>
    </dict>
</array>
<key>DefaultUsername</key>
<string>%USER%</string>
<key>EnableServerManagement</key>
<false/>
<key>EnableAutoUpdater</key>
<false/>

ブール値は、整数の0と1としても指定できます。

Linux：ポリシーファイル

Linuxでは、アプリは/etc/antimatter-desktop/policies.jsonを読み取ります。これは設定テーブルのキーを持つJSONオブジェクトです：

{
    "DefaultServerList": [
        {"name": "Chat", "url": "https://chat.example.com"}
    ],
    "DefaultUsername": "%USER%",
    "EnableServerManagement": false,
    "EnableAutoUpdater": false,
    "TrustedEmbeddedMediaOrigins": []
}

構成管理ツール（Ansible、Puppet、Saltなど）を使用してデプロイし、所有者をroot、全員が読み取り可能、rootのみが書き込み可能にします：

sudo install -d /etc/antimatter-desktop
sudo install -m 644 policies.json /etc/antimatter-desktop/policies.json

有効なJSONではないファイルは無視され、アプリのログに警告が表示されます。Flatpakバージョンはホストの/etcを見ません：読み取りアクセスを与え、/run/host/etc/antimatter-desktop/policies.jsonからファイルを読み取ります：

sudo flatpak override --system --filesystem=host-etc:ro chat.antimatter.desktop

Mattermostデスクトップアプリ用に設定されたポリシー

Windows では、アプリはフォールバックとして、SOFTWARE\Policies\Mattermost に設定された Mattermost デスクトップアプリのポリシーも読み取ります。読み取りは場所ごとに実行され、ポリシーキーの直下、DefaultServerList サブキー、および TrustedEmbeddedMediaOrigins サブキーの値が対象です。これら3つの場所それぞれについて、Antimatter キーに値が設定されていない場合（どちらかのハイブでも）にのみ、Mattermost キーの値が読み取られます。したがって、Antimatter キーの直下に1つの値が設定されると（例えば MSI の AUTOUPDATE プロパティによって）、Mattermost キーの直下にあるどの値も読み取られなくなります。すべてのポリシーを一度に Antimatter キーへ移行してください。

macOS では、Mattermost デスクトップアプリの管理設定（com.mattermost.desktop）は読み取られません：chat.antimatter.desktop に対して設定してください。

未署名ビルド

デスクトップアプリのビルドは、まだ発行者証明書で署名されていません。

  • Windows. 人がダウンロードした .exe または .msi を開くと、Microsoft Defender SmartScreen によって Windows がコンピューターを保護したことが通知され、不明な発行者の名前が表示されます。ユーザーは詳細情報を選択し、その後実行を選択します。SmartScreen はダウンロード後に人が開くファイルをチェックするため、SCCM、Intune、またはグループポリシーを通じてアプリをデプロイする場合、ユーザーはこの警告を見ません。コンピューターが承認された発行者からのソフトウェアのみを実行する場合（AppLocker または App Control for Business ルール）、インストールパスまたはファイルハッシュによってアプリを許可してください。
  • macOS. アプリはアドホックで署名されていますが、Apple によるノタリゼーションは行われていません。人がダウンロードしたコピーを初めて開く際、macOS はアプリがマルウェアから安全であることを検証できないと通知し、開きません。macOS 15 以降では、システム設定 › プライバシーとセキュリティを開き、開くを選択します。以前のバージョンでは、アプリを Control クリックして開くを選択します。Gatekeeper はダウンロードとしてマークされたファイル（quarantine 属性を持つもの）のみをチェックします：独自のツールでアプリをインストールする場合は、インストールスクリプト内で xattr -dr com.apple.quarantine /Applications/Antimatter.app を使用してマークを削除してください。
