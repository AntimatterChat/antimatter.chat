公開するもの

ポートサービス公開範囲
443/tcp, 443/udp, 80/tcpHTTPSプロキシ (Caddyまたはnginx)公開:これがAntimatterへのアクセス経路です。
8443/udpおよび8443/tcp通話メディアネットワーク外から通話を使用する場合、公開します。
8065/tcpAntimatterのWebサーバープロキシ専用: 127.0.0.1 (HTTP_PORT=127.0.0.1:8065) に公開します。
8067/tcpメトリクス有効化された場合、プライベートネットワーク専用。サインインは不要です。
8074/tcpおよびudpクラスタゴシップクラスタノード間のみ。
5432, 9000, 8080, 8066PostgreSQL、ファイルストレージ、GIFサービス、プッシュプロキシ公開しない。Composeファイルはこれらを公開ポートなしの内部ネットワーク上に保持します。

サイトのComposeファイルは、すべてのコンテナを no-new-privileges で実行し、Antimatterをdistrolessイメージ上で非特権ユーザーとして実行し、GIFサービスを読み取り専用ファイルシステムで実行します。データベース、ストレージ、GIFサービスはインターネットアクセスのないネットワーク上に配置されます。

インストール後のチェックリスト

  1. 他のユーザーがサーバーにアクセスする前に、最初の管理者アカウントを作成します (インストール)。
  2. AntimatterはHTTPS経由でのみ配信し、サイトURLを https:// アドレスに設定します (ドメインとHTTPS)。
  3. .env、config.json、TLSキーはroot(またはサーバーのユーザー)のみが読み取れるようにします: chmod 600 .env。
  4. アカウント作成を許可するユーザーを決定してください。コミュニティが公開でない限り、オープンサーバーを有効にするはオフにしてください。メール機能が正常に動作するようになったら、電子メールアドレスの確認が必要をオンにしてください（サインインとアカウント）。
  5. 多要素認証を有効にし、少なくとも管理者アカウントには強制するか、アイデンティティプロバイダーのものを使用します。
  6. 以下の外部接続を確認し、特に通話がデフォルトで使用するSTUNサーバーを確認します。
  7. バックアップを作成し、リストアをテストします (バックアップとアップグレード)。
  8. イメージを最新に保ちます:セキュリティ修正は新しいイメージとともに提供されます。

レート制限

サーバーは、各クライアントからのAPIリクエスト数を制限できます。デフォルトでは無効です。システムコンソール › 環境 › 投稿頻度制限で設定します。

設定項目キーデフォルト値
投稿頻度制限を有効にするRateLimitSettings.Enableオフ
最大クエリー数(1秒当たり)RateLimitSettings.PerSec10
最大バーストサイズRateLimitSettings.MaxBurst100
メモリー保存サイズRateLimitSettings.MemoryStoreSize追跡対象のクライアント数: 10000
リモートアドレスで投稿頻度制限を変更RateLimitSettings.VaryByRemoteAddron
ユーザーによって投稿頻度制限を変更RateLimitSettings.VaryByUserオフ
HTTPヘッダーで投稿頻度制限を変更RateLimitSettings.VaryByHeader空

プロキシの背後では、サーバーが各クライアントのアドレスを知っている場合 (ServiceSettings.TrustedProxyIPHeader および ServiceSettings.TrustedProxyIPs、プロキシの背後のクライアントアドレスを参照) に限り、アドレスによる制限が機能します。そうでない場合、すべてのリクエストがプロキシからのものであるように見えます。そのため、全員が同じ制限を共有することになります。IP フィルタリングや監査ログ内のアドレスについても同様です。

サインイン試行は別途制限されます: 最大ログイン試行回数 (10) は、パスワードの失敗がこの回数に達した時点でアカウントをロックします。

IP フィルタリング

システムコンソール › サイト設定 › IPフィルタリングでは、IPアドレスに基づいてサーバーへのアクセスを制限できます。許可ルールと拒否ルール（それぞれアドレスまたはCIDR範囲）を設定できます。IPフィルタリングの有効化をオンにすると、拒否ルールに一致するアドレス、または許可ルールが存在する場合にどの許可ルールにも一致しないアドレスを持つユーザーはサーバーにアクセスできなくなります。このページは、ご自身のアドレスをブロックしてしまうルールを拒否します。プロキシの背後にある場合は、まずクライアントアドレスを設定してください（プロキシの背後にあるクライアントアドレス）。そうしないと、すべてのリクエストがプロキシから来たように見えます。

無視、ブロック、メッセージリクエスト

無視、ブロック、メッセージリクエストを有効にするがオン(既定値)の場合、ユーザーは互いを無視したりブロックしたりでき、見知らぬ人からのダイレクトメッセージをメッセージリクエストとして受け取るように選択できます。これらは承認されるまで通知されません。これは公開コミュニティに適しています。同僚が常に連絡できる必要がある職場では、これをオフにしてください(AM_PRIVACYSETTINGS_ENABLEUSERBLOCKING=false): これらの機能は強制されなくなります。ただし、ユーザーが作成したリストや選択は保持され、再度オンにすると再び適用されます。

セッションとトークン

  • セッションの長さとアイドルタイムアウト: サインインとアカウントを参照してください。セッションを短くすると、紛失したラップトップやスマートフォンがサインインされた状態のまま放置される時間が短くなります。
  • パーソナルアクセストークンを有効にする（ServiceSettings.EnableUserAccessTokens、デフォルトはオフ）をオンにすると、ユーザーがAPIトークンを作成できます。個人アクセストークンの最大有効期間 (日)でその期間を制限できます。両方ともシステムコンソール › 統合機能 › 統合機能管理にあります。
  • 例えば、侵害が疑われる場合などに、すべてのユーザーを一度にサインアウトさせるには：システムコンソール › ユーザー管理 › ユーザーにあるすべてのセッションを破棄するを使用します。

外部サービスへの接続

Antimatterは、Mattermost, Inc.が運営するサービスに一切接続しません。テレメトリ、クラッシュレポート、セキュリティ更新の確認、製品通知の取得は行いません。Mattermostから移行した設定で、Mattermostのサービス(プッシュサービス、アプリマーケットプレイス、通知、通話用のSTUNサーバー)を指定している場合でも、サーバーがそれらに接続することはありません。これらのアドレスは無視されます。

サーバーとアプリは、必要な機能のために、および設定したサービスに対してのみ、他の外部サービスに接続します:

機能接続先既定
通話: STUNによるパブリックアドレスの特定。サーバーと通話に参加する各ユーザーがリクエストを送信し、STUNサーバーにIPアドレスとポートが表示されます。CloudflareのパブリックSTUNサーバー、stun.cloudflare.comオン。Calls アプリが有効な場合です。変更するには、Callsを参照してください。
リンクプレビュー：サーバーは、メッセージ内でリンクされたページを取得します（ウェブサイトプレビューを有効にする、ServiceSettings.EnableLinkPreviews）ユーザーがリンクするWebサイトオン。AM_SERVICESETTINGS_ENABLELINKPREVIEWS=falseでオフにできます。
モバイルアプリへのプッシュ通知独自のプッシュプロキシ（プッシュ通知）アドレスを設定するまでオフ
リモートアプリマーケットプレイス（PluginSettings.EnableRemoteMarketplace）設定したマーケットプレースURLオフで、アドレスなし
メールSMTPサーバーデフォルトのサーバーはlocalhostです
シングルサインオン、AIモデル、音声認識と翻訳、アウトゴーイングWebhook、Mail、Calendar、GitHub、GitLab、Jiraなどのアプリ設定したサービス設定するまでオフ

デフォルトでは、サーバーはこれらの機能（リンクプレビュー、Webhook、アプリ）に対して、プライベートアドレスやループバックアドレスへの接続を拒否します。これにより、メッセージや統合機能が内部ネットワークにアクセスするのを防ぐことができます。接続を許可する内部ホストを信頼されていない内部接続を許可する（ServiceSettings.AllowedUntrustedInternalConnections、システムコンソール › 環境 › 開発者内）にリストアップしてください。サイトのcomposeファイルには、そこにgifsがリストされています。

脆弱性の報告

セキュリティの問題は公開Issueではなく、Antimatterセキュリティポリシーに説明されているように、非公開で報告してください。
