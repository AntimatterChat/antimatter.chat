アプリの動作原理

  • サーバー部分はGoで書かれたプログラムです。サーバーはこれを独立したプロセスとして起動し、RPCを介して通信します。サーバーはアプリのフック（メッセージが投稿されようとしている、コマンドが実行されたなど）を呼び出し、アプリはサーバーのプラグインAPI（投稿の作成、ユーザーの読み取り、データの保存など）を呼び出します。また、/plugins/<app id>/配下のHTTPルートを提供することもできます。
  • Webアプリ部分は、Webアプリとともにブラウザに読み込まれるJavaScriptバンドルです。レジストリにReactコンポーネントとコールバックを登録します。メニュー内のボタン、パネル、メッセージタイプの描画方法などがこれにあたります。
  • どちらかの部分のみでも構いません。アプリは.tar.gzバンドルとしてインストールされ、システム管理者が有効化、無効化、設定を行います。
サーバー部分はサーバーのデータに完全なアクセス権を持って実行されます。アプリはサーバーにデプロイするコードとして扱ってください。

AntimatterはMattermost向けに書かれたアプリを実行でき、逆もまた然りです（アプリが両方に共通するフックのみを使用する場合）。Antimatter固有のフックを参照してください。

バンドルの構成

個別のスターターテンプレートはありません。antimatter-plugin-pollsやantimatter-plugin-todoのような小さなバンドル済みアプリから始め、IDとコードを変更してください。Pollsの構成は以下の通りです：

antimatter-plugin-polls/
├── plugin.json            the manifest
├── Makefile               build, test, bundle, deploy
├── build/                 the manifest and pluginctl helper tools (Go), setup.mk
├── assets/icon.svg        files shipped with the bundle
├── go.mod
├── server/
│   ├── main.go            plugin.ClientMain(&Plugin{})
│   ├── plugin.go          the Plugin type, OnActivate, ServeHTTP
│   ├── manifest.go        generated from plugin.json
│   ├── api.go, command.go, hooks.go, store.go …
│   └── dist/              compiled binaries, one per platform
└── webapp/
    ├── package.json, webpack.config.js, tsconfig.json
    ├── i18n/              en.json and one file per language
    ├── src/index.tsx      registers the app with the web app
    ├── src/manifest.ts    generated from plugin.json
    ├── src/translations.ts
    └── dist/main.js       the bundle

任意：public/フォルダ。/plugins/<app id>/public/でそのまま配信されます。

  • id：一意かつ永続的な値。逆ドメイン名が一般的です。ルート、保存される設定、WebSocketイベントの名前になります。
  • version：セマンティックバージョニング。バンドル済みアプリはplugin.jsonからこれを省略しており、ビルドツールが最新のv* gitタグから取得します。

  • settings_schema: システムコンソールのアプリ設定ページ（設定を参照）。

make apply はマニフェストを server/manifest.go と webapp/src/manifest.ts にコピーします。make manifest-check で検証できます。

サーバー部分

サーバー部分は、Mattermost アプリと同じ Go モジュール github.com/mattermost/mattermost/server/public を Go モジュールプロキシからインポートします。その main はアプリを起動するだけです。

package main

import "github.com/mattermost/mattermost/server/public/plugin"

func main() {
	plugin.ClientMain(&Plugin{})
}

Plugin 型は plugin.MattermostPlugin を埋め込み、p.API を取得し、必要なフックを実装します。

type Plugin struct {
	plugin.MattermostPlugin
	router *mux.Router
}

func (p *Plugin) OnActivate() error {
	p.router = p.newRouter()
	return p.API.RegisterCommand(&model.Command{
		Trigger:          "weather",
		AutoComplete:     true,
		AutoCompleteDesc: "Show the forecast",
		AutoCompleteHint: "[city]",
	})
}

func (p *Plugin) ExecuteCommand(c *plugin.Context, args *model.CommandArgs) (*model.CommandResponse, *model.AppError) {
	city := strings.TrimSpace(strings.TrimPrefix(args.Command, "/weather"))
	return &model.CommandResponse{
		ResponseType: model.CommandResponseTypeEphemeral,
		Text:         "Forecast for " + city + ": sunny",
	}, nil
}

func (p *Plugin) ServeHTTP(c *plugin.Context, w http.ResponseWriter, r *http.Request) {
	p.router.ServeHTTP(w, r)
}

一般的なフック

フック実行タイミング
OnActivate, OnDeactivateアプリの有効化・無効化時、およびサーバーの起動・停止時。OnActivate でコマンドやボットを登録します。
OnConfigurationChange設定が変更されたとき。p.API.LoadPluginConfiguration(&cfg) で読み込みます。
ServeHTTP/plugins/<app id>/… へのリクエスト。ログイン済みユーザーからのリクエストの場合、サーバーは Mattermost-User-Id ヘッダーを設定します。公開目的でない限り、このヘッダーがないリクエストは拒否してください。
ExecuteCommandアプリが登録したコマンドが実行されたとき。
MessageWillBePosted, MessageWillBeUpdatedメッセージが保存される前：変更された投稿を返すか、拒否理由を返します。
MessageHasBeenPosted, MessageHasBeenUpdated, MessageHasBeenDeleted事後の副作用のために使用します。
ReactionHasBeenAdded, ReactionHasBeenRemovedリアクション。
UserHasJoinedChannel, UserHasLeftChannel, UserHasJoinedTeam, UserHasLeftTeam, ChannelHasBeenCreatedメンバーシップとチャンネルの変更。チームはコミュニティです。
FileWillBeUploadedファイルが保存される前：変更するか拒否します。
OnPluginClusterEventクラスタ内の別のサーバー上の同じアプリからのメッセージ。

正確なシグネチャ付きの完全なリストは server/public/plugin/hooks.go にあります。API は server/public/plugin/api.go にあります。pluginapi パッケージ（server/public/pluginapi）は、API をより使いやすいヘルパーでラップしています。

便利な API 呼び出し

  • CreatePost、UpdatePost、SendEphemeralPost：アプリのボットまたはユーザーとして投稿します。
  • EnsureBotUser(&model.Bot{Username, DisplayName})：アプリのボットを一度作成し、その ID を取得します。
  • PublishWebSocketEvent("poll_updated", payload, &model.WebsocketBroadcast{ChannelId: id})：Web アプリにイベントを送信します。custom_<app id>_poll_updated として届きます。
  • OpenInteractiveDialog：ダイアログを開きます。
  • LogInfo、LogError などの関数：アプリの ID をタグとして付与し、サーバーログに書き込みます。
  • GetUser、GetChannel、HasPermissionToChannel：ユーザーに代わって操作する前に、誰が何をできるかを確認します。

アプリはクラスタのすべてのサーバーで実行されます。状態はメモリだけでなく、キーバリューストアまたはデータベースに保存してください。

データの保存

各アプリには、サーバーのデータベースに独自のキーバリューストアがあります：

  • KVSet(key, value)、KVGet(key)、KVDelete(key)：値はバイト列（通常は JSON）です。キーは最大 150 文字です。
  • KVSetWithExpiry(key, value, seconds)：指定した時間後に値が削除されます。
  • KVCompareAndSet(key, old, new) および Atomic を使用した KVSetWithOptions：複数のリクエストやサーバーが同じキーに書き込む場合の安全な更新です。Polls はこの方法で各投票を保存し、競合が発生した場合は再試行します。
  • KVList(page, perPage)：ページごとにキーを列挙します。

Web アプリ部分

バンドルは window.registerPlugin でクラスを登録します。その initialize はレジストリと Redux ストアを受け取ります：

import manifest from './manifest';

class Plugin {
    initialize(registry, store) {
        registry.registerTranslations((locale) => translationsFor(locale));
        registry.registerPostTypeComponent('custom_poll', PollPost);
        registry.registerWebSocketEventHandler(`custom_${manifest.id}_poll_updated`, (msg) => {
            store.dispatch(pollUpdated(JSON.parse(msg.data.poll)));
        });
        registry.registerReconnectHandler(() => store.dispatch(reloadPolls()));
    }
}

window.registerPlugin(manifest.id, new Plugin());
  • 共有ライブラリ。 Web アプリは React、ReactDOM、Redux、React Redux、React Intl を提供します：これらを webpack の externals（React、ReactDOM、Redux、ReactRedux、ReactIntl）として列挙し、独自のコピーをバンドルしないでください。Polls の webpack.config.js を参照してください。
  • サーバー部分への呼び出し。 Client4.getOptions()（mattermost-redux/client から）のオプションを使用して、${window.basename}/plugins/<app id>/… をフェッチします：これらは、サーバーがブラウザからのリクエストを受け入れるために必要なヘッダーを保持しています。
  • 独自の状態。 registerReducer はリデューサーを追加し、state['plugins-<app id>'] 以下に保存されます。
  • 型。 Antimatter の追加レジストリメソッドは、Mattermost の公開されている型には含まれていません：Polls は使用するレジストリを webapp/src/types/host.ts で宣言しています。

レジストリのメソッドとそのパラメータは、webapp/fusion/src/plugins/registry.ts（Fusion）および webapp/channels/src/plugins/registry.ts（クラシック）のコードにドキュメント化されています。

Fusion インターフェースのサポート

Antimatter には Fusion（デフォルト）とクラシックという 2 つの Web インターフェースがあります。どちらも同じアプリバンドルを読み込み、同じレジストリを持ちますが、Fusion は多くの要素を自分で描画し、プラグインコンポーネントを独自の方式で配置します。両方のインターフェースでアプリをテストしてください。

インターフェースの検出

アプリが読み込まれる前に、両方のインターフェースは window.antimatterWebUI を 'fusion' または 'classic' に設定し、ページのルート要素にも data-am-web-ui として同じ値を設定します。Mattermost では、どちらも設定されません。

export function isFusionUI(): boolean {
    return window.antimatterWebUI === 'fusion' || document.documentElement.dataset.amWebUi === 'fusion';
}

バンドルアプリは、これを使用して異なる描画を行います。Pollsは、Fusionのスタイルで投票カードと作成ダイアログを描画し、Fusion内の/pollには独自のダイアログを開きます。CallsとVoice channelsは、Fusionが独自の通話インターフェースで置き換えるサイドバーとトーストコンポーネントを省略します。Agentsアプリは、ホバーツールバーではなく、メッセージメニューのサブメニューにAIアクションを配置します。Fusion独自のCSSクラス（am-プレフィックス付き）とダイアログレイヤー（am-layer要素）は、これらのアプリがインターフェースに合わせるために使用しますが、文書化された安定したAPIではありません。

Fusionが表示または実行しないもの

  • registerPostDropdownMenuComponent（メッセージメニュー内のコンポーネント）、registerPostCardTypeComponent（右側パネル内の投稿カード）、およびregisterProductSwitcherMenuItemは、Fusionのメインビューでは表示されません。最初のものではなく、代わりにregisterPostDropdownMenuActionを使用してください。
  • registerMessageWillBeUpdatedHookは、Fusionでメッセージが編集されたときに実行されません。代わりに、MessageWillBeUpdatedフックを使用してサーバー側で編集を確認してください。
  • registerActionAfterChannelCreationは、従来のチャンネル作成ダイアログからのみ実行されます。Fusionは、そのチャンネルを作成ダイアログ内のその他のオプション…から従来のダイアログを開きます。
  • アプリバーのコンポーネントは、supportedProductIdsに関わらず表示されます。
  • registerNeedsTeamRouteおよびregisterCustomRouteからのルートは、プロダクトと同様に従来のページフレームを維持します。

Antimatterにのみ存在するフック

これらのレジストリメソッドはMattermostには存在しません。アプリがMattermostでも動作するように、呼び出す前にメソッドの存在を確認してください：

if (typeof registry.registerComposerMenuItem === 'function') {
    registry.registerComposerMenuItem({
        text: 'Create a poll',
        icon: <i className='icon icon-chart-bar'/>,
        fusionIcon: 'poll',
        action: ({channelId, rootId}) => openPollCreation(channelId, rootId),
    });
} else {
    registry.registerChannelHeaderButtonAction(icon, (channel) => openPollCreation(channel.id), 'Create a poll', 'Create a poll');
}
メソッド追加されるもの
registerComposerMenuItem({text, icon, fusionIcon, action, shouldRender})両方のインターフェースで、メッセージボックスの+メニュー内の項目。actionは{channelId, rootId}を受け取ります。
registerEmojiPickerTab({id, label, icon, fusionIcon, order, component, shouldRender, replacesGifPicker})メッセージボックスの絵文字ピッカーのタブです。GIFやステッカーなどが該当します。Fusionでは、orderが10未満のタブは絵文字タブの前に表示されます。このコンポーネントはchannelId、rootId、filter、onFilterChange、onSelectDone、insertText、isFusionを受け取ります。
registerChannelViewPanel({matcher, component})チャンネルヘッダーとメッセージの間のパネルです。matcher(state, channel)が選択したチャンネルに表示されます。音声チャンネルのように、メッセージとコンポーザーを非表示にすることもできます（setMessagesVisible）。
registerSidebarChannelFooterComponent(component)サイドバーのチャンネルの下に表示される行です。例えば、通話に参加しているメンバーなどが該当します。channelを受け取ります。
registerIntegrationsOption({title, description, fusionIcon, action, shouldRender})Fusion専用: 統合機能ページの項目で、カスタム絵文字の隣にあります。GIFアプリは、そのカスタムGIFやステッカーをここに追加します。

fusionIconは、Fusionのアイコンセットのアイコンを指定します（例: poll、sticker、calendar、image。詳細はwebapp/fusion/src/fusion/components/iconを参照）。Fusionではiconの代わりにこれを表示するため、他の項目と一貫性を保てます。

設定

plugin.json内のsettings_schemaは、システムコンソール › プラグインのアプリページを記述します:

"settings_schema": {
  "header": "Forecasts come from the weather service below.",
  "settings": [
    {"key": "ServiceURL", "display_name": "Service URL", "type": "text", "default": "https://api.example.com"},
    {"key": "Units", "display_name": "Units", "type": "dropdown", "default": "metric",
     "options": [{"display_name": "Celsius", "value": "metric"}, {"display_name": "Fahrenheit", "value": "imperial"}]},
    {"key": "EnableAlerts", "display_name": "Severe weather alerts", "type": "bool", "default": false,
     "help_text": "Post alerts in the channels that follow a city."}
  ]
}

設定の種類: bool、text、longtext、number、dropdown、radio、generated（ランダムなシークレット）、username、custom（Webアプリ部分でregisterAdminConsoleCustomSettingに登録されたコンポーネントによって描画されます）。設定はsectionsにグループ化できます。

サーバー部分は、キーと一致するフィールドを持つ構造体としてこれらを読み込みます:

type configuration struct {
	ServiceURL   string
	Units        string
	EnableAlerts bool
}

func (p *Plugin) OnConfigurationChange() error {
	var cfg configuration
	if err := p.API.LoadPluginConfiguration(&cfg); err != nil {
		return err
	}
	p.setConfiguration(&cfg)
	return nil
}

管理者は、PluginSettings.Plugins.<app id>の下で設定ファイルにも設定できます（キーは小文字。詳細は管理者ガイドを参照）。

翻訳

Antimatterは37言語に翻訳されており、バンドルアプリも同様です。Webアプリ部分は次のように行います:

  1. すべての文字列をReact Intlで記述し、IDと英語テキストを指定します: <FormattedMessage id='polls.create' defaultMessage='Create a poll'/>またはdefineMessages。IDにはアプリ名をプレフィックスとして付けます。
  2. 英語の文字列をwebapp/i18n/en.jsonに抽出します（バンドルアプリはformatjs extractを使用）。
  3. 同じIDを持つファイルを言語ごとに1つずつ隣に追加します: fr.json、de.json、pt-BR.json、zh-CN.json…
  4. Web アプリに渡します。Web アプリはユーザーの言語を要求します。 
    import fr from '../i18n/fr.json';
import ptBR from '../i18n/pt-BR.json';

const catalogs = {fr, 'pt-BR': ptBR};

export function translationsFor(locale) {
    return catalogs[locale] || catalogs[locale.split('-')[0]] || {};
}

registry.registerTranslations(translationsFor);

文字列が見つからない場合、defaultMessage の英語にフォールバックします。サーバー側が送信する文字列（コマンドの応答、ボットメッセージなど）については、pluginapi/i18n パッケージがバンドルに同梱されている翻訳ファイル（assets/i18n など）を読み込み、各ユーザーの言語に合わせたローカライザーを提供します。

ビルド、インストール、デバッグ

Go と Node.js（アプリの .nvmrc に記載されているバージョン）が必要です。アプリのフォルダ内で以下を実行します。

コマンド機能
make distすべてのプラットフォーム向けのサーバー部分と Web アプリ部分をビルドし、dist/<app id>-<version>.tar.gz にバンドルを書き出します。
make testGo と JavaScript のテストを実行します。
make check-styleコードを Lint（golangci-lint、ESLint）し、TypeScript の型チェックを実行します。
make deployビルドした後、サーバー上にバンドルをインストールして有効化します。
make watch, make deploy-from-watch前者は保存するたびに Web アプリ部分を再ビルドし、後者はビルドした内容をバンドル化してサーバーにインストールします。
make enable, make disable, make resetサーバー上のアプリを有効化、無効化、または再起動します。
make logs, make logs-watchサーバーログ内のアプリ関連の行を表示します。
make attach実行中のサーバー部分に Delve デバッガーをアタッチします（事前に AM_DEBUG=1 でビルドしてください）。

make deploy およびその他のサーバーコマンドは、ローカルモードのソケット（/var/tmp/antimatter_local.socket または AM_LOCALSOCKETPATH）が見つかった場合、それを使用します。その場合は、ローカルモードをオンにしてサーバーのマシン上で実行してください。見つからない場合は、MM_SERVICESETTINGS_SITEURL で指定されたサーバーに AM_ADMIN_TOKEN、または AM_ADMIN_USERNAME と AM_ADMIN_PASSWORD を使用してサインインします。ビルドツールは、サイト URL 用の AM_ 接頭辞付きの環境変数を読み取っていません。

バンドルを手動でインストールする

  • システム管理者は AM_PLUGINSETTINGS_ENABLEUPLOADS=true を設定することでアップロードを許可します（デフォルトでは無効で、システムコンソールには切り替えスイッチがありません）。
  • その後、システムコンソール › プラグイン › プラグイン管理 › プラグインをアップロードする を選択するか、amctl plugin add weather.tar.gz を実行した後に amctl plugin enable com.example.weather を実行します。
  • サーバーで プラグイン署名が必要 がオンになっている場合、サーバーが信頼する鍵で署名されたバンドルのみを受け入れます。その他のアプリのインストール を参照してください。
開発サーバーでの高速な反復開発のために、サーバー上で AM_SERVICESETTINGS_ENABLEDEVELOPER=true を設定してください。これにより、エラーに詳細情報が含まれるようになります。バンドルされたアプリの Makefile は、シェルで MM_SERVICESETTINGS_ENABLEDEVELOPER が設定されている場合のみ、現在のプラットフォーム向けのサーバー部分をビルドします。
