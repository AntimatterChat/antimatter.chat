Webhooks verwalten

Öffnen Sie oben rechts Ihr Profilbild und wählen Sie dann Integrationen. Die Integrationsseiten der aktuellen Community listen Eingehende Webhooks und Ausgehende Webhooks auf. Jeder Webhook gehört zu einer Community.

Standardmäßig können Community-Administratoren und Systemadministratoren Webhooks erstellen. Ein Systemadministrator kann dieses Recht in den Berechtigungseinstellungen der Systemkonsole auch anderen Rollen zuweisen. Ein Systemadministrator kann zudem jede Art von Webhook in Systemkonsole › Integrationen › Integrationsverwaltung deaktivieren: Aktiviere eingehende Webhooks und Aktiviere ausgehende Webhooks sind standardmäßig beide aktiviert.

Einen eingehenden Webhook erstellen

  1. Wählen Sie in Integrationen Eingehende Webhooks und dann Eingehenden Webhook hinzufügen.
  2. Geben Sie einen Titel und eine Beschreibung ein: Diese werden nur auf den Integrationsseiten angezeigt.
  3. Wählen Sie den Kanal, in den die Nachrichten standardmäßig gesendet werden. Für einen privaten Kanal müssen Sie Mitglied davon sein.
  4. Aktivieren Sie Auf diesen Kanal beschränken, wenn Absender nicht in anderen Kanälen posten dürfen.
  5. Setzen Sie optional einen Benutzernamen und eine Profilbild-URL für seine Nachrichten (siehe Name und Icon).
  6. Wählen Sie Speichern. Kopieren Sie die angezeigte URL: https://chat.example.com/hooks/<key>.
Die URL ist das einzige Geheimnis: Jeder, der sie hat, kann in den Kanal posten. Halten Sie sie aus öffentlichen Repositories heraus und löschen Sie den Webhook, wenn er geleakt wird.

Mit der API: POST /api/v4/hooks/incoming mit {"channel_id", "display_name", "description", "username", "icon_url", "channel_locked"}; die id in der Antwort ist der Schlüssel. Von der Kommandozeile: amctl webhook create-incoming --channel <channel id> --user <user> --display-name "CI".

Eine Nachricht an einen eingehenden Webhook senden

curl -X POST https://chat.example.com/hooks/xgh5ycrx1jf7mbs9w8z4c8e7ho \
  -H 'Content-Type: application/json' \
  -d '{"text": "Deploy of **api 2.4.0** finished :white_check_mark:"}'

Der Server antwortet mit 200 und dem Body ok. Er akzeptiert auch application/x-www-form-urlencoded mit dem JSON in einem payload-Feld, wie bei Webhooks von Slack, sodass Tools, die für Slack erstellt wurden, in der Regel ohne Änderungen funktionieren.

FeldBedeutung
textDie Nachricht in Markdown. Pflichtfeld, sofern keine attachments vorhanden sind. Texte, die das Nachrichtenlimit des Servers überschreiten, werden in mehrere Nachrichten aufgeteilt.
channelEin weiterer Kanal der Community des Webhooks, nach Name (ops-alerts oder #ops-alerts), oder @username für eine Direktnachricht vom Besitzer des Webhooks. Wird abgelehnt, wenn der Webhook auf seinen Kanal gesperrt ist.
username, icon_url, icon_emojiDer Name und das Bild, die angezeigt werden, wenn der Server Überschreibungen zulässt.
attachmentsAnhänge der Nachricht, dargestellt als Karten (unten).
propsZusätzliche Eigenschaften, die in der Nachricht gespeichert werden, für Apps, die sie auslesen.
typeEin benutzerdefinierter Nachrichtentyp, z. B. custom_poll, für eine App, die ihn darstellt. Typen, die mit system_ beginnen, werden abgelehnt.
root_idDie ID der ersten Nachricht eines Threads, um in diesem Thread zu antworten.
priorityNachrichtenpriorität, z. B. {"priority": "urgent"}.
silenttrue sendet die Nachricht ohne Push-Benachrichtigungen.

Nachrichten, die unter einem überschriebenen Namen angezeigt werden, tragen ein BOT-Symbol daneben, damit sie von echten Konten unterschieden werden können. Webhook-Nachrichten lösen niemals ausgehende Webhooks aus.

Name und Symbol

Ein Webhook postet als die Person, die ihn erstellt hat, es sei denn, der Server erlaubt Überschreibungen. Zwei Einstellungen in Systemkonsole › Integrationen › Integrationsverwaltung, beide standardmäßig deaktiviert, ändern das:

  • Erlaube Integrationen den Benutzernamen zu ändern (ServiceSettings.EnablePostUsernameOverride): Der Benutzername des Webhooks oder der username der Anfrage wird angezeigt; ohne beide wird der Name webhook verwendet.
  • Erlaube Integrationen das Profilbild zu ändern (ServiceSettings.EnablePostIconOverride): Das Profilbild des Webhooks oder das icon_url bzw. icon_emoji der Anfrage wird angezeigt.

Ein Wert in der Anfrage hat Vorrang vor dem auf dem Webhook gespeicherten Wert.

Anhänge

Anhänge fügen strukturierte Inhalte unter dem Text hinzu. Sie folgen dem Nachrichtenanhänge-Format von Slack:

{
  "text": "Build failed on `main`",
  "attachments": [{
    "fallback": "main #1902 failed",
    "color": "#d24b4e",
    "author_name": "GitHub Actions",
    "author_icon": "https://chat.example.com/static/ci.png",
    "title": "main #1902 failed",
    "title_link": "https://ci.example.com/runs/1902",
    "text": "Commit `0f4d8e2` by Jonas Weber",
    "fields": [
      {"title": "Branch", "value": "zephyr-3.7", "short": true},
      {"title": "Duration", "value": "3m 40s", "short": true}
    ],
    "footer": "Lumen CI",
    "ts": 1760000000
  }]
}
FeldBedeutung
fallbackEinfacher Text für Stellen, die die Karte nicht anzeigen können, z. B. Benachrichtigungen.
colorDie Farbleiste: eine Hex-Farbe oder good, warning, danger.
pretextText über der Karte.
author_name, author_link, author_iconEine kleine Kopfzeile.
title, title_linkDer Titel der Karte, optional ein Link.
textDer Inhalt der Karte, in Markdown.
fieldsEine Liste von {"title", "value", "short"}; short-Felder werden nebeneinander angeordnet.
image_url, thumb_urlEin großes Bild unten oder ein kleines an der Seite.
footer, footer_icon, tsEine Fußzeile und eine Zeit (Unix-Sekunden).
actionsSchaltflächen und Menüs: siehe Interaktive Nachrichten.

Karten: Stufen und Diagramme

Antimatter fügt Anhängen zwei Felder hinzu, die von der Standardoberfläche dargestellt werden:

  • stages: die Schritte einer Pipeline als Pills, bis zu 20. Jeder Schritt ist {"name", "status"} mit einem Status von passed, failed, running, pending, skipped oder canceled.
  • chart: ein kleines Liniendiagramm mit den letzten Werten, {"values": [2 to 200 numbers], "threshold": number, "label": "…"}. Der Schwellenwert wird als gestrichelte Linie dargestellt, für das Limit eines Alerts.
{
  "attachments": [{
    "color": "danger",
    "title": "main #1902 failed",
    "stages": [
      {"name": "build", "status": "failed"},
      {"name": "unit", "status": "skipped"},
      {"name": "publish", "status": "skipped"}
    ]
  }, {
    "color": "warning",
    "title": "API latency above 400 ms",
    "chart": {"values": [210, 230, 260, 390, 450, 470], "threshold": 400, "label": "p95 latency, ms"}
  }]
}

Die klassische Oberfläche und andere Clients ignorieren diese beiden Felder. Fügen Sie daher auch die wesentlichen Informationen in text oder fields ein.

Einen ausgehenden Webhook erstellen

Ein ausgehender Webhook überwacht die öffentlichen Kanäle einer Community. Wenn das erste Wort einer Nachricht mit einem seiner Auslösewörter übereinstimmt, sendet Antimatter die Nachricht an Ihre URL.

  1. Wählen Sie in Integrationen Ausgehende Webhooks und dann Ausgehenden Webhook hinzufügen.
  2. Geben Sie Titel und Beschreibung ein.
  3. Wählen Sie den Inhaltstyp der Anfrage: application/x-www-form-urlencoded oder application/json.
  4. Wählen Sie einen Kanal, geben Sie Auslösewörter (eins pro Zeile) ein oder beides. Bei einem Kanal ohne Auslösewörter wird jede Nachricht dieses Kanals gesendet. Bei beiden muss die Nachricht beide Bedingungen erfüllen.
  5. Wählen Sie unter Auslösen sobald entweder Erstes Wort entspricht exakt einem Auslösewort oder Erstes Wort startet mit dem Auslösewort.
  6. Geben Sie die Callback-URLs (eine pro Zeile) ein. Jede URL erhält jede passende Nachricht.
  7. Geben Sie optional den Benutzernamen und das Profilbild an, die für Antworten verwendet werden.
  8. Wählen Sie Speichern und kopieren Sie den angezeigten Token. Ihr Dienst verwendet ihn, um zu überprüfen, ob die Anfragen von Ihrem Server stammen.

Über die API: POST /api/v4/hooks/outgoing mit {"team_id", "channel_id", "trigger_words", "trigger_when", "callback_urls", "content_type", "display_name"} (trigger_when: 0 für exakte Übereinstimmung, 1 für "beginnt mit").

Wenn Ihr Dienst in einem privaten Netzwerk läuft, muss ein Systemadministrator dessen Adresse in Erlaube ungesicherte interne Verbindungen zu (ServiceSettings.AllowedUntrustedInternalConnections) erlauben. Andernfalls ruft der Server keine privaten Adressen auf.

Die ausgehende Anfrage

Antimatter sendet einen POST mit diesen Feldern, als JSON oder formular-kodiert, je nach Inhaltstyp:

{
  "token": "6kd1ofo5ojr5zgu5ipfipybgnc",
  "team_id": "…",
  "team_domain": "lumen-labs",
  "channel_id": "…",
  "channel_name": "ops-alerts",
  "timestamp": 1760010000000,
  "user_id": "…",
  "user_name": "priya",
  "post_id": "…",
  "text": "deploy api 2.4.0",
  "trigger_word": "deploy",
  "file_ids": ""
}

Vergleichen Sie token mit dem Token des Webhooks, bevor Sie etwas tun. In der form-kodierten Version ist timestamp in Sekunden statt in Millisekunden angegeben. Der Server wartet auf Ihre Antwort so lange, wie es Zeitüberschreitung der Integrationsanfrage zulässt (standardmäßig 30 Sekunden, ServiceSettings.OutgoingIntegrationRequestsTimeout).

Antwort auf einen ausgehenden Webhook

Um eine Antwort zu senden, antworten Sie mit JSON. Um nichts zu senden, antworten Sie mit einem leeren Body.

{
  "text": "Deploying **api 2.4.0** to staging…",
  "response_type": "comment",
  "username": "deploy-bot",
  "icon_url": "https://chat.example.com/static/deploy.png"
}
  • text und attachments: die Antwort. Ohne eines davon wird nichts gesendet.
  • response_type: comment sendet die Antwort in den Thread der auslösenden Nachricht; andernfalls wird sie in den Kanal gesendet.
  • username, icon_url: werden angezeigt, wenn der Server Überschreibungen zulässt; andernfalls werden die eigenen Werte des Webhooks verwendet.
  • props, type, priority: wie bei eingehenden Webhooks.

Die Antwort wird als Ersteller des Webhooks gesendet, unter dem überschriebenen Namen, falls vorhanden. Für alles, was länger als eine kurze Antwort ist, antworten Sie sofort und senden Sie später mit einem eingehenden Webhook oder der API.

Wenn ein Webhook nicht funktioniert

  • 501 von der Hook-URL: Eingehende Webhooks sind auf dem Server deaktiviert.
  • 400 "Failed to decode the payload…": Das JSON ist ungültig oder das Formularfeld heißt nicht payload. "No text specified." bedeutet, dass die Anfrage weder text noch attachments enthält.
  • 403: Der Webhook ist an einen anderen Kanal gebunden oder sein Besitzer kann den Kanal nicht mehr lesen.
  • Ein ausgehender Webhook wird nie ausgelöst: Der Kanal ist privat, der Trigger ist nicht das erste Wort oder die Nachricht stammt von einem Webhook.
  • Protokolle: Wenn Aktiviere Webhook-Debugging aktiviert ist (LogSettings.EnableWebhookDebugging) und das Protokolllevel auf DEBUG steht, protokolliert der Server die Nutzlasten fehlgeschlagener eingehender Anfragen. Fehlgeschlagene ausgehende Aufrufe werden als Outgoing Webhook POST failed protokolliert.
