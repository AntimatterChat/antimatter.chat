So funktioniert ein Slash-Befehl

  1. Jemand gibt /weather Paris ein und sendet es. Der Text wird nicht veröffentlicht.
  2. Antimatter sendet eine HTTP-Anfrage an die URL des Befehls, mit Angaben dazu, wer ihn eingegeben hat, wo und dem Text nach dem Triggerwort.
  3. Ihr Dienst antwortet innerhalb der Anfrage-Timeout-Zeit (standardmäßig 30 Sekunden) mit einer Nachricht.
  4. Antimatter zeigt die Antwort an: nur für diese Person (ephemeral) oder im Kanal für alle.

Befehle gehören zu einer Community, und ein Triggerwort ist innerhalb dieser eindeutig. Eingebaute Befehle wie /join, /msg oder /away können nicht ersetzt werden. Apps (Plugins) können ebenfalls Befehle registrieren; siehe Der Server-Teil.

Befehl erstellen

Benutzerdefinierte Slash-Befehle sind standardmäßig aktiviert (Aktiviere benutzerdefinierte Slash-Befehle in Systemkonsole › Integrationen › Integrationsverwaltung, ServiceSettings.EnableCommands). Community-Administratoren und Systemadministratoren können sie standardmäßig erstellen.

  1. Öffnen Sie oben rechts Ihr Avatar, dann Integrationen › Slash-Befehle, dann Slash-Befehl hinzufügen.
  2. Geben Sie Titel und Beschreibung ein (diese werden auf den Integrationsseiten angezeigt).
  3. Gib das Befehlsauslösewort ein, ohne Schrägstrich und ohne Leerzeichen, zum Beispiel weather.
  4. Gib die Anfrage-URL ein und wähle die Anforderungsmethode: POST (Standard) oder GET.
  5. Gib optional einen Benutzernamen der Antwort und ein Antwort-Symbol an. Sie werden nur verwendet, wenn der Server es Integrationen erlaubt, Namen und Symbole zu überschreiben (siehe Name und Symbol).
  6. Aktiviere Autovervollständigung, um den Befehl aufzulisten, wenn Personen / eingeben, mit einem Autovervollständigungshinweis (seine Argumente, z. B. [city]) und einer Beschreibung Autovervollständigung.
  7. Wählen Sie Speichern und kopieren Sie den angezeigten Token. Ihr Dienst verwendet ihn, um sicherzustellen, dass Anfragen von Ihrem Server stammen.

Über die API: POST /api/v4/commands mit {"team_id", "trigger", "url", "method": "P", "display_name", "description", "auto_complete": true, "auto_complete_hint", "auto_complete_desc", "username", "icon_url"}. Die Methode ist P für POST oder G für GET. PUT /api/v4/commands/{command_id}/regen_token erstellt ein neues Token.

Die Anfrage, die Ihr Dienst erhält

Ein POST-Befehl sendet einen form-kodierten Body (application/x-www-form-urlencoded); ein GET-Befehl sendet dieselben Felder in der Query-String. Das Token befindet sich außerdem im Authorization: Token <token>-Header.

FeldWert
tokenDas Token des Befehls. Prüfen Sie es bei jeder Anfrage.
commandDer Trigger mit seinem Schrägstrich, zum Beispiel /weather.
textAlles nach dem Trigger, zum Beispiel Paris.
user_id, user_nameWer ihn ausgeführt hat.
channel_id, channel_nameWo er ausgeführt wurde.
team_id, team_domainDie ID und der URL-Name des Arbeitsbereichs.
root_idDer Thread, wenn er in der Antwortbox eines Threads ausgeführt wurde.
trigger_idErmöglicht es, dass Ihre Antwort einen Dialog öffnet (siehe Dialoge). Es ist nur für kurze Zeit gültig.
response_urlEine URL, um später weitere Antworten zu senden (siehe Verspätete Antworten).
user_mentions, user_mentions_ids, channel_mentions, channel_mentions_idsDie Personen und öffentlichen Kanäle, die im Text erwähnt werden, sofern vorhanden.
Die Seiten-URL des Servers muss für die Ausführung benutzerdefinierter Befehle festgelegt sein: Antimatter erstellt response_url daraus.

Die Antwort

Antworten Sie mit 200 und JSON (Content-Type: application/json):

{
  "response_type": "in_channel",
  "text": "Paris: 18 °C, light rain",
  "attachments": []
}
FeldBedeutung
response_typeephemeral (Standard): Nur die Person, die den Befehl ausgeführt hat, sieht die Antwort, und sie wird nach einem Neuladen nicht gespeichert. in_channel: Die Antwort wird im Kanal gepostet.
text, attachmentsDie Nachricht, wie bei Webhooks: Markdown-Text und Anhänge, einschließlich Buttons und Menüs.
username, icon_urlDer Name und das Bild, die angezeigt werden sollen, wenn Überschreibungen erlaubt sind. Die eigenen Einstellungen des Befehls haben Vorrang vor diesen.
channel_idPosten Sie die Antwort in einem anderen Kanal, dessen Mitglied die Person sein muss.
goto_locationEine URL, die geöffnet werden soll, sobald der Befehl ausgeführt wurde.
props, typeZusätzliche Eigenschaften und ein benutzerdefinierter Post-Typ, wie bei Webhooks.
extra_responsesWeitere Antworten, jeweils mit denselben Feldern, die nach der ersten gepostet werden.
skip_slack_parsingtrue belässt den Text unverändert, ohne Slack-Stil-Links und Erwähnungen umzuwandeln.

Eine Antwort, die kein JSON ist, wird als ephemeral Nachricht mit dem Body als Text angezeigt. 204 No Content zeigt nichts an. Jeder Status außerhalb des Bereichs 200–299 zeigt der Person einen Fehler an.

Beispiel-Dienst

Ein minimaler Befehlsdienst in Python, nur mit der Standardbibliothek:

import hmac
import json
from http.server import BaseHTTPRequestHandler, HTTPServer
from urllib.parse import parse_qs

TOKEN = "the token shown when you saved the command"

class Handler(BaseHTTPRequestHandler):
    def do_POST(self):
        body = self.rfile.read(int(self.headers["Content-Length"])).decode()
        form = {key: values[0] for key, values in parse_qs(body).items()}
        if not hmac.compare_digest(form.get("token", ""), TOKEN):
            self.send_response(401)
            self.end_headers()
            return
        answer = {
            "response_type": "ephemeral",
            "text": f"Hello @{form['user_name']}, you asked for: {form.get('text', '')}",
        }
        data = json.dumps(answer).encode()
        self.send_response(200)
        self.send_header("Content-Type", "application/json")
        self.end_headers()
        self.wfile.write(data)

HTTPServer(("0.0.0.0", 8080), Handler).serve_forever()

Wenn der Dienst auf einer privaten Netzwerkadresse ausgeführt wird, muss ein Systemadministrator ihn unter Erlaube ungesicherte interne Verbindungen zu (ServiceSettings.AllowedUntrustedInternalConnections) erlauben.

Verzögerte Antworten

Für Arbeit, die länger dauert als die Zeitüberschreitung, antworten Sie sofort (z. B. mit einer ephemeralen Nachricht „Ich arbeite daran …“), und senden Sie dann die eigentliche Antwort per POST an response_url. Sie akzeptiert dasselbe JSON wie die Antwort und funktioniert bis zu 5-mal innerhalb von 30 Minuten nach dem Befehl.

curl -X POST "$RESPONSE_URL" -H 'Content-Type: application/json' \
  -d '{"response_type": "in_channel", "text": "Report ready: https://reports.example.com/42"}'

Befehl über die API ausführen

Skripte und Bots können jeden Befehl, eingebaut oder benutzerdefiniert, ausführen, als hätten sie ihn eingegeben:

curl -X POST https://chat.example.com/api/v4/commands/execute \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"channel_id": "'$CHANNEL_ID'", "command": "/weather Paris"}'

GET /api/v4/teams/{team_id}/commands/autocomplete listet die Befehle, die Personen in einer Community automatisch vervollständigen können.

Autovervollständigung

Befehle, die auf den Integrationsseiten erstellt werden, werden mit ihrem Trigger, ihrer Anzeige und ihrer Beschreibung automatisch vervollständigt. Von Apps registrierte Befehle können ihre Unterbefehle und Argumente mit AutocompleteData im Detail beschreiben, abgeleitet von model.NewAutocompleteData(trigger, hint, helpText):

  • AddCommand(sub) fügt einen Unterbefehl hinzu, der selbst ein AutocompleteData ist.
  • AddTextArgument(helpText, hint, pattern) fügt freien Text hinzu.
  • AddStaticListArgument(helpText, required, items) bietet eine feste Liste von AutocompleteListItem{Item, Hint, HelpText} an.
  • AddDynamicListArgument(helpText, url, required) fragt Ihre App um Vorschläge, während Personen tippen. Die URL ist eine Route Ihrer App, z. B. /plugins/com.example.weather/cities. Sie erhält Benutzer, Kanal und Community und gibt eine JSON-Liste von {"Item", "Hint", "HelpText"} zurück.

Die Named…-Varianten (AddNamedTextArgument und andere) fügen --name value-Flags hinzu. Beide Web-Oberflächen zeigen diese Vorschläge an.
