Installation mit Docker Compose

Dies ist die empfohlene Methode. Eine Compose-Datei führt Antimatter, PostgreSQL, die Dateispeicherung und den GIF-Dienst aus. Sie benötigen einen Linux-Server mit Docker Engine und dem Compose-Plugin (docker compose), 2 CPU-Kerne und 4 GB Arbeitsspeicher oder mehr.

1. Compose-Datei herunterladen

mkdir antimatter && cd antimatter
curl -fsSLO https://antimatter.chat/compose.yaml

2. .env-Datei erstellen

Die Compose-Datei liest ihre Einstellungen aus einer .env-Datei im selben Verzeichnis. Erstellen Sie diese mit zufälligen Geheimnissen:

cat > .env <<EOF
SITE_URL=http://localhost:8065
POSTGRES_PASSWORD=$(openssl rand -hex 24)
S3_SECRET_KEY=$(openssl rand -hex 24)
GIFS_API_KEY=$(openssl rand -hex 24)
EOF
chmod 600 .env

Setzen Sie SITE_URL auf die Adresse, die die Benutzer in ihrem Browser eingeben, beispielsweise http://192.168.1.20:8065 im lokalen Netzwerk oder https://chat.example.com mit einer Domain. Bewahren Sie die .env-Datei auf: Die Datenbank und die Speicherung verwenden diese Passwörter ab dem ersten Start, und Sie benötigen dieselbe Datei, um ein Backup wiederherzustellen.

3. Starten

docker compose up -d
docker compose ps

Der erste Start dauert ein oder zwei Minuten: PostgreSQL erstellt die Datenbank, ein einmaliger bucket-Dienst erstellt das Speicher-Bucket, ein einmaliger gifs-stickers-Dienst importiert das Starter-Sticker-Pack und Antimatter erstellt seine Tabellen. Verfolgen Sie den Fortschritt mit docker compose logs -f antimatter.

Um von Anfang an einen Domainnamen und HTTPS zu verwenden, siehe Domain und HTTPS: Mit der Compose-Datei sind es zwei zusätzliche Zeilen in .env und das https-Profil.

PostgreSQL, der Speicher und der GIF-Dienst befinden sich auf einem internen Netzwerk (private) ohne Internetzugang, dem nur Antimatter beitreten. Keiner von ihnen veröffentlicht einen Port.

Der Antimatter-Container speichert nichts auf der Festplatte: Seine Einstellungen befinden sich in der Datenbank (AM_CONFIG verweist darauf) und seine Dateien und Apps im Speicherdienst. Sie können den Container jederzeit entfernen und neu erstellen. Alles, was gesichert werden muss, befindet sich in den Volumes postgres, files und gifs sowie in Ihrer .env.

Ein Image auswählen

Es werden zwei Antimatter-Images veröffentlicht, beide für linux/amd64 und linux/arm64, und beide aus dem main-Branch aller Repositorien erstellt:

ImageMitgelieferte AppsTags
ghcr.io/antimatterchat/antimatterAgents, Calls, GitHub, GitLab, Jira, Kanban, Metrics und Playbooks.latest, X.Y.Z für Releases, sha-<commit>
ghcr.io/antimatterchat/antimatter-nextDasselbe, plus Sprachkanäle, Umfragen, Mail, Kalender, Notizen, Whiteboard, GIFs, Zu erledigen und Memes. Wird jede Nacht neu erstellt.latest, nightly, nightly-<YYYYMMDD>, sha-<commit>

Die Compose-Datei der Website verwendet antimatter-next, da der GIF-Dienst und die meisten auf dieser Website beschriebenen Apps nur in diesem Image enthalten sind. Um das Image zu ändern, setzen Sie ANTIMATTER_IMAGE in .env und führen Sie docker compose up -d aus.

latest ändert sich unter Ihren Füßen. In der Produktion sollten Sie ein Tag wie nightly-20261015 oder sha-<commit> festlegen und es nur absichtlich ändern, wenn Sie ein Upgrade durchführen. Der Server aktualisiert seine Datenbank beim Start, daher können Sie nicht zu einem älteren Image oder von antimatter-next zu antimatter zurückkehren, ohne zuvor ein Backup wiederherzustellen. Siehe Backups und Upgrades.

Im Inneren des Images

  • Der Server befindet sich in /antimatter, mit den Binärdateien antimatter und amctl in /antimatter/bin (auf dem PATH).
  • Er wird als nicht privilegierte Benutzer antimatter (uid 2000) auf einer minimalen distroless-Basis ausgeführt, ohne Shell.
  • Ports: 8065 (Web und API), 8067 (Metriken), 8074 (Cluster), 8443 UDP und TCP (Anrufe).
  • Der lokale Modus (ServiceSettings.EnableLocalMode) ist aktiviert, sodass amctl --local innerhalb des Containers funktioniert. Der Health-Check führt amctl system status --local aus.
  • Die mitgelieferten Apps befinden sich in /antimatter/prepackaged_plugins und sind mit dem Antimatter-App-Signierungsschlüssel signiert.
  • Textextraktionswerkzeuge (pdftotext, wvText, unrtf, tidy) sind enthalten, sodass der Inhalt hochgeladener Dokumente durchsucht werden kann.

Weitere Compose-Dateien

Das Repository antimatter-docker enthält eine Produktionsumgebung in deploy/compose/: nginx mit eigenen Zertifikaten oder Let's Encrypt (certbot), PostgreSQL, den optionalen GIF-Dienst (Profil gifs) und benannte Volumes für die Konfiguration, Daten und Protokolle des Servers, dokumentiert in der README. Standardmäßig wird das stabile Image verwendet und Dateien werden auf einem lokalen Volume statt in S3 gespeichert. Verwenden Sie diese Konfiguration, wenn Sie nginx gegenüber Caddy bevorzugen oder bereits Zertifikate besitzen.

Erstellen des ersten Administrators

Öffnen Sie SITE_URL in Ihrem Browser und erstellen Sie ein Konto. Das erste auf einem neuen Server erstellte Konto wird zum Systemadministrator. Anschließend führt die Einrichtung Sie durch die Erstellung Ihrer ersten Community (der Bezeichnung von Antimatter für ein Team oder einen Arbeitsbereich).

Führen Sie dies unmittelbar nach dem ersten Start aus: Bis dahin wird jede Person, die zuerst den Server erreicht, zu dessen Administrator. Um das Konto stattdessen über die Befehlszeile zu erstellen, bevor der Server von außen erreichbar ist:

docker compose exec antimatter amctl --local user create --system-admin --email-verified \
    --email admin@example.com --username admin --password 'a-long-password'
docker compose exec antimatter amctl --local team create --name main --display-name "Main"
docker compose exec antimatter amctl --local team users add main admin

Melden Sie sich anschließend unter SITE_URL an. Beginnen Sie den Befehl mit einem Leerzeichen, um das Passwort aus der Shell-Historie auszuschließen (mit HISTCONTROL=ignorespace), oder ändern Sie das Passwort nach der Anmeldung.

Nächste Schritte, nachdem Sie angemeldet sind:

  1. Bestimmen Sie, wer Konten erstellen darf: Anmeldung und Konten.
  2. Konfigurieren Sie die E-Mail, damit Einladungen und Passwort-Resets funktionieren: E-Mail- und Push-Benachrichtigungen.
  3. Öffnen Sie den Anruf-Port in Ihrer Firewall: Anrufe und Sprache.
  4. Prüfen Sie, welche Apps aktiviert sind: Mitgelieferte Apps.

Installation aus einem Release-Archiv

Ohne Docker wird der Server aus einem Archiv mit dem Namen antimatter-<os>-<arch>.tar.gz (z. B. antimatter-linux-amd64.tar.gz) ausgeführt. Es enthält ein einzelnes Verzeichnis antimatter/ mit bin/antimatter, bin/amctl, config/config.json, den Web-Apps (client/ und client-fusion/), den E-Mail-Vorlagen und den Übersetzungen.

1. PostgreSQL vorbereiten

Antimatter unterstützt nur PostgreSQL, Version 15 oder neuer (ältere Versionen starten mit einem Fehler in der Protokolldatei). Erstellen Sie einen Benutzer und eine Datenbank:

sudo -u postgres psql <<'EOF'
CREATE USER antimatter WITH PASSWORD 'a-long-password';
CREATE DATABASE antimatter OWNER antimatter;
EOF

2. Entpacken und konfigurieren

sudo tar -xzf antimatter-linux-amd64.tar.gz -C /opt
sudo useradd --system --user-group antimatter
sudo mkdir -p /opt/antimatter/data
sudo chown -R antimatter:antimatter /opt/antimatter

Verweisen Sie den Server auf die Datenbank, entweder in /opt/antimatter/config/config.json (SqlSettings.DataSource) oder über Umgebungsvariablen, und setzen Sie die Site-URL:

AM_SQLSETTINGS_DRIVERNAME=postgres
AM_SQLSETTINGS_DATASOURCE=postgres://antimatter:a-long-password@localhost:5432/antimatter?sslmode=disable&connect_timeout=10
AM_SERVICESETTINGS_SITEURL=https://chat.example.com

Die config.json im Archiv ist eine vollständige Standardkonfiguration: Einstellungen, die Sie in der Systemkonsole ändern, werden darin gespeichert. Um die Konfiguration stattdessen in der Datenbank zu speichern, siehe Konfiguration.

3. Als Dienst ausführen

Eine systemd-Einheit in /etc/systemd/system/antimatter.service:

[Unit]
Description=Antimatter
After=network.target postgresql.service

[Service]
Type=notify
User=antimatter
Group=antimatter
WorkingDirectory=/opt/antimatter
ExecStart=/opt/antimatter/bin/antimatter
EnvironmentFile=-/etc/antimatter.env
TimeoutStartSec=3600
Restart=always
RestartSec=10
LimitNOFILE=49152

[Install]
WantedBy=multi-user.target

Legen Sie Ihre AM_-Variablen in /etc/antimatter.env (nur für root lesbar) ab, dann:

sudo systemctl daemon-reload
sudo systemctl enable --now antimatter
journalctl -u antimatter -f

Der Server lauscht auf Port 8065. Öffnen Sie http://<server>:8065 oder Ihre Domain, sobald ein Reverse Proxy eingerichtet ist (siehe Domain und HTTPS), und erstellen Sie das erste Konto: Es wird zum Systemadministrator.

bin/amctl verwaltet den laufenden Server von der Kommandozeile. Auf dem Server selbst funktioniert es ohne Anmeldung über den lokalen Modus: Setzen Sie AM_SERVICESETTINGS_ENABLELOCALMODE=true und führen Sie dann sudo -u antimatter /opt/antimatter/bin/amctl --local system status aus.

Weitere Serverbefehle

Neben dem Ausführen des Servers (antimatter oder antimatter server) bietet die Binärdatei einige Wartungsbefehle. Sie lesen dieselbe Konfiguration wie der Server.

BefehlFunktion
antimatter versionGibt die Version, die Build-Nummer, das Baudatum und den Build-Hash aus.
antimatter db pingPrüft, ob die Datenbank erreichbar ist.
antimatter db initErstellt die Konfiguration in der Datenbank (mit AM_CONFIG auf eine postgres://-URL gesetzt).
antimatter db migrateWendet die Datenbankmigrationen an, ohne den Server zu starten.
antimatter db versionGibt die zuletzt auf die Datenbank angewendete Migration aus.
antimatter import bulk, antimatter export bulkImportiert oder exportiert Daten im Bulk-Format (siehe Backups und Upgrades).
