So funktionieren Anrufe

Anrufe werden von der App Calls (id com.mattermost.calls) bereitgestellt, die standardmäßig installiert und aktiviert ist. Sprachkanäle (die App Voice Channels, antimatter-next-Image) sind permanente Anrufräume auf Basis von Calls: Sie erfordern, dass Calls aktiviert ist, und verwenden dieselben Einstellungen, Ports und Server.

Die Calls-App betreibt einen Medienserver innerhalb von Antimatter. Die Web-App, die Desktop-App und die mobilen Apps verbinden sich mit diesem über WebRTC:

  • das Signaling läuft über die normale Webverbindung (Ihr HTTPS-Proxy);
  • die Medien (Audio, Video, Bildschirmfreigabe) nicht: Sie gehen direkt an den Server über den Anruf-Port, standardmäßig 8443 UDP und TCP.

Die Einstellungen befinden sich unter Systemkonsole › Plugins › Calls. Jede einzelne kann auch über eine AM_CALLS_-Umgebungsvariable im antimatter-Dienst gesetzt werden, die dann Vorrang vor der Systemkonsole hat und die Einstellung dort sperrt. Die veralteten MM_CALLS_-Namen funktionieren ebenfalls.

Prüfen Sie dies nach der Installation

  1. Öffnen Sie den Anruf-Port. Erlauben Sie 8443/udp und 8443/tcp in der Firewall des Servers und Ihres Cloud-Anbieters.
  2. Schalten Sie den Testmodus aus. Test mode (DefaultEnabled) ist standardmäßig aktiviert: Nur Systemadministratoren können Anrufe in Kanälen starten, damit Sie überprüfen können, ob Anrufe funktionieren, bevor sie von allen genutzt werden. Setzen Sie dies in Systemkonsole › Plugins › Calls auf Aus oder setzen Sie AM_CALLS_DEFAULT_ENABLED=true.
  3. Entscheiden Sie sich für Video. Enable video calls in DMs (Experimental) (EnableVideo, AM_CALLS_ENABLE_VIDEO) ist standardmäßig deaktiviert. Solange es deaktiviert ist, kann niemand eine Kamera einschalten, auch nicht in Sprachkanälen. Wenn es aktiviert ist, funktionieren Kameras in Anrufen über Direktnachrichten und in Sprachkanälen (außer, wenn Allow video in voice channels der Voice-Channels-App deaktiviert ist).
  4. Hinter NAT die öffentliche Adresse festlegen (nächster Abschnitt).

Die Adresse, an die die Clients die Medien senden

Der Server teilt jedem Client die Adresse mit, an die dieser die Medien senden soll (sein „Host-Kandidat“). Standardmäßig ermittelt er seine öffentliche Adresse, indem er einen STUN-Server abfragt, einen öffentlichen Dienst, der die Adresse und den Port zurückgibt, von denen eine Anfrage stammt. Standardmäßig wird der öffentliche STUN-Server von Cloudflare verwendet, stun:stun.cloudflare.com:3478. Der Server ist nicht der Einzige, der ihn nutzt: Jeder Client, der einem Anruf beitritt, fragt ihn ebenfalls nach seiner eigenen öffentlichen Adresse ab. Der STUN-Server sieht nur IP-Adressen und Ports, niemals Audio, Video oder Nachrichten aus Anrufen.

Ein Server, in dessen Konfiguration der ICE-Server noch der STUN-Server von Mattermost (stun.global.calls.mattermost.com) gespeichert ist, zum Beispiel nach einem Wechsel von Mattermost, verwendet stattdessen den von Cloudflare. Die gespeicherte Einstellung wird nicht geändert.

Setzen Sie die Adresse manuell, wenn:

  • der Server hinter einer NAT liegt oder mehrere öffentliche Adressen hat: Setzen Sie ICE-Host-Override auf die öffentliche IP-Adresse (oder einen Hostnamen, der darauf aufgelöst wird);
  • die NAT einen anderen öffentlichen Port auf 8443 abbildet: Setzen Sie auch ICE-Host-Port-Override auf diesen öffentlichen Port;
  • der Server keinen Internetzugang hat oder Sie nicht möchten, dass der Server und die Clients einen externen STUN-Server kontaktieren: Setzen Sie ICE-Host-Override und leeren Sie die STUN-Liste mit AM_CALLS_ICE_SERVERS_CONFIGS=[]. Wenn ICE-Host-Override gesetzt ist, fragt der Server keinen STUN-Server mehr nach seiner Adresse ab; die leere Liste verhindert, dass die Clients einen abfragen.
services:
  antimatter:
    environment:
      AM_CALLS_ICE_HOST_OVERRIDE: 203.0.113.10
      AM_CALLS_ICE_SERVERS_CONFIGS: "[]"

Um STUN ohne Drittanbieter zu nutzen, betreiben Sie einen eigenen STUN-Server (ein TURN-Server wie coturn beantwortet ebenfalls STUN-Anfragen) und listen Sie ihn in der Konfiguration der ICE-Server auf, wie im TURN-Beispiel unten.

Verwenden Sie in einem rein lokalen Netzwerk die LAN-Adresse des Servers. Starten Sie den Server neu, nachdem Sie Ports, Adressen oder ICE-Einstellungen geändert haben, oder deaktivieren und aktivieren Sie die Calls-App: Der Medien-Server wird beim Start der App eingerichtet.

TURN für strenge Firewalls

Manche Netzwerke blockieren sowohl UDP als auch ausgehende Verbindungen zu ungewöhnlichen TCP-Ports. Nutzer in solchen Netzen benötigen einen TURN-Server, der die Medien über einen erreichbaren Port (oft 443) weiterleitet. Antimatter enthält keinen; betreiben Sie einen TURN-Server wie coturn und fügen Sie ihn zu ICE Servers Configurations hinzu, einer JSON-Liste:

[
  {"urls": ["stun:turn.example.com:3478"]},
  {"urls": ["turn:turn.example.com:3478?transport=udp", "turns:turn.example.com:443?transport=tcp"]}
]
  • Bei Verwendung eines gemeinsamen Geheimnisses (coturns use-auth-secret) geben Sie dasselbe Geheimnis in TURN Static Auth Secret (AM_CALLS_TURN_STATIC_AUTH_SECRET) ein: Der Server stellt jedem Client kurzlebige Zugangsdaten aus, die für die Dauer von TURN Credentials Expiration (minutes) (Standard: 240) gültig sind.
  • Bei festen Zugangsdaten fügen Sie stattdessen "username" und "credential" zum TURN-Eintrag hinzu.
  • Server Side TURN (standardmäßig deaktiviert) verwendet die TURN-Server auch für Verbindungen, die vom Server initiiert werden.

Größere Server: ein externes rtcd

Standardmäßig verarbeitet ein Antimatter-Server alle Anrufmedien. Bei vielen gleichzeitigen Anrufen oder um die Medien vom Chatserver fernzuhalten, kann die Calls-App die Medien an rtcd weitergeben, einen separaten Medienserver (Mattermosts Open-Source-rtcd, Version 0.17 oder neuer). Setzen Sie RTCD service URL (AM_CALLS_RTCD_SERVICE_URL), zum Beispiel https://rtcd.example.com: Alle Anrufe laufen dann darüber, und Clients senden ihre Medien an den eigenen Port von rtcd statt an den von Antimatter. Zugangsdaten können mit AM_CALLS_RTCD_CLIENT_ID und AM_CALLS_RTCD_AUTH_KEY angegeben werden; ohne diese registriert sich die App selbst bei rtcd. Eine Lizenz ist nicht erforderlich. Die Calls-App zeigt Administratoren eine Warnung an, die rtcd empfiehlt, wenn auf einem Server häufig mehr als 50 Personen gleichzeitig in Anrufen sind.

Transkription und Live-Untertitel

Antimatter kann Anrufe mit einem von Ihnen selbst betriebenen Speech-to-Text-Modell transkribieren und während des Sprechens Live-Untertitel anzeigen. Antimatter verwendet jeden Server, der einen OpenAI-kompatiblen /v1/audio/transcriptions-Endpunkt anbietet, wie zum Beispiel einen Whisper-Server in Ihrem Netzwerk. Ein zusätzlicher Dienst von Antimatter ist nicht erforderlich.

So funktioniert es

  • Der Host eines Anrufs startet die Transkription mit Anruf transkribieren in den Anrufsteuerungen. Ein Wird transkribiert-Badge informiert alle Teilnehmer.
  • Die App jedes Teilnehmers lauscht auf das eigene Mikrofon, schneidet die Sprache in kurze Abschnitte (maximal 12 Sekunden, nie während der Stummschaltung) und sendet sie an Antimatter, die sie an Ihren Speech-to-Text-Server weiterleitet.
  • Wenn Live-Untertitel aktiviert sind, wird der Text jedes Abschnitts den Teilnehmern sofort als Untertitel angezeigt.
  • Wenn die Transkription gestoppt oder der Anruf beendet wird, postet der Calls-Bot das Transkript als Textdatei und WebVTT-Untertiteldatei im Thread des Anrufs (in Sprachkanälen im Kanal).
  • Wenn Transkriptionen zusammenfassen aktiviert ist, postet der Standard-Agent der Agents-App auch eine Zusammenfassung im Thread (siehe KI).

Einrichtung

Richten Sie dies auf dem antimatter-Dienst ein:

services:

      AM_CALLS_LIVE_CAPTIONS_LANGUAGE: en

In der Systemkonsole erscheinen die Transkriptionseinstellungen nur, wenn Anrufaufnahmen aktivieren aktiviert ist, obwohl diese Art der Transkription keine Aufnahme erfordert. Die Festlegung über die oben genannten Variablen vermeidet dies. Schalten Sie Aufnahmen nicht zusammen mit dem openai-Transkriber ein: Der Start einer Aufnahme würde dann versuchen, den Job-Service-Transkriber zu starten, was fehlschlagen würde.

Das Audio aller Personen, die während der aktiven Transkription sprechen, wird an den von Ihnen konfigurierten Speech-to-Text-Server gesendet, und das Transkript wird dort veröffentlicht, wo es alle im Kanal lesen können. Informieren Sie Ihre Benutzer und halten Sie diesen Server in Ihrem eigenen Netzwerk, wenn die Anrufe vertraulich sind.

Aufnahmen

Die Aufnahme von Anrufen (und die Transkription mit den integrierten whisper.cpp- oder Azure-Transkribern) wird in separaten Containern ausgeführt, die von einem Job-Service gestartet werden: Mattermosts Open-Source-Projekt calls-offloader, das Sie selbst neben Antimatter bereitstellen. Die Einstellungen sind Anrufaufnahmen aktivieren (AM_CALLS_ENABLE_RECORDINGS, standardmäßig deaktiviert), Job-Service-URL (AM_CALLS_JOB_SERVICE_URL), Maximale Dauer der Anrufaufnahme (standardmäßig 60 Minuten, zwischen 15 und 180) und Qualität der Anrufaufnahme (niedrig, mittel oder hoch; standardmäßig mittel). Es wird keine Lizenz benötigt. Für nur Transkriptionen und Untertitel ist die oben beschriebene Speech-to-Text-Konfiguration einfacher: Sie benötigt keinen Job-Service.
