AI

Antimatter-এর AI ফিচারগুলো আপনার বেছে নেওয়া মডেল ব্যবহার করে: একটি ক্লাউড প্রোভাইডার, অথবা আপনার নিজের নেটওয়ার্কে থাকা একটি সার্ভার। আপনি যতক্ষণ না একটি মডেল কনফিগার করেন, ততক্ষণ কিছুই কোথাও পাঠানো হয় না। এই পেজে মডেল কানেকশন, প্রতিটি ফিচার, যে ডেটা পাঠানো হয় এবং সেটি বন্ধ করার পদ্ধতি নিয়ে আলোচনা করা হয়েছে।

AI ফিচারসমূহ

ফিচারকোথায় কনফিগার করা হয়মডেলের ধরনডিফল্টভাবে চালু আছে কি না
কম্পোজারে রিসাইট: পাঠানোর আগে একটি ম্যাসেজ উন্নত করুন, ছোট করুন, সংশোধন করুন বা অনুবাদ করুনAI › বিল্ট-ইন ফিচার, একটি মডেল কানেকশনসহএকটি চ্যাট মডেল (LLM)না
রিক্যাপ: মানুষের বেছে নেওয়া চ্যানেলসমূহের সারসংক্ষেপAI › বিল্ট-ইন ফিচার, একটি মডেল কানেকশনসহএকটি চ্যাট মডেল (LLM)না
চ্যানেলসমূহের স্বয়ংক্রিয় অনুবাদসাইট কনফিগারেশন › লোকালাইজেশনএকটি মডেল কানেকশন, LibreTranslate অথবা একটি OpenAI-সম্পাদিত APIনা
Read aloudইন্টিগ্রেশনসমূহ › টেক্সট টু স্পিচ, ঐচ্ছিকভাবে একটি মডেল কানেকশনসহText-to-speech, OpenAI-compatibleনা
AI এজেন্ট: একটি বটের সাথে চ্যাট, থ্রেডসমূহের সারসংক্ষেপ, কলের সারসংক্ষেপThe Agents appযেকোনো লার্জ ল্যাঙ্গুয়েজ মডেল (LLM) সার্ভিসঅ্যাপটি চালু আছে, তবে আপনি যতক্ষণ একটি সার্ভিস যোগ করেন না ততক্ষণ এটি কিছুই করে না
কলের ট্রান্সক্রিপশন এবং লাইভ ক্যাপশনThe Calls appSpeech-to-text, OpenAI-compatibleনা

"OpenAI-সম্পাদিত" বলতে এমন একটি সার্ভারকে বোঝায় যা OpenAI-এর মতো একই HTTP API প্রদান করে। বেশিরভাগ মডেল সার্ভার যা আপনি নিজে চালান তা এটি করে (যেমন Ollama, vLLM, llama.cpp-এর সার্ভার, অথবা Whisper এবং টেক্সট-টু-স্পিচ সার্ভার), এবং LiteLLM বা OpenRouter-এর মতো অনেক ক্লাউড প্রোভাইডার ও গেটওয়েও এটি করে। এই ফিচারগুলোর জন্য কোনো লাইসেন্সের প্রয়োজন নেই।

বিল্ট-ইন ফিচারগুলো (রিসাইট, রিক্যাপ, ট্রান্সলেশন এবং রিড অ্যালউড) Agents অ্যাপের প্রয়োজন নেই: তারা মডেল কানেকশন ব্যবহার করে যা আপনি System Console-এ যোগ করেন।

মডেল কানেকশন

একটি মডেল কানেকশন হলো এমন একটি AI প্রোভাইডার যাকে Antimatter কল করতে পারে: এর ঠিকানা, এর কী এবং এর মডেলসমূহ। আপনি একবার এটি যোগ করেন, তারপর প্রতিটি ফিচারের জন্য বেছে নেন যেটি এটি ব্যবহার করবে। এর দুটি ধরন আছে:

  • সার্ভার-ওয়াইড কানেকশন, যা সিস্টেম অ্যাডমিনরা System Console › AI › মডেল কানেকশন-এ পরিচালনা করেন। শুধুমাত্র তারা বিল্ট-ইন ফিচারগুলোর সেবা দিতে পারে। অ্যাপগুলোও এগুলোর ব্যবহার করতে পারে, যাদের অনুমতি আছে তাদের জন্য।
  • কমিউনিটি কানেকশন, যা একটি কমিউনিটির অ্যাডমিনরা তাদের নিজের কমিউনিটির জন্য কমিউনিটির সেটিংসে যোগ করেন (দেখুন নিচে)। অ্যাপগুলো কমিউনিটির মানুষদের জন্য এগুলোর ব্যবহার করে। তারা কখনোই বিল্ট-ইন ফিচারগুলোর সেবা দেয় না।

System Console-এর AI সেকশনটি সেই মানুষদের দেখায় যারা সার্ভার-ওয়াইড কানেকশন পরিচালনা করতে পারেন: ডিফল্টভাবে সিস্টেম অ্যাডমিনরা। এর মডেল কানেকশন পেজে সার্ভার-ওয়াইড কানেকশন এবং প্রতিটি কমিউনিটির কানেকশন তালিকাভুক্ত থাকে।

একটি কানেকশন যোগ করুন

System Console › AI › মডেল কানেকশন-এ, একটি কানেকশন যোগ করুন-এ ক্লিক করুন, তারপর ফর্মটি পূরণ করুন:

ফিল্ডকী বসাতে হবে
প্রিসেটএকটি পরিচিত সার্ভিসের প্রোভাইডার এবং ঠিকানা পূরণ করে: OpenAI, Mistral, Gemini, OpenRouter, অথবা সার্ভারের নিজের ওপর থাকা Ollama এবং LiteLLM। এটি ঐচ্ছিক।
নামঅ্যাডমিনরা যখন এটি বেছে নেবেন তখন তারা যে নামটি দেখবেন, যেমন "Company OpenAI"।
প্রোভাইডারOpenAI-compatible (যেমন আপনি নিজে চালানো বেশিরভাগ প্রোভাইডার, গেটওয়ে এবং মডেল সার্ভার) অথবা Anthropic। নিজস্ব সাইন-ইন সহ ক্লাউড সার্ভিস, যেমন AWS Bedrock, Google Vertex AI বা Entra ID সহ Azure, তাদের নিজস্ব OpenAI-compatible এন্ডপয়েন্ট বা LiteLLM-এর মতো কোনো গেটওয়ের মাধ্যমে যুক্ত হয়।
Base URLAPI-এর ঠিকানা, /v1 পর্যন্ত, যেমন http://ollama:11434/v1। খালি রাখলে এটি প্রোভাইডারের নিজস্ব ঠিকানা (https://api.openai.com/v1 বা https://api.anthropic.com/v1)।
API কীপ্রোভাইডারের কী। যদি এন্ডপয়েন্টে কোনো কী না লাগে তবে এটি খালি রাখুন। এটি এনক্রিপ্ট করা অবস্থায় সংরক্ষিত থাকে এবং কখনোই আবার দেখানো হয় না: ফর্মে শুধুমাত্র এর শেষ চারটি অক্ষর দেখানো হয়, এবং এটি রাখা, পরিবর্তন করা বা মুছে ফেলার অপশন দেওয়া হয়।
Extra headersপ্রতিটি রিকোয়েস্টের সাথে পাঠানোর জন্য হেডার, যে গেটওয়েগুলোর জন্য এটি প্রয়োজন। কীর মতো এগুলোর মানও এনক্রিপ্ট করা অবস্থায় সংরক্ষিত থাকে এবং কখনোই আবার দেখানো হয় না: পরিবর্তন করতে হলে সবগুলো আবার টাইপ করতে হবে।
মডেলসমূহযখন কোনো ফিচার বা অ্যাপ কোনো নির্দিষ্ট মডেলের নাম উল্লেখ করে না, তখন প্রতিটি ক্ষমতার জন্য যে মডেল ব্যবহার হবে: চ্যাট, Embeddings, ট্রান্সক্রিপশন এবং Decisions। Load models এন্ডপয়েন্টটি যেসব মডেল অফার করে তা তালিকাভুক্ত করে। যদি এন্ডপয়েন্ট কোনো নির্দিষ্ট ক্ষমতা অফার না করে তবে সেই ক্ষমতার জন্য খালি রাখুন। Anthropic কানেকশন শুধুমাত্র চ্যাট করতে পারে।
Decisions APIডিসিশন মডেলটি কীভাবে কল করা হয়: OpenAI decisions অথবা SystemOne। শুধুমাত্র সেই অ্যাপগুলোর জন্য এটি গুরুত্বপূর্ণ যা ডিসিশন চায়।
সীমাবদ্ধতাদেখুন সীমাবদ্ধতা এবং বাজেট।
কমিউনিটিসমূহশুধুমাত্র সার্ভার-ওয়াইড কানেকশনের জন্য। সব কমিউনিটি: প্রতিটি কমিউনিটিতে এবং ডাইরেক্ট ও গ্রুপ মেসেজে ব্যবহারযোগ্য। অন্যথায়, শুধুমাত্র আপনি যে কমিউনিটিগুলো বেছে নেবেন সেখানে ব্যবহারযোগ্য।
কে এটি ব্যবহার করতে পারবেযেখানে এটি ব্যবহারযোগ্য সেখানে সবাই, অথবা শুধুমাত্র আপনি যে টিম (কমিউনিটির ভেতরের মানুষের দল) এবং রোল (সিস্টেম অ্যাডমিন, কমিউনিটি অ্যাডমিন) বেছে নেবেন। অতিথিরাও চাইলে অতিথিরা এটি ব্যবহার করতে পারবে; না থাকলে, এমনকি সবাই থাকলেও, অতিথিরা এটি ব্যবহার করতে পারবে না।

কানেকশন টেস্ট ঠিকানা এবং কী পরীক্ষা করে: সার্ভার এন্ডপয়েন্ট থেকে তার মডেলসমূহ চায়, অথবা একটি টোকেনের চ্যাট পাঠায়। পরিবর্তিত ঠিকানাটি শুধুমাত্র আপনি সেভ করার পরে বা আপনি কীটি আবার টাইপ করলে সংরক্ষিত কী দিয়ে পরীক্ষা করা হয়। সেভ করতে Add connection ক্লিক করুন।

সার্ভার নিজেই রিকোয়েস্ট পাঠায়, তাই এটির API-তে পৌঁছাতে হবে: একই কম্পোজ প্রজেক্টের একটি মডেল সার্ভার, আপনার নেটওয়ার্কে, বা ইন্টারনেটে। আউটগোয়িং রিকোয়েস্ট HTTP_PROXY এবং HTTPS_PROXY ভ্যারিয়েবল মেনে চলে।

একটি কানেকশন মুছে ফেললে তার কী ভুলে যায়। যে ফিচারগুলো এটি ব্যবহার করছিল, আপনি অন্য কোনো কানেকশন বেছে না নেওয়া পর্যন্ত তারা আর AI ব্যবহার করবে না।

সীমা এবং বাজেট

প্রতিটি কানেকশনের চারটি সীমা রয়েছে। খালি বা 0 মানে কোনো সীমা নেই।

  • প্রতি মিনিটে রিকোয়েস্ট এবং প্রতি ব্যক্তির জন্য, প্রতি মিনিটে রিকোয়েস্ট। এগুলো প্রতিটি সার্ভার আলাদাভাবে গণনা করে: তিনটি সার্ভারের একটি ক্লাস্টার সর্বোচ্চ তিন গুণ হারে রিকোয়েস্ট পাশ করে দিতে পারে।
  • প্রতি মাসে টোকেন এবং প্রতি ব্যক্তির জন্য, প্রতি মাসে টোকেন: টোকেন বাজেট, প্রতি ক্যালেন্ডার মাসে (UTC), পুরো ক্লাস্টারের জন্য ডাটাবেসে গণনা করা হয়। একই সময়ে চলমান একাধিক রিকোয়েস্ট বাজেটের সামান্য বেশি হতে পারে।

প্রতি ব্যক্তির সীমাগুলো পুনর্লিখন এবং রি-ক্যাপসমূহের ক্ষেত্রেও প্রযোজ্য: এগুলো সেই ব্যক্তির বিরুদ্ধে গণনা করা হয় যিনি পুনর্লিখন করেন, অথবা যিনি রি-ক্যাপের মালিক।

ব্যবহার

তালিকায় এই মাসে প্রতিটি কানেকশনের ব্যবহার দেখানো হয়। ব্যবহার খুললে বিস্তারিত দেখা যায়: ইন এবং আউট টোকেন, রিকোয়েস্ট, মাসিক বাজেট, প্রতিদিনের (UTC) এবং ব্যবহারের ধরন অনুযায়ী (পুনর্লিখন, রি-ক্যাপসমূহ, অটো-অনুবাদ, টেক্সট টু স্পিচ, ব্যক্তি, অ্যাপসের মাধ্যমে, বা কোনো অ্যাপ) ব্যবহার।

একটি ব্যক্তি বা অ্যাপ যেকোনো কানেকশনের মাধ্যমে যে কল করে, তার জন্য একটি অডিট রেকর্ডও লেখা হয়: কে, কোন কানেকশন, কোন ব্যবহার, কোন মডেল, টোকেনের সংখ্যা এবং এটি সফল হয়েছে কিনা, কখনোই কী বলা হয়েছে তা নয়। বিল্ট-ইন ফিচারগুলো শুধুমাত্র ব্যবহার হিসেবে গণনা করা হয়: অনুবাদ মাত্র একটি মাসে প্রতিটি ম্যাসেজ এবং ভাষার জন্য একটি কল করে।

কমিউনিটি কানেকশন

কমিউনিটি অ্যাডমিনরা কমিউনিটির সেটিংসে, মডেল কানেকশন ট্যাবে তাদের কমিউনিটির নিজস্ব কানেকশন যোগ করেন। ফর্মটি একই, তবে কমিউনিটিসমূহ ছাড়া: একটি কমিউনিটির কানেকশন শুধুমাত্র তার নিজস্ব চ্যানেলসমূহে, তার নিজস্ব সদস্যদের জন্য কাজ করে, এবং তার অডিয়েন্স শুধুমাত্র তার নিজস্ব টিমগুলোর নাম দিতে পারে। মডেল কানেকশন পরিচালনা পারমিশনযুক্ত রোলগুলোও এগুলো পরিচালনা করতে পারে। ডিফল্টভাবে, কমিউনিটি অ্যাডমিনরা এটি পেয়ে থাকেন।

একটি কমিউনিটির কানেকশন প্রাইভেট বা লুপব্যাক ঠিকানায় (যেমন, আপনার নেটওয়ার্কে একটি Ollama সার্ভার) পৌঁছাতে পারে না, যদি না সিস্টেম কনসোল › এনভাইরনমেন্ট › ডেভেলপার › অপপ্রমাণিত অভ্যন্তরীণ সংযোগ অনুমোদন করুন (ServiceSettings.AllowedUntrustedInternalConnections) তালিকায় তারা থাকে। সার্ভার-ওয়াইড কানেকশনগুলো এতে পৌঁছাতে পারে।

কমিউনিটি অ্যাডমিনদের দিকটি দেখতে কমিউনিটি সেটিংস দেখুন।

এনক্রিপশন কী

মডেল সংযোগের কী এবং বাড়তি হেডারগুলো ডাটাবেসে (AES-256-GCM) একটি এনক্রিপশন কী দিয়ে এনক্রিপ্ট করা থাকে। শুধুমাত্র ডাটাবেসের ব্যাকআপ থেকে এগুলো বের করা যায় না। সার্ভার এই ক্রমে কী খোঁজে:

  1. AM_AI_ENCRYPTION_KEY ভেরিয়েবল: base64-এ ৩২ র‍্যান্ডম বাইট। openssl rand -base64 32 দিয়ে একটি তৈরি করুন।
  2. নইলে, সার্ভারের ডাটা ডিরেক্টরির (FileSettings.Directory, ডিফল্ট ./data/) রুটে ai-encryption.key ফাইল। প্রথমবার যখন কোনো সংযোগের কী দরকার হয়, তখন সার্ভার এটি তৈরি করে, যা শুধুমাত্র নিজের পড়তে পারে। অ্যাপস, এক্সপোর্ট এবং ফাইল আর্কাইভ এটি পড়তে পারে না।
কী ছাড়া সংরক্ষিত API কীগুলো পড়া যায় না, এবং প্রতিটি সংযোগের জন্য আবার তার কী দিতে হয়। ডাটাবেসের সাথে কীটির ব্যাকআপ নিন (ব্যাকআপ এবং আপগ্রেড দেখুন), এবং ডাটাবেস ব্যাকআপ থেকে এটি আলাদা রাখুন।

কখন ভেরিয়েবল সেট করতে হবে:

  • সাইটের compose ফাইলের সাথে। compose.yaml .env থেকে AM_AI_ENCRYPTION_KEY পাঠায়, এবং ভেরিয়েবল খালি থাকলে data ভলিউমে কী ফাইলটি রাখে। ভেরিয়েবল সেট করা ভালো: তখন .env-এর ব্যাকআপে কীটি থাকে, ডাটাবেস থেকে আলাদা। এটি .env-এ যোগ করুন এবং docker compose up -d চালান: 
    echo "AM_AI_ENCRYPTION_KEY=$(openssl rand -base64 32)" >> .env
    যদি সার্ভার আগে থেকেই তার কী ফাইল তৈরি করে থাকে, তবে সংরক্ষিত কীগুলো পড়ার জন্য .env-এ সেই কীটি বসান: docker compose exec antimatter cat /antimatter/data/ai-encryption.key এটি প্রিন্ট করবে।
  • S3-এ ফাইল থাকা ক্লাস্টার। এর সার্ভারগুলো কোনো ডিরেক্টরি শেয়ার করে না, তাই সার্ভার ফাইল তৈরি করে না: প্রতিটি সার্ভারে একই ভেরিয়েবল সেট করুন। সেট না হওয়া পর্যন্ত সংযোগগুলো কী সংরক্ষণ করতে পারে না।
  • রিলিজ আর্কাইভ বা প্যাকেজের ক্ষেত্রে, ফাইলটি data/-এ থাকে (প্যাকেজের জন্য /var/lib/antimatter/data)। আপনি এটি সেখানে রাখতে পারেন, অথবা আপনার এনভায়রনমেন্ট ফাইলে ভেরিয়েবল সেট করতে পারেন।

কী পরিবর্তন করতে, নতুনটি AM_AI_ENCRYPTION_KEY-এ এবং পুরোনোটি AM_AI_ENCRYPTION_PREVIOUS_KEYS-এ (কমা দিয়ে আলাদা করা একাধিক কী) সেট করুন: পুরোনো কী দিয়ে সংরক্ষিত কীগুলো এখনো পড়া যাবে। আপনি আবার টাইপ করলে সংযোগের কী নতুন কী দিয়ে এনক্রিপ্ট হবে। প্রতিটি সংযোগের কী আবার টাইপ না হওয়া পর্যন্ত পুরোনো কীটি তালিকায় রাখুন।

বিল্ট-ইন ফিচারসমূহ

সিস্টেম কনসোল › AI › Built-in features-এ, প্রতিটি ফিচারের জন্য একটি সার্ভার-ওয়াইড কানেকশন এবং এর মডেল নির্বাচন করুন, অথবা বন্ধ নির্বাচন করুন। কোনো কানেকশন ছাড়া একটি ফিচার AI ব্যবহার করে না। Load models কানেকশনের সমস্ত মডেল তালিকাভুক্ত করে; ডিফল্টভাবে প্রতিটি ফিচার কানেকশনের চ্যাট মডেল ব্যবহার করে।

ফিচারসেটিংএর জন্য আরও যা প্রয়োজন
Rewrite in the composer: মেসেজ বক্সের AI মেনু (improve, shorten, fix, translate)AISettings.Rewriteকিছুই নয়: একটি কানেকশন নির্বাচিত হলে মেনুটি দেখা যায়।
রি-ক্যাপসমূহ: মানুষেরা যে চ্যানেলসমূহ বেছে নেয়, তাদের সারসংক্ষেপ, চাহিদা অনুযায়ী বা নির্দিষ্ট সময়সূচি অনুযায়ীAISettings.Recapsসিস্টেম কনসোল › সাইট কনফিগারেশন › রি-ক্যাপসমূহ-এ AI রিক্যাপ সক্রিয় করুন (ডিফল্টভাবে অন), যা মানুষ কতগুলো রিক্যাপ তৈরি করতে পারে তাও নির্ধারণ করে।
অটো-অনুবাদAISettings.AutoTranslationAutomatic translation-এ অনুবাদ প্রোভাইডার Model connection (recommended)।
টেক্সট টু স্পিচAISettings.TextToSpeechText-to-speech-এ ম্যাসেজ শুনুন অন করুন। কানেকশনের /audio/speech এন্ডপয়েন্ট সেখানে সেট করা ঠিকানা এবং কী-কে প্রতিস্থাপন করে।

প্রতিটি সেটিং-এর একটি ConnectionId এবং একটি Model কী রয়েছে, যেমন AISettings.Rewrite.ConnectionId (AM_AISETTINGS_REWRITE_CONNECTIONID)। একটি খালি Model কানেকশনের ডিফল্ট মডেল ব্যবহার করে।

Built-in ফিচারগুলো কানেকশনের সীমাবদ্ধতা ব্যবহার করে, কিন্তু এর অডিয়েন্স নয়: যে কেউ ফিচারটি ব্যবহার করতে পারে, সে তার কানেকশন ব্যবহার করতে পারে। একটি কানেকশন যদি মনোযোগের প্রয়োজন হয়, অথবা মুছে ফেলা হয়, তবে আপনি অন্য একটি নির্বাচন না করা পর্যন্ত ফিচারটি ব্যর্থ হবে: পেজটি তা উল্লেখ করে।

AI এজেন্ট

এজেন্টসমূহ অ্যাপ (id mattermost-ai) ডিফল্টভাবে চালু থাকে। সেটআপ করার জন্য দুইটি ধাপ অনুসরণ করতে হবে: প্রথমে একটি সার্ভিস (মডেল প্রোভাইডারের সাথে সংযোগ) যোগ করুন, তারপর এজেন্টসমূহ (যে সার্ভিস ব্যবহার করে) তৈরি করুন।

Agents অ্যাপের এজেন্টসমূহ এখনও অ্যাপের নিজস্ব AI Services ব্যবহার করে, মডেল কানেকশন নয়। Built-in ফিচারগুলো আর অ্যাপের মাধ্যমে যায় না। 0.9.0-এ আপগ্রেড করা সার্ভারে, অ্যাপের সার্ভিসগুলো একবার সার্ভার-ওয়াইড মডেল কানেকশনে কপি করা হয়েছিল (দেখুন Upgrading to 0.9.0)।

১. একটি সার্ভিস যোগ করুন

সিস্টেম কনসোল › প্লাগইনসমূহ › এজেন্টসমূহ এ যান এবং AI Services এর নিচে Add an AI Service এ ক্লিক করুন। Service type নির্বাচন করুন:

  • OpenAI Compatible: নিজের চালাতে থাকা মডেল সার্ভারের জন্য, অথবা OpenAI-স্টাইল API সহ যেকোনো প্রোভাইডারের জন্য। API URL (যেমন http://ollama:11434/v1 বা http://vllm.internal:8000/v1) এবং সার্ভারের যদি প্রয়োজন হয় তবে API কী পূরণ করুন। যদি সার্ভারটি শুধুমাত্র Chat Completions API সাপোর্ট করে, তবে Use Responses API বন্ধ করে দিন।
  • OpenAI, Anthropic, Google Gemini, Google Vertex AI, AWS Bedrock, Azure, Cohere, Mistral: হোস্টেড প্রোভাইডার। প্রতিটির জন্য API কী প্রয়োজন (Bedrock-এর জন্য: একটি AWS region এবং credentials বা একটি IAM role; Vertex AI-এর জন্য: একটি project, region এবং service account; Azure-এর জন্য: API URL-ও)।

তারপর Default model নির্ধারণ করুন (প্রোভাইডার যদি তার মডেলগুলির তালিকা রিপোর্ট করতে পারে, তবে সেই তালিকা থেকে বেছে নিন; নয়তো নামটি টাইপ করুন), এবং প্রোভাইডার যদি টোকেন লিমিট রিপোর্ট না করে, তবে Input token limit এবং Output token limit নির্ধারণ করুন। এই সার্ভিসটি ব্যর্থ হলে Fallback Service কাজ করতে পারে। সংরক্ষণ করুন।

সার্ভার নিজেই এই রিকোয়েস্টগুলো পাঠায়, তাই এটির API-তে পৌঁছাতে হবে: একই compose প্রজেক্টে থাকা একটি মডেল সার্ভার, আপনার নেটওয়ার্কে থাকা একটি সার্ভার, বা ইন্টারনেটে থাকা একটি সার্ভার। আউটগোয়িং রিকোয়েস্টগুলো HTTP_PROXY এবং HTTPS_PROXY ভেরিয়েবল মেনে চলে।

2. এজেন্ট তৈরি করুন

এজেন্টসমূহ ওয়েব অ্যাপের এজেন্টসমূহ পেজে তৈরি করা হয়: এজেন্ট প্যানেলের এজেন্ট সিলেক্টরে ব্যবস্থাপনা খুলুন (ক্লাসিক ইন্টারফেসে প্রোডাক্ট মেনু থেকেও খোলা যায়)। এর ঠিকানা হলো https://chat.example.com/plug/mattermost-ai/agents। প্রতিটি এজেন্টের একটি ডিসপ্লে নাম, একটি এজেন্ট ইউজারনেম (যেভাবে মানুষ এটি মেনশন করে), একটি সার্ভিস এবং ঐচ্ছিকভাবে একটি মডেল, কাস্টম ইনস্ট্রাকশনস, এবং ভিশন সক্রিয় করুন (ইমেজ) এবং টুলস সক্রিয় করুন-এর সুইচ থাকে। এর অ্যাক্সেস ট্যাব সীমাবদ্ধ করে কোন চ্যানেলে এটি ব্যবহার করা যাবে এবং কোন সদস্যরা এটি ব্যবহার করতে পারবেন। সিস্টেম কনসোলের AI Functions-এ, ডিফল্ট বট নির্ধারণ করে কোন এজেন্ট ব্যবহার হবে যদি কোনোটি নির্বাচিত না করা হয়, যেমন কল সামারি-এর জন্য।

ডিফল্টভাবে, প্রতিটি ব্যবহারকারী আপনার কনফিগার করা সার্ভিসগুলোর সাহায্যে নিজের এজেন্ট তৈরি করতে পারে। এটি শুধুমাত্র অ্যাডমিনদের জন্য রাখতে চাইলে, সিস্টেম কনসোল › ব্যবহাৰকৰী ব্ৰবস্থাপনা › পৰমিশন এ সদস্যদের রোল থেকে নিজের AI এজেন্ট পরিচালনা পারমিশনটি সরিয়ে ফেলুন।

Agents অ্যাপের ঐচ্ছিক ফিচারসমূহ

  • Embedding search (পরীক্ষামূলক, বন্ধ): ম্যাসেজগুলির ওপর সেম্যান্টিক সার্চ। এর জন্য PostgreSQL-এ pgvector এক্সটেনশন এবং একটি embedding মডেল (OpenAI বা OpenAI-compatible) প্রয়োজন। এটি প্রতিটি ম্যাসেজ embedding মডেলে পাঠায়, প্রাইভেট চ্যানেল এবং ডাইরেক্ট মেসেজসহ।
  • Web search (বন্ধ): এজেন্টগুলিকে Google, Brave বা আপনি চালিত SearXNG সার্ভারের মাধ্যমে ওয়েব সার্চ করতে দেয়।
  • Native tools: যেসব প্রোভাইডার এগুলি সরবরাহ করে, তাদের এজেন্ট প্রোভাইডারের নিজস্ব ওয়েব সার্চ (নতুন এজেন্টগুলির জন্য সাপোর্ট থাকলে ডিফল্টভাবে চালু), ওয়েব ফেচ এবং কোড এক্সিকিউশন ব্যবহার করতে পারে। এগুলি প্রোভাইডারের পক্ষে চলে। এজেন্ট অনুযায়ী এগুলি বন্ধ করুন।
  • Model Context Protocol (MCP): আপনার বিশ্বাসী MCP সার্ভারগুলির সাথে এজেন্ট সংযুক্ত করুন, অতিরিক্ত টুলের জন্য।
  • ডিবাগ: Trace Output (বন্ধ, সার্ভার লগ বা একটি OpenTelemetry endpoint) এবং Enable Token Usage Logging, যা টোকেনের সংখ্যা logs/agents/token_usage.log এ লেখে।

ভাষা থেকে টেক্সট: কল ট্রান্সক্রিপশন এবং ক্যাপশন

কলসমূহ ট্রান্সক্রিপ্ট করা যায়, লাইভ ক্যাপশনসহ, একটি স্পিচ-টু-টেক্সট সার্ভার দ্বারা যা একটি OpenAI-সম্পাদিত /v1/audio/transcriptions এন্ডপয়েন্ট প্রদান করে। সেটআপটি কল এবং ভয়েস অনুচ্ছেদে রয়েছে। Summarize transcriptions চালু থাকলে, ডিফল্ট এজেন্ট প্রতিটি ট্রান্সক্রিপ্টের একটি সারসংক্ষেপও পোস্ট করে।

টেক্সট-টু-স্পিচ: মুখে পড়া

টেক্সট টু স্পিচ চালু থাকলে, প্রতিটি ম্যাসেজের মেনুতে শব্দে পড়ুন থাকে: সার্ভারটি ম্যাসেজের টেক্সটটি একটি টেক্সট টু স্পিচ API-তে পাঠায় এবং অডিওটি চালায়। সেটিংস, সিস্টেম কনসোল › ইন্টিগ্রেশনসমূহ › টেক্সট টু স্পিচ এ:

সেটিংকী এবং ভেরিয়েবলকী বসাতে হবে
ম্যাসেজ শুনুনTextToSpeechSettings.Enable, AM_TEXTTOSPEECHSETTINGS_ENABLEtrue (ডিফল্টভাবে বন্ধ)
API বেস URLTextToSpeechSettings.URL, AM_TEXTTOSPEECHSETTINGS_URL/v1 পর্যন্ত (সহিত) বেস URL, যেমন http://tts.internal:8000/v1। সার্ভার এর /audio/speech এন্ডপয়েন্ট কল করে।
মডেলTextToSpeechSettings.Model, AM_TEXTTOSPEECHSETTINGS_MODELAPI-এর নামানুসারে মডেল, যেমন tts-1। আবশ্যক।
ভয়েসTextToSpeechSettings.Voice, AM_TEXTTOSPEECHSETTINGS_VOICEমডেলের ভয়েসগুলোর একটি, অথবা ডিফল্টের জন্য খালি রাখুন।
API কীTextToSpeechSettings.APIKey, AM_TEXTTOSPEECHSETTINGS_APIKEYবেরার টোকেন হিসেবে পাঠানো হয়। যদি API-এর কোনো চাহিদা না থাকে তবে খালি রাখুন।

উপরের ঠিকানা এবং কী-এর পরিবর্তে একটি মডেল কানেকশন ব্যবহার করতে, AI › Built-in features-এ টেক্সট টু স্পিচ-এর জন্য এটি নির্বাচন করুন। তখন পেজে বলা হয় যে সেই কানেকশন দিয়ে ম্যাসেজগুলো শোনানো হবে: API বেস URL এবং API কী ব্যবহার করা হবে না, ভয়েস ব্যবহার হবে, এবং কানেকশনে কোনো মডেলের নাম না থাকলে মডেলও ব্যবহার হবে। ম্যাসেজ শুনুন অবশ্যই চালু থাকতে হবে।

পাঠানোর আগে, সার্ভার কোড ব্লক, লিংক, ইমোজি কোড এবং ফরম্যাটিং সরিয়ে ফেলে এবং সর্বোচ্চ 4000 অক্ষর পর্যন্ত রাখে। এটি MP3 অডিও চায় এবং মেমরিতে শেষ 64টি ফলাফল রাখে, তাই দুবার পড়া মেসেজটি একবারই পাঠানো হয়।

স্বয়ংক্রিয় অনুবাদ

অটো-অনুবাদ একটি চ্যানেলের ম্যাসেজগুলো প্রতিটি পাঠকের নিজস্ব ভাষায় প্রদর্শন করে। এটি সিস্টেম কনসোল › সাইট কনফিগারেশন › লোকালাইজেশন এর অটো-অনুবাদ অংশ থেকে কনফিগার করা যায়:

সেটিংকীডিফল্ট
চালুAutoTranslationSettings.Enableবন্ধ
অনুবাদ প্রোভাইডারAutoTranslationSettings.Providerconnection (প্রদর্শিত হয় "Model connection (recommended)", যদি কিছু নির্বাচিত না করা হয় তবে এটিই নির্বাচিত হয়), libretranslate, openai ("OpenAI-compatible API, set up here") বা agents ("AI chat app's service (older)")
অনুমোদিত ভাষাসমূহAutoTranslationSettings.TargetLanguagesen: যে ভাষায় মেসেজগুলো অনুবাদ করা যেতে পারে
অনুবাদ টাইমআউট (ms)AutoTranslationSettings.TimeoutMs5000
Restrict auto-translation on direct messages and group messagesAutoTranslationSettings.RestrictDMAndGMবন্ধ

প্রতিটি প্রোভাইডারের নিজস্ব ফিল্ড রয়েছে:

  • মডেল কানেকশন: সার্ভার-ব্যাপী একটি কানেকশন এবং এর মডেল, যা AI › Built-in features-এ অটো-অনুবাদ-এর সমান সেটিং (AISettings.AutoTranslation)। একটি নিবেদিত অনুবাদ মডেল দ্রুত এবং নির্ভুল; একটি সাধারণ LLM-ও কাজ করে।
  • LibreTranslate: LibreTranslate API Endpoint এবং LibreTranslate API Key (AutoTranslationSettings.LibreTranslate.URL, .APIKey)। একটি LibreTranslate সার্ভার আপনার নিজের নেটওয়ার্কে চালানো যেতে পারে।
  • OpenAI-compatible API: API বেস URL (/v1 পর্যন্ত; সার্ভারটি তার চ্যাট কমপ্লিশনস এন্ডপয়েন্ট ব্যবহার করে), মডেল এবং API কী (AutoTranslationSettings.OpenAI.URL, .Model, .APIKey)। স্থানীয়ভাবে (লোকালি) চালানো একটি ছোট অনুবাদ মডেল ভালোভাবে কাজ করে।
  • AI চ্যাট অ্যাপের সার্ভিস (পুরোনো): 0.9.0-এর আগে সেটআপ করা সার্ভারগুলোর প্রোভাইডার, যেগুলো এজেন্টস অ্যাপের একটি সার্ভিস ব্যবহার করত। এটি আর অ্যাপের প্রয়োজন নেই: এটি AI › Built-in features-এ অটো-অনুবাদের জন্য নির্বাচিত কানেকশন দিয়ে অনুবাদ করে, নাহলে আপগ্রেডের সময় অ্যাপের সার্ভিস থেকে কপি করা কানেকশন দিয়ে করে। মডেল কানেকশনে সুইচ করুন সেটিংটি সুপারিশকৃত প্রোভাইডারে সরিয়ে দেয়।

এটি চালু করার পর, চ্যানেল অ্যাডমিনসমূহ চ্যানেলের সেটিংস (অটো-অনুবাদ) থেকে চ্যানেলের জন্য অনুবাদ চালু করতে পারেন, এবং প্রতিটি সদস্য চ্যানেল মেনু (ম্যাসেজ অনুবাদ করুন) থেকে এটি বন্ধ করতে পারেন। ডাইরেক্ট এবং গ্রুপ ম্যাসেজে যেকোনো সদস্য এটি চালু করতে পারেন; তবে সীমাবদ্ধতা থাকলে সেখানে অনুবাদ উপলব্ধ নয়। অনুবাদকৃত ম্যাসেজে “Translated from …” লেখা থাকে এবং মূল ম্যাসেজে যাওয়ার একটি লিংক থাকে।

টেক্সট পাঠানোর আগে কোড, লিংক, মেনশনসমূহ এবং ইমোজি প্লেসহোল্ডার দিয়ে প্রতিস্থাপিত হয়, এবং পরে তা ফিরিয়ে আনা হয়।

রিস্রাইটযে ম্যাসেজটি লেখা হচ্ছে, এবং নির্বাচিত নির্দেশনাএর জন্য নির্বাচিত কানেকশন
রিকাপসমূহরিক্যাপে থাকা চ্যানেলগুলোর ম্যাসেজ, এবং ব্যক্তির নির্দেশনাএর জন্য নির্বাচিত কানেকশন
মডেল কানেকশন ব্যবহারকারী অ্যাপসমূহপ্রতিটি অ্যাপ ব্যবহারকারী ব্যক্তির জন্য যা পাঠায়সেই ব্যক্তি যে কানেকশনগুলো ব্যবহার করতে পারে
এজেন্টসমূহরিকোয়েস্ট, যার বিষয়ে থ্রেড বা চ্যানেলের মসেজসমূহ, এজেন্টের নির্দেশনা, টুলের ফলাফল, ভিশন চালু থাকলে ছবি, এবং জিজ্ঞাসাকারী ব্যবহারকারীর নাম, ইউজারনেম, পদ এবং ভাষাসার্ভিসের API
এমবেডিং সার্চপ্রতিটি মসেজ (বট এবং সিস্টেম মসেজ বাদে)এমবেডিং API
নেটিভ টুল এবং ওয়েব সার্চসার্চ কোয়েরি, পেজ ফেচ করার জন্য, কোডপ্রোভাইডার, অথবা আপনি যে সার্চ ইঞ্জিন বেছেছেন
কল ট্রান্সক্রিপশনযে সময় এটি চালু থাকে, সেই সময়ে যারা কথা বলে তাদের ভয়েসস্পিচ-টু-টেক্সট API
Read aloudপাঠানো হওয়া মসেজের টেক্সটটেক্সট-টু-স্পিচ API, বা এর জন্য নির্বাচিত কানেকশন
অনুবাদঅনুবাদকৃত চ্যানেলে মসেজগুলোর টেক্সটমডেল কানেকশন, LibreTranslate বা OpenAI-compatible API

সবকিছু আপনার নেটওয়ার্কে রাখতে, প্রতিটি ফিচারের জন্য নিজেরা চালানো সার্ভারের দিকে ইঙ্গিত করুন। ক্লাউড প্রোভাইডার ব্যবহার করলে, তার ডেটা রিটেনশন শর্তগুলো পরীক্ষা করুন, এবং আপনার ব্যবহারকারীদের জানান কোন ফিচারগুলো তাদের মসেজ বাইরে পাঠায়।

AI বন্ধ করা

একটি একক সুইচ নেই: প্রতিটি ফিচারের নিজস্ব সুইচ আছে।

  • রিসাইট্রাইট এবং রিক্যাপ: সিস্টেম কনসোল › AI › বিল্ট-ইন ফিচারস এ সেগুলোকে বন্ধ করুন। মানুষ তাদের কাছে আগে থেকেই থাকা রিক্যাপগুলো পড়তে থাকে।
  • মডেল কানেকশনস: একটি কানেকশন মুছে ফেললে তার সব ব্যবহার থেমে যায়। কোনো কানেকশন না থাকলে, সার্ভারের মাধ্যমে বিল্ট-ইন ফিচারস বা অ্যাপস AI ব্যবহার করতে পারে না।
  • এজেন্টসমূহ: সিস্টেম কনসোল › প্লাগইনসমূহ › প্লাগইন ম্যানেজমেন্ট এ এজেন্টসমূহ অ্যাপটি নিষ্ক্রিয় করুন। এতে কল সামারিসও মুছে যায়।
  • ট্রান্সক্রিপশন এবং ক্যাপশন: AM_CALLS_ENABLE_TRANSCRIPTIONS=false এবং AM_CALLS_ENABLE_LIVE_CAPTIONS=false (ডিফল্ট)।
  • শব্দে পড়ুন: ম্যাসেজ শুনুন বন্ধ রাখুন (AM_TEXTTOSPEECHSETTINGS_ENABLE=false, ডিফল্ট), যেকোনো কানেকশন ব্যবহার করুক বা না করুক।
  • অনুবাদ: অটো-অনুবাদ বন্ধ (AM_AUTOTRANSLATIONSETTINGS_ENABLE=false, ডিফল্ট)।

এজেন্টসমূহ অ্যাপটি নিষ্ক্রিয় করলে অন্য ফিচারস বন্ধ হয় না: তারা মডেল কানেকশনস বা নিজস্ব API ব্যবহার করে।
