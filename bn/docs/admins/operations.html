অপারেশনস

সার্ভারের দিকে নজর রাখুন, এতে আরও বেশি মানুষকে সামলে নিতে সক্ষম করুন, ডেটা কতদিন রাখা হবে তা ঠিক করুন, এবং অ্যাডমিনদের সবচেয়ে বেশি যে সমস্যার সম্মুখীন হতে হয় তা সমাধান করুন।

হেলথ চেক

  • amctl --local system status (কন্টেইনারে: docker compose exec antimatter amctl --local system status)। Docker ইমেজের হেলথ চেক প্রতি ৩০ সেকেন্ডে একবার এটি চালায়, তাই docker compose ps healthy বা unhealthy দেখাবে।
  • GET /api/v4/system/ping সাইন-ইন ছাড়াই উত্তর দেয়, যা বাইরের মনিটর বা লোড ব্যালান্সারের জন্য ব্যবহার করা যায়: curl -fsS https://chat.example.com/api/v4/system/ping।
  • antimatter db ping পরীক্ষা করে যে কনফিগার করা সেটিংস অনুযায়ী ডেটাবেসে পৌঁছানো সম্ভব কিনা।
  • সিস্টেম কনসোল › রিপোর্টিং › সিস্টেম পরিসংখ্যান ব্যবহারকারী, পোস্ট এবং সেশনের সংখ্যা দেখায়, এবং ওয়ার্কস্পেস অপটিমাইজেশন সেগুলোর কনফিগারেশন সমস্যাগুলো তালিকাভুক্ত করে যা পরীক্ষা করা উচিত।

মেট্রিকস

সার্ভার Prometheus মেট্রিক্স প্রকাশ করতে পারে: রিকোয়েস্ট রেট এবং সময়কাল, ওয়েবসকট কানেকশন, ডাটাবেস এবং ক্যাশ ব্যবহার, জব, প্লগইন হুক এবং আরও অনেক কিছু। এগুলি চালু করুন সিস্টেম কনসোল › এনভাইরনমেন্ট › পারফরম্যান্স মনিটরিং-এ:

সেটিংকী এবং ভেরিয়েবলডিফল্ট
পারফরম্যান্স মনিটরিং সক্রিয় করুনMetricsSettings.Enable, AM_METRICSSETTINGS_ENABLEবন্ধ
লিসেন ঠিকানাMetricsSettings.ListenAddress, AM_METRICSSETTINGS_LISTENADDRESS:8067
ক্লায়েন্ট পারফরম্যান্স মনিটরিং সক্রিয় করুনMetricsSettings.EnableClientMetricsচালু: ব্রাউজার এবং অ্যাপস তাদের নিজস্ব সময়কাল রিপোর্ট করে

Prometheus এরপর http://<server>:8067/metrics থেকে মেট্রিকস সংগ্রহ করে। প্রতিটি মেট্রিক Mattermost নামে (mattermost_…) এবং Antimatter নামে (antimatter_…) প্রকাশিত হয়, তাই বিদ্যমান Mattermost ড্যাশবোর্ডগুলো কাজ করতে থাকে। অ্যাপস তাদের নিজস্ব মেট্রিকস প্রকাশ করে, যেমন Agents অ্যাপ /plugins/mattermost-ai/metrics-এ।

মেট্রিকস পোর্টে সাইন-ইনের প্রয়োজন নেই: এটি একটি প্রাইভেট নেটওয়ার্কে রাখুন। সাইটের compose ফাইল এটি প্রকাশ করে না; হোস্ট থেকে এটি সংগ্রহ করতে antimatter সার্ভিসের ports-এ "127.0.0.1:8067:8067" যোগ করুন।

মেট্রিকস অ্যাপ

Prometheus সার্ভার ছাড়া, Metrics অ্যাপ (ডিফল্টভাবে বন্ধ, দেখুন Bundled apps) একই মেট্রিক্সগুলি Antimatter-এর ভেতরে একটি ছোট টাইম-সিরিজ ডাটাবেসে সংগ্রহ করে: প্রতি ৬০ সেকেন্ডে, ১৫ দিনের জন্য সংরক্ষিত। এটি শুরু হলে মেট্রিক্স এন্ডপয়েন্ট চালু করে। এর সিস্টেম কনসোল › প্লাগইনসমূহ-এর পেজে ডাটাবেসের আকার দেখা যায় এবং ডেটার ডাম্প ডাউনলোড করা যায়, আপনার নিজস্ব বিশ্লেষণের জন্য বা একটি বাগ রিপোর্টে যুক্ত করার জন্য; সর্বশেষ দিনের তথ্য সাপোর্ট প্যাকেটেও যুক্ত হয়।

সাপোর্ট প্যাকেট

সাপোর্ট প্যাকেট হলো একটি zip ফাইল যা সমস্যা নির্ণয়ের জন্য যা প্রয়োজন তা ধারণ করে: ভার্সন, পরিসংখ্যান, গোপন তথ্য বাদ দেওয়া কনফিগারেশন, অ্যাপ এবং জবের তালিকা, ডাটাবেস স্কিমা, সাম্প্রতিক লগ এবং পারফরম্যান্স প্রোফাইল। amctl system supportpacket দিয়ে একটি তৈরি করুন, অথবা সিস্টেম কনসোলের সাইডবারের উপরের মেনু থেকে (কমার্সিয়াল সাপোর্ট, যা তারপর আপনি যা অন্তর্ভুক্ত করতে চান তা বেছে নিতে দেয়)। শেয়ার করার আগে এটি পড়ে নিন: এতে কোনো ম্যাসেজ নেই, তবে এতে কমিউনিটি, ব্যবহারকারী এবং সেটিংসের নাম রয়েছে।

পারফরম্যান্স এবং স্কেলিং

২টি CPU কোর এবং ৪ GB মেমরির একটি সার্ভার কয়েকশো মানুষকে পরিষেবা দিতে পারে। নতুন সার্ভার যোগ করার আগে, নিম্নলিখিত বিষয়গুলো দেখুন:

  • ডাটাবেস। PostgreSQL বেশিরভাগ কাজ করে: এতে দ্রুত স্টোরেজ এবং মেমরি দিন। রিড রিপ্লিকা রিড লোড নিতে পারে (SqlSettings.DataSourceReplicas, একটি কানেকশন URL-এর তালিকা)।
  • সার্চ। ডিফল্টভাবে ডাটাবেসে ম্যাসেজ সার্চ করা হয়। বড় সার্ভারগুলোর জন্য Elasticsearch বা OpenSearch সার্চ এবং ইনডেক্সিং সামলে নিতে পারে: সিস্টেম কনসোল › এনভাইরনমেন্ট › Elasticsearch (ElasticsearchSettings: ব্যাকএন্ড টাইপ Elasticsearch বা OpenSearch, সার্ভার কানেকশন ঠিকানা, ক্রেডেনশিয়াল, তারপর ইনডেক্সিং চালু করুন, ইনডেক্স তৈরি করুন, এবং সার্চ চালু করুন)।
  • কলসমূহ। কল মিডিয়া সবচেয়ে ভারী লোড। এগুলি একটি rtcd সার্ভারে সরান: দেখুন Calls and voice।
  • খোলা ফাইল। প্রতিটি সংযুক্ত ব্যক্তি একটি websocket খোলা রাখে। antimatter-docker-এর প্রোডাকশন compose ফাইল সীমাটি 49152-এ বাড়িয়ে দেয় (ulimits: nofile); systemd-এর সাথেও একই কাজ করুন (LimitNOFILE)।
  • লগ। LogSettings.ConsoleLevel কে INFO বা WARN-এ নামান: ব্যস্ত সার্ভারে DEBUG অনেক লগ করে।

হাই অ্যাভেইলেবিলিটি

একটি লোড ব্যালান্সারের পেছনে একাধিক Antimatter সার্ভার লাইসেন্স ছাড়াই ক্লাস্টার হিসেবে চলতে পারে। তাদের একই PostgreSQL ডেটাবেস, একই S3 ফাইল স্টোরেজ এবং ডেটাবেসে থাকা কনফিগারেশন (AM_CONFIG) শেয়ার করতে হবে। সিস্টেম কনসোল › এনভাইরনমেন্ট › হাই অ্যাভেইলবিলিটি (ClusterSettings) গিয়ে High Availability মোড সক্রিয় করুন (ClusterSettings.Enable) চালু করুন, প্রতিটি নোডকে একই ক্লাস্টারের নাম (ClusterSettings.ClusterName) দিন, এবং নোডগুলোর একে অপরের সাথে গসিপ পোর্ট 8074 TCP এবং UDP (ClusterSettings.GossipPort)-এ যোগাযোগ করার ব্যবস্থা করুন। নোডগুলো ডেটাবেসের মাধ্যমে একে অপরকে খুঁজে পায়। লোড ব্যালান্সারকে ওয়েবসকেট পাস করতে হবে। ক্লাস্টারে কলের জন্য rtcd ব্যবহার করুন।

ডাটা রিটেনশন

ডিফল্টভাবে Antimatter প্রতিটি মেসেজ এবং ফাইল চিরকাল সংরক্ষণ রাখে। পুরনোগুলো স্বয়ংক্রিয়ভাবে মুছে ফেলতে, সিস্টেম কনসোল › কমপ্লায়েন্স › ডেটা রিটেনশন পলিসিসমূহ-এ যান:

  • গ্লোবাল রিটেনশন নীতি পুরো সার্ভারের জন্য চ্যানেল ও ডাইরেক্ট মেসেজ রিটেনশন এবং ফাইল রিটেনশন নির্ধারণ করে: চিরকাল সংরক্ষণ করুন, অথবা ঘণ্টা, দিন বা বছরের সংখ্যা (DataRetentionSettings.EnableMessageDeletion, MessageRetentionHours, EnableFileDeletion, FileRetentionHours)।
  • কাস্টম রিটেনশন নীতিসমূহ নির্দিষ্ট কমিউনিটি এবং চ্যানেলের জন্য আলাদা সময়কাল নির্ধারণ করে।
  • ডিলিট জবটি প্রতিদিন আপনার নির্বাচিত সময়ে চলে (DataRetentionSettings.DeletionJobStartTime, ডিফল্ট 02:00 UTC)। এখনই ডিলিট জব চালান দিয়ে তা সাথে সাথে চালাতে পারেন, আর নীতি লগ-এ প্রতিটি রানে কী কী মুছে ফেলা হয়েছে তা তালিকাভুক্ত থাকে।
মুছে ফেলা মাসেজ এবং ফাইল ডাটাবেস এবং ফাইল স্টোরেজ থেকে চিরতরে হারিয়ে যায়। কোনো পলিসি চালু করার আগে সময়কালগুলো যাচাই করুন, এবং মনে রাখুন যে আপনার ব্যাকআপগুলো মেয়াদ শেষ না হওয়া পর্যন্ত মুছে ফেলা ডাটা ধরে রাখে।

কমপ্লায়েন্স এক্সপোর্ট এবং অডিট লগ

  • সিস্টেম কনসোল › কমপ্লায়েন্স › কমপ্লায়েন্স এক্সপোর্ট প্রতিদিন সকল মেসেজ এবং ফাইল এক্সপোর্ট করে (কমপ্লায়েন্স এক্সপোর্ট সক্রিয় করুন, MessageExportSettings.EnableExport, ডিফল্ট অবস্থায় বন্ধ; কমপ্লায়েন্স এক্সপোর্ট সময়, ডিফল্ট 01:00) এমন একটি ফরম্যাটে যা আর্কাইভিং সিস্টেম পড়তে পারে: CSV, Actiance XML, বা Global Relay (একটি zip ফাইল, অথবা SMTP-এর মাধ্যমে পাঠানো EML)। amctl compliance-export কমান্ড লাইন থেকে এক্সপোর্ট চালিয়ে ডাউনলোড করে।
  • কমপ্লায়েন্স মনিটরিং (ComplianceSettings) একটি ডিরেক্টরিতে দৈনিক রিপোর্ট লেখে। এটি একটি পুরনো মেকানিজম; Compliance Export ব্যবহার করা উত্তম।
  • অডিট লগিং (বেটা, ExperimentalAuditSettings) প্রশাসনিক এবং নিরাপত্তা-সম্পর্কিত ঘটনা (সাইন-ইন, পারমিশন এবং সেটিংস পরিবর্তন) একটি আলাদা ফাইলে রেকর্ড করে।
  • কাস্টম Terms of Service Antimatter ব্যবহারের আগে এবং আপনি শর্তাবলি পরিবর্তন করার পরেও সবাইকে আপনার শর্তাবলি স্বীকার করতে চাইতে থাকে।

সাধারণ সমস্যা

"সার্ভারে সংযোগ স্থাপন করা যাচ্ছে না", বা রিলোড করার পরে মাত্র ম্যাসেজ দেখা যায়

WebSocket-এর সংযোগ স্থাপন হচ্ছে না। চেক করুন যে রিভার্স প্রক্সি Upgrade এবং Connection হেডার পাস করছে (দেখুন nginx-এর উদাহরণ), এবং ব্রাউজারে দেখা ঠিকানাটির সাথে সাইটের URL-এর সম্পূর্ণ মিল আছে, https সহ।

"413 Request Entity Too Large" এর সাথে আপলোড ব্যর্থ হয়

প্রক্সি সাইজটি প্রত্যাখ্যান করছে। System Console › Environment › File Storage-এ সর্বোচ্চ ফাইল সাইজ (FileSettings.MaxFileSize, ডিফল্ট 100 MB)-এর কমপক্ষে সমান হওয়া পর্যন্ত nginx-এর client_max_body_size লিমিট বাড়ান।

লোকজন কল শুরু করতে পারে না, বা যোগ দিলেও কিছু শুনতে পায় না

যদি শুধুমাত্র অ্যাডমিনরা কল শুরু করতে পারেন, তবে Calls-এর Test mode বন্ধ করুন। যদি লোকজন যোগ দিলেও কিছু শুনতে না পায়, তবে মিডিয়া পোর্ট ব্লকড বা সার্ভার ভুল ঠিকানা ঘোষণা করছে: 8443 UDP এবং TCP খুলুন, এবং NAT-এর পেছনে ICE Host Override সেট করুন। যেসব নেটওয়ার্ক দুটোই ব্লক করে, তাদের জন্য TURN সার্ভার প্রয়োজন। দেখুন Calls and voice।

GIF পিকার খালি

System Console › Plugins › GIFs-এ GIF service URL (সাইটের compose ফাইলে http://gifs:8080/v2) এবং API কী (.env-এর GIFS_API_KEY) চেক করুন, এবং নিশ্চিত হোন যে gifs সার্ভিসটি চলছে: docker compose ps gifs।

কোনো ইমেইল আসছে না

System Console › Environment › SMTP-এ কানেকশন টেস্ট ব্যবহার করুন, নোটিফিকেশন ফ্রম ঠিকানা এখনো test@example.com না সেটা চেক করুন, এবং লগে smtp বা mail সার্চ করুন।

একটি অ্যাপ "Failed to start" দেখায়

লগে তার id খুঁজুন (docker compose logs antimatter | grep <app id>)। Plugin Management-এ এটি ডিসেবল করে আবার এনেবল করুন, যাতে রিস্টার্ট হয়।

সার্ভার শুরু হয় না

তার লগের শেষ অংশ পড়ুন। সবচেয়ে সাধারণ কারণ হলো ডাটাবেসে সংযোগ করা যাচ্ছে না (antimatter db ping দিয়ে AM_SQLSETTINGS_DATASOURCE চেক করুন), ডাটাবেস মাইগ্রেশন ব্যর্থ হয়েছে (আপগ্রেডের আগে নেওয়া ব্যাকআপ রিস্টোর করুন এবং এররটি রিপোর্ট করুন), অথবা লিসেন পোর্টটি অন্য কোথাও ব্যবহৃত হচ্ছে।

অ্যাডমিনিস্ট্রেটর অ্যাকাউন্ট থেকে লকআউট

সার্ভার থেকে লোকাল মোডে কোনো পাসওয়ার্ডের প্রয়োজন নেই:

docker compose exec antimatter amctl --local user change-password admin --password 'a-new-password'
docker compose exec antimatter amctl --local user resetmfa admin
docker compose exec antimatter amctl --local roles system-admin admin
