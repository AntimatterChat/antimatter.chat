Inloggning och konton

Avgör vem som kan skapa ett konto och hur personer loggar in. Alla inloggningsmetoder i Antimatter fungerar utan licens, inklusive enhetlig inloggning och kataloger.

Vem kan skapa ett konto

Kontrollera Systemkonsol › Autentisering › Registrera användarkonto direkt efter installationen. Med standardinställningarna kan alla som har en inbjudningslänk till en gemenskap skapa ett konto, men ingen kan registrera sig utan en sådan.

InställningNyckelStandardVad den gör
Aktivera Skapa KontoTeamSettings.EnableUserCreationpåAv, ingen kan skapa ett konto med någon metod; endast administratörer kan (Systemkonsol eller amctl user create).
Aktivera Open ServerTeamSettings.EnableOpenServerAvPå, alla som når servern kan registrera sig med en e-postadress, utan inbjudan. Använd det endast för publika gemenskaper.
Begränsa nya system- och teammedlemmar till angivna e-postdomänerTeamSettings.RestrictCreationToDomainstomKommaavgränsade domäner, till exempel example.com, example.org: endast adresser från dessa domäner kan skapa ett konto.
Aktivera inbjudning med e-postServiceSettings.EnableEmailInvitationsav på en ny serverGör det möjligt för medlemmar att bjuda in personer via e-post (kräver SMTP). Annullera obesvarade e-postinbjudningar avbryter inbjudningar som ännu inte har accepterats; de löper i alla fall ut efter 48 timmar.

Gemenskapsadministratörer styr också vem som går med i deras gemenskap, med inbjudningslänkar och deras egna tillåtna domäner: se guiden Driva en gemenskap.

Från kommandoraden: amctl user create (lägg till --system-admin eller --guest), amctl user invite, amctl user deactivate, amctl roles system-admin <user> för att göra någon till systemadministratör, och amctl roles member <user> för att ångra det.

E-post och lösenord

I Systemkonsol › Autentisering › E-post:

InställningNyckelStandard
Aktivera "skapa konto med e-post"EmailSettings.EnableSignUpWithEmailpå. Stäng av det när alla loggar in via enhetlig inloggning.
Kräv e-postverifieringEmailSettings.RequireEmailVerificationav. Slå på det när e-post fungerar: personer bekräftar då sin adress innan de kan logga in.
Aktivera inloggning med e-postEmailSettings.EnableSignInWithEmailpå
Aktivera inloggning med användarnamnEmailSettings.EnableSignInWithUsernamepå

I Systemkonsol › Autentisering › Lösenord:

InställningNyckelStandard
Minsta lösenordslängdPasswordSettings.MinimumLength8 (5 till 72)
Lösenordskrav: gemina, versala, siffra, symbolPasswordSettings.Lowercase, .Uppercase, .Number, .Symbolallt av
Maximalt antal inloggningsförsökServiceSettings.MaximumLoginAttempts10: efter så många misslyckanden låses kontot tills lösenordet återställs via e-post
Aktivera länk för glömt lösenordPasswordSettings.EnableForgotLinkpå

En längd på 12 tecken eller mer bidrar mer till säkerheten än teckenregler. För att återställa någon annans lösenord: Systemkonsol › Hantera användare › Användare, eller amctl user change-password <user> --password <new>.

Multifaktorautentisering

Multifaktorautentisering (MFA) lägger till en kod från en autentiseringsapp till lösenordet. Den gäller för konton som loggar in med e-post eller AD/LDAP; vid enkel inloggning använder du din identitetsleverantörs MFA. I Systemkonsol › Autentisering › MFA:

  • Aktivera flerfaktorsautentisering (ServiceSettings.EnableMultifactorAuthentication, av): användare kan aktivera MFA i sina säkerhetsinställningar.
  • Tvinga flerfaktorautentisering (ServiceSettings.EnforceMultifactorAuthentication, av): alla måste ställa in det, antingen vid registrering eller vid nästa inloggning.

Om någon förlorar sin enhet: amctl user resetmfa <user>, eller återställ den från deras sida i Systemkonsol › Hantera användare › Användare.

Enkel inloggning

Antimatter kan logga in användare genom din identitetsleverantör. Vid första inloggningen skapas deras konto (om kontoskapning är tillåten) från namnet, e-postadressen och användarnamnet som leverantören skickar.

OpenID Connect, GitLab, Google och Entra ID

Gå till Systemkonsol › Autentisering › OpenID Connect och välj under Välj service provider: GitLab, Google Apps, Entra ID (Office 365) eller OpenID Connect (övriga) för andra leverantörer (Keycloak, Authentik, Zitadel, Okta, Auth0…).

  1. Skapa i din leverantör en applikation (en "client") av typen web, med denna omdirigerings-URI, för din sajtadress:
    LeverantörOmdirigerings-URI
    OpenID Connect (Annat)https://chat.example.com/signup/openid/complete
    GitLabhttps://chat.example.com/signup/gitlab/complete
    Googlehttps://chat.example.com/signup/google/complete
    Entra IDhttps://chat.example.com/signup/office365/complete
  2. I Antimatter, fyll i Identifieringspunkt (leverantörens /.well-known/openid-configuration-URL; för GitLab, Adress till GitLab istället), Klient ID och Klient-hemlighet. För andra leverantörer, även Knappnamn och Knappfärg för inloggningsknappen.
  3. Använd föredraget användarnamn (GitLab och andra leverantörer) tar Antimatters användarnamn från leverantörens preferred_username-anspråk.
  4. Spara, logga ut och testa den nya knappen på inloggningssidan.

Inställningarna lagras i OpenIdSettings, GitLabSettings, GoogleSettings eller Office365Settings (till exempel AM_OPENIDSETTINGS_ENABLE, AM_OPENIDSETTINGS_DISCOVERYENDPOINT, AM_OPENIDSETTINGS_ID, AM_OPENIDSETTINGS_SECRET). Den äldre sidan för OAuth 2.0 visas endast för servrar som fortfarande har en konfiguration för OAuth 2.0 för GitLab, Google eller Entra ID.

SAML 2.0

I Systemkonsol › Autentisering › SAML 2.0, aktivera Aktivera inloggning med SAML 2.0 (SamlSettings.Enable) och fyll i det din identitetsleverantör ger dig: Identity Provider Metadata URL, eller SAML SSO URL, Identitetsleverantörens utfärdande URL och Identitetsleverantör för publikt autentiseringscertifikat. På identitetsleverantörens sida:

  • URL för inloggning som tjänsteleverantör (assertion consumer service): https://chat.example.com/login/sso/saml;
  • Antimatters metadata, för leverantörer som importerar den: https://chat.example.com/api/v4/saml/metadata.

Mappa de attribut som din leverantör skickar: åtminstone Attribut för mejl och Attribut för användarnamn, samt valfritt ID, för- och efternamn, smeknamn, position, språk, gäst- och administratörsattribut. Verifiera signatur och Aktivera kryptering är aktiverade som standard (kryptering kräver en service provider-nyckel och ett certifikat; endast RSA-nycklar stöds); Sign Request är av. Signaturalgoritmen är som standard RSAwithSHA256.

AD/LDAP

I Systemkonsol › Autentisering › AD/LDAP finns en steg-för-steg-sida som kopplar Antimatter till Active Directory eller en annan LDAP-server: server och port (LdapSettings.LdapServer, LdapSettings.LdapPort, 389 som standard), anslutningssäkerhet (ingen, TLS eller STARTTLS), bas-DN och ett bind-konto (BaseDN, BindUsername, BindPassword), filter för användare, gäster, administratörer och grupper, samt attribut för e-post, användarnamn, ID, namn och bild. Användare loggar sedan in med sina kataloginloggningsuppgifter.

En synkroniseringsjobb körs var 60:e minut (LdapSettings.SyncIntervalMinutes) för att uppdatera namn och inaktivera personer som har tagits bort från katalogen. Kör det nu med amctl ldap sync. LDAP-grupper kan länkas till communityer och kanaler i Systemkonsol › Hantera användare › Grupper. SAML-konton kan också hållas synkroniserade med AD/LDAP (Aktivera synkronisering av SAML-konton med AD/LDAP).

Flytta befintliga konton

För att byta befintliga e-postkonton till enkel inloggning, flyttar amctl user migrate-auth email saml users.json (eller ldap) dem i bulk. En användare kan också ändra sin egen inloggningsmetod i sina säkerhetsinställningar när Tillåt överföring av autentisering (ServiceSettings.ExperimentalEnableAuthenticationTransfer, i Systemkonsol › Experimentella › Funktioner) är påslaget.

Gästkonton

Gäster är personer utanför din organisation som endast ser de kanaler de är inbjudna till. Slå dem på i Systemkonsol › Autentisering › Gäståtkomst:

InställningNyckelStandard
Aktivera gäståtkomstGuestAccountsSettings.EnableAv
Vitlistade gästdomänerGuestAccountsSettings.RestrictCreationToDomainstomt: gäster kan ha valfri e-postdomän
Tvinga flerfaktorautentiseringGuestAccountsSettings.EnforceMultifactorAuthenticationavslaget; endast tillgängligt när MFA är aktiverat och tvingas på för alla
Dölj gästtaggGuestAccountsSettings.HideTagsavslaget: en "gäst"-tagg visas bredvid deras namn

När det är påslaget bjuder community-administratörer in gäster till specifika kanaler. Administratörer kan göra en medlem om till gäst med amctl user demote, och en gäst om till medlem med amctl user promote.

Sessioner

Hur länge personer förblir inloggade anges i Systemkonsol › Miljö › Sessionslängd:

InställningNyckelStandard på en ny server
Utöka sessionen vid aktivitetServiceSettings.ExtendSessionLengthWithActivitypåslaget: sessioner förnyas medan personer använder Antimatter
Sessionslängd för AD/LDAPoch e-post (timmar)ServiceSettings.SessionLengthWebInHours720 timmar (30 dagar)
Sessionslängd för mobil (timmar)ServiceSettings.SessionLengthMobileInHours720 timmar
Sessionslängd SSO (timmar)ServiceSettings.SessionLengthSSOInHours720 timmar
Timeout för inaktiv Session (minuter)ServiceSettings.SessionIdleTimeoutInMinutes43200 minuter (30 dagar); visas endast när sessioner inte förlängs med aktivitet
Avsluta sessioner vid lösenordsbyteServiceSettings.TerminateSessionsOnPasswordChangepå

För att logga ut alla på en gång, använd Återkalla alla sessioner i Systemkonsol › Hantera användare › Användare. För att logga ut en enskild person, öppna deras sida där.
