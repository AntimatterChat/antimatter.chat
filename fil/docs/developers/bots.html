Mga bot at interaktibong mensahe

Ang bot account ay isang user na ginawa para sa isang program. May sarili nitong pangalan, larawan, at tokens, at may BOT tag sa tabi ng pangalan nito. Tinatalakay din ng pahinang ito ang mga interaktibong bahagi ng mga mensahe: mga button, menu, at dialog, na maaaring gamitin ng anumang integration.

Bakit kailangan ng bot account

  • Ang mga mensahe nito ay mula sa malinaw na identidad, na may BOT tag, sa halip na mula sa account ng isang kapwa-employee.
  • Ang mga token nito ay patuloy na gumagana kahit magbago ng role o umalis ang taong nag-set nito (maliban kung na-disable ng server ang mga bot ng mga na-deactivate na owner, tingnan sa ibaba).
  • Hindi makapag-sign in ang mga bot gamit ang password, at hindi nila nakikita ang web app.

Lumilikha ang mga app ng sarili nilang mga bot, tulad ng mga bot ng Todo o Playbooks, gamit ang plugin API (EnsureBotUser).

Pahintulutan ang mga bot account

Pinapalitan ng isang system admin ang Pahintulutan ang paggawa ng Bot Account sa System Console › Mga Integration › Mga bot account (ServiceSettings.EnableBotAccountCreation, AM_SERVICESETTINGS_ENABLEBOTACCOUNTCREATION). Ito ay off sa default. Maaari lamang ng mga system admin ang lumikha ng mga bot, maliban kung ibinibigay nila ang karapatan sa ibang mga role sa mga setting ng pahintulutan.

Sa parehong pahina, ang I-disable ang mga bot account kapag na-deactivate ang owner (ServiceSettings.DisableBotsWhenOwnerIsDeactivated, on sa default) ay nagpapahina ng bot kapag na-deactivate ang account ng owner nito.

Lumikha ng bot

  1. Buksan ang avatar sa itaas na kanang sulok, tapos Mga Integration › Mga bot account, tapos Magdagdag ng Bot Account.
  2. Ilagay ang Username (mga malaking titik, numero, tuldok, dash, at underscore), at opsyonal ang Bot Icon, Display Name, at Paglalarawan.
  3. Piliin ang Role: Miyembro, o System Admin para sa isang bot na pamamahala sa server. Bigyan ang bot ng pinakamaliit na karapatan na kailangan lang.
  4. Tikman ang post:channels para payagan itong mag-post sa bawat pampublikong channel, o post:all para sa lahat ng channel, kabilang ang mga pribadong channel at Direct Message, nang hindi siya miyembro.
  5. Itakda kailan mag-expire ang default token nito, tapos piliin ang Lumikha ng Bot Account.
  6. Kopyahin ang access token na ipinapakita. Hindi na ito ipapakita ulit.

Pagkatapos, ang Lumikha ng Bagong Token sa linya ng bot ay nagdadagdag ng token, at bawat token ay maaaring i-disable o burahin. Gumagana ang mga bot token kahit na-off ang mga personal access token para sa mga tao.

Gamit ang API:

# create the bot (you become its owner)
curl -X POST https://chat.example.com/api/v4/bots \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"username": "deploy-bot", "display_name": "Deploy", "description": "Posts deployments"}'

# give it a token
curl -X POST https://chat.example.com/api/v4/users/$BOT_USER_ID/tokens \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"description": "deploy pipeline"}'

Mula sa command line, na-sign in bilang admin (hindi sa local mode): amctl bot create deploy-bot --display-name Deploy --with-token --expires-in 90d. Iba pang mga endpoint: GET /api/v4/bots, PUT /api/v4/bots/{bot_user_id}, POST /api/v4/bots/{bot_user_id}/disable at /enable, POST /api/v4/bots/{bot_user_id}/assign/{user_id} upang palitan ang owner nito.

Idagdag ang bot sa mga community at channel

Ang bagong bot ay hindi naka-join sa anumang community. Idagdag ito gaya ng tao, mula sa member management ng community o gamit ang API:

curl -X POST https://chat.example.com/api/v4/teams/$TEAM_ID/members \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"team_id": "'$TEAM_ID'", "user_id": "'$BOT_USER_ID'"}'

curl -X POST https://chat.example.com/api/v4/channels/$CHANNEL_ID/members \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"user_id": "'$BOT_USER_ID'"}'

Ang bot na may post:channels o post:all ay maaaring mag-post nang hindi miyembro, ngunit tinatanggap lamang nito ang mga WebSocket event para sa mga channel na kabilang dito.

Mag-post bilang bot

Gumamit ng token ng bot sa anumang API call; ang POST /api/v4/posts ang pinakakaraniwan (tingnan ang Mga pangunahing resource). Para sumulat direkta sa isang tao, buksan muna ang direct message channel:

# returns the channel; use its "id" as channel_id
curl -X POST https://chat.example.com/api/v4/channels/direct \
  -H "Authorization: Bearer $BOT_TOKEN" -H 'Content-Type: application/json' \
  -d '["'$BOT_USER_ID'", "'$USER_ID'"]'

Upang mag-reaction sa sinasabi ng mga tao, sundan ang WebSocket gamit ang token ng bot at sagutin ang mga posted event na interesado ka. Huwag pansinin ang mga mensahe ng sarili ng bot upang maiwasan ang loop.

Ang mensahe na nakikita lamang ng isang tao (ephemeral message) ay ipinapadala gamit ang POST /api/v4/posts/ephemeral at {"user_id", "post": {"channel_id", "message"}}. Kailangan nito ang create_post_ephemeral permission, na mayroon lamang ang mga system admin sa default. Karaniwang ipinapadala ng mga integration ang ephemeral messages bilang sagot sa mga slash command at buttons.

Mga interactive na mensahe: buttons at menus

Ang anumang mensahe na may attachment ay maaaring magdala ng mga action: buttons, at menus para pumili. Gumagana ito sa mga mensahe na ipinapadala gamit ang API, webhooks, at mga sagot ng slash command. Kapag gumamit ng isang tao, tinatawag ng Antimatter ang URL ng iyong integration.

{
  "channel_id": "…",
  "message": "Deploy **api 2.4.0** to production?",
  "props": {
    "attachments": [{
      "actions": [
        {
          "id": "approve",
          "type": "button",
          "name": "Approve",
          "style": "primary",
          "integration": {"url": "https://deploy.example.com/actions", "context": {"release": "2.4.0", "action": "approve"}}
        },
        {
          "id": "env",
          "type": "select",
          "name": "Pick an environment",
          "options": [{"text": "Staging", "value": "staging"}, {"text": "Production", "value": "production"}],
          "integration": {"url": "https://deploy.example.com/actions", "context": {"release": "2.4.0", "action": "env"}}
        }
      ]
    }]
  }
}
  • type: button o select.
  • id: mga letra, numero, dashes, at underscores, na iba-iba para sa bawat action ng mensahe. Ito ay nagagawa kapag binayaan mo ito.
  • style (buttons): default, primary, success, good, warning, danger, o hex colour.
  • options (menus), o data_source: users o channels upang pumili ng tao o channel. Ang default_option ay nagpili nang maaga ng isang value.
  • integration.url: kung saan ipinapadala ang click. Maaaring gamitin ng isang app (plugin) ang sarili nitong route, tulad ng /plugins/com.example.deploy/actions. Ang integration.context ay para sa iyo: bumabalik ito kasama ang click, at hindi nakikita ng mga client.

Ang request na natatanggap ng iyong integration

{
  "user_id": "…",
  "user_name": "priya",
  "channel_id": "…",
  "channel_name": "releases",
  "team_id": "…",
  "team_domain": "lumen-labs",
  "post_id": "…",
  "trigger_id": "…",
  "type": "button",
  "context": {"release": "2.4.0", "action": "approve"}
}

Para sa menu, ang type ay select at ang context.selected_option ang naglalaman ng napiling halaga.

Ang iyong sagot

{
  "update": {"message": "Deploy of **api 2.4.0** approved by @priya", "props": {}},
  "ephemeral_text": "Done. The deploy starts in a minute."
}
  • update: pinapalit ang teksto at mga katangian ng mensahe, halimbawa upang alisin ang mga button pagkatapos gamitin (isang walang laman na props).
  • ephemeral_text: isang mensahe na nakikita lamang ng taong nag-click.
  • goto_location: isang URL na bubuksan.
  • Ang walang laman na body ay hindi nagbabago ng anumang bagay.

Naghihintay ang server hangga't pinapayagan ng Integration request timeout (30 segundo ang default). Ang mga integration URL sa mga private network address ay dapat payagan ng isang system admin, katulad ng webhooks.

Mga Dialog

Ang dialog ay isang form na bumubukas sa ibabaw ng chat. Maaari itong buksan lamang bilang sagot sa bagong ginawa ng tao, tulad ng slash command o button, dahil kailangan nito ang trigger_id ng request. Ang trigger_id ay valid hangga't tumatagal ang integration request timeout.

curl -X POST https://chat.example.com/api/v4/actions/dialogs/open \
  -H 'Content-Type: application/json' \
  -d '{
    "trigger_id": "'$TRIGGER_ID'",
    "url": "https://deploy.example.com/dialog",
    "dialog": {
      "callback_id": "new-release",
      "title": "New release",
      "introduction_text": "Fill in the release details.",
      "submit_label": "Create",
      "notify_on_cancel": false,
      "state": "anything you want back",
      "elements": [
        {"display_name": "Version", "name": "version", "type": "text", "placeholder": "2.4.0"},
        {"display_name": "Notes", "name": "notes", "type": "textarea", "optional": true},
        {"display_name": "Environment", "name": "env", "type": "select",
         "options": [{"text": "Staging", "value": "staging"}, {"text": "Production", "value": "production"}]},
        {"display_name": "Owner", "name": "owner", "type": "select", "data_source": "users"},
        {"display_name": "Notify the channel", "name": "notify", "type": "bool", "default": "true"}
      ]
    }
  }'
Uri ng elementAng ipapakita nito
textIsang isang-linyang field. subtype: text, email, number, password, tel o url. Pinupuntahan ng min_length at max_length ito.
textareaIsang multi-line field.
selectIsang listahan: options, o data_source na users, channels, o dynamic na may data_source_url. Ang multiselect ay nagpapahintulot ng maraming halaga.
boolIsang checkbox.
radioIsang pagpipilian mula sa options.
date, datetimeIsang petsa, o isang petsa at oras.

Ang bawat element ay tumatanggap ng display_name, name, help_text, placeholder, default at optional.

Kapag ipinasa ng tao, ipinapadala ng Antimatter ang POST sa url ng dialog:

{
  "type": "dialog_submission",
  "callback_id": "new-release",
  "state": "anything you want back",
  "user_id": "…",
  "channel_id": "…",
  "team_id": "…",
  "submission": {"version": "2.4.0", "notes": "", "env": "staging", "owner": "…", "notify": true},
  "cancelled": false
}

Sagutin gamit ang walang laman na body upang isara ang dialog, o ituloy ang pagbubukas at ipakita kung ano ang mali:

{"errors": {"version": "This version already exists."}}

Ang {"error": "…"} ay nagpapakita ng mensahe para sa buong form. May notify_on_cancel, ang pagsasara ng dialog ay nagpapadala ng "cancelled": true. Gumagana nang pare-pareho ang mga dialog sa mga app: ang OpenInteractiveDialog ng plugin API ay tumatanggap ng parehong request.
