AI

Gumagamit ang mga AI feature ng Antimatter ng mga model na iyong pipiliin: isang cloud provider, o isang server sa iyong sariling network. Walang ipinapadala saan man hangga't hindi mo pa nakakonekta ang model. Tinatalakay ng pahinang ito ang mga model connection, bawat feature, ang data na ipinapadala nito, at paano itong isasara.

Ang "OpenAI-compatible" ay nangangahulugang isang server na nag-aalok ng parehong HTTP API ng OpenAI. Karamihan sa mga model server na maaari mong sariling gawin ay ganyan (halimbawa, Ollama, vLLM, server ng llama.cpp, o mga Whisper at text-to-speech server), pati na rin maraming cloud provider at gateway tulad ng LiteLLM o OpenRouter. Walang kailangang lisensya para sa anumang ng mga feature na ito.

Hindi nangangailangan ng Agents app ang mga built-in feature (rewrite, recaps, translation, at read aloud): gumagamit sila ng mga model connection na idadagdag mo sa System Console.

Mga model connection

Ang model connection ay isang AI provider na maaaring tawagin ng Antimatter: ang address nito, ang key nito, at ang mga model nito. Idadagdag mo ito nang isang beses, tapos pipiliin mo ito para sa bawat feature na gagamitin nito. May dalawang uri:

  • Mga server-wide connection, pinangangasiwaan ng mga system administrator sa System Console › AI › Model connections. Sila lamang ang maaaring magbigay ng serbisyo sa mga built-in feature. Maaari ring gamitin ng mga app, para sa mga tao na may pahintulot.
  • Mga community connection, idinadagdag ng mga admin ng isang community para sa kanilang sariling community sa mga setting ng community (tingnan sa ibaba). Ginagamit ng mga app para sa mga tao ng community. Hindi nila pinapaligiran ang mga built-in feature.

Ang AI section ng System Console ay ipinapakita sa mga tao na maaaring pamahalaan ang mga server-wide connection: mga system administrator, sa pamamaraan. Ang Model connections page nito ay nakalista ang mga server-wide connection at ang mga ng bawat community.

Ang Test ng Connection ay sinusubok ang address at key: hinaharap ng server ang endpoint para sa mga model nito, o ipinadala ang isang one-token chat. Ang binagong address ay sinusubok gamit ang na-save na key lamang pagkatapos mong i-save, o kung isulat ulit ang key. Pindutin ang Add connection upang i-save.

Ang server mismo ang nagpapadala ng mga request, kaya ito ay dapat makabigkas sa API: isang model server sa parehong compose project, sa inyong network, o sa Internet. Ang mga saluhang request ay sumusunod sa mga variable na HTTP_PROXY at HTTPS_PROXY.

Kapag tinanggal ang isang connection, mawawala ang key nito. Ang mga feature na gumagamit nito ay titigil sa paggamit ng AI hangga't pipiliin ninyo ang ibang connection.

Mga limitasyon at budget

May apat na limitasyon bawat connection. Ang blangko o 0 ay nangangahulugang walang limitasyon.

  • Requests bawat minuto at Bawat tao, requests bawat minuto. Ito ay binibilang ng bawat server nang hiwalay: isang cluster ng tatlong server ay pumapasa ng hanggang tatlong beses ang rate.
  • Tokens bawat buwan at Bawat tao, tokens bawat buwan: mga budget ng tokens, bawat buwan ng kalendaryo (UTC), na binibilang sa database para sa buong cluster. Maaaring lumampas nang kaunti ang budget kung may ilang request na tumatakbo sa parehong oras.

Ang mga limitasyon bawat tao ay tumutukoy din sa rewrite at sa mga recap: ito ay binibilang sa taong nag-rewrite, o sa may-ari ng recap.

Paggamit

Ang listahan ay nagpapakita ng paggamit ng bawat connection ngayong buwan. Ang Paggamit ay nagbubukas ng mga detalye: pumasok at lumabas na tokens, mga request, ang buwang budget, paggamit bawat araw (UTC) at bawat gamit (I-rewrite, Mga Recap, Auto-translation, Mula sa teksto hanggang sa boses, Mga tao, sa pamamagitan ng mga app, o isang app).

Bawat tawg na ginawa ng isang tao o app sa pamamagitan ng isang connection ay naglilista rin ng audit record: sino, ang connection, ang gamit, ang model, ang bilang ng tokens, at kung naging matagumpay, ngunit hindi kung ano ang sinabi. Ang mga built-in na feature ay binibilang lamang sa paggamit: ang translation ay nagdudulot ng isang tawg bawat mensahe at wika.

Mga community connection

Ang mga admin ng community ay nagdadagdag ng sariling connection ng kanilang community sa mga setting nito, sa tab na Model connections. Iisa ang form, ngunit walang Mga Komunidad: ang connection ng isang community ay gumagana lamang sa mga channel nito, para sa mga miyembro nito, at ang audience nito ay maaari lamang magpakilala ng sariling team nito. Ang mga role na may pahintulot na Manage model connections ay maaari ring pamahalaan ito. Sa default, mayroon ito ang mga admin ng community.

Hindi makabigkas ang connection ng isang community sa mga private o loopback na address (halimbawa, isang Ollama server sa inyong network), maliban kung nakalista sila sa System Console › Environment › Developer › Pahintulutan ang mga untrusted internal connections sa (ServiceSettings.AllowedUntrustedInternalConnections). Maaari ito ng mga server-wide na connection.

Tingnan ang Mga setting ng community para sa panig ng mga admin ng community.

Ang encryption key

Ang mga key at extra headers ng mga koneksyon ng model ay naka-encrypt sa database (AES-256-GCM) gamit ang isang encryption key. Ang backup ng database ay hindi nagpapakita ng mga ito. Hanapin ng server ang key sa sumusunod na pagkakasunod-sunod:

  1. Ang AM_AI_ENCRYPTION_KEY variable: 32 random bytes, naka-base64. Gumawa ng isa gamit ang openssl rand -base64 32.
  2. Kung wala, ang file ai-encryption.key sa root ng data directory ng server (FileSettings.Directory, ./data/ bilang default). Gagawa nito ng server, na mababasa lamang nito, sa unang pag-need ng koneksyon. Hindi mababasa nito ng mga app, export, at file archive.
Kung wala ang key, hindi mababasa ang mga na-save na API key, at kailangan muli ang pagbibigay ng key sa bawat koneksyon. I-back up ang key kasama ang database (tingnan ang Backups and upgrades), at itago ito nang hiwalay mula sa mga backup ng database.

Kapag dapat itakda ang variable:

  • Sa compose file ng site. Ang compose.yaml ay pumapasa ng AM_AI_ENCRYPTION_KEY mula sa .env, at pinapanatili ang key file sa data volume kapang walang laman ang variable. Mas maganda ang pagtakda ng variable: ang backup ng .env ay naglalaman ng key, hiwalay sa database. Idagdag ito sa .env at patakbuhin ang docker compose up -d: 
    echo "AM_AI_ENCRYPTION_KEY=$(openssl rand -base64 32)" >> .env
    Kung nagawa na ng server ang kanyang key file, ilagay ang key na hawak nito sa .env sa halip, upang manatiling mababasa ang mga na-save na key: ang docker compose exec antimatter cat /antimatter/data/ai-encryption.key ay ipapakita ito.
  • Isang cluster na ang mga file nito ay nasa S3. Walang magkatiwalaan na directory ang mga server nito, kaya hindi gagawa ng file ang server: itakda ang parehong variable sa bawat server. Hangga't hindi ito itinakda, hindi maaaring i-save ng mga koneksyon ang mga key.
  • Sa release archive o mga package, nasa data/ ang file (/var/lib/antimatter/data para sa mga package). Maaari mong itago ito doon, o itakda ang variable sa iyong environment file.

Para palitan ang key, itakda ang bago sa AM_AI_ENCRYPTION_KEY at ang lumang isa sa AM_AI_ENCRYPTION_PREVIOUS_KEYS (maraming key na hiwalay ng koma): mababasa pa rin ang mga key na na-save gamit ang lumang isa. Ang key ng isang koneksyon ay naka-encrypt gamit ang bagong key kapag inilagay mo ulit ito. Panatilihing nasa listahan ang lumang key hangga't inilagay ulit ang key ng bawat koneksyon.

Ang mga built-in na feature

Sa System Console › AI › Built-in features, pumili para sa bawat feature ng server-wide connection at model, o Patay. Ang feature na walang connection ay hindi gumagamit ng AI. Ang Load models ay naglilista ng lahat ng model ng connection; sa default, gumagamit ang bawat feature ng chat model ng connection.

Ang connection na nangangailangan ng atensyon, o na tinanggal, ay magpapa-fail sa feature hangga't hindi mo napipili ang isa pa: sinasabi ng page na ito.

Mga AI agent

Naka-on nang default ang Agents app (id mattermost-ai). Dalawang hakbang ang kailangan para ito i-configure: magdagdag ng service (isang koneksyon sa model provider), tapos gumawa ng mga agent (mga bot na gumagamit ng service).

Ang mga agent ng Agents app ay gumagamit pa rin ng sariling AI Services ng app, hindi ng model connections. Ang mga built-in features ay hindi na dumadaan sa app. Sa server na na-upgrade sa 0.9.0, ang mga service ng app ay na-copy din nang isang beses sa server-wide model connections (tingnan ang Upgrading to 0.9.0).

1. Magdagdag ng service

Pumunta sa System Console › Plugins › Agents at, ilalim ng AI Services, pindutin ang Add an AI Service. Piliin ang Service type:

  • OpenAI Compatible: para sa model server na iyong pinapatakbo, o anumang provider na may OpenAI-style API. Punan ang API URL (halimbawa, http://ollama:11434/v1 o http://vllm.internal:8000/v1), at ang API Key lamang kung kailangan ng server. Kung ang server ay tumatanggap lamang ng Chat Completions API, pabain ang Use Responses API.
  • OpenAI, Anthropic, Google Gemini, Google Vertex AI, AWS Bedrock, Azure, Cohere, Mistral: mga hosted provider. Bawat isa ay nangangailangan ng API Key (Bedrock: AWS region at credentials o IAM role; Vertex AI: project, region, at service account; Azure: kailangan din ng API URL).

Pagkatapos, itakda ang Default model (isang listahan kung ang provider ay maaaring ilarawan ang mga model nito, kung hindi, isulat ang pangalan), at, kung hindi nila ilarawan ng provider, ang Input token limit at Output token limit. Maaaring tumanggap ng tungkulin ang Fallback Service kapag nabigo ito. I-save.

Ang server mismo ang nagpapa-require ng mga ito, kaya dapat maabot nito ang API: isang model server sa parehong compose project, sa network mo, o sa Internet. Ang mga saluhang request ay sumusunod sa mga variable na HTTP_PROXY at HTTPS_PROXY.

2. Lumikha ng mga agent

Ang mga Agent ay nilikha sa pahina ng Mga Agent ng web app: buksan ito gamit ang Pamahalaan sa agent selector ng Agents panel (sa classic interface, maaari ring mula sa product menu). Ang address nito ay https://chat.example.com/plug/mattermost-ai/agents. Bawat agent ay may Display Name, Agent Username (paano ito ma-mention ng mga tao), Service, at opsyonal na model, Custom Instructions, at mga switch para sa Enable Vision (mga imahe) at Enable Tools. Ang tab ng Access nito ay naglilimita sa aling mga channel ito ay maaaring gamitin at aling mga user ang maaari itong gamitin. Sa ilalim ng AI Functions sa System Console, ang Default bot ay pumipili ng agent na gagamitin kapag wala pang napili, halimbawa para sa mga summary ng tawag.

Sa default, maaari ng bawat user na lumikha ng sariling mga agent, gamit ang mga service na iyong naka-configure. Para itama ito sa mga administrator lamang, alisin ang permiso na Pamahalaan ang sariling AI agent mula sa role ng mga miyembro sa System Console › Pamamahala ng Mga User › Mga Permiso.

Mga opsyonal na feature ng Agents app

  • Embedding search (eksperimental, off): semantic search sa mga mensahe. Kailangan nito ng PostgreSQL na may pgvector extension at isang embedding model (OpenAI o OpenAI-compatible). Ipinapadala nito ang bawat mensahe sa embedding model, kasama ang mga pribadong channel at direct message.
  • Web search (off): nagpapahintulot sa mga agent na maghanap sa web gamit ang Google, Brave, o isang SearXNG server na iyong pinapatakbo.
  • Native tools: sa mga provider na nag-aalok ng mga ito, maaari ng mga agent na gamitin ang sariling web search ng provider (on sa default para sa mga bagong agent, kung sinusuportahan), web fetch, at code execution. Ito ay tumatakbo sa provider. I-off nito bawat agent.
  • Model Context Protocol (MCP): ikonekta ang mga agent sa mga MCP server na tiwala mo, para sa karagdagang tools.
  • Debug: Trace Output (off, server logs o isang OpenTelemetry endpoint) at Enable Token Usage Logging, na sumusulat ng bilang ng token sa logs/agents/token_usage.log.

Speech-to-text: transkripsyon at captions ng tawag

Ang mga tawag ay maaaring magkaroon ng transkripsyon, kasama ang live captions, gamit ang isang speech-to-text server na nag-aalok ng OpenAI-compatible /v1/audio/transcriptions endpoint. Ang setup ay nasa Tawag at boses. Kapag naka-on ang Summarize transcriptions, ang default agent ay nagpo-post din ng buod ng bawat transkripsyon.

Mula sa teksto hanggang sa boses: basahin nang malakas

Kapag naka-on ang mula sa teksto hanggang sa boses, ang menu ng bawat mensahe ay may Basahin nang malakas: ipinapadala ng server ang teksto ng mensahe sa isang text-to-speech API at pinapalabas ang audio. Ang mga setting ay nasa System Console › Mga Integration › Mula sa teksto hanggang sa boses:

SettingKey at variableAno ang ilalagay
Basahin nang malakas ang mga mensaheTextToSpeechSettings.Enable, AM_TEXTTOSPEECHSETTINGS_ENABLEtrue (naka-off sa default)
API base URLTextToSpeechSettings.URL, AM_TEXTTOSPEECHSETTINGS_URLAng base URL hanggang sa kasama ang /v1, halimbawa http://tts.internal:8000/v1. Tinatawag ng server ang /audio/speech endpoint nito.

Para gumamit ng model connection sa halip sa address at key sa itaas, piliin ito para sa Mula sa teksto hanggang sa boses sa AI › Built-in features. Sabi ng pahina na ang mga mensahe ay babasahin nang malakas gamit ang connection na iyon: hindi gagamitin ang API base URL at API key, pero gagamitin pa rin ang Boses, at pati ang Model kapag wala pang model na tinatawag ng connection. Dapat pa ring naka-on ang Basahin nang malakas ang mga mensahe.

Bago ipadala, tinatanggal ng server ang mga code block, link, emoji code, at formatting, at pinapanatili lamang ang 4000 na character. Hinihiling nito ang MP3 audio at pinapanatili ang huling 64 na resulta sa memory, kaya ang mensahe na dalawang beses binasa ay isang beses lamang ipinapadala.

Awtomatikong pagsasalin

Ang awtomatikong pagsasalin ay nagpapakita ng mga mensahe ng isang channel sa sariling wika ng bawat mambabasa. I-configure ito sa System Console › Konfigurasyon ng Site › Localization, ilalim ng Auto-translation:

SettingSusiDefault
PaganahinAutoTranslationSettings.EnableOff
Translation providerAutoTranslationSettings.Providerconnection (ipinapakita bilang “Model connection (recommended)”, ang napipili kung wala ang naka-set), libretranslate, openai (“OpenAI-compatible API, set up here”) o agents (“AI chat app's service (older)”)”
Mga pinapayagang wikaAutoTranslationSettings.TargetLanguagesen: ang mga wikang maaaring salain ang mga mensahe
Translation timeout (ms)AutoTranslationSettings.TimeoutMs5000
Limitahan ang auto-translation sa mga Direct Message at mensahe ng grupoAutoTranslationSettings.RestrictDMAndGMOff

Bawat provider ay may sariling mga field:

  • Model connection: isang server-wide connection at ang model nito, parehong setting sa Auto-translation sa AI › Built-in features (AISettings.AutoTranslation). Ang dedikadong translation model ay mabilis at tumpak; ang general LLM ay gumagana rin.
  • LibreTranslate: LibreTranslate API Endpoint at LibreTranslate API Key (AutoTranslationSettings.LibreTranslate.URL, .APIKey). Ang LibreTranslate server ay maaaring tumakbo sa sarili mong network.
  • OpenAI-compatible API: API base URL (hanggang sa kasama ang /v1; ginagamit ng server ang chat completions endpoint nito), Model at API key (AutoTranslationSettings.OpenAI.URL, .Model, .APIKey). Ang maliit na translation model na tumatakbo sa local ay maganda ang resulta.
  • AI chat app's service (older): ang provider ng mga server na naka-set bago ang 0.9.0, na gumagamit ng service ng Agents app. Hindi na ito nangangailangan ng app: nagtatali ito gamit ang connection na napili para sa auto-translation sa AI › Built-in features, o kaya naman gamit ang connection na nakopya mula sa service ng app noong upgrade. Ang Switch to Model connection ay naglalakbay ng setting sa recommended provider.

Kapag naka-on na ito, ang mga admin ng channel ang nagpapa-on ng pagsasalin para sa isang channel sa mga setting nito (Auto-translation), at bawat miyembro ay maaaring lumabas mula sa menu ng channel (Translate messages). Sa mga direct at group message, maaaring i-on ng anumang miyembro; kapag naka-on ang restriction, hindi available ang pagsasalin doon. Ang mga salin na mensahe ay nagpapakita ng "Translated from …" na may link sa orihinal.

Ang code, links, mentions at emoji ay pinapalit ng mga placeholder bago ipadala ang text, at ibinabalik pagkatapos.

Upang manatili ang lahat sa iyong network, ituturo ang bawat feature sa mga server na iyong pinapatakbo. Kapag may cloud provider, suriin ang mga tuntunin nito sa pagpapanatili ng data, at ipaalam sa iyong mga user kung aling mga feature ang nagpapadala ng kanilang mga mensahe palabas.

Pagpapatay ng AI

Wala iisang switch: bawat feature ay may sarili nitong switch.

  • Rewrite and recaps: itinatag ang mga ito sa Patay sa System Console › AI › Built-in features. Patuloy na binabasa ng mga tao ang mga recaps na kanilang mayroon na.
  • Model connections: burahin ang connection upang mapigilan ang anumang paggamit nito. Kung wala nang connection, hindi na maaaring gamitin ang AI ng built-in features o ng mga app sa pamamagitan ng server.
  • Mga Agent: patayin ang Agents app sa System Console › Mga Plugin › Pamamahala ng Plugin. Tinatanggal din nito ang mga call summaries.
  • Transkripsyon at captions: AM_CALLS_ENABLE_TRANSCRIPTIONS=false at AM_CALLS_ENABLE_LIVE_CAPTIONS=false (ang mga default).
  • Basahin nang malakas: patayin ang Basahin nang malakas ang mga mensahe (AM_TEXTTOSPEECHSETTINGS_ENABLE=false, ang default), kahit gumagamit ito ng connection o hindi.
  • Pagsasalin: auto-translation off (AM_AUTOTRANSLATIONSETTINGS_ENABLE=false, ang default).

Ang pagpapatalo ng Agents app ay hindi nagpapatalo ng ibang features: gumagamit sila ng model connections o ng kanilang sariling APIs.
