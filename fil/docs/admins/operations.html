Operasyon

Panghusga sa server, gawin itong makapangasiwa ng mas maraming tao, tukuyin kung gaano katagal ang pagpapanatili ng data, at ayusin ang mga problema na karaniwang nakikita ng mga administrator.

Mga Health Check

  • amctl --local system status (sa loob ng container: docker compose exec antimatter amctl --local system status). Ang health check ng Docker image ay nagpapatupad nito bawat 30 segundo, kaya ang docker compose ps ay nagpapakita ng healthy o unhealthy.
  • Ang GET /api/v4/system/ping ay sumasagot nang walang pag-sign-in, para sa isang external monitor o load balancer: curl -fsS https://chat.example.com/api/v4/system/ping.
  • Ang antimatter db ping ay sinusuri kung maaabot ang database gamit ang mga nakonfigura na setting.
  • Ang System Console › Reporting › Mga Statistics ng System ay nagpapakita ng bilang ng mga user, post, at session, at ang Optimization ng Workspace ay naglilista ng mga problema sa configuration na dapat pansinin.

Metrics

Maaaring ipubliko ng server ang mga Prometheus metrics: bilis at haba ng mga request, mga websocket connection, paggamit ng database at cache, mga job, plugin hooks, at iba pa. I-on ito sa System Console › Environment › Performance Monitoring:

SettingKey at variableDefault
Paggawin ang Performance MonitoringMetricsSettings.Enable, AM_METRICSSETTINGS_ENABLEOff
Listen AddressMetricsSettings.ListenAddress, AM_METRICSSETTINGS_LISTENADDRESS:8067
Paggawin ang Client Performance MonitoringMetricsSettings.EnableClientMetricson: ang mga browser at app ay nag-uulat ng kanilang sariling timing

Pagkatapos, ang Prometheus ay nag-a-“scrape” ng http://<server>:8067/metrics. Bawat metric ay ipinapubliko gamit ang pangalan nito sa Mattermost (mattermost_…) at ang pangalan nito sa Antimatter (antimatter_…), kaya ang mga existing na Mattermost dashboard ay mananatiling gumagana. Ang mga app ay nagpapakita ng kanilang sariling metrics, halimbawa ang Agents app sa /plugins/mattermost-ai/metrics.

Hindi kailangan ng sign-in para sa port ng metrics: itago ito sa isang private network. Ang compose file ng site ay hindi nagpapakita nito; upang ma-“scrape” ito mula sa host, magdagdag ng "127.0.0.1:8067:8067" sa ports ng antimatter service.

Ang Metrics app

Kung wala kang Prometheus server, ang Metrics app (naka-off sa default, tingnan ang Mga built-in na app) ay nagkokolekta ng parehong metrics sa isang maliit na time-series database sa loob ng Antimatter: bawat 60 segundo, at pinapanatili ng 15 araw. Ipinapalito nito ang metrics endpoint kapag nag-start. Ang kanyang pahina sa System Console › Mga Plugin ay nagpapakita ng laki ng database at nagbibigay-daan sa iyo na mag-download ng mga dump ng data, para sa sarili mong pagsusuri o upang idagdag sa isang bug report; ang pinakabagong araw ay idinadagdag din sa mga support packet.

Support packet

Ang support packet ay isang zip file na may mga kailangan upang matukoy ang isang problema: mga bersyon, estadistika, ang configuration na may mga secret na tinanggal, ang listahan ng mga app at jobs, ang database schema, ang kamakailang log at performance profiles. Gumawa ng isa gamit ang amctl system supportpacket, o sa System Console mula sa menu sa itaas ng kanyang sidebar (Commercial Support, na pagkatapos ay nagbibigay-daan sa iyo na pumili ng kailangan isama). Basahin ito bago ibahagi: hindi ito naglalaman ng mga mensahe, ngunit naglalaman ito ng mga pangalan ng mga community, user, at setting.

Performance at pagpapalaki

Isang server na may 2 CPU cores at 4 GB ng memory ay maaaring maglingkod sa ilang daang tao. Bago magdagdag ng mga server, tingnan ang:

  • Ang database. Ang PostgreSQL ang nagtatalima ng trabaho: bigyan ito ng mabilis na storage at memory. Ang mga read replica ay maaaring tanggungan ang load ng pagbabasa (SqlSettings.DataSourceReplicas, isang listahan ng mga connection URL).
  • Paghahanap. Sa default, ang mga mensahe ay hinahanap sa database. Para sa malalaking server, ang Elasticsearch o OpenSearch ay maaaring tanggungan ang paghahanap at pag-index: System Console › Environment › Elasticsearch (ElasticsearchSettings: Uri ng backend Elasticsearch o OpenSearch, Server Connection Address, mga kredensyal, pagkatapos ay i-activate ang pag-index, gawin ang index, at i-activate ang paghahanap).
  • Mga Tawag. Ang media ng mga tawag ang pinakamabigat na load. Ilipat ito sa isang rtcd server: tingnan ang Mga Tawag at boses.
  • Mga bukas na file. Bawat konektadong tao ay nagpapatuloy ng isang bukas na websocket. Ang production compose file ng antimatter-docker ay nagtaas ng limit sa 49152 (ulimits: nofile); gawin ang pareho gamit ang systemd (LimitNOFILE).
  • Mga Log. Pababaan ang LogSettings.ConsoleLevel sa INFO o WARN: ang mga DEBUG log ay maraming naglala sa isang mabibilog na server.

Mataas na availability

Maraming Antimatter server ang maaaring tumakbo bilang cluster sa likod ng load balancer, nang walang lisensya. Dapat nilang magbahagi ng iisang PostgreSQL database, iisang S3 file storage, at ang configuration sa database (AM_CONFIG). Sa System Console › Environment › High Availability (ClusterSettings): i-on ang Enable High Availability Mode (ClusterSettings.Enable), bigyan ng iisang Cluster Name (ClusterSettings.ClusterName) ang bawat node, at payagan ang mga node na makapag-ugnayan sa bawat isa sa gossip port, 8074 TCP at UDP (ClusterSettings.GossipPort). Nakikilala ng mga node ang bawat isa sa pamamagitan ng database. Dapat ding ipasa ng load balancer ang websockets. Para sa mga tawag sa loob ng cluster, gamitin ang rtcd.

Retention ng data

Sa default, pinapanatili ng Antimatter ang bawat mensahe at file nang walang hanggan. Para matanggal ang lumang mga ito nang awtomatiko, pumunta sa System Console › Compliance › Data Retention Policies:

  • Ang Global retention policy ay nagtatakda ng Channel & direct message retention at File retention para sa buong server: Keep forever, o isang bilang ng oras, araw, o taon (DataRetentionSettings.EnableMessageDeletion, MessageRetentionHours, EnableFileDeletion, FileRetentionHours).
  • Ang Custom retention policies ay nagtatakda ng ibang haba ng panahon para sa mga napiling community at channel.
  • Ang deletion job ay tumatakbo araw-araw sa oras na iyong pipili (DataRetentionSettings.DeletionJobStartTime, 02:00 UTC sa default). Ang Run Deletion Job Now ay nagpapatupad nito agad, at ang Policy log ay naglilista ng mga tinanggal ng bawat run.
Ang mga tinanggal na mensahe at file ay nawawala nang tuluyan, mula sa database at mula sa file storage. Suriin ang mga haba ng panahon bago i-on ang isang policy, at tandaan na ang iyong mga backup ay nagpapatuloy pa ring naglalaman ng tinanggal na data hangga't hindi pa ito nag-expire.

Compliance export at audit logs

  • System Console › Pagkakaunawa › Pag-export ng Compliance ay nag-e-export ng lahat ng mensahe at files araw-araw (Enable Compliance Export, MessageExportSettings.EnableExport, off by default; Oras ng Compliance Export, 01:00 by default) sa isa sa mga format na mababasa ng mga archiving system: CSV, Actiance XML, o Global Relay (isang zip file, o EML na ipinadala sa pamamagitan ng SMTP). Ang amctl compliance-export ay nagpapatakbo at nagda-download ng mga export mula sa command line.
  • Ang Compliance Monitoring (ComplianceSettings) ay sumusulat ng mga araw-araw na ulat sa isang directory. Ito ang mas lumang mekanismo; mas mabuti ang Compliance Export.
  • Ang Audit Logging (beta, ExperimentalAuditSettings) ay nagre-record ng mga pang-administrasyon at pangkaligtasan na kaganapan (tulad ng sign-in, pagbabago ng mga permiso at setting) sa sariling file.
  • Ang Custom Terms of Service ay humihingi sa lahat na tanggapin ang iyong mga tuntunin bago gamitin ang Antimatter, at muli pagkatapos mong baguhin ito.

Mga karaniwang problema

"Hindi makakonekta sa server", o lumalabas lang ang mga mensahe pagkatapos ng reload

Hindi dumadaan ang websocket. Tingnan kung ang reverse proxy ay nagpasa ng mga Upgrade at Connection headers (tingnan ang halimbawa ng nginx), at kung ang URL ng site ay eksaktong tumutugma sa address sa browser, kasama ang https.

Hindi matagumpay ang mga upload dahil sa "413 Request Entity Too Large"

Tinutanggihan ng proxy ang laki. Itaas ang limit nito (nginx client_max_body_size) ng hindi bababa sa Pinakamataas na Laki ng File sa System Console › Environment › File Storage (FileSettings.MaxFileSize, 100 MB ang default).

Hindi makapagsimula ng mga tawag, o sumasali pero walang naririnig

Kung wala pang admin ang makapagsimula ng tawag, patayin ang Test mode ng Calls. Kung sumasali pero walang naririnig, blocked ang media port o maling address ang ipinapaalam ng server: buksan ang 8443 UDP at TCP, at i-set ang ICE Host Override sa likod ng NAT. Kailangan ng TURN server ang mga nasa network na nagbabanta sa pareho. Tingnan ang Calls and voice.

Walang laman ang GIF picker

Tingnan ang GIF service URL (http://gifs:8080/v2 gamit ang compose file ng site) at API key (ang GIFS_API_KEY ng .env) sa System Console › Plugins › Mga GIF, at kung tumatakbo ang gifs service: docker compose ps gifs.

Walang dumating na email

Gamitin ang Test ng Connection sa System Console › Environment › SMTP, siguraduhing hindi pa rin test@example.com ang Mga Notisikasyon Mula sa Address, at hanapin sa log ang smtp o mail.

Napakita ng app na "Failed to start"

Hanapin ang id nito sa log (docker compose logs antimatter | grep <app id>). I-disable at i-enable ito sa Plugin Management para i-restart.

Hindi tumatakbo ang server

Basahin ang dulo ng log nito. Pinakamadalas ay hindi maabot ang database (tingnan ang AM_SQLSETTINGS_DATASOURCE gamit ang antimatter db ping), nabigo ang database migration (ibalik ang backup na kinuha bago ang upgrade at i-report ang error), o okupado na ang listen port.

Nalock sa administrator account

Mula sa server, hindi kailangan ng password sa local mode:

docker compose exec antimatter amctl --local user change-password admin --password 'a-new-password'
docker compose exec antimatter amctl --local user resetmfa admin
docker compose exec antimatter amctl --local roles system-admin admin

Pag-uulat ng bug

Magbukas ng isyu sa Antimatter community repository, kasama ang bersyon, kung paano mo ito na-install, ang iyong ginawa, at ang mga pinalamutang linya ng log. Iulat nang pribado ang mga problema sa seguridad, ayon sa paliwanag ng patakaran sa seguridad.
