Kaligtasan

Isang checklist upang patibayin ang isang Antimatter server: ano ang ipapakita, ang mga limitasyon at setting sa privacy na dapat suriin, ang mga serbisyo sa labas na tinutukoy ng server, at kung paano mag-uulat ng isang problema sa kaligtasan.

Ano ang ipapakita

PortServicePagpapalabas
443/tcp, 443/udp, 80/tcpAng HTTPS proxy (Caddy o nginx)Pampubliko: ito ang paraan ng pag-abot ng mga tao sa Antimatter.
8443/udp at 8443/tcpMedia ng TawagPampubliko, kung gumagamit ng Tawag ang mga tao mula sa labas ng iyong network.
8065/tcpWeb server ng AntimatterSa proxy lamang: ipakita ito sa 127.0.0.1 (HTTP_PORT=127.0.0.1:8065).
8067/tcpMetricsPribadong network lamang, kapag pinagana. Walang sign-in.
8074/tcp at udpGossip ng clusterSa pagitan ng mga node ng cluster lamang.
5432, 9000, 8080, 8066PostgreSQL, file storage, GIF service, push proxyHindi kailanman. Ang mga compose file ay nagpapanatili ng mga ito sa mga internal network na walang published port.

Ang compose file ng site ay nagpapatakbo rin ng bawat container gamit ang no-new-privileges, nagpapatakbo ng Antimatter bilang isang unprivileged user sa isang distroless image, at nagpapatakbo ng GIF service gamit ang isang read-only file system. Ang database, ang storage, at ang GIF service ay nasa network na walang access sa Internet.

Checklist pagkatapos mag-install

  1. Gumawa ng unang administrator account bago maabot ng iba ang server (Pag-install).
  2. I-serve ang Antimatter sa pamamagitan ng HTTPS lamang, at itakda ang site URL sa https:// address (Domain at HTTPS).
  3. Panatilihing mababasa ng root (o user ng server) lamang ang .env, config.json, at mga TLS key: chmod 600 .env.
  4. Magdesisyon kung sino ang makakagawa ng account, itigil ang Pahintulutan ang Open Server maliban kung pampubliko ang komunidad, at i-on ang Kinakailangan ng Email Verification kapag gumana na ang email (Sign-in at mga account).
  5. I-on ang multi-factor authentication, at ipilit ito sa mga account ng administrator kahit sa minimum, o gamitin ang ng iyong identity provider.
  6. Suriin ang mga koneksyon sa labas sa ibaba, lalo na ang STUN server na ginagamit ng Tawag bilang default.
  7. Gawing backup, at subukang i-restore (Mga backup at upgrade).
  8. Panatilihing up-to-date ang mga image: ang mga security fix ay dumating kasama ang mga bagong image.

Rate limiting

Maaaring limitahan ng server ang bilang ng API requests na ginagawa ng bawat client. Sa default, ito ay naka-off. Sa System Console › Environment › Rate Limiting:

SettingSusiDefault
Paganahin ang Rate LimitingRateLimitSettings.EnableOff
Pinakamataas na Queries bawat SegundoRateLimitSettings.PerSec10
Pinakamataas na Burst SizeRateLimitSettings.MaxBurst100
Memory Store SizeRateLimitSettings.MemoryStoreSize10000 clients tracked
Mag-iba ang rate limit ayon sa remote addressRateLimitSettings.VaryByRemoteAddron
Mag-iba ang rate limit ayon sa userRateLimitSettings.VaryByUserOff
Mag-iba ang rate limit ayon sa HTTP headerRateLimitSettings.VaryByHeaderwalang laman

Kung nasa likod ng proxy, ang mga limitasyon base sa address ay gumagana lamang kung alam ng server ang address ng bawat client (ServiceSettings.TrustedProxyIPHeader at ServiceSettings.TrustedProxyIPs, tingnan ang Client addresses behind a proxy). Kung hindi, tila mula sa proxy ang lahat ng request, at iisang limit lang ang ibinahagi ng lahat. Ito rin ang nangyayari sa IP filtering at sa mga address sa audit logs.

Ilimitado nang hiwalay ang mga pagtatangkang mag-sign in: ang Maximum Login Attempts (10) ay naglo-lock ng account pagkatapos ng ganun kalaking maling password.

IP filtering

System Console › Konfigurasyon ng Site › IP Filtering ay naglilimita ng access sa server ayon sa IP address, gamit ang mga allow at deny rule (bawat isa ay isang address o CIDR range). Kapag on ang I-enable ang IP Filtering, hindi makakapunta sa server ang mga taong ang address nila ay tumutugma sa isang deny rule, o walang tumutugma sa allow rule kung mayroon nang mga allow rule. Tinatanggi ng pahina ang mga rule na pindot ang sarili mong address. Kung nasa likod ng proxy, i-configure muna ang mga client address (Mga client address sa likod ng proxy): kung hindi, tila galing sa proxy ang lahat ng request.

Ipakita ang Buong PangalanPrivacySettings.ShowFullNameonKung Off, ang mga buong pangalan ay nakatago at ipapakita ang mga username sa halip.
Paganahin ang pag-i-ignore, pag-block, at mga message requestPrivacySettings.EnableUserBlockingonTingnan sa ibaba.

Pag-iignore, pag-block, at mga hiling sa mensahe

Kapag on ang Paganahin ang pag-i-ignore, pag-block, at mga message request (ang default), maaaring i-ignore at i-block ang isa’t isa, at pumili na tanggapin ang mga Direct Message mula sa mga hindi kilala bilang message request, na hindi nagpapadala ng notisikasyon hangga’t hindi tinatanggap. Angkop ito sa mga pampublikong komunidad. Sa isang workplace na dapat laging makapag-ugnayan ang mga kapwa, itigil ito (AM_PRIVACYSETTINGS_ENABLEUSERBLOCKING=false): hindi na ipinapatupok ang anumang bagay, ngunit pinapanatili ang mga listahan at mga desisyon ng mga tao, at magkakaroon muli ng epekto kung ibabalik ito.

Mga session at token

  • Habang ng session at idle timeout: tingnan sa Sign-in and accounts. Mas maikling session nangangahulugang ang nawalang laptop o phone ay mas maikli ang panahon na naka-sign in.
  • I-enable ang mga Personal Access Tokens (ServiceSettings.EnableUserAccessTokens, off) ay nagpapahintulot sa mga tao na gumawa ng API token; Pinakamataas na Tagal ng Validity ng Personal Access Token (araw) ang naglilimita sa kanila. Parehong nasa System Console › Mga Integration › Pamamahala ng Integration.
  • Para palabasin ang lahat nang sabay-sabay, halimbawa pagkatapos ng posibleng paglabag: Burahin ang Lahat ng Session sa System Console › Pamamahala ng Mga User › Mga User.

Mga koneksyon sa mga serbisyo sa labas

Hindi nakikipag-ugnayan ang Antimatter sa anumang serbisyo na pinapatakbo ng Mattermost, Inc. Hindi nagpapadala ng telemetry, crash reports, o security update checks, at hindi humihingi ng mga product notices. Ang isang configuration na dala mula sa Mattermost na nagpapakita pa rin ng isa sa mga serbisyo ng Mattermost (ang mga push service nito, app marketplace, notices, o STUN server para sa mga tawag) ay hindi nagpapagawa ng server na makikipag-ugnayan sa kanila: ang mga address na iyon ay pinagbabalewala.

Ang server at mga app ay nakikipag-ugnayan sa ibang mga serbisyo sa labas lamang para sa mga feature na nangangailangan nito, at sa mga serbisyo na iyong inuugnay:

FeatureNakikipag-ugnayanSa default
Mga tawag: paghahanap ng mga pampublikong address gamit ang STUN. Ang server at bawat tao na sumasali sa tawag ay nagpapadala ng isang hiling, na ipinapakita sa STUN server ang IP address at port nito.Pampublikong STUN server ng Cloudflare, stun.cloudflare.comon, habang aktibo ang Calls app. Para baguhin ito, tingnan ang Calls.
Link previews: hahakot ng server ang mga pahina na nakatalik sa mga mensahe (Pahintulutan ang website link previews, ServiceSettings.EnableLinkPreviews)ang mga website na nilalangkaw ng mga taoon. I-off gamit ang AM_SERVICESETTINGS_ENABLELINKPREVIEWS=false.
Mga push notification sa mobile appang sarili mong push proxy (Push notifications)off hangga't hindi mo pa itinakda ang address nito
Ang remote app marketplace (PluginSettings.EnableRemoteMarketplace)ang Marketplace URL na itinakda mooff, at walang address
Emailang SMTP server moang default na server ay localhost
Single sign-on, AI models, speech-to-text at translation, outgoing webhooks, at mga app tulad ng Mail, Calendar, GitHub, GitLab o Jiraang mga serbisyo na iyong ikakalkulaoff hangga't hindi mo pa ito ikakalkula

Sa pamamagitan ng default, tumatanggi ang server na makonekta sa mga pribado at loopback na address para sa mga ito (link previews, webhooks, apps), kaya hindi maaaring gamitin ang isang mensahe o integration upang maabot ang iyong internal network. Ilista ang mga internal na host na maaaring maabot sa Pahintulutan ang mga untrusted internal connections sa (ServiceSettings.AllowedUntrustedInternalConnections, sa System Console › Environment › Developer); ang compose file ng site ay nakalista ang gifs doon.

Pag-uulat ng vulnerability

Uulat ng mga problema sa seguridad nang pribado, ayon sa paliwanag sa Antimatter security policy, hindi sa mga public na issue.
