Pagpapatakbo ng Antimatter para sa isang organisasyon

Kailangan ng mas maraming kontrol ang workspace ng kompanya o organisasyon kaysa sa isang hobby community: sino ang makapasok, ano ang makikita ng mga nasa labas, gaano katagal na nilalagay ang mga mensahe at paano nila ito na-archive. Karamihan sa mga ito ay mga setting ng server: sa pahinang ito, ipinapakita kung ano ang umiiral, ano ang maaari mong gawin, at ano ang hihiling sa iyong system admin.

Sino ang nagdedesisyon

Sa isang organisasyon, karaniwang pinangangalagaan ng mga community admin ang workspace araw-araw, at pinangangalagaan ng isang IT team ang server. Ang pagkakaiba ay ganito:

  • Iyong sarili, bilang community admin: mga setting ng community, mga channel at kategorya, mga role, onboarding, mga attribute ng miyembro, mga channel ng mga bisita, moderation at mga integrasyon. Lahat nito ay nakasalaysay sa gabay na ito.
  • Ang system admin: sino ang makagawa ng account at paano nag-sign-in ang mga tao, mga guest account, mga server-wide na permissions, retention ng mga mensahe, compliance exports, mga privacy setting at mga app. Nakalagay ito sa System Console.

Kung ang iyong server ay para lamang sa inyong organisasyon, hilingin sa iyong system admin na itakda ang Uri ng mga bagong community sa Workspace (System Console › Konfigurasyon ng Site › Mga User at Team), upang ang bawat bagong community ay isang workspace. Kung itatakda ito bago ang pag-upgrade sa Antimatter 0.9.0 (gamit ang environment variable na AM_TEAMSETTINGS_DEFAULTCOMMUNITYKIND=workplace), magagamit din ito sa mga community na umiiral na; pagkatapos nito, ang mga admin ng bawat community ang magbabago ng uri nito.

Sa isang maliit na organisasyon, karaniwang isang tao lamang ang gumagawa ng pareho. Kung ikaw ay system admin, makikita mo ang System Console mula sa iyong avatar menu; ang mga setting mismo ay ipinaliwanag sa Pagpapatakbo ng server.

Kontrollin kung sino ang makapasok

Sa community:

  • Gawing pribado ang community (Pribadong Team sa Mga setting ng team › Access), upang walang makakasali nang walang imbitasyon.
  • Payagan lamang ang mga email domain ng iyong organisasyon na sumali (tingnan ang Sino ang makapasok).
  • I-regenerate ang invitation link kapag may umalis na maaaring may hawak pa rito.

Sa server, magtanong sa iyong system admin tungkol sa:

  • Mag-sign in gamit ang mga account ng kumpanya: Maaaring mag-sign in ang Antimatter sa mga tao gamit ang AD/LDAP, SAML 2.0, OpenID Connect, Google o Office 365, sa System Console › Pagpapatunay. Ginagamit ng mga tao ang account na meron na sila, at ang pag-alis sa kumpanya ay pagsasara sa kanilang access.
  • Group sync: gamit ang AD/LDAP, ang mga group ng iyong directory ay maaaring pamahalaan kung sino ang nasa community at sa mga private channel nito. Sabi ng Access tab ng community na ang mga miyembro ay idinadagdag at tinatanggal ng mga linked groups.
  • Paglikha ng account: Pahintulutan ang Paglikha ng Account at Limitahan ang mga bagong miyembro ng system at team sa mga partikular na email domain, sa System Console › Pagpapatunay › Pagparehistro.
  • Mga patakaran sa pagiging miyembro base sa mga attribute: Sa pamamagitan ng attribute-based access control (System Console › Mga Attributo ng Sistema › Access Base sa Attribute), maaaring panatilihin ang isang community o channel para sa mga taong tugma ang mga attribute, tulad ng isang departamento o antas ng clearance. Kapag pinagana na ito, makikita sa mga setting ng inyong community ang mga tab na Team Membership at Channel Membership, at makikita sa mga setting ng channel ang tab na Membership Policy.

Mga bisita mula sa labas

Ang mga bisita ay nagbibigay-daan sa inyo na makipagtulungan sa mga kliyente, kontratista, at kasosyo sa ilang channel, nang hindi binibigyan sila ng access sa natitirang bahagi ng workspace (tingnan ang Mga Bisita). Ang mga account ng bisita ay hindi aktibo hangga't hindi pinapagana ng isang system admin sa System Console › Pagpapatunay › Access ng Bisita, kung saan maaari rin nilang:

  • ilista ang mga email domain na pinagmumulan ng mga bisita (Mga Pinapayagang Guest Domain);
  • kailanganin ang two-factor authentication para sa mga bisita (Patupad ang Multi-factor Authentication);
  • payagan ang mga bisita na mag-sign in gamit ang link na ipinadala sa email, nang walang password.

Mabuting gawi: bigyan ang bawat organisasyon ng kasosyo ng sariling pribadong channel, at suriin ang mga bisita sa iyong community mula panahon sa panahon. Ang mga channel na may bisita ay ipinapahiwatig nito sa kanilang header, kaya't hindi nakakalimutan kung sino ang nagbabasa.

Mga channel at istruktura

  • Itakda ang Uri ng komunidad sa Workspace (Mga setting ng team › General): Ang mga taong gumagawa ng channel ay maaaring i-archive ito, at aktibo ang mga tawag sa mga channel. Tingnan ang Uri ng komunidad.
  • I-off ang Nasa lahat ng channel ang mga miyembro (Mga setting ng team › General), maliban na lamang kung ang pagtakda ng uri sa Workspace ay nagawa na ito (tingnan sa ibaba): sa isang workspace, sumasali ang mga tao sa mga channel ng kanilang trabaho at umalis sa iba.
  • Gamitin ang Workspace o Hybrid na layout, at ang mga kategorya para sa lahat para sa mga channel na mahalaga sa lahat (mga anunsyo, tulong sa IT, opisina). Ang Workspace na preset ay nagtatakda ng uri sa Workspace at kusang pinapagana ang Members are in every channel off; ang Hybrid naman ay nagtatakda ng uri sa Guild, kaya ibalik ito sa Workspace pagkatapos.
  • Gumawa ng mga team para sa iyong mga departamento, kasama ang kanilang tag, lead, at channel, at paganahin ang Everyone shows a team badge upang makita agad ng mga tao kung saan sila nagtatrabaho (tingnan ang Mga Team sa loob ng isang community).
  • Gumamit ng mga attribute ng miyembro na itinatag ng mga admin para sa mga detalye tulad ng site, kumpanya ng isang subcontractor, o uri ng kontrata (tingnan ang Mga attribute ng miyembro).
  • Panatilihing pribado ang mga sensitibong channel, at kung kinakailangan, panatilihing para sa ilang roles lamang (tingnan ang Mga permiso ng channel).

Pribasiya sa pagitan ng mga kapwa-kaibigan

Ang mga ito ay mga setting ng server, nasa System Console › Konfigurasyon ng Site › Mga User at Team:

  • Show Email Address at Show Full Name: kung makikita ba ng mga tao ang email address at buong pangalan ng isa't isa. Ang dalawa ay ipinapakita bilang default.
  • Enable users to open Direct Message channels with: Any user on the Antimatter server, o Any member of the team lamang, ibig sabihin ay ang mga taong nagbabahagi ng isang community.
  • Enable ignoring, blocking and message requests: aktibo bilang default. Maraming lugar ng trabaho ang pinapagana ito off upang laging maaabot ang mga katrabaho; ang mga pinili ng mga tao ay naitatago kung sakaling ipagana ulit ito.
  • Limitahan ang export ng channel sa mga admin: sa default, ang sinumang mababasa ang channel ay maaaring i-export ang mga mensahe nito sa isang CSV file. I-on ito upang panatilihin ang mga export para sa mga channel, community, at system admin.

Gaano katagal pinapanatili ang mga mensahe

Bilang default, panatilihin ng Antimatter ang bawat mensahe at file magpakailanman. Ang isang system admin ay maaaring magtakda ng data retention policy sa System Console › Pagkakaunawa › Mga Data Retention Policy:

  • isang Global retention policy, na pinapaalisan ang mga mensahe at file matapos ang isang tiyak na panahon sa buong server;
  • Custom retention policies, para sa mga partikular na community at channel, halimbawa upang mas matagal na panatilihin ang isang legal channel o mas maikli ang isang social channel.

Ang mga pinapaalisan na mensahe ay permanenteng tinatanggal. Tumawag ng kasunduan sa mga tagal ng panahon sa inyong legal o compliance team bago humingi ng isang policy.

Pag-archive at compliance

  • Compliance export (System Console › Pagkakaunawa › Pag-export ng Compliance): isang regular na pag-export ng lahat ng mensahe sa CSV, Actiance XML o Global Relay EML, para sa isang archiving system. Ito ay hindi aktibo bilang default.
  • Channel export: upang ipasa ang history ng isang channel, i-export ninyo ito sa CSV mula sa menu nito (tingnan ang Export a channel).
  • Edit time limit: sa mga permissions ng server, ang isang system admin ay maaaring limitahan kung gaano katagal pagkatapos ng pag-post maaari ng mga tao na i-edit ang kanilang sariling mensahe.
  • Reports of sensitive information: maaaring i-report ng mga miyembro ang isang mensahe na hindi dapat naroon, halimbawa ang personal na data na na-post sa maling channel. Pagkatapos ay itinatago ito habang nagdedesisyon ang mga reviewer. Pinapagana ng isang system admin ang feature na ito at pinipili ang mga reviewer sa System Console › Konfigurasyon ng Site › Paglilinis ng Data Spillage (tingnan ang Mga Report).
  • Classification markings (System Console › Konfigurasyon ng Site › Mga Marka ng Klasipikasyon): isang banner na may antas ng klasipikasyon sa itaas at ibaba ng app, at isang antas bawat channel.
  • Custom Terms of Service (System Console › Pagkakaunawa): mga tuntunin na kailangang tanggapin ng lahat bago gamitin ang server.
  • Audit log: Inirekord ng server ang mga aksyon ng administrasyon at moderasyon sa audit log nito, na mababasa ng mga system admin.
