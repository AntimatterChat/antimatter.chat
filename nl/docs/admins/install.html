Antimatter installeren

Installeer Antimatter met de kant-en-klare compose-bestand, kies het juiste image of voer de server uit een releasearchief uit. Maak daarna het eerste beheerdersaccount aan.

Installeren met Docker Compose

Dit is de aanbevolen methode. Eén compose-bestand voert Antimatter, PostgreSQL, de opslag en de GIF-service uit. Je hebt een Linux-server nodig met Docker Engine en de Compose-plugin (docker compose), 2 CPU-kernen en 4 GB geheugen of meer.

1. Het compose-bestand downloaden

mkdir antimatter && cd antimatter
curl -fsSLO https://antimatter.chat/compose.yaml

2. Het .env-bestand aanmaken

Het compose-bestand leest zijn instellingen uit een .env-bestand in dezelfde map. Maak dit aan met willekeurige geheimen:

cat > .env <<EOF
SITE_URL=http://localhost:8065
POSTGRES_PASSWORD=$(openssl rand -hex 24)
S3_SECRET_KEY=$(openssl rand -hex 24)
GIFS_API_KEY=$(openssl rand -hex 24)
EOF
chmod 600 .env

Stel SITE_URL in op het adres dat mensen in hun browser invoeren, bijvoorbeeld http://192.168.1.20:8065 op een lokaal netwerk of https://chat.example.com met een domein. Bewaar het .env-bestand: de database en de opslag gebruiken deze wachtwoorden vanaf de eerste start, en je hebt hetzelfde bestand nodig om een back-up te herstellen.

3. Starten

docker compose up -d
docker compose ps

De eerste start duurt een of twee minuten: PostgreSQL maakt de database aan, een eenmalige bucket-service maakt de opslagbucket aan, een eenmalige gifs-stickers-service importeert het beginstickerpakket en Antimatter maakt zijn tabellen aan. Volg dit met docker compose logs -f antimatter.

Zie Domein en HTTPS als je vanaf het begin een domeinnaam en HTTPS wilt gebruiken: met het compose-bestand zijn dat twee extra regels in .env en het https-profiel.

PostgreSQL, de opslag en de GIF-dienst zitten op een intern netwerk (private) zonder internettoegang, waaraan alleen Antimatter deelneemt. Geen van hen publiceert een poort.

De Antimatter-container bewaart niets op schijf: de instellingen staan in de database (AM_CONFIG wijst erop) en de bestanden en apps in de opslagdienst. Je kunt de container op elk moment verwijderen en opnieuw aanmaken. Alles wat je moet back-uppen zit in de postgres, files en gifs-volumes, plus je .env.

Kies een image

Er zijn twee Antimatter-images gepubliceerd, beide voor linux/amd64 en linux/arm64, en beide gebouwd vanuit de main-tak van elke repository:

ImageInbegrepen appsTags
ghcr.io/antimatterchat/antimatterAgents, Calls, GitHub, GitLab, Jira, Kanban, Metrics en Playbooks.latest, X.Y.Z voor releases, sha-<commit>
ghcr.io/antimatterchat/antimatter-nextHetzelfde, plus Voice channels, Polls, Mail, Calendar, Notes, Whiteboard, GIFs, Todo en Memes. Elke nacht opnieuw gebouwd.latest, nightly, nightly-<YYYYMMDD>, sha-<commit>

Het compose-bestand van de site gebruikt antimatter-next, omdat de GIF-dienst en de meeste apps die op deze site worden beschreven alleen in dat image zitten. Om het image te wijzigen, stel je ANTIMATTER_IMAGE in .env in en voer je docker compose up -d uit.

latest verandert onder je voeten. In productie koppel je een tag vast, zoals nightly-20261015 of sha-<commit>, en wijzig je die bewust bij een upgrade. De server upgradet zijn database bij het opstarten, dus je kunt niet terug naar een ouder image, of van antimatter-next naar antimatter, zonder eerst een back-up te herstellen die vóór de upgrade is gemaakt. Zie Backups en upgrades.

In het image

  • De server staat in /antimatter, met de binaire bestanden antimatter en amctl in /antimatter/bin (op de PATH).
  • Het draait als de niet-geprivilegieerde gebruiker antimatter (uid 2000) op een minimale distroless-basis, zonder shell.
  • Poorten: 8065 (web en API), 8067 (metrics), 8074 (cluster), 8443 UDP en TCP (calls).
  • De lokale modus (ServiceSettings.EnableLocalMode) is ingeschakeld, zodat amctl --local binnen de container werkt. De gezondheidscontrole voert amctl system status --local uit.
  • De meegeleverde apps bevinden zich in /antimatter/prepackaged_plugins en zijn ondertekend met de Antimatter-app-ondertekeningsleutel.
  • Er zijn hulpmiddelen voor tekstextractie (pdftotext, wvText, unrtf, tidy) opgenomen, zodat de inhoud van geüploade documenten doorzocht kan worden.

Andere compose-bestanden

De antimatter-docker-repository bevat een productiesetup in deploy/compose/: nginx met eigen certificaten of Let's Encrypt (certbot), PostgreSQL, de optionele GIF-service (profiel gifs) en genoteerde volumes voor de configuratie, gegevens en logboeken van de server, zoals beschreven in de bijbehorende README. Standaard wordt het stabiele image gebruikt en worden bestanden op een lokaal volume opgeslagen in plaats van in S3-opslag. Gebruik dit als je de voorkeur geeft aan nginx boven Caddy, of als je al certificaten hebt.

De eerste beheerder aanmaken

Open SITE_URL in je browser en maak een account aan. Het eerste account dat op een nieuwe server wordt aangemaakt, wordt de systeembeheerder. Vervolgens leidt de installatie je door het aanmaken van je eerste community (de benaming van Antimatter voor een team of werkruimte).

Doe dit direct na de eerste start: tot die tijd wordt de eerste persoon die de server bereikt, de beheerder. Om het account in plaats daarvan via de opdrachtregel te maken, voordat de server van buitenaf bereikbaar is:

docker compose exec antimatter amctl --local user create --system-admin --email-verified \
    --email admin@example.com --username admin --password 'a-long-password'
docker compose exec antimatter amctl --local team create --name main --display-name "Main"
docker compose exec antimatter amctl --local team users add main admin

Log daarna in via SITE_URL. Begin de opdracht met een spatie om het wachtwoord uit je shellgeschiedenis te houden (met HISTCONTROL=ignorespace), of wijzig het wachtwoord zodra je bent ingelogd.

Volgende stappen zodra je bent ingelogd:

  1. Bepaal wie accounts kan aanmaken: Inloggen en accounts.
  2. Configureer e-mail, zodat uitnodigingen en wachtwoordreset werken: E-mail- en pushmeldingen.
  3. Open de poort voor gesprekken in je firewall: Gesprekken en spraak.
  4. Controleer welke apps zijn ingeschakeld: Meegeleverde apps.

Installeren uit een releasearchief

Zonder Docker wordt de server uitgevoerd vanuit een archief met de naam antimatter-<os>-<arch>.tar.gz (bijvoorbeeld antimatter-linux-amd64.tar.gz). Het bevat een enkele antimatter/-map met bin/antimatter, bin/amctl, config/config.json, de webapps (client/ en client-fusion/), de e-mailtemplates en de vertalingen.

1. PostgreSQL voorbereiden

Antimatter ondersteunt alleen PostgreSQL, versie 15 of nieuwer (oudere versies starten wel, maar met een foutmelding in het logboek). Maak een gebruiker en een database aan:

sudo -u postgres psql <<'EOF'
CREATE USER antimatter WITH PASSWORD 'a-long-password';
CREATE DATABASE antimatter OWNER antimatter;
EOF

2. Uitpakken en configureren

sudo tar -xzf antimatter-linux-amd64.tar.gz -C /opt
sudo useradd --system --user-group antimatter
sudo mkdir -p /opt/antimatter/data
sudo chown -R antimatter:antimatter /opt/antimatter

Wijs de server naar de database, ofwel in /opt/antimatter/config/config.json (SqlSettings.DataSource) of met omgevingsvariabelen, en stel de site-URL in:

AM_SQLSETTINGS_DRIVERNAME=postgres
AM_SQLSETTINGS_DATASOURCE=postgres://antimatter:a-long-password@localhost:5432/antimatter?sslmode=disable&connect_timeout=10
AM_SERVICESETTINGS_SITEURL=https://chat.example.com

De config.json in het archief is een complete standaardconfiguratie: instellingen die u in de Systeemconsole wijzigt, worden daar weer in opgeslagen. Als u de configuratie liever in de database wilt bewaren, zie Configuratie.

3. Als service uitvoeren

Een systemd-unit, in /etc/systemd/system/antimatter.service:

[Unit]
Description=Antimatter
After=network.target postgresql.service

[Service]
Type=notify
User=antimatter
Group=antimatter
WorkingDirectory=/opt/antimatter
ExecStart=/opt/antimatter/bin/antimatter
EnvironmentFile=-/etc/antimatter.env
TimeoutStartSec=3600
Restart=always
RestartSec=10
LimitNOFILE=49152

[Install]
WantedBy=multi-user.target

Plaats uw AM_-variabelen in /etc/antimatter.env (alleen leesbaar door root), en voer daarna het volgende uit:

sudo systemctl daemon-reload
sudo systemctl enable --now antimatter
journalctl -u antimatter -f

De server luistert op poort 8065. Open http://<server>:8065, of uw domein zodra een reverse proxy is geïmplementeerd (zie Domein en HTTPS), en maak het eerste account aan: dit wordt de systeembeheerder.

bin/amctl beheert de draaiende server vanuit de opdrachtregel. Op de server zelf werkt het zonder inloggen via de lokale modus: stel AM_SERVICESETTINGS_ENABLELOCALMODE=true in en voer sudo -u antimatter /opt/antimatter/bin/amctl --local system status uit.

Andere serveropdrachten

Naast het uitvoeren van de server (antimatter, of antimatter server) heeft het binair bestand een aantal onderhoudsopdrachten. Deze lezen dezelfde configuratie als de server.

OpdrachtWat het doet
antimatter versionToont de versie, het bouwnummer, de bouwdatum en de bouwhash.
antimatter db pingControleert of de database bereikbaar is.
antimatter db initMaakt de configuratie in de database aan (met AM_CONFIG ingesteld op een postgres://-URL).
antimatter db migratePast de databasemigraties toe zonder de server te starten.
antimatter db versionToont de laatste migratie die is toegepast op de database.
antimatter import bulk, antimatter export bulkImporteert of exporteert gegevens in het bulkformaat (zie Backups en upgrades).
