De REST API

Alles wat de Antimatter-apps doen verloopt via dezelfde HTTP API, dus je scripts kunnen hetzelfde. Deze pagina legt uit hoe je je identificeert, de bronnen die je het meest zult gebruiken, hoe antwoorden en fouten eruitzien en hoe je live gebeurtenissen volgt via de WebSocket.

Basis

  • Basis-URL: https://chat.example.com/api/v4. Alle endpoints hieronder zijn relatief ten opzichte daarvan.
  • Formaat: JSON in en uit, behalve bij het uploaden van bestanden (multipart). Stuur Content-Type: application/json.
  • ID’s: elk object heeft een id van 26 tekens. Tijden zijn milliseconden sinds de Unix-epoch (create_at, update_at, delete_at; 0 betekent “niet verwijderd”).
  • Gemeenschappen zijn teams: de API noemt ze teams, met een team_id.
  • jezelf: overal waar een pad een user_id verwacht, betekent me de aangemelde gebruiker, zoals in GET /users/me.

De volledige lijst met endpoints staat in de code van de server: de routes zijn gedefinieerd in server/channels/api4/*.go en de types in server/public/model. De OpenAPI-beschrijving in de map api/v4/source van de repository dekt de endpoints die zijn overgenomen van Mattermost, niet de toevoegingen van Antimatter.

Authenticatie

Elk verzoek, behalve het aanmelden en enkele openbare endpoints, vereist een token in de Authorization-header:

curl -H "Authorization: Bearer $TOKEN" https://chat.example.com/api/v4/users/me

Er worden drie soorten tokens daar geaccepteerd: persoonlijke toegangstokens, sessietokens en OAuth-toegangstokens. Ook Authorization: Token … wordt geaccepteerd. Tokens in de querystring (?access_token=) worden alleen geaccepteerd voor OAuth-toegangstokens.

Persoonlijke toegangstokens (aanbevolen voor scripts)

Een persoonlijke toegangstoken handelt in jouw naam, verloopt niet tenzij je een vervaldatum geeft en kan op elk moment worden ingetrokken. Persoonlijke toegangstokens zijn standaard uitgeschakeld:

  1. Een systeembeheerder schakelt Persoonlijke toegangstokens inschakelen in via Systeemconsole › Integraties › Integratiebeheer (ServiceSettings.EnableUserAccessTokens, AM_SERVICESETTINGS_ENABLEUSERACCESSTOKENS).
  2. Voor elke persoon die tokens mag aanmaken, opent een systeembeheerder Systeemconsole › Gebruikersbeheer › Gebruikers, kiest Rollen beheren in het menu van de persoon en vinkt Sta dit account toe om persoonlijke toegangstokens te genereren aan. Systeembeheerders kunnen ze altijd aanmaken.
  3. De persoon opent de eigen avatar rechtsboven, daarna Profiel & instellingen › Beveiliging. Onder Persoonlijke toegangstokens beschrijft de persoon waar het token voor is en kiest Nieuw Token Aanmaken. Het token wordt slechts één keer getoond: kopieer het.

Met de API: POST /users/{user_id}/tokens met {"description": "backup script", "expires_at": 0} (expires_at in milliseconden; 0 voor geen). Het token-veld in de respons is het geheim; de id is wat je gebruikt om het te intrekken (POST /users/tokens/revoke met {"token_id": "…"}). Vanuit de opdrachtregel: amctl token generate <user> <description>.

Een systeembeheerder kan de levensduur van tokens beperken met Maximale levensduur persoonlijke toegangstokens (dagen) op dezelfde Systeemconsole-pagina.

Sessietokens

Inloggen met een wachtwoord geeft een sessietoken terug in de Token-responsheader, hetzelfde type sessie dat de apps gebruiken:

curl -i -X POST https://chat.example.com/api/v4/users/login \
  -H 'Content-Type: application/json' \
  -d '{"login_id": "maya", "password": "…"}'

Voeg "token": "123456" toe voor een account met meervoudige verificatie. Sessies verlopen zoals de sessie-instellingen van de server voorschrijven, en het inlogpunt is rate-limited (5 verzoeken per seconde). POST /users/logout beëindigt de sessie.

Browsers authenticeren met een cookie in plaats daarvan. Een verzoek dat is geauthenticeerd via de cookie moet voor alles behalve GET ook de X-CSRF-Token-header versturen; een token in de Authorization-header vereist geen CSRF-header.

OAuth 2.0-apps

Om mensen toe te staan in te loggen op uw toepassing met hun Antimatter-account, registreert u een OAuth 2.0-app. Antimatter is dan de OAuth-provider:

  1. Aanzetten van OAuth 2.0 Service Provider moet ingeschakeld zijn (Systeemconsole › Integraties › Integratiebeheer, ServiceSettings.EnableOAuthServiceProvider, standaard ingeschakeld).
  2. Iemand met het recht om OAuth-apps te beheren (standaard systeembeheerders) opent de eigen avatar, vervolgens Integraties › OAuth 2.0-apps, en voegt de app toe met de callback-URL’s. Ze krijgen een client ID en een client secret.
  3. Uw applicatie stuurt mensen door naar https://chat.example.com/oauth/authorize met response_type=code, client_id, redirect_uri en state. PKCE met code_challenge_method=S256 wordt ondersteund.
  4. Daarna wisselt het de code in bij POST https://chat.example.com/oauth/access_token (grant_type=authorization_code, en daarna refresh_token om te vernieuwen) en roept het de API aan met Authorization: Bearer <access token>.

Gebruikers zien de apps waaraan ze toegang hebben gegeven in Profiel & instellingen › Beveiliging › Apps waaraan je toegang hebt gegeven.

Een bericht plaatsen

curl -X POST https://chat.example.com/api/v4/posts \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"channel_id": "'$CHANNEL_ID'", "message": "Backup finished: **42 GB** in 3 min"}'

Berichten zijn Markdown. Voeg "root_id" (het eerste bericht van een draadje) toe om in een draadje te antwoorden, "file_ids" voor bestanden en "props" voor bijlagen en andere extra's (zie Bijlagen).

Het ID van een kanaal vinden

curl -H "Authorization: Bearer $TOKEN" \
  https://chat.example.com/api/v4/teams/name/lumen-labs/channels/name/ops-alerts

De namen zijn die in de link van het kanaal: /lumen-labs/channels/ops-alerts.

Paginering

Lijst-endpoints accepteren page (vanaf 0) en per_page (standaard 60, maximaal 200). Blijf de volgende pagina opvragen totdat een pagina korter is dan per_page.

De berichten van een kanaal (GET /channels/{channel_id}/posts) accepteren ook since (een tijdstip: alles wat sindsdien is gewijzigd), of before en after (een bericht-ID). Ze worden teruggegeven als een lijst met berichten: {"order": [IDs, newest first], "posts": {ID: post}, "next_post_id", "prev_post_id"}.

Fouten

Fouten gebruiken de gebruikelijke HTTP-statuscodes (400 ongeldige invoer, 401 niet aangemeld, 403 niet toegestaan, 404 niet gevonden, 501 functie uitgeschakeld) en een JSON-lichaam:

{
  "id": "api.context.permissions.app_error",
  "message": "You do not have the appropriate permissions.",
  "detailed_error": "",
  "request_id": "jz8zm5nunpbt8f3gpqsz5dq6so",
  "status_code": 403
}

Gebruik id in uw code: message wordt vertaald naar de taal van de gebruiker. detailed_error is leeg, tenzij de server in ontwikkelaarsmodus draait (ServiceSettings.EnableDeveloper). Vermeld request_id bij de beheerder van de server: deze staat in de logs.

Snelheidslimieten

Snelheidsbeperking is standaard uitgeschakeld. Wanneer een systeembeheerder deze inschakelt (Systeemconsole › Omgeving › Snelheidsbeperking), krijgt elke client standaard 10 verzoeken per seconde met pieken van 100, geteld op IP-adres of op gebruiker. Antwoorden bevatten X-RateLimit-Limit, X-RateLimit-Remaining en X-RateLimit-Reset; boven de limiet antwoordt de server met 429 en een Retry-After-header in seconden. Sommige eindpunten, zoals het aanmelden, hebben hun eigen limiet ongeacht de instelling.

Schrijf scripts die wachten en opnieuw proberen bij 429, en vermijd polling: gebruik in plaats daarvan de WebSocket.

De WebSocket-gebeurtenisstream

Maak een verbinding met wss://chat.example.com/api/v4/websocket. Authenticatie gebeurt via de Authorization: Bearer-header in het verzoek voor de verbinding, of door dit als eerste bericht te verzenden:

{"seq": 1, "action": "authentication_challenge", "data": {"token": "…"}}

De server stuurt een hello-gebeurtenis, gevolgd door een gebeurtenis voor alles waarvoor u bevoegdheid heeft:

{
  "event": "posted",
  "data": {"channel_id": "…", "channel_type": "O", "post": "{\"id\":\"…\",\"message\":\"Hello\",…}"},
  "broadcast": {"channel_id": "…", "team_id": "", "user_id": "", "omit_users": null},
  "seq": 4
}

Merk op dat data.post het bericht is als een JSON-tekenreeks. Veelvoorkomende gebeurtenissen: posted, post_edited, post_deleted, reaction_added, reaction_removed, typing, status_change, user_added, direct_added. Apps sturen hun eigen gebeurtenissen, genaamd custom_<app id>_<event>.

U kunt ook acties verzenden, elk met een toenemende seq: user_typing met {"channel_id", "parent_id"}, of get_statuses. Herstel de verbinding wanneer deze verbroken is, en haal wat u hebt gemist op met since (zie Paginering).

Antimatter voegt de volgende gebeurtenissen toe: community_attributes_updated, member_timeouts_updated, post_put_on_top, post_removed_from_top, server_categories_updated, channel_overrides_updated en category_overrides_updated.

Clientbibliotheken

  • Ga: model.Client4 in server/public/model (import github.com/mattermost/mattermost/server/public/model). model.NewAPIv4Client(url), daarna client.SetToken(token); model.NewWebSocketClient4(wsURL, token) volgt gebeurtenissen. De kopie van Antimatter voegt methoden toe voor de eigen eindpunten, zoals UpdateMessageRequest, PutPostOnTop en ExportChannel.
  • TypeScript: de Client4-klasse van @mattermost/client, te vinden in webapp/platform/client, met de bijbehorende types in webapp/platform/types. De kopie in het repository van Antimatter bevat de eindpunten van Antimatter; het pakket dat Mattermost op npm publiceert, niet.
package main

import (
	"context"
	"log"

	"github.com/mattermost/mattermost/server/public/model"
)

func main() {
	client := model.NewAPIv4Client("https://chat.example.com")
	client.SetToken("…")
	post, _, err := client.CreatePost(context.Background(), &model.Post{
		ChannelId: "…",
		Message:   "Hello from Go",
	})
	if err != nil {
		log.Fatal(err)
	}
	log.Println("posted", post.Id)
}

Wat Antimatter aan de API toevoegt

Deze eindpunten en velden bestaan niet op een Mattermost-server. Ze vereisen allemaal een sessie.

EindpuntWat het doet
GET /teams/{team_id}/user_attributes/fields
POST zelfde pad
PATCH, DELETE …/fields/{field_id}		Community-attributen: de profielvelden die beheerders van een community definiëren voor de leden (maximaal 20). Leden kunnen ze lezen; communitybeheerders maken ze aan en wijzigen ze.
GET /teams/{team_id}/members/{user_id}/user_attributes
PATCH zelfde pad
POST /teams/{team_id}/user_attributes/values/search		De attribuutwaarden van een lid, in de vorm {field_id: value}. Leden stellen hun eigen waarden in (behalve de door beheerders beheerde); beheerders kunnen de waarden van iedereen instellen. De zoekopdracht accepteert {"user_ids": [...]} (maximaal 200).
GET /teams/{team_id}/timeouts
PUT /teams/{team_id}/members/{user_id}/timeout
GET /teams/{team_id}/members/{user_id}/moderation		Time-outs: {"until": time, "reason": "…"} verhindert dat iemand tot die tijd (maximaal 28 dagen) berichten plaatst, reageert of bestanden uploadt in de community; "until": 0 heft de time-out op. Het moderatieoverzicht toont wanneer het lid is toegetreden en hoeveel het onlangs heeft gepost.
GET /channels/{channel_id}/on_top
PUT, DELETE /posts/{post_id}/on_top		Berichten die bovenaan een kanaal worden vastgehouden (maximaal 10). {"duration": ms}, maximaal 30 dagen; 0 houdt het vast totdat het wordt verwijderd. Vereist het recht om in het kanaal te posten.
POST /channels/{channel_id}/message_requestWerkt op uw eigen berichtverzoek: {"action": "accept"}, "dismiss" of "request" om een conversatie terug te plaatsen onder de verzoeken. Geeft uw kanaallidmaatschap terug.
GET, PUT /channels/{channel_id}/overrides
GET /channels/{channel_id}/overrides/effective
GET, PUT /channels/{channel_id}/role_access		Wat een rol of persoon in een kanaal mag doen, en welke rollen een kanaal met rolbeperkingen kunnen zien.
GET, PUT /teams/{team_id}/server_categories
GET, PUT …/server_categories/overrides		De gedeelde categoriën van de community, en de overriden die gelden voor elk kanaal in een categorie.
GET /groups/{group_id}/team_role
PUT …/team_role/permissions		De rechten die een communityrol verleent.
POST /teams/{team_id}/autolinks/previewTest de autolink-regels van de community op een tekst.
POST /channels/{channel_id}/export?format=csv&since=&until=Downloadt de berichten van een kanaal als CSV (maximaal 50.000), voor personen die het kanaal kunnen lezen.
GET /posts/{post_id}/speechDe boodschap die als audio wordt voorgelezen wanneer tekst-naar-spraak is geconfigureerd.

Nieuwe velden

  • Communities (Team, en PUT /teams/{team_id}/patch): all_channels_membership (iedereen is lid van elk kanaal dat ze kunnen zien), default_channel_id (waar nieuwe leden terechtkomen; leeg betekent Town Square), hide_role_colors, require_team_badges, onboarding en autolinks (beide JSON-strings).
  • Inlineresponses: een bericht met "props": {"reply_to": "<post id>"} citeert dat bericht uit hetzelfde kanaal. Voeg "reply_to_mention": false toe om de auteur niet te verwittigen. De server vult metadata.reply_to in met een korte beschrijving van het geciteerde bericht.
  • Spoilers: "props": {"spoiler": true} verbergt de tekst en bestanden van een bericht tot de lezer kiest om ze te bekijken.
  • Negeren en blokkeren zijn voorkeuren: categorie user_block, vernoemd naar het ID van de andere persoon, met de waarde ignore of block. Of een privébericht als verzoek wacht, staat in notify_props.dm_request van uw kanaallid (pending, accepted of dismissed).
  • Berichtbijlagen kunnen stages en een chart bevatten: zie Kaarten.
