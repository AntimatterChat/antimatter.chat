Apps schrijven (plugins)

Apps voegen functionaliteit toe aan Antimatter van binnenuit: een servergedeelte in Go dat zich aan de server koopt, en een webappgedeelte in React dat menu’s, panelen, berichttypen en pagina’s toevoegt. Deze pagina toont hoe een app is opgebouwd, met de meegeleverde Peilingen-app als voorbeeld, en wat er verandert in de Fusion-interface van Antimatter.

Hoe een app werkt

  • Het servergedeelte is een Go-programma. De server start dit als een apart proces en communiceert erover RPC mee: het roept de hooks van de app aan (er staat een bericht op het punt te worden gepost, er is een opdracht uitgevoerd…), en de app roept de plugin-API van de server aan (een bericht aanmaken, een gebruiker lezen, data opslaan…). Het kan ook HTTP-routes aanbieden onder /plugins/<app id>/.
  • Het webappgedeelte is een JavaScript-bundel die in de browser wordt geladen met de webapp. Het registreert React-componenten en callbacks bij het register: een knop in een menu, een paneel, een manier om een berichttype te tekenen.
  • Elk van beide gedeeltes is optioneel. Een app wordt geïnstalleerd als een .tar.gz-bundel, en systeembeheerders schakelen deze in, uit en configureren deze.
Het servergedeelte wordt uitgevoerd met volledige toegang tot de gegevens van de server. Behandel een app als code die je op de server uitrolt.

Antimatter voert apps uit die voor Mattermost zijn geschreven, en andersom, zolang een app alleen hooks gebruikt die beide hebben. Zie Alleen door Antimatter beschikbare hooks.

De bundelstructuur

Er is geen apart starttemplate: begin bij een kleine meegeleverde app zoals antimatter-plugin-polls of antimatter-plugin-todo, en wijzig de ID en de code. De structuur van Peilingen is als volgt:

antimatter-plugin-polls/
├── plugin.json            the manifest
├── Makefile               build, test, bundle, deploy
├── build/                 the manifest and pluginctl helper tools (Go), setup.mk
├── assets/icon.svg        files shipped with the bundle
├── go.mod
├── server/
│   ├── main.go            plugin.ClientMain(&Plugin{})
│   ├── plugin.go          the Plugin type, OnActivate, ServeHTTP
│   ├── manifest.go        generated from plugin.json
│   ├── api.go, command.go, hooks.go, store.go …
│   └── dist/              compiled binaries, one per platform
└── webapp/
    ├── package.json, webpack.config.js, tsconfig.json
    ├── i18n/              en.json and one file per language
    ├── src/index.tsx      registers the app with the web app
    ├── src/manifest.ts    generated from plugin.json
    ├── src/translations.ts
    └── dist/main.js       the bundle

Optioneel: een public/-map, die ongewijzigd wordt aangeboden op /plugins/<app id>/public/.

plugin.json

{
  "id": "com.example.weather",
  "name": "Weather",
  "description": "Forecasts in the chat.",
  "homepage_url": "https://github.com/example/weather",
  "support_url": "https://github.com/example/weather/issues",
  "icon_path": "assets/icon.svg",
  "version": "1.0.0",
  "min_server_version": "12.0.0",
  "server": {
    "executables": {
      "linux-amd64": "server/dist/plugin-linux-amd64",
      "linux-arm64": "server/dist/plugin-linux-arm64",
      "darwin-amd64": "server/dist/plugin-darwin-amd64",
      "darwin-arm64": "server/dist/plugin-darwin-arm64",
      "windows-amd64": "server/dist/plugin-windows-amd64.exe"
    }
  },
  "webapp": {"bundle_path": "webapp/dist/main.js"},
  "settings_schema": {"settings": []}
}
  • id: uniek en permanent; een omgekeerd domeinnaam is gebruikelijk. Het noemt de routes, de opgeslagen instellingen en de WebSocket-gebeurtenissen.
  • version: semantische versie. De meegeleverde apps laten dit weg uit plugin.json; hun bouwtol haalt het uit de nieuwste v*-git-tag.
  • min_server_version: Antimatter meldt 12.0.0.
  • settings_schema: de instellingenpagina van de app in de Systeemconsole (zie Instellingen).

make apply kopieert het manifest naar server/manifest.go en webapp/src/manifest.ts; make manifest-check valideert het.

Het servergedeelte

Het servergedeelte importeert dezelfde Go-module als Mattermost-apps, github.com/mattermost/mattermost/server/public, via de Go-module-proxy. De main start alleen de app:

package main

import "github.com/mattermost/mattermost/server/public/plugin"

func main() {
	plugin.ClientMain(&Plugin{})
}

Het type Plugin bevat plugin.MattermostPlugin, waardoor het p.API heeft, en implementeert de hooks die het nodig heeft:

type Plugin struct {
	plugin.MattermostPlugin
	router *mux.Router
}

func (p *Plugin) OnActivate() error {
	p.router = p.newRouter()
	return p.API.RegisterCommand(&model.Command{
		Trigger:          "weather",
		AutoComplete:     true,
		AutoCompleteDesc: "Show the forecast",
		AutoCompleteHint: "[city]",
	})
}

func (p *Plugin) ExecuteCommand(c *plugin.Context, args *model.CommandArgs) (*model.CommandResponse, *model.AppError) {
	city := strings.TrimSpace(strings.TrimPrefix(args.Command, "/weather"))
	return &model.CommandResponse{
		ResponseType: model.CommandResponseTypeEphemeral,
		Text:         "Forecast for " + city + ": sunny",
	}, nil
}

func (p *Plugin) ServeHTTP(c *plugin.Context, w http.ResponseWriter, r *http.Request) {
	p.router.ServeHTTP(w, r)
}

Algemene hooks

HookWanneer het wordt uitgevoerd
OnActivate, OnDeactivateWanneer de app wordt ingeschakeld of uitgeschakeld, en wanneer de server start en stopt. Registreer slash-opdrachten en bots in OnActivate.
OnConfigurationChangeWanneer de instellingen veranderen; laad ze in met p.API.LoadPluginConfiguration(&cfg).
ServeHTTPVerzoeken naar /plugins/<app id>/…. De server zet de Mattermost-User-Id-header wanneer het verzoek afkomstig is van een ingelogde gebruiker; weiger verzoeken zonder deze header, tenzij ze bedoeld zijn om publiek te zijn.
ExecuteCommandEen door de app geregistreerde slash-opdracht is uitgevoerd.
MessageWillBePosted, MessageWillBeUpdatedVoor een bericht wordt opgeslagen: geef een gewijzigd bericht terug, of een reden om het te weigeren.
MessageHasBeenPosted, MessageHasBeenUpdated, MessageHasBeenDeletedNaderhand, voor neveneffecten.
ReactionHasBeenAdded, ReactionHasBeenRemovedReacties.
UserHasJoinedChannel, UserHasLeftChannel, UserHasJoinedTeam, UserHasLeftTeam, ChannelHasBeenCreatedLidmaatschap en wijzigingen in kanalen. Een team is een community.
FileWillBeUploadedVoor een bestand wordt opgeslagen: wijzig het of weiger het.
OnPluginClusterEventEen bericht van dezelfde app op een andere server van een cluster.

De volledige lijst, met de exacte signaturen, staat in server/public/plugin/hooks.go; de API staat in server/public/plugin/api.go. Het pluginapi-pakket (server/public/pluginapi) verpakt de API in vriendelijkere helpers.

Handige API-aanroepen

  • CreatePost, UpdatePost, SendEphemeralPost: een bericht plaatsen als de bot van de app of als een gebruiker.
  • EnsureBotUser(&model.Bot{Username, DisplayName}): maak de bot van de app een keer aan en verkrijg de ID ervan.
  • PublishWebSocketEvent("poll_updated", payload, &model.WebsocketBroadcast{ChannelId: id}): stuur een evenement naar de webapp. Het komt binnen als custom_<app id>_poll_updated.
  • OpenInteractiveDialog: open een dialoog.
  • LogInfo, LogError en dergelijke: schrijf naar de serverlog, gemarkeerd met de ID van de app.
  • GetUser, GetChannel, HasPermissionToChannel: controleer wie wat mag doen voordat u handelt namens een gebruiker.

Een app wordt op elke server van een cluster uitgevoerd. Bewaar de status in de key-value store of de database, niet alleen in het geheugen.

Data opslaan

Elke app heeft een eigen key-value store in de database van de server:

  • KVSet(key, value), KVGet(key), KVDelete(key): waarden zijn bytes, meestal JSON. Sleutels zijn maximaal 150 tekens lang.
  • KVSetWithExpiry(key, value, seconds): de waarde verdwijnt na deze tijd.
  • KVCompareAndSet(key, old, new) en KVSetWithOptions met Atomic: veilige updates wanneer meerdere verzoeken of servers dezelfde sleutel schrijven. Peilingen bewaart elke stem op deze manier en probeert opnieuw bij een conflict.
  • KVList(page, perPage): de sleutels, pagina voor pagina.

Het webapp-deel

Het bundle registreert een klasse met window.registerPlugin. De initialize-methode ontvangt het registry en de Redux store:

import manifest from './manifest';

class Plugin {
    initialize(registry, store) {
        registry.registerTranslations((locale) => translationsFor(locale));
        registry.registerPostTypeComponent('custom_poll', PollPost);
        registry.registerWebSocketEventHandler(`custom_${manifest.id}_poll_updated`, (msg) => {
            store.dispatch(pollUpdated(JSON.parse(msg.data.poll)));
        });
        registry.registerReconnectHandler(() => store.dispatch(reloadPolls()));
    }
}

window.registerPlugin(manifest.id, new Plugin());
  • Gedeelde bibliotheken. De webapp biedt React, ReactDOM, Redux, React Redux en React Intl aan: vermeld deze als webpack externals (React, ReactDOM, Redux, ReactRedux, ReactIntl) in plaats van uw eigen kopieën te bundelen. Zie webpack.config.js van Peilingen.
  • Uw server-deel aanroepen. Haal ${window.basename}/plugins/<app id>/… op met de opties uit Client4.getOptions() (uit mattermost-redux/client): deze bevatten de headers die de server nodig heeft om een verzoek van de browser te accepteren.
  • Uw eigen status. registerReducer voegt een reducer toe, opgeslagen onder state['plugins-<app id>'].
  • Types. De extra registry-methoden van Antimatter staan niet in de gepubliceerde types van Mattermost: Peilingen declareert het registry dat het gebruikt in webapp/src/types/host.ts.

De methoden en parameters van het registry zijn gedocumenteerd in de code, in webapp/fusion/src/plugins/registry.ts (Fusion) en webapp/channels/src/plugins/registry.ts (klassiek).

Ondersteuning voor de Fusion-interface

Antimatter heeft twee webinterfaces: Fusion, de standaard, en de klassieke. Beide laden dezelfde app-bundles en hebben hetzelfde registry, maar Fusion tekent veel zaken zelf en plaatst plugincomponenten op zijn eigen manier. Test uw app in beide.

De interface detecteren

Vóórdat een app wordt geladen, stellen beide interfaces window.antimatterWebUI in op 'fusion' of 'classic', en dezelfde waarde op het wortелеlement van de pagina als data-am-web-ui. In Mattermost is er geen van beide ingesteld.

export function isFusionUI(): boolean {
    return window.antimatterWebUI === 'fusion' || document.documentElement.dataset.amWebUi === 'fusion';
}

De ingebouwde apps gebruiken dit om anders te tekenen. Peilingen tekent zijn peilingskaarten en zijn aanmaakscherm in de stijl van Fusion en opent een eigen dialoog voor /poll in Fusion. Gesprekken en spraakkanaal laten de zijbalk en toast-componenten weg die Fusion vervangt door zijn eigen gespreksinterface. De Agents-app plaatst zijn AI-acties in een submenu van het berichtmenu in plaats van in de hover-toolbar. De eigen CSS-classes van Fusion (met het voorvoegsel am-) en de dialooglaag (het am-layer-element) zijn wat deze apps gebruiken om de interface te matchen; het is geen gedocumenteerde, stabiele API.

Wat Fusion niet toont of uitvoert

  • registerPostDropdownMenuComponent (een component in het berichtmenu), registerPostCardTypeComponent (een kaart van een bericht in het paneel rechts) en registerProductSwitcherMenuItem worden niet getoond in de hoofdweergaven van Fusion. Gebruik in plaats daarvan registerPostDropdownMenuAction voor het eerste.
  • registerMessageWillBeUpdatedHook wordt niet uitgevoerd wanneer een bericht in Fusion wordt bewerkt. Controleer bewerkingen op de server met de MessageWillBeUpdated-hook.
  • registerActionAfterChannelCreation wordt alleen uitgevoerd vanuit het klassieke dialoogvenster voor kanaalaanmaak, dat Fusion opent via Meer opties… in het dialoogvenster Kanaal aanmaken.
  • Componenten in de appbalk worden getoond ongeacht hun supportedProductIds.
  • Routes van registerNeedsTeamRoute en registerCustomRoute behouden het klassieke paginakader, net als producten.

Hooks die alleen Antimatter heeft

Deze registratiemethoden bestaan niet in Mattermost. Controleer of een methode bestaat voordat u hem aanroept, zodat de app daar ook werkt:

if (typeof registry.registerComposerMenuItem === 'function') {
    registry.registerComposerMenuItem({
        text: 'Create a poll',
        icon: <i className='icon icon-chart-bar'/>,
        fusionIcon: 'poll',
        action: ({channelId, rootId}) => openPollCreation(channelId, rootId),
    });
} else {
    registry.registerChannelHeaderButtonAction(icon, (channel) => openPollCreation(channel.id), 'Create a poll', 'Create a poll');
}
MethodeWat het toevoegt
registerComposerMenuItem({text, icon, fusionIcon, action, shouldRender})Een item in het +-menu van het berichtvak, in beide interfaces. action ontvangt {channelId, rootId}.
registerEmojiPickerTab({id, label, icon, fusionIcon, order, component, shouldRender, replacesGifPicker})Een tab van de emoji-kiezer in het berichtvak, zoals GIF's of stickers. In Fusion verschijnen tabs met een order lager dan 10 vóór de Emoji-tab. Het component ontvangt channelId, rootId, filter, onFilterChange, onSelectDone, insertText en isFusion.
registerChannelViewPanel({matcher, component})Een paneel tussen de kanaalkop en de berichten, voor de kanalen die matcher(state, channel) selecteert. Het kan de berichten en de invoerbalk verbergen (setMessagesVisible), zoals spraakkanaal dat doet.
registerSidebarChannelFooterComponent(component)Een regel onder een kanaal in de zijbalk, zoals de personen in het gesprek. Het ontvangt het channel.
registerIntegrationsOption({title, description, fusionIcon, action, shouldRender})Alleen Fusion: een item op de pagina's Integraties, naast aangepaste emoji. De GIF-app voegt daar zijn aangepaste GIF's en stickers toe.

fusionIcon noemt een pictogram uit de pictogramset van Fusion (bijvoorbeeld poll, sticker, calendar of image; zie webapp/fusion/src/fusion/components/icon). Fusion toont dit in plaats van icon, zodat het item overeenkomt met de andere.

Instellingen

settings_schema in plugin.json beschrijft de pagina van de app in Systeemconsole › Plugins:

"settings_schema": {
  "header": "Forecasts come from the weather service below.",
  "settings": [
    {"key": "ServiceURL", "display_name": "Service URL", "type": "text", "default": "https://api.example.com"},
    {"key": "Units", "display_name": "Units", "type": "dropdown", "default": "metric",
     "options": [{"display_name": "Celsius", "value": "metric"}, {"display_name": "Fahrenheit", "value": "imperial"}]},
    {"key": "EnableAlerts", "display_name": "Severe weather alerts", "type": "bool", "default": false,
     "help_text": "Post alerts in the channels that follow a city."}
  ]
}

Instellingstypen: bool, text, longtext, number, dropdown, radio, generated (een willekeurige sleutel), username en custom (getekend door een component dat het webapp-deel registreert met registerAdminConsoleCustomSetting). Instellingen kunnen worden gegroepeerd in sections.

Het serverdeel leest ze in naar een structuur waarvan de velden overeenkomen met de sleutels:

type configuration struct {
	ServiceURL   string
	Units        string
	EnableAlerts bool
}

func (p *Plugin) OnConfigurationChange() error {
	var cfg configuration
	if err := p.API.LoadPluginConfiguration(&cfg); err != nil {
		return err
	}
	p.setConfiguration(&cfg)
	return nil
}

Beheerders kunnen ze ook instellen in de configuratie, onder PluginSettings.Plugins.<app id>, met sleutels in kleine letters (zie de beheerdersgids).

Vertalingen

Antimatter is vertaald in 37 talen, en ook de meegeleverde apps. Het webapp-deel doet dit als volgt:

  1. Schrijf elke tekenreeks met React Intl, met een ID en de Engelse tekst: <FormattedMessage id='polls.create' defaultMessage='Create a poll'/> of defineMessages. Voeg de ID's voor met de naam van uw app.
  2. Extraheer de Engelse tekenreeksen naar webapp/i18n/en.json (de meegeleverde apps gebruiken formatjs extract).
  3. Voeg er één bestand per taal toe, met dezelfde ID's: fr.json, de.json, pt-BR.json, zh-CN.json…
  4. Geef ze door aan de webapp, die de taal van de gebruiker vraagt: 
    import fr from '../i18n/fr.json';
import ptBR from '../i18n/pt-BR.json';

const catalogs = {fr, 'pt-BR': ptBR};

export function translationsFor(locale) {
    return catalogs[locale] || catalogs[locale.split('-')[0]] || {};
}

registry.registerTranslations(translationsFor);

Een ontbrekende string valt terug op de Engelse defaultMessage. Voor strings die het servergedeelte verstuurt (antwoorden op opdrachten, botberichten), laadt het pluginapi/i18n-pakket de vertaalbestanden die in het bundle worden meegeleverd (bijvoorbeeld assets/i18n) en geeft een localizer in de taal van elke gebruiker.

Bouwen, installeren en debuggen

U heeft Go en Node.js nodig (de versie in het .nvmrc van de app). In de map van de app:

OpdrachtWat het doet
make distBouwt het servergedeelte voor elk platform en het webappgedeelte, en schrijft het bundle naar dist/<app id>-<version>.tar.gz.
make testVoert de Go- en JavaScript-tests uit.
make check-styleControleert de code (golangci-lint, ESLint) en de TypeScript-types.
make deployBouwt, installeert en activeert het bundle op een server.
make watch, make deploy-from-watchDe eerste bouwt het webappgedeelte elke keer dat u opslaat; de tweede bundelt wat het heeft gebouwd en installeert het op de server.
make enable, make disable, make resetActiveert, deactiveert of herstart de app op de server.
make logs, make logs-watchToont de regels van de app in het serverlog.
make attachKoppelt de Delve-debugger aan het draaiende servergedeelte (bouw eerst met AM_DEBUG=1).

make deploy en de andere serveropdrachten gebruiken een lokale modus socket als ze er een vinden (/var/tmp/antimatter_local.socket, of AM_LOCALSOCKETPATH): voer ze uit op de machine van de server met lokale modus aan. Anders melden ze zich aan bij de server die is opgegeven door MM_SERVICESETTINGS_SITEURL met AM_ADMIN_TOKEN, of AM_ADMIN_USERNAME en AM_ADMIN_PASSWORD. De bouwgereedschappen lezen nog geen AM_-naam voor de site-URL.

Een bundle handmatig installeren

  • Een systeembeheerder staat uploads toe met AM_PLUGINSETTINGS_ENABLEUPLOADS=true (standaard uit; er is geen schakelaar in de Systeemconsole).
  • Vervolgens Systeemconsole › Plugins › Plugin Beheer › Plugin Uploaden, of amctl plugin add weather.tar.gz gevolgd door amctl plugin enable com.example.weather.
  • Als de server Plugin-handtekening vereist heeft ingeschakeld, accepteert het alleen bundles die zijn ondertekend met een sleutel waaraan het vertrouwen hecht; zie Andere apps installeren.
Voor snelle iteraties op een ontwikkelserver, stel AM_SERVICESETTINGS_ENABLEDEVELOPER=true in op de server: fouten dragen dan hun details mee. De Makefiles van de gebundelde apps bouwen het servergedeelte alleen voor uw platform als MM_SERVICESETTINGS_ENABLEDEVELOPER is ingesteld in uw shell.
