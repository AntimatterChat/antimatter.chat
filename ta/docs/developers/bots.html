பாட்களும் இடைவினை சேய்திகளும்

ஒரு பாட் கணக்கு என்பது ஒரு நிரலுக்காக உருவாக்கப்பட்ட பயனராகும். அதற்கு தனி பெயர், படம் மற்றும் டோக்கன்கள் உள்ளன, மேலும் அதன் பெயருக்கு பக்கத்தில் BOT குறிப்பு காட்டப்படும். இந்த பக்கம் சேய்திகளின் இடைவினை பகுதிகளையும், அனைத்து இணைப்புகளும் பயன்படுத்தக்கூடிய பொத்தான்கள், மெனுவ்கள் மற்றும் டயலாக்க்களையும் உள்ளடக்கியது.

ஏன் ஒரு பாட் கணக்கு

  • அதன் சேய்திகள் ஒரு சகபயனரின் கணக்கிலிருந்து அல்லாமல், பாட் குறிப்புடன் தெளிவான அடையாளத்திலிருந்து வருகின்றன.
  • அதை அமைத்தவர் பங்கை மாற்றினாலும் அல்லது வெளியேறினாலும் (சேவையகம் முடக்கப்பட்ட உரிமையாளர்களின் பாட்களை முடக்கினால் தவிர, கீழே காண்க) அதன் டோக்கன்கள் செயல்படத் தொடருகின்றன.
  • பாட்கள் கடவுச்சொல்லுடன் உள்நுழைய முடியாது, மேலும் அவை இணைய பயன்பாட்டை ஒருபோதும் பார்க்காது.

Todo அல்லது Playbooks போன்ற பாட்களைப் போல, செயலி API (EnsureBotUser) மூலம் பயன்பாடுகள் தங்கள் சொந்த பாட்களை உருவாக்குகின்றன.

பாட் கணக்குகளை இயக்கு

ஒரு அமைப்பு நிர்வாகி அமைப்பு கன்சோல் › இணைப்புகள் › பாட் கணக்குகள் இல் பாட் கணக்கு உருவாக்கத்தை இயக்கு (ServiceSettings.EnableBotAccountCreation, AM_SERVICESETTINGS_ENABLEBOTACCOUNTCREATION) ஐ இயக்குகிறார். இது இயல்பாக அணைக்கப்பட்டிருக்கும். அனுமதி அமைப்புகளில் மற்ற பங்குகளுக்கு உரிமையை வழங்கினால் தவிர, பாட்களை உருவாக்க அமைப்பு நிர்வாகிகள் மட்டுமே உரிமையுடையவர்கள்.

அதே பக்கத்தில், உரிமையாளர் முடக்கப்பட்டால் பாட் கணக்குகளை முடக்கு (ServiceSettings.DisableBotsWhenOwnerIsDeactivated, இயல்பாக இயக்கப்பட்டது) உரிமையாளரின் கணக்கு முடக்கப்பட்டால் பாட்களை முடக்குகிறது.

ஒரு பாட்களை உருவாக்கு

  1. வலது மேலே உள்ள உங்கள் அவதாரத்தை திறக்கவும், பின்னர் இணைப்புகள் › பாட் கணக்குகள், பின்னர் பாட் கணக்கை சேர் ஐ அழுத்தவும்.
  2. ஒரு பயனர் பெயர் (குறைந்த எழுத்துகள், எண்கள், புள்ளிகள், கோடுகள் மற்றும் அடிக்குறிகள்), மற்றும் விருப்பத்திற்கு ஏற்ப ஒரு பாட் ஐகன், காட்சி பெயர் மற்றும் விளக்கம் ஐ உள்ளிடவும்.
  3. பங்கு ஐ தேர்ந்தெடுக்கவும்: உறுப்பினர், அல்லது சேவையகத்தை நிர்வகிக்கும் பாட்களுக்கு அமைப்பு நிர்வாகி. பாட்களுக்கு அவை தேவைப்படுத்தும் குறைந்த அளவு உரிமையை மட்டுமே வழங்கவும்.
  4. அனைத்து பொது சேனல்களிலும் பதிவு செய்ய அனுமதிக்க post:channels ஐ குறிக்கவும், அல்லது உறுப்பினராக இல்லாமல் தனிப்பட்ட சேனல்கள் மற்றும் நேரடி சேய்திகள் உட்பட அனைத்து சேனல்களிலும் பதிவு செய்ய post:all ஐ குறிக்கவும்.
  5. அதன் இயல்பு டோக்கன் எப்போது காலாவதியாகும் என்பதை அமைக்கவும், பின்னர் பாட் கணக்கை உருவாக்கு ஐ தேர்ந்தெடுக்கவும்.
  6. காட்டப்பட்ட அணுகல் டோக்கனை நகலெடுக்கவும். இது மீண்டும் காட்டப்படாது.

பின்னர், பாட்களின் வரிசையில் புதிய டோக்கனை உருவாக்கு மூலம் ஒரு டோக்கனை சேர்க்கலாம், மேலும் ஒவ்வொரு டோக்கனையும் முடக்கலாம் அல்லது நீக்கலாம். தனிப்பட்ட அணுகல் டோக்கன்கள் மக்களுக்கு அணைக்கப்பட்டிருந்தாலும் பாட் டோக்கன்கள் செயல்படும்.

API மூலம்:

# create the bot (you become its owner)
curl -X POST https://chat.example.com/api/v4/bots \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"username": "deploy-bot", "display_name": "Deploy", "description": "Posts deployments"}'

# give it a token
curl -X POST https://chat.example.com/api/v4/users/$BOT_USER_ID/tokens \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"description": "deploy pipeline"}'

கட்டளை வரிசையிலிருந்து, நிர்வாகியாக உள்நுழைந்து (உள்ளூர் முறையில் இல்லாமல்): amctl bot create deploy-bot --display-name Deploy --with-token --expires-in 90d. மற்ற முனைகள்: GET /api/v4/bots, PUT /api/v4/bots/{bot_user_id}, POST /api/v4/bots/{bot_user_id}/disable மற்றும் /enable, அதன் உரிமையாளரை மாற்ற POST /api/v4/bots/{bot_user_id}/assign/{user_id}.

பாட்டை சமூகங்களிலும் சேனல்களிலும் சேர்க்கவும்

புதிய பாட் எந்த சமூகத்திலும் இல்லை. அதை ஒரு நபரைச் சேர்க்கும் போல, சமூகத்தின் உறுப்பினர் மேலாண்மையிலிருந்து அல்லது API மூலம் சேர்க்கவும்:

curl -X POST https://chat.example.com/api/v4/teams/$TEAM_ID/members \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"team_id": "'$TEAM_ID'", "user_id": "'$BOT_USER_ID'"}'

curl -X POST https://chat.example.com/api/v4/channels/$CHANNEL_ID/members \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"user_id": "'$BOT_USER_ID'"}'

post:channels அல்லது post:all உரிமையுள்ள பாட் உறுப்பினராக இல்லாமலும் பதிவிட முடியும், ஆனால் அது சேர்ந்துள்ள சேனல்களுக்கான WebSocket நிகழ்வுகளை மட்டுமே பெறும்.

பாட்டின் பெயரில் பதிவிடுதல்

எந்த API அழைப்பிலும் பாட்டின் டோக்கனைப் பயன்படுத்தவும்; POST /api/v4/posts மிகவும் பொதுவானது (பார்க்க முதன்மை வளங்கள்). ஒருவருக்கு நேரடியாக எழுத, முதலில் நேரடிக் கணவரிடத்தைத் திறக்கவும்:

# returns the channel; use its "id" as channel_id
curl -X POST https://chat.example.com/api/v4/channels/direct \
  -H "Authorization: Bearer $BOT_TOKEN" -H 'Content-Type: application/json' \
  -d '["'$BOT_USER_ID'", "'$USER_ID'"]'

மக்கள் சொல்வதற்கு வினைபுரிய, பாட்டின் டோக்கனுடன் WebSocket-ஐப் பின்தொடர்ந்து, உங்களுக்கு முக்கியமான posted நிகழ்வுகளுக்கு பதிலளிக்கவும். சுழற்சிகளைத் தவிர்க்க, பாட்டின் சொந்த செய்திகளை புறக்கணிக்கவும்.

ஒரு நபருக்கு மட்டுமே தெரியும் ஒரு செய்தி (தற்காலிக செய்தி) POST /api/v4/posts/ephemeral மற்றும் {"user_id", "post": {"channel_id", "message"}} மூலம் அனுப்பப்படுகிறது. இது create_post_ephemeral உரிமையைத் தேவைப்படுகிறது, இது இயல்பாக அமைப்பு நிர்வாகிகளுக்கு மட்டுமே உண்டு. ஒருங்கிணைப்புகள் பொதுவாக ஸ்லாஷ் கட்டளைகள் மற்றும் பொத்தான்களுக்கு பதிலாக தற்காலிக செய்திகளை அனுப்புகின்றன.

பயன்பாட்டு செய்திகள்: பொத்தான்கள் மற்றும் மென்கள்

இணைப்புகளுடன் கூடிய எந்த செய்தியும் செயல்களைக் கொண்டிருக்கலாம்: பொத்தான்கள், தேர்ந்தெடுக்க மென்கள். இவை API மூலம், வெப்கூக்குகள் மற்றும் ஸ்லாஷ் கட்டளை பதில்களில் பதிவிடப்பட்ட செய்திகளில் செயல்படுகின்றன. யாராவது ஒன்றைப் பயன்படுத்தும்போது, Antimatter உங்கள் ஒருங்கிணைப்பின் URL-ஐ அழைக்கிறது.

{
  "channel_id": "…",
  "message": "Deploy **api 2.4.0** to production?",
  "props": {
    "attachments": [{
      "actions": [
        {
          "id": "approve",
          "type": "button",
          "name": "Approve",
          "style": "primary",
          "integration": {"url": "https://deploy.example.com/actions", "context": {"release": "2.4.0", "action": "approve"}}
        },
        {
          "id": "env",
          "type": "select",
          "name": "Pick an environment",
          "options": [{"text": "Staging", "value": "staging"}, {"text": "Production", "value": "production"}],
          "integration": {"url": "https://deploy.example.com/actions", "context": {"release": "2.4.0", "action": "env"}}
        }
      ]
    }]
  }
}
  • type: button அல்லது select.
  • id: எழுத்துகள், எண்கள், கோடுகள் மற்றும் அடிக்குறிகள், செய்தியின் ஒவ்வொரு செயலுக்கும் வேறுபட்டவை. நீங்கள் விடுபடுத்தினால், இது உருவாக்கப்படும்.
  • style (பொத்தான்கள்): default, primary, success, good, warning, danger, அல்லது ஒரு hex நிறம்.
  • options (மென்கள்), அல்லது data_source: ஒரு நபரை அல்லது சேனலைத் தேர்ந்தெடுக்க users அல்லது channels. default_option ஒரு மதிப்பை முன்னே தேர்ந்தெடுக்கிறது.
  • integration.url: கிளிக் அனுப்பப்படும் இடம். ஒரு செயலி (பிளகின்) தனது சொந்த வழியைப் பயன்படுத்தலாம், எடுத்துக்காட்டாக /plugins/com.example.deploy/actions. integration.context உங்களுடையது: அது கிளிக்குடன் திரும்பி வருகிறது, மற்றும் கிளையண்டுகள் அதை ஒருபோதும் பார்க்காது.

உங்கள் இணைப்பால் பெறப்படும் கோரிக்கை

{
  "user_id": "…",
  "user_name": "priya",
  "channel_id": "…",
  "channel_name": "releases",
  "team_id": "…",
  "team_domain": "lumen-labs",
  "post_id": "…",
  "trigger_id": "…",
  "type": "button",
  "context": {"release": "2.4.0", "action": "approve"}
}

ஒரு மெனுவிற்கு, type என்பது select ஆகவும், context.selected_option என்பது தேர்ந்தெடுக்கப்பட்ட மதிப்பைக் கொண்டுள்ளது.

  "ephemeral_text": "Done. The deploy starts in a minute."
}
  • update: செய்தியின் உரை மற்றும் பண்புகளை மாற்றுகிறது, எடுத்துக்காட்டாக பயன்படுத்தப்பட்ட பின்னர் பொத்தான்களை நீக்க (வெற்று props).
  • ephemeral_text: கிளிக் செய்த நபர் மட்டுமே காணும் செய்தி.
  • goto_location: திறக்க வேண்டிய URL.
  • வெற்று உடல் எதுவும் மாற்றாது.

சர்வர் இணைப்பு கோரிக்கை நேரம் முடிவு அனுமதிக்கும் வரை காத்திருக்கும் (இயல்பாக 30 வினாடிகள்). தனியார் நெட்வொர்க் முகவரிகளில் உள்ள இணைப்பு URL-கள், வெப்க்குக்கள்கள்க்கு போல, அமைப்பு நிர்வாகியால் அனுமதிக்கப்பட வேண்டும்.

டயலாக்கள்கள்

ஒரு டயலாக் என்பது சாட்டின் மேல் திறக்கப்படும் ஒரு படிவம். நீங்கள் அதை நபர் சமீபத்தில் செய்த ஏதேனும் விஷயத்திற்கு (ஒரு ஸ்லாஷ் கட்டளையாக அல்லது ஒரு பொத்தானாக) பதிலாக மட்டுமே திறக்க முடியும், ஏனெனில் அது அந்த கோரிக்கையின் trigger_id ஐத் தேவைப்படுகிறது. trigger_id இணைப்பு கோரிக்கை நேரம் முடிவு வரை செல்லுபடியாகும்.

curl -X POST https://chat.example.com/api/v4/actions/dialogs/open \
  -H 'Content-Type: application/json' \
  -d '{
    "trigger_id": "'$TRIGGER_ID'",
    "url": "https://deploy.example.com/dialog",
    "dialog": {
      "callback_id": "new-release",
      "title": "New release",
      "introduction_text": "Fill in the release details.",
      "submit_label": "Create",
      "notify_on_cancel": false,
      "state": "anything you want back",
      "elements": [
        {"display_name": "Version", "name": "version", "type": "text", "placeholder": "2.4.0"},
        {"display_name": "Notes", "name": "notes", "type": "textarea", "optional": true},
        {"display_name": "Environment", "name": "env", "type": "select",
         "options": [{"text": "Staging", "value": "staging"}, {"text": "Production", "value": "production"}]},
        {"display_name": "Owner", "name": "owner", "type": "select", "data_source": "users"},
        {"display_name": "Notify the channel", "name": "notify", "type": "bool", "default": "true"}
      ]
    }
  }'
உருவக வகைஅது என்ன காட்டுகிறது
textஒரு வரி புலம். subtype: text, email, number, password, tel அல்லது url. min_length மற்றும் max_length அதைக் கட்டுப்படுத்துகின்றன.
textareaபல வரி புலம்.
selectஒரு பட்டியல்: options, அல்லது data_source users, channels, அல்லது data_source_url உடன் dynamic. multiselect பல மதிப்புகளை அனுமதிக்கிறது.
boolஒரு சரிபார்ப்புப் பெட்டி.
radiooptions இல் இருந்து ஒரு தேர்வு.
date, datetimeஒரு தேதி, அல்லது தேதி மற்றும் நேரம்.

ஒவ்வொரு உருவகமும் display_name, name, help_text, placeholder, default மற்றும் optional ஐ ஏற்கிறது.

நபர் சமர்ப்பிக்கும்போது, Antimatter டயலாக்கின் url க்கு POST செய்கிறது:

{
  "type": "dialog_submission",
  "callback_id": "new-release",
  "state": "anything you want back",
  "user_id": "…",
  "channel_id": "…",
  "team_id": "…",
  "submission": {"version": "2.4.0", "notes": "", "env": "staging", "owner": "…", "notify": true},
  "cancelled": false
}

டயலாக்கை மூட ஒரு வெற்று உடலுடன் பதிலளிக்கவும், அல்லது அதை திறந்த நிலையில் வைத்து என்ன தவறு என்று காட்டவும்:

{"errors": {"version": "This version already exists."}}

{"error": "…"} முழு படிவத்திற்கும் ஒரு செய்தியைக் காட்டுகிறது. notify_on_cancel உடன், டயலாக்கை மூடுவது "cancelled": true ஐ அனுப்புகிறது. செயலிகளில் டயலாக்கள்கள் அதே விதமாக செயல்படுகின்றன: பிளகின் API இன் OpenInteractiveDialog அதே கோரிக்கையை ஏற்கிறது.
