வெப்க்குக்கள்து

உள்வரவு வெப்க்கு ஒரு சேனலுக்கு மற்றொரு அமைப்பு JSON-ஐ ரகசிய URL-க்கு அனுப்பி சேய்தி அனுப்பவதை அனுமதிக்கிறது. வெளியேறவு வெப்க்கு எதிரெதிர் செய்கிறது: டிரிகர் வார்த்தையுடன் தொடங்கும் சேய்திகளை உங்கள் URL-க்கு அனுப்பி, நீங்கள் பதிலளிப்பதை அது சேனலில் அனுப்புகிறது.

வெப்க்குக்களை மேலாணம் செய்ய இடம்

மேலே வலதுபுறம் உங்கள் அவட்டரை திறந்து, பின் இணைப்புகள்து என்பதை தேர்ந்தெடுக்கவும். தற்போதைய கம்யூனிட்டியின் இணைப்பு பக்கங்கள் உள்வரவு வெப்க்குக்கள்து மற்றும் வெளியேறவு வெப்க்குக்கள்து ஆகியவற்றை பட்டியலிடுகின்றன. ஒவ்வொரு வெப்க்கும் ஒரு கம்யூனிட்டியை சேர்ந்தது.

By default, community admins and system admins can create webhooks. A system admin can give the right to other roles in the permission settings of the System Console. A system admin can also turn each kind off in System Console › Integrations › Integration Management: Enable Incoming Webhooks and Enable Outgoing Webhooks are both on by default.

உள்வரவு வெப்க்கை உருவாக்குதல்

  1. இணைப்புகள்து இல், உள்வரவு வெப்க்குக்கள்து என்பதை தேர்ந்தெடுத்து, பின் உள்வரவு வெப்க்கை சேர் என்பதை அழுத்தவும்.
  2. ஒரு தலைப்பு மற்றும் ஒரு விளக்கம் ஐ நிரப்பவும்: அவை இணைப்பு பக்கங்களில் மட்டுமே தோன்றும்.
  3. சேய்திகள் இயல்பாக செல்லும் சேனல் ஐ தேர்ந்தெடுக்கவும். தனிப்பட்ட சேனலுக்கு, நீங்கள் அதன் உறுப்பினராக இருக்க வேண்டும்.
  4. அனுப்பிகள் வேறு இடங்களில் அனுப்ப முடியாவிட்டால், இந்த சேனலுக்கு பின்தொடரவும் என்பதை குறிக்கவும்.
  5. விருப்பத்திற்கு ஏற்ப, அதன் சேய்திகளுக்கான பயனர் பெயர் மற்றும் சுயவிவரப் படம் URL-ஐ அமைக்கவும் (பார்க்க பெயரும் ஐகனும்).
  6. சேமி என்பதை தேர்ந்தெடுக்கவும். காட்டப்படும் URL-ஐ நகலெடுக்கவும்: https://chat.example.com/hooks/<key>.
URL மட்டுமே ரகசியம்: அதைக் கொண்டிருப்பவர் யாரும் சேனலில் அனுப்ப முடியும். அதை பொதுவான ரிபொசிட்டரிகளில் இருந்து தள்ளி வைக்கவும், மற்றும் அது கசிந்தால் வெப்க்கை நீக்கவும்.

API மூலம்: POST /api/v4/hooks/incoming with {"channel_id", "display_name", "description", "username", "icon_url", "channel_locked"}; பதிலின் id ஆனது விசை. கமாண்ட் லைன் மூலம்: amctl webhook create-incoming --channel <channel id> --user <user> --display-name "CI".

உள்வரவு வெப்க்குக்கு சேய்தி அனுப்பல்

curl -X POST https://chat.example.com/hooks/xgh5ycrx1jf7mbs9w8z4c8e7ho \
  -H 'Content-Type: application/json' \
  -d '{"text": "Deploy of **api 2.4.0** finished :white_check_mark:"}'

சர்வர் 200 உடன் ok உடல்பகுதியுடன் பதிலளிக்கிறது. அது application/x-www-form-urlencoded ஐயும் ஏற்கிறது, JSON-ஐ payload புலத்தில் வைத்து, Slack-இன் வெப்க்குக்கள் செய்வது போல, எனவே Slack-க்காக உருவாக்கப்பட்ட கருவிகள் பொதுவாக மாற்றமின்றி வேலை செய்கின்றன.

புலம்அர்த்தம்
textMarkdown வடிவிலான செய்தி. attachments இல்லை என்றால் இது அவசியம். சேவையகத்தின் செய்தி வரம்பை விட நீளமான உரை பல செய்திகளாகப் பிரிக்கப்படும்.
channelவெப்கூக்கின் (webhook) சமூகத்தின் மற்றொரு சேனல், பெயரால் (ops-alerts அல்லது #ops-alerts), அல்லது வெப்கூக்கின் உரிமையாளரிடமிருந்து நேரடி செய்திக்காக @username. வெப்கூக் அதன் சேனலுக்குத் தடைசெய்யப்பட்டிருந்தால் இது நிராகரிக்கப்படும்.
username, icon_url, icon_emojiசேவையகம் மாற்றங்களை அனுமதிக்கும்போது காட்ட வேண்டிய பெயரும் படமும்.
attachmentsஅட்டைகளாக (கீழே) வரையப்படும் செய்தி இணைப்புகள்.
propsஅவற்றைப் படிக்கும் பயன்பாடுகளுக்காக செய்தியில் சேமிக்கப்படும் கூடுதல் பண்புகள்.
typeஅதை வரைய ஒரு பயன்பாட்டிற்கான தனிப்பயன் செய்தி வகை, எடுத்துக்காட்டாக custom_poll. system_ உடன் தொடங்கும் வகைகள் நிராகரிக்கப்படும்.
root_idஅந்த த்ரெட்டில் பதிலளிக்க, ஒரு த்ரெட்டின் முதல் செய்தியின் ID.
priorityசெய்தி முன்னுரிமை, எடுத்துக்காட்டாக {"priority": "urgent"}.
silenttrue எனில், செய்தி தள்ளல் அறிவிப்புகளின்றி அனுப்பப்படும்.

மாற்றப்பட்ட பெயருடன் காட்டப்படும் செய்திகள், உண்மையான கணக்குகளிலிருந்து அவற்றை வேறுபடுத்த அருகில் பாட் குறியீட்டைக் கொண்டிருக்கும். வெப்கூக் செய்திகள் வெளியேறும் வெப்கூக்குகளை (outgoing webhooks) எப்போதும் தூண்டாது.

பெயரும் ஐகானமும்

சேவையகம் மாற்றங்களை அனுமதிக்கவில்லை என்றால், ஒரு வெப்கூக் அதை உருவாக்கிய நபராகப் பதிவு செய்யும். அமைப்பு கன்சோல் › இணைப்புகள் › இணைப்புகள் மேலாண்மை இல் உள்ள இரண்டு அமைப்புகள் (இரண்டும் இயல்பாக அணைக்கப்பட்டவை) இதை மாற்றுகின்றன:

  • பயனர்ப்பெயர்களை மாற்ற இணைப்புகளை இயக்கு (ServiceSettings.EnablePostUsernameOverride): வெப்கூக்கின் பயனர்பெயர்ப் அல்லது கோருவின் username அதற்குப் பதிலாகக் காட்டப்படும்; இரண்டும் இல்லையெனில், பெயர் webhook ஆகும்.
  • இணைப்புகள் சுயவிவரப் புகைப்பட அடையாளங்களை மாற்ற அனுமதி (ServiceSettings.EnablePostIconOverride): வெப்கூக்கின் சுயவிவரப் படம், அல்லது கோருவின் icon_url அல்லது icon_emoji காட்டப்படும்.

வெப்கூக்கில் சேமிக்கப்பட்ட மதிப்புக்குப் பதிலாக, கோருவிலுள்ள மதிப்பு முன்னுரிமை பெறும்.

இணைப்புகள்

இணைப்புகள் உரையின் கீழே கட்டமைக்கப்பட்ட உள்ளடக்கத்தைச் சேர்க்கின்றன. அவை Slack-இன் செய்தி இணைப்பு வடிவத்தைப் பின்பற்றுகின்றன:

{
  "text": "Build failed on `main`",
  "attachments": [{
    "fallback": "main #1902 failed",
    "color": "#d24b4e",
    "author_name": "GitHub Actions",
    "author_icon": "https://chat.example.com/static/ci.png",
    "title": "main #1902 failed",
    "title_link": "https://ci.example.com/runs/1902",
    "text": "Commit `0f4d8e2` by Jonas Weber",
    "fields": [
      {"title": "Branch", "value": "zephyr-3.7", "short": true},
      {"title": "Duration", "value": "3m 40s", "short": true}
    ],
    "footer": "Lumen CI",
    "ts": 1760000000
  }]
}
புலம்அர்த்தம்
fallbackஅட்டையைக் காட்ட முடியாத இடங்களுக்கு, எடுத்துக்காட்டாக அறிவிப்புகளுக்கு, எளிய உரை.
colorநிறப் பட்டை: ஒரு hex நிறம், அல்லது good, warning, danger.
pretextஅட்டையின் மேல் உள்ள உரை.
author_name, author_link, author_iconஒரு சிறிய தலைப்பு வரி.
title, title_linkஅட்டையின் தலைப்பு, விருப்பத்திற்கு ஏற்ப ஒரு இணைப்பு.
textMarkdown வடிவிலான அட்டையின் உடல்.
fields{"title", "value", "short"} உடன் ஒரு பட்டியல்; short புலங்கள் பக்கவாட்டில் அமைகின்றன.
image_url, thumb_urlகீழே ஒரு பெரிய படம், அல்லது பக்கவாட்டில் ஒரு சிறிய படம்.
footer, footer_icon, tsஒரு காலடி வரி மற்றும் நேரம் (Unix வினாடிகள்).
actionsபட்டன்களும் மெனுவ்களும்: இடைவினை செய்திகள் காண்க.

அட்டைகள்: நிலைகள் மற்றும் வரைபடங்கள்

Antimatter இணைப்புகளுக்கு (attachments) இரண்டு புலங்களைச் சேர்க்கிறது; இவை இயல்பு இடைமுகத்தால் (default interface) காட்டப்படுகின்றன:

  • stages: ஒரு பைப்லைனின் (pipeline) படிகள், பில்ல்களாக (pills) — அதிகபட்சம் 20. ஒவ்வொன்றும் {"name", "status"} வடிவில் இருக்கும்; நிலை (status) passed, failed, running, pending, skipped அல்லது canceled ஆக இருக்கும்.
  • chart: சமீபத்திய மதிப்புகளின் சிறிய கோட்டு வரைபடம், {"values": [2 to 200 numbers], "threshold": number, "label": "…"}. எச்சரிக்கையின் எல்லைக்காக, எல்லை மதிப்பு தட்டையான கோட்டாக வரையப்படுகிறது.
{
  "attachments": [{
    "color": "danger",
    "title": "main #1902 failed",
    "stages": [
      {"name": "build", "status": "failed"},
      {"name": "unit", "status": "skipped"},
      {"name": "publish", "status": "skipped"}
    ]
  }, {
    "color": "warning",
    "title": "API latency above 400 ms",
    "chart": {"values": [210, 230, 260, 390, 450, 470], "threshold": 400, "label": "p95 latency, ms"}
  }]
}

பழைய இடைமுகம் (classic interface) மற்றும் மற்ற கிளையண்டுகள் (clients) இந்த இரண்டு புலங்களையும் புறக்கணிக்கும்; எனவே, முக்கிய தகவல்களை text அல்லது fields இலும் சேர்த்து வைக்கவும்.

வெளியேறும் வெப்கூகை (outgoing webhook) உருவாக்குதல்

வெளியேறும் வெப்கூகை (outgoing webhook) ஒரு சமூகத்தின் பொது சேனல்களைக் கண்காணிக்கிறது. ஒரு செய்தியின் முதல் சொல் அதன் டிரிகர் சொற்களில் (trigger words) ஒன்றைப் பொருந்தும்போது, Antimatter அந்த செய்தியை உங்கள் URL-க்கு அனுப்பும்.

  1. இணைப்புகள்து இல், வெளியேறும் வெப்கூக்கள்து ஐத் தேர்ந்தெடுத்து, பின்னர் வெளியேறும் வெப்கூகை சேர் ஐ அழுத்தவும்.
  2. தலைப்பு மற்றும் விளக்கம் ஐ நிரப்பவும்.
  3. கோரிக்கையின் (request) Content Type ஐத் தேர்ந்தெடுங்கள்: application/x-www-form-urlencoded அல்லது application/json.
  4. ஒரு சேனல் ஐத் தேர்ந்தெடுத்து, Trigger Words (ஒவ்வொன்றும் ஒரு வரிசையில்) ஐ உள்ளிடவும், அல்லது இரண்டையும் செய்யவும். சேனல் மட்டும் தேர்ந்தெடுக்கப்பட்டு டிரிகர் சொற்கள் இல்லையெனில், அந்த சேனலின் அனைத்து செய்திகளும் அனுப்பப்படும். இரண்டும் இருந்தால், செய்தி இரண்டையும் பொருந்த வேண்டும்.
  5. Trigger செய்யும்போது கீழே, முதல் சொல் டிரிகர் சொல்லுக்கு துல்லியமாக பொருந்துகிறது அல்லது முதல் சொல் டிரிகர் சொல்லுடன் தொடங்குகிறது ஐத் தேர்ந்தெடுங்கள்.
  6. பின்செயல் URL-கள் (ஒவ்வொரு வரிசையிலும் ஒன்று) ஐ உள்ளிடவும். ஒவ்வொரு URL-க்கும் பொருந்தும் அனைத்து செய்திகளும் அனுப்பப்படும்.
  7. விருப்பத்திற்குரியவாக, பதில்களுக்கு (replies) பயன்படுத்தப்படும் பயனர் பெயர் மற்றும் சுயவிவரப் படம் ஐ அமைக்கவும்.
  8. சேமி ஐத் தேர்ந்தெடுத்து, காட்டப்படும் டோக்கனை (token) நகலெடுக்கவும். உங்கள் சேவை, கோரிக்கைகள் உங்கள் சர்வரிலிருந்து வருகின்றன என்பதைச் சரிபார்க்க இதைப் பயன்படுத்தும்.

API மூலம்: POST /api/v4/hooks/outgoing உடன் {"team_id", "channel_id", "trigger_words", "trigger_when", "callback_urls", "content_type", "display_name"} (trigger_when: துல்லியமான பொருத்தத்திற்கு 0, "starts with"-க்கு 1).

உங்கள் சேவை தனிப்பட்ட நெட்வொர்க்கில் (private network) இருந்தால், அமைப்பு நிர்வாகி (system admin) அதன் முகவரியை அந்நம்பிக்கையான உள்நூல் இணைப்புகளை அனுமதிக்க (ServiceSettings.AllowedUntrustedInternalConnections) இல் அனுமதிக்க வேண்டும். இல்லையெனில், சர்வர் தனிப்பட்ட முகவரிகளை அழைக்காது.

வெளியேறும் கோரிக்கை (outgoing request)

Antimatter, Content Type-க்கு ஏற்ப JSON அல்லது form-encoded வடிவில், இந்த புலங்களுடன் ஒரு POST-ஐ அனுப்புகிறது:

{
  "token": "6kd1ofo5ojr5zgu5ipfipybgnc",
  "team_id": "…",
  "team_domain": "lumen-labs",
  "channel_id": "…",
  "channel_name": "ops-alerts",
  "timestamp": 1760010000000,
  "user_id": "…",
  "user_name": "priya",
  "post_id": "…",
  "text": "deploy api 2.4.0",
  "trigger_word": "deploy",
  "file_ids": ""
}

எதையும் செய்யும் முன், token ஐ வெப்கூகின் டோக்கனுடன் ஒப்பிடுங்கள். பார்ம்-என்கோடெட் பதிப்பில், timestamp மில்லிசெகண்ட்களாக இல்லாமல் வினாடிகளாக இருக்கும். சேவையகம் உங்கள் பதிலுக்காக Integration request timeout அனுமதிக்கும் வரை (இயல்பாக 30 வினாடிகள், ServiceSettings.OutgoingIntegrationRequestsTimeout) காத்திருக்கும்.

வெளியேறும் வெப்கூகிற்கு பதில் அனுப்புதல்

பதில் அனுப்ப, JSON மூலம் பதிலளிக்கவும். எதுவும் அனுப்ப விரும்பவில்லை என்றால், காலியான உடலுடன் (empty body) பதிலளிக்கவும்.

{
  "text": "Deploying **api 2.4.0** to staging…",
  "response_type": "comment",
  "username": "deploy-bot",
  "icon_url": "https://chat.example.com/static/deploy.png"
}
  • text மற்றும் attachments: பதில். இவற்றில் எதுவும் இல்லையெனில், எதுவும் வெளியிடப்படாது.
  • response_type: comment என்பது தூண்டிய செய்தியின் த்ரெட்டில் பதிலை வெளியிடுகிறது; இல்லையெனில் அது சேனலுக்கு செல்கிறது.
  • username, icon_url: சேவையகம் மாற்றங்களை அனுமதிக்கும்போது காட்டப்படுகின்றன; இல்லையெனில் வெப்கூகின் சொந்த மதிப்புகள் பயன்படுத்தப்படுகின்றன.
  • props, type, priority: உள்வரும் வெப்கூகுகளுக்கு போலவே.

பதில் வெப்கூகின் உருவாக்குநராக, மாற்றப்பட்ட பெயர் இருந்தால் அந்த பெயரின் கீழ் வெளியிடப்படுகிறது. விரைவான பதில்களுக்கு மீதான எதற்கும், உடனடியாக பதிலளிக்கவும், பின்னர் உள்வரும் வெப்கூகை அல்லது API மூலம் வெளியிடவும்.

வெப்கூகம் வேலை செய்யாதபோது

  • வெப்கூக URL இலிருந்து 501: சேவையகத்தில் உள்வரும் வெப்கூகுகள் முடக்கப்பட்டுள்ளன.
  • 400 "Failed to decode the payload…": JSON தவறானது, அல்லது பார்ம் புலம் payload என பெயரிடப்படவில்லை. "No text specified." என்பது கோரிக்கையில் text அல்லது attachments இரண்டும் இல்லை என்பதைக் குறிக்கிறது.
  • 403: வெப்கூகம் வேறு சேனலுக்கு பூட்டப்பட்டிருக்கிறது, அல்லது அதன் உரிமையாளர் சேனலை இனிமேல் படிக்க முடியாது.
  • வெளியேறும் வெப்கூகம் ஒருபோதும் தூண்டப்படுவதில்லை: சேனல் தனியானது, தூண்டுபொருள் முதல் சொல்லல்ல, அல்லது செய்தி ஒரு வெப்கூகிலிருந்து வந்தது.
  • பதிவுகள்: Enable Webhook Debugging இயக்கப்பட்டிருந்தால் (LogSettings.EnableWebhookDebugging), பதிவு நிலை DEBUG இல் இருந்தால், சேவையகம் தோல்வியடைந்த உள்வரும் கோரிக்கைகளின் பதிவுகளை பதிவு செய்யும். தோல்வியடைந்த வெளியேறும் அழைப்புகள் Outgoing Webhook POST failed என பதிவு செய்யப்படுகின்றன.
