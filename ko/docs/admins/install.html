Antimatter 설치

준비된 compose 파일로 Antimatter를 설치하거나, 올바른 이미지를 선택하거나, 릴리스 아카이브에서 서버를 실행합니다. 그런 다음 첫 번째 관리자 계정을 생성합니다.

Docker Compose로 설치

이것이 권장하는 방법입니다. 하나의 compose 파일로 Antimatter, PostgreSQL, 파일 저장소 및 GIF 서비스를 실행합니다. Docker Engine 및 Compose 플러그인(docker compose)이 설치된 Linux 서버, 2개의 CPU 코어 및 4GB 이상의 메모리가 필요합니다.

1. compose 파일 다운로드

mkdir antimatter && cd antimatter
curl -fsSLO https://antimatter.chat/compose.yaml

2. .env 파일 생성

compose 파일은 같은 디렉터리의 .env 파일에서 설정을 읽습니다. 랜덤한 시크릿을 사용하여 파일을 생성하세요:

cat > .env <<EOF
SITE_URL=http://localhost:8065
POSTGRES_PASSWORD=$(openssl rand -hex 24)
S3_SECRET_KEY=$(openssl rand -hex 24)
GIFS_API_KEY=$(openssl rand -hex 24)
EOF
chmod 600 .env

SITE_URL을 사람들이 브라우저에 입력할 주소로 설정하세요. 예를 들어 로컬 네트워크에서는 http://192.168.1.20:8065, 도메인을 사용하는 경우 https://chat.example.com입니다. .env 파일을 보관하세요: 데이터베이스와 저장소가 첫 시작 시 이 비밀번호를 사용하며, 백업을 복원할 때에도 동일한 파일이 필요합니다.

3. 시작

docker compose up -d
docker compose ps

첫 시작에는 1~2분이 소요됩니다: PostgreSQL이 데이터베이스를 생성하고, 원샷 bucket 서비스가 저장소 버킷을 생성하며, 원샷 gifs-stickers 서비스가 시작 스티커 팩을 가져오고, Antimatter가 테이블을 생성합니다. docker compose logs -f antimatter로 진행 상황을 추적하세요.

처음부터 도메인 이름과 HTTPS를 사용하려면 도메인과 HTTPS를 참고하세요: compose 파일에서는 .env에 두 줄과 https 프로필만 추가하면 됩니다.

PostgreSQL, 스토리지 및 GIF 서비스는 인터넷 접근이 없는 내부 네트워크(private)에 있으며, Antimatter만 이 네트워크에 참여합니다. 이 서비스들은 포트를 공개하지 않습니다.

Antimatter 컨테이너는 디스크에 아무것도 저장하지 않습니다: 설정은 데이터베이스에 있으며(AM_CONFIG가 이를 가리킴) 파일과 앱은 스토리지 서비스에 있습니다. 컨테이너를 언제든 삭제하고 다시 생성할 수 있습니다. 백업해야 할 모든 것은 postgres, files, gifs 볼륨과 .env 파일에 있습니다.

이미지 선택

두 가지 Antimatter 이미지가 공개되며, 모두 linux/amd64와 linux/arm64를 지원하며, 모든 저장소의 main 브랜치에서 빌드됩니다:

이미지번들 앱태그
ghcr.io/antimatterchat/antimatter에이전트, 통화, GitHub, GitLab, Jira, Kanban, 메트릭스, 플레이북.latest, 릴리스용 X.Y.Z, sha-<commit>
ghcr.io/antimatterchat/antimatter-next위 항목에 더해 음성 채널, 투표, 메일, 캘린더, 메모, 화이트보드, GIF, 할 일, 밈. 매일 밤 재빌드됩니다.latest, nightly, nightly-<YYYYMMDD>, sha-<commit>

이 사이트의 compose 파일은 GIF 서비스와 이 사이트에서 설명하는 대부분의 앱이 해당 이미지에만 포함되어 있기 때문에 antimatter-next를 사용합니다. 이미지를 변경하려면 .env에서 ANTIMATTER_IMAGE를 설정하고 docker compose up -d를 실행하세요.

latest는 사용 중인 환경이 변경됩니다. 프로덕션에서는 nightly-20261015나 sha-<commit>와 같은 태그를 고정하고, 업그레이드할 때 의도적으로 변경하세요. 서버는 시작 시 데이터베이스를 업그레이드하므로, 이전 백업을 복원하지 않고는 이전 이미지로 되돌리거나 antimatter-next에서 antimatter로 전환할 수 없습니다. 백업 및 업그레이드를 참조하세요.

이미지 내부

  • 서버는 /antimatter에 위치하며, 바이너리 antimatter와 amctl는 /antimatter/bin에 있습니다(PATH에 포함됨).
  • 권한이 없는 사용자 antimatter(uid 2000)로 실행되며, 셸이 없는 최소한의 distroless 기반을 사용합니다.
  • 포트: 8065(웹 및 API), 8067(메트릭스), 8074(클러스터), 8443 UDP 및 TCP(통화).
  • 로컬 모드(ServiceSettings.EnableLocalMode)가 켜져 있으므로 컨테이너 내부에서 amctl --local를 사용할 수 있습니다. 헬스 체크는 amctl system status --local를 실행합니다.
  • 번들된 앱은 /antimatter/prepackaged_plugins에 있으며, Antimatter 앱 서명 키로 서명되어 있습니다.
  • 텍스트 추출 도구(pdftotext, wvText, unrtf, tidy)가 포함되어 있어 업로드된 문서의 내용을 검색할 수 있습니다.

기타 compose 파일

antimatter-docker 저장소에는 deploy/compose/에 프로덕션 환경 설정이 포함되어 있습니다. 자체 인증서 또는 Let's Encrypt(certbot)를 사용하는 nginx, PostgreSQL, 선택적 GIF 서비스(프로필 gifs), 그리고 서버의 설정, 데이터, 로그를 위한 이름 지정 볼륨이 README에 문서화되어 있습니다. 기본적으로 안정 버전 이미지를 사용하며, S3 스토리지 대신 로컬 볼륨에 파일을 저장합니다. Caddy 대신 nginx를 선호하거나 이미 인증서를 보유하고 있는 경우 이 설정을 사용하세요.

첫 번째 관리자 생성

브라우저에서 SITE_URL을 열고 계정을 생성하세요. 새 서버에서 생성된 첫 번째 계정은 시스템 관리자가 됩니다. 이후 설정 과정은 첫 번째 커뮤니티(Antimatter에서 팀 또는 워크스페이스를 지칭하는 용어)를 만드는 단계를 안내합니다.

서버가 처음 시작된 직후에 이 작업을 수행하세요. 그 전까지 서버에 가장 먼저 접속한 사람이 관리자가 됩니다. 서버가 외부에서 접근 가능하기 전에 대신 명령줄에서 계정을 생성하려면:

docker compose exec antimatter amctl --local user create --system-admin --email-verified \
    --email admin@example.com --username admin --password 'a-long-password'
docker compose exec antimatter amctl --local team create --name main --display-name "Main"
docker compose exec antimatter amctl --local team users add main admin

이후 SITE_URL에서 로그인하세요. 명령어 앞에 공백을 추가하여 셸 히스토리에 비밀번호가 기록되지 않도록 하세요(HISTCONTROL=ignorespace 설정 시), 또는 로그인 후 비밀번호를 변경하세요.

로그인 후 다음 단계를 진행하세요:

  1. 누가 계정을 생성할 수 있는지 결정하세요: 로그인 및 계정.
  2. 초대 및 비밀번호 재설정이 작동하도록 이메일을 설정하세요: 이메일 및 푸시 알림.
  3. 방화벽에서 통화 포트를 열세요: 통화 및 음성.
  4. 활성화된 앱을 확인하세요: 번들된 앱.

릴리스 아카이브에서 설치

Docker 없이 서버를 실행하려면 antimatter-<os>-<arch>.tar.gz라는 이름의 아카이브(예: antimatter-linux-amd64.tar.gz)를 사용합니다. 이 아카이브에는 antimatter/ 디렉터리 하나와 그 안의 bin/antimatter, bin/amctl, config/config.json, 웹 앱(client/ 및 client-fusion/), 이메일 템플릿, 번역 파일이 포함됩니다.

1. PostgreSQL 준비

Antimatter는 PostgreSQL 15 이상만 지원합니다(구버전은 로그에 오류가 발생하며 시작되지 않습니다). 사용자와 데이터베이스를 생성하세요:

sudo -u postgres psql <<'EOF'
CREATE USER antimatter WITH PASSWORD 'a-long-password';
CREATE DATABASE antimatter OWNER antimatter;
EOF

2. 압축 해제 및 설정

sudo tar -xzf antimatter-linux-amd64.tar.gz -C /opt
sudo useradd --system --user-group antimatter
sudo mkdir -p /opt/antimatter/data
sudo chown -R antimatter:antimatter /opt/antimatter

/opt/antimatter/config/config.json(SqlSettings.DataSource) 또는 환경 변수를 통해 서버를 데이터베이스에 연결하고, 사이트 URL을 설정하세요:

AM_SQLSETTINGS_DRIVERNAME=postgres
AM_SQLSETTINGS_DATASOURCE=postgres://antimatter:a-long-password@localhost:5432/antimatter?sslmode=disable&connect_timeout=10
AM_SERVICESETTINGS_SITEURL=https://chat.example.com

아카이브의 config.json는 완전한 기본 설정 파일입니다. 시스템 콘솔에서 변경한 설정은 이 파일에 다시 저장됩니다. 대신 데이터베이스에 설정을 유지하려면 설정을 참고하세요.

3. 서비스로 실행

/etc/systemd/system/antimatter.service에 systemd 유닛을 추가하세요:

[Unit]
Description=Antimatter
After=network.target postgresql.service

[Service]
Type=notify
User=antimatter
Group=antimatter
WorkingDirectory=/opt/antimatter
ExecStart=/opt/antimatter/bin/antimatter
EnvironmentFile=-/etc/antimatter.env
TimeoutStartSec=3600
Restart=always
RestartSec=10
LimitNOFILE=49152

[Install]
WantedBy=multi-user.target

AM_ 변수를 /etc/antimatter.env에 기록(루트만 읽을 수 있도록)한 다음:

sudo systemctl daemon-reload
sudo systemctl enable --now antimatter
journalctl -u antimatter -f

서버는 포트 8065에서 리스닝합니다. http://<server>:8065를 열거나, 리버스 프록시가 설정된 후에는 도메인을 사용하세요(도메인과 HTTPS 참고). 첫 번째 계정을 생성하면 시스템 관리자가 됩니다.

bin/amctl는 명령줄에서 실행 중인 서버를 관리합니다. 서버 자체에서는 로컬 모드를 통해 로그인 없이 사용할 수 있습니다: AM_SERVICESETTINGS_ENABLELOCALMODE=true를 설정한 후 sudo -u antimatter /opt/antimatter/bin/amctl --local system status를 실행하세요.

기타 서버 명령

서버 실행(antimatter 또는 antimatter server) 외에도 바이너리에는 몇 가지 유지보수 명령이 있습니다. 이 명령들은 서버와 동일한 설정을 읽습니다.

명령기능
antimatter version버전, 빌드 번호, 빌드 날짜, 빌드 해시를 출력합니다.
antimatter db ping데이터베이스에 접근할 수 있는지 확인합니다.
antimatter db init데이터베이스에 설정을 생성합니다(AM_CONFIG를 postgres:// URL로 설정).
antimatter db migrate서버를 시작하지 않고 데이터베이스 마이그레이션을 적용합니다.
antimatter db version데이터베이스에 마지막으로 적용된 마이그레이션을 출력합니다.
antimatter import bulk, antimatter export bulk벌크 형식으로 데이터를 가져오기 또는 내보내기합니다(백업 및 업그레이드 참고).
