REST API

Antimatter 앱이 수행하는 모든 작업은 동일한 HTTP API를 통해 이루어지므로, 스크립트도 이를 사용할 수 있습니다. 이 페이지에서는 인증 방법, 가장 많이 사용하는 리소스, 응답과 오류의 형식, 그리고 WebSocket을 통해 실시간으로 이벤트를 추적하는 방법을 설명합니다.

기본 사항

  • 기본 URL: https://chat.example.com/api/v4. 아래에 나열된 모든 엔드포인트는 이 URL을 기준으로 합니다.
  • 형식: 파일 업로드(multipart)를 제외하고는 입력과 출력 모두 JSON 형식입니다. Content-Type: application/json을 보내야 합니다.
  • ID: 모든 객체는 26자리의 id를 가집니다. 시간은 Unix epoch 기준 밀리초 단위입니다(create_at, update_at, delete_at; 0은 "삭제되지 않음"을 의미합니다).
  • 커뮤니티는 팀입니다: API에서는 이를 teams라고 부르며, team_id를 사용합니다.
  • 당신: user_id를 받는 경로에서 me는 로그인한 사용자를 의미하며, GET /users/me와 같습니다.

엔드포인트의 전체 목록은 서버 코드에 있습니다: 라우트는 server/channels/api4/*.go에, 타입은 server/public/model에 선언되어 있습니다. 저장소의 api/v4/source 폴더에 있는 OpenAPI 설명서는 Mattermost에서 상속된 엔드포인트를 다루며, Antimatter의 추가 기능은 포함되지 않습니다.

인증

로그인 및 일부 공개 엔드포인트를 제외한 모든 요청에는 Authorization 헤더에 토큰이 필요합니다:

curl -H "Authorization: Bearer $TOKEN" https://chat.example.com/api/v4/users/me

여기서 세 가지 유형의 토큰이 허용됩니다: 개인 액세스 토큰, 세션 토큰, OAuth 액세스 토큰. Authorization: Token … 형식도 허용됩니다. 쿼리 문자열(?access_token=)에 포함된 토큰은 OAuth 액세스 토큰에 대해서만 허용됩니다.

개인 액세스 토큰(스크립트 사용 권장)

개인 액세스 토큰은 사용자를 대신하여 작동하며, 만료일을 지정하지 않는 한 만료되지 않고, 언제든지 폐기할 수 있습니다. 개인 액세스 토큰은 기본적으로 비활성화되어 있습니다:

  1. 시스템 관리자가 시스템 콘솔 › 통합 › 통합관리에서 개인 액세스 토큰을 활성화합니다(ServiceSettings.EnableUserAccessTokens, AM_SERVICESETTINGS_ENABLEUSERACCESSTOKENS).
  2. 토큰을 생성할 수 있는 각 사용자를 위해, 시스템 관리자는 시스템 콘솔 › 사용자 관리 › 사용자를 열고 해당 사용자의 메뉴에서 역할 관리를 선택한 뒤 이 계정이 개인 액세스 토큰을 생성할 수 있도록 허용을 선택합니다. 시스템 관리자는 항상 토큰을 생성할 수 있습니다.
  3. 사용자는 오른쪽 위 아바타를 연 다음 프로필 & 설정 › 보안으로 이동합니다. 개인 액세스 토큰 아래에서 토큰의 용도를 설명하고 토큰 생성하기를 선택합니다. 토큰은 한 번만 표시됩니다: 복사해 두세요.

API를 사용하는 경우: POST /users/{user_id}/tokens에 {"description": "backup script", "expires_at": 0}를 전달합니다 (expires_at는 밀리초 단위이며, 0이면 만료 없음). 응답의 token 필드가 시크릿이며, id는 토큰을 폐기할 때 사용합니다 (POST /users/tokens/revoke에 {"token_id": "…"}를 전달). 명령줄에서는: amctl token generate <user> <description>를 사용합니다.

시스템 관리자는 같은 시스템 콘솔 페이지의 개인 액세스 토큰 최대 유효 기간(일)으로 토큰 유효 기간을 제한할 수 있습니다.

세션 토큰

비밀번호로 로그인하면 Token 응답 헤더에 세션 토큰이 반환됩니다. 이는 앱이 사용하는 것과 동일한 종류의 세션입니다:

curl -i -X POST https://chat.example.com/api/v4/users/login \
  -H 'Content-Type: application/json' \
  -d '{"login_id": "maya", "password": "…"}'

다중 인증을 사용하는 계정의 경우 "token": "123456"을 추가합니다. 세션은 서버의 세션 설정에 따라 만료되며, 로그인 엔드포인트는 속도 제한이 적용됩니다(초당 5개 요청). POST /users/logout를 호출하면 세션이 종료됩니다.

브라우저는 쿠키를 사용하여 인증합니다. 쿠키로 인증된 요청은 GET 요청을 제외한 모든 요청에 대해 X-CSRF-Token 헤더를 함께 전송해야 합니다. Authorization 헤더에 포함된 토큰은 CSRF 헤더가 필요 없습니다.

OAuth 2.0 앱

사용자가 Antimatter 계정으로 애플리케이션에 로그인할 수 있도록 하려면 OAuth 2.0 앱을 등록합니다. 그러면 Antimatter가 OAuth 제공자가 됩니다:

  1. OAuth 2.0 서비스 제공자가 켜져 있어야 합니다(시스템 콘솔 › 통합 › 통합관리, ServiceSettings.EnableOAuthServiceProvider, 기본적으로 켜져 있음).
  2. OAuth 앱 관리 권한이 있는 사용자(기본적으로 시스템 관리자)는 아바타를 열고 통합 › OAuth 2.0 앱으로 이동한 뒤 콜백 URL과 함께 앱을 추가합니다. 그러면 클라이언트 ID와 클라이언트 시크릿을 받게 됩니다.
  3. 애플리케이션은 response_type=code, client_id, redirect_uri 및 state와 함께 사용자를 https://chat.example.com/oauth/authorize로 이동시킵니다. code_challenge_method=S256를 사용한 PKCE가 지원됩니다.
  4. POST https://chat.example.com/oauth/access_token에서 코드를 교환합니다(grant_type=authorization_code, 이후 refresh_token으로 갱신)하고, Authorization: Bearer <access token>를 사용하여 API를 호출합니다.

사용자는 프로필 및 설정 › 보안 › 승인한 앱에서 승인한 앱을 볼 수 있습니다.

메시지 게시

curl -X POST https://chat.example.com/api/v4/posts \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"channel_id": "'$CHANNEL_ID'", "message": "Backup finished: **42 GB** in 3 min"}'

메시지는 Markdown 형식입니다. 글타래에 답글을 달려면 "root_id"(글타래의 첫 게시물)를, 파일을 첨부하려면 "file_ids"를, 첨부 파일 및 기타 추가 정보를 위해 "props"를 사용합니다(첨부 파일 참조).

채널 ID 찾기

curl -H "Authorization: Bearer $TOKEN" \
  https://chat.example.com/api/v4/teams/name/lumen-labs/channels/name/ops-alerts

이름은 채널 링크에 있는 것입니다: /lumen-labs/channels/ops-alerts.

페이지네이션

목록 엔드포인트는 page(0부터)와 per_page(기본값 60, 최대 200)를 받습니다. per_page보다 짧은 페이지가 반환될 때까지 다음 페이지를 계속 요청합니다.

채널의 메시지(GET /channels/{channel_id}/posts)도 since(시간: 그 이후에 변경된 모든 것) 또는 before와 after(게시물 ID)를 받습니다. 게시글 목록으로 반환됩니다: {"order": [IDs, newest first], "posts": {ID: post}, "next_post_id", "prev_post_id"}.

오류

오류는 일반적인 HTTP 상태 코드(400 잘못된 입력, 401 로그인 안 됨, 403 권한 없음, 404 찾을 수 없음, 501 기능 비활성화)와 JSON 본문으로 반환됩니다:

{
  "id": "api.context.permissions.app_error",
  "message": "You do not have the appropriate permissions.",
  "detailed_error": "",
  "request_id": "jz8zm5nunpbt8f3gpqsz5dq6so",
  "status_code": 403
}

코드에서는 id를 사용하세요: message는 사용자의 언어로 번역됩니다. detailed_error는 서버가 개발자 모드(ServiceSettings.EnableDeveloper)로 실행되지 않는 한 비어 있습니다. request_id를 서버 관리자에게 인용하세요: 로그에 있습니다.

요청 제한

속도 제한은 기본적으로 꺼져 있습니다. 시스템 관리자가 활성화하면(시스템 콘솔 › 환경 › 속도 제한), 기본적으로 각 클라이언트는 초당 10개 요청, 최대 100개 버스트를 허용받으며 IP 주소 또는 사용자별로 계산됩니다. 응답에는 X-RateLimit-Limit, X-RateLimit-Remaining, X-RateLimit-Reset가 포함되며, 한도를 초과하면 서버는 429와 함께 초 단위의 Retry-After 헤더로 응답합니다. 로그인과 같은 일부 엔드포인트는 설정과 관계없이 자체 한도가 적용됩니다.

429 발생 시 대기하고 재시도하는 스크립트를 작성하고, 폴링을 피하세요: 대신 WebSocket을 따르세요.

WebSocket 이벤트 스트림

wss://chat.example.com/api/v4/websocket에 연결하세요. 연결 요청에 Authorization: Bearer 헤더를 사용하여 인증하거나, 이를 첫 번째 메시지로 보내서 인증할 수 있습니다:

{"seq": 1, "action": "authentication_challenge", "data": {"token": "…"}}

서버는 hello 이벤트를 보내고, 이후 볼 수 있는 모든 것에 대한 이벤트를 보내습니다:

{
  "event": "posted",
  "data": {"channel_id": "…", "channel_type": "O", "post": "{\"id\":\"…\",\"message\":\"Hello\",…}"},
  "broadcast": {"channel_id": "…", "team_id": "", "user_id": "", "omit_users": null},
  "seq": 4
}

data.post는 JSON 문자열인 게시글임을 유의하세요. 일반적인 이벤트: posted, post_edited, post_deleted, reaction_added, reaction_removed, typing, status_change, user_added, direct_added. 앱은 custom_<app id>_<event>로 명명된 자체 이벤트를 보내습니다.

증가하는 seq가 포함된 작업을 보낼 수도 있습니다: {"channel_id", "parent_id"}가 포함된 user_typing 또는 get_statuses. 연결이 끊기면 다시 연결하고, since로 놓친 것을 가져오세요( 페이지네이션 참고).

Antimatter는 다음 이벤트를 추가합니다: community_attributes_updated, member_timeouts_updated, post_put_on_top, post_removed_from_top, server_categories_updated, channel_overrides_updated 및 category_overrides_updated.

클라이언트 라이브러리

  • 시작: server/public/model의 model.Client4(github.com/mattermost/mattermost/server/public/model 가져오기). model.NewAPIv4Client(url)를 호출한 뒤 client.SetToken(token)를 실행합니다. model.NewWebSocketClient4(wsURL, token)는 이벤트를 추적합니다. Antimatter의 코피는 UpdateMessageRequest, PutPostOnTop, ExportChannel과 같은 자체 엔드포인트용 메서드를 추가합니다.
  • TypeScript: webapp/platform/client의 @mattermost/client Client4 클래스, 타입은 webapp/platform/types에 있습니다. Antimatter 저장소의 복사본에는 Antimatter의 엔드포인트가 포함되어 있지만, Mattermost가 npm에 게시한 패키지에는 포함되어 있지 않습니다.
package main

import (
	"context"
	"log"

	"github.com/mattermost/mattermost/server/public/model"
)

func main() {
	client := model.NewAPIv4Client("https://chat.example.com")
	client.SetToken("…")
	post, _, err := client.CreatePost(context.Background(), &model.Post{
		ChannelId: "…",
		Message:   "Hello from Go",
	})
	if err != nil {
		log.Fatal(err)
	}
	log.Println("posted", post.Id)
}

Antimatter가 API에 추가한 내용

이 엔드포인트와 필드는 Mattermost 서버에 존재하지 않습니다. 모두 세션이 필요합니다.

엔드포인트기능
GET /teams/{team_id}/user_attributes/fields
POST 동일한 경로
PATCH, DELETE …/fields/{field_id}		커뮤니티 속성: 커뮤니티 관리자가 멤버를 위해 정의하는 프로필 필드(최대 20개). 멤버는 읽을 수 있으며, 커뮤니티 관리자가 생성 및 변경합니다.
GET /teams/{team_id}/members/{user_id}/user_attributes
PATCH 동일한 경로
POST /teams/{team_id}/user_attributes/values/search		{field_id: value} 형식의 멤버 속성 값. 멤버는 자신의 값을 설정할 수 있으며(관리자가 관리하는 필드 제외), 관리자는 누구의 값이든 설정할 수 있습니다. 검색은 {"user_ids": [...]}(최대 200개)를 받습니다.
GET /teams/{team_id}/timeouts
PUT /teams/{team_id}/members/{user_id}/timeout
GET /teams/{team_id}/members/{user_id}/moderation		타임아웃: {"until": time, "reason": "…"}는 해당 시점까지(최대 28일) 커뮤니티에서 게시, 반응, 업로드를 방지합니다. "until": 0은 이를 해제합니다. 모더레이션 뷰에서는 가입 시점과 최근 게시량을 보여줍니다.
GET /channels/{channel_id}/on_top
PUT, DELETE /posts/{post_id}/on_top		채널 상단에 고정된 메시지(최대 10개). {"duration": ms}, 최대 30일; 0이면 제거될 때까지 유지됩니다. 채널에 게시할 권한이 필요합니다.
POST /channels/{channel_id}/message_request자신의 메시지 요청에 대한 작업: {"action": "accept"}, "dismiss", 또는 요청 목록에 대화를 다시 넣기 위한 "request". 자신의 채널 멤버를 반환합니다.
GET, PUT /channels/{channel_id}/overrides
GET /channels/{channel_id}/overrides/effective
GET, PUT /channels/{channel_id}/role_access		채널에서 역할 또는 사용자가 수행할 수 있는 작업, 그리고 역할 기반 접근 제한이 설정된 채널을 볼 수 있는 역할입니다.
GET, PUT /teams/{team_id}/server_categories
GET, PUT …/server_categories/overrides		커뮤니티의 공유 채널 카테고리, 그리고 해당 카테고리 내 모든 채널에 적용되는 예외 설정입니다.
GET /groups/{group_id}/team_role
PUT …/team_role/permissions		커뮤니티 역할이 부여하는 권한입니다.
POST /teams/{team_id}/autolinks/preview커뮤니티의 자동 링크 규칙을 텍스트에 적용해 테스트합니다.
POST /channels/{channel_id}/export?format=csv&since=&until=채널의 메시지를 CSV 파일로 다운로드합니다(최대 50,000개). 채널을 읽을 수 있는 사용자만 사용할 수 있습니다.
GET /posts/{post_id}/speech텍스트 음성 변환(TTS)이 설정된 경우, 음성으로 낭독되는 메시지입니다.

새로운 필드

  • 커뮤니티 (Team, PUT /teams/{team_id}/patch): all_channels_membership(Discord처럼 모든 사용자가 볼 수 있는 모든 채널에 자동으로 포함됨), default_channel_id(새로 온 사용자가 처음 도착하는 채널. 비어 있으면 Town Square), hide_role_colors, require_team_badges, onboarding 및 autolinks(둘 다 JSON 문자열).
  • 인라인 답글: "props": {"reply_to": "<post id>"}를 포함하는 게시물은 같은 채널의 해당 메시지를 인용합니다. "reply_to_mention": false를 추가하면 작성자에게 알림을 보내지 않습니다. 서버는 인용된 메시지의 간략한 설명을 metadata.reply_to에 채웁니다.
  • 스포일러: "props": {"spoiler": true}를 사용하면 독자가 보기로 선택할 때까지 게시물의 텍스트와 파일이 숨겨집니다.
  • 무시 및 차단은 사용자 설정입니다. 범주는 user_block이며, 이름은 상대방의 ID를 따르고 값은 ignore 또는 block입니다. 다이렉트 메시지가 요청으로 대기되는지 여부는 채널 멤버의 notify_props.dm_request에 저장됩니다(pending, accepted 또는 dismissed).
  • 메시지 첨부 파일에는 stages와 chart를 포함할 수 있습니다: 카드를 참조하세요.
