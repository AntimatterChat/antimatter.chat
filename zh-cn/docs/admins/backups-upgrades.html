备份与升级

需要备份的内容、如何在新主机上还原、如何升级，以及如何将 Mattermost 服务器或单个社区迁移至 Antimatter。

需要备份的内容

内容使用站点的 compose 文件使用发布包
数据库：消息、用户、社区、频道，以及使用站点 compose 文件时的配置卷 antimatter_postgres，通过 pg_dump您的 PostgreSQL 数据库
上传的文件、图片和已安装的应用卷 antimatter_files（S3 存储）FileSettings.Directory，默认为 ./data/
配置文件（位于数据库中）config/config.json
GIF 和贴纸卷 antimatter_gifsGIF 服务的数据目录
密钥.env（以及 compose.override.yaml）您的环境文件

数据库和文件是配套的：请同时备份它们，并将副本保存在服务器之外。卷名称以 compose 项目名称 antimatter 开头（docker volume ls 可列出它们）。

备份

在 compose.yaml 所在的目录中运行。先停止 Antimatter 可获得完全一致的副本；在运行期间进行备份通常也没问题，但备份期间上传的文件可能会缺失。

stamp=$(date +%Y%m%d-%H%M%S)
mkdir -p backups
docker compose stop antimatter
# Database
docker compose exec -T postgres pg_dump -U antimatter -d antimatter -Fc \
    > "backups/antimatter-db-$stamp.dump"
# File storage and GIF service
for v in files gifs; do
    docker run --rm -v "antimatter_$v:/data:ro" -v "$PWD/backups:/backup" \
        alpine tar -czf "/backup/antimatter-$v-$stamp.tar.gz" -C /data .
done
docker compose start antimatter
# Secrets
cp .env "backups/env-$stamp"

通过 cron 运行以实现每日备份，并将 backups/ 目录复制到另一台机器。请像保护服务器一样妥善保管 .env 的副本：其中包含其密码。

若要逐个对象复制上传的文件（例如复制到另一个 S3 存储），请使用 bucket 服务的 AWS 命令行工具：

docker compose run --rm -v "$PWD/backups/files:/backup" bucket \
    "aws --endpoint-url http://files:9000 s3 sync s3://antimatter /backup"

使用发布包时，用 pg_dump -Fc 备份数据库，并用常用工具备份 data/ 和 config/ 目录。

在新主机上还原

将 compose.yaml、保存的 .env 和备份文件放入一个新目录，然后：

stamp=20261016-030000          # the backup to restore
docker compose create           # creates the volumes, starts nothing
docker compose up -d postgres
docker compose exec -T postgres pg_restore -U antimatter -d antimatter --no-owner \
    < "backups/antimatter-db-$stamp.dump"
for v in files gifs; do
    docker run --rm -v "antimatter_$v:/data" -v "$PWD/backups:/backup" \
        alpine tar -xzf "/backup/antimatter-$v-$stamp.tar.gz" -C /data
done
docker compose up -d

使用相同的 .env：存储和数据库必须保留原有的密码。如果新主机地址不同，请更新 SITE_URL（以及 DOMAIN）。

时不时地在另一台机器上还原备份，以测试备份的有效性。

升级

  1. 先进行备份。
  2. 如果您固定了镜像标签（如建议的那样），请更改 .env 中的镜像标签（ANTIMATTER_IMAGE）。
  3. 拉取并重启： 
    docker compose pull
docker compose up -d
docker compose logs -f antimatter

启动时，服务器会升级数据库架构（可在日志中跟踪进度；大型服务器可能需要几分钟），并从镜像中安装捆绑应用的更新版本。如果使用发布归档：请停止服务器，用新归档的内容替换除 config/、data/、logs/、plugins/ 和 client/plugins/ 之外的所有内容，然后重新启动。

升级只能向前进行。一旦较新的服务器升级了数据库，旧版本就无法使用它：若要回退，请恢复升级前创建的备份。从 antimatter-next 回退到 antimatter 的情况也是如此。

版本

Antimatter 服务器会报告其基于的 Mattermost 版本（当前为 12.0.0）。镜像从 main 分支重新构建：antimatter-next 每晚构建一次（标签为 nightly-<YYYYMMDD>），两个镜像则在每次更改时构建（标签为 sha-<commit>）。请固定使用其中一个标签，有意进行升级，并记录之前的标签，以便知道哪个备份与之对应。

PostgreSQL 主要版本

compose 文件使用 postgres:17-alpine。Antimatter 需要 PostgreSQL 15 或更高版本。PostgreSQL 的新主要版本无法读取旧版本的数据目录：若要迁移，请转储数据库，在新卷上启动新版本，并将转储内容恢复到其中。

从 Mattermost 迁移

Antimatter 使用 Mattermost 的数据库架构并添加了自身的表，因此可以接管 Mattermost 服务器的 PostgreSQL 数据库和文件。请先在副本上尝试：

  1. 备份 Mattermost 数据库、其文件存储（data/ 或 S3 存储桶）以及 config.json，然后停止 Mattermost。
  2. 将数据库恢复到 Antimatter 的 PostgreSQL 中，或将 Antimatter 指向其副本（AM_SQLSETTINGS_DATASOURCE）。
  3. 将文件复制到 Antimatter 的存储中，保持其路径不变：使用 S3 工具复制到 antimatter 存储桶，或使用发布归档复制到 data/。
  4. 重用您的设置：复制 config.json，或使用 amctl --local config migrate 将其迁移到数据库中（参见 配置）。您的 MM_ 环境变量将继续有效；方便时可将其重命名为 AM_。
  5. 启动 Antimatter，并跟踪日志以查看数据库升级过程。然后检查 系统控制台 › 插件 › 插件管理。当通话、操作手册、看板（Boards）、智能体及集成的版本比已安装版本更新时，Antimatter 会安装其自带的构建版本。如果 Mattermost 拥有其中某个应用的更新版本，请删除该应用并重启 Antimatter，以便安装 Antimatter 自带的构建版本。
  6. 使用您自己的推送代理重新设置推送通知：Antimatter 从不向 Mattermost 的推送服务（无论是测试环境还是托管环境）发送通知，因为这些服务仅向 Mattermost 自己的应用投递通知。在您更改 推送通知服务器 之前，服务器不会发送任何推送通知（参见 推送通知）。

Antimatter 不会联系由 Mattermost, Inc. 运行的任何服务（参见 与外部服务的连接），即使您的配置中仍然指定了这些服务：

  • Mattermost 的推送通知服务器保留在设置中，但从未被使用；
  • Mattermost 的应用市场（市场 URL）和产品通知地址已被清空；
  • 通话应用使用 Cloudflare 的公共 STUN 服务器，而不是 Mattermost 的服务器，且不会更改已保存的设置（参见 通话）；
  • 安全更新检查和崩溃报告已被移除，相关的系统控制台设置（启用安全警报、启用诊断和错误报告）以及 通知 页面也随之消失。

本地模式套接字现在是 /var/tmp/antimatter_local.socket；amctl 也会尝试旧的 /var/tmp/mattermost_local.socket。Mattermost 的近期版本仅支持 PostgreSQL，Antimatter 也是如此：请先将 MySQL 数据库迁移到 PostgreSQL。在 Antimatter 升级数据库后返回 Mattermost，意味着需要恢复您的 Mattermost 备份。

导出和导入数据

批量导出格式用于在服务器之间迁移数据：可以是整个服务器、某些社区或某些频道，如果您愿意，还可以包含附件、个人资料图片和自定义表情符号。

# on the source server
amctl export create --team-name design --include-profile-pictures
amctl export list
amctl export download <export file> design.zip
# on the destination server
amctl import upload design.zip
amctl import list available
amctl import process <uploaded file> --imported-users active

使用 amctl export job list 和 amctl import job list 查看任务。对于社区或频道导出，必须指定 --imported-users：当用户迁移到该服务器时使用 active；当导入到用户已有账户的服务器时使用 inactive，这样从不确定匹配中创建的账户将保持停用，直到管理员确认。使用 --destination-team-name 可导入到现有团队。导出和导入文件默认在服务器存储（ExportSettings.Directory、ImportSettings.Directory）中保留 30 天。

在服务器本身，antimatter export bulk 和 antimatter import bulk --apply 可从文件执行相同操作，无需通过 API。
