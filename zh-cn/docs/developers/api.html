REST API

Antimatter 应用的所有操作都通过同一个 HTTP API 进行，因此您的脚本也可以这样做。本页介绍如何进行身份验证、您将最常使用的资源、响应和错误的格式，以及如何通过 WebSocket 实时跟踪事件。

基础

  • 基础 URL：https://chat.example.com/api/v4。以下所有端点均相对于此 URL。
  • 格式：输入和输出均为 JSON，文件上传除外（multipart）。请发送 Content-Type: application/json。
  • ID：每个对象都有一个 26 个字符的 id。时间表示自 Unix 纪元以来的毫秒数（create_at、update_at、delete_at；0 表示“未删除”）。
  • 社区即团队：API 将其称为 teams，并带有 team_id。
  • 您自己：在任何接受 user_id 的路径中，me 表示当前登录的用户，例如 GET /users/me。

完整的端点列表位于服务器代码中：路由声明在 server/channels/api4/*.go 中，类型定义在 server/public/model 中。仓库 api/v4/source 文件夹中的 OpenAPI 描述涵盖了从 Mattermost 继承的端点，而非 Antimatter 的添加内容。

身份验证

除登录和少数公共端点外，每个请求都需要在 Authorization 头中包含令牌：

curl -H "Authorization: Bearer $TOKEN" https://chat.example.com/api/v4/users/me

此处接受三种类型的令牌：个人访问令牌、会话令牌和 OAuth 访问令牌。也接受 Authorization: Token …。查询字符串中的令牌（?access_token=）仅对 OAuth 访问令牌有效。

个人访问令牌（推荐用于脚本）

个人访问令牌代表您进行操作，除非您设置了过期日期，否则不会过期，并且可以随时撤销。个人访问令牌默认处于关闭状态：

  1. 系统管理员需在系统控制台 › 集成 › 集成管理中开启开启个人访问令牌（ServiceSettings.EnableUserAccessTokens、AM_SERVICESETTINGS_ENABLEUSERACCESSTOKENS）。
  2. 对于每位可能创建令牌的用户，系统管理员需打开 系统控制台 › 用户管理 › 用户，在该用户的菜单中选择 管理角色，并勾选 允许此账户生成个人访问令牌。系统管理员始终可以创建令牌。
  3. 该用户打开右上角的头像，然后进入 个人资料与设置 › 安全。在 个人访问令牌 部分，描述该令牌的用途，然后选择 创建新令牌。令牌仅显示一次：请复制它。

通过 API：POST /users/{user_id}/tokens，请求体为 {"description": "backup script", "expires_at": 0}（expires_at 以毫秒为单位；0 表示永不过期）。响应中的 token 字段即为密钥；其 id 用于撤销该令牌（POST /users/tokens/revoke，请求体为 {"token_id": "…"}）。从命令行：amctl token generate <user> <description>。

系统管理员可以在同一系统控制台页面通过 个人访问令牌最长生命周期（天） 来限制令牌的生命周期。

会话令牌

使用密码登录会在 Token 响应头中返回一个会话令牌，这与应用程序使用的会话类型相同：

curl -i -X POST https://chat.example.com/api/v4/users/login \
  -H 'Content-Type: application/json' \
  -d '{"login_id": "maya", "password": "…"}'

对于启用了多因素认证的账户，请添加 "token": "123456"。会话的过期时间遵循服务器的会话设置，且登录端点受到速率限制（每秒 5 次请求）。POST /users/logout 用于结束会话。

浏览器使用 Cookie 进行身份验证。对于除 GET 以外的任何请求，通过 Cookie 进行身份验证的请求还必须发送 X-CSRF-Token 头；而在 Authorization 头中提供的令牌则无需 CSRF 头。

OAuth 2.0 应用

要允许用户使用其 Antimatter 账户登录您的应用程序，请注册一个 OAuth 2.0 应用。此时 Antimatter 充当 OAuth 服务提供商：

  1. 必须开启 启动 OAuth 2.0 服务提供商（系统控制台 › 集成 › 集成管理，ServiceSettings.EnableOAuthServiceProvider，默认开启）。
  2. 拥有管理 OAuth 应用权限的人员（默认为系统管理员）打开其头像，然后进入 集成 › OAuth 2.0 应用，添加该应用及其回调 URL。他们将获得一个客户端 ID 和一个客户端密钥。
  3. 您的应用将用户重定向到 https://chat.example.com/oauth/authorize，并附带 response_type=code、client_id、redirect_uri 和 state。支持使用 code_challenge_method=S256 的 PKCE。
  4. 随后，应用通过 POST https://chat.example.com/oauth/access_token 交换授权码（使用 grant_type=authorization_code，之后使用 refresh_token 进行续期），并在调用 API 时携带 Authorization: Bearer <access token>。

用户可以在 个人资料与设置 › 安全 › 您已授权的应用 中查看已授权的应用。

发送消息

curl -X POST https://chat.example.com/api/v4/posts \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"channel_id": "'$CHANNEL_ID'", "message": "Backup finished: **42 GB** in 3 min"}'

消息使用 Markdown 格式。添加 "root_id"（话题的首条消息）可在话题中回复，添加 "file_ids" 用于文件，添加 "props" 用于附件及其他扩展信息（参见 附件）。

查找频道 ID

curl -H "Authorization: Bearer $TOKEN" \
  https://chat.example.com/api/v4/teams/name/lumen-labs/channels/name/ops-alerts

名称即频道链接中的部分：/lumen-labs/channels/ops-alerts。

分页

列表端点接受 page（从 0 开始）和 per_page（默认 60，最大 200）。持续请求下一页，直到返回的页面长度小于 per_page 为止。

频道的消息（GET /channels/{channel_id}/posts）也接受 since（时间：返回自该时间点以来发生变化的所有内容），或 before 和 after（帖子 ID）。返回结果为帖子列表：{"order": [IDs, newest first], "posts": {ID: post}, "next_post_id", "prev_post_id"}。

错误

错误使用标准的 HTTP 状态码（400 输入错误，401 未登录，403 权限不足，404 未找到，501 功能已关闭）以及 JSON 响应体：

{
  "id": "api.context.permissions.app_error",
  "message": "You do not have the appropriate permissions.",
  "detailed_error": "",
  "request_id": "jz8zm5nunpbt8f3gpqsz5dq6so",
  "status_code": 403
}

在代码中使用 id：message 会翻译为用户的语言。detailed_error 仅在服务器运行于开发者模式（ServiceSettings.EnableDeveloper）时非空。向服务器管理员引用 request_id：它记录在日志中。

速率限制

速率限制默认关闭。当系统管理员启用它（系统控制台 › 环境 › 速率限制）时，每个客户端默认每秒 10 次请求，突发上限为 100 次，按 IP 地址或用户计数。响应包含 X-RateLimit-Limit、X-RateLimit-Remaining 和 X-RateLimit-Reset；超出限制时，服务器返回 429 并附带以秒为单位的 Retry-After 头。某些端点（如登录）无论设置如何都有独立的限制。

编写脚本以在遇到 429 时等待并重试，并避免轮询：请改用 WebSocket。

WebSocket 事件流

连接到 wss://chat.example.com/api/v4/websocket。认证方式有两种：在连接请求中使用 Authorization: Bearer 头，或发送此消息作为第一条消息：

{"seq": 1, "action": "authentication_challenge", "data": {"token": "…"}}

服务器发送 hello 事件，随后发送您有权查看的所有事件：

{
  "event": "posted",
  "data": {"channel_id": "…", "channel_type": "O", "post": "{\"id\":\"…\",\"message\":\"Hello\",…}"},
  "broadcast": {"channel_id": "…", "team_id": "", "user_id": "", "omit_users": null},
  "seq": 4
}

注意 data.post 是作为 JSON 字符串的帖子。常见事件包括：posted、post_edited、post_deleted、reaction_added、reaction_removed、typing、status_change、user_added、direct_added。应用发送其自身的事件，命名为 custom_<app id>_<event>。

您也可以发送操作，每个操作带有递增的 seq：user_typing 附带 {"channel_id", "parent_id"}，或 get_statuses。当连接断开时重新连接，并使用 since 获取遗漏的内容（参见 分页）。

Antimatter 添加了以下事件：community_attributes_updated、member_timeouts_updated、post_put_on_top、post_removed_from_top、server_categories_updated、channel_overrides_updated 和 category_overrides_updated。

客户端库

  • Go：位于 server/public/model 中的 model.Client4（导入 github.com/mattermost/mattermost/server/public/model）。使用 model.NewAPIv4Client(url)，然后调用 client.SetToken(token)；model.NewWebSocketClient4(wsURL, token) 用于跟踪事件。Antimatter 的副本为其自身端点添加了方法，例如 UpdateMessageRequest、PutPostOnTop 和 ExportChannel。
  • TypeScript：@mattermost/client 中的 Client4 类，位于 webapp/platform/client，其类型定义位于 webapp/platform/types。Antimatter 仓库中的副本包含 Antimatter 的端点；Mattermost 在 npm 上发布的包则不包含。
package main

import (
	"context"
	"log"

	"github.com/mattermost/mattermost/server/public/model"
)

func main() {
	client := model.NewAPIv4Client("https://chat.example.com")
	client.SetToken("…")
	post, _, err := client.CreatePost(context.Background(), &model.Post{
		ChannelId: "…",
		Message:   "Hello from Go",
	})
	if err != nil {
		log.Fatal(err)
	}
	log.Println("posted", post.Id)
}

Antimatter 对 API 的扩展

这些端点和字段在 Mattermost 服务器上不存在。它们都需要会话。

端点功能说明
GET /teams/{team_id}/user_attributes/fields
POST 相同路径
PATCH、DELETE …/fields/{field_id}		社区属性：社区管理员为其成员定义的个人资料字段（最多 20 个）。成员可以读取这些字段；社区管理员可以创建和修改它们。
GET /teams/{team_id}/members/{user_id}/user_attributes
PATCH 相同路径
POST /teams/{team_id}/user_attributes/values/search		成员的属性值，格式为 {field_id: value}。成员可以设置自己的值（管理员管理的字段除外）；管理员可以设置任何人的值。搜索接受 {"user_ids": [...]}（最多 200 个）。
GET /teams/{team_id}/timeouts
PUT /teams/{team_id}/members/{user_id}/timeout
GET /teams/{team_id}/members/{user_id}/moderation		超时设置：{"until": time, "reason": "…"} 会在指定时间之前（最长 28 天）阻止用户在社区中发帖、添加表情回应或上传内容；"until": 0 则会解除该限制。管理视图会显示用户加入的时间以及近期的发帖数量。
GET /channels/{channel_id}/on_top
PUT, DELETE /posts/{post_id}/on_top		将消息固定在频道顶部（最多 10 条）。{"duration": ms}，最长 30 天；设为 0 则保留至手动移除。需要拥有在该频道发帖的权限。
POST /channels/{channel_id}/message_request处理您自己的消息请求：{"action": "accept"}、"dismiss" 或 "request"（将对话重新放回请求列表）。返回您的频道成员信息。
GET, PUT /channels/{channel_id}/overrides
GET /channels/{channel_id}/overrides/effective
GET, PUT /channels/{channel_id}/role_access		角色或个人可在频道中执行的操作，以及哪些角色可以查看受角色限制的频道。
GET, PUT /teams/{team_id}/server_categories
GET, PUT …/server_categories/overrides		社区共享的频道分类，以及适用于该分类下所有频道的覆盖设置。
GET /groups/{group_id}/team_role
PUT …/team_role/permissions		社区角色所授予的权限。
POST /teams/{team_id}/autolinks/preview使用社区的自动链接规则测试一段文本。
POST /channels/{channel_id}/export?format=csv&since=&until=将频道的消息下载为 CSV 文件（最多 50,000 条），适用于有权读取该频道的人员。
GET /posts/{post_id}/speech当配置了文本转语音功能时，以音频形式朗读的消息。

新字段

  • 社区（Team，以及 PUT /teams/{team_id}/patch）：all_channels_membership（所有人均可加入其有权查看的所有频道）、default_channel_id（新成员加入的默认频道；为空则默认为 Town Square）、hide_role_colors、require_team_badges、onboarding 和 autolinks（均为 JSON 字符串）。
  • 内联回复：包含 "props": {"reply_to": "<post id>"} 的帖子会引用同一频道中的该消息。添加 "reply_to_mention": false 可避免通知原作者。服务器会在 metadata.reply_to 中填入被引用消息的简短描述。
  • 剧透："props": {"spoiler": true} 会隐藏帖子的文本和文件，直到读者选择显示。
  • 忽略和屏蔽属于偏好设置：分类为 user_block，名称为对方的 ID，值为 ignore 或 block。私信是否作为请求等待处理，取决于您频道成员中的 notify_props.dm_request（pending、accepted 或 dismissed）。
  • 消息附件可以包含 stages 和 chart：请参阅 卡片。
