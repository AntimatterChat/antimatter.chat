Встановлення Antimatter

Встановіть Antimatter за допомогою готового файлу compose, з пакета .deb або .rpm релізу або з архіву релізу. Потім створіть обліковий запис першого адміністратора.

Встановлення за допомогою Docker Compose

Це рекомендований спосіб. Один файл compose запускає Antimatter, PostgreSQL, сховище файлів та службу GIF. Вам потрібен Linux-сервер із Docker Engine та його плагіном Compose (docker compose), 2 ядра CPU та 4 ГБ пам’яті або більше.

1. Завантажте файл compose

mkdir antimatter && cd antimatter
curl -fsSLO https://antimatter.chat/compose.yaml

2. Створіть файл .env

Файл compose читає свої налаштування з файлу .env в тому самому каталозі. Створіть його з випадковими секретами:

cat > .env <<EOF
SITE_URL=http://localhost:8065
POSTGRES_PASSWORD=$(openssl rand -hex 24)
S3_SECRET_KEY=$(openssl rand -hex 24)
GIFS_API_KEY=$(openssl rand -hex 24)
AM_AI_ENCRYPTION_KEY=$(openssl rand -base64 32)
EOF
chmod 600 .env

Встановіть SITE_URL на адресу, яку люди вводитимуть у браузері, наприклад http://192.168.1.20:8065 у локальній мережі або https://chat.example.com із доменом. Збережіть файл .env: база даних та сховище використовують ці паролі з першого запуску, ключі API для підключення моделей ШІ шифруються за допомогою AM_AI_ENCRYPTION_KEY, а той самий файл потрібен для відновлення з резервної копії.

3. Запустіть

docker compose up -d
docker compose ps

Перший запуск триває хвилину-дві: PostgreSQL створює базу даних, одноразова служба bucket створює бакет сховища, одноразова служба gifs-stickers імпортує стартовий набір стікерів, а Antimatter створює свої таблиці. Слідкуйте за процесом за допомогою docker compose logs -f antimatter.

Щоб одразу використовувати доменне ім’я та HTTPS, див. Домен і HTTPS: у файлі compose це лише дві додаткові рядки в .env та профіль https.

PostgreSQL, сховище та служба GIF працюють у внутрішній мережі (private) без доступу в Інтернет, до якої приєднується лише Antimatter. Жоден із цих компонентів не публікує портів.

Контейнер Antimatter не зберігає нічого на диску: його налаштування зберігаються в базі даних (AM_CONFIG вказує на неї), а файли та застосунки — у службі сховища. Ви можете видалити та повторно створити контейнер у будь-який момент. Його том data містить лише файл ключа шифрування ШІ, який сервер створює, коли AM_AI_ENCRYPTION_KEY порожній. Усе, що потрібно резервувати, зберігається у томах postgres, files, gifs та data, а також у вашому файлі .env.

Оберіть образ

Опубліковано два образи Antimatter, обидва для linux/amd64 та linux/arm64, і обидва зібрані з гілки main кожного репозиторію:

ЗображенняВбудовані додаткиТеги
ghcr.io/antimatterchat/antimatterАгенти, Дзвінки, GitHub, GitLab, Jira, Kanban, Метрики та Плейбуки.latest, X.Y.Z для релізів, sha-<commit>
ghcr.io/antimatterchat/antimatter-nextТе саме, плюс Голосові канали, Опитування, Пошта, Календар, Нотатки, Дошка для малювання, GIF, Списки справ і Мемі. Перезбирається щовечора.latest, nightly, nightly-<YYYYMMDD>, sha-<commit>

Файл compose сайту використовує antimatter-next, оскільки служба GIF та більшість додатків, описаних на цьому сайті, доступні лише в цьому образі. Щоб змінити образ, встановіть ANTIMATTER_IMAGE у .env та виконайте docker compose up -d.

latest змінюється під ногами. У продуктивному середовищі закріпіть тег, наприклад nightly-20261015 або sha-<commit>, і змінюйте його свідомо під час оновлення. Сервер оновлює свою базу даних під час запуску, тому повернутися до старішого образу, або з antimatter-next на antimatter, неможливо без відновлення резервної копії, зробленої раніше. Див. Резервне копіювання та оновлення.

Усередині образу

  • Сервер розташований у /antimatter, з бінарними файлами antimatter та amctl у /antimatter/bin (у PATH).
  • Він працює від імені непривілейованого користувача antimatter (uid 2000) на мінімальному базовому образі distroless, без оболонки.
  • Порти: 8065 (веб та API), 8067 (метрики), 8074 (кластер), 8443 UDP та TCP (дзвінки).
  • Локальний режим (ServiceSettings.EnableLocalMode) увімкнено, тому amctl --local працює всередині контейнера. Перевірка працездатності виконує amctl system status --local.
  • Вбудовані додатки розташовані в /antimatter/prepackaged_plugins та підписані ключем підпису додатків Antimatter.
  • Включено інструменти для видобування тексту (pdftotext, wvText, unrtf, tidy), тому можна шукати вміст завантажених документів.

Інші файли compose

Репозиторій antimatter-docker містить продуктивну конфігурацію в deploy/compose/: nginx із власними сертифікатами або Let's Encrypt (certbot), PostgreSQL, необов'язковий GIF-сервіс (профіль gifs) та іменовані томи для конфігурації, даних і журналів сервера, описані в його README. За замовчуванням використовується стабільний образ і зберігає файли на локальному томі замість S3-сховища. Користуйтеся ним, якщо віддаєте перевагу nginx перед Caddy або вже маєте сертифікати.

Створення першого адміністратора

Відкрийте SITE_URL у браузері та створіть акаунт. Перший акаунт, створений на новому сервері, стає системним адміністратором, а далі процес налаштування проведе вас через створення першої спільноти (так у Antimatter називають команду або робоче середовище).

Зробіть це одразу після першого запуску: до того моменту будь-хто, хто першим отримає доступ до сервера, стане його адміністратором. Щоб створити акаунт із командного рядка замість цього, до того, як сервер стане доступним із зовні:

docker compose exec antimatter amctl --local user create --system-admin --email-verified \
    --email admin@example.com --username admin --password 'a-long-password'
docker compose exec antimatter amctl --local team create --name main --display-name "Main"
docker compose exec antimatter amctl --local team users add main admin

Потім увійдіть за адресою SITE_URL. Почніть команду з пробілу, щоб пароль не потрапив до історії оболонки (за умови HISTCONTROL=ignorespace), або змініть пароль після входу.

Дальші кроки після того, як ви потрапили всередину:

  1. Для компанії або організації встановіть Тип нових спільнот на Робоче середовище, а тип спільноти, яку ви вже створили, змініть у її налаштуваннях: Робоче середовище або спільнота.
  2. Визначте, хто може створювати акаунти: Вхід та акаунти.
  3. Налаштуйте електронну пошту, щоб запрошення та скидання паролів працювали: Електронна пошта та push-сповіщення.
  4. Відкрийте порт для дзвінків у вашому файрволі: Дзвінки та голос.
  5. Перевірте, які додатки увімкнено: Вбудовані додатки.

Завантажити реліз

Без Docker встановіть Antimatter з файлів релізу на GitHub: github.com/AntimatterChat/antimatter/releases. Кожен реліз має номер версії, наприклад 0.9.0, а його мітка — той самий номер із префіксом v (v0.9.0).

Antimatter перебуває на стадії бета-тестування: її випуски належать до серії 0.9.0. Випуск, у версії якого після дефіса є суфікс, наприклад 0.9.0-rc.1, позначений на GitHub як Pre-release. Це тестова версія, опублікована перед остаточною.

Кожен випуск містить такі файли для серверів amd64 та arm64:

ФайлПризначення
antimatter_<version>-1_amd64.deb, antimatter_<version>-1_arm64.debПакет для Debian, Ubuntu та дистрибутивів, заснованих на них.
antimatter-<version>-1.x86_64.rpm, antimatter-<version>-1.aarch64.rpmПакет для Fedora, RHEL та сумісних із RHEL дистрибутивів.
antimatter-<version>-linux-amd64.tar.gz, antimatter-<version>-linux-arm64.tar.gzАрхів випуску для будь-якого дистрибутива Linux, який налаштовується вручну.
SHA256SUMSКонтрольна сума SHA-256 для всіх файлів випуску.

Пакети та архів містять однакову програму: сервер (antimatter), інструмент командного рядка (amctl), обидві веб-додатки (типовий інтерфейс та класичний), вбудовані додатки, шаблони електронних листів та переклади. Пакети додають службу systemd та файл налаштувань, тому кожен з них є комплексною інсталяцією: потрібно лише додати базу даних PostgreSQL. Окремих завантажень виконуваних файлів немає: вони містяться в архіві, у antimatter/bin/. Вони є статичними, тому працюють на будь-якому дистрибутиві Linux відповідної архітектури.

У назвах пакетів дефіс у версії попереднього випуску замінюється на тильду, щоб менеджер пакетів сортував попередній випуск перед остаточною версією: версія 0.9.0-rc.1 дає antimatter_0.9.0~rc.1-1_amd64.deb та antimatter-0.9.0~rc.1-1.x86_64.rpm. Архів зберігає дефіс.

antimatter version виводить версію випуску як Номер збірки, а коміт, з якого вона збудована, — як Геш збірки. Рядок Версія вказує версію рядка Mattermost, на якому базується Antimatter.

Перевірка завантаження

Завантажте потрібний файл та SHA256SUMS в одну й ту саму теку, зі сторінки випуску або за допомогою curl, а потім перевірте файл:

curl -fLO https://github.com/AntimatterChat/antimatter/releases/download/v<version>/antimatter_<version>-1_amd64.deb
curl -fLO https://github.com/AntimatterChat/antimatter/releases/download/v<version>/SHA256SUMS
sha256sum --check --ignore-missing SHA256SUMS

Кожен завантажений вами файл має бути перелічений із позначкою OK. Будь-який інший результат означає, що файл пошкоджений або неповний: завантажте його повторно та не встановлюйте. SHA256SUMS не підписаний: він виявляє пошкоджене завантаження, але не доводить нічого більше, ніж HTTPS-завантаження з GitHub.

Встановлення пакета .deb або .rpm

Пакет встановлює Antimatter як службу systemd, якій для запуску потрібна лише база даних. Використовуйте його на 64-бітовому сервері Debian, Ubuntu, Fedora або сумісному з RHEL із systemd.

Що встановлює пакет

ШляхЗміст
/opt/antimatterПрограма: bin/antimatter, bin/amctl, веб-додатки (client/, client-fusion/), вбудовані додатки (prepackaged_plugins/), шаблони, переклади та шрифти. Під час оновлення ця частина заміняється.
/etc/antimatter/antimatter.envНалаштування служби у вигляді змінних AM_: база даних, URL сайту, служба GIF. Доступна лише для root. Оновлення зберігає ці дані.
/etc/antimatter/config/config.jsonФайл конфігурації, куди сервер зберігає налаштування, змінені в Системній консолі. Створюється з /opt/antimatter/defaults/config.json під час першої встановлення і ніколи не заміняється після цього.
/var/lib/antimatterЗавантажені файли (data/) та встановлені додатки (plugins/, client-plugins/).
/var/log/antimatterФайли журналів, якщо ви увімкнете ведення журналів у файлах. За замовчуванням вимкнено: журнали пишуться в журнал системи.
/usr/lib/systemd/system/antimatter.serviceСлужба.
/usr/bin/amctlПосилання на /opt/antimatter/bin/amctl.

Каталоги, куди сервер записує дані в /opt/antimatter (config, data, plugins, client/plugins та logs), є посиланнями на /etc/antimatter, /var/lib/antimatter та /var/log/antimatter. Тому оновлення, яке заміняє /opt/antimatter, ніколи не торкається ваших даних. Пакет також створює системного користувача antimatter, який запускає сервер і є власником цих каталогів.

Пакет залежить від ca-certificates. Рекомендує PostgreSQL (postgresql у Debian та Ubuntu, postgresql-server у Fedora та RHEL), media-types (mailcap для .rpm) та gifs-server — службу GIF, яка має власний реліз (див. нижче). apt та dnf встановлюють рекомендовані пакети, якщо їх знаходять. Пакет також пропонує poppler-utils, wv, unrtf та tidy (без wv для .rpm): вони видобувають текст із завантажених документів, щоб пошук знаходив слова всередині них. Встановіть їх самостійно, якщо потрібна ця функція.

1. Встановіть пакети

Завантажте пакет Antimatter та пакет служби GIF для вашої архітектури, перевірте їх, як показано вище, та встановіть обидва однією командою, щоб виконати рекомендацію щодо gifs-server (його немає в репозиторіях дистрибутивів):

# Debian, Ubuntu
sudo apt install ./antimatter_<version>-1_amd64.deb ./gifs-server_*_amd64.deb
# Fedora, RHEL
sudo dnf install ./antimatter-<version>-1.x86_64.rpm ./gifs-server-*.x86_64.rpm

Залиште ./: це вказує apt і dnf, що потрібно встановити локальний файл. Щоб встановити без служби GIF, просто не додавайте її пакет. Пакет вмикає службу antimatter, але не запускає її, а виводить наступні кроки.

2. Створення бази даних

Antimatter потребує PostgreSQL 15 або новішої версії, на цьому сервері або на іншому. Перевірте версію PostgreSQL вашого дистрибутива за допомогою psql --version. Якщо вона старіша, встановіть новішу версію з репозиторіїв проєкту PostgreSQL або використовуйте базу даних на іншому сервері. На Debian і Ubuntu пакет postgresql запускає базу даних. На Fedora і RHEL спершу створіть і запустіть її:

sudo postgresql-setup --initdb
sudo systemctl enable --now postgresql

Потім створіть користувача та базу даних для Antimatter:

sudo -u postgres psql -c "CREATE USER antimatter WITH PASSWORD 'a-long-password'"
sudo -u postgres psql -c "CREATE DATABASE antimatter OWNER antimatter"

PostgreSQL має приймати з’єднання з паролем з 127.0.0.1: рядки host у файлі pg_hba.conf з методом scram-sha-256.

3. Налаштування бази даних та URL сайту

Відкрийте /etc/antimatter/antimatter.env (sudoedit /etc/antimatter/antimatter.env). Приберіть # перед рядками, які ви використовуєте, і вкажіть базу даних та адресу, яку відкриватимуть користувачі:

AM_SQLSETTINGS_DRIVERNAME=postgres
AM_SQLSETTINGS_DATASOURCE=postgres://antimatter:a-long-password@localhost:5432/antimatter?sslmode=disable&connect_timeout=10
AM_SERVICESETTINGS_SITEURL=https://chat.example.com

У цей файл можна додати будь-який параметр конфігурації у форматі AM_<SECTION>_<SETTING>: наприклад, SqlSettings.DataSource буде AM_SQLSETTINGS_DATASOURCE. Параметр, встановлений тут, не можна змінити в Системній консолі. Див. Конфігурація. Перезапустіть сервер після кожної зміни: sudo systemctl restart antimatter.

Служба також встановлює кілька значень за замовчуванням, які можна перевизначити рядком у antimatter.env: запис у файли вимкнено (AM_LOGSETTINGS_ENABLEFILE=false, AM_NOTIFICATIONLOGSETTINGS_ENABLEFILE=false), а локальний режим увімкнено (AM_SERVICESETTINGS_ENABLELOCALMODE=true), щоб amctl --local працювало на сервері.

4. Запуск

sudo systemctl start antimatter
journalctl -u antimatter -f
sudo -u antimatter amctl --local system status

Під час першого запуску сервер створює свої таблиці, а потім слухає порт 8065. Відкрийте http://<server>:8065 або вашу домену, якщо налаштовано reverse proxy (див. Домен і HTTPS), і одразу створіть перший акаунт: він стане системним адміністратором. Щоб створити його замість цього з командного рядка, скористайтеся командами amctl з розділу Створення першого адміністратора, замінивши docker compose exec antimatter amctl --local на sudo -u antimatter amctl --local.

5. Увімкніть GIFки

Додаток GIFки вбудовано та увімкнено, а antimatter.env вже вказує на службу GIF на тому самому сервері (AM_GIFS_SERVICE_URL=http://127.0.0.1:8080/v2). Проте все ще потрібен ключ API цієї служби. Пакет gifs-server згенерував його під час встановлення:

sudo systemctl start gifs-server-stickers    # imports the sticker pack, about a minute and a half
sudo systemctl start gifs-server
sudo grep -v '^#' /etc/gifs-server/api-keys

Вкажіть ключ у antimatter.env як AM_GIFS_API_KEY=<key> і перезапустіть Antimatter, або введіть його як Ключ API у Системна консоль › Плагіни › GIFки. Якщо служба GIF працює на іншому сервері, встановіть для AM_GIFS_SERVICE_URL її адресу. Щоб дозволити користувачам додавати власні GIFки та наклейки, див. GIFки.

Служба

  • Вона працює від імені користувача antimatter, у каталозі /opt/antimatter та читає /etc/antimatter/antimatter.env. systemd перезапускає сервер щоразу, коли той завершує роботу, і дає йому до години на запуск, оскільки міграції бази даних нової версії можуть тривати довго.
  • Її журнали зберігаються в journal: journalctl -u antimatter.
  • Служба захищена: /usr та /etc для сервера доступні лише для читання, за винятком /etc/antimatter/config, а /home, /root та /run/user для нього невидимі. Якщо ви переміщуєте сховище файлів (FileSettings.Directory), оберіть каталог поза цими, власником якого є antimatter.
  • Оновлення заміняють файл служби. Щоб його змінити, скористайтеся sudo systemctl edit antimatter, що збереже ваші зміни в окремому файлі.

Оновлення пакета

  1. Зробіть резервну копію (див. Резервні копії та оновлення).
  2. Завантажте новий пакет і SHA256SUMS, а потім перевірте їх.
  3. Зупиніть сервер, встановіть новий пакет замість старого та запустіть його знову: 
    sudo systemctl stop antimatter
sudo apt install ./antimatter_<new version>-1_amd64.deb     # or: sudo dnf install ./antimatter-<new version>-1.x86_64.rpm
sudo systemctl start antimatter
journalctl -u antimatter -f

Пакет не перезапускає сервер самостійно. Після оновлення він виводить Antimatter was upgraded; restart it to run the new version: sudo systemctl restart antimatter: якщо ви не зупинили сервер заздалегідь, перезапустіть його одразу. Оновлення замінює /opt/antimatter та файл служби, але зберігає antimatter.env, config.json, /var/lib/antimatter та журнали. Під час запуску сервер оновлює базу даних та встановлює новіші версії вбудованих додатків.

Якщо нова версія змінює типовий antimatter.env, apt запитує, чи зберігати вашу версію: зберігайте її. dnf зберігає вашу версію та зберігає нову як /etc/antimatter/antimatter.env.rpmnew. Оновлення можливі лише вперед: не встановлюйте стару версію поверх нової.

Видалення пакета

sudo apt remove antimatter або sudo dnf remove antimatter зупиняє та вимикає службу, а також видаляє програму. Дані (/var/lib/antimatter), налаштування (/etc/antimatter), база даних та користувач antimatter зберігаються: видаліть їх самостійно, щоб повністю прибрати Antimatter.

Додатки в пакетах та архіві

Пакети та архів містять останній підписаний реліз цих додатків у prepackaged_plugins/: Agents, Calls, GIFs, Memes, Notes, Polls, Todo, Voice Channels та Whiteboard. Додаток, для якого ще не було релізу на момент збірки сервера, не включається: ls /opt/antimatter/prepackaged_plugins показує, що містить ваш реліз. Memes та Todo включені, але не активовані: Вбудовані додатки пояснює, як їх встановити та увімкнути.

Інші додатки з Docker-образів не входять до пакетів чи архіву: Kanban, Playbooks, Mail, Calendar, GitHub, GitLab, Jira та Metrics. Встановіть кожен із них з його власних релізів:

ДодатокРелізиІдентифікатор додатка
Kanbanantimatter-plugin-boardsfocalboard
Плейбукиantimatter-plugin-playbooksplaybooks
Поштаantimatter-plugin-mailcom.antimatterchat.mail
Календарantimatter-plugin-calendarcom.antimatterchat.calendar
GitHubantimatter-plugin-githubgithub
GitLabantimatter-plugin-gitlabcom.github.manland.mattermost-plugin-gitlab
Jiraantimatter-plugin-jirajira

Кожен реліз додатка містить його пакет (файл .tar.gz), його підпис (файл з тим самим назвою, але з додаванням .sig) та файл SHA256SUMS. Щоб встановити додаток, дозвольте завантаження, а потім додайте пакет за допомогою amctl:

# 1. In /etc/antimatter/antimatter.env, add this line, then restart Antimatter
AM_PLUGINSETTINGS_ENABLEUPLOADS=true
sudo systemctl restart antimatter
# 2. Download the bundle where the antimatter user can read it, and install it
cd /tmp
curl -fLO https://github.com/AntimatterChat/antimatter-plugin-boards/releases/download/v<version>/<bundle>.tar.gz
sudo -u antimatter amctl --local plugin add <bundle>.tar.gz
sudo -u antimatter amctl --local plugin enable focalboard

Щоб оновити додаток, встановлений таким чином, додайте новий пакет за допомогою plugin add --force: оновлення пакетів оновлює лише вбудовані додатки. Після цього ви можете знову видалити рядок AM_PLUGINSETTINGS_ENABLEUPLOADS. Інші способи встановлення додатків описано в розділі Встановлення інших додатків.

Підписи додатків

Пакети додатків підписані ключем підпису додатків Antimatter: кожен файл .tar.gz.sig є відокремленим GPG-підписом відповідного пакета. Сервер перевіряє ці підписи перед встановленням вбудованого додатка. Щоб перевірити пакет самостійно:

curl -fsSLO https://raw.githubusercontent.com/AntimatterChat/antimatter-docker/main/keys/antimatter-plugin-signing.asc
gpg --import antimatter-plugin-signing.asc
gpg --verify <bundle>.tar.gz.sig <bundle>.tar.gz

gpg має повідомити про коректний підпис від Antimatter Plugin Signing з відбитком 06C8 1032 4677 0F08 BBA7 78B9 E69B 05C3 92A6 9A45. Також програма попереджає, що ключ не сертифікований довіреним підписом: це нормально для ключа, який ви не підписали самостійно. Реліз додатка без файлів .sig є непідписаним, і про це зазначено в примітках до релізу.

Встановлення з архіву релізу

Архів antimatter-<version>-linux-<arch>.tar.gz (наприклад, antimatter-0.9.0-linux-amd64.tar.gz) підходить для дистрибутивів без пакетів .deb або .rpm, або для власної конфігурації. Він містить один каталог antimatter/ з файлами bin/antimatter, bin/amctl, config/config.json, веб-додатками (client/ та client-fusion/), вбудованими додатками (prepackaged_plugins/, див. вище), шаблонами електронних листів та перекладами.

1. Підготовка PostgreSQL

Antimatter підтримує лише PostgreSQL версії 15 або новішої (старіші версії запускаються, але в журналі з'являється помилка). Створіть користувача та базу даних:

sudo -u postgres psql <<'EOF'
CREATE USER antimatter WITH PASSWORD 'a-long-password';
CREATE DATABASE antimatter OWNER antimatter;
EOF

2. Розпакування та налаштування

sudo tar -xzf antimatter-<version>-linux-amd64.tar.gz -C /opt
sudo useradd --system --user-group antimatter
sudo mkdir -p /opt/antimatter/data
sudo chown -R antimatter:antimatter /opt/antimatter

Вкажіть серверу базу даних, або у /opt/antimatter/config/config.json (SqlSettings.DataSource), або за допомогою змінних середовища, та встановіть URL сайту:

AM_SQLSETTINGS_DRIVERNAME=postgres
AM_SQLSETTINGS_DATASOURCE=postgres://antimatter:a-long-password@localhost:5432/antimatter?sslmode=disable&connect_timeout=10
AM_SERVICESETTINGS_SITEURL=https://chat.example.com

Файл config.json в архіві — це повна конфігурація за замовчуванням: зміни, які ви вносите в Системній консолі, зберігаються назад у цей файл. Щоб зберігати конфігурацію в базі даних, див. Конфігурація.

3. Запуск як служби

Одиниця systemd у /etc/systemd/system/antimatter.service:

[Unit]
Description=Antimatter
After=network.target postgresql.service

[Service]
Type=notify
User=antimatter
Group=antimatter
WorkingDirectory=/opt/antimatter
ExecStart=/opt/antimatter/bin/antimatter
EnvironmentFile=-/etc/antimatter.env
TimeoutStartSec=3600
Restart=always
RestartSec=10
LimitNOFILE=49152

[Install]
WantedBy=multi-user.target

Розмістіть ваші змінні AM_ у /etc/antimatter.env (доступний лише для root), потім:

sudo systemctl daemon-reload
sudo systemctl enable --now antimatter
journalctl -u antimatter -f

Сервер слухає порт 8065. Відкрийте http://<server>:8065, або ваш домен, коли зворотний проксі налаштовано (див. Домен і HTTPS), та створіть перший акаунт: він стане системним адміністратором.

bin/amctl керує запущеним сервером з командного рядка. На самому сервері він працює без входу через локальний режим: встановіть AM_SERVICESETTINGS_ENABLELOCALMODE=true, потім виконайте sudo -u antimatter /opt/antimatter/bin/amctl --local system status.

Для GIF встановіть службу GIF (див. нижче) та встановіть AM_GIFS_SERVICE_URL та AM_GIFS_API_KEY, як у кроці 5 для пакетів.

Пакети служби GIF та проксі-сервера push-сповіщень

Служба GIF і проксі для сповіщень мають власні релізи за тими самими правилами, що й сервер: архів .tar.gz, пакети .deb і .rpm для amd64 та arm64, а також файл SHA256SUMS. Версії з дефісом — це попередні релізи. Перевіряйте завантаження командою sha256sum --check --ignore-missing SHA256SUMS, як і для сервера.

Служба GIF (gifs-server)

Релізи: github.com/AntimatterChat/gifs-server/releases. Архів має назву gifs-server-<version>-linux-<arch>.tar.gz, а пакети називаються gifs-server.

sudo apt install ./gifs-server_*_amd64.deb      # Debian, Ubuntu
sudo dnf install ./gifs-server-*.x86_64.rpm     # Fedora, RHEL

Пакет встановлює:

  • /usr/bin/gifs-server та службу gifs-server, яка працює від імені користувача gifs-server і зберігає свій каталог у /var/lib/gifs-server;
  • службу gifs-server-stickers, яка імпортує або оновлює набір наліпок у /usr/share/gifs-server/stickers під час запуску, а потім зупиняється;
  • свої налаштування: /etc/gifs-server/gifs-server.env (змінні AM_GIFS_, які зберігаються під час оновлень) та /etc/gifs-server/api-keys (один API-ключ на рядок; під час першого встановлення генерується випадковий ключ).

Служба слухає на 127.0.0.1:8080, тому до неї може звертатися лише Antimatter на тому самому сервері. Якщо Antimatter працює на іншому сервері, встановіть AM_GIFS_LISTEN=:8080 у gifs-server.env та обмежте доступ до порту за допомогою файрвола. У файлі також перелічено інші налаштування: AM_GIFS_UPLOAD_KEYS (ключі, яким дозволено додавати GIF і наліпки та видаляти ті, що були додані за їх допомогою), AM_GIFS_PUBLIC_URL, AM_GIFS_TRUST_PROXY та AM_GIFS_LOG_LEVEL. Пакет рекомендує встановити ffmpeg, gifsicle, librsvg2-bin (librsvg2-tools для .rpm) та шрифт DejaVu: служба використовує їх для створення форматів GIF, відео та наліпок під час імпортування або отримання файлів, але може працювати і без них.

Як і сервер, служба вмикається, але не запускається під час встановлення. Запустіть її, як показано в кроці 5 розділу про пакети. Після оновлення перезапустіть службу: sudo systemctl restart gifs-server. При видаленні пакета каталог у /var/lib/gifs-server зберігається.

Проксі для сповіщень

Релізи: github.com/AntimatterChat/push-proxy/releases. Архів має назву antimatter-push-proxy-<version>-linux-<arch>.tar.gz, а пакети називаються antimatter-push-proxy. Пакет встановлює /usr/bin/antimatter-push-proxy та службу antimatter-push-proxy, яка працює від імені користувача antimatter-push-proxy та читає /etc/antimatter-push-proxy/antimatter-push-proxy.json (файл зберігається під час оновлень). Облікові дані Apple та Firebase зберігаються в /etc/antimatter-push-proxy/certs: розділ Push-повідомлення пояснює, звідки їх отримати.

sudo apt install ./antimatter-push-proxy_*_amd64.deb      # or: sudo dnf install ./antimatter-push-proxy-*.x86_64.rpm
sudo install -o root -g antimatter-push-proxy -m 0640 \
    AuthKey_ABCDE12345.p8 firebase-service-account.json /etc/antimatter-push-proxy/certs/
sudoedit /etc/antimatter-push-proxy/antimatter-push-proxy.json
sudo systemctl start antimatter-push-proxy
journalctl -u antimatter-push-proxy -f

У файлі налаштувань шляхи є відносними відносно /etc/antimatter-push-proxy: наприклад, "AppleAuthKeyFile": "./certs/AuthKey_ABCDE12345.p8" та "ServiceFileLocation": "./certs/firebase-service-account.json". Потім встановіть Сервер push-повідомлень в Antimatter як http://<proxy host>:8066. Після оновлення перезапустіть службу: sudo systemctl restart antimatter-push-proxy.

Push-проксі слухає порт 8066 на всіх адресах і не перевіряє, хто до нього звертається. Тримайте порт у приватній мережі або за зворотним проксі, який обмежує доступ.
