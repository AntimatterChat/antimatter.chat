Alkalmazások (bővítmények) írása

Az alkalmazások belülről bővítik az Antimattert: egy Go nyelven írt szerverrész, amely a szerverbe horgonyozódik, és egy React nyelven írt webalkalmazásrész, amely menüket, paneleket, üzenettípusokat és oldalakat ad hozzá. Ez az oldal a csatolt Polls-alkalmazás példáján mutatja be, hogyan épül fel egy alkalmazás, és mi változik az Antimatter Fusion-felületén.

Hogyan működik egy alkalmazás

  • A szerverrész egy Go program. A szerver külön folyamatként indítja el, és RPC-n keresztül kommunikál vele: meghívja az alkalmazás horgonyait (pl. egy üzenet即将 beküldésre kerül, egy parancs lefutott…), az alkalmazás pedig a szerver bővítmény-API-ját használja (pl. bejegyzés létrehozása, felhasználó olvasása, adatok tárolása…). HTTP útvonalakat is szolgálhat a /plugins/<app id>/ alatt.
  • A webalkalmazásrész egy JavaScript-csomag, amelyet a böngésző betölt a webalkalmazással együtt. A rejiszterben regisztrál React-komponenseket és visszahívásokat: egy gombot a menüben, egy panelt, egy üzenettípus megjelenítési módját.
  • Bármelyik rész opcionális. Az alkalmazás egy .tar.gz csomagként települ, a rendszeradminisztrátorok pedig engedélyezik, letiltják és konfigurálják.
A szerverrész teljes hozzáféréssel rendelkezik a szerver adataihoz. Az alkalmazást úgy kezelje, mint olyan kódot, amelyet a szerverre telepít.

Az Antimatter futtathat Mattermost-nak írt alkalmazásokat, és fordítva, amennyiben az alkalmazás csak olyan horgonyokat használ, amelyek mindkettőben léteznek. Lásd: Csak az Antimatterben lévő horgonyok.

A csomag szerkezete

Nincs külön kezdősablon: induljon egy kicsi, csatolt alkalmazásból, például a antimatter-plugin-polls vagy a antimatter-plugin-todo alkalmazásból, és módosítsa annak azonosítóját és kódját. A Polls szerkezete így néz ki:

antimatter-plugin-polls/
├── plugin.json            the manifest
├── Makefile               build, test, bundle, deploy
├── build/                 the manifest and pluginctl helper tools (Go), setup.mk
├── assets/icon.svg        files shipped with the bundle
├── go.mod
├── server/
│   ├── main.go            plugin.ClientMain(&Plugin{})
│   ├── plugin.go          the Plugin type, OnActivate, ServeHTTP
│   ├── manifest.go        generated from plugin.json
│   ├── api.go, command.go, hooks.go, store.go …
│   └── dist/              compiled binaries, one per platform
└── webapp/
    ├── package.json, webpack.config.js, tsconfig.json
    ├── i18n/              en.json and one file per language
    ├── src/index.tsx      registers the app with the web app
    ├── src/manifest.ts    generated from plugin.json
    ├── src/translations.ts
    └── dist/main.js       the bundle

Opcionális: public/ mappa, amely a /plugins/<app id>/public/ alatt szolgálja ki a fájlokat változatlanul.

  • id: egyedi és állandó; általában fordított domainnév. Ez nevezi meg az útvonalakat, a tárolt beállításokat és a WebSocket-eseményeket.
  • version: szemantikus verzió. A csatolt alkalmazások nem adják meg a plugin.json-ban; a build-eszköz a legutóbbi v* git-címkéből veszi.
  • min_server_version: az Antimatter 12.0.0 verziót jelent.
  • settings_schema: az alkalmazás beállításai a Rendszerkonzolon (lásd Beállítások).

A make apply parancs a manifestet a server/manifest.go és a webapp/src/manifest.ts fájlba másolja; a make manifest-check parancs pedig validálja.

A szerverrész

A szerverrész ugyanazt a Go-modult importálja, mint a Mattermost-alkalmazások, a github.com/mattermost/mattermost/server/public modult a Go-modul proxy-ról. A main függvény csak elindítja az alkalmazást:

package main

import "github.com/mattermost/mattermost/server/public/plugin"

func main() {
	plugin.ClientMain(&Plugin{})
}

A Plugin típus beágyazza a plugin.MattermostPlugin típust, amely biztosítja a p.API hozzáférést, és megvalósítja a szükséges hookokat:

type Plugin struct {
	plugin.MattermostPlugin
	router *mux.Router
}

func (p *Plugin) OnActivate() error {
	p.router = p.newRouter()
	return p.API.RegisterCommand(&model.Command{
		Trigger:          "weather",
		AutoComplete:     true,
		AutoCompleteDesc: "Show the forecast",
		AutoCompleteHint: "[city]",
	})
}

func (p *Plugin) ExecuteCommand(c *plugin.Context, args *model.CommandArgs) (*model.CommandResponse, *model.AppError) {
	city := strings.TrimSpace(strings.TrimPrefix(args.Command, "/weather"))
	return &model.CommandResponse{
		ResponseType: model.CommandResponseTypeEphemeral,
		Text:         "Forecast for " + city + ": sunny",
	}, nil
}

func (p *Plugin) ServeHTTP(c *plugin.Context, w http.ResponseWriter, r *http.Request) {
	p.router.ServeHTTP(w, r)
}

Gyakori hookok

HookAmikor fut
OnActivate, OnDeactivateAmikor az alkalmazás engedélyezve vagy letiltva, valamint amikor a szerver elindul és leáll. A parancsokat és botokat a OnActivate hookban kell regisztrálni.
OnConfigurationChangeAmikor a beállítások megváltoznak; a p.API.LoadPluginConfiguration(&cfg) hívással tölthetők be.
ServeHTTPKérések a /plugins/<app id>/… útvonalra. A szerver beállítja a Mattermost-User-Id fejlécet, ha a kérés bejelentkezett felhasználótól érkezik; utasítsa vissza azokat a kéréseket, amelyeknél ez a fejléc hiányzik, hacsak nem nyilvánosak.
ExecuteCommandAmikor egy az alkalmazás által regisztrált parancs fut le.
MessageWillBePosted, MessageWillBeUpdatedMielőtt egy üzenet elmentésre kerül: módosított bejegyzést vagy elutasítás okát adja vissza.
MessageHasBeenPosted, MessageHasBeenUpdated, MessageHasBeenDeletedUtólag, mellékhatások végrehajtásához.
ReactionHasBeenAdded, ReactionHasBeenRemovedReakciók.
UserHasJoinedChannel, UserHasLeftChannel, UserHasJoinedTeam, UserHasLeftTeam, ChannelHasBeenCreatedTaglétiségi és csatornaváltozások. A csapat egy közösség.
FileWillBeUploadedMielőtt egy fájl tárolásra kerül: módosítsa vagy utasítsa vissza.
OnPluginClusterEventÜzenet ugyanazon alkalmazástól egy klaszter másik szerveréről.

A teljes lista, a pontos aláírásokkal, a server/public/plugin/hooks.go fájlban található; az API a server/public/plugin/api.go fájlban. A pluginapi csomag (server/public/pluginapi) barátságosabb segédfüggvényekkel burkolja be az API-t.

Hasznos API-hívások

  • CreatePost, UpdatePost, SendEphemeralPost: bejegyzés küldése az alkalmazás botjaként vagy felhasználóként.
  • EnsureBotUser(&model.Bot{Username, DisplayName}): egyszeri bot létrehozása az alkalmazás számára és annak azonosítójának lekérése.
  • PublishWebSocketEvent("poll_updated", payload, &model.WebsocketBroadcast{ChannelId: id}): esemény küldése a webalkalmazásnak. A custom_<app id>_poll_updated néven érkezik meg.
  • OpenInteractiveDialog: párbeszéd megnyitása.
  • LogInfo, LogError és társaik: írás a szerver naplófájlba, az alkalmazás azonosítójával címkézve.
  • GetUser, GetChannel, HasPermissionToChannel: ellenőrzés, ki mit tehet, mielőtt felhasználó nevében cselekszik.

Egy alkalmazás a klaszter minden szerverén fut. Az állapotot tárolja a kulcs-érték tárolóban vagy az adatbázisban, ne csak a memóriaban.

Adattárolás

Minden alkalmazásnak van saját kulcs-érték tárolója a szerver adatbázisában:

  • KVSet(key, value), KVGet(key), KVDelete(key): az értékek bájtok, általában JSON. A kulcsok legfeljebb 150 karakter hosszúak.
  • KVSetWithExpiry(key, value, seconds): az érték eltűnik az adott idő elteltével.
  • KVCompareAndSet(key, old, new) és KVSetWithOptions Atomic opcióval: biztonságos frissítések, ha több kérés vagy szerver ír ugyanarra a kulcsra. A Szavazás így ment el minden szavazást, és újrapróbálja a konfliktus esetén.
  • KVList(page, perPage): a kulcsok, oldalanként.

A webalkalmazás rész

A csomag egy osztályt regisztrál a window.registerPlugin segítségével. Az initialize metódus megkapja a registry-t és a Redux store-t:

import manifest from './manifest';

class Plugin {
    initialize(registry, store) {
        registry.registerTranslations((locale) => translationsFor(locale));
        registry.registerPostTypeComponent('custom_poll', PollPost);
        registry.registerWebSocketEventHandler(`custom_${manifest.id}_poll_updated`, (msg) => {
            store.dispatch(pollUpdated(JSON.parse(msg.data.poll)));
        });
        registry.registerReconnectHandler(() => store.dispatch(reloadPolls()));
    }
}

window.registerPlugin(manifest.id, new Plugin());
  • Megosztott könyvtárak. A webalkalmazás biztosítja a Reactet, a ReactDOMot, a Reduxot, a React Reduxot és a React Intlt: ezeket a webpack externals listájába kell felvenni (React, ReactDOM, Redux, ReactRedux, ReactIntl), nem pedig saját másolatokat csomagolni. Lásd a Szavazás webpack.config.js fájlját.
  • A szerveri rész hívása. A ${window.basename}/plugins/<app id>/… URL-t a Client4.getOptions() (a mattermost-redux/client-ből) által visszaadott opciókkal kell lekérni: ezek tartalmazzák a fejléceket, amelyeket a szervernek szüksége van a böngészőből érkező kérések elfogadásához.
  • Saját állapot. A registerReducer hozzáad egy reducer-t, amely a state['plugins-<app id>'] alatt tárolódik.
  • Típusok. Az Antimatter extra registry-metódusai nem szerepelnek a Mattermost közzétett típusaiban: a Szavazás a webapp/src/types/host.ts fájlban deklarálja a használt registry-t.

A registry metódusai és paraméterei a kódban vannak dokumentálva, a webapp/fusion/src/plugins/registry.ts (Fusion) és a webapp/channels/src/plugins/registry.ts (klasszikus) fájlokban.

A Fusion felület támogatása

Az Antimatternek két webes felülete van: a Fusion (az alapértelmezett) és a klasszikus. Mindkettő ugyanazokat az alkalmazáscsomagokat tölti be, és ugyanazt a registry-t használja, de a Fusion sok elemet saját maga rajzol, és a plugin komponenseket saját módon helyezi el. Tesztelje az alkalmazását mindkét felületen.

A felület azonosítása

Minden alkalmazás betöltése előtt mindkét felület beállítja a window.antimatterWebUI értékét 'fusion'-ra vagy 'classic'-ra, és ugyanezt az értéket a data-am-web-ui attribútumként is a lap gyökérelemére. A Mattermostban egyik sem van beállítva.

export function isFusionUI(): boolean {
    return window.antimatterWebUI === 'fusion' || document.documentElement.dataset.amWebUi === 'fusion';
}

A csatolt alkalmazások ezt használják a felület eltérő megjelenítésére. A Szavazás a szavazási kártyáit és a létrehozási párbeszédablakát a Fusion stílusában rajzolja meg, és a Fusionban a /poll parancsra saját párbeszédablakot nyit. A Hívások és a Hangcsatornák kihagyják az oldalsávot és a toast-komponenseket, amelyeket a Fusion a saját hívásfelületével helyettesít. Az Ügynökök alkalmazás a MI-műveleteit az üzenetmenü almeneüjébe helyezi, nem a lebegő eszköztáblára. A Fusion saját CSS-osztályai (a am- előtaggal) és a párbeszédablak-rétege (az am-layer elem) azok, amiket ezek az alkalmazások a felülethez igazodáshoz használnak; ezek nem dokumentált, stabil API-k.

Ami a Fusion nem jelenít meg vagy nem futtat

  • A registerPostDropdownMenuComponent (egy komponens az üzenetmenüben), a registerPostCardTypeComponent (egy bejegyzés kártyája a jobb oldali panelben) és a registerProductSwitcherMenuItem nem jelennek meg a Fusion fő nézeteiben. Az első helyett használja a registerPostDropdownMenuAction metódust.
  • A registerMessageWillBeUpdatedHook nem fut le, ha egy üzenetet a Fusionban szerkesztenek. A szerkesztéseket a szerveren a MessageWillBeUpdated hookkal ellenőrizze.
  • A registerActionAfterChannelCreation csak a klasszikus csatornalétrehozási párbeszédablakból fut le, amelyet a Fusion a Csatorna létrehozása párbeszédablak További beállítások… menüjéből nyit meg.
  • Az alkalmazás sáv komponensei akkor is megjelennek, ha a supportedProductIds értéke bármilyen is.
  • A registerNeedsTeamRoute és registerCustomRoute útvonalai a klasszikus oldalkeretet használják, hasonlóan a termékekhez.

Kizárólag az Antimatterben meglévő hookok

Ezek a regisztrációs metódusok nem léteznek a Mattermostban. Ellenőrizze, hogy a metódus létezik-e, mielőtt meghívná, így az alkalmazás ott is működik:

if (typeof registry.registerComposerMenuItem === 'function') {
    registry.registerComposerMenuItem({
        text: 'Create a poll',
        icon: <i className='icon icon-chart-bar'/>,
        fusionIcon: 'poll',
        action: ({channelId, rootId}) => openPollCreation(channelId, rootId),
    });
} else {
    registry.registerChannelHeaderButtonAction(icon, (channel) => openPollCreation(channel.id), 'Create a poll', 'Create a poll');
}
MetódusMit ad hozzá
registerComposerMenuItem({text, icon, fusionIcon, action, shouldRender})Egy elem az üzenetmező + menüjében, mindkét felületen. Az action paraméter {channelId, rootId} értéket kap.
registerEmojiPickerTab({id, label, icon, fusionIcon, order, component, shouldRender, replacesGifPicker})Az üzenetmező emoji-választójának egy fülé, például GIF-ek vagy matricák. A Fusionban a 10-nél kisebb order értékű fülek az Emoji fül előtt jelennek meg. A komponens channelId, rootId, filter, onFilterChange, onSelectDone, insertText és isFusion paramétereket kap.
registerChannelViewPanel({matcher, component})Egy panel a csatorna-fejléc és az üzenetek között, amelyeket a matcher(state, channel) függvény választ ki. Elrejtheti az üzeneteket és a szerkesztőt (setMessagesVisible), ahogy a hangcsatornák teszik.
registerSidebarChannelFooterComponent(component)Egy sor a csatorna alatt az oldalsávban, például a csatlakozottak listája egy hívás során. A komponens a channel objektumot kapja.
registerIntegrationsOption({title, description, fusionIcon, action, shouldRender})Csak Fusion: egy bejegyzés az Integrációk oldalon, a saját emoji mellett. A GIFs app a saját GIFjeit és matricáit ide adja hozzá.

A fusionIcon a Fusion ikonkészletének egy ikonját nevezi meg (például poll, sticker, calendar vagy image; lásd webapp/fusion/src/fusion/components/icon). A Fusion ezt jeleníti meg a icon helyett, hogy az elem összhangban legyen a többivel.

Beállítások

A plugin.json settings_schema mezője leírja az app oldalát a Rendszerkonzol › Bővítmények alatt:

"settings_schema": {
  "header": "Forecasts come from the weather service below.",
  "settings": [
    {"key": "ServiceURL", "display_name": "Service URL", "type": "text", "default": "https://api.example.com"},
    {"key": "Units", "display_name": "Units", "type": "dropdown", "default": "metric",
     "options": [{"display_name": "Celsius", "value": "metric"}, {"display_name": "Fahrenheit", "value": "imperial"}]},
    {"key": "EnableAlerts", "display_name": "Severe weather alerts", "type": "bool", "default": false,
     "help_text": "Post alerts in the channels that follow a city."}
  ]
}

Beállítás-típusok: bool, text, longtext, number, dropdown, radio, generated (véletlenszerű titok), username és custom (egy komponens által rajzolt, amelyet a webalkalmazás-rész a registerAdminConsoleCustomSetting függvénnyel regisztrál). A beállítások csoportosíthatók sections segítségével.

A szerver-rész ezekbe a struktúrába olvassa be, amelynek mezői a kulcsokkal egyeznek:

type configuration struct {
	ServiceURL   string
	Units        string
	EnableAlerts bool
}

func (p *Plugin) OnConfigurationChange() error {
	var cfg configuration
	if err := p.API.LoadPluginConfiguration(&cfg); err != nil {
		return err
	}
	p.setConfiguration(&cfg)
	return nil
}

Az adminisztrátorok a konfigurációban is beállíthatják ezeket, a PluginSettings.Plugins.<app id> alatt, kisbetűs kulcsokkal (lásd az adminisztrátori útmutatót).

Fordítások

Az Antimatter 37 nyelvre van fordítva, a csomagolt alkalmazások is. A webalkalmazás-rész így végzi el:

  1. Minden szöveget React Intl-lel írj meg, azonosítóval és angol szöveggel: <FormattedMessage id='polls.create' defaultMessage='Create a poll'/> vagy defineMessages. Az azonosítókat az alkalmazás nevével kezdő előtaggal látni el.
  2. Az angol szövegeket a webapp/i18n/en.json fájlba kell kivonni (a csomagolt alkalmazások a formatjs extract parancsot használják).
  3. Minden nyelvhez adj hozzá egy fájlt az en.json mellé, ugyanazokkal az azonosítókkal: fr.json, de.json, pt-BR.json, zh-CN.json…
  4. Adja át őket a webes alkalmazásnak, amely a felhasználó nyelvét kéri: 
    import fr from '../i18n/fr.json';
import ptBR from '../i18n/pt-BR.json';

const catalogs = {fr, 'pt-BR': ptBR};

export function translationsFor(locale) {
    return catalogs[locale] || catalogs[locale.split('-')[0]] || {};
}

registry.registerTranslations(translationsFor);

Ha egy sztring hiányzik, az angol defaultMessage értékre esik vissza. Azoknál a sztringeknél, amelyeket a szerver rész küld (parancsválaszok, botüzenetek), a pluginapi/i18n csomag betölti a csomagban szállított fordítási fájlokat (például az assets/i18n mappát), és minden felhasználó nyelvét használó lokalizátort ad.

Fordítás, telepítés és hibakeresés

Go és Node.js szükséges (az alkalmazás .nvmrc fájljában megadott verzió). Az alkalmazás mappájában:

ParancsMire szolgál
make distFordítja a szerver részt minden platformra, valamint a webes alkalmazás részét, és a csomagot a dist/<app id>-<version>.tar.gz fájlba írja.
make testVégrehajtja a Go és JavaScript tesztek.
make check-styleEllenőrzi a kódot (golangci-lint, ESLint), és ellenőrzi a TypeScript típusokat.
make deployFordítja, majd telepíti és engedélyezi a csomagot a szerveren.
make watch, make deploy-from-watchAz első minden mentéskor újra fordítja a webes alkalmazás részét; a második csomagolja a fordított kódot, és telepíti a szerverre.
make enable, make disable, make resetEngedélyezi, letiltja vagy újraindítja az alkalmazást a szerveren.

A make deploy és a többi szerverparancs helyi módban működő szoketot használ, ha talál ilyet (/var/tmp/antimatter_local.socket, vagy AM_LOCALSOCKETPATH): futtassa ezeket a szerver gépén, helyi módban. Egyébként a MM_SERVICESETTINGS_SITEURL által megadott szerverre jelentkeznek be AM_ADMIN_TOKEN, vagy AM_ADMIN_USERNAME és AM_ADMIN_PASSWORD használatával. A fordítóeszközök még nem olvasnak be AM_ nevű változót a szerver URL-jéhez.

Csomag kézi telepítése

  • A rendszeradminisztrátor engedélyezi a feltöltést a AM_PLUGINSETTINGS_ENABLEUPLOADS=true beállítással (alapértelmezetten kikapcsolva; nincs erre kapcsoló a Rendszerkonzolban).
  • Ezután Rendszerkonzol › Bővítmények › Bővítmény kezelés › Bővítmény feltöltése, vagy amctl plugin add weather.tar.gz, majd amctl plugin enable com.example.weather.
  • Ha a szerveren be van kapcsolva a Bővítmény aláírás szükséges, csak olyan csomagokat fogad el, amelyeket egy megbízható kulccsal aláírtak; lásd Egyéb appok telepítése.
Gyors iterációkhoz fejlesztői szerveren állítsa be a szerveren a AM_SERVICESETTINGS_ENABLEDEVELOPER=true értéket: ekkor a hibák részletes információt tartalmaznak. A csatolt alkalmazások Makefile-jai csak akkor fordítják a szerver részt a saját platformjára, ha a shell-ben be van állítva a MM_SERVICESETTINGS_ENABLEDEVELOPER.
