モデレーション

Antimatterがモデレーターに提供するツール、それぞれの機能と非機能、そしてコミュニティを快適に保つためにそれらを組み合わせる方法。

モデレーションできる人

コミュニティ管理者はこのページのすべてのツールを使用でき、他の管理者を除くすべての人に対して適用できます。その他の人は、適切な権限を持つロールが必要です( ロールと権限を参照):

  • メッセージの管理を使って、他の人のメッセージを編集・削除したり、メッセージをチャンネルの上部に固定したり、固定を解除したりできます。
  • ユーザーの削除で、ユーザーをタイムアウトさせたりコミュニティから削除したりできます。
  • ロールの管理: ロールを付与および削除。

これら3つのいずれかがあれば、モデレータービューにアクセスできます。ユーザーの削除を持つモデレーターは、自分より上位のロールを持たないユーザーのみをタイムアウトさせることができます。

モデレーションビュー

モデレータービューには、特定のユーザーに関する必要な情報と、実行可能なアクションがまとめられています。開くには、ユーザーのプロフィールカードを開き、右上のシールドボタンを選択するか、ユーザー名を右クリックしてモデレータービューを選択します。右側のパネルで開きます。

  • 概要: コミュニティへの参加日(メンバー登録日)、アカウント作成日、過去1日と過去1週間にコミュニティで投稿したメッセージ数。表示でその人のメッセージを検索できます。
  • ロール: その人のコミュニティ内のロール。ロールを管理できる場合、ロールを追加で追加するか、×で削除できます。
  • 主な権限: メンバーとして以上のことができること、例えばメッセージの管理やメンバーの削除とタイムアウトなど。
  • アクション: メッセージ、タイムアウト、チームから削除。システム管理者にはアカウントを無効化するも表示されます。

新しいアカウントが初日に大量に投稿することはスパムの典型的な兆候です: 概要で一目でわかります。

タイムアウト

タイムアウトは、人を削除せずに一時的に活動を停止させます。タイムアウト中、その人はコミュニティのチャンネルを読むことができますが、メッセージを送信、リアクション、ファイル添付、メンションを行うことはできません。ダイレクトメッセージは開いたままです。

  1. モデレーションビューでタイムアウトを選択するか、名前を右クリックしてタイムアウト…を選択します。
  2. 期間を選択します: 60秒、5分、10分、1時間、1日、または1週間。
  3. 必要に応じて、他のモデレーター向けの理由を入力します。
  4. タイムアウトを選択します。

タイムアウトが終了するまで、メッセージ入力欄の代わりに「…までタイムアウト中です」が表示されます。コミュニティの音声チャンネルや通話に参加し直すこともできません。メンバーリストではその人の名前横に タイムアウト中 のタグが表示され、プロフィールカードの下部にはタイムアウトの終了時刻が表示されます。

タイムアウトは自動的に終了します。早期に終了させるには、モデレータービューまたはユーザーのメニューでタイムアウトを解除を選択します。新しいタイムアウトは以前のものを置き換えます。コミュニティからユーザーを削除しても、そのタイムアウトは解除されません。タイムアウトが終了する前に戻ってきた場合、依然としてタイムアウト状態のままです。コミュニティ管理者はタイムアウトにできません。

タイムアウトされた本人には理由が表示されませんが、他のメンバーはサーバーの API を通じて理由を読み取ることができます。本人が見ても問題ない理由を記載してください。

コミュニティから人を削除する

モデレータービューでチームから削除を選択するか、ユーザー名を右クリックしてチームから削除…を選択し、確認します。そのユーザーはコミュニティのすべてのチャンネルから退出し、そのコミュニティでのロールを失いますが、メッセージは残ります。理由が伝えられることはありません。コミュニティは単にそのユーザーのサイドバーから消えます。

削除された人は、新しい招待状があれば戻って来られます。コミュニティが公開の場合は、すぐに戻って来られます。戻ってほしくない場合は、コミュニティを非公開にし、招待リンクを再生成してください（参加できる人 を参照）、または 人を締め出す を参照してください。

単一のチャンネルからだけ削除するには、名前を右クリックして チャンネルから削除 を選択するか、そのチャンネルで /kick @username と入力します。コミュニティの全員がすべてのチャンネルにいる場合、この操作はできません。

人を締め出す

Antimatter には BAN リストはありません。最も軽いものから順に、以下の選択肢があります。

  • 最大 1 週間の タイムアウト。
  • 削除 を行い、非公開コミュニティまたは新しい招待リンクと組み合わせる。
  • アカウントの無効化。これはシステム管理者がモデレータービューまたはシステムコンソールから行います。すべての場所からサインアウトされ、システム管理者が再有効化するまでサインインできません。これはコミュニティだけでなくサーバー全体に適用されるため、スパマーや重大な悪用のために用意されています。

メッセージの削除と編集

メッセージの管理（またはコミュニティ管理者）の場合、メッセージの ⋯ メニューを開き 削除 を選択します。メッセージを削除すると、返信を含むすべてのユーザーから削除され、元に戻すことはできません。コミュニティ管理者は削除できますが、デフォルトでは他の人のメッセージを編集できません。メッセージの管理 ロールを持つユーザーは、削除と編集の両方を行うことができます。

上部に固定されたメッセージはモデレーターの管理下にあります。メッセージを上部に固定したり、固定を解除で解除したりできるのは、チャンネルの管理者、コミュニティの管理者、およびメッセージの管理権限を持つユーザーのみです。これにより、メンバーがアナウンスを削除できないようにしています。ピン留めは異なります。チャンネルの読み取り権限があるユーザーは誰でもピン留めとピン留めの解除を行うことができます。上部に固定されたメッセージを参照してください。

スローモードは存在しません。過熱したチャンネルを鎮めるには、一時的に投稿できるユーザーを制限する（チャンネルの権限を参照）か、関係者にタイムアウトを適用してください。

報告

サーバーの報告機能が有効な場合、メンバーはメッセージの⋯メニューからメッセージを報告を選択してメッセージを報告できます。理由を選択し、コメントを追加します。レビュー中はメッセージはチャンネルから非表示になり、レビュー担当者はボットからのダイレクトメッセージでそのメッセージを受け取ります。このメッセージにはメッセージを削除とメッセージを保持のボタンが付いています。

報告機能はデフォルトでオフになっており、システムコンソール › サイト設定 › データ漏洩の処理でシステム管理者のみがオンにできます。そこでシステム管理者は以下を選択します:

  • レビュー担当者：すべてのコミュニティで同じ担当者にするか、コミュニティごとに担当者を変えるか、またコミュニティ管理者やシステム管理者もレビューに参加させるか（コミュニティ管理者はデフォルトで参加します）；
  • ユーザーが選択できる理由のリスト；
  • 報告者とレビュー担当者がコメントの追加を必須とするか、またレビュー中にメッセージを非表示にするか。

この機能はコンプライアンス用途から生まれたもので、デフォルトの理由（「分類不一致」、「必要最小限の知見違反」など）は機密情報を扱う組織向けに作成されています。公開コミュニティでは、システム管理者に「スパム」、「ハラスメント」、「オフトピック」などの理由に置き換え、モデレーターをレビュー担当者に指名するよう依頼してください。メッセージの管理権限を持つだけではレビュー担当者にはなりません。

無視とブロック

メンバーはモデレーターを介さず、ユーザー名のメニューから自分自身を保護できます：

  • 無視する: そのユーザーからの通知を受け取らず、メッセージは折りたたまれ、ダイレクトメッセージはメッセージリクエストとして保留されます。
  • ブロック…：上記に加え、そのユーザーはあなたにメッセージを送信したり、あなたを含むグループメッセージを開始したりできません。そのユーザーには通知されません。

ユーザーは設定のプライバシーとセキュリティの下で、まだやり取りしていない人からのダイレクトメッセージを通常通り受け取る(全員から受け入れる)か、メッセージリクエストとして受け取る(最初に確認する)かを選択できます。これはすべてのコミュニティに適用するか、コミュニティごとに設定できます。これは個人の選択であり、コミュニティ管理者はメンバーのために設定できません。

モデレーターが知っておくべきこと：

  • ブロックしても、コミュニティのチャンネルへの投稿を妨げることはできません。ブロックしたユーザーのメッセージは、ブロックした本人の画面で折りたたまれるだけです。チャンネルでの悪質な行為に対処するには、モデレーターの対応が必要です。
  • メンバーは、モデレーターやコミュニティ管理者を無視またはブロックすることもできます。その場合、モデレーターからのダイレクトメッセージは通知なしのリクエストとして届くか、拒否される可能性があります。システム管理者とボットは常にメッセージを届けることができます。重要な警告を発する場合は、その人が読めるチャンネルに投稿するか、システム管理者に依頼してください。
  • システム管理者は、システムコンソール › サイト設定 › ユーザーとチーム の 無視、ブロック、メッセージリクエストを有効にする をオフにすることで、サーバー全体でこれらの機能を無効にできます。これは、同僚が常に連絡可能でなければならない職場環境向けです。

通話と音声チャンネル

通話のモデレーション権限を持つのは、ホスト、コミュニティ管理者、チャンネル管理者、システム管理者です。音声チャンネルでは、メッセージの管理、ユーザーの削除、または ロールの管理 権限を持つモデレーターもモデレーションを行うことができます。モデレーター自身が通話に参加している必要はありません。

参加者のタイルまたは行を右クリックして、メニューを開きます。

  • ミュート: 一度だけミュートします。本人は自分でミュート解除できます。
  • この通話でミュート: 許可するまでミュートされたままです。退出して再参加しても同様です。マイクにはモデレーターによりミュートされましたと表示されます。退出または通話終了後10分間ミュートは維持されるため、退出して再参加しても回避できません。ミュート解除を許可で解除されます。
  • ミュート解除を依頼: ミュートされている人に発言を依頼します。相手はリクエストを確認し、ミュート解除するか選択します。20秒後に同じ人に再度依頼できます。
  • 手を下ろす および 画面共有を停止。
  • 音声チャンネルから退出させるまたは通話から削除: 切断します。すぐに再参加できます。排除し続けるには、タイムアウトを使用してください。

通話でミュートできるのは、自分より階層が下のユーザーのみです。通話ホストは音声チャンネルのモデレーターより下、モデレーターはチャンネル管理者より下、チャンネル管理者はコミュニティ管理者より下、コミュニティ管理者はシステム管理者より下です。

ホストとシステム管理者は、ユーザーのメニューからホストにするを選択して、そのユーザーにホストの操作権限を与えることもできます。

すべてのユーザーの通話を終了する

通話を終了すると、自分だけが通話から退出します。すべてのユーザーの通話を終了するには、会話内の通話カードを使用します。通話から退出すると、参加するの横にすべてのユーザーの通話を終了が表示されます。これは通話を開始したユーザー（音声チャンネルを除く）と通話のモデレーターに対して表示されます。通話を終了で確認すると、まだ通話に参加しているすべてのユーザーが切断され、通話は終了します。

記録の管理

コミュニティにはモデレーションログはありません。タイムアウト、削除などの操作はサーバーの監査ログに記録されますが、これはシステム管理者のみが閲覧できます。非公開のモデレーター用チャンネルに、誰がタイムアウトまたは削除されたか、いつ、なぜそうしたかという記録を自分で残してください。

公開コミュニティ向けのベストプラクティス

  • ルールを文書化してください。 ロックされた「情報」カテゴリのチャンネルに配置し、バナーで強調し、オンボーディングのウェルカムテキストにも要約を記載してください。
  • 種類を「コミュニティ」に設定したままにしてください（チーム設定 › チャンネル）。これにより、チャンネルの管理権限を持つ管理者とモデレーターのみがチャンネルをアーカイブできます。
  • 新規参加者の実行可能な操作を制限します。デフォルトではメンバーがチャンネルの名前を変更したり、メンバーを管理したりできますが、システム管理者に、これらの操作ができないコミュニティ向けの権限スキームを依頼してください。
  • モデレーターロールを作成します。メッセージの管理とユーザーの削除を個別に表示することで、誰に依頼すればよいかを明確にします。レイアウトプリセットの「Moderators」ロールには両方が含まれています。モデレーター用の非公開チャンネルを用意してください。
  • 段階的にエスカレーションする：チャンネルでの注意、ダイレクトメッセージ、短いタイムアウト、長いタイムアウト、削除、そしてスパムや悪用に対するシステム管理者によるアカウント無効化。
  • 新規アカウントを監視する。モデレータービューでは、アカウントの作成日時と投稿数が確認できます。非公開コミュニティに切り替え、招待リンクを再生成することで、新規アカウントの大量流入をより容易に抑制できます。
  • レポート機能を有効化し、レビュアーとしてモデレーターを設定し、コミュニティに合った理由項目を用意してください。
  • サーバーのメンバー上限を確認する。コミュニティにはデフォルトで上限がありませんが、システム管理者が設定できます。上限が設定されている場合は、上限に達する前に引き上げてもらうよう依頼してください。
