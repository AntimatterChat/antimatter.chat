AI

AntimatterのAI機能は、ご自身で選択したモデルを使用します。クラウドプロバイダー、または自社ネットワーク上のサーバーです。モデルを設定するまで、どこにもデータは送信されません。このページでは、各機能、送信されるデータ、および無効にする方法について説明します。

AI機能

機能設定場所モデルの種類デフォルトで有効
AIエージェント：ボットとのチャット、スレッドやチャンネルの要約、コンポーザーでのサポートAgentsアプリ任意の大型言語モデル（LLM）サービスアプリは有効ですが、サービスを追加するまで何も実行されません
通話の文字起こしとライブ字幕Callsアプリ音声認識（OpenAI互換）いいえ
読み上げサーバーテキスト読み上げ（OpenAI互換）いいえ
チャンネルの自動翻訳サーバーLibreTranslate、OpenAI互換のLLM、またはAgentsサービスいいえ

「OpenAI互換」とは、OpenAIと同じHTTP APIを提供するサーバーを指します。自社で実行可能なほとんどのモデルサーバー（Ollama、vLLM、llama.cppのサーバー、Whisperやテキスト読み上げサーバーなど）や、多くのクラウドプロバイダーがこれに該当します。これらの機能にはライセンスは不要です。

AIエージェント

Agentsアプリ（ID: mattermost-ai）はデフォルトで有効です。設定には2つのステップが必要です：サービス（モデルプロバイダーへの接続）を追加し、その後エージェント（サービスを使用するボット）を作成します。

1. サービスの追加

システムコンソール › プラグイン › エージェントに移動し、AIサービスの下にあるAIサービスを追加をクリックします。サービスタイプを選択します。

  • OpenAI Compatible: 自分でホストするモデルサーバー、またはOpenAI互換APIを持つプロバイダー向け。API URL（例: http://ollama:11434/v1 または http://vllm.internal:8000/v1）を入力し、サーバーが必要とする場合のみAPIキーを入力します。サーバーがChat Completions APIのみをサポートする場合、Responses APIを使用をオフにします。
  • OpenAI、Anthropic、Google Gemini、Google Vertex AI、AWS Bedrock、Azure、Cohere、Mistral: ホスティングプロバイダー。それぞれAPIキーが必要です（Bedrock: AWSリージョンと認証情報またはIAMロール; Vertex AI: プロジェクト、リージョン、サービスアカウント; Azure: API URLも必要）。

次に、デフォルトモデル（プロバイダーがモデルを報告できる場合はリストから選択、そうでない場合は名前を入力）を設定します。プロバイダーが報告しない場合は、入力トークン制限と出力トークン制限も設定します。フォールバックサービスを設定すると、このサービスが失敗したときに引き継ぐことができます。保存してください。

サーバーはこれらのリクエストを自分自身で発行するため、APIに到達できる必要があります。同じcomposeプロジェクト内のモデルサーバー、ネットワーク内、またはインターネット上のサーバーが対象です。送信リクエストはHTTP_PROXYおよびHTTPS_PROXY変数を尊重します。

2. エージェントの作成

エージェントはWebアプリのエージェントページで作成します。プロダクトメニューから開くか、エージェントパネルのエージェントセレクターにある管理から開きます。アドレスはhttps://chat.example.com/plug/mattermost-ai/agentsです。各エージェントには表示名、エージェントユーザー名（メンションに使用するもの）、サービス、任意でモデル、カスタム指示、ビジョンを有効化（画像）およびツールを有効化のスイッチがあります。アクセスタブでは、使用可能なチャンネルと使用可能なユーザーを制限できます。システムコンソールのAI機能内のデフォルトボットでは、エージェントが選択されていない場合に使用されるエージェント（例：通話の要約）を選択します。

デフォルトでは、すべてのユーザーが設定したサービスを使用して自分のエージェントを作成できます。これを管理者に限定するには、システムコンソール › ユーザー管理 › 権限で、メンバーロールから自分のAIエージェントの管理権限を削除します。

エージェントアプリの任意の機能

  • 埋め込み検索（実験的、無効）：メッセージに対するセマンティック検索。pgvector拡張機能付きのPostgreSQLと埋め込みモデル（OpenAIまたはOpenAI互換）が必要です。すべてのメッセージ（非公開チャンネルやダイレクトメッセージを含む）を埋め込みモデルに送信します。
  • Web検索（無効）：エージェントがGoogle、Brave、または自分で運用しているSearXNGサーバーを通じてWebを検索できるようにします。
  • ネイティブツール：提供しているプロバイダーの場合、エージェントはプロバイダー独自のWeb検索（サポートされている場合、新規エージェントではデフォルトで有効）、Webフェッチ、コード実行を使用できます。これらはプロバイダー側で実行されます。エージェントごとに無効にできます。
  • Model Context Protocol (MCP)：信頼できるMCPサーバーにエージェントを接続し、追加のツールを使用します。
  • Debug: Trace Output（オフ、サーバーログ、またはOpenTelemetryエンドポイント）とEnable Token Usage Logging（トークン使用量をlogs/agents/token_usage.logに書き出します）。

音声認識：通話の文字起こしと字幕

通話は、OpenAI互換の/v1/audio/transcriptionsエンドポイントを提供する音声認識サーバーによって、ライブ字幕付きで文字起こしできます。設定は通話と音声を参照してください。文字起こしの要約をオンにすると、デフォルトのエージェントは各文字起こしの要約を投稿します。

テキスト読み上げ: 音声読み上げ

テキスト読み上げを有効にすると、すべてのメッセージのメニューに読み上げるが表示されます。サーバーはメッセージのテキストをテキスト読み上げAPIに送信し、オーディオを再生します。設定はシステムコンソール › 統合機能 › テキスト読み上げにあります。

設定項目キーと変数入力内容
メッセージを読み上げるTextToSpeechSettings.Enable, AM_TEXTTOSPEECHSETTINGS_ENABLEtrue (デフォルトはオフ)
APIベースURLTextToSpeechSettings.URL, AM_TEXTTOSPEECHSETTINGS_URL/v1を含むベースURLです。例: http://tts.internal:8000/v1。サーバーはその/audio/speechエンドポイントを呼び出します。
モデルTextToSpeechSettings.Model, AM_TEXTTOSPEECHSETTINGS_MODELAPIが使用するモデル名です。例: tts-1。必須です。
音声TextToSpeechSettings.Voice, AM_TEXTTOSPEECHSETTINGS_VOICEモデルのボイスのいずれか、またはデフォルトにする場合は空欄にします。
APIキーTextToSpeechSettings.APIKey, AM_TEXTTOSPEECHSETTINGS_APIKEYベアラートークンとして送信されます。APIが不要な場合は空欄にします。

送信前に、サーバーはコードブロック、リンク、絵文字コード、書式設定を削除し、最大4000文字まで保持します。MP3オーディオを要求し、直近64件の結果をメモリに保持するため、同じメッセージを2回読み上げても1回だけ送信されます。

自動翻訳

自動翻訳は、チャンネルのメッセージを各読み手の言語で表示します。システムコンソール › サイト設定 › 言語の自動翻訳セクションで設定します。

設定項目キーデフォルト値
有効化AutoTranslationSettings.Enableオフ
翻訳プロバイダーAutoTranslationSettings.Providerlibretranslate、openai (「OpenAI互換API」として表示) または agents (Agentsアプリのサービス)
許可された言語AutoTranslationSettings.TargetLanguagesen: メッセージを翻訳できる対象言語
翻訳タイムアウト(ms)AutoTranslationSettings.TimeoutMs5000
ダイレクトメッセージとグループメッセージでの自動翻訳を制限するAutoTranslationSettings.RestrictDMAndGMオフ

各プロバイダーには独自のフィールドがあります:

  • LibreTranslate: LibreTranslate APIエンドポイント と LibreTranslate APIキー (AutoTranslationSettings.LibreTranslate.URL、.APIKey)。LibreTranslateサーバーは自社ネットワーク内で実行できます。
  • OpenAI互換API: APIベースURL (/v1までを含む。サーバーはチャット補完エンドポイントを使用)、モデル と APIキー (AutoTranslationSettings.OpenAI.URL、.Model、.APIKey)。ローカルで実行される小型の翻訳モデルが効果的です。
  • エージェント: AIサービス、エージェントアプリで設定したサービスのいずれか。

有効化後、チャンネル管理者は設定（自動翻訳）でチャンネルの翻訳をオンにします。各メンバーはチャンネルメニュー（メッセージを翻訳）からオプトアウトできます。ダイレクトメッセージとグループメッセージでは、どのメンバーもオンにできますが、制限が設定されている場合は利用できません。翻訳されたメッセージには「…から翻訳」という表示と、元のメッセージへのリンクが表示されます。

テキストが送信される前に、コード、リンク、メンション、絵文字はプレースホルダーに置き換えられ、その後元に戻されます。

データがどこに送信されるか

機能送信されるもの送信先
エージェントリクエスト、対象のスレッドまたはチャンネルのメッセージ、エージェントの指示、ツールの結果、ビジョン機能がオンの場合の画像、質問したユーザーの名前、ユーザー名、役職、言語サービスのAPI
埋め込み検索すべてのメッセージ（ボットとシステムメッセージを除く）埋め込みAPI
ネイティブツールとWeb検索検索クエリ、取得するページ、コードプロバイダー、または選択した検索エンジン
通話の文字起こし有効な間、発言するすべての人の音声音声認識API
読み上げ読み上げ対象のメッセージのテキスト音声合成API
翻訳翻訳対象のチャンネル内のメッセージのテキストLibreTranslate、LLM API、またはエージェントサービス

すべてを自社ネットワーク内に保つには、各機能を自社で運用するサーバーに向けます。クラウドプロバイダーを使用する場合は、データ保持ポリシーを確認し、どの機能がメッセージを外部に送信しているかをユーザーに伝えましょう。

AI機能を無効にする

単一のスイッチはありません。各機能には個別のスイッチがあります。

  • エージェント: システムコンソール › プラグイン › プラグイン管理でエージェントアプリを無効にします。これにより、通話の要約とエージェントによる翻訳プロバイダーも削除されます。
  • 文字起こしと字幕: AM_CALLS_ENABLE_TRANSCRIPTIONS=false および AM_CALLS_ENABLE_LIVE_CAPTIONS=false（デフォルト値）。
  • 読み上げ: メッセージを読み上げるをオフにします（AM_TEXTTOSPEECHSETTINGS_ENABLE=false、デフォルト値）。
  • 翻訳: 自動翻訳をオフにします（AM_AUTOTRANSLATIONSETTINGS_ENABLE=false、デフォルト値）。

エージェントアプリを無効にしても、他の3つの機能はオフになりません。それらはそれぞれ独自のAPIを直接呼び出します。
