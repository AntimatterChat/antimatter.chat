Webhooks

Webhook נכנס מאפשר למערכת אחרת לשלוח הודעה לערוץ על ידי שליחת JSON לכתובת סודית. Webhook יוצא עושה את ההפך: הוא שולח לכתובת שלך הודעות המתחילות במילה טריגר, ומפרסם את התשובה שאתה שולח.

מקום לניהול Webhooks

פתח את האייקון שלך בפינה העליונה-ימנית, ואז אינטגרציות. עמודי האינטגרציות של הקהילה הנוכחית מציגים Webhooks נכנסים ו-Webhooks יוצאים. כל Webhook שייך לקהילה אחת.

By default, community admins and system admins can create webhooks. A system admin can give the right to other roles in the permission settings of the System Console. A system admin can also turn each kind off in System Console › Integrations › Integration Management: Enable Incoming Webhooks and Enable Outgoing Webhooks are both on by default.

יצירת Webhook נכנס

  1. ב-אינטגרציות, בחר Webhooks נכנסים, ואז הוספת Webhook נכנס.
  2. מלא כותרת ו-תיאור: הם מופיעים רק בעמודי האינטגרציות.
  3. בחר את הערוץ אליו ההודעות נשלחות כברירת מחדל. עבור ערוץ פרטי, עליך להיות חבר בו.
  4. סמן נעילה לערוץ זה אם השולחים לא יכולים לשלוח לערוצים אחרים.
  5. באופן אופציונלי, הגדר שם משתמש ו-URL ל-תמונת פרופיל להודעות שלו (ראה שם ואייקון).
  6. בחר שמירה. העתק את הכתובת המוצגת: https://chat.example.com/hooks/<key>.
הכתובת היא הסוד היחיד: כל מי שיש לו אותה יכול לשלוח לערוץ. אל תפרסם אותה במאגרי קוד ציבוריים, ומחק את ה-Webhook אם הוא נחשף.

עם API: POST /api/v4/hooks/incoming עם {"channel_id", "display_name", "description", "username", "icon_url", "channel_locked"}; השדה id בתגובה הוא המפתח. משורת הפקודה: amctl webhook create-incoming --channel <channel id> --user <user> --display-name "CI".

שליחת הודעה ל-Webhook נכנס

curl -X POST https://chat.example.com/hooks/xgh5ycrx1jf7mbs9w8z4c8e7ho \
  -H 'Content-Type: application/json' \
  -d '{"text": "Deploy of **api 2.4.0** finished :white_check_mark:"}'

השרת עונה 200 עם הגוף ok. הוא מקבל גם application/x-www-form-urlencoded עם ה-JSON בשדה payload, כפי שעושים Webhooks של Slack, כך שכלים שנועדו ל-Slack עובדים בדרך כלל ללא שינויים.

שדהמשמעות
textההודעה, ב־Markdown. חובה, אלא אם כן יש attachments. טקסט ארוך יותר מהמגבלה של השרת יחלק להודעות מרובות.
channelערוץ נוסף של קהילת ה־webhook, לפי שם (ops-alerts או #ops-alerts), או @username להודעה ישירה מהבעלים של ה־webhook. נדחה כאשר ה־webhook נעול לערוץ שלו.
username, icon_url, icon_emojiהשם והתמונה להצגה, כאשר השרת מאפשר החלפות.
attachmentsקבצים מצורפים להודעה, המוצגים ככרטיסים (למטה).
propsמאפיינים נוספים שמאוחסנים על ההודעה, לאפליקציות שקוראות אותם.
typeסוג פוסט מותאם אישית, כמו custom_poll, לאפליקציה שמציגה אותו. סוגים המתחילים ב־system_ נדחים.
root_idהמזהה של ההודעה הראשונה בשרשור, כדי להגיב בשרשור זה.
priorityעדיפות ההודעה, למשל {"priority": "urgent"}.
silenttrue שולח את ההודעה ללא התראות דחיפה.

הודעות המוצגות תחת שם שהוחלף נושאות תג בוט לצידו, כדי שאנשים יוכלו להבחין בינן ובחשבונות אמיתיים. הודעות webhook לעולם לא מפעילות webhooks יוצאים.

שם ואייקון

webhook פוסט בשם האדם שצורך, אלא אם כן השרת מאפשר החלפות. שתי הגדרות בקונסולת מערכת › אינטגרציות › ניהול אינטגרציות, שתיהן כבויות כברירת מחדל, משנות זאת:

  • Enable integrations to override usernames (ServiceSettings.EnablePostUsernameOverride): the webhook's Username or the request's username is shown instead; without either, the name is webhook.
  • הרשאה לאינטגרציות להחליף את אייקון תמונת הפרופיל (ServiceSettings.EnablePostIconOverride): תמונת פרופיל של ה־Webhook, או icon_url או icon_emoji של הבקשה, מוצגים.

ערך מהבקשה מנצח על הערך שמאוחסן על ה־webhook.

קבצים מצורפים

קבצים מצורפים מוסיפים תוכן מובנה מתחת לטקסט. הם עוקבים אחר פורמט ההודעות של Slack:

{
  "text": "Build failed on `main`",
  "attachments": [{
    "fallback": "main #1902 failed",
    "color": "#d24b4e",
    "author_name": "GitHub Actions",
    "author_icon": "https://chat.example.com/static/ci.png",
    "title": "main #1902 failed",
    "title_link": "https://ci.example.com/runs/1902",
    "text": "Commit `0f4d8e2` by Jonas Weber",
    "fields": [
      {"title": "Branch", "value": "zephyr-3.7", "short": true},
      {"title": "Duration", "value": "3m 40s", "short": true}
    ],
    "footer": "Lumen CI",
    "ts": 1760000000
  }]
}
שדהמשמעות
fallbackטקסט רגיל למקומות שאינם יכולים להציג את הכרטיס, כמו התראות.
colorסרגל הצבע: צבע hex, או good, warning, danger.
pretextטקסט מעל הכרטיס.
author_name, author_link, author_iconשורת כותרת קטנה.
title, title_linkכותרת הכרטיס, אופציונלית קישור.
textגוף הכרטיס, ב־Markdown.
fieldsרשימה של {"title", "value", "short"}; שדות short מוצבים זה לצד זה.
image_url, thumb_urlתמונה גדולה למטה, או קטנה בצד.
footer, footer_icon, tsשורת כותרת תחתונה וזמן (שניות Unix).
actionsכפתורים ותפריטים: ראו הודעות אינטראקטיביות.

כרטיסים: שלבים ותרשימים

Antimatter מוסיף שני שדות לקבצים מצורפים, שמוצגים בממשק ברירת המחדל:

  • stages: שלבי צינור כ"גלוליות", עד 20. כל אחד הוא {"name", "status"}, עם סטטוס של passed, failed, running, pending, skipped או canceled.
  • chart: גרף קווים קטן של ערכים אחרונים, {"values": [2 to 200 numbers], "threshold": number, "label": "…"}. הסף מוצג כקו מקווקו, כמגבלה להתראה.
{
  "attachments": [{
    "color": "danger",
    "title": "main #1902 failed",
    "stages": [
      {"name": "build", "status": "failed"},
      {"name": "unit", "status": "skipped"},
      {"name": "publish", "status": "skipped"}
    ]
  }, {
    "color": "warning",
    "title": "API latency above 400 ms",
    "chart": {"values": [210, 230, 260, 390, 450, 470], "threshold": 400, "label": "p95 latency, ms"}
  }]
}

הממשק הקלאסי וכלי אחרים מתעלמים משני השדות הללו, לכן יש להכניס את המידע החיוני גם לtext או לfields.

הוספת Webhook יוצא

Webhook יוצא עוקב אחר הערוצים הציבוריים של קהילה. כאשר המילה הראשונה בהודעה תואמת אחת ממילות הטריגר שלו, Antimatter שולח את ההודעה לכתובת שלך.

  1. באינטגרציות, בחרו בWebhooks יוצאים, ואז בהוספת Webhook יוצא.
  2. מלאו את הכותרת ואת התיאור.
  3. בחרו את סוג התוכן של הבקשה: application/x-www-form-urlencoded או application/json.
  4. בחרו ערוץ, הזינו מילות טריגר (מילה בשורה), או את שניהם. עם ערוץ בלבד וללא מילות טריגר, כל ההודעות בערוץ נשלחות. עם שניהם, ההודעה חייבת להתאים לשניהם.
  5. מתחת לטריגר כאשר, בחרו בהמילה הראשונה תואמת במדויק מילה מפתח או בהמילה הראשונה מתחילה במילה מפתח.
  6. הזינו את כתובות קריאה חוזרת (שורה לכל כתובת). כל כתובת מקבלת את כל ההודעות המתאימות.
  7. אופציונלית, הגדירו את שם המשתמש ואת תמונת הפרופיל שיושמשו לתשובות.
  8. בחרו בשמירה והעתיקו את האסימון שמוצג. השירות שלך משתמש בו כדי לוודא שהבקשות מגיעות מהשרת שלך.

באמצעות API: POST /api/v4/hooks/outgoing עם {"team_id", "channel_id", "trigger_words", "trigger_when", "callback_urls", "content_type", "display_name"} (trigger_when: 0 להתאמה מדויקת, 1 ל"מתחיל ב").

אם השירות שלך נמצא ברשת פרטית, מנהל מערכת חייב לאפשר את הכתובת שלו באפשרות חיבורים פנימיים לא אמורים אל (ServiceSettings.AllowedUntrustedInternalConnections). אחרת, השרת לא יקרא כתובות פרטיות.

הבקשה היוצאת

Antimatter שולח בקשת POST עם השדות הבאים, כ-JSON או כטופס מקודד, בהתאם לסוג התוכן:

{
  "token": "6kd1ofo5ojr5zgu5ipfipybgnc",
  "team_id": "…",
  "team_domain": "lumen-labs",
  "channel_id": "…",
  "channel_name": "ops-alerts",
  "timestamp": 1760010000000,
  "user_id": "…",
  "user_name": "priya",
  "post_id": "…",
  "text": "deploy api 2.4.0",
  "trigger_word": "deploy",
  "file_ids": ""
}

יש להשוות את token עם ה-token של ה-Webhook לפני כל פעולה. בגרסה הקודדת-טופוגרפית, timestamp מבוטא בשניות ולא במילי-שניות. השרת ממתינה לתשובה עד לתום הזמן המוגדר בתום זמן לבקשות אינטגרציה (30 שניות כברירת מחדל, ServiceSettings.OutgoingIntegrationRequestsTimeout).

תשובה ל-Webhook יוצא

כדי לפרסם תשובה, יש לענות ב-JSON. כדי לא לפרסם כלום, יש לענות בגוף ריק.

{
  "text": "Deploying **api 2.4.0** to staging…",
  "response_type": "comment",
  "username": "deploy-bot",
  "icon_url": "https://chat.example.com/static/deploy.png"
}
  • text ו-attachments: התשובה. ללא אחד מהם, לא יפורסם כלום.
  • response_type: comment מפרסם את התשובה בשרשור של ההודעה שהפעילה את ה-Webhook; אחרת, היא מפורסמת בערוץ.
  • username, icon_url: מוצגים כאשר השרת מאפשר החלפה; אחרת, נעשה שימוש בערכים של ה-Webhook עצמו.
  • props, type, priority: כפי שמוגדר עבור Webhooks נכנסים.

התשובה מפורסמת בשם יוצר ה-Webhook, תחת השם המוחלף אם קיים. לכל תוכן שאינו תשובה קצרה, יש לענות מיד ולפרסם מאוחר יותר באמצעות Webhook נכנס או ה-API.

כאשר Webhook אינו עובד

  • 501 מכתובת ה-Webhook: Webhooks נכנסים כבויים על השרת.
  • 400 "Failed to decode the payload…": ה-JSON אינו תקין, או ששדה הטופס אינו נקרא payload. "No text specified." פירושו שהבקשה אינה מכילה לא text ולא attachments.
  • 403: ה-Webhook נעול לערוץ אחר, או שהבעלים שלו אינו יכול עוד לקרוא את הערוץ.
  • Webhook יוצא nie מופעל מעולם: הערוץ פרטי, המילה המפעילה אינה המילה הראשונה, או שההודעה הגיעה מ-Webhook.
  • יומנים: כאשר הפעלת ניפוי Webhook מופעלת (LogSettings.EnableWebhookDebugging), ורמת היומן מוגדרת על DEBUG, השרת רושם ביומן את תוכן הבקשות הנכנסות שהתקלקלו. קריאות יוצאות שהתקלקלו מרושמות כ-Outgoing Webhook POST failed.
