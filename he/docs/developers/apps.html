כתיבת אפליקציות (תוספים)

אפליקציות מוסיפות יכולות ל-Antimatter מבפנים: חלק שרת בשפת Go שמתחבר לשרת, וחלק אפליקציית Web ב-React שמוסיף תפריטים, פאנלים, סוגי הודעות ועמודים. עמוד זה מציג כיצד אפליקציה מונחת, תוך שימוש באפליקציית סקרים (Polls) המצורפת כדוגמה, ומה משתנה בממשק Fusion של Antimatter.

כיצד אפליקציה עובדת

  • חלק השרת הוא תוכנית בשפת Go. השרת מריץ אותו כתהליך נפרד ומתקשר איתו באמצעות RPC: הוא קורא להוקים של האפליקציה (הודעה עומדת להתפרסם, פקודה הורצה…), והאפליקציה קוראת לplugin API של השרת (יצירת פוסט, קריאת משתמש, אחסון נתונים…). היא יכולה גם לשרת נתיבי HTTP תחת /plugins/<app id>/.
  • חלק אפליקציית ה-Web הוא חבילת JavaScript שנטענת בדפדפן יחד עם אפליקציית ה-Web. היא רשומה בregistry: רכיבי React וקריאות חזרה (callbacks) – כפתור בתפריט, פאנל, דרך לצייר סוג הודעה.
  • כל חלק מהחלקים הוא אופציונלי. אפליקציה מותקנת כחבילת .tar.gz, ומנהלי מערכת מאפשרים, מעכבים ומגדירים אותה.
חלק השרת רץ עם גישה מלאה לנתוני השרת. יש להתייחס לאפליקציה כאל קוד שמועלה לשרת.

Antimatter מריץ אפליקציות שכתובות עבור Mattermost, ולהפך, כל עוד האפליקציה משתמשת רק בהוקים שיש לשני הצדדים. ראו הוקים שיש רק ל-Antimatter.

מבנה החבילה

אין תבנית התחלה נפרדת: יש להתחיל מאפליקציה מצורפת קטנה כמו antimatter-plugin-polls או antimatter-plugin-todo, ולשנות את המזהה (ID) והקוד שלה. אפליקציית Polls מונחת כך:

antimatter-plugin-polls/
├── plugin.json            the manifest
├── Makefile               build, test, bundle, deploy
├── build/                 the manifest and pluginctl helper tools (Go), setup.mk
├── assets/icon.svg        files shipped with the bundle
├── go.mod
├── server/
│   ├── main.go            plugin.ClientMain(&Plugin{})
│   ├── plugin.go          the Plugin type, OnActivate, ServeHTTP
│   ├── manifest.go        generated from plugin.json
│   ├── api.go, command.go, hooks.go, store.go …
│   └── dist/              compiled binaries, one per platform
└── webapp/
    ├── package.json, webpack.config.js, tsconfig.json
    ├── i18n/              en.json and one file per language
    ├── src/index.tsx      registers the app with the web app
    ├── src/manifest.ts    generated from plugin.json
    ├── src/translations.ts
    └── dist/main.js       the bundle

אופציונלי: תיקיית public/, שמוגשת כפי שהיא בנתיב /plugins/<app id>/public/.

  • id: ייחודי וקבוע; שם דומיין הפוך הוא נפוץ. הוא קובע את שם הנתיבים, ההגדרות המאוחסנות ואירועי WebSocket.
  • version: גרסה סמנטית. האפליקציות המצורפות משמיטות את השדה הזה מ-plugin.json; כלי הבנייה שלהן לוקח אותו מהתגית v* האחרונה ב-git.
  • min_server_version: Antimatter מדווח 12.0.0.
  • settings_schema: עמוד ההגדרות של האפליקציה בקונסולת המערכת (ראו הגדרות).

make apply מועיל את המניפסט לserver/manifest.go ולwebapp/src/manifest.ts; make manifest-check מאמת אותו.

חלק השרת

חלק השרת יוצא את אותו מודול Go כמו אפליקציות Mattermost, github.com/mattermost/mattermost/server/public, מהפרוקסי של מודולי Go. הmain שלו פשוט מריץ את האפליקציה:

package main

import "github.com/mattermost/mattermost/server/public/plugin"

func main() {
	plugin.ClientMain(&Plugin{})
}

הטיפוס Plugin משלב את plugin.MattermostPlugin, שמעניק לו p.API, ומממש את ה- hooks הנדרשים:

type Plugin struct {
	plugin.MattermostPlugin
	router *mux.Router
}

func (p *Plugin) OnActivate() error {
	p.router = p.newRouter()
	return p.API.RegisterCommand(&model.Command{
		Trigger:          "weather",
		AutoComplete:     true,
		AutoCompleteDesc: "Show the forecast",
		AutoCompleteHint: "[city]",
	})
}

func (p *Plugin) ExecuteCommand(c *plugin.Context, args *model.CommandArgs) (*model.CommandResponse, *model.AppError) {
	city := strings.TrimSpace(strings.TrimPrefix(args.Command, "/weather"))
	return &model.CommandResponse{
		ResponseType: model.CommandResponseTypeEphemeral,
		Text:         "Forecast for " + city + ": sunny",
	}, nil
}

func (p *Plugin) ServeHTTP(c *plugin.Context, w http.ResponseWriter, r *http.Request) {
	p.router.ServeHTTP(w, r)
}

hooks נפוצים

OnActivate, OnDeactivateכשהאפליקציה מופעלת או נכבית, וכשהשרת נדלק ונכבה. יש להרשיל פקודות ובוטים בOnActivate.

ExecuteCommandפקודה שהאפליקציה הרשילה הורצה.
MessageWillBePosted, MessageWillBeUpdatedלפני שהודעה נשמרת: להחזיר פוסט שונה, או סיבה לדחות אותו.

הרשימה המלאה, עם החתימות המדויקות, נמצאת בserver/public/plugin/hooks.go; ה-API נמצא בserver/public/plugin/api.go. חבילת pluginapi (server/public/pluginapi) עוטפת את ה-API בעזרים נוחים יותר.

קריאות API שימושיות

  • CreatePost, UpdatePost, SendEphemeralPost: לפרסם כבוט של האפליקציה או כמשתמש.
  • EnsureBotUser(&model.Bot{Username, DisplayName}): ליצור את הבוט של האפליקציה פעם אחת ולקבל את המזהה שלו.
  • PublishWebSocketEvent("poll_updated", payload, &model.WebsocketBroadcast{ChannelId: id}): לשלוח אירוע לאפליקציית הווב. הוא מגיע כcustom_<app id>_poll_updated.
  • OpenInteractiveDialog: לפתוח דיאלוג.
  • LogInfo, LogError ושות': לכתוב ליומן השרת, עם תגית המזהה של האפליקציה.
  • GetUser, GetChannel, HasPermissionToChannel: לבדוק מי יכול לעשות מה לפני שפועלים בשם משתמש.

האפליקציה רצה על כל שרת בקלאסטר. יש לשמור את המצב במאגר מפתח־ערך או במסד הנתונים, ולא רק בזיכרון.

שמירת נתונים

לכל אפליקציה יש מאגר מפתח־ערך משלה במסד הנתונים של השרת:

  • KVSet(key, value), KVGet(key), KVDelete(key): הערכים הם בתים, בדרך כלל JSON. המפתחות הם עד 150 תווים.
  • KVSetWithExpiry(key, value, seconds): הערך נעלם לאחר הזמן שצוין.
  • KVCompareAndSet(key, old, new) ו־KVSetWithOptions עם Atomic: עדכונים בטוחים כאשר מספר בקשות או שרתים כותבים את אותו מפתח. Polls שומרת כל קול כך ומנסה שוב במקרה של סתירה.
  • KVList(page, perPage): המפתחות, עמוד אחרי עמוד.

חלק האפליקציה הוובית

הבאנדל מרשם מחלקה באמצעות window.registerPlugin. ה־initialize שלה מקבל את הרשומה (registry) ומאגר Redux:

import manifest from './manifest';

class Plugin {
    initialize(registry, store) {
        registry.registerTranslations((locale) => translationsFor(locale));
        registry.registerPostTypeComponent('custom_poll', PollPost);
        registry.registerWebSocketEventHandler(`custom_${manifest.id}_poll_updated`, (msg) => {
            store.dispatch(pollUpdated(JSON.parse(msg.data.poll)));
        });
        registry.registerReconnectHandler(() => store.dispatch(reloadPolls()));
    }
}

window.registerPlugin(manifest.id, new Plugin());
  • ספריות משותפות. האפליקציה הוובית מספקת React, ReactDOM, Redux, React Redux ו־React Intl: יש לרשום אותן כ־externals ב־webpack (React, ReactDOM, Redux, ReactRedux, ReactIntl) במקום להכליל עותקים משלכם. ראו את webpack.config.js של Polls.
  • קריאה לחלק השרת שלכם. יש לבצע Fetch ל־${window.basename}/plugins/<app id>/… עם האפשרויות מ־Client4.getOptions() (מ־mattermost-redux/client): הן נושאות את הכותרות (headers) שהשרת זקוק לקבלת בקשה מהדפדפן.
  • המצב שלכם. registerReducer מוסיף reducer, הנשמר תחת state['plugins-<app id>'].
  • טיפוסים. שיטות הרשומה הנוספות של Antimatter אינן נכללות בטיפוסים שפורסמו עבור Mattermost: Polls מרשמה את הרשומה שהיא משתמשת בה ב־webapp/src/types/host.ts.

שיטות הרשומה ופרמטרים שלהן מודרכות בקוד, ב־webapp/fusion/src/plugins/registry.ts (Fusion) וב־webapp/channels/src/plugins/registry.ts (קלאסי).

תמיכה בממשק Fusion

ל־Antimatter יש שני ממשקי ווב: Fusion, הממשק ברירת המחדל, והממשק הקלאסי. שניהם טוענים את אותם באנדלים של האפליקציות ומשתמשים באותה רשומה, אך Fusion מצייר רבות מהדברים בעצמו ומציב רכיבי תוספים בדרך משלו. יש לבדוק את האפליקציה בשני הממשקים.

זיהוי הממשק

לפני שכל אפליקציה נטענת, שני הממשקים מגדירים את window.antimatterWebUI ל־'fusion' או 'classic', ואת אותה ערך על האלמנט השורש של הדף כ־data-am-web-ui. ב־Mattermost, שניהם אינם מוגדרים.

export function isFusionUI(): boolean {
    return window.antimatterWebUI === 'fusion' || document.documentElement.dataset.amWebUi === 'fusion';
}

האפליקציות המובנות משתמשות בכך כדי להציג את עצמן בצורה שונה. סקרים מציגים את כרטיסי הסקר ואת חלון היצירה בסגנון של Fusion, ופותחים חלון ייעודי עבור /poll בתוך Fusion. שיחות וערוצי קול מוותרים על רכיבי סרגל הצד וההודעות הזמניות (toasts) ש-Fusion מחליפה בממשק השיחה שלה. אפליקציית הסוכנים מציגה את פעולות ה-AI שלה בתת-תפריט של תפריט ההודעה, במקום בסרגל הפעולות המופיע בריחוף. מחלקות ה-CSS של Fusion (המתחילות ב-am-) ושרת החלונות שלה (האלמנט am-layer) הם מה שהאפליקציות משתמשות בו כדי להתאים את עצמן לממשק; אלו אינם API מתועד ויציב.

registerProductעמודים מלאים בכתובת האפליקציה, המפורטים תחת מוצרים באודות Antimatter. עמודי המוצרים שומרים על מסגרת העמוד הקלאסית.
registerRootComponent, registerGlobalComponent, הוקים כמו registerMessageWillBePostedHook, registerSlashCommandWillBePostedHook, registerMessageWillFormatHook, registerFilesWillUploadHook, registerDesktopNotificationHook, registerWebSocketEventHandler, registerReducer, registerTranslationsעובדים כפי שעושים בממשק הקלאסי.
registerAdminConsolePlugin, registerAdminConsoleCustomSettingקונסולת מערכת, שהיא הקלאסית בשני הממשקים.

מה ש-Fusion לא מציג או לא מריץ

  • registerPostDropdownMenuComponent (רכיב בתפריט ההודעה), registerPostCardTypeComponent (כרטיס של פוסט בפאנל הימני) ו-registerProductSwitcherMenuItem אינם מוצגים בתצוגות הראשיות של Fusion. השתמשו בregisterPostDropdownMenuAction במקום הראשון.
  • registerMessageWillBeUpdatedHook אינו מורץ כאשר הודעה נערכת ב-Fusion. בדקו עריכות על השרת באמצעות ההוק MessageWillBeUpdated במקום.
  • registerActionAfterChannelCreation מורץ רק מתיבת יצירת הערוץ הקלאסית, ש-Fusion פותח מאפשרויות נוספות… בתיבת היצירת ערוץ שלו.
  • רכיבי סרגל האפליקציה מוצגים ללא קשר לsupportedProductIds שלהם.
  • נתיבים מregisterNeedsTeamRoute ו-registerCustomRoute שומרים על מסגרת העמוד הקלאסית, כמו מוצרים.

הוקים שיש רק ב-Antimatter

שיטות רישום אלו אינן קיימות ב-Mattermost. ודאו ששיטה קיימת לפני שאתם קוראים אליה, כדי שהאפליקציה תעבוד שם גם:

if (typeof registry.registerComposerMenuItem === 'function') {
    registry.registerComposerMenuItem({
        text: 'Create a poll',
        icon: <i className='icon icon-chart-bar'/>,
        fusionIcon: 'poll',
        action: ({channelId, rootId}) => openPollCreation(channelId, rootId),
    });
} else {
    registry.registerChannelHeaderButtonAction(icon, (channel) => openPollCreation(channel.id), 'Create a poll', 'Create a poll');
}
שיטהמה שהיא מוסיפה
registerComposerMenuItem({text, icon, fusionIcon, action, shouldRender})פריס בתפריט + של תיבת ההודעה, בשני הממשקים. action מקבל {channelId, rootId}.
registerEmojiPickerTab({id, label, icon, fusionIcon, order, component, shouldRender, replacesGifPicker})לשונית במבחר האמוג'י של תיבת ההודעה, כגון GIF או מדבקות. ב-Fusion, לשוניות עם order נמוך מ-10 מופיעות לפני לשונית האמוג'י. הרכיב מקבל channelId, rootId, filter, onFilterChange, onSelectDone, insertText ו-isFusion.
registerChannelViewPanel({matcher, component})פאנל בין כותרת הערוץ להודעות, עבור הערוצים שmatcher(state, channel) בוחר. הוא יכול להסתיר את ההודעות ואת עורך ההודעה (setMessagesVisible), כפי שעושים ערוצי קול.
registerSidebarChannelFooterComponent(component)שורה מתחת לערוץ בסרגל הצד, כגון האנשים בשיחה שלו. היא מקבלת את channel.
registerIntegrationsOption({title, description, fusionIcon, action, shouldRender})Fusion בלבד: פריט בדפי אינטגרציות, ליד האמוג'י המותאמים אישית. אפליקציית GIFs מוסיפה שם את ה-GIFs והמדבקות המותאמים אישית.

fusionIcon שם סמל במערכת הסמלים של Fusion (למשל poll, sticker, calendar או image; ראו webapp/fusion/src/fusion/components/icon). Fusion מציגה אותו במקום icon, כך שהפריט תואם את האחרים.

הגדרות

settings_schema בplugin.json מתאר את דף האפליקציה בקונסולת מערכת › תוספים:

"settings_schema": {
  "header": "Forecasts come from the weather service below.",
  "settings": [
    {"key": "ServiceURL", "display_name": "Service URL", "type": "text", "default": "https://api.example.com"},
    {"key": "Units", "display_name": "Units", "type": "dropdown", "default": "metric",
     "options": [{"display_name": "Celsius", "value": "metric"}, {"display_name": "Fahrenheit", "value": "imperial"}]},
    {"key": "EnableAlerts", "display_name": "Severe weather alerts", "type": "bool", "default": false,
     "help_text": "Post alerts in the channels that follow a city."}
  ]
}

סוגי הגדרות: bool, text, longtext, number, dropdown, radio, generated (סוד אקראי), username, ו-custom (מוציג על ידי רכיב שחלק האפליקציה הוובי רשם עם registerAdminConsoleCustomSetting). ניתן לקבץ הגדרות בsections.

חלק השרת קורא אותם ל-struct ששדותיו תואמים למפתחות:

type configuration struct {
	ServiceURL   string
	Units        string
	EnableAlerts bool
}

func (p *Plugin) OnConfigurationChange() error {
	var cfg configuration
	if err := p.API.LoadPluginConfiguration(&cfg); err != nil {
		return err
	}
	p.setConfiguration(&cfg)
	return nil
}

מנהלים יכולים גם להגדיר אותם בקונפיגורציה, תחת PluginSettings.Plugins.<app id>, עם מפתחות באותיות קטנות (ראו מדריך המנהלים).

תרגומים

Antimatter מתורגם ל-37 שפות, וכן האפליקציות המצורפות. חלק האפליקציה הוובי עושה זאת כך:

  1. כתבו כל מחרוזת עם React Intl, עם מזהה וטקסט באנגלית: <FormattedMessage id='polls.create' defaultMessage='Create a poll'/> או defineMessages. הוסיפו קידומת של שם האפליקציה למזהים.
  2. חלצו את המחרוזות באנגלית לwebapp/i18n/en.json (האפליקציות המצורפות משתמשות בformatjs extract).
  3. הוסיפו קובץ אחד לכל שפה לצידו, עם אותם מזהים: fr.json, de.json, pt-BR.json, zh-CN.json…
  4. מעבירים אותם לאפליקציית הווב, ששואלת את שפת המשתמש: 
    import fr from '../i18n/fr.json';
import ptBR from '../i18n/pt-BR.json';

const catalogs = {fr, 'pt-BR': ptBR};

export function translationsFor(locale) {
    return catalogs[locale] || catalogs[locale.split('-')[0]] || {};
}

registry.registerTranslations(translationsFor);

מחרוזת חסרה חוזרת לערך ברירת המחדל שלה באנגלית, defaultMessage. עבור מחרוזות ששולח חלק השרת (תשובות פקודות, הודעות בוטים), חבילת pluginapi/i18n טוענת קבצי תרגום שמשוחררים בחבילה (למשל assets/i18n) ומספקת מקומליזר בשפת כל משתמש.

בנייה, התקנה וניפוי תקלות

נדרשים Go ו־Node.js (הגרסה המצוינת ב־.nvmrc של האפליקציה). תוך תיקיית האפליקציה:

פקודהמה היא עושה
make distבונה את חלק השרת לכל הפלטפורמות ואת חלק אפליקציית הווב, וכותב את החבילה ל־dist/<app id>-<version>.tar.gz.
make testמריץ את מבחני Go ו־JavaScript.
make check-styleמבצע בדיקת קוד (golangci-lint, ESLint) ובדיקת סוגי TypeScript.
make deployבונה, ואז מתקין ומפעיל את החבילה על השרת.
make watch, make deploy-from-watchהראשונה בונה מחדש את חלק אפליקציית הווב בכל שמירה; השנייה אורזת את מה שבנייה ומתקינה אותו על השרת.
make enable, make disable, make resetמפעיל, מכבה או מאתח מחדש את האפליקציה על השרת.
make logs, make logs-watchמציג את שורות האפליקציה ביומן השרת.
make attachמחבר את מחליף Delve לחלק השרת הפועל (יש לבנות תחילה עם AM_DEBUG=1).

make deploy ופקודות השרת האחרות משתמשות בסקטת מצב מקומי אם מוצאים אחת (/var/tmp/antimatter_local.socket, או AM_LOCALSOCKETPATH): יש להריץ אותן על מכונת השרת עם מצב מקומי פעיל. אחרת, הן נכנסות לשרת שנקבע על ידי MM_SERVICESETTINGS_SITEURL באמצעות AM_ADMIN_TOKEN, או AM_ADMIN_USERNAME ו־AM_ADMIN_PASSWORD. כלי הבנייה עדיין אינם קוראים שם AM_ כתכתובת האתר.

התקנת חבילה ידנית

  • מנהל מערכת מאפשר העלאות עם AM_PLUGINSETTINGS_ENABLEUPLOADS=true (כבוי כברירת מחדל; אין מתג בקונסולת מערכת).
  • לאחר מכן קונסולת מערכת › תוספים › ניהול פלאגינים › העלאת פלאגין, או amctl plugin add weather.tar.gz ולאחריו amctl plugin enable com.example.weather.
  • אם על השרת מופעלת האפשרות דרישה לחתימת תוסף, הוא מקבל רק חבילות שחתומות במפתח שהוא מאמין בו; ראו התקנת אפליקציות נוספות.
לחזרות מהירות על שרת פיתוח, יש להגדיר AM_SERVICESETTINGS_ENABLEDEVELOPER=true על השרת: אז שגיאות נושאות את הפרטים שלהן. קבצי Makefile של האפליקציות המצורפות בונים את חלק השרת לפלטפורמה שלך בלבד כאשר MM_SERVICESETTINGS_ENABLEDEVELOPER מוגדר ב־shell שלך.
