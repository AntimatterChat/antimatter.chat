La API REST

Todo lo que hacen las aplicaciones de Antimatter pasa por la misma API HTTP, por lo que tus scripts también pueden hacerlo. Esta página explica cómo autenticarse, los recursos que más usarás, cómo son las respuestas y los errores, y cómo seguir los eventos en vivo a través de WebSocket.

Básicos

  • URL base: https://chat.example.com/api/v4. Todos los puntos finales siguientes son relativos a esta.
  • Formato: JSON de entrada y salida, excepto las subidas de archivos (multipart). Envía Content-Type: application/json.
  • Identificadores: cada objeto tiene un id de 26 caracteres. Los tiempos son milisegundos desde la época Unix (create_at, update_at, delete_at; 0 significa «no eliminado»).
  • Las comunidades son equipos: la API los llama teams, con un team_id.
  • Tú mismo: donde quiera que una ruta acepte un user_id, me significa el usuario autenticado, como en GET /users/me.

La lista completa de puntos de conexión se encuentra en el código del servidor: las rutas se declaran en server/channels/api4/*.go y los tipos en server/public/model. La descripción OpenAPI en la carpeta api/v4/source del repositorio cubre los puntos de conexión heredados de Mattermost y algunas de las adiciones de Antimatter: mover hilos, conexiones de modelos y acciones de mensajes. El resto solo está en el código.

Autenticación

Cada solicitud, excepto el inicio de sesión y algunos puntos finales públicos, requiere un token en la cabecera Authorization:

curl -H "Authorization: Bearer $TOKEN" https://chat.example.com/api/v4/users/me

Se aceptan tres tipos de token allí: tokens de acceso personal, tokens de sesión y tokens de acceso OAuth. También se acepta Authorization: Token …. Los tokens en la cadena de consulta (?access_token=) solo se aceptan para tokens de acceso OAuth.

Tokens de acceso personal (recomendados para scripts)

Un token de acceso personal actúa como tú, no caduca a menos que le asignes una fecha de expiración, y puede revocarse en cualquier momento. Los tokens de acceso personal están desactivados por defecto:

  1. Un administrador del sistema habilita Habilitar Tokens de Acceso Personales en Consola de sistema › Integraciones › Gestión de Integraciones (ServiceSettings.EnableUserAccessTokens, AM_SERVICESETTINGS_ENABLEUSERACCESSTOKENS).
  2. Para cada persona que pueda crear tokens, un administrador del sistema abre Consola de sistema › Gestión de Usuarios › Usuarios, elige Gestionar roles en el menú de la persona y marca Permitir que esta cuenta genere tokens de acceso personal. Los administradores del sistema siempre pueden crearlos.
  3. La persona abre su avatar en la parte superior derecha y luego Perfil y configuración › Seguridad. Bajo Tokens de Acceso Personales, describe para qué se usará el token y elige Crear Token. El token se muestra una sola vez: cópialo.

Con la API: POST /users/{user_id}/tokens con {"description": "backup script", "expires_at": 0} (expires_at en milisegundos; 0 para ninguno). El campo token de la respuesta es el secreto; su id es lo que se usa para revocarlo (POST /users/tokens/revoke con {"token_id": "…"}). Desde la línea de comandos: amctl token generate <user> <description>.

Un administrador del sistema puede limitar la vida útil de los tokens con Vida útil máxima de token de acceso personal (días) en la misma página de la Consola de sistema.

Tokens de sesión

Iniciar sesión con una contraseña devuelve un token de sesión en la cabecera de respuesta Token, el mismo tipo de sesión que usan las aplicaciones:

curl -i -X POST https://chat.example.com/api/v4/users/login \
  -H 'Content-Type: application/json' \
  -d '{"login_id": "maya", "password": "…"}'

Añade "token": "123456" para una cuenta con autenticación multifactor. Las sesiones expiran según la configuración de sesiones del servidor, y el punto de entrada de inicio de sesión tiene un límite de frecuencia (5 solicitudes por segundo). POST /users/logout termina la sesión.

Los navegadores se autentican con una cookie. Una solicitud autenticada por la cookie también debe enviar la cabecera X-CSRF-Token para cualquier cosa que no sea GET; un token en la cabecera Authorization no necesita cabecera CSRF.

Aplicaciones OAuth 2.0

Para permitir que las personas inicien sesión en tu aplicación con su cuenta de Antimatter, registra una aplicación OAuth 2.0. Antimatter será entonces el proveedor OAuth:

  1. Habilitar el Proveedor de Servicios de OAuth 2.0 debe estar activado (Consola de sistema › Integraciones › Gestión de Integraciones, ServiceSettings.EnableOAuthServiceProvider, activado por defecto).
  2. Alguien con el derecho de gestionar aplicaciones OAuth (los administradores del sistema por defecto) abre su avatar, luego Integraciones › Aplicaciones OAuth 2.0, y añade la aplicación con sus URL de callback. Obtiene un ID de cliente y un secreto de cliente.
  3. Tu aplicación envía a las personas a https://chat.example.com/oauth/authorize con response_type=code, client_id, redirect_uri y state. Se admite PKCE con code_challenge_method=S256.
  4. Intercambia el código en POST https://chat.example.com/oauth/access_token (grant_type=authorization_code, y luego refresh_token para renovarlo) y llama a la API con Authorization: Bearer <access token>.

Las personas ven las aplicaciones que han autorizado en Perfil y configuración › Seguridad › Aplicaciones que has autorizado.

Publicar un mensaje

curl -X POST https://chat.example.com/api/v4/posts \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"channel_id": "'$CHANNEL_ID'", "message": "Backup finished: **42 GB** in 3 min"}'

Los mensajes usan Markdown. Añade "root_id" (el primer mensaje de un hilo) para responder en un hilo, "file_ids" para archivos y "props" para adjuntos y otros elementos adicionales (consulta Adjuntos).

Buscar el ID de un canal

curl -H "Authorization: Bearer $TOKEN" \
  https://chat.example.com/api/v4/teams/name/lumen-labs/channels/name/ops-alerts

Los nombres son los que aparecen en el enlace del canal: /lumen-labs/channels/ops-alerts.

Paginación

Los puntos de conexión de listas aceptan page (desde 0) y per_page (60 por defecto, máximo 200). Sigue solicitando la siguiente página hasta que una página devuelva menos elementos que per_page.

Los mensajes de un canal (GET /channels/{channel_id}/posts) también aceptan since (un momento: todo lo que cambió desde entonces) o before y after (un ID de publicación). Se devuelven como una lista de publicaciones: {"order": [IDs, newest first], "posts": {ID: post}, "next_post_id", "prev_post_id"}.

Errores

Los errores usan los códigos de estado HTTP habituales (400 entrada incorrecta, 401 no autenticado, 403 no autorizado, 404 no encontrado, 501 función desactivada) y un cuerpo JSON:

{
  "id": "api.context.permissions.app_error",
  "message": "You do not have the appropriate permissions.",
  "detailed_error": "",
  "request_id": "jz8zm5nunpbt8f3gpqsz5dq6so",
  "status_code": 403
}

Usa id en tu código: message se traduce al idioma del usuario. detailed_error está vacío a menos que el servidor se ejecute en modo desarrollador (ServiceSettings.EnableDeveloper). Cita request_id al administrador del servidor: aparece en los registros.

Límites de velocidad

El límite de velocidad está desactivado por defecto. Cuando un administrador del sistema lo activa (Consola de sistema › Entorno › Límite de Velocidad), cada cliente obtiene 10 solicitudes por segundo con ráfagas de 100 por defecto, contadas por dirección IP o por usuario. Las respuestas incluyen X-RateLimit-Limit, X-RateLimit-Remaining y X-RateLimit-Reset; al superar el límite, el servidor responde 429 con una cabecera Retry-After en segundos. Algunos puntos de conexión, como el inicio de sesión, tienen su propio límite independientemente de la configuración.

Escribe scripts que esperen y reintente ante un 429, y evita las consultas repetidas: usa el WebSocket en su lugar.

El flujo de eventos WebSocket

Conéctate a wss://chat.example.com/api/v4/websocket. Autentícate mediante la cabecera Authorization: Bearer en la petición de conexión, o enviando esto como primer mensaje:

{"seq": 1, "action": "authentication_challenge", "data": {"token": "…"}}

El servidor envía un evento hello y, a continuación, un evento por todo lo que tengas permiso para ver:

{
  "event": "posted",
  "data": {"channel_id": "…", "channel_type": "O", "post": "{\"id\":\"…\",\"message\":\"Hello\",…}"},
  "broadcast": {"channel_id": "…", "team_id": "", "user_id": "", "omit_users": null},
  "seq": 4
}

Ten en cuenta que data.post es el mensaje como una cadena JSON. Eventos habituales: posted, post_edited, post_deleted, reaction_added, reaction_removed, typing, status_change, user_added, direct_added. Las aplicaciones envían sus propios eventos, nombrados custom_<app id>_<event>.

También puedes enviar acciones, cada una con un seq creciente: user_typing con {"channel_id", "parent_id"}, o get_statuses. Reconéctate cuando la conexión se interrumpa y recupera lo que hayas perdido con since (ver Paginación).

Antimatter añade estos eventos: community_attributes_updated, member_timeouts_updated, post_put_on_top, post_removed_from_top, server_categories_updated, channel_overrides_updated y category_overrides_updated.

Bibliotecas de cliente

  • Ir: model.Client4 en server/public/model (importar github.com/mattermost/mattermost/server/public/model). model.NewAPIv4Client(url), luego client.SetToken(token); model.NewWebSocketClient4(wsURL, token) sigue los eventos. La copia de Antimatter añade métodos para sus propios puntos de conexión, como UpdateMessageRequest, PutPostOnTop y ExportChannel.
  • TypeScript: la clase Client4 de @mattermost/client, en webapp/platform/client, con sus tipos en webapp/platform/types. La copia en el repositorio de Antimatter incluye los puntos de conexión de Antimatter; el paquete publicado en npm por Mattermost no los incluye.
package main

import (
	"context"
	"log"

	"github.com/mattermost/mattermost/server/public/model"
)

func main() {
	client := model.NewAPIv4Client("https://chat.example.com")
	client.SetToken("…")
	post, _, err := client.CreatePost(context.Background(), &model.Post{
		ChannelId: "…",
		Message:   "Hello from Go",
	})
	if err != nil {
		log.Fatal(err)
	}
	log.Println("posted", post.Id)
}

Nuevos campos

  • Comunidades (Team, y PUT /teams/{team_id}/patch): all_channels_membership (todos están en cada canal que pueden ver), default_channel_id (donde caen los nuevos; vacío significa General), kind (community o workplace: en un workplace, los administradores de canal también pueden archivar sus canales; las nuevas comunidades obtienen el TeamSettings.DefaultCommunityKind del servidor, community por defecto), member_list_view (cómo la lista de miembros agrupa a los miembros: choice, el valor predeterminado, permite que cada miembro elija; roles o teams lo fija), hide_role_colors, require_team_badges, onboarding y autolinks (ambos cadenas JSON).
  • El canal predeterminado de una nueva comunidad es general (General), no town-square. La actualización a la versión 0.9.0 cambia el nombre de town-square a general en cada comunidad, conservando su ID, a menos que la comunidad ya tenga un canal general. Los nombres antiguos siguen funcionando: GET /teams/{team_id}/channels/name/town-square, GET /teams/name/{team}/channels/name/town-square y el campo channel de un webhook entrante devuelven el canal predeterminado de la comunidad cuando no existe un canal con ese nombre. Utilice default_channel_id o el nombre general en el nuevo código.
  • Enlaces de canal: #channel-name enlaza a un canal, al igual que ~channel-name. La propiedad channel_mentions de la publicación lista los canales enlazados de cualquiera de las dos formas; un #word que no corresponde a ningún canal se mantiene como etiqueta. La interfaz web y la aplicación móvil de Antimatter escriben #name.
  • Los Canales Archivados siguen admitiendo nuevos miembros (POST /channels/{channel_id}/members), que pueden leer su historial. Nadie puede publicar, reaccionar, fijar, poner un mensaje en la parte superior, cambiar el nombre del canal ni modificar los roles de sus miembros allí.
  • Respuestas en línea: una publicación con "props": {"reply_to": "<post id>"} cita ese mensaje del mismo canal. Añade "reply_to_mention": false para no notificar a su autor. El servidor rellena metadata.reply_to con una descripción breve del mensaje citado.
  • Alertas de contenido: "props": {"spoiler": true} oculta el texto y los archivos de una publicación hasta que el lector elige verlos.
  • Ignorar y bloquear son preferencias: categoría user_block, nombrada con el ID de la otra persona, con el valor ignore o block. Si un mensaje directo espera como solicitud está en notify_props.dm_request de tu miembro de canal (pending, accepted o dismissed).
  • Adjuntos de mensajes pueden llevar stages y un chart: ver Tarjetas.

Mover un hilo

POST /posts/{post_id}/move_to_channel mueve un hilo, su primer mensaje y todas sus respuestas, a otro canal de la misma comunidad. post_id puede ser el primer mensaje o cualquier respuesta.

curl -X POST https://chat.example.com/api/v4/posts/$POST_ID/move_to_channel \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"channel_id": "'$TARGET_CHANNEL_ID'", "flatten": false}'
  • channel_id (obligatorio): el canal al que se mueve el hilo.
  • flatten (valor predeterminado false): si se establece en true, las respuestas se convierten en mensajes del canal de destino en lugar de un hilo. La función Convertir en canal de Fusion la utiliza.

Los mensajes conservan sus autores, horas, reacciones y archivos. Sus copias llevan la propiedad silent_notification, por lo que no notifican a nadie. Los mensajes originales se eliminan. La respuesta es el primer mensaje movido, con su nuevo ID.

Quién puede mover un hilo

  • Debe poder leer el hilo y publicar en el canal de destino.
  • Los administradores del canal, los administradores de la comunidad, las personas con Gestionar mensajes (delete_others_posts) en el canal y los administradores del sistema pueden mover cualquier hilo.
  • El autor del hilo puede moverlo cuando ambos canales son públicos, o cuando todos los mensajes del hilo son suyos. En caso contrario, la respuesta es 403 con el ID api.post.move_thread.private_needs_moderator.app_error.
  • Ambos canales deben pertenecer a la misma comunidad (no se permiten mensajes directos ni de grupo), ser diferentes y no estar archivados. No se pueden mover mensajes del sistema ni mensajes que se eliminan tras la lectura.
  • Se rechaza un hilo con más de WranglerSettings.MoveThreadMaxCount mensajes (100 por defecto; 0 para sin límite).

El puntero y la nota

La operación de mover deja dos mensajes del sistema de tipo system_wrangler: un puntero en el canal de origen ("Un hilo con 13 mensajes se ha movido a #target") y una nota en el destino ("Este hilo se movió desde #source"), bajo el hilo movido o, con flatten, después de sus mensajes. Además del texto del mensaje, sus propiedades permiten a un cliente dibujar el nombre del canal como un enlace:

  • El puntero: MovedThreadPermalink, NumMessages, MovedThreadChannelId, MovedThreadTeamName, MovedThreadPostId y, para un destino público, MovedThreadChannelName y MovedThreadChannelDisplayName.
  • La nota: MovedFromChannelId, MovedFromTeamName, MovedFromPostId (el puntero), MovedFromPermalink y, para un origen público, MovedFromChannelName y MovedFromChannelDisplayName.

Ambos también tienen un TranslationID. El nombre de un canal privado se omite: los lectores ven "otro canal". El propio POST /posts/{post_id}/move de Mattermost permanece desactivado en Antimatter; usa este punto de conexión.

Conexiones de modelos

Una conexión de modelo es la dirección y la clave de un proveedor de IA, configurada por un administrador. Las funciones de IA del servidor y las aplicaciones que llaman al servicio de IA las utilizan. Los administradores del sistema gestionan las conexiones de todo el servidor (manage_ai_connections); los administradores de una comunidad gestionan las de su propia comunidad (manage_team_ai_connections). Las claves son solo de escritura: ninguna respuesta las incluye, solo api_key_set y api_key_last4.

Punto de conexiónQué hace
GET /ai/connections?scope=Las conexiones que gestionas. scope es server o el ID de una comunidad; sin él, todos los ámbitos que gestionas.
POST /ai/connectionsAñade una conexión (responde 201).
POST /ai/connections/test, POST /ai/connections/modelsPrueba una conexión o lista sus modelos antes de guardarla. Mismo cuerpo que al añadirla; no se guarda nada.
GET, PATCH (o PUT), DELETE /ai/connections/{connection_id}Lee, modifica o elimina una conexión. Un parche solo incluye los campos a cambiar; omite api_key para conservar la clave.
POST /ai/connections/{connection_id}/testPrueba una conexión guardada: {"ok", "error", "status_code", "latency_ms", "model_count"}.
GET /ai/connections/{connection_id}/modelsLos modelos que ofrece el proveedor.
GET /ai/connections/{connection_id}/usageLas solicitudes y los tokens de este mes.
GET /ai/connections/usable?channel_id=&team_id=Para cualquier persona iniciada en la sesión: las conexiones que puede usar allí, con sus modelos y capacidades, nunca sus claves o direcciones.

El cuerpo de una nueva conexión:

{
  "name": "Local models",
  "scope": "server",
  "provider": "openai_compatible",
  "base_url": "http://llm.internal:8000/v1",
  "api_key": "…",
  "extra_headers": {},
  "models": {"chat": "qwen3-32b", "embeddings": "", "transcription": "", "decisions": ""},
  "limits": {"requests_per_minute": 0, "monthly_token_budget": 0, "per_user_requests_per_minute": 0, "per_user_monthly_token_budget": 0},
  "sharing": {"all_teams": true, "team_ids": []},
  "audience": {"everyone": true, "group_ids": [], "roles": [], "allow_guests": false}
}

provider es openai_compatible o anthropic. scope tiene como valor predeterminado server; el ID de una comunidad la convierte en la conexión de esa comunidad. En limits, 0 significa sin límite; las solicitudes por minuto se cuentan en cada servidor, y los presupuestos de tokens por mes calendario (UTC) para todo el clúster. sharing indica qué comunidades pueden usar una conexión de todo el servidor (los mensajes directos y de grupo requieren all_teams), y audience quién puede usarla; solo invitados con allow_guests. Los cambios se escriben en el registro de auditoría. La guía de administración explica la configuración: ver IA.
