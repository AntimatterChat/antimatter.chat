Escritura de aplicaciones (plugins)

Las aplicaciones añaden funciones a Antimatter desde el interior: una parte de servidor en Go que se integra con el servidor, y una parte de aplicación web en React que añade menús, paneles, tipos de mensaje y páginas. Esta página muestra cómo se estructura una aplicación, usando la aplicación integrada de Encuestas como ejemplo, y qué cambia en la interfaz de Fusion de Antimatter.

Cómo funciona una aplicación

  • La parte del servidor es un programa en Go. El servidor lo inicia como un proceso independiente y se comunica con él mediante RPC: llama a los hooks de la aplicación (un mensaje está a punto de publicarse, se ejecutó un comando, etc.) y la aplicación llama a la API de plugins del servidor (crear una publicación, leer un usuario, almacenar datos, etc.). También puede servir rutas HTTP bajo /plugins/<app id>/.
  • La parte de la aplicación web es un paquete de JavaScript que se carga en el navegador junto con la aplicación web. Registra componentes y callbacks de React en el registro: un botón en un menú, un panel, una forma de dibujar un tipo de mensaje.
  • Cada parte es opcional. Una app se instala como un paquete .tar.gz, y los administradores del sistema la habilitan, deshabilitan y configuran.
La parte de servidor se ejecuta con acceso completo a los datos del servidor. Trata una aplicación como código que se despliega en el servidor.

Antimatter ejecuta las aplicaciones escritas para Mattermost, y viceversa, siempre que la aplicación solo use los hooks que ambos tienen. Consulte Hooks que solo tiene Antimatter.

El diseño del paquete

No existe una plantilla de inicio separada: empieza con una pequeña aplicación integrada como antimatter-plugin-polls o antimatter-plugin-todo, y cambia su ID y su código. Encuestas se estructura así:

antimatter-plugin-polls/
├── plugin.json            the manifest
├── Makefile               build, test, bundle, deploy
├── build/                 the manifest and pluginctl helper tools (Go), setup.mk
├── assets/icon.svg        files shipped with the bundle
├── go.mod
├── server/
│   ├── main.go            plugin.ClientMain(&Plugin{})
│   ├── plugin.go          the Plugin type, OnActivate, ServeHTTP
│   ├── manifest.go        generated from plugin.json
│   ├── api.go, command.go, hooks.go, store.go …
│   └── dist/              compiled binaries, one per platform
└── webapp/
    ├── package.json, webpack.config.js, tsconfig.json
    ├── i18n/              en.json and one file per language
    ├── src/index.tsx      registers the app with the web app
    ├── src/manifest.ts    generated from plugin.json
    ├── src/translations.ts
    └── dist/main.js       the bundle

Opcional: una carpeta public/, servida tal cual en /plugins/<app id>/public/.

plugin.json

{
  "id": "com.example.weather",
  "name": "Weather",
  "description": "Forecasts in the chat.",
  "homepage_url": "https://github.com/example/weather",
  "support_url": "https://github.com/example/weather/issues",
  "icon_path": "assets/icon.svg",
  "version": "1.0.0",
  "min_server_version": "12.0.0",
  "server": {
    "executables": {
      "linux-amd64": "server/dist/plugin-linux-amd64",
      "linux-arm64": "server/dist/plugin-linux-arm64",
      "darwin-amd64": "server/dist/plugin-darwin-amd64",
      "darwin-arm64": "server/dist/plugin-darwin-arm64",
      "windows-amd64": "server/dist/plugin-windows-amd64.exe"
    }
  },
  "webapp": {"bundle_path": "webapp/dist/main.js"},
  "settings_schema": {"settings": []}
}
  • id: único y permanente; lo habitual es usar un nombre de dominio inverso. Nombra las rutas, la configuración almacenada y los eventos de WebSocket.
  • version: versión semántica. Las aplicaciones incluidas no la incluyen en plugin.json; su herramienta de compilación la toma de la etiqueta git v* más reciente.
  • min_server_version: Antimatter informa 12.0.0.
  • settings_schema: la página de configuración de la app en la Consola de sistema (ver Configuración).

make apply copia el manifiesto en server/manifest.go y webapp/src/manifest.ts; make manifest-check lo valida.

La parte del servidor

La parte del servidor importa el mismo módulo Go que las apps de Mattermost, github.com/mattermost/mattermost/server/public, desde el proxy de módulos Go. Su main solo inicia la app:

package main

import "github.com/mattermost/mattermost/server/public/plugin"

func main() {
	plugin.ClientMain(&Plugin{})
}

El tipo Plugin incrusta plugin.MattermostPlugin, lo que le proporciona p.API, e implementa los hooks que necesita:

type Plugin struct {
	plugin.MattermostPlugin
	router *mux.Router
}

func (p *Plugin) OnActivate() error {
	p.router = p.newRouter()
	return p.API.RegisterCommand(&model.Command{
		Trigger:          "weather",
		AutoComplete:     true,
		AutoCompleteDesc: "Show the forecast",
		AutoCompleteHint: "[city]",
	})
}

func (p *Plugin) ExecuteCommand(c *plugin.Context, args *model.CommandArgs) (*model.CommandResponse, *model.AppError) {
	city := strings.TrimSpace(strings.TrimPrefix(args.Command, "/weather"))
	return &model.CommandResponse{
		ResponseType: model.CommandResponseTypeEphemeral,
		Text:         "Forecast for " + city + ": sunny",
	}, nil
}

func (p *Plugin) ServeHTTP(c *plugin.Context, w http.ResponseWriter, r *http.Request) {
	p.router.ServeHTTP(w, r)
}

Hooks comunes

HookCuándo se ejecuta
OnActivate, OnDeactivateCuando la app se habilita o deshabilita, y cuando el servidor se inicia y se detiene. Registra los comandos y los bots en OnActivate.
OnConfigurationChangeCuando cambian sus ajustes; cárgalos con p.API.LoadPluginConfiguration(&cfg).
ServeHTTPSolicitudes a /plugins/<app id>/…. El servidor establece la cabecera Mattermost-User-Id cuando la solicitud proviene de un usuario conectado; rechaza las solicitudes sin ella, a menos que estén destinadas a ser públicas.
ExecuteCommandSe ejecutó un comando registrado por la app.
MessageWillBePosted, MessageWillBeUpdatedAntes de que se guarde un mensaje: devuelve un mensaje modificado o un motivo para rechazarlo.
MessageHasBeenPosted, MessageHasBeenUpdated, MessageHasBeenDeletedDespués del hecho, para efectos secundarios.
ReactionHasBeenAdded, ReactionHasBeenRemovedReacciones.
UserHasJoinedChannel, UserHasLeftChannel, UserHasJoinedTeam, UserHasLeftTeam, ChannelHasBeenCreatedCambios de membresía y de canal. Un equipo es una comunidad.
FileWillBeUploadedAntes de que se almacene un archivo: modifícalo o recházalo.
OnPluginClusterEventUn mensaje de la misma app en otro servidor de un clúster.

La lista completa, con las firmas exactas, está en server/public/plugin/hooks.go; la API está en server/public/plugin/api.go. El paquete pluginapi (server/public/pluginapi) envuelve la API en asistentes más amigables.

Llamadas de API útiles

  • CreatePost, UpdatePost, SendEphemeralPost: publicar como el bot de la app o como un usuario.
  • EnsureBotUser(&model.Bot{Username, DisplayName}): crea el bot de la app una vez y obtiene su ID.
  • PublishWebSocketEvent("poll_updated", payload, &model.WebsocketBroadcast{ChannelId: id}): envía un evento a la app web. Llega como custom_<app id>_poll_updated.
  • OpenInteractiveDialog: abre un diálogo.
  • LogInfo, LogError y similares: escribe en el registro del servidor, etiquetado con el ID de la app.
  • GetUser, GetChannel, HasPermissionToChannel: comprueba quién puede hacer qué antes de actuar en nombre de un usuario.

Una app se ejecuta en cada servidor de un clúster. Mantén el estado en el almacén de clave-valor o en la base de datos, no solo en memoria.

Almacenamiento de datos

Cada app tiene su propio almacén de clave-valor en la base de datos del servidor:

  • KVSet(key, value), KVGet(key), KVDelete(key): los valores son bytes, generalmente JSON. Las claves tienen un máximo de 150 caracteres.
  • KVSetWithExpiry(key, value, seconds): el valor desaparece después de ese tiempo.
  • KVCompareAndSet(key, old, new) y KVSetWithOptions con Atomic: actualizaciones seguras cuando varias solicitudes o servidores escriben la misma clave. Polls guarda cada voto de esta manera y reintenta en caso de conflicto.
  • KVList(page, perPage): las claves, página por página.

La parte de la app web

El paquete registra una clase con window.registerPlugin. Su initialize recibe el registro y el almacén de Redux:

import manifest from './manifest';

class Plugin {
    initialize(registry, store) {
        registry.registerTranslations((locale) => translationsFor(locale));
        registry.registerPostTypeComponent('custom_poll', PollPost);
        registry.registerWebSocketEventHandler(`custom_${manifest.id}_poll_updated`, (msg) => {
            store.dispatch(pollUpdated(JSON.parse(msg.data.poll)));
        });
        registry.registerReconnectHandler(() => store.dispatch(reloadPolls()));
    }
}

window.registerPlugin(manifest.id, new Plugin());
  • Bibliotecas compartidas. La app web proporciona React, ReactDOM, Redux, React Redux y React Intl: decláralas como externals de webpack (React, ReactDOM, Redux, ReactRedux, ReactIntl) en lugar de incluir tus propias copias. Consulta el webpack.config.js de Polls.
  • Llamadas a tu parte de servidor. Usa Fetch con ${window.basename}/plugins/<app id>/… y las opciones de Client4.getOptions() (de mattermost-redux/client): estas llevan las cabeceras que el servidor necesita para aceptar una solicitud del navegador.
  • Tu propio estado. registerReducer añade un reducer, almacenado bajo state['plugins-<app id>'].
  • Tipos. Los métodos adicionales del registro de Antimatter no están en los tipos publicados de Mattermost: Polls declara el registro que utiliza en webapp/src/types/host.ts.

Los métodos del registro y sus parámetros están documentados en el código, en webapp/fusion/src/plugins/registry.ts (Fusion) y webapp/channels/src/plugins/registry.ts (clásico).

Soporte para la interfaz Fusion

Antimatter tiene dos interfaces web: Fusion, la predeterminada, y la clásica. Ambas cargan los mismos paquetes de apps y tienen el mismo registro, pero Fusion dibuja muchas cosas por sí misma y coloca los componentes de las apps de su propia manera. Prueba tu app en ambas.

Detectar la interfaz

Antes de que se cargue cualquier app, ambas interfaces establecen window.antimatterWebUI en 'fusion' o 'classic', y el mismo valor en el elemento raíz de la página como data-am-web-ui. En Mattermost, ninguno de los dos se establece.

export function isFusionUI(): boolean {
    return window.antimatterWebUI === 'fusion' || document.documentElement.dataset.amWebUi === 'fusion';
}

Las aplicaciones integradas usan esto para dibujarse de manera diferente. Encuestas dibuja sus tarjetas de encuesta y su diálogo de creación con el estilo de Fusion, y abre su propio diálogo para /poll en Fusion. Las llamadas y los canales de voz omiten los componentes de la barra lateral y las notificaciones emergentes que Fusion reemplaza con su propia interfaz de llamadas. La aplicación Agentes coloca sus acciones de IA en un submenú del menú de mensajes en lugar de la barra de herramientas al pasar el cursor. Las clases CSS propias de Fusion (con el prefijo am-) y su capa de diálogos (el elemento am-layer) son lo que estas aplicaciones usan para coincidir con la interfaz; no son una API documentada y estable.

Lo que Fusion no muestra ni ejecuta

  • registerPostDropdownMenuComponent (un componente en el menú de mensajes), registerPostCardTypeComponent (una tarjeta de un mensaje en el panel derecho) y registerProductSwitcherMenuItem no se muestran en las vistas principales de Fusion. Use registerPostDropdownMenuAction en lugar del primero.
  • registerMessageWillBeUpdatedHook no se ejecuta cuando se edita un mensaje en Fusion. Compruebe las ediciones en el servidor con el hook MessageWillBeUpdated en su lugar.
  • registerActionAfterChannelCreation solo se ejecuta desde el diálogo clásico de creación de canal, que Fusion abre desde Más opciones… en su diálogo Crear canal.
  • Los componentes de la barra de la aplicación se muestran independientemente de su supportedProductIds.
  • Las rutas de registerNeedsTeamRoute y registerCustomRoute conservan el marco de página clásico, al igual que los productos.

Hooks que solo tiene Antimatter

Estos métodos de registro no existen en Mattermost. Compruebe que un método existe antes de llamarlo, para que la aplicación también funcione allí:

if (typeof registry.registerComposerMenuItem === 'function') {
    registry.registerComposerMenuItem({
        text: 'Create a poll',
        icon: <i className='icon icon-chart-bar'/>,
        fusionIcon: 'poll',
        action: ({channelId, rootId}) => openPollCreation(channelId, rootId),
    });
} else {
    registry.registerChannelHeaderButtonAction(icon, (channel) => openPollCreation(channel.id), 'Create a poll', 'Create a poll');
}
MétodoQué añade
registerComposerMenuItem({text, icon, fusionIcon, action, shouldRender})Un elemento en el menú + de la caja de mensajes, en ambas interfaces. action recibe {channelId, rootId}.
registerEmojiPickerTab({id, label, icon, fusionIcon, order, component, shouldRender, replacesGifPicker})Una pestaña del selector de emojis del cuadro de mensajes, como GIF o pegatinas. En Fusion, las pestañas con un order menor que 10 aparecen antes de la pestaña Emoji. El componente recibe channelId, rootId, filter, onFilterChange, onSelectDone, insertText y isFusion.
registerChannelViewPanel({matcher, component})Un panel entre la cabecera del canal y los mensajes, para los canales que selecciona matcher(state, channel). Puede ocultar los mensajes y el compositor (setMessagesVisible), como hacen los canales de voz.
registerSidebarChannelFooterComponent(component)Una línea bajo un canal en la barra lateral, como las personas en su llamada. Recibe el channel.
registerIntegrationsOption({title, description, fusionIcon, action, shouldRender})Solo Fusion: una entrada en las páginas Integraciones, junto a los emojis personalizados. La app de GIF añade sus GIF y pegatinas personalizados allí.

fusionIcon nombra un icono del conjunto de iconos de Fusion (por ejemplo poll, sticker, calendar o image; ver webapp/fusion/src/fusion/components/icon). Fusion lo muestra en lugar de icon, para que el elemento coincida con los demás.

Configuración

settings_schema en plugin.json describe la página de la app en Consola de sistema › Plugins:

"settings_schema": {
  "header": "Forecasts come from the weather service below.",
  "settings": [
    {"key": "ServiceURL", "display_name": "Service URL", "type": "text", "default": "https://api.example.com"},
    {"key": "Units", "display_name": "Units", "type": "dropdown", "default": "metric",
     "options": [{"display_name": "Celsius", "value": "metric"}, {"display_name": "Fahrenheit", "value": "imperial"}]},
    {"key": "EnableAlerts", "display_name": "Severe weather alerts", "type": "bool", "default": false,
     "help_text": "Post alerts in the channels that follow a city."}
  ]
}

Tipos de configuración: bool, text, longtext, number, dropdown, radio, generated (un secreto aleatorio), username y custom (dibujado por un componente que la parte de la app web registra con registerAdminConsoleCustomSetting). Las configuraciones se pueden agrupar en sections.

La parte del servidor las lee en una estructura cuyos campos coinciden con las claves:

type configuration struct {
	ServiceURL   string
	Units        string
	EnableAlerts bool
}

func (p *Plugin) OnConfigurationChange() error {
	var cfg configuration
	if err := p.API.LoadPluginConfiguration(&cfg); err != nil {
		return err
	}
	p.setConfiguration(&cfg)
	return nil
}

Los administradores también pueden establecerlas en la configuración, bajo PluginSettings.Plugins.<app id>, con claves en minúsculas (ver la guía de administración).

Traducciones

Antimatter está traducido a 37 idiomas, y las apps incluidas también. La parte de la app web lo hace así:

  1. Escribe cada cadena con React Intl, con un ID y su texto en inglés: <FormattedMessage id='polls.create' defaultMessage='Create a poll'/> o defineMessages. Prefija los IDs con el nombre de tu app.
  2. Extrae las cadenas en inglés a webapp/i18n/en.json (las apps incluidas usan formatjs extract).
  3. Añade un archivo por idioma junto a él, con los mismos IDs: fr.json, de.json, pt-BR.json, zh-CN.json…
  4. Pásalas a la aplicación web, que solicita el idioma del usuario: 
    import fr from '../i18n/fr.json';
import ptBR from '../i18n/pt-BR.json';

const catalogs = {fr, 'pt-BR': ptBR};

export function translationsFor(locale) {
    return catalogs[locale] || catalogs[locale.split('-')[0]] || {};
}

registry.registerTranslations(translationsFor);

Si falta una cadena, se usa su defaultMessage en inglés. Para las cadenas que envía la parte del servidor (respuestas de comandos, mensajes de bots), el paquete pluginapi/i18n carga los archivos de traducción incluidos en el paquete (por ejemplo, assets/i18n) y proporciona un localizador en el idioma de cada usuario.

Compilar, instalar y depurar

Necesitas Go y Node.js (la versión indicada en el .nvmrc de la aplicación). En la carpeta de la aplicación:

ComandoQué hace
make distCompila la parte del servidor para todas las plataformas y la parte de la aplicación web, y escribe el paquete en dist/<app id>-<version>.tar.gz.
make testEjecuta las pruebas de Go y JavaScript.
make check-styleAnaliza el código (golangci-lint, ESLint) y comprueba los tipos de TypeScript.
make deployCompila, luego instala y habilita el paquete en un servidor.
make watch, make deploy-from-watchEl primero recompila la parte de la aplicación web cada vez que guardas; el segundo empaqueta lo que compiló y lo instala en el servidor.
make enable, make disable, make resetHabilita, deshabilita o reinicia la aplicación en el servidor.
make logs, make logs-watchMuestra las líneas de la aplicación en el registro del servidor.
make attachAdjunta el depurador Delve a la parte del servidor en ejecución (compila primero con AM_DEBUG=1).

make deploy y los otros comandos del servidor usan un socket de modo local cuando lo encuentran (/var/tmp/antimatter_local.socket, o AM_LOCALSOCKETPATH): ejecútalos en la máquina del servidor con el modo local activado. De lo contrario, inician sesión en el servidor indicado por MM_SERVICESETTINGS_SITEURL con AM_ADMIN_TOKEN, o con AM_ADMIN_USERNAME y AM_ADMIN_PASSWORD. Las herramientas de compilación aún no leen un nombre AM_ para la URL del sitio.

Instalar un paquete manualmente

  • Un administrador del sistema permite las subidas con AM_PLUGINSETTINGS_ENABLEUPLOADS=true (desactivado por defecto; no hay un interruptor en la Consola de sistema).
  • Luego Consola de sistema › Plugins › Gestión de Plugins › Cargar Plugin, o amctl plugin add weather.tar.gz seguido de amctl plugin enable com.example.weather.
  • Si el servidor tiene activado Requerir Firma del Plugin, solo acepta paquetes firmados con una clave de confianza; consulte Instalación de otras aplicaciones.
Para iteraciones rápidas en un servidor de desarrollo, establece AM_SERVICESETTINGS_ENABLEDEVELOPER=true en el servidor: los errores entonces incluyen sus detalles. Los Makefiles de las aplicaciones incluidas solo compilan la parte del servidor para tu plataforma cuando MM_SERVICESETTINGS_ENABLEDEVELOPER está definido en tu shell.
