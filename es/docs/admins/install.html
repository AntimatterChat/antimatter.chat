Instalación de Antimatter

Instala Antimatter con el archivo compose listo para usar, desde el paquete .deb o .rpm de una liberación, o desde un archivo de liberación. Después, crea la cuenta de administrador principal.

Instalación con Docker Compose

Esta es la forma recomendada. Un solo archivo compose ejecuta Antimatter, PostgreSQL, el almacenamiento de archivos y el servicio de GIF. Necesita un servidor Linux con Docker Engine y su plugin Compose (docker compose), 2 núcleos de CPU y 4 GB de memoria o más.

1. Descargar el archivo compose

mkdir antimatter && cd antimatter
curl -fsSLO https://antimatter.chat/compose.yaml

2. Crear el archivo .env

El archivo compose lee su configuración desde un archivo .env en el mismo directorio. Créelo con secretos aleatorios:

cat > .env <<EOF
SITE_URL=http://localhost:8065
POSTGRES_PASSWORD=$(openssl rand -hex 24)
S3_SECRET_KEY=$(openssl rand -hex 24)
GIFS_API_KEY=$(openssl rand -hex 24)
AM_AI_ENCRYPTION_KEY=$(openssl rand -base64 32)
EOF
chmod 600 .env

Establece SITE_URL con la dirección que las personas escribirán en su navegador, por ejemplo http://192.168.1.20:8065 en una red local o https://chat.example.com con un dominio. Conserva el archivo .env: la base de datos y el almacenamiento usan estas contraseñas desde el primer inicio, las claves API de las conexiones de modelos de IA se cifran con AM_AI_ENCRYPTION_KEY, y necesitas el mismo archivo para restaurar una copia de seguridad.

3. Iniciar

docker compose up -d
docker compose ps

El primer inicio tarda uno o dos minutos: PostgreSQL crea la base de datos, un servicio de un solo uso bucket crea el contenedor de almacenamiento, un servicio de un solo uso gifs-stickers importa el paquete de pegatinas inicial y Antimatter crea sus tablas. Sígalo con docker compose logs -f antimatter.

Para usar un nombre de dominio y HTTPS desde el inicio, consulte Dominio y HTTPS: con el archivo compose, son dos líneas más en .env y el perfil https.

Lo que se ejecuta

PostgreSQL, el almacenamiento y el servicio de GIF están en una red interna (private) sin acceso a Internet, a la que solo se une Antimatter. Ninguno de ellos publica un puerto.

El contenedor de Antimatter no conserva nada en el disco: su configuración está en la base de datos (AM_CONFIG apunta a ella) y sus archivos y aplicaciones están en el servicio de almacenamiento. Puedes eliminar y recrear el contenedor en cualquier momento. Su volumen data solo contiene el archivo de la clave de cifrado de IA, que el servidor crea cuando AM_AI_ENCRYPTION_KEY está vacío. Todo lo que hay que hacer copia de seguridad está en los volúmenes postgres, files, gifs y data, además de tu .env.

Elegir una imagen

Se publican dos imágenes de Antimatter, ambas para linux/amd64 y linux/arm64, y ambas construidas desde la rama main de cada repositorio:

ImagenAplicaciones incluidasEtiquetas
ghcr.io/antimatterchat/antimatterAgentes, Llamadas, GitHub, GitLab, Jira, Kanban, Métricas y Playbooks.latest, X.Y.Z para las versiones, sha-<commit>
ghcr.io/antimatterchat/antimatter-nextLo mismo, más Canales de voz, Encuestas, Correo, Calendario, Notas, Pizarra, GIF, Por hacer y Memes. Se reconstruye cada noche.latest, nightly, nightly-<YYYYMMDD>, sha-<commit>

El archivo compose del sitio usa antimatter-next, porque el servicio de GIF y la mayoría de las aplicaciones descritas en este sitio solo están en esa imagen. Para cambiar la imagen, configura ANTIMATTER_IMAGE en .env y ejecuta docker compose up -d.

latest cambia bajo tus pies. En producción, fija una etiqueta como nightly-20261015 o sha-<commit>, y cámbiala deliberadamente al actualizar. El servidor actualiza su base de datos al iniciarse, por lo que no puedes volver a una imagen anterior, ni pasar de antimatter-next a antimatter, sin restaurar una copia de seguridad tomada antes. Consulta Copias de seguridad y actualizaciones.

Dentro de la imagen

  • El servidor está en /antimatter, con los binarios antimatter y amctl en /antimatter/bin (en el PATH).
  • Se ejecuta como el usuario sin privilegios antimatter (uid 2000) sobre una base distroless mínima, sin shell.
  • Puertos: 8065 (web y API), 8067 (métricas), 8074 (clúster), 8443 UDP y TCP (llamadas).
  • El modo local (ServiceSettings.EnableLocalMode) está activado, por lo que amctl --local funciona dentro del contenedor. La comprobación de estado ejecuta amctl system status --local.
  • Las aplicaciones incluidas se encuentran en /antimatter/prepackaged_plugins y están firmadas con la clave de firma de aplicaciones de Antimatter.
  • Se incluyen herramientas de extracción de texto (pdftotext, wvText, unrtf, tidy), de modo que se pueda buscar en el contenido de los documentos subidos.

Otros archivos de compose

El repositorio antimatter-docker incluye una configuración de producción en deploy/compose/: nginx con tus propios certificados o Let's Encrypt (certbot), PostgreSQL, el servicio opcional de GIF (perfil gifs) y volúmenes con nombre para la configuración, los datos y los registros del servidor, todo documentado en su README. Utiliza la imagen estable por defecto y almacena los archivos en un volumen local en lugar de almacenamiento S3. Úsalo si prefieres nginx a Caddy o si ya tienes certificados.

Crear el primer administrador

Abre SITE_URL en tu navegador y crea una cuenta. La primera cuenta creada en un servidor nuevo se convierte en el administrador del sistema, y la configuración te guiará a continuación para crear tu primera comunidad (el nombre que Antimatter da a un equipo o espacio de trabajo).

Hazlo inmediatamente después del primer inicio: hasta entonces, cualquiera que acceda al servidor primero se convertirá en su administrador. Para crear la cuenta desde la línea de comandos en su lugar, antes de que el servidor sea accesible desde el exterior:

docker compose exec antimatter amctl --local user create --system-admin --email-verified \
    --email admin@example.com --username admin --password 'a-long-password'
docker compose exec antimatter amctl --local team create --name main --display-name "Main"
docker compose exec antimatter amctl --local team users add main admin

Después, inicia sesión en SITE_URL. Comienza el comando con un espacio para mantener la contraseña fuera del historial de tu shell (con HISTCONTROL=ignorespace), o cambia la contraseña una vez que hayas iniciado sesión.

Próximos pasos una vez que estés dentro:

  1. Para una empresa u organización, establece Kind of new communities en Lugar de trabajo y cambia el tipo de una comunidad que ya hayas creado en su configuración: Lugar de trabajo o comunidad.
  2. Decide quién puede crear cuentas: Inicio de sesión y cuentas.
  3. Configura el correo electrónico para que las invitaciones y los restablecimientos de contraseña funcionen: Correo electrónico y notificaciones push.
  4. Abre el puerto de las llamadas en tu cortafuegos: Llamadas y voz.
  5. Comprueba qué aplicaciones están activas: Aplicaciones incluidas.

Descargar una liberación

Sin Docker, instala Antimatter desde los archivos de una liberación en GitHub: github.com/AntimatterChat/antimatter/releases. Cada liberación tiene un número de versión, como 0.9.0, y su etiqueta es el mismo número con una v delante (v0.9.0).

Antimatter está en beta: sus versiones se encuentran en la serie 0.9.0. Una versión cuyo número incluye un sufijo después de un guion, como 0.9.0-rc.1, se marca como Pre-release en GitHub. Se trata de una versión de prueba, publicada antes de la versión final.

Cada versión incluye estos archivos, para servidores amd64 y arm64:

ArchivoDescripción
antimatter_<version>-1_amd64.deb, antimatter_<version>-1_arm64.debEl paquete para Debian, Ubuntu y las distribuciones basadas en ellas.
antimatter-<version>-1.x86_64.rpm, antimatter-<version>-1.aarch64.rpmEl paquete para Fedora, RHEL y las distribuciones compatibles con RHEL.
antimatter-<version>-linux-amd64.tar.gz, antimatter-<version>-linux-arm64.tar.gzEl archivo de la versión, para cualquier distribución de Linux, configurado manualmente.
SHA256SUMSLa suma de verificación SHA-256 de todos los archivos de la versión.

Los paquetes y el archivo contienen el mismo programa: el servidor (antimatter), la herramienta de línea de comandos (amctl), ambas aplicaciones web (la interfaz predeterminada y la clásica), las aplicaciones incluidas, las plantillas de correo electrónico y las traducciones. Los paquetes añaden un servicio de systemd y un archivo de configuración, por lo que cada uno constituye una instalación integral: solo es necesario añadir una base de datos PostgreSQL. No hay descargas de binarios separados: los binarios se encuentran en el archivo, en antimatter/bin/. Son estáticos, por lo que funcionan en cualquier distribución de Linux de su arquitectura.

En los nombres de los paquetes, el guion de una versión preliminar se convierte en una tilde, para que el gestor de paquetes ordene la versión preliminar antes de la versión final: la versión 0.9.0-rc.1 genera antimatter_0.9.0~rc.1-1_amd64.deb y antimatter-0.9.0~rc.1-1.x86_64.rpm. El archivo conserva el guion.

antimatter version muestra la versión de la compilación como Número de compilación, con el commit desde el que se compiló como Hash de compilación. Su línea Versión indica la versión de la línea de Mattermost en la que se basa Antimatter.

Verificar la descarga

Descargue el archivo que necesite y SHA256SUMS en el mismo directorio, desde la página de la versión o con curl, y luego verifique el archivo:

curl -fLO https://github.com/AntimatterChat/antimatter/releases/download/v<version>/antimatter_<version>-1_amd64.deb
curl -fLO https://github.com/AntimatterChat/antimatter/releases/download/v<version>/SHA256SUMS
sha256sum --check --ignore-missing SHA256SUMS

Cada archivo descargado debe aparecer listado con OK. Cualquier otro resultado significa que el archivo está dañado o incompleto: descárguelo de nuevo y no lo instale. SHA256SUMS no está firmado: detecta una descarga dañada, pero no demuestra nada más de lo que ya demuestra la descarga HTTPS desde GitHub.

Instalar el paquete .deb o .rpm

El paquete instala Antimatter como un servicio de systemd, que solo necesita una base de datos para iniciarse. Úselo en un servidor de 64 bits compatible con Debian, Ubuntu, Fedora o RHEL con systemd.

Qué instala el paquete

RutaContenido
/opt/antimatterEl programa: bin/antimatter, bin/amctl, las aplicaciones web (client/, client-fusion/), las aplicaciones integradas (prepackaged_plugins/), las plantillas, las traducciones y las fuentes. Cada actualización lo reemplaza.
/etc/antimatter/antimatter.envLa configuración del servicio, como variables AM_: la base de datos, la URL del sitio, el servicio de GIF. Solo root puede leerla. Las actualizaciones la conservan.
/etc/antimatter/config/config.jsonEl archivo de configuración, donde el servidor guarda los ajustes modificados en la Consola de sistema. Se crea a partir de /opt/antimatter/defaults/config.json en la primera instalación y nunca se reemplaza después.
/var/lib/antimatterLos archivos subidos (data/) y las aplicaciones instaladas (plugins/, client-plugins/).
/var/log/antimatterLos archivos de registro, si activas el registro en archivo. Está desactivado: los registros se envían al journal.
/usr/lib/systemd/system/antimatter.serviceEl servicio.
/usr/bin/amctlUn enlace a /opt/antimatter/bin/amctl.

Los directorios a los que escribe el servidor en /opt/antimatter (config, data, plugins, client/plugins y logs) son enlaces a /etc/antimatter, /var/lib/antimatter y /var/log/antimatter. Así, una actualización, que reemplaza /opt/antimatter, nunca toca tus datos. El paquete también crea el usuario de sistema antimatter, que ejecuta el servidor y es propietario de estos directorios.

El paquete depende de ca-certificates. Recomienda PostgreSQL (postgresql en Debian y Ubuntu, postgresql-server en Fedora y RHEL), media-types (mailcap para el .rpm) y gifs-server, el servicio de GIF, que tiene su propia versión (ver abajo). apt y dnf instalan los paquetes recomendados si los encuentran. Sugiere poppler-utils, wv, unrtf y tidy (sin wv para el .rpm): extraen el texto de los documentos subidos, para que la búsqueda encuentre palabras dentro de ellos. Instálalos tú mismo si quieres esto.

1. Instalar los paquetes

Descarga el paquete de Antimatter y el paquete del servicio de GIF de tu arquitectura, verifícalos como se muestra arriba e instala ambos en un solo comando, para que se cumpla la recomendación de gifs-server (no está en los repositorios de las distribuciones):

# Debian, Ubuntu
sudo apt install ./antimatter_<version>-1_amd64.deb ./gifs-server_*_amd64.deb
# Fedora, RHEL
sudo dnf install ./antimatter-<version>-1.x86_64.rpm ./gifs-server-*.x86_64.rpm

Mantén el ./: indica a apt y dnf que instalen un archivo local. Para instalar sin el servicio de GIF, omite su paquete. El paquete habilita el servicio antimatter, pero no lo inicia, e imprime los siguientes pasos.

2. Crear la base de datos

Antimatter necesita PostgreSQL 15 o una versión posterior, en este servidor o en otro. Comprueba la versión de PostgreSQL de tu distribución con psql --version. Si es anterior, instala una versión más reciente desde los repositorios propios del proyecto PostgreSQL, o usa una base de datos en otro servidor. En Debian y Ubuntu, el paquete postgresql inicia la base de datos. En Fedora y RHEL, créala e iníciala primero:

sudo postgresql-setup --initdb
sudo systemctl enable --now postgresql

Luego, crea un usuario y una base de datos para Antimatter:

sudo -u postgres psql -c "CREATE USER antimatter WITH PASSWORD 'a-long-password'"
sudo -u postgres psql -c "CREATE DATABASE antimatter OWNER antimatter"

PostgreSQL debe aceptar conexiones con contraseña desde 127.0.0.1: las líneas host de su archivo pg_hba.conf, con el método scram-sha-256.

3. Configurar la base de datos y la URL del sitio

Edita /etc/antimatter/antimatter.env (sudoedit /etc/antimatter/antimatter.env). Elimina el # que precede a las líneas que vayas a usar, y configura la base de datos y la dirección que las personas abrirán:

AM_SQLSETTINGS_DRIVERNAME=postgres
AM_SQLSETTINGS_DATASOURCE=postgres://antimatter:a-long-password@localhost:5432/antimatter?sslmode=disable&connect_timeout=10
AM_SERVICESETTINGS_SITEURL=https://chat.example.com

Cualquier ajuste de la configuración puede ir en este archivo, como AM_<SECTION>_<SETTING>: por ejemplo, SqlSettings.DataSource es AM_SQLSETTINGS_DATASOURCE. Un ajuste definido aquí no se puede cambiar en la Consola de sistema. Consulta Configuración. Reinicia el servidor después de cada cambio: sudo systemctl restart antimatter.

El servicio también establece algunos valores predeterminados, que una línea en antimatter.env puede sobrescribir: el registro en archivos está desactivado (AM_LOGSETTINGS_ENABLEFILE=false, AM_NOTIFICATIONLOGSETTINGS_ENABLEFILE=false), y el modo local está activado (AM_SERVICESETTINGS_ENABLELOCALMODE=true), de modo que amctl --local funcione en el servidor.

4. Iniciar el servicio

sudo systemctl start antimatter
journalctl -u antimatter -f
sudo -u antimatter amctl --local system status

En el primer arranque, el servidor crea sus tablas y luego escucha en el puerto 8065. Abra http://<server>:8065, o su dominio una vez que tenga un proxy inverso configurado (consulte Dominio y HTTPS), y cree de inmediato la primera cuenta: esta se convertirá en el administrador del sistema. Para crearla desde la línea de comandos, use los comandos amctl de Crear el primer administrador, sustituyendo docker compose exec antimatter amctl --local por sudo -u antimatter amctl --local.

5. Activar GIF

La aplicación GIF está incluida y activada, y antimatter.env ya la apunta al servicio de GIF en el mismo servidor (AM_GIFS_SERVICE_URL=http://127.0.0.1:8080/v2). Sin embargo, aún necesita la clave de API del servicio. El paquete gifs-server generó una clave durante su instalación:

sudo systemctl start gifs-server-stickers    # imports the sticker pack, about a minute and a half
sudo systemctl start gifs-server
sudo grep -v '^#' /etc/gifs-server/api-keys

Coloque la clave en antimatter.env como AM_GIFS_API_KEY=<key> y reinicie Antimatter, o ingrésela como Clave de API en Consola de sistema › Plugins › GIF. Si el servicio de GIF se ejecuta en otro servidor, configure AM_GIFS_SERVICE_URL con su dirección. Para permitir que las personas añadan sus propios GIF y pegatinas, consulte GIF.

El servicio

  • Se ejecuta como el usuario antimatter, en /opt/antimatter, y lee /etc/antimatter/antimatter.env. systemd reinicia el servidor cada vez que este termina, y le otorga hasta una hora para arrancar, ya que las migraciones de base de datos de una nueva versión pueden tardar mucho.
  • Sus registros están en el journal: journalctl -u antimatter.
  • Está endurecido: /usr y /etc son de solo lectura para el servidor, excepto /etc/antimatter/config, y no puede ver /home, /root ni /run/user. Si mueve el almacenamiento de archivos (FileSettings.Directory), elija un directorio fuera de estos, propiedad de antimatter.
  • Las actualizaciones reemplazan el archivo del servicio. Para modificarlo, use sudo systemctl edit antimatter, que conserva sus cambios en un archivo separado.

Actualizar un paquete

  1. Realice una copia de seguridad (consulte Copias de seguridad y actualizaciones).
  2. Descargue el nuevo paquete y SHA256SUMS, y verifíquelos.
  3. Detenga el servidor, instale el nuevo paquete sobre el antiguo y vuelva a iniciarlo: 
    sudo systemctl stop antimatter
sudo apt install ./antimatter_<new version>-1_amd64.deb     # or: sudo dnf install ./antimatter-<new version>-1.x86_64.rpm
sudo systemctl start antimatter
journalctl -u antimatter -f

El paquete no reinicia el servidor por sí mismo. Después de una actualización, muestra Antimatter was upgraded; restart it to run the new version: sudo systemctl restart antimatter: si no detuviste el servidor antes, reinícialo de inmediato. La actualización reemplaza /opt/antimatter y el archivo de servicio, y conserva antimatter.env, config.json, /var/lib/antimatter y los registros. Al iniciarse, el servidor actualiza la base de datos e instala las versiones más recientes de las aplicaciones incluidas.

Si una nueva versión modifica el antimatter.env predeterminado, apt pregunta si deseas conservar tu versión: consérvala. dnf conserva la tuya y guarda la nueva como /etc/antimatter/antimatter.env.rpmnew. Las actualizaciones solo se realizan hacia adelante: no instales una versión anterior sobre una más reciente.

Eliminar un paquete

sudo apt remove antimatter o sudo dnf remove antimatter detiene y deshabilita el servicio, y elimina el programa. Conserva los datos (/var/lib/antimatter), la configuración (/etc/antimatter), la base de datos y el usuario antimatter: elimínalos tú mismo para eliminar Antimatter por completo.

Aplicaciones en los paquetes y el archivo

Los paquetes y el archivo incluyen la última versión firmada de estas aplicaciones, en prepackaged_plugins/: Agents, Calls, GIFs, Memes, Notes, Polls, Todo, Voice Channels y Whiteboard. Una aplicación que aún no tenía una versión publicada cuando se creó la versión del servidor se omite: ls /opt/antimatter/prepackaged_plugins muestra lo que incluye tu versión. Memes y Todo están incluidos pero no activados: Aplicaciones incluidas explica cómo instalarlas y activarlas.

Las otras aplicaciones de las imágenes de Docker no están en los paquetes ni en el archivo: Kanban, Playbooks, Mail, Calendar, GitHub, GitLab, Jira y Metrics. Instala cada una desde sus propias versiones:

AplicaciónVersionesId de la aplicación
Kanbanantimatter-plugin-boardsfocalboard
Playbooksantimatter-plugin-playbooksplaybooks
Correoantimatter-plugin-mailcom.antimatterchat.mail
Calendarioantimatter-plugin-calendarcom.antimatterchat.calendar
GitHubantimatter-plugin-githubgithub
GitLabantimatter-plugin-gitlabcom.github.manland.mattermost-plugin-gitlab
Jiraantimatter-plugin-jirajira
MétricasAntimatter-plugin-metricscom.mattermost.mattermost-plugin-metrics

Cada versión de la app incluye el paquete de la app (un archivo .tar.gz), su firma (el mismo nombre con .sig añadido) y un archivo SHA256SUMS. Para instalar una app, permite las subidas y luego añade el paquete con amctl:

# 1. In /etc/antimatter/antimatter.env, add this line, then restart Antimatter
AM_PLUGINSETTINGS_ENABLEUPLOADS=true
sudo systemctl restart antimatter
# 2. Download the bundle where the antimatter user can read it, and install it
cd /tmp
curl -fLO https://github.com/AntimatterChat/antimatter-plugin-boards/releases/download/v<version>/<bundle>.tar.gz
sudo -u antimatter amctl --local plugin add <bundle>.tar.gz
sudo -u antimatter amctl --local plugin enable focalboard

Para actualizar una app instalada de esta manera, añade el nuevo paquete con plugin add --force: las actualizaciones de paquetes solo actualizan las apps empaquetadas. Después puedes volver a eliminar la línea AM_PLUGINSETTINGS_ENABLEUPLOADS. Consulta Instalación de otras apps para conocer las demás formas de instalar apps.

Firmas de las apps

Los paquetes de las apps están firmados con la clave de firma de apps de Antimatter: cada archivo .tar.gz.sig es una firma GPG separada de su paquete. El servidor comprueba estas firmas antes de instalar una app empaquetada. Para comprobar un paquete tú mismo:

curl -fsSLO https://raw.githubusercontent.com/AntimatterChat/antimatter-docker/main/keys/antimatter-plugin-signing.asc
gpg --import antimatter-plugin-signing.asc
gpg --verify <bundle>.tar.gz.sig <bundle>.tar.gz

gpg debe informar de una firma válida de Antimatter Plugin Signing, con la huella 06C8 1032 4677 0F08 BBA7 78B9 E69B 05C3 92A6 9A45. También advertirá de que la clave no está certificada con una firma de confianza: eso es normal para una clave que no has firmado tú mismo. Una versión de la app sin archivos .sig no está firmada, y sus notas de versión lo indican.

Instalar desde un archivo de liberación

El archivo antimatter-<version>-linux-<arch>.tar.gz (por ejemplo, antimatter-0.9.0-linux-amd64.tar.gz) es adecuado para una distribución sin paquetes .deb o .rpm, o para un esquema propio. Contiene un único directorio antimatter/ con bin/antimatter, bin/amctl, config/config.json, las apps web (client/ y client-fusion/), las apps empaquetadas (prepackaged_plugins/, ver arriba), las plantillas de correo y las traducciones.

1. Preparar PostgreSQL

Antimatter solo admite PostgreSQL, versión 15 o posterior (las versiones anteriores se inician, pero generan un error en el registro). Crea un usuario y una base de datos:

sudo -u postgres psql <<'EOF'
CREATE USER antimatter WITH PASSWORD 'a-long-password';
CREATE DATABASE antimatter OWNER antimatter;
EOF

2. Descomprimir y configurar

sudo tar -xzf antimatter-<version>-linux-amd64.tar.gz -C /opt
sudo useradd --system --user-group antimatter
sudo mkdir -p /opt/antimatter/data
sudo chown -R antimatter:antimatter /opt/antimatter

Indica al servidor la base de datos, ya sea en /opt/antimatter/config/config.json (SqlSettings.DataSource) o mediante variables de entorno, y establece la URL del sitio:

AM_SQLSETTINGS_DRIVERNAME=postgres
AM_SQLSETTINGS_DATASOURCE=postgres://antimatter:a-long-password@localhost:5432/antimatter?sslmode=disable&connect_timeout=10
AM_SERVICESETTINGS_SITEURL=https://chat.example.com

El config.json del archivo es una configuración predeterminada completa: los ajustes que cambies en la Consola de sistema se guardan en él. Para mantener la configuración en la base de datos en su lugar, consulta Configuración.

3. Ejecutarlo como un servicio

Una unidad de systemd, en /etc/systemd/system/antimatter.service:

[Unit]
Description=Antimatter
After=network.target postgresql.service

[Service]
Type=notify
User=antimatter
Group=antimatter
WorkingDirectory=/opt/antimatter
ExecStart=/opt/antimatter/bin/antimatter
EnvironmentFile=-/etc/antimatter.env
TimeoutStartSec=3600
Restart=always
RestartSec=10
LimitNOFILE=49152

[Install]
WantedBy=multi-user.target

Coloca tus variables AM_ en /etc/antimatter.env (legible solo por root) y luego:

sudo systemctl daemon-reload
sudo systemctl enable --now antimatter
journalctl -u antimatter -f

El servidor escucha en el puerto 8065. Abre http://<server>:8065, o tu dominio una vez que esté configurado un proxy inverso (consulta Dominio y HTTPS), y crea la primera cuenta: esta se convertirá en el administrador del sistema.

bin/amctl gestiona el servidor en ejecución desde la línea de comandos. En el propio servidor, funciona sin iniciar sesión mediante el modo local: establece AM_SERVICESETTINGS_ENABLELOCALMODE=true y luego ejecuta sudo -u antimatter /opt/antimatter/bin/amctl --local system status.

Para los GIF, instala el servicio de GIF (ver abajo) y configura AM_GIFS_SERVICE_URL y AM_GIFS_API_KEY como en el paso 5 de los paquetes.

Paquetes del servicio de GIF y del proxy de notificaciones

El servicio de GIF y el proxy de notificaciones push tienen sus propias versiones de lanzamiento, con las mismas reglas que las del servidor: un archivo .tar.gz, un paquete .deb y un paquete .rpm para amd64 y arm64, y un archivo SHA256SUMS. Las versiones con un guion son versiones preliminares. Comprueba las descargas con sha256sum --check --ignore-missing SHA256SUMS, igual que con el servidor.

El servicio de GIF (gifs-server)

Versiones de lanzamiento: github.com/AntimatterChat/gifs-server/releases. El archivo es gifs-server-<version>-linux-<arch>.tar.gz; los paquetes se denominan gifs-server.

sudo apt install ./gifs-server_*_amd64.deb      # Debian, Ubuntu
sudo dnf install ./gifs-server-*.x86_64.rpm     # Fedora, RHEL

El paquete instala:

  • /usr/bin/gifs-server, y el servicio gifs-server, que se ejecuta como el usuario gifs-server y mantiene su catálogo en /var/lib/gifs-server;
  • el servicio gifs-server-stickers, que importa o actualiza el paquete de pegatinas en /usr/share/gifs-server/stickers cuando lo inicias, y luego se detiene;
  • sus ajustes, /etc/gifs-server/gifs-server.env (variables AM_GIFS_, conservadas en las actualizaciones) y /etc/gifs-server/api-keys, una clave de API por línea, con una clave aleatoria generada en la primera instalación.

Escucha en 127.0.0.1:8080, por lo que solo Antimatter en el mismo servidor puede acceder a él. Si Antimatter se ejecuta en otro lugar, configura AM_GIFS_LISTEN=:8080 en gifs-server.env y restringe el acceso al puerto con tu cortafuegos. El archivo enumera los demás ajustes: AM_GIFS_UPLOAD_KEYS (las claves autorizadas para añadir GIF y pegatinas, y para eliminar las añadidas con ellas), AM_GIFS_PUBLIC_URL, AM_GIFS_TRUST_PROXY y AM_GIFS_LOG_LEVEL. El paquete recomienda ffmpeg, gifsicle, librsvg2-bin (librsvg2-tools para el .rpm) y una fuente DejaVu: el servicio las utiliza para crear los formatos de GIF, vídeo y pegatina al importar o recibir archivos, y se ejecuta sin ellas.

Al igual que el servidor, el servicio se habilita pero no se inicia en la instalación. Inícialo como se muestra en el paso 5 de los paquetes. Después de una actualización, reinícialo: sudo systemctl restart gifs-server. Al eliminar el paquete, se conserva el catálogo en /var/lib/gifs-server.

El proxy de notificaciones push

Versiones: github.com/AntimatterChat/push-proxy/releases. El archivo es antimatter-push-proxy-<version>-linux-<arch>.tar.gz; los paquetes se denominan antimatter-push-proxy. El paquete instala /usr/bin/antimatter-push-proxy y el servicio antimatter-push-proxy, que se ejecuta como el usuario antimatter-push-proxy y lee /etc/antimatter-push-proxy/antimatter-push-proxy.json (se conserva en las actualizaciones). Las credenciales de Apple y Firebase se colocan en /etc/antimatter-push-proxy/certs: Notificaciones push explica de dónde proceden.

sudo apt install ./antimatter-push-proxy_*_amd64.deb      # or: sudo dnf install ./antimatter-push-proxy-*.x86_64.rpm
sudo install -o root -g antimatter-push-proxy -m 0640 \
    AuthKey_ABCDE12345.p8 firebase-service-account.json /etc/antimatter-push-proxy/certs/
sudoedit /etc/antimatter-push-proxy/antimatter-push-proxy.json
sudo systemctl start antimatter-push-proxy
journalctl -u antimatter-push-proxy -f

En el archivo de configuración, las rutas son relativas a /etc/antimatter-push-proxy: por ejemplo, "AppleAuthKeyFile": "./certs/AuthKey_ABCDE12345.p8" y "ServiceFileLocation": "./certs/firebase-service-account.json". A continuación, configure Servidor de Notificaciones Móviles en Antimatter como http://<proxy host>:8066. Después de una actualización, reinícielo: sudo systemctl restart antimatter-push-proxy.

El proxy de notificaciones push escucha en el puerto 8066 en todas las direcciones y no verifica quién lo llama. Mantenga el puerto en una red privada o detrás de un proxy inverso que restrinja el acceso.

Otros comandos del servidor

Además de ejecutar el servidor (antimatter o antimatter server), el binario tiene algunos comandos de mantenimiento. Leen la misma configuración que el servidor.

ComandoQué hace
antimatter versionImprime la versión, el número de compilación, la fecha de compilación y el hash de compilación.
antimatter db pingComprueba que la base de datos es accesible.
antimatter db initCrea la configuración en la base de datos (con AM_CONFIG establecido en una URL postgres://).
antimatter db migrateAplica las migraciones de la base de datos sin iniciar el servidor.
antimatter db versionImprime la última migración aplicada a la base de datos.
antimatter import bulk, antimatter export bulkImporta o exporta datos en el formato por lotes (consulta Copias de seguridad y actualizaciones).
