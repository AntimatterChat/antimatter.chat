Σύνταξη εφαρμογών (πρόσθετα)

Οι εφαρμογές προσθέτουν λειτουργικότητα στο Antimatter από μέσα: ένα server μέρος σε Go που συνδέεται με τον server, και ένα web app μέρος σε React που προσθέτει μενού, πάνελ, τύπους μηνυμάτων και σελίδες. Αυτή η σελίδα δείχνει πώς δομείται μια εφαρμογή, χρησιμοποιώντας τη συσκευασμένη εφαρμογή Polls ως παράδειγμα, και τι αλλάζει στο Fusion interface του Antimatter.

Πώς λειτουργεί μια εφαρμογή

  • Το server μέρος είναι ένα πρόγραμμα Go. Ο server το εκτελεί ως ξεχωριστή διεργασία και επικοινωνεί με αυτό μέσω RPC: καλεί τα hooks της εφαρμογής (ένα μήνυμα πρόκειται να δημοσιευτεί, εκτελέστηκε μια εντολή…) και η εφαρμογή καλεί το plugin API του server (δημιουργία μηνύματος, ανάγνωση χρήστη, αποθήκευση δεδομένων…). Μπορεί επίσης να εξυπηρετεί HTTP routes κάτω από /plugins/<app id>/.
  • Το web app μέρος είναι ένα JavaScript bundle που φορτώνεται στον browser μαζί με το web app. Εγγραφεί React components και callbacks στο μητρώο: ένα κουμπί σε ένα μενού, ένα πάνελ, ένας τρόπος απόδοσης ενός τύπου μηνύματος.
  • Κάθε μέρος είναι προαιρετικό. Μια εφαρμογή εγκαθίσταται ως δέσμευμα .tar.gz, και οι διαχειριστές συστήματος την ενεργοποιούν, απενεργοποιούν και ρυθμίζουν.
Το server μέρος εκτελείται με πλήρη πρόσβαση στα δεδομένα του server. Χρησιμοποιήστε μια εφαρμογή όπως κώδικα που αναπτύσσετε στον server.

Το Antimatter εκτελεί εφαρμογές γραμμένες για Mattermost, και το αντίστροφο, εφόσον μια εφαρμογή χρησιμοποιεί μόνο hooks που και τα δύο έχουν. Δείτε Hooks που έχει μόνο το Antimatter.

Η δομή του δέσμευματος

Δεν υπάρχει ξεχωριστό starter template: ξεκινήστε από μια μικρή συσκευασμένη εφαρμογή όπως το antimatter-plugin-polls ή το antimatter-plugin-todo, και αλλάξτε το ID και τον κώδικά της. Το Polls έχει τη δομή:

antimatter-plugin-polls/
├── plugin.json            the manifest
├── Makefile               build, test, bundle, deploy
├── build/                 the manifest and pluginctl helper tools (Go), setup.mk
├── assets/icon.svg        files shipped with the bundle
├── go.mod
├── server/
│   ├── main.go            plugin.ClientMain(&Plugin{})
│   ├── plugin.go          the Plugin type, OnActivate, ServeHTTP
│   ├── manifest.go        generated from plugin.json
│   ├── api.go, command.go, hooks.go, store.go …
│   └── dist/              compiled binaries, one per platform
└── webapp/
    ├── package.json, webpack.config.js, tsconfig.json
    ├── i18n/              en.json and one file per language
    ├── src/index.tsx      registers the app with the web app
    ├── src/manifest.ts    generated from plugin.json
    ├── src/translations.ts
    └── dist/main.js       the bundle

Προαιρετικά: ένα φάκελο public/, που εξυπηρετείται ως έχει στο /plugins/<app id>/public/.

plugin.json

{
  "id": "com.example.weather",
  "name": "Weather",
  "description": "Forecasts in the chat.",
  "homepage_url": "https://github.com/example/weather",
  "support_url": "https://github.com/example/weather/issues",
  "icon_path": "assets/icon.svg",
  "version": "1.0.0",
  "min_server_version": "12.0.0",
  "server": {
    "executables": {
      "linux-amd64": "server/dist/plugin-linux-amd64",
      "linux-arm64": "server/dist/plugin-linux-arm64",
      "darwin-amd64": "server/dist/plugin-darwin-amd64",
      "darwin-arm64": "server/dist/plugin-darwin-arm64",
      "windows-amd64": "server/dist/plugin-windows-amd64.exe"
    }
  },
  "webapp": {"bundle_path": "webapp/dist/main.js"},
  "settings_schema": {"settings": []}
}
  • id: μοναδικό και μόνιμο· συνήθως χρησιμοποιείται reverse domain name. Ονοματίζει τις routes, τις αποθηκευμένες ρυθμίσεις και τα WebSocket events.
  • version: semantic version. Οι συσκευασμένες εφαρμογές το αφήνουν εκτός του plugin.json· το build tool το παίρνει από το τελευταίο v* git tag.
  • min_server_version: το Antimatter αναφέρει 12.0.0.
  • settings_schema: η σελίδα ρυθμίσεων της εφαρμογής στην Κονσόλα συστήματος (βλ. Ρυθμίσεις).

Η εντολή make apply αντιγράφει το manifest στα αρχεία server/manifest.go και webapp/src/manifest.ts· η εντολή make manifest-check το ελέγχει.

Το μέρος του server

Το μέρος του server εισάγει το ίδιο Go module με τις εφαρμογές Mattermost, github.com/mattermost/mattermost/server/public, από το Go module proxy. Το main του απλώς εκκινεί την εφαρμογή:

package main

import "github.com/mattermost/mattermost/server/public/plugin"

func main() {
	plugin.ClientMain(&Plugin{})
}

Ο τύπος Plugin ενσωματώνει τον τύπο plugin.MattermostPlugin, ο οποίος του παρέχει το p.API, και υλοποιεί τα hooks που χρειάζεται:

type Plugin struct {
	plugin.MattermostPlugin
	router *mux.Router
}

func (p *Plugin) OnActivate() error {
	p.router = p.newRouter()
	return p.API.RegisterCommand(&model.Command{
		Trigger:          "weather",
		AutoComplete:     true,
		AutoCompleteDesc: "Show the forecast",
		AutoCompleteHint: "[city]",
	})
}

func (p *Plugin) ExecuteCommand(c *plugin.Context, args *model.CommandArgs) (*model.CommandResponse, *model.AppError) {
	city := strings.TrimSpace(strings.TrimPrefix(args.Command, "/weather"))
	return &model.CommandResponse{
		ResponseType: model.CommandResponseTypeEphemeral,
		Text:         "Forecast for " + city + ": sunny",
	}, nil
}

func (p *Plugin) ServeHTTP(c *plugin.Context, w http.ResponseWriter, r *http.Request) {
	p.router.ServeHTTP(w, r)
}

Κοινά hooks

HookΠότε εκτελείται
OnActivate, OnDeactivateΌταν η εφαρμογή ενεργοποιείται ή απενεργοποιείται, καθώς και κατά την εκκίνηση και τον τερματισμό του server. Εγγραφείτε εντολές και bots στο OnActivate.
OnConfigurationChangeΌταν αλλάζουν οι ρυθμίσεις της. Φορτώστε τις με p.API.LoadPluginConfiguration(&cfg).
ServeHTTPΑιτήματα προς /plugins/<app id>/…. Το server ορίζει το header Mattermost-User-Id όταν το αίτημα προέρχεται από συνδεδεμένο χρήστη· απορρίψτε αιτήματα χωρίς αυτό, εκτός αν προορίζονται να είναι δημόσια.
ExecuteCommandΌταν εκτελείται μια εντολή που εγγραφήθηκε από την εφαρμογή.
MessageWillBePosted, MessageWillBeUpdatedΠριν αποθηκευτεί ένα μήνυμα: επιστρέψτε ένα τροποποιημένο post ή έναν λόγο απόρριψής του.
MessageHasBeenPosted, MessageHasBeenUpdated, MessageHasBeenDeletedΜετά τη δράση, για δευτερεύουσες επιπτώσεις.
ReactionHasBeenAdded, ReactionHasBeenRemovedΑντιδράσεις.
UserHasJoinedChannel, UserHasLeftChannel, UserHasJoinedTeam, UserHasLeftTeam, ChannelHasBeenCreatedΑλλαγές στη συμμετοχή και στα κανάλια. Ένα team είναι μια κοινότητα.
FileWillBeUploadedΠριν αποθηκευτεί ένα αρχείο: τροποποιήστε το ή απορρίψτε το.
OnPluginClusterEventΈνα μήνυμα από την ίδια εφαρμογή σε άλλο server ενός cluster.

Η πλήρης λίστα, με τις ακριβείς υπογραφές, βρίσκεται στο server/public/plugin/hooks.go· το API βρίσκεται στο server/public/plugin/api.go. Το πακέτο pluginapi (server/public/pluginapi) περιτυλίγει το API σε πιο φιλικές βοηθητικές συναρτήσεις.

Χρήσιμες κλήσεις API

  • CreatePost, UpdatePost, SendEphemeralPost: δημοσίευση ως το bot της εφαρμογής ή ως χρήστης.
  • EnsureBotUser(&model.Bot{Username, DisplayName}): δημιουργία του bot της εφαρμογής μία φορά και λήψη του ID του.
  • PublishWebSocketEvent("poll_updated", payload, &model.WebsocketBroadcast{ChannelId: id}): αποστολή συμβάντος στο web app. Φτάνει ως custom_<app id>_poll_updated.
  • OpenInteractiveDialog: άνοιγμα διαλόγου.
  • LogInfo, LogError και συναφή: εγγραφή στο αρχείο καταγραφής του server, με ετικέτα το ID της εφαρμογής.
  • GetUser, GetChannel, HasPermissionToChannel: έλεγχος ποιος μπορεί να κάνει τι, πριν ενεργήσετε για λογαριασμό χρήστη.

Μια εφαρμογή εκτελείται σε κάθε διακομιστή ενός κλάστου. Κρατήστε την κατάσταση (state) στο αποθετήριο κλειδιών-τιμών ή στη βάση δεδομένων, όχι μόνο στη μνήμη.

Αποθήκευση δεδομένων

Κάθε εφαρμογή έχει το δικό της αποθετήριο κλειδιών-τιμών στη βάση δεδομένων του διακομιστή:

  • KVSet(key, value), KVGet(key), KVDelete(key): οι τιμές είναι bytes, συνήθως JSON. Τα κλειδιά είναι έως και 150 χαρακτήρες.
  • KVSetWithExpiry(key, value, seconds): η τιμή εξαφανίζεται μετά από αυτό το χρονικό διάστημα.
  • KVCompareAndSet(key, old, new) και KVSetWithOptions με Atomic: ασφαλείς ενημερώσεις όταν πολλά αιτήματα ή διακομιστές γράφουν στο ίδιο κλειδί. Η εφαρμογή Ψηφοφοριών αποθηκεύει έτσι κάθε ψήφο και επαναλαμβάνει τη διαδικασία σε περίπτωση σύγκρουσης.
  • KVList(page, perPage): τα κλειδιά, σελίδα προς σελίδα.

Το μέρος της web εφαρμογής

Το bundle καταγράφει μια κλάση με window.registerPlugin. Η μέθοδος initialize της λαμβάνει το μητρώο (registry) και το Redux store:

import manifest from './manifest';

class Plugin {
    initialize(registry, store) {
        registry.registerTranslations((locale) => translationsFor(locale));
        registry.registerPostTypeComponent('custom_poll', PollPost);
        registry.registerWebSocketEventHandler(`custom_${manifest.id}_poll_updated`, (msg) => {
            store.dispatch(pollUpdated(JSON.parse(msg.data.poll)));
        });
        registry.registerReconnectHandler(() => store.dispatch(reloadPolls()));
    }
}

window.registerPlugin(manifest.id, new Plugin());
  • Κοινές βιβλιοθήκες. Η web εφαρμογή παρέχει React, ReactDOM, Redux, React Redux και React Intl: αναφέρετε τις ως webpack externals (React, ReactDOM, Redux, ReactRedux, ReactIntl) αντί να συμπεριλάβετε δικές σας αντιγραφές. Δείτε το webpack.config.js της Ψηφοφορίας.
  • Κλήσεις στο μέρος του διακομιστή σας. Κάντε Fetch στο ${window.basename}/plugins/<app id>/… με τις επιλογές από Client4.getOptions() (από mattermost-redux/client): αυτές μεταφέρουν τα headers που χρειάζεται ο διακομιστής για να δεχτεί ένα αίτημα από το πρόγραμμα περιήγησης.
  • Η δική σας κατάσταση. Η registerReducer προσθέτει έναν reducer, αποθηκευμένο κάτω από state['plugins-<app id>'].
  • Τύποι. Οι επιπλέον μέθοδοι μητρώου του Antimatter δεν υπάρχουν στους δημοσιευμένους τύπους του Mattermost: η Ψηφοφορία δηλώνει το μητρώο που χρησιμοποιεί στο webapp/src/types/host.ts.

Οι μέθοδοι του μητρώου και οι παράμετροί τους τεκμηριώνονται στον κώδικα, στο webapp/fusion/src/plugins/registry.ts (Fusion) και στο webapp/channels/src/plugins/registry.ts (κλασική).

Υποστήριξη της διεπαφής Fusion

Το Antimatter έχει δύο web διεπαφές: την Fusion, η οποία είναι η προεπιλογή, και την κλασική. Και οι δύο φορτώνουν τα ίδια bundles εφαρμογών και έχουν το ίδιο μητρώο, αλλά η Fusion σχεδιάζει πολλά στοιχεία από μόνη της και τοποθετεί τα συστατικά των εφαρμογών με τον δικό της τρόπο. Δοκιμάστε την εφαρμογή σας και στις δύο.

Ανίχνευση της διεπαφής

Πριν φορτωθεί οποιαδήποτε εφαρμογή, και οι δύο διεπαφές ορίζουν το window.antimatterWebUI σε 'fusion' ή 'classic', και την ίδια τιμή στο ριζικό στοιχείο της σελίδας ως data-am-web-ui. Στο Mattermost, κανένα από τα δύο δεν ορίζεται.

export function isFusionUI(): boolean {
    return window.antimatterWebUI === 'fusion' || document.documentElement.dataset.amWebUi === 'fusion';
}

Οι ενσωματωμένες εφαρμογές χρησιμοποιούν αυτό για να αποδίδονται διαφορετικά. Η εφαρμογή Ψηφοφοριών αποδίδει τις κάρτες ψηφοφορίας και τον διάλογο δημιουργίας της στο στυλ του Fusion, και ανοίγει τον δικό της διάλογο για την /poll εντολή στο Fusion. Οι κλήσεις και τα φωνητικά κανάλια παραλείπουν τα στοιχεία της πλευρικής στήλης και των ειδοποιήσεων (toasts) που το Fusion αντικαθιστά με τη δική του διεπαφή κλήσεων. Η εφαρμογή Πράκτορες τοποθετεί τις ενέργειες Τ.Π. της σε ένα υπομενού του μενού μηνύματος, αντί για την εργαλειοθήκη που εμφανίζεται με το πέρασμα του δείκτη. Οι δικές του κλάσεις CSS (με πρόθεμα am-) και η στρώση διαλόγων (το στοιχείο am-layer) είναι αυτά που χρησιμοποιούν οι εφαρμογές για να ταιριάζουν με τη διεπαφή· δεν πρόκειται για τεκμηριωμένο, σταθερό API.

Τι δεν εμφανίζει ή εκτελεί το Fusion

  • Τα registerPostDropdownMenuComponent (ένα στοιχείο στο μενού μηνύματος), registerPostCardTypeComponent (μια κάρτα μηνύματος στο δεξί πάνελ) και registerProductSwitcherMenuItem δεν εμφανίζονται στις κύριες απόψεις του Fusion. Χρησιμοποιήστε το registerPostDropdownMenuAction αντί για το πρώτο.
  • Το registerMessageWillBeUpdatedHook δεν εκτελείται όταν ένα μήνυμα επεξεργάζεται στο Fusion. Ελέγξτε τις επεξεργασίες στον διακομιστή με το hook MessageWillBeUpdated αντί για αυτό.
  • Το registerActionAfterChannelCreation εκτελείται μόνο από τον κλασικό διάλογο δημιουργίας καναλιού, τον οποίο το Fusion ανοίγει από Περισσότερες επιλογές… στον διάλογο Δημιουργία καναλιού.
  • Τα στοιχεία της γραμμής εργαλείων της εφαρμογής εμφανίζονται ανεξάρτητα από το supportedProductIds.
  • Οι διαδρομές από registerNeedsTeamRoute και registerCustomRoute διατηρούν το κλασικό πλαίσιο σελίδας, όπως και τα προϊόντα.

Hooks που υπάρχουν μόνο στο Antimatter

Αυτές οι μέθοδοι μητρώου δεν υπάρχουν στο Mattermost. Ελέγξτε ότι μια μέθοδος υπάρχει πριν την καλέσετε, ώστε η εφαρμογή να λειτουργεί και εκεί:

if (typeof registry.registerComposerMenuItem === 'function') {
    registry.registerComposerMenuItem({
        text: 'Create a poll',
        icon: <i className='icon icon-chart-bar'/>,
        fusionIcon: 'poll',
        action: ({channelId, rootId}) => openPollCreation(channelId, rootId),
    });
} else {
    registry.registerChannelHeaderButtonAction(icon, (channel) => openPollCreation(channel.id), 'Create a poll', 'Create a poll');
}
ΜέθοδοςΤι προσθέτει
registerComposerMenuItem({text, icon, fusionIcon, action, shouldRender})Ένα στοιχείο στο μενού + του πεδίου μηνύματος, και στα δύο περιβάλλοντα. Το action λαμβάνει {channelId, rootId}.
registerEmojiPickerTab({id, label, icon, fusionIcon, order, component, shouldRender, replacesGifPicker})Μια καρτέλα του επιλογέα emoji του πεδίου μηνύματος, όπως GIF ή αυτοκόλλητα. Στο Fusion, οι καρτέλες με τιμή order μικρότερη από 10 εμφανίζονται πριν την καρτέλα Emoji. Το στοιχείο λαμβάνει channelId, rootId, filter, onFilterChange, onSelectDone, insertText και isFusion.
registerChannelViewPanel({matcher, component})Ένα πάνελ ανάμεσα στην κεφαλίδα του καναλιού και τα μηνύματα, για τα κανάλια που επιλέγει ο matcher(state, channel). Μπορεί να κρύψει τα μηνύματα και το πεδίο σύνταξης (setMessagesVisible), όπως κάνουν τα φωνητικά κανάλια.
registerSidebarChannelFooterComponent(component)Μια γραμμή κάτω από ένα κανάλι στην πλευρική στήλη, όπως τα άτομα που συμμετέχουν στην κλήση του. Λαμβάνει το channel.
registerIntegrationsOption({title, description, fusionIcon, action, shouldRender})Μόνο Fusion: μια εγγραφή στις σελίδες Ολοκληρώσεις, δίπλα στα προσαρμοσμένα emoji. Η εφαρμογή GIFs προσθέτει εκεί τα προσαρμοσμένα GIFs και τα αυτοκόλλητα της.

Το fusionIcon ονομάζει ένα εικονίδιο του σετ εικονιδίων του Fusion (για παράδειγμα poll, sticker, calendar ή image; δείτε webapp/fusion/src/fusion/components/icon). Το Fusion το εμφανίζει αντί για το icon, ώστε το στοιχείο να ταιριάζει με τα υπόλοιπα.

Ρυθμίσεις

Το settings_schema στο plugin.json περιγράφει τη σελίδα της εφαρμογής στο Κονσόλα συστήματος › Προσθήκες:

"settings_schema": {
  "header": "Forecasts come from the weather service below.",
  "settings": [
    {"key": "ServiceURL", "display_name": "Service URL", "type": "text", "default": "https://api.example.com"},
    {"key": "Units", "display_name": "Units", "type": "dropdown", "default": "metric",
     "options": [{"display_name": "Celsius", "value": "metric"}, {"display_name": "Fahrenheit", "value": "imperial"}]},
    {"key": "EnableAlerts", "display_name": "Severe weather alerts", "type": "bool", "default": false,
     "help_text": "Post alerts in the channels that follow a city."}
  ]
}

Τύποι ρυθμίσεων: bool, text, longtext, number, dropdown, radio, generated (μια τυχαία μυστική τιμή), username και custom (αποδίδεται από ένα στοιχείο που εγγράφει το μέρος της web εφαρμογής με registerAdminConsoleCustomSetting). Οι ρυθμίσεις μπορούν να ομαδοποιηθούν σε sections.

Το μέρος του server τις διαβάζει σε μια δομή (struct) cuyos campos coinciden con las claves:

type configuration struct {
	ServiceURL   string
	Units        string
	EnableAlerts bool
}

func (p *Plugin) OnConfigurationChange() error {
	var cfg configuration
	if err := p.API.LoadPluginConfiguration(&cfg); err != nil {
		return err
	}
	p.setConfiguration(&cfg)
	return nil
}

Οι διαχειριστές μπορούν επίσης να τις ορίσουν στη διαμόρφωση, κάτω από PluginSettings.Plugins.<app id>, με κλειδιά σε πεζά (βλ. οδηγός διαχείρισης).

Μεταφράσεις

Το Antimatter μεταφράζεται σε 37 γλώσσες, και οι ενσωματωμένες εφαρμογές επίσης. Το μέρος της web εφαρμογής το κάνει ως εξής:

  1. Γράψτε κάθε συμβολοσειρά με React Intl, με ένα ID και το αγγλικό κείμενο: <FormattedMessage id='polls.create' defaultMessage='Create a poll'/> ή defineMessages. Προθέστε τα ID με το όνομα της εφαρμογής σας.
  2. Εκτελέστε τις αγγλικές συμβολοσειρές στο webapp/i18n/en.json (οι ενσωματωμένες εφαρμογές χρησιμοποιούν formatjs extract).
  3. Προσθέστε ένα αρχείο ανά γλώσσα δίπλα του, με τα ίδια ID: fr.json, de.json, pt-BR.json, zh-CN.json…
  4. Δώστε τα στην web εφαρμογή, η οποία ζητά τη γλώσσα του χρήστη: 
    import fr from '../i18n/fr.json';
import ptBR from '../i18n/pt-BR.json';

const catalogs = {fr, 'pt-BR': ptBR};

export function translationsFor(locale) {
    return catalogs[locale] || catalogs[locale.split('-')[0]] || {};
}

registry.registerTranslations(translationsFor);

Ένα λείπον string επιστρέφει στο αγγλικό defaultMessage. Για τα strings που στέλνει το server (απαντήσεις εντολών, μηνύματα bot), το πακέτο pluginapi/i18n φορτώνει τα αρχεία μετάφρασης που περιλαμβάνονται στο bundle (για παράδειγμα assets/i18n) και παρέχει έναν localizer στη γλώσσα κάθε χρήστη.

Συγκόλληση, εγκατάσταση και αποσφαλμάτωση

Χρειάζεστε Go και Node.js (η έκδοση στο .nvmrc της εφαρμογής). Στον φάκελο της εφαρμογής:

ΕντολήΛειτουργία
make distΣυγκολλεί το μέρος του server για κάθε πλατφόρμα και το μέρος της web εφαρμογής, και γράφει το bundle στο dist/<app id>-<version>.tar.gz.
make testΕκτελεί τις δοκιμές Go και JavaScript.
make check-styleΕλέγχει τον κώδικα (golangci-lint, ESLint) και ελέγχει τους τύπους TypeScript.
make deployΣυγκολλεί, στη συνέχεια εγκαθιστά και ενεργοποιεί το bundle σε έναν server.
make watch, make deploy-from-watchΤο πρώτο συγκεολλεί ξανά το μέρος της web εφαρμογής κάθε φορά που αποθηκεύετε. Το δεύτερο συσκευάζει ό,τι συγκεολλήθηκε και το εγκαθιστά στον server.
make enable, make disable, make resetΕνεργοποιεί, απενεργοποιεί ή επανεκκινεί την εφαρμογή στον server.
make logs, make logs-watchΕμφανίζει τις γραμμές της εφαρμογής στο αρχείο καταγραφής (log) του server.
make attachΣυνδέει τον αποσφαλματωτή Delve στο τρέχον μέρος του server (συγκεολλήστε πρώτα με AM_DEBUG=1).

Η make deploy και οι άλλες εντολές του server χρησιμοποιούν μια τοπική socket όταν βρουν μία (/var/tmp/antimatter_local.socket, ή AM_LOCALSOCKETPATH): εκτελέστε τις στον υπολογιστή του server με τοπική λειτουργία ενεργοποιημένη. Αλλιώς, συνδέονται στον server που δίνεται από το MM_SERVICESETTINGS_SITEURL με το AM_ADMIN_TOKEN, ή με το AM_ADMIN_USERNAME και το AM_ADMIN_PASSWORD. Τα εργαλεία συγκεολλησης δεν διαβάζουν ακόμα ένα όνομα AM_ για το site URL.

Εγκατάσταση bundle με το χέρι

  • Ένας διαχειριστής συστήματος επιτρέπει ανεβάσματα με AM_PLUGINSETTINGS_ENABLEUPLOADS=true (απενεργοποιημένο από προεπιλογή. Δεν υπάρχει διακόπτης στο Κονσόλα συστήματος).
  • Στη συνέχεια Κονσόλα συστήματος › Προσθήκες › Διαχείριση Plugins › Ανέβασμα Plugin, ή amctl plugin add weather.tar.gz ακολουθούμενο από amctl plugin enable com.example.weather.
  • Αν ο διακομιστής έχει ενεργοποιημένη την Απαιτείται υπογραφή plugin, αποδέχεται μόνο δέσμευες υπογεγραμμένες με κλειδί που εμπιστεύεται· δείτε Εγκατάσταση άλλων εφαρμογών.
Για γρήγορες επαναλήψεις σε έναν server ανάπτυξης, ορίστε AM_SERVICESETTINGS_ENABLEDEVELOPER=true στον server: τα σφάλματα θα φέρουν τότε τις λεπτομέρειές τους. Τα Makefiles των συσκευασμένων εφαρμογών συγκεολλούν το μέρος του server μόνο για την πλατφόρμα σας όταν το MM_SERVICESETTINGS_ENABLEDEVELOPER είναι ορισμένο στο shell σας.
