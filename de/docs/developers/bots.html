Bots und interaktive Nachrichten

Ein Bot-Konto ist ein Benutzer, der für ein Programm erstellt wurde. Es hat einen eigenen Namen, ein eigenes Bild und eigene Tokens und zeigt neben dem Namen das BOT-Symbol. Diese Seite behandelt auch die interaktiven Elemente von Nachrichten: Schaltflächen, Menüs und Dialoge, die von jeder Integration verwendet werden können.

Warum ein Bot-Konto?

  • Seine Nachrichten stammen von einer klaren Identität mit dem BOT-Symbol, nicht vom Konto einer Kollegin oder eines Kollegen.
  • Seine Tokens funktionieren weiter, wenn die Person, die es eingerichtet hat, ihre Rolle ändert oder das Unternehmen verlässt (außer der Server deaktiviert die Bots inaktiver Besitzer, siehe unten).
  • Bots können sich nicht mit einem Passwort anmelden und sehen die Web-App nie.

Apps erstellen ihre eigenen Bots, wie die Bots für To-do oder Playbooks, über die Plugin-API (EnsureBotUser).

Bot-Konten aktivieren

Ein Systemadministrator aktiviert Aktiviere Bot-Kontoerstellung in Systemkonsole › Integrationen › Bot-Konten (ServiceSettings.EnableBotAccountCreation, AM_SERVICESETTINGS_ENABLEBOTACCOUNTCREATION). Standardmäßig ist diese Option deaktiviert. Nur Systemadministratoren können Bots erstellen, es sei denn, sie gewähren diese Berechtigung in den Einstellungsoptionen für Berechtigungen auch anderen Rollen.

Auf derselben Seite deaktiviert Deaktiviere Bot-Konten, wenn der Besitzer deaktiviert ist (ServiceSettings.DisableBotsWhenOwnerIsDeactivated, standardmäßig aktiv) einen Bot, wenn das Konto seines Besitzers deaktiviert wird.

Bot erstellen

  1. Öffnen Sie oben rechts Ihr Profilbild, dann Integrationen › Bot-Konten und dann Bot-Konto hinzufügen.
  2. Geben Sie einen Benutzernamen (Kleinbuchstaben, Ziffern, Punkte, Bindestriche und Unterstriche) sowie optional ein Bot-Symbol, einen Anzeigenamen und eine Beschreibung ein.
  3. Wählen Sie die Rolle: Mitglied oder Systemadministrator für einen Bot, der den Server verwaltet. Vergeben Sie einem Bot nur die Berechtigungen, die er wirklich benötigt.
  4. Aktivieren Sie post:channels, damit er in jedem öffentlichen Kanal posten kann, oder post:all, damit er in jedem Kanal, einschließlich privater Kanäle und Direktnachrichten, posten kann, ohne Mitglied zu sein.
  5. Legen Sie fest, wann sein Standard-Token abläuft, und wählen Sie dann Bot-Konto erstellen.
  6. Kopieren Sie das angezeigte Zugriffstoken. Es wird nicht erneut angezeigt.

Später fügt Neues Token erstellen in der Zeile des Bots ein Token hinzu. Jedes Token kann deaktiviert oder gelöscht werden. Bot-Tokens funktionieren auch dann, wenn persönliche Zugriffstokens für Benutzer deaktiviert sind.

Über die API:

# create the bot (you become its owner)
curl -X POST https://chat.example.com/api/v4/bots \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"username": "deploy-bot", "display_name": "Deploy", "description": "Posts deployments"}'

# give it a token
curl -X POST https://chat.example.com/api/v4/users/$BOT_USER_ID/tokens \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"description": "deploy pipeline"}'

Von der Kommandozeile aus, angemeldet als Administrator (nicht im lokalen Modus): amctl bot create deploy-bot --display-name Deploy --with-token --expires-in 90d. Weitere Endpunkte: GET /api/v4/bots, PUT /api/v4/bots/{bot_user_id}, POST /api/v4/bots/{bot_user_id}/disable und /enable, POST /api/v4/bots/{bot_user_id}/assign/{user_id}, um den Besitzer zu ändern.

Den Bot zu Communities und Kanälen hinzufügen

Ein neuer Bot gehört keiner Community an. Fügen Sie ihn wie eine Person hinzu, über die Mitgliederverwaltung der Community oder über die API:

curl -X POST https://chat.example.com/api/v4/teams/$TEAM_ID/members \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"team_id": "'$TEAM_ID'", "user_id": "'$BOT_USER_ID'"}'

curl -X POST https://chat.example.com/api/v4/channels/$CHANNEL_ID/members \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"user_id": "'$BOT_USER_ID'"}'

Ein Bot mit post:channels oder post:all kann posten, ohne Mitglied zu sein, erhält aber nur WebSocket-Ereignisse für die Kanäle, in denen er sich befindet.

Als Bot posten

Verwenden Sie das Token des Bots für jeden API-Aufruf; POST /api/v4/posts ist der häufigste (siehe Hauptressourcen). Um jemandem direkt zu schreiben, öffnen Sie zuerst den Direktnachrichten-Kanal:

# returns the channel; use its "id" as channel_id
curl -X POST https://chat.example.com/api/v4/channels/direct \
  -H "Authorization: Bearer $BOT_TOKEN" -H 'Content-Type: application/json' \
  -d '["'$BOT_USER_ID'", "'$USER_ID'"]'

Um auf das zu reagieren, was die Leute sagen, folgen Sie dem WebSocket mit dem Token des Bots und beantworten Sie die posted-Ereignisse, die Sie interessieren. Ignorieren Sie die eigenen Nachrichten des Bots, um Schleifen zu vermeiden.

Eine Nachricht, die nur eine Person sehen kann (eine ephemere Nachricht), wird mit POST /api/v4/posts/ephemeral und {"user_id", "post": {"channel_id", "message"}} gesendet. Dafür wird die Berechtigung create_post_ephemeral benötigt, die standardmäßig nur Systemadministratoren haben. Integrationen senden ephemere Nachrichten in der Regel als Antwort auf Slash-Befehle und Schaltflächen.

Interaktive Nachrichten: Schaltflächen und Menüs

Jede Nachricht mit Anhängen kann Aktionen enthalten: Schaltflächen und Menüs zur Auswahl. Sie funktionieren in Nachrichten, die über die API, Webhooks oder als Antwort auf Slash-Befehle gepostet werden. Wenn jemand eine davon verwendet, ruft Antimatter die URL Ihrer Integration auf.

{
  "channel_id": "…",
  "message": "Deploy **api 2.4.0** to production?",
  "props": {
    "attachments": [{
      "actions": [
        {
          "id": "approve",
          "type": "button",
          "name": "Approve",
          "style": "primary",
          "integration": {"url": "https://deploy.example.com/actions", "context": {"release": "2.4.0", "action": "approve"}}
        },
        {
          "id": "env",
          "type": "select",
          "name": "Pick an environment",
          "options": [{"text": "Staging", "value": "staging"}, {"text": "Production", "value": "production"}],
          "integration": {"url": "https://deploy.example.com/actions", "context": {"release": "2.4.0", "action": "env"}}
        }
      ]
    }]
  }
}
  • type: button oder select.
  • id: Buchstaben, Zahlen, Bindestriche und Unterstriche, für jede Aktion der Nachricht unterschiedlich. Wenn Sie sie weglassen, wird sie generiert.
  • style (Schaltflächen): default, primary, success, good, warning, danger oder eine Hex-Farbcode.
  • options (Menüs) oder data_source: users oder channels, um eine Person oder einen Kanal auszuwählen. default_option wählt einen Wert vor.
  • integration.url: der Ort, an den der Klick gesendet wird. Eine App (ein Plugin) kann einen eigenen Pfad verwenden, z. B. /plugins/com.example.deploy/actions. integration.context gehört Ihnen: Er wird mit dem Klick zurückgesendet und ist für Clients unsichtbar.

Die Anfrage, die Ihre Integration erhält

{
  "user_id": "…",
  "user_name": "priya",
  "channel_id": "…",
  "channel_name": "releases",
  "team_id": "…",
  "team_domain": "lumen-labs",
  "post_id": "…",
  "trigger_id": "…",
  "type": "button",
  "context": {"release": "2.4.0", "action": "approve"}
}

Für ein Menü ist type select und context.selected_option enthält den gewählten Wert.

Ihre Antwort

{
  "update": {"message": "Deploy of **api 2.4.0** approved by @priya", "props": {}},
  "ephemeral_text": "Done. The deploy starts in a minute."
}
  • update: Ersetzt den Text und die Eigenschaften der Nachricht, z. B. um die Schaltflächen nach der Verwendung zu entfernen (ein leeres props).
  • ephemeral_text: Eine Nachricht, die nur die Person sieht, die geklickt hat.
  • goto_location: Eine URL, die geöffnet wird.
  • Ein leerer Body ändert nichts.

Der Server wartet so lange, wie die Zeitüberschreitung der Integrationsanfrage es zulässt (standardmäßig 30 Sekunden). Integrations-URLs auf privaten Netzwerkadressen müssen von einem Systemadministrator freigegeben werden, wie bei Webhooks.

Dialoge

Ein Dialog ist ein Formular, das über dem Chat geöffnet wird. Sie können ihn nur als Antwort auf etwas öffnen, das die Person gerade getan hat, z. B. einen Slash-Befehl oder eine Schaltfläche, da dafür der trigger_id dieser Anfrage benötigt wird. Der trigger_id ist so lange gültig, wie die Zeitüberschreitung der Integrationsanfrage.

curl -X POST https://chat.example.com/api/v4/actions/dialogs/open \
  -H 'Content-Type: application/json' \
  -d '{
    "trigger_id": "'$TRIGGER_ID'",
    "url": "https://deploy.example.com/dialog",
    "dialog": {
      "callback_id": "new-release",
      "title": "New release",
      "introduction_text": "Fill in the release details.",
      "submit_label": "Create",
      "notify_on_cancel": false,
      "state": "anything you want back",
      "elements": [
        {"display_name": "Version", "name": "version", "type": "text", "placeholder": "2.4.0"},
        {"display_name": "Notes", "name": "notes", "type": "textarea", "optional": true},
        {"display_name": "Environment", "name": "env", "type": "select",
         "options": [{"text": "Staging", "value": "staging"}, {"text": "Production", "value": "production"}]},
        {"display_name": "Owner", "name": "owner", "type": "select", "data_source": "users"},
        {"display_name": "Notify the channel", "name": "notify", "type": "bool", "default": "true"}
      ]
    }
  }'
ElementtypWas es anzeigt
textEin einzeiliges Feld. subtype: text, email, number, password, tel oder url. min_length und max_length begrenzen es.
textareaEin mehrzeiliges Feld.
selectEine Liste: options, oder data_source users, channels oder dynamic mit einer data_source_url. multiselect erlaubt mehrere Werte.
boolEin Kontrollkästchen.
radioEine Auswahl aus options.
date, datetimeEin Datum oder ein Datum und eine Uhrzeit.

Jedes Element akzeptiert display_name, name, help_text, placeholder, default und optional.

Wenn die Person absendet, sendet Antimatter einen POST an die url des Dialogs:

{
  "type": "dialog_submission",
  "callback_id": "new-release",
  "state": "anything you want back",
  "user_id": "…",
  "channel_id": "…",
  "team_id": "…",
  "submission": {"version": "2.4.0", "notes": "", "env": "staging", "owner": "…", "notify": true},
  "cancelled": false
}

Antworten Sie mit einem leeren Body, um den Dialog zu schließen, oder lassen Sie ihn offen und zeigen Sie an, was falsch ist:

{"errors": {"version": "This version already exists."}}

{"error": "…"} zeigt eine Nachricht für das gesamte Formular an. Mit notify_on_cancel sendet das Schließen des Dialogs "cancelled": true. Dialoge funktionieren in Apps auf die gleiche Weise: Die OpenInteractiveDialog-Methode der Plugin-API akzeptiert dieselbe Anfrage.
