Die REST-API

Alles, was die Antimatter-Apps tun, läuft über dieselbe HTTP-API – Ihre Skripte können das also auch. Diese Seite erklärt, wie Sie sich authentifizieren, welche Ressourcen Sie am häufigsten verwenden, wie Antworten und Fehler aussehen und wie Sie Ereignisse live über den WebSocket verfolgen können.

Grundlagen

  • Basis-URL: https://chat.example.com/api/v4. Alle unten genannten Endpunkte sind relativ dazu.
  • Format: JSON als Eingang und Ausgang, außer bei Datei-Uploads (multipart). Senden Sie Content-Type: application/json.
  • IDs: Jedes Objekt hat eine 26 Zeichen lange id. Zeitangaben sind Millisekunden seit dem Unix-Epoch (create_at, update_at, delete_at; 0 bedeutet „nicht gelöscht“).
  • Communities sind Teams: Die API bezeichnet sie als teams mit einer team_id.
  • Sie selbst: Wo immer ein Pfad eine user_id erwartet, bedeutet me die angemeldete Person, wie in GET /users/me.

Die vollständige Liste der Endpunkte befindet sich im Servercode: Die Routen sind in server/channels/api4/*.go und die Typen in server/public/model deklariert. Die OpenAPI-Beschreibung im Ordner api/v4/source des Repositories deckt die von Mattermost geerbten Endpunkte sowie einige Erweiterungen von Antimatter ab: das Verschieben von Threads, Modellverbindungen und Nachrichtenaktionen. Die übrigen Endpunkte sind nur im Code dokumentiert.

Authentifizierung

Jede Anfrage, mit Ausnahme des Anmeldevorgangs und einiger öffentlicher Endpunkte, benötigt ein Token im Authorization-Header:

curl -H "Authorization: Bearer $TOKEN" https://chat.example.com/api/v4/users/me

Dort werden drei Arten von Tokens akzeptiert: persönliche Zugriffstokens, Sitzungstokens und OAuth-Zugriffstokens. Auch Authorization: Token … wird akzeptiert. Tokens in der Abfragezeichenfolge (?access_token=) werden nur für OAuth-Zugriffstokens akzeptiert.

Persönliche Zugriffstokens (empfohlen für Skripte)

Ein persönliches Zugriffstoken handelt in Ihrem Namen, läuft nicht ab, es sei denn, Sie vergeben ein Ablaufdatum, und kann jederzeit widerrufen werden. Persönliche Zugriffstokens sind standardmäßig deaktiviert:

  1. Ein Systemadministrator aktiviert Persönliche Zugriffs-Token aktivieren in Systemkonsole › Integrationen › Integrationsverwaltung (ServiceSettings.EnableUserAccessTokens, AM_SERVICESETTINGS_ENABLEUSERACCESSTOKENS).
  2. Für jede Person, die Tokens erstellen darf, öffnet ein Systemadministrator die Systemkonsole › Benutzerverwaltung › Benutzer, wählt im Menü der Person Rollen verwalten und aktiviert Diesem Konto die Erstellung persönlicher Zugriffstokens erlauben. Systemadministratoren können diese immer erstellen.
  3. Die Person öffnet oben rechts das eigene Avatar und dann Profil & Einstellungen › Sicherheit. Unter Persönliche Zugriffs-Token wird beschrieben, wofür das Token verwendet wird, und Token erstellen ausgewählt. Das Token wird nur einmal angezeigt: Es muss kopiert werden.

Über die API: POST /users/{user_id}/tokens mit {"description": "backup script", "expires_at": 0} (expires_at in Millisekunden; 0 für keine Ablaufzeit). Das Feld token in der Antwort ist das Geheimnis; die id wird verwendet, um es zu widerrufen (POST /users/tokens/revoke mit {"token_id": "…"}). Von der Kommandozeile: amctl token generate <user> <description>.

Ein Systemadministrator kann die Gültigkeitsdauer von Tokens über Maximale Gültigkeitsdauer für persönliche Zugriffstokens (Tage) auf derselben Systemkonsole-Seite begrenzen.

Sitzungstokens

Bei der Anmeldung mit einem Passwort wird ein Sitzungstoken im Antwort-Header Token zurückgegeben, die gleiche Art von Sitzung, die die Apps verwenden:

curl -i -X POST https://chat.example.com/api/v4/users/login \
  -H 'Content-Type: application/json' \
  -d '{"login_id": "maya", "password": "…"}'

Fügen Sie für ein Konto mit Multi-Faktor-Authentifizierung "token": "123456" hinzu. Sitzungen laufen ab, wie es die Sitzungseinstellungen des Servers vorsehen, und der Anmelde-Endpunkt ist ratenbegrenzt (5 Anfragen pro Sekunde). POST /users/logout beendet die Sitzung.

Browser authentifizieren sich stattdessen mit einem Cookie. Eine durch das Cookie authentifizierte Anfrage muss für alles außer GET auch den Header X-CSRF-Token senden; ein Token im Header Authorization benötigt keinen CSRF-Header.

OAuth-2.0-Apps

Um es Personen zu ermöglichen, sich mit ihrem Antimatter-Konto in Ihrer Anwendung anzumelden, registrieren Sie eine OAuth-2.0-App. Antimatter ist dann der OAuth-Anbieter:

  1. Aktiviere OAuth-2.0-Dienstprovider muss aktiviert sein (Systemkonsole › Integrationen › Integrationsverwaltung, ServiceSettings.EnableOAuthServiceProvider, standardmäßig aktiviert).
  2. Jemand mit dem Recht, OAuth-Apps zu verwalten (standardmäßig Systemadministratoren), öffnet sein Profilbild, dann Integrationen › OAuth-2.0-Apps und fügt die App mit ihren Callback-URLs hinzu. Sie erhalten eine Client-ID und ein Client-Geheimnis.
  3. Ihre Anwendung leitet Personen an https://chat.example.com/oauth/authorize weiter, mit response_type=code, client_id, redirect_uri und state. PKCE mit code_challenge_method=S256 wird unterstützt.
  4. Sie tauscht den Code an POST https://chat.example.com/oauth/access_token ein (grant_type=authorization_code, dann refresh_token zur Erneuerung) und ruft die API mit Authorization: Bearer <access token> auf.

Personen sehen die Apps, die sie autorisiert haben, unter Profil & Einstellungen › Sicherheit › Von dir autorisierte Apps.

Eine Nachricht senden

curl -X POST https://chat.example.com/api/v4/posts \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"channel_id": "'$CHANNEL_ID'", "message": "Backup finished: **42 GB** in 3 min"}'

Nachrichten sind Markdown. Fügen Sie "root_id" (der erste Post eines Threads) hinzu, um in einem Thread zu antworten, "file_ids" für Dateien und "props" für Anhänge und andere Zusatzinformationen (siehe Anhänge).

Die ID eines Kanals finden

curl -H "Authorization: Bearer $TOKEN" \
  https://chat.example.com/api/v4/teams/name/lumen-labs/channels/name/ops-alerts

Die Namen sind die aus dem Link des Kanals: /lumen-labs/channels/ops-alerts.

Paginierung

Liste-Endpunkte akzeptieren page (ab 0) und per_page (Standard 60, höchstens 200). Fordern Sie die nächste Seite an, bis eine Seite zurückkommt, die kürzer ist als per_page.

Die Nachrichten eines Kanals (GET /channels/{channel_id}/posts) akzeptieren auch since (eine Zeit: alles, was sich seitdem geändert hat) oder before und after (eine Beitrags-ID). Sie werden als Beitragsliste zurückgegeben: {"order": [IDs, newest first], "posts": {ID: post}, "next_post_id", "prev_post_id"}.

Fehler

Fehler verwenden die üblichen HTTP-Statuscodes (400 ungültige Eingabe, 401 nicht angemeldet, 403 nicht erlaubt, 404 nicht gefunden, 501 Funktion deaktiviert) und einen JSON-Body:

{
  "id": "api.context.permissions.app_error",
  "message": "You do not have the appropriate permissions.",
  "detailed_error": "",
  "request_id": "jz8zm5nunpbt8f3gpqsz5dq6so",
  "status_code": 403
}

Verwenden Sie id in Ihrem Code: message wird in die Sprache des Nutzers übersetzt. detailed_error ist leer, es sei denn, der Server läuft im Entwicklermodus (ServiceSettings.EnableDeveloper). Nennen Sie dem Server-Administrator die request_id: Sie ist in den Logs zu finden.

Ratenbegrenzung

Die Geschwindigkeitsbegrenzung ist standardmäßig deaktiviert. Wenn ein Systemadministrator sie aktiviert (Systemkonsole › Umgebung › Geschwindigkeitsbegrenzung), erhält jeder Client standardmäßig 10 Anfragen pro Sekunde mit Burst-Werten von 100, gezählt nach IP-Adresse oder Benutzer. Die Antworten enthalten X-RateLimit-Limit, X-RateLimit-Remaining und X-RateLimit-Reset; bei Überschreitung des Limits antwortet der Server mit 429 und einem Retry-After-Header in Sekunden. Einige Endpunkte, wie das Anmelden, haben unabhängig von der Einstellung ein eigenes Limit.

Schreiben Sie Skripte, die bei 429 warten und erneut versuchen, und vermeiden Sie Polling: Verwenden Sie stattdessen den WebSocket.

Der WebSocket-Ereignisstrom

Verbinden Sie sich mit wss://chat.example.com/api/v4/websocket. Authentifizieren Sie sich entweder über den Authorization: Bearer-Header in der Verbindungsanfrage oder indem Sie dies als erste Nachricht senden:

{"seq": 1, "action": "authentication_challenge", "data": {"token": "…"}}

Der Server sendet ein hello-Ereignis, gefolgt von einem Ereignis für alles, was Sie sehen dürfen:

{
  "event": "posted",
  "data": {"channel_id": "…", "channel_type": "O", "post": "{\"id\":\"…\",\"message\":\"Hello\",…}"},
  "broadcast": {"channel_id": "…", "team_id": "", "user_id": "", "omit_users": null},
  "seq": 4
}

Beachten Sie, dass data.post der Post als JSON-String ist. Häufige Ereignisse: posted, post_edited, post_deleted, reaction_added, reaction_removed, typing, status_change, user_added, direct_added. Apps senden eigene Ereignisse, benannt als custom_<app id>_<event>.

Sie können auch Aktionen senden, jeweils mit einer steigenden seq: user_typing mit {"channel_id", "parent_id"} oder get_statuses. Stellen Sie die Verbindung wieder her, wenn sie abbricht, und holen Sie sich mit since das nach,, was Sie verpasst haben (siehe Paginierung).

Antimatter fügt diese Ereignisse hinzu: community_attributes_updated, member_timeouts_updated, post_put_on_top, post_removed_from_top, server_categories_updated, channel_overrides_updated und category_overrides_updated.

Client-Bibliotheken

  • Los: model.Client4 in server/public/model (Import github.com/mattermost/mattermost/server/public/model). model.NewAPIv4Client(url), dann client.SetToken(token); model.NewWebSocketClient4(wsURL, token) folgt Ereignissen. Die Antimatter-Kopie fügt Methoden für eigene Endpunkte hinzu, wie UpdateMessageRequest, PutPostOnTop und ExportChannel.
  • TypeScript: die Client4-Klasse von @mattermost/client in webapp/platform/client, mit den Typen in webapp/platform/types. Die Kopie im Antimatter-Repository enthält die Endpunkte von Antimatter; das von Mattermost auf npm veröffentlichte Paket nicht.
package main

import (
	"context"
	"log"

	"github.com/mattermost/mattermost/server/public/model"
)

func main() {
	client := model.NewAPIv4Client("https://chat.example.com")
	client.SetToken("…")
	post, _, err := client.CreatePost(context.Background(), &model.Post{
		ChannelId: "…",
		Message:   "Hello from Go",
	})
	if err != nil {
		log.Fatal(err)
	}
	log.Println("posted", post.Id)
}

Neue Felder

  • Communities (Team, und PUT /teams/{team_id}/patch): all_channels_membership (jeder ist in jedem Kanal, den er sehen darf), default_channel_id (wo neue Mitglieder landen; leer bedeutet General), kind (community oder workplace: in einem Workplace können Kanaladministratoren ihre Kanäle auch archivieren; neue Communities erhalten die Servereinstellung TeamSettings.DefaultCommunityKind, standardmäßig community), member_list_view (wie die Mitgliederliste die Mitglieder gruppiert: choice, die Standardoption, lässt jedes Mitglied wählen; roles oder teams legt dies fest), hide_role_colors, require_team_badges, onboarding und autolinks (beide JSON-Zeichenketten).
  • Der Standardkanal einer neuen Community ist general (Allgemein), nicht town-square. Das Upgrade auf 0.9.0 benennt den town-square-Kanal jeder Community in general um, wobei die ID beibehalten wird, sofern die Community nicht bereits einen general-Kanal besitzt. Die alten Namen funktionieren weiterhin: GET /teams/{team_id}/channels/name/town-square, GET /teams/name/{team}/channels/name/town-square sowie das channel-Feld eines eingehenden Webhooks liefern den Standardkanal der Community, wenn kein Kanal diesen Namen trägt. Verwenden Sie in neuem Code default_channel_id oder den Namen general.
  • Kanallinks: #channel-name verlinkt einen Kanal, genau wie ~channel-name. Die channel_mentions-Eigenschaft des Beitrags listet die auf diese Weise verlinkten Kanäle auf; ein #word, der keinen Kanal benennt, bleibt ein Hashtag. Die Web-Oberfläche und die Mobile-App von Antimatter schreiben #name.
  • Archivierte Kanäle können weiterhin neue Mitglieder aufnehmen (POST /channels/{channel_id}/members), die deren Verlauf lesen können. Niemand kann dort posten, reagieren, anheften, Nachrichten nach oben setzen, den Kanal umbenennen oder die Rollen der Mitglieder ändern.
  • Inlinen-Antworten: Ein Beitrag mit "props": {"reply_to": "<post id>"} zitiert diese Nachricht aus demselben Kanal. Fügen Sie "reply_to_mention": false hinzu, um den Autor nicht zu benachrichtigen. Der Server füllt metadata.reply_to mit einer kurzen Beschreibung der zitierten Nachricht.
  • Spoiler: "props": {"spoiler": true} verbirgt den Text und die Dateien eines Beitrags, bis der Leser entscheidet, sie anzuzeigen.
  • Ignorieren und Sperren sind Einstellungen: Kategorie user_block, benannt nach der ID der anderen Person, mit dem Wert ignore oder block. Ob eine Direktnachricht als Anfrage wartet, steht in den notify_props.dm_request Ihres Kanalmitglieds (pending, accepted oder dismissed).
  • Nachrichtenanhänge können stages und ein chart enthalten: siehe Cards.

Thread verschieben

POST /posts/{post_id}/move_to_channel verschiebt einen Thread, seine erste Nachricht und alle Antworten in einen anderen Kanal derselben Community. post_id kann die erste Nachricht oder eine beliebige Antwort sein.

curl -X POST https://chat.example.com/api/v4/posts/$POST_ID/move_to_channel \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"channel_id": "'$TARGET_CHANNEL_ID'", "flatten": false}'
  • channel_id (Pflichtfeld): Der Kanal, in den der Thread verschoben wird.
  • flatten (Standardwert false): true macht die Antworten zu Nachrichten des Zielkanals, anstatt sie als Thread zu belassen. Fusion verwendet dies für In einen Kanal umwandeln.

Die Nachrichten behalten ihre Autoren, Zeitstempel, Reaktionen und Dateien. Ihre Kopien tragen die Eigenschaft silent_notification, sodass sie niemanden benachrichtigen. Die ursprünglichen Nachrichten werden gelöscht. Die Antwort ist die verschobene erste Nachricht mit ihrer neuen ID.

Wer einen Thread verschieben darf

  • Sie müssen in der Lage sein, den Thread zu lesen und im Zielkanal zu posten.
  • Die Administratoren des Kanals, die Administratoren der Community, Personen mit Nachrichten verwalten (delete_others_posts) im Kanal sowie Systemadministratoren dürfen jeden Thread verschieben.
  • Der Autor des Threads darf ihn verschieben, wenn beide Kanäle öffentlich sind oder wenn alle Nachrichten des Threads von ihm stammen. Andernfalls lautet die Antwort 403 mit der ID api.post.move_thread.private_needs_moderator.app_error.
  • Beide Kanäle müssen in derselben Community liegen (keine Direktnachrichten oder Gruppennachrichten), sich unterscheiden und dürfen nicht archiviert sein. Systemnachrichten und Nachrichten, die nach dem Lesen gelöscht werden, können nicht verschoben werden.
  • Ein Thread mit mehr als WranglerSettings.MoveThreadMaxCount Nachrichten (Standardmäßig 100; 0 für keine Grenze) wird abgelehnt.

Der Zeiger und die Notiz

Der Vorgang hinterlässt zwei Systemnachrichten vom Typ system_wrangler: einen Zeiger im alten Kanal („Ein Thread mit 13 Nachrichten wurde nach #target verschoben“) und eine Notiz im Zielkanal („Dieser Thread wurde aus #source verschoben“), unter dem verschobenen Thread oder, bei flatten, nach dessen Nachrichten. Neben dem Nachrichtentext ermöglichen deren Eigenschaften, dass ein Client den Kanalnamen als Link darstellt:

  • Der Zeiger: MovedThreadPermalink, NumMessages, MovedThreadChannelId, MovedThreadTeamName, MovedThreadPostId und, für ein öffentliches Ziel, MovedThreadChannelName und MovedThreadChannelDisplayName.
  • Die Notiz: MovedFromChannelId, MovedFromTeamName, MovedFromPostId (der Zeiger), MovedFromPermalink und, für eine öffentliche Quelle, MovedFromChannelName und MovedFromChannelDisplayName.

Beide haben auch eine TranslationID. Der Name eines privaten Kanals wird weggelassen: Leser sehen „ein anderer Kanal“. Der eigene POST /posts/{post_id}/move-Endpunkt von Mattermost ist in Antimatter deaktiviert; verwenden Sie diesen Endpunkt.

Modellverbindungen

Eine Modellverbindung ist die Adresse und der Schlüssel eines KI-Anbieters, die von einem Administrator eingerichtet werden. Die KI-Funktionen des Servers und die Apps, die den KI-Dienst aufrufen, nutzen sie. Systemadministratoren verwalten die serverweiten Verbindungen (manage_ai_connections); die Administratoren einer Community verwalten die eigenen ihrer Community (manage_team_ai_connections). Schlüssel sind nur schreibbar: Keine Antwort enthält einen, nur api_key_set und api_key_last4.

EndpunktFunktion
GET /ai/connections?scope=Die Verbindungen, die Sie verwalten. scope ist server oder die ID einer Community; ohne Angabe alle Bereiche, die Sie verwalten.
POST /ai/connectionsFügt eine Verbindung hinzu (antwortet mit 201).
POST /ai/connections/test, POST /ai/connections/modelsTestet eine Verbindung oder listet deren Modelle auf, bevor sie gespeichert wird. Gleicher Body wie beim Hinzufügen; es wird nichts gespeichert.
GET, PATCH (oder PUT), DELETE /ai/connections/{connection_id}Liest, ändert oder löscht eine Verbindung. Ein Patch enthält nur die Felder, die geändert werden sollen; lassen Sie api_key weg, um den Schlüssel beizubehalten.
POST /ai/connections/{connection_id}/testTestet eine gespeicherte Verbindung: {"ok", "error", "status_code", "latency_ms", "model_count"}.
GET /ai/connections/{connection_id}/modelsDie vom Anbieter angebotenen Modelle.
GET /ai/connections/{connection_id}/usageAnfragen und Token dieses Monats.
GET /ai/connections/usable?channel_id=&team_id=Für alle angemeldeten Benutzer: die dort verfügbaren Verbindungen samt deren Modellen und Funktionen – niemals deren Schlüssel oder Adressen.

Der Inhalt einer neuen Verbindung:

{
  "name": "Local models",
  "scope": "server",

provider ist entweder openai_compatible oder anthropic. scope ist standardmäßig server; die ID einer Community macht daraus eine Verbindung dieser Community. In limits bedeutet 0 kein Limit; Anfragen pro Minute werden auf jedem Server gezählt, Token-Budgets gelten pro Kalendermonat (UTC) für den gesamten Cluster. sharing bestimmt, welche Communities eine serverweite Verbindung nutzen dürfen (für Direktnachrichten und Gruppennachrichten ist all_teams erforderlich), und audience, wer sie nutzen darf; Gäste nur mit allow_guests. Änderungen werden im Audit-Protokoll festgehalten. Die Administrator-Dokumentation erklärt die Einstellungen: siehe KI.
